# DIY 读取与安装实施计划

计划日期：2026-11-01。DIY 读取、安装与验收进行中。原始任务清单保留；已实施内容、验证证据和未覆盖项见[实施进展](05-DIY接入进展-20261111.md)。

设计依据：[DIY 包体设计](../../docs/设计/DIY包体设计.md)。DIY 包提供模式和扩展；第一期通过新模式、扩展事件及 Lua 规则差异验证完整链路。先完成游戏的独立读取与装配，再把同一包交给安装器。安装器能解压不等于游戏已支持 DIY。

2026-11-14 新增的准备流程需求按[18 准备阶段框架实施计划](18-准备阶段框架实施计划-20261114.md)推进：固定企业分发与确认节点，模式配置前、中、后三段流程，中间所有卡牌选择页统一提供本人企业板预览。现有规则事件绑定不等于已经提供该流程入口。

## B0 固定封装与数据路径

- [ ] 建立 `nomadcity.diy` v1 清单、模式声明、事件追加配方格式及作者用 Schema；与 core schema 3 明确区分，允许只提供模式、只提供扩展或同时提供两者。
- [ ] 落实包 ID、发布版本、模式 ID、扩展 ID、定义/处理器/配方/文案命名空间、依赖范围和能力标识；模式/扩展记录来源包，不用包 ID 代替玩法 ID。
- [ ] 固定模式的展示信息、机制配置、必需扩展、地图约束、`setupRecipeRefs` 与 Lua 绑定合同；包依赖和扩展依赖分开校验。核对当前可用入口的调用时机、上下文、返回类型、顺序和续接身份，不虚构已实现的钩子。
- [ ] 新清单、模式和配方的示例由真实解析器检查；允许引用已有内容的模式不带新卡牌，不要求每个扩展必须拥有卡牌定义。
- [ ] 统一游戏与安装器的数据路径规则：当前用户、已知文件夹、真实 `app.info` 身份及旧中文目录处理。制定多个安装版本共享用户目录时的行为。
- [ ] 固定 `Mods/<packId>/<version>`、ZIP 根结构、ModProfiles、安装回执和同卷暂存目录。游戏发现阶段不扫描暂存或备份目录。
- [ ] 确定并公布文件数量、解压大小、图片尺寸和 Lua 预算等限制，所有导入入口共用同一校验实现或一致的测试向量。

验收：路径不依赖固定用户名/G 盘；包版本与 API/能力不混用；同一 ZIP 无论手动放置或由安装器导入，得到同一内容身份。

## B1 发现与单包校验

- [ ] 新增只扫描指定层级的包发现服务，读取名称、作者、版本、提供的模式/扩展与兼容要求，形成可用、未就绪、损坏等状态。
- [ ] 读取声明文件并校验重复 JSON 键、未知字段、ID、缺文件、脚本语法及图像/切片引用，保留包与相对路径来源。
- [ ] 防止绝对路径、目录穿越、目录联接/符号链接越界、大小写路径冲突和超限归档；不执行包内程序或未选 Lua。
- [ ] 在房间外的本地内容配置中管理包版本绑定，版本和错误保留于诊断；首次唯一可用版本可作为默认，升级不静默切换。房间只显示当前目录中的模式/扩展，不把版本并列成玩法选项；一局每个包只解析一个版本。
- [ ] 未选坏包留在诊断列表但不阻止基础对局；选中坏包时清晰失败，不静默关闭它继续开局。
- [ ] 将包内校验与跨包引用校验分开，不能在依赖包尚未汇总时把合法替换判为缺失。

验收：合法包、缺脚本、坏清单、缺图、重复包身份和不可读目录均有定位明确的结果；没有 Mods 时原有基础模式正常。

## B2 多包装配和开局内容

- [ ] 为 `ExternalContentPack` 周边增加包来源/组合快照抽象；复用现有定义与 Lua 校验能力，不把多个根目录简单拼成一个相对路径字典。
- [ ] 所有脚本、图片、文案、切片、共享模块、完成处理器、缓存和诊断携带来源身份；验证两包均有 `lua/main.lua` 时仍互不覆盖。
- [ ] 依赖拓扑和同级稳定排序确定装配；处理缺依赖、能力不足、版本不兼容、循环和冲突。
- [ ] 建立统一模式和扩展目录，基础、企业家与 DIY 使用相同注册合同。将 `GameRuleConfiguration.TryValidate` 及 `ExternalContentPack` 的模式/扩展白名单改为目录校验，保留重复身份、适用性与真实依赖检查。
- [ ] 将 `RuleModeReadiness` 和 `ActiveContentCatalogBuilder` 的企业家要求归入对应模式声明；禁止给所有非基础模式附加企业家能力。可复用机制按配置/能力启用，不为每个新模式再加 C# 特判。
- [ ] 按所有启用模式的 `setupRecipeRefs` 装配开局，再合并实际启用扩展的贡献。迁移固定 `standard` 及 enterprise/infected/entrepreneur 配方拼接，明确共享基础配方的适用范围，保留原官方组合行为；重复配方不重复入堆，参数冲突明确诊断。
- [ ] 模式和扩展的 Lua 绑定沿正式注册、规则调用、效果树与完成续接链装配；验证只读查询与效果入口的不同合同，以及切换、离局、恢复时不残留或重复注册。模式样例同时覆盖纯配置组合和 Lua 规则差异。
- [ ] `ActiveContentCatalogBuilder` 接入事件追加配方、地图及模式适用范围、数量与目标颜色牌堆；纯替换不额外追加一张。只提供模式或规则绑定的合法包不因缺少自有卡牌而失败。
- [ ] 对整个启用集合解析 `replaces`，维护稳定运行时槽位、最终定义身份、图片、按钮和脚本。验证链式替换、同目标冲突、缺目标、循环和新旧扩展组合。
- [ ] 分离官方基础内容完整性检查与新事件合法性检查；原企业必需替换保留明确约束，不用删校验来放行未知状态。
- [ ] 核对当前 `IsFourPlayerOnly` 的事件 ID 过滤，将其等价表达为基础配方地图限制；DIY 按声明控制，不误用实际人数替代地图。
- [ ] 收敛所有生产入口到同一活动快照，包括 `GameSessionBootstrapper`、Bootstrap、卡牌查询、展示与图片缓存。保持全局单例和资源生命周期一致。

验收：完成宿主适配后，添加 DIY 无需修改正式 core。纯模式包可登记平级模式并复用现有内容，扩展包可把新增事件合法入堆，混合包可同时提供两者；Lua 规则差异通过正式入口生效。替换只改变对应槽位内容，其他模式、未启用包和官方组合保持正确。

## B3 房间模式与扩展选择

- [ ] 确定实际菜单/房间资产来源，列出需新增或复用的引用与组件；任何界面生成、保存覆盖按资产所有权要求单独落实明确范围。
- [ ] 现有模式控件从统一目录生成候选，基础、企业家和 DIY 模式平级，允许组合不冲突的模式；扩展控件展示与已启用模式兼容的选项。模式/扩展名称和简介读取声明，既有静态标题与样式保留资产来源。
- [ ] 房间只保留模式与扩展这两类玩法选择，不新增包选择、包版本选择或先选包再选模式的流程。包名、版本、依赖和错误可放在详情/诊断中；“打开 DIY 文件夹”和版本配置放在房间外。
- [ ] 选择模式后按声明确定必需扩展，显示为已启用且不可取消；其余兼容扩展由房主勾选。切换模式保留兼容选项、明确展示移除的不兼容项；缺依赖或冲突时阻止准备，不能悄悄改变成另一种玩法。
- [ ] 从模式与扩展推导包依赖闭包并解析本地版本绑定；支持保存本地新局配置，旧存档和房间锁定清单优先于默认配置，不自动切换到最新包。
- [ ] 启用组合变化重新装配并使准备状态失效。失败返回可修改状态，不留下只更新规则或只更新显示的半套配置。
- [ ] 明确文件修改后的生效时机。第一期允许要求重启；菜单刷新只在无活动对局/房间的安全边界执行，不热换正在使用的内容。

验收：安装后，DIY 模式和扩展直接出现在房间对应选项中，无需先选择包。只提供模式、只提供扩展和混合包均可正常选择，失败可理解且可返回修改；不通过命令行测试开关代替正式入口。

## B4 内容指纹、联机和存档

- [ ] 建立安装清单与活动内容指纹的分离；未启用、无依赖的额外包不影响本局哈希。
- [ ] 指纹包含所有启用模式及来源、包/扩展/规则合同、机制配置、配方、Lua 规则绑定、奖励脚本及模块装配、按钮绑定与布局、图片和文案；顺序规范化保留真正有意义的列表顺序。
- [ ] 接入 `BasicRoomContentCapabilityProvider`、房间消息、准备校验与正式开局检查；缺包、版本不同、同版本源码被修改应分别显示具体差异。
- [ ] 房间与存档写入模式、扩展及精确包锁定清单；加入房间和恢复按精确版本与哈希装配，不读最新默认配置，不下载或覆盖用户包。
- [ ] 将新按钮选择和处理器身份接入保存、重连、检查点与确定性重放。不同程序执行合同仍检查，不能只比较内容包文件。
- [ ] 检查两个用户安装根路径不同仍得到相同活动哈希；本地绝对路径、时间戳和安装回执不得进入规则指纹。
- [ ] 不实现自动分发/下载；第一期联机要求各自安装一致内容，房间负责核验并说明差异。

验收：相同模式与扩展组合可正常联机；未启用的额外包不影响加入；缺包和同版本异内容被拦截；切换模式后重新准备，中断恢复无重复事件奖励或模式规则注册。

## C1 发布包与安装器组件

- [ ] 新增 DIY 发布包构建流程：纯模式、纯扩展和混合包共用校验、文件清单、SHA256 与 ZIP 输出；源包不修改，同一输入可复现文件内容身份。
- [ ] 安装器直接嵌入同一发布 ZIP，避免维护另一套随安装包复制的内容目录。
- [ ] 在 `tools/packaging/build_windows_installer.py` 中新增 DIY 输入清单与可选组件，列出包名、版本、简介、体积和兼容要求。
- [ ] 分出“安装或更新游戏”“仅安装 DIY 内容”“导出 DIY 内容包”入口，移除仅补装模式对游戏必选 Section 的依赖。
- [ ] 初次安装按本次构建身份确定数据根；仅补装按已安装游戏身份与能力检查，不把安装器自带版本当作目标游戏版本。
- [ ] 无法找到游戏或目标不兼容时说明原因并允许导出；导出不写游戏目录、AppData、快捷方式或卸载注册。

验收：安装游戏时可跳过 DIY；再次运行同一个安装包可单独补装；未安装游戏也能导出 ZIP。仅补装不重写主程序、快捷方式和卸载信息。

## C2 写入事务、重复安装和卸载

- [ ] ZIP 在同卷独立暂存目录提取并验证，成功后一次发布到最终版本目录，最后记录安装回执。失败、磁盘满或取消不产生可被发现的半包。
- [ ] 路径、文件数量和大小限制与游戏导入约定一致；拒绝归档中的越界项、链接、规范化重名和伪造身份路径。
- [ ] 同版本同哈希跳过；同版本不同哈希保留并提示冲突。明确修复时先完整备份，不默默覆盖作者本地修改。
- [ ] 新旧版本并存；运行旧安装包不能自动降级当前默认配置或覆盖新版本。
- [ ] 安装完成不通知正在运行的对局热换包；说明下次启动或安全刷新生效。
- [ ] 默认卸载保留数据；选择删除 AppData 时明确列出存档、DIY 和修改/备份的范围。若增加仅卸载附带 DIY 的功能，依据回执核对每个目标与文件哈希，修改过的文件不默删。
- [ ] 删除测试只使用明确授权的隔离目录或专用测试用户。逐目标核验绝对路径，按当前 AGENTS 与 Windows 路径要求执行，不能清理开发者真实存档来验证卸载。

验收：覆盖安装、取消、异常中断、并行安装冲突、用户修改及旧版本补装均保留正确数据；卸载默认保留 Mods，并准确区分可选删除行为。

## C3 完整流程与交付

| 场景 | 完成证据 |
| --- | --- |
| 首次选装 | 安装器选择包 → 实际 AppData 内容及回执 → 游戏发现 → 房间选择该包提供的模式/扩展 |
| 忘记安装后补装 | 首次未选 DIY → 同安装包仅补装 → 主程序未重写 → 游戏识别 |
| 导出和手动安装 | 导出 ZIP 与内置包哈希相同 → 按约定放置 → 得到相同内容身份 |
| 平级 DIY 模式 | 无自有卡牌的模式包进入现有模式列表 → 正常建房开局 → 复用既有机制及内容；基础/企业家仍可正常选择 |
| 模式 Lua 差异 | 正常流程到达声明的规则入口 → 绑定 Lua 的结果正确 → 保存恢复与联机保持一致，未到达入口记未覆盖 |
| 模式与扩展组合 | 混合包的模式/扩展分别进入对应控件；必需项锁定、可选项生效、不兼容组合明确提示；切换模式重置准备 |
| 新增事件 | 正常对局实际抽到 → 对应按钮/脚本 → 正确结算，未抽到保持未覆盖 |
| 替换事件 | 正常启用组合下使用最终图片、按钮、Lua，未重复入堆 |
| 联机和恢复 | 不同机器同包一致；缺包/异内容提示；事件中间请求恢复恰好一次 |
| 维护和卸载 | 重复安装、局部修改、版本并存、默认保留及明确删除的隔离验证 |

- [ ] 覆盖记录按程序版本、活动内容哈希、包锁定清单、GameId 和实际完成证据保存，不把不同版本结果混成一次通过。
- [ ] 真实 Steam 多账号、正常单机与隔离检查分别报告。未覆盖随机事件继续正常多局，不通过注入状态完成指标。
- [ ] 更新安装使用说明、DIY 作者文档、兼容说明及群内发布文案。安装成功、加载成功、可启用和正常对局已验证是不同状态，描述准确。
- [ ] 复核只交付经校验的样例和安装产物；用户目录、修改、旧存档及无关工作均保留。

最终验收目标：玩家不打开 Unity、不修改 core，从安装包选装或补装 DIY，在房间现有模式与扩展控件中选择并合法游玩；新模式通过现有机制及 Lua 表达规则，安装、读取、按钮奖励、联机与存档使用同一份内容身份。

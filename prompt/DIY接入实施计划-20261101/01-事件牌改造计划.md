# 事件牌改造实施计划

日期：2026-11-01。状态：全部待实施。阶段 A 完成后才进入独立 DIY 读取和安装。

依据：[DIY 包体设计第 3 节](../../docs/设计/DIY包体设计.md#3-事件牌选择合同)。目标是每个事件按钮条目直接声明奖励 Lua，卡面上下边界由 JSON 配置，按钮数量取自同一列表。不得继续使用独立布局表到 `optionIndex` 的映射作为新协议。

## A0 核对事件流程与迁移清单

- [ ] 核对当期提交、未提交改动、core 版本和现行 Lua API，记录不可覆盖的并行工作。
- [ ] 从当前 `pack.json` 追踪所有事件定义、替换关系、实际图片切片、脚本和开局配方。核查时有 24 个事件定义，数量只作基线，后续以真实清单为准。
- [ ] 逐选项整理：规则说明、旧数组下标、卡面显示顺序、按钮区域、奖励/支付、影响力选择、共享流程、完成处理器及适用模式。
- [ ] 审计正式入口和遗留入口的消费者：生产、隔离测试、自动玩家、日志、存档、克隆/相等比较和公开投影分别归类；不能以“搜索到旧方法”直接认定它是正式规则来源。
- [ ] 特别核对 `event_red_01`、`event_red_03` 及企业替换牌的卡面顺序差异；以当前实际切片和合法结果为准，不访问受限原档案。

## A1 定义、读取与脚本注册

- [ ] 增加 `eventChoiceSchemaVersion: 1`、`choices` 和显式零选项 `immediateResolve`；每个条目具备稳定 `choiceId`、内容说明、按钮上下百分比、脚本、入口版本及可选完成处理器。
- [ ] 在 `EventCardDefinition` 及其全部克隆、比较、序列化和公开读取中保留新字段；移除依赖旧数组计算选项数量的生产逻辑。
- [ ] 更新 `ExternalContentPack` 的原始 JSON 校验、脚本收集、内容冻结、`CreateEvents`、共享模块绑定及诊断。每个按钮脚本都进入正式注册与内容指纹，不能只加载整卡 `effectScript`。
- [ ] 新增事件能力标识，并明确旧格式不支持原因；升级事件定义/执行合同。新的事件字段不自动等于新的独立 DIY 包格式已可用。
- [ ] 完善 JSON Schema 与加载器同等验证：重复 ID、缺脚本、非法版本、未知字段、新旧格式混写、零选项与立即入口冲突、超出选项上限等。
- [ ] 确保注册键包含来源内容身份和稳定 `choiceId`。共享同一个 Lua 文件不等于两个按钮共享同一选择身份。

验收：1、2、3、4、6 个选项及零选项可正确解析；没有独立 `buttonCount`；缺失、重复或错误引用能定位到具体选择。旧数组与新列表混写明确失败。

## A2 正式选择、奖励执行和恢复

- [ ] 修改 `EventCardOptionIdFactory`，把 `choiceId` 纳入正式候选身份；校验编码、解析、重复和命名空间，不靠分隔符拼接猜测身份。
- [ ] `EventCardEffectExecutor` 由真实选择列表生成候选、保存所选身份并路由唯一奖励入口；UI 仅回传正式候选，不提交脚本路径或奖励参数。
- [ ] `EventCardLuaCatalog` 按卡牌和选择绑定调用正确 Lua；新增受校验的 `ctx.payload.choiceId`，清理依赖数字 `optionIndex` 分派的新协议路径。
- [ ] 保持抽牌、资源点建立、公开信息、基础影响力和奖励的既有合法顺序；将公共动作收敛为共同流程，禁止每个奖励脚本再重复一次。
- [ ] 将旧 `ChoicePendingEffects` 的影响力预选、支付等改为当前合法的 Lua/专门选择流程；没有目标、资源不足和取消等情况使用正式规则结果。
- [ ] 接入正式完成处理器、Effect 子树与版本检查。重复点击和重发不重复结算；等待目标、等待支付、子效果进行中和已完成时均可保存并按原进度恢复。
- [ ] 同步正式入口、自动玩家、日志/回放消费者。自动玩家依据合法候选作答，不能预执行未选脚本或读取隐藏状态模拟按钮奖励。
- [ ] 更新恢复原始字段检查及内容身份。旧存档未完成节点不按数组顺序自动转新协议，给出可理解的拒绝原因且保留原档。

关键验证：两个收益明显不同的选择确实只执行被选脚本；交换 JSON 数组顺序或按钮位置，`choiceId` 与奖励绑定保持不变；伪造脚本、其他卡的选择和旧请求全部拒绝；保存恢复不重复抽牌、放资源点、扣费或发奖。

## A3 卡面按钮显示

- [ ] `EventChoiceDialog` 从最终活动事件定义生成按钮，删除生产中的 `GetArtworkChoiceIndex` 和按卡牌 ID 决定按钮边界的逻辑。
- [ ] `EventCardInteractionUiCoordinator`、选择控制器及自动化定位使用稳定选择身份，不能再用视觉行号表示规则分支。
- [ ] 使用 JSON 的 `topPercent/bottomPercent`，按从卡面顶端向下的百分比转换到实际卡面局部坐标。
- [ ] 核对 `CardArtworkView`、`UiEventArtworkLayoutGroup`、现有弹窗布局和图集切片：单张图像比例、留白、缩放、窗口变化时，实际点击区始终与同一图片区域对齐。
- [ ] 继续实例化当前实际资产中的按钮模板；横向范围、反馈与视觉风格由模板提供。无卡面文字列表仅作为明确的既有展示路径，不能用它冒充卡面按钮验收。
- [ ] 对替换牌使用最终定义的图片、按钮、文案与脚本；检查场景覆盖和引用来源，不拿源预制体替代实际场景来宣称一致。
- [ ] 校验区间范围、正高度和非重叠；接壤区域只命中一项。错误不得静默夹紧、自动排序或套用默认旧卡位置。

验收：不同按钮数量、不等高区域、非等距布局、图集单卡与独立图片、缩放后边界及四项以上选择均可操作；按合法候选验证正确 Lua，不锁死美术坐标。没有重建或保存覆盖既有 UI 资产。

## A4 迁移正式事件与作者文档

- [ ] 按 A0 清单逐牌建立稳定选择 ID 和独立奖励脚本，保持现有真实规则；可复用已声明的冻结模块，但不增加文件读取权限。
- [ ] 同步基础事件与两张企业替换事件，删除新定义里的旧三组数组和整卡分支入口。旧材料仅作为隔离迁移输入，不留生产双路执行。
- [ ] 核对公共影响力处理只出现一次；记录选择/支付流程从旧数组迁出的等价证据。遇到原有真实错误，单独登记并按正确规则修复，不把错误固化为迁移基线。
- [ ] 为零选项、四选项和不等高区域准备明确标记的验证内容；正式样例卡面须来自用户提供或许可范围内素材，缺图则记录缺项。
- [ ] 更新 `content.schema.json`、相关包能力与版本，以及现行 JSON/Lua 作者文档；删除与新合同冲突的“通过 optionIndex 分派奖励”指引，保留明确的旧版本迁移说明。
- [ ] 检查所有文案与实际效果、按钮选区对应；不得通过改卡面或覆盖预制体来掩盖映射错误。

验收：所有正式事件都有可追溯的新条目；规则和对应关系明确，未留下靠卡牌 ID 修正顺序的生产特判。文档示例能被新加载器校验。

## A5 分层验收与阶段放行

| 层次 | 必测内容 |
| --- | --- |
| 格式/隔离规则 | 条目数量、百分比、ID、脚本/完成处理器、支付失败、目标为空、重复回答、旧格式拒绝、未选脚本无副作用 |
| UI 隔离定位 | 从实际资产实例化、卡面缩放、四项以上按钮、绑定正确性；单独标记，不计正常验收 |
| 正常单机 | 正常菜单和建房开局，合法探索/移动触发事件，完成选项、支付与后续选择，多局覆盖替换事件 |
| 恢复 | 事件待选、奖励中间请求、已完成三个边界保存恢复，无重复收益 |
| 联机 | 相同版本/内容的真实请求与稳定选择一致；不同绑定/内容拒绝；网络重发不重复结算 |

- [ ] 每局按版本、哈希、GameId、事件定义与 choiceId 记录已覆盖、未覆盖和失败。
- [ ] 随机未出现目标时继续当前局，下一局按合法候选补缺；禁止强刷、注入牌或预设对局冒充验收。
- [ ] 夹具差异与真实阻塞按项目中断标准处理，保留首次失败现场。
- [ ] A1～A4 完整、关键规则/恢复验证通过，正常覆盖及剩余缺口已明确后，判断是否满足阶段完成条件；关键按钮或结算未覆盖不得标记全部通过。

# NMC-012：移动城市、探索与事件牌迁移

## 任务提示词

你负责把移动城市、探索和事件牌结算迁移到 Event + Effect + Interaction 管线，消除旧服务间隐式串联与专用 `PendingCardSession`/选择状态。先做移动城市完整纵向切片，再按行为族迁移事件牌。

## 前置任务

`NMC-006`、`NMC-007`、`NMC-011` 已完成。

## 目标

1. 实现 `BeforeCityMove`、移动执行与 `CityMoveCompleted` 生命周期。
2. 将移动候选、玩家选择、影响力移除/放置、探索和事件牌 continuation 组合为可恢复 Effect 树。
3. 把事件牌规则迁移到版本化 Lua handler 和通用 Effect。
4. 清理被替代的旧移动/探索/事件牌 dispatcher、pending 与测试。

## 实施要求

1. 明确移动 Effect 的输入、候选来源、hard constraints、可拒绝性、资源成本、合法无变化和失败结果。客户端只提交稳定候选 ID。
2. `BeforeCityMove` 响应在实际移动提交前完成，可通过规范允许的 Effect 改变状态；响应结束后必须重新验证目标。
3. 城市移动状态提交后产生 `CityMoveCompleted`，其订阅者（包括探索/事件牌）作为响应子节点执行；不得由旧服务额外触发一次。
4. 需要移动影响力时复用 `NMC-011` 合同，不直接写集合；对部分失败/玩家拒绝的传播由 owning Effect 明确决定。
5. 事件牌按“无选择即时、单/多候选、条件式、影响力组合、移动后响应、动态 continuation”等行为族迁移。`completionHandlerId` 与绑定参数必须持久化，不能保存 C# 回调或 Lua 函数。
6. 事件牌 ID 只用于注册/内容身份，不在 C# 建规则分支。新增能力先定义通用 Effect 合同，再由脚本调用。
7. `PendingCardSession`、旧 candidate provider、探索协调器和事件检测器只有在所有真实调用方切断后才能逐项删除；每阶段用 `rg` 留证。

## 测试精简要求

- 用移动状态机矩阵覆盖：前置响应、候选失效、拒绝、成功、业务失败、完成响应和各 commit 恢复点。
- 事件牌按行为族和 catalog 数据表测试，不为每张牌复制 UI/命令/序列化全链路。
- 合并现有 MoveCity、Explore、EventCard、PendingCardSession 测试中的跨层重复；Presentation 只保留通用选择和可见性冒烟。
- 每张牌至少进入 schema/catalog 验证，但只有独特规则分支需要独立断言。

## 非目标

- 不迁移城市样式、特殊行动或设施内容。
- 不改变事件牌现有规则文本；不明确的内容记录为阻塞，不猜测。
- 不让探索或事件牌绕过通用 Interaction/Effect 直接改状态。

## 验收标准

- 移动前后 Event、候选复验、移动提交和探索/事件牌响应只有一条权威链路。
- 任意 commit 中断恢复不重复移动、抽牌、事件响应或玩家选择。
- 现有事件牌按行为族迁移且 C# 无内容 ID 特判生产分支。
- 已失去调用方的旧 pending/service/test 被逐项清理，暂留项有后续任务与真实引用。
- 完整 EditMode 通过且用例数未按卡牌数量线性膨胀，`git diff --check` 通过。

## 交付报告

提供移动时序、事件牌迁移矩阵、continuation/恢复证据、旧入口清理表、未决规则和测试净变化。

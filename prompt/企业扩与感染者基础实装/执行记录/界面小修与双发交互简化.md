## 已确认语义

- 保留现有回合主链和角色技能挂载结构，主要问题是交互冗余；不重做主链层级。
- 角色第一技能及响应完成后，双发自动进入另一技能；不再出现“继续第二效果／结束本次使用”的中间页。
- 第二技能待选时点击“结束行动”：停止该第二技能剩余部分，已支付、已获得和已放置等结果保留，不回滚。
- 若主要行动尚未完成，只停止第二技能并回到主要行动；主要行动完成后才能真正结束玩家行动。
- 阿米娅已经消费的来源不返还；三种双发资格、使用次数、角色最终去向仍由同一使用节点管理。已触发的其他玩家响应不能靠关闭自己的页面全局清除。

## 当前实际链

回合由 `RoundMainChainBuilder` 构建顺序主链，行动轮通过 `player_action_window.ActionRound=1/2` 区分，没有另设行动轮父 Effect。正式角色命令由 `TryCreatePlayerActionEffect` 挂到当前窗口的 `ExecutionEffectId`，不会另开脱离主链的根。

```text
第 R 回合主链
└─ 当前行动轮、当前玩家的 player_action_window
   └─ round.mainline.node（该主节点的执行 Effect）
      └─ character.quick_action（使用某张真实角色牌）
         └─ character.use（同一 UseId）
            ├─ character.effect.activate（策略或计谋，先选者）
            │  └─ 正式 Lua 返回的 Effect 子链及响应
            └─ character.effect.activate（另一模式）
               └─ 正式 Lua 返回的 Effect 子链及响应
```

首动资格来自 Host 的先手身份；拓荒指挥中枢在另一个样式特殊行动子树中授予当前行动轮资格，样式特殊行动与角色快速行动是玩家行动窗口下的兄弟。两者修订前的单模式 UI 入口在第一技能后发出 `character.use.second_mode` 请求，该请求不是另一个 Effect 子节点。本轮新使用协议自动追加并进入剩余模式，不再生成这个中间请求；旧协议已保存的中间请求由窄兼容迁移处理。

阿米娅在同一 `character.use` 下插入 `effect.condition → 消费持续来源 → effect.character.double_use_rule(scope=current_use)`，然后确定两模式顺序，原本已经自动连续。此次统一其后续停止交互，不新增第二次角色使用，也不再次消费阿米娅。修订前核查及实现方案见 `Logs/UiSmallRevision/20261008/flow/当前三种双发链与最小修订方案.md`；其中早期“已支付后不得停止”的草稿已被本节用户确认替代，实施必须按本节执行。

## 跳过与结算语义

- 玩家主动、允许跳过的当前 Effect 可由底栏停止剩余部分，保留已经生效的获得、支付、移动等结果，不回滚整个角色使用或主要行动。
- 第二技能自动进入待选但尚未做主要行动时，底栏结束只跳过第二技能并返回主要行动；完成主要行动才能真正结束行动。
- 调度两次移动是同一主要行动的两个子节点；一次完成后的跳过不撤销已移动棋子、不重复消耗主要行动。
- 自身必须承担的负面效果、强制付款、其他不可跳过步骤不能因这次 UI 简化获得跳过能力。使用执行层明确的可选/可中止状态，不按页面类型猜测。
- 收尾中未点击的可选项在结束时失效；已点击并执行到一半的效果按其本身可跳过规则处理。不能把所有收尾强制结算一并略过。

### 数量与收尾协议定稿

- 数量请求 `InteractionTypeId=effect.quantity.choose`、`AnswerSchema=bounded_amount`；PromptParameters 的 `minAmount/maxAmount` 为整数，`amountKind` 为 `player_marker` 或标准资源 ID。CandidateIds 为空。答案沿既有 `answerValue` 携带十进制整数字符串，结果沿 `ContinuationData.selectedAmount` 保存。Host 复核当前上下限，不静默裁剪过期答案。旧数字候选请求保持恢复兼容。
- UI 使用既有 `EffectDialogShell.AddResourceAllocation(RectTransform, ResourceAllocationSpec)` 数量行，不套出售规则，不增加内部跳过按钮，不能把空 CandidateIds 当作没有可执行选项。数量为零或跳过时遵守原有空载体退出政策。
- 底栏优先提交当前允许停止的请求 `Boolean false`，其次原有第二技能停止，最后真正结束行动；不能一次点击既跳过效果又结束玩家窗口。
- 收尾登记节点为 `effect.character.content.cleanup_offer`，来源参数为 `apiVersion/cardInstanceId/abilityId/windowEffectId`，正文保存在既有 NestedEffects/NestedGroupSizes。登记不执行、不扣费。强制子效果完成后主收尾请求 `character.cleanup.settlement` 开放，现有结算区显示来源。
- 点击沿 `InvokeSettlementOption`；OwnerEffectId 为主收尾节点、InteractionId 为当前窗口请求、CandidateId 为来源节点、TargetUseId 为空。`invokedOptionIds` 收据与正文子树同一次提交；完成后显示剩余可选项。结束提交 false，未用项失效。Lua 与能力声明使用 `character.execute_cleanup` 和既有标题/说明键；不把玩家可选窗口逐个改成待答弹窗。
- 异客拆为资源选择、标准玩家选择、数量分配，显示只用中文名和资源图标，保留双方得分和双发第二技能。具体请求键由 015 交接，012 不按角色名另建分支。

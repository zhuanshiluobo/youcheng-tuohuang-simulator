## 5. 数据接口、导航与正式请求边界

### 5.1 独立只读模式

在 `EnterpriseSelectionMode` 末尾追加 **BrowseDepartment**，既有四个值不重排。它是表现模式，不注册任何 `InteractionRequest`。其投影必须 `ReadOnly=true`、`SubmissionAvailable=false`，所有展示 target 使用真实可见 ItemId、`Available=false`；`Validate` 拒绝将此模式作为可提交投影，`CanConfirm` / `TryBeginSubmit` 明确排除它。

两个页面 Prefab 的 `modeText` 同步配置第五项，避免当前固定 `Length != 4` 和数组下标失配。不要沿用 `Mode >= InitialDepartment` 推断可提交业务；意图中 `DepartmentId` 仅由 InitialDepartment / SwitchDepartment 填入，CompanyId 仅由 Company / Effect 填入。只读页的会话键可沿现有 `RequestId` 字段承载本局/查看人/企业的展示身份，但不得当作规则请求 ID 发送。

拟新增私有表现入口：

- `GameplayExpansionUi.BuildPublicDepartmentProjection(GameStateView view, string enterpriseItemId)`：从同一份 `VisibleView()` 快照寻找该真实公开企业，确认其正式定义支持 `DepartmentRewardPolicy == active_department`；科室仅取当前可见的 `core.zone.department_display` 实例，并按 `FindDepartment(...).EnterpriseRuntimeId` 与企业匹配。
- 此目录与当前 `EnterpriseStateQuery.GetDepartmentCandidates` 的归属、展示区和排除当前值条件一致，但不读取全局未公开数据，也不拿真实规则请求候选替换浏览目录。没有候选显示空态，不补样例、不造 ID。
- `GameplayExpansionUi.OpenPublicDepartments(string enterpriseItemId)`：经 Registry 的 department=true 生成独立只读页实例，和 Coordinator 持有的正式 department 实例分开；绑定 `BindSubmission(null,null,null)`，普通信息页 `Present(...,false)`。
- `GameplayExpansionUi.ReturnToPublicEnterprises()`：检查当前 GameId、ViewerPlayerId、企业仍可见；重新取得可见投影并返回原公开页实例。玩家或游戏切换后清理旧导航上下文，不恢复过期页面。
- `EnterpriseSelectionDialogView.BindBrowseNavigation(Action<string> openDepartment, Action returnToEnterprises)`：单独接线浏览导航，不能复用 `cancelRequest` 或业务 Submit。
- `SuspendForNavigation()` / `ResumeFromNavigation(projection)`：保存、恢复原公开页的查看 ID、候选 ScrollRect 位置、正文滚动位置和可用焦点。`GameplayHudFrame.ShowPage` 对此类页面仅 SetActive(false)，不会自动清空 Draft；不要调用 `ClearPresentation/Close` 后重建父页来冒充保留状态。

`Refresh()` 应分别刷新当前可见公开企业页或只读科室页。只读科室页显示期间不将父页重新 ShowPage；返回时才应用最新父投影及仍有效的滚动/查看状态。`Clear()` / `OnDestroy()` 清理两个公开实例及导航回调。正式效果被信息页挂起/恢复仍沿 `GameplayHudFrame` 现有机制，不改 Frame 的通用导航实现。

### 5.2 单击、查看及返回

- 公开企业页单击莱茵本体或叠层：找到同一莱茵企业 target，设置相同 `Draft.InspectedId`。如果原来查看别家企业，切到莱茵整体；若已经查看莱茵，不能再切成科室状态。
- `OpenDetails(boardId)` 识别公开页中支持科室的企业，或其已激活科室 ID，统一路由到该企业的只读科室页。没有当前科室的莱茵仍可浏览其公开科室目录。
- 其余企业仍走原全图详情；右侧科室候选的右键、双击、长按仍查看科室原板。科室原板详情单击返回只读科室页；独立“返回企业合作板”再返回父页，两层返回不能混用。
- 所有手势继续复核当前投影、页是否激活、revision / viewer、pending 和同帧防误点；过期叠层不能打开旧科室，也不能保留旧关系文本。
- 固定莱茵和叠层没有任何入口，候选区域不因固定板输入改变 selection。

### 5.3 整体摘要

增加 `GameplayExpansionUi.BuildCooperationBoardSummary(view,itemId,definitionId)`，仅用于公开企业合作板。沿 `ProjectBoard` 已校验的 active relation 和真实科室定义取得当前科室完整 2—5 级原文，形成五个对应等级的段落：1 级使用莱茵原文；2、3、4、5 级各自使用当前科室相应等级的奖励原文。去掉企业 2—5 级的重复科室占位说明，保留各级编号、完整费用和效果。

根协调已澄清此前“合入莱茵 1 级”只是组合整体的简写，不能把科室奖励排进 1 级文段。整体查看身份统一，等级段落仍严格对应 1/2/3/4/5；不改领域触发等级和规则结算。格式沿现有可序列化 `LevelFormat` / `DepartmentFormat` 和正式内容原文，不在控制器散落新固定中文。无合法当前科室时展示莱茵原说明，不杜撰奖励。关系更换/移除后重新合成。原 `BoardSummary` 的正式选择、Effect 描述及奖励调用保持。

### 5.4 正式候选与提交

`EnterpriseInteractionUiCoordinator.BuildProjection` 保持从 `request.CandidateIds` 生成 Boards/Targets；`setup.department.choose`、`enterprise.department` 等原 Handles 集合不新增浏览请求。原 `EffectInteractionCommands.Answer(request,player,intent.TargetIds)`、版本复核、取消和费用结算不改。

当前科室的显示排除集中在 DialogView，适用于 InitialDepartment、SwitchDepartment、BrowseDepartment；正式开局无当前值不额外排除。Draft 对当前科室维持不可提交约束；模式、关系或版本变化时清理已失效选中项与详情。只读目录可以排除当前项，但不得修改宿主的正式候选 ID 集合。

已核对真实 ID 语义：Coordinator 的 `CurrentDepartmentId` 来自 `ActiveDepartmentRelation.TargetItemId`，是科室实例 **ItemId**；正式科室 target 的 `Id`、`DepartmentId`、`BoardId` 来自同一 `request.CandidateIds` 实例 ID，`ProjectBoard.ActiveDepartment.ItemId` 也取实际实例 ID。因此显示排除按对应 board 的 `Id` 或 target 的 `DepartmentId` 与 `CurrentDepartmentId` 做序数相等比较。`DefinitionId` 只用于读取定义、校验企业归属及找贴图，不能与 CurrentDepartmentId 混比，也不能用同定义的另一实例替代。只读投影遵守相同映射；关系失效时清理当前值和旧叠层，不回退到按名称/定义匹配。

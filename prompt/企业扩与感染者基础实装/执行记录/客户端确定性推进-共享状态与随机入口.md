## 连续随机与恢复的必要边界

新局seed只是起点，重新new Random(seed)不是恢复已经消费的序列。骰子、洗牌和企业准备的默认随机取值应读当前工作GameState中的RandomRuntime，用同一版本算法和明确流ID；事务失败不提交游标，成功把状态与规则结果一同提交。GameSetupRecipe新局组装的随机、开局顺序的随机也要登记或明确封存为不再消费的初始化流。EventDeckService/CardPoolService原显式seed/Random/next注入保留，正式路径只能使用已收到的局事实，不能从无参兼容构造偷回20260615。

每流状态应保存算法完整可序列化内部状态及游标（算法由根收口定版），不只保存调用次数。RandomRuntime不另存一份与EventDeckSeed冲突的种子；同局GameId/seed/算法不符拒绝。状态进入GameState的工作副本、存档和确认检查点，重连/重复START/重复初始包只采用已有状态，不重新Assemble、重排顺序或重洗牌库。老存档若没有可恢复的随机状态/完整确认重放依据，保留旧牌序/骰点/收据并明确确定性恢复缺口，不能偷偷生成新种子。

在上述状态文件未获写权前，不把CWT/Registry里不可序列化的Random当作已经完成恢复，也不先替换正式默认生成器造成旧存档重置。可先完成授权的熵取样入口/草稿；完整接线待根定界。正式新局使用随机seed后，两局碰巧相同也是合法随机结果，测试不要求它们绝对不同。洗牌不更换本局初始seed，只推进并保留随机状态；干员特派全部放回后即使牌数不变，也不能按seed＋牌数重新生成同一个过程。后继自然抽到同牌合法，不新增防重复重洗、排除上一组或保证两次牌序不同的规则。

## 旁路的唯一实际分类（只读设计）

用户最新限定优先：Lua声明可省略，旧返回effects列表保持兼容，缺省RequiredChild。DeferredPlayerResponse只是允许旁路，实际分类仍由共享调度依据真实主操作窗口作一次决定。

建议唯一分类入口DetermineResponseDependency(requestedKind, respondingPlayerId, sourceWindowContext)，以下均为后继接口草案，当前不改Kernel/Lua解析器：

```text
requestedKind缺省或不是DeferredPlayerResponse -> RequiredChild
真实源主操作窗口缺失、尚不能确定mainWindowPlayerId或响应玩家 -> RequiredChild
respondingPlayerId == sourceWindowContext.mainWindowPlayerId -> RequiredChild
其余明确不同且已声明允许 -> DeferredPlayerResponse
```

mainWindowPlayerId必须来自触发该响应的真实操作窗口归属/已验证操作上下文；多人共享窗口的某次操作仍须记录真实操作者，不能用CurrentPlayerId、Host、本地UI玩家、EventType或猜测卡牌主人补它。回应玩家来自实际响应请求/角色owner及正式授权规则，声明本身不能伪造回答权。缺少足够事实一律RequiredChild，不能因“正在等待”就降级。

分类结果随对应子任务保存并由各端同一事实消费，不在UI路由、恢复或每次调度各自重新猜测。RequiredChild继续原自动挂链/阻塞/完成屏障：多萝西本人移除本人影响力时，必须等待本人收留/拒绝并结清，随后Effect才可继续；EndAction不能跳过。DeferredPlayerResponse只让不依赖该回答的另一主窗口继续，仍保存并结清真实待办，不等于可放弃/漏结/超时默认拒绝。普通Event仍自动挂链，不把全部Event改成手动、可选或非阻塞。准确离场实例保留/牌离场/最终依赖围栏以规则owner已审方案为准。

### 统一边界与真实命令

费用必须由Host从实际执行节点/正式定义计算并克隆，客户端只传稳定身份和选项，不传可写费用、标记列表或正文。唯一`PaymentId = OwnerEffectId = 实际付款节点EffectId`；最多2个本人标记只替代Originium/OriginiumShard/Iron，不能替代GoldVoucher/PureOriginium。预览不扣款，冻结草稿不扣款，点击来源只挂真实正文；最终提交即时复核真实载区/本人标记/余款，在同一工作副本移动标记、TryPay余款并置IsCommitted，然后处理空载体离场。来源未点击时SelectedSubstitution为空，必须付完整原费，不因CanPayWithStoredMarkers预览结果自动替代。

当前可直接消费的正式入口是`GameCommandKind.PreparePaymentDraft`，由已存在`Application/Interactions/PreparePaymentDraftCommandHandler.cs`调用`EffectTreeExecutor.TryPreparePaymentDraft`。命令携带PlayerId/CommandId；Parameters为`ownerEffectId`、`interactionId`、`candidateId`、`expectedRevision`（十进制数字字符串）。**此入口当前只接受effect.resource.payment_choice的原open请求**；不能把普通Pay、建设或父Condition ID塞进该命令并声称已有通用Host入口。

真实请求投影`PromptParameters.paymentOptions[] = { candidateId:string, cost:{ originium:int, originiumShard:int, iron:int, pureOriginium:int, goldVoucher:int } }`，只与原CandidateIds相交。candidateId对UI是不透明ID，禁止拆解`pay|...`反推费用。Host复验当前revision/本人/真实open请求/原候选/活动嵌套范围，在工作副本用TryInitializeSelectedPayment冻结唯一费用，再用TryOpenPaymentWindow绑定同一既有请求并RefreshSettlementOffers；该命令不回答请求、不推进付款、不新增确认。

界面必须经GameSession/正式网络命令入口提交，随后取得新frame：GameSession在提交后RebaseOpenInteractionRevisions；原请求ID即使没变，revision也要从新frame读。Domain内核答案同时检查Runtime.StateRevision与请求StateRevision，不能直接准备后沿用旧投影，也不能为此放松版本校验。重复选择同费用可复核；冻结后改选另一费用返回payment_cost_changed，当前没有可任意换费用的重置接口，UI不得悄悄覆盖PaymentCost或新建PaymentId。

真实底栏点击走既有`GameCommandKind.InvokeSettlementOption`，参数`optionId/useId/expectedRevision`，付款useId为空；来源取最新授权投影，Host核option所属窗口是否仍为ActiveSettlementWindowId并即时复核资格。点击受理后原费用请求invalidated并保存SuspendedInteractionId/ResumeFlowStage，再挂真实PaymentSubstitution段；不是先回答费用请求再事后补Offer。

最终只走既有`GameCommandKind.AnswerInteraction`，参数`interactionId/expectedRevision/answerValue`，取当前open请求身份和当前frame revision。未点击来源时answerValue为原费用candidateId；点击来源后当前请求schema为bounded_resource_allocation，按其rowIds/rowMaximums/maxAmount及QuantityRows构建数量，answerValue沿既有分配编码（如`Originium=1,Iron=1`）。分配最终回答设置IsCommitRequested，父付款立即沿同一工作副本原子提交；成功不恢复原费用确认，不再问一次是否付款。

停止/取消消费原EndAction投影和当前节点原停止许可；不能由整段Optional扩大许可。已点击来源后允许取消时，CancelDraft仅清替代草稿和提交意图、不扣款；Host恢复原FlowStage与原费用页面的新请求身份/revision，保留同PaymentId和已受理的来源次数收据。数量为0是一次有效最终确认、付完整原费；取消是返回原页继续待决，二者不同。嵌套付款结束后ActiveSettlementWindowId由Host回到真实祖先窗口，UI不自行选择历史window或重开段正文。

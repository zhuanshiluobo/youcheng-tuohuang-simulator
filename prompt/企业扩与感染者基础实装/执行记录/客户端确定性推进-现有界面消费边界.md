# 客户端确定性推进：现有界面消费边界

2026-10-11，界面集成负责人只读核查。依据[最新合同第一节第3项、第三节及第四节](G:/NoMadCity/prompt/企业扩与感染者基础实装/客户端确定性推进-操作窗口与随机数迁移合同.md)，本轮只写此报告；没有修改生产源码、预制体或场景，没有运行测试、构建、Unity、Player或自动点击，也没有重跑此前43项稳定检查。`GameSessionBootstrapper.cs` 的每局种子入口归共享负责人，本人未写该文件。此次修订更新界面消费约束，没有重新核验内核旁路实现或执行新流程。

## 核查结论

当前代码已把多萝西的 `store/decline` 请求接入原通用选择弹窗：`lua.choice` 经角色能力控制器进入 `ShowCandidateOptions`，选一项后由原确认入口提交。收留选择已有显示路径，不需要新建页面或说明区域。这里指原 `EffectDialogShell` 的选项弹窗；快速行动“使用角色牌”打开的卡面页是 `CardViewer`，它的两个能力按钮不是本次收留选择的入口。不同玩家各自在本机回答自己的请求，现有请求过滤可继续复用。

目前仍不能宣称“多萝西待答时另一玩家主窗口继续”已经成立。现有请求路由、HUD和结算条各自只绑定一个当前请求或窗口；行动面板又把全局 `HasPendingChoice()` 当作普通行动阻塞条件。如果新客户端直接把完整模拟态送入该判断，另一玩家的多萝西开放请求会使本机主行动禁用，即使该请求已经从本机选择列表中过滤掉。必须先有统一的主窗口、旁路任务及动作资格语义，再接相应消费，不能只隐藏弹窗或解除旧 pending 锁。

本结论来自静态入口核查，没有执行多进程旁路流程或验证实际画面。最新决定只允许有条件的异人旁路；同人响应正常阻塞。离场实例保留、旁路回答最迟时点、来源牌离场和依赖窗口的规则由规则负责人收口。

## 最新分类与界面消费约束

Lua的响应调度声明可以省略，缺省为 `RequiredChild`。声明 `DeferredPlayerResponse` 只表示允许内核评估旁路；真实 `respondingPlayerId` 与当前真实单人主操作窗口的 `mainWindowPlayerId` 明确不同，才满足异人条件。界面消费内核最终分类及操作资格，不根据卡牌名称、Lua声明、EventType、Host身份、LocalPlayerId或旧UI `CurrentPlayerId` 自行分类。下表是消费要求，不代表这些新接口已经实现。

| 内核实际分类或身份条件 | 原选择弹窗 | 主流程推进及待办 |
| --- | --- | --- |
| 未声明旁路，或内核分类为 `RequiredChild` | 按正常顺序显示本人选择 | 保留原完成依赖；回答并结清后才推进后继，不因这是多萝西请求而放行。 |
| 已声明允许旁路，但回答者与真实主窗口玩家相同 | 当场显示并等待本人收留或拒绝 | 仍为 `RequiredChild`；不加入旁路待办，不允许“等待”、折叠或 `EndAction` 跳过选择或提前执行下一Effect。真实离场实例去向结清后才继续。 |
| 已声明允许旁路，身份明确不同，且内核实际分类为旁路 | 多萝西玩家继续使用原选择弹窗回答 | 仅按内核资格放行另一玩家不依赖该回答的主操作；保留响应、原实例及统一命令身份。旁路任务仍须回答，不能自动放弃、拒绝或被主窗口结束清除。 |
| 主窗口或身份不明确，或多人窗口规则尚未收口 | 消费内核给出的正常完成依赖 | 不猜测旁路、不自行新增待办分类或放行行为；多人窗口判定由共享/协议收口。 |

普通Event保持自动挂链。收留和拒绝都是明确提交的答案；页面隐藏、主操作等待或窗口结束都不是答案。原折叠功能只改变显示，同人请求的完成依赖保持。后继不增加等待、跳过或额外关闭按钮，不修改资产。

跨进程的目标分两支：同人按原顺序回答并结清，再执行后继；只有内核认定为异人旁路时，多萝西所属玩家在原选择弹窗回答，另一玩家继续其不依赖该回答的主窗口操作。共享调度与动作资格决定后者是否可继续；本机请求过滤不决定规则阻塞范围。

## 后继最少验证与交付边界

接口收口并取得准确写权后，将 UI 验证合成少量实际消费场景即可：

1. 合并必要分类分支：未声明保持 `RequiredChild`；已声明但A本人主操作触发A的收留时仍立即等待，选择并结清真实实例后才执行下一Effect，等待、折叠及 `EndAction` 均不能绕过。声明允许且内核确认A、B身份不同的旁路时，A保留原选择及离场实例，B仅继续不依赖回答的操作；A候选只在A界面展示。
2. B继续操作后A回答：使用统一序号及当前合法任务身份提交，原选中候选与文档不串节点；重复、错 owner、旧版本不能重复回答或误清新任务。界面不得按卡名、脚本声明、Host、本机身份或旧 `CurrentPlayerId` 改写内核实际分类。
3. 主窗口结束、页面折叠/恢复与后继窗口到来：只关闭对应展示；同人保留正常完成依赖，实际异人旁路保留任务，是否必须等待、是否仍可回答以已收口规则为准。没有回答不能算拒绝或放弃。确认状态与画面必须分列。

本轮没有执行以上场景，也不以旧Player、单个主机结果或选择页可显示作为新架构验证。已交地图/锡人[稳定回执](G:/NoMadCity/Logs/SettlementUi/地图与正式购买正文-20261011/稳定交付回执.json)继续供下一次必要构建；源码、资产和提交链保持。卡候选说明遵守“有则用、无则不加”，此前已确认有卡图分支没有说明栏，当前不展示附加说明；不挪缺图 fallback 或页面 Prompt，不缩图、不改容量、不加快捷键或额外弹窗。科室旧问题独立保留。

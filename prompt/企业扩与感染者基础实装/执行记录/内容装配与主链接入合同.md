## 装配入口与唯一写入者

房间与本地入口冻结 `GameRuleConfiguration`，调用 `ActiveContentCatalogBuilder.Build(installedPack, configuration)`，把返回的 `ContentPackHash` 写入该份配置，再调用 `catalog.Register(registry)` 和 `GameLaunchStateFactory.CreateInitialState(..., configuration, seed, catalog.SetupRecipe, catalog.ContentDefinitions)`。`MapId` 原样保留；事件池、特派数量和变体补偿使用真实 `PlayerCount`。不得把安装包哈希用作局内握手指纹，也不得修改磁盘 `enabledExpansionIds`。

| 数据 | 唯一创建或提交入口 | 恢复行为 |
| --- | --- | --- |
| 有效定义与脚本 | ActiveContentCatalogBuilder；安装目录保持独立 | registry、Host 档和启动配置必须使用同一指纹 |
| 实例、初始牌序、样式抽取、供应槽 | GameSetupRecipe.Assemble，仅 Host 调用 | 恢复读取 ItemZones，不再次 Assemble |
| 企业候选、三人补板、科室 | ExpansionSetupFlow.PreparationSpec | 候选、未抽集合、补板和选中主体保存在 ContinuationData |
| 入场城市、资源点、补偿 | PlayerEntrance 与首回合 RoundStarted 子树 | 真实实例及已提交子节点保存，恢复不重领奖 |
| 初始基础角色保留 | ExpansionSetupFlow.RetentionSpec | 固定初始集合，选择保留 5；其他牌整组移入 secret_retired |
| 红区回合升级、两人裁供应 | RoundStarted → RoundPreparationSpec | 按玩家顺序逐子树完成，再推进盖牌；已完成子树不重执行 |
| 回合推进与终局 | 既有 RoundExecutionService | 无新增平行回合驱动；两个行动轮、采集、收尾和第八回合终局沿用同一链 |
| 未使用盖牌回收 | round.player.recycle_characters → CharacterLifecycleService.Recycle | 明确指定 covered/discard 范围；持续区不参加回收 |

## 内容登记与串行合入

内容作者沿用 07 的 DefinitionId、RuntimeId、abilities、levels、cardZones、条件配方和 replaces 字段，在对应登记清单写全实际 JSON/Lua/素材及来源。正式企业 pack 由企业内容验收任务串行登记；感染者配方和能力由感染者装配任务提供。提交后先 Build，再 Register，再真实开局测试；测试定义只存在内存夹具，不进入 StreamingAssets。

本局的状态型 Database.Get/TryGet 接口优先读取冻结 ContentDefinitions，旧无状态重载仅用于兼容旧非实体入口。客户状态投影保留本地同指纹目录供动态显示；Host 原始配方、定义快照、秘密候选与续段不进入网络视图。界面源场景/预制体继续由对应 UI 任务维护，本合同不授权重建或保存覆盖。

现有基础角色面板已使用冻结定义解析可见 ItemId，按唯一主链的实际盖牌顺序启用当前玩家入口。CardVisualCatalog 的运行时实例解析器只在内存绑定到当前可见会话；Host 和 Client 用同一 DefinitionId 读取基础原卡面，既有资产保持原样。企业、多槽持续角色和感染者专用界面仍由后继 UI 任务接续。

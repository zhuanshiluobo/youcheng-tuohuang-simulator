## 布局所有权与性能边界

| 对象 | 尺寸/位置拥有者 |
| --- | --- |
| Viewport 宽度 | Prefab 的 stretch 和右侧 20 宽通道。 |
| Content 宽度 / 高度 | 横向锚点 / 仅纵向 PreferredSize 的 ContentSizeFitter；主体布局只报告 preferredHeight。ScrollRect 负责滚动位置。 |
| MemberList 尺寸与位置 | RoomBodyResponsiveLayout。 |
| SettingsPanel | 主体布局只设置位置；宽高、scale 由原 Prefab 保持。 |
| 成员 Header、Seat List 与四座根 | 两层原生 VerticalLayoutGroup；成员 Frame 忽略纵向布局并 stretch。 |
| 座位框、标题、动态文字、按钮 | RoomSeatResponsiveLayout 在标准 ILayout 顺序中先排宽、再测高、再排纵向。头像只移动位置，136×136 尺寸保持。 |

布局尺寸优先于座位装饰 Image 的图片原始尺寸。新代码没有 Update/LateUpdate/FixedUpdate、强制同步布局重建或场景查找；Render 结束后只比较已绑定四座的文字及可见状态，变化时提交标准布局脏标记。请求 pending 仅改变按钮可交互性时，不额外请求房间布局更新。所有布局参数及引用序列化在 Prefab，未给静态文字重新赋固定文案。

已有 View 的 Escape 输入 Update、房间事件/权限、热座逻辑和性能标记未改动。本轮没有改动其他任务负责的联机服务或性能缓存。

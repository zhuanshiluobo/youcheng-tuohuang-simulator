## 显式联机生命周期

命名空间均为 `YC.Application.Sessions`。

```csharp
// DeterministicSimulationCoordinator
bool IsBackgroundExecutionEnabled { get; }
void StartBackgroundExecution();
int DrainMainThreadNotifications(int maximumCount);
bool TryReadPublishedSnapshot(out SimulationPublishedSnapshot snapshot);
void RequestStop();
Task ExecutionStopped { get; }
Exception BackgroundExecutionException { get; }
Task<SimulationRecoveryCheckpointDto> CreateSaveCheckpointAsync();
Task<SimulationRecoveryCheckpointDto> CreateConfirmedRecoveryCheckpointAsync(long expectedConfirmedSequence, long targetEpoch);
```

只在正式 Host/Client 确定性联机入口、registry/内容/handler 装配完成后明确 `StartBackgroundExecution()`。允许先创建协调器再启动；`Begin()` 在后台模式只入队。Local/Sequential 不调用 Start，仍原样同步 `GameSession.Submit`、`Begin/Pump`。初始化未发表固定版本时 TryRead 返回 false，不读取活动会话兜底。

Mirror 主线程继续调用既有 TryCreateLocalProposal、AdmitProposal、ReceiveOrdered/Boundary/Ready/Permit/Validation/ProposalResult、ReadMissingRange；后台模式协议输入入有界队列，AdmitProposal 使用稳定许可及唯一 sequencer 快速编号，不等待 Submit。`Pump()` 的主线程调用只消费通知，不再执行规则；推荐 Update 明确调用 Drain（maximumCount 是发布帧数量）。

所有既有 Applied/Validation/Permission/Fault/Ordered/Boundary/Ready/Permit/Missing 事件在主线程交付。每份 Applied 对应的固定 UI 状态及视图先安装，再交该原 CommandId 的结果；不能以 Validation 再次 settle。通知队列不合并 Applied，输出满时只让 worker 等待，主线程不 Join/Wait。RequestStop 立即停接纳、撤该代次通知，ExecutionStopped 只表示旧 owner 安全退出，不表示规则成功。

后台模式公开 LastAppliedSequence、ValidatedThroughSequence、ReadLocalValidationPrefix、ReadBoundary 与已 Drain 的可见帧一致，避免初始 Ready 或旧 Applied 消费看到工作线程的未来结果而跳过原回执。Host 快速 Admit 单独读取工作线程原子发布的最新稳定许可，不读取活动 State/replica Submit 锁。LastSequencedSequence 仍是主线程唯一编序账本的当前尾号。Drain/TryRead 与协议门面须在启动该循环的主线程调用；RequestStop/ExecutionStopped 可供异步安全退出。

调用一次 TryRead 后用同一 snapshot 读完整视图、身份、序号及窗口事实。公开 DTO/列表连嵌套内容均防御复制；改 ReadView 返回对象不影响捕获或 worker。不要把不同次读取的字段拼成一个版本。

网络模式中 GameSession 的主线程展示端口只接收 worker 提前复制的独立 UI 状态图，不与活动 State 别名；不能从 UI 调用 Submit/ReplaceState/RefreshLocalProjection/EnableConfirmedRecoveryCapture。C 应优先直接消费 snapshot.ReadView，保其它 partial 的同版只读适配。活动 registry、Lua 和 Current 重配置仅 worker/启动阶段所有，UI 使用纯发布值或私有展示实例。默认 Local 的 State/View/StateCommitted 行为不变。

## 保存与正式恢复

```csharp
// MatchSaveData：header 仅现有Mode/Seats/身份元数据，先防御复制
static Task<MatchSaveData> CreateFromPublishedSnapshotAsync(MatchSaveData header, SimulationPublishedSnapshot snapshot);
// SimulationConfirmedRecoveryInstaller
Task<PreparedSimulationRecovery> PrepareAsync(SimulationRecoveryNoticeDto expected,
    string bundleJson, DeterministicSimulationCoordinator previousCoordinator);
```

已发表 snapshot 的固定捕获/随机状态/continuation 不依赖活动 State 或会话三点保留窗口。Create…CheckpointAsync/保存工厂只从该点后台生成原 checkpoint/JSON/Validate；禁止 Task.Run 读 session.State。工厂入口只复制头部身份及席位，忽略旧 ArchiveJson/ContinuationJson/SimulationCheckpointJson，重对象均重新由固定点生成。网络同步 TryCreate…Checkpoint 原方法不能用来在运输 Update 里生成重对象，使用以上异步口。自动保存合并与顺序落盘归 C；手动/离开仍等待真实保存结果，不把未确认尾段标确认。

恢复先通过 PrepareAsync 请求旧协调器停止并异步等待安全点，再后台校验/准备；主线程在原协议 Commit 阶段 TryCommit。新协调器接回后显式 StartBackgroundExecution，再 CompleteConfirmedRecovery；不复用初始安装器覆盖运行态。只保留真实 baseline/原日志及旧 pending/版本/hash 门禁。

恢复预检同时覆盖“已绑定但执行线程尚未 Claim”的启动空隙；未安全退出时同步 TryPrepare/TryCommit 返回 recovery_execution_not_quiescent。正常恢复等原已接受尾段完成；真实停止/业务故障仍可从保留的准确确认点准备，不将未执行尾段伪造为成功。后台准备预建私有日志，网络 Commit 只换根；Local 原同步日志重建路径保持。

终局仍先保留同局已确认 snapshot/检查点句柄，后续关闭协调器也能后台准备正式保存。旧终局缓存补丁与真实失败/重试不能撤回；保存 DTO 与协议版本不改。

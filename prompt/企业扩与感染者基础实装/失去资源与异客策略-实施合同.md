## 最小Effect接口

新增唯一公开构造器`Effect.LoseResource`，唯一typeId=`effect.resource.lose`，注册为`Atomic`，初版`DefinitionVersion="1.0.0"`。建议独立类型`ResourceLossEffectExecutor`，接入现有注册根，不复制资源账本。

Lua固定调用：

```lua
Effect.LoseResource({
    apiVersion = 1,
    player = ctx.playerId,
    targetPlayer = targetPlayer,
    resourceType = resourceType,
    amount = selectedAmount
})
```

`player`为执行者，`targetPlayer`为实际失去资源的玩家，不切换节点执行者或让目标代答。使用既有稳定玩家引用与资源归一化。`amount`为非负整数，拒绝负数、小数、越界与非法引用；上界同时受既有`NormalizedValue.MaxInteger`约束（当前1,000,000,000），不扩大通用规范值范围，也不能把int.MaxValue当合法接口输入。资源类型沿项目已注册资源集合，不能将此通用接口限制成异客专用三资源。

沿用户前文“不要求有充足资源”的语义：实际失去量为`min(amount, 当前可扣余额)`，最低0，余额不能变负；0请求或0余额正常完成。金券须使用现有可用/预留语义，不侵犯已经托管的路费；若现有资源层无法安全表达，定向报告接口接缝，不能直接覆盖托管账。返回可持久化规范结果`changed, requestedAmount, amount, targetPlayer, resourceType`，其中`amount`为实际失去量。结果字段用于后继获得量，不把请求量当实际发生量。

它不是支付：不创建PaymentId、不检查足额、不打开付款/替代窗口、不消费异客牌上标记，也不增加接收者余额。扣减由该原子节点唯一执行；GainResource另为后继节点。沿既有Effect提交、事件、序号和恢复机制防重放，不能以UI直接写余额或增加平行收据。

## 异客策略的五步及后继得分

1. 本人选择真实对手（排除本人），沿已有玩家选择页面；两人局也保留本次用户明确的选择步骤。
2. 本人选择源岩/源石碎片/异铁，沿既有资源选择页面，不能连玩家与资源合成一个选项。
3. 本人选择整数数量`0…min(4,目标所选资源当前余额)`，沿既有`effect.quantity.choose`、`bounded_amount`、空CandidateIds和`answerValue`协议及数量页面，不伪造0/1/2/3/4的普通选项列表。保持既有允许0的规则；范围失效须拒绝/刷新准确请求，不能悄悄截断用户答案。
4. 全部选择完成后执行LoseResource；三步UI前不扣资源、不发奖励。选择阶段无新确认页/新布局/新按钮。
5. 只在失去节点正常完成后，按其实际失去量执行本人GainResource，0量按现有Gain参数合同处理，不伪造正数奖励。
6. 保留原卡面双方各得1分，0数量不擅自取消得分；得分各一次，不因续接重复。

阶段数据必须在现有规范参数/结果/ContinuationData内持久保存，用当前内容版本和真实Effect关联，不能用Lua闭包、全局变量、UI草稿或隐式最近选择保存规则进度。规则组合由Lua定义；不把角色ID/异客专属转移流程硬编码进通用最小Effect。

若当前Choice缺少数量输出/选择间上下文能力，规则owner先提交准确的最小通用增量schema与恢复语义，由根核定技术接口后实施该增量；复用`Effect.Choice`及已有bounded_amount UI协议，不新增名为Transfer的替代大Effect，不新增卡牌专用公开API。此技术接缝不要求用户重复作UI决定。

## 已核定通用选择与续接增量

根核`失去资源与异客策略-接口接缝方案.md`后批准以下技术范围，仍只复用既有页面。规则新增唯一写权：`G:\NoMadCity\Assets\YC\Domain\Effects\GenericLuaEffectExecutor.cs`、`G:\NoMadCity\Assets\YC\Infrastructure\Lua\LuaRuntimeContracts.cs`。

- `Effect.Choice`增加可选`resultContext`，纯规范对象、遵守现有数据类型/大小/深度限制，无函数/闭包/效果对象；不作为授权凭据。未提供时原字符串/数组结果不变，提供时结果`{value=原选择结果,context=resultContext}`。
- 数量模式由可选`amountRange={minAmount,maxAmount,sourcePlayer?,resourceType?}`开启，与options/branches/minSelections/maxSelections互斥。上下限非负整数且min≤max；sourcePlayer/resourceType同有同无。有库存约束时有效上限=min(maxAmount,当前可用余额)，异客必须提供。无库存约束时仅使用静态上限。金券不侵占预留。小于最小值则无合法数量，异客min=0因此0…0合法。
- 数量只生成既有`effect.quantity.choose/bounded_amount`请求，空CandidateIds和answerValue；PromptParameters保留minAmount/maxAmount/amountKind，并给一致的单行rowIds/rowMaximums用于现有资源图文绑定。该节点不扣资源。返回整数，带resultContext时按上述包装。过期范围先拒绝/刷新，不静默截断；参数、FlowStage=`awaiting_amount`及结果用既有字段持久化。
- Choice与LoseResource允许可选`completionHandlerId`元数据，Host提取到`LuaEffectSpec.CompletionHandlerId`，Compiler写入现有EffectSpec完成绑定，不进入Loss业务参数。仅显式顶层节点可用，初次必须匹配该能力声明的完成handler，续接必须匹配正在执行的同内容continuation handler；拒绝跨内容/能力、未声明/任意handler及未支持的嵌套绑定。未提供时完全保留现有默认，其他角色不得被递归绑定。
- 正式异客handler改为`content.operator.passenger.strategy.step_completed`并更新策略版本。依次通过Choice的context.stage区分target/resource/amount，阶段目标/资源为已验稳定引用；数量结束才创建Loss。Loss完成回调按actual amount创建Gain（0跳过非法Gain(0)）及两份GainScore；这些奖励不再绑定完成handler。

本轮固定新增定义ID、文件位置和schema；尚未创建这些运行文件。用户批准的卡面规则不因接口定名改变。读取依据为：

- `G:\NoMadCity\Assets\StreamingAssets\Content\core\pack.json`、`facility_inventory.json`、`artwork_slices.json`：当前正式入口。
- `G:\NoMadCity\Assets\StreamingAssets\Content\core\character\texas.json`及`lua\characters\texas.tactic.lua`：角色返回函数及Condition写法。
- `G:\NoMadCity\Assets\StreamingAssets\Content\core\city_style\city_style_military_industrial_area.json`：现有图案/轨道/特殊行动数据字段。
- `G:\NoMadCity\Assets\YC\Domain\Facilities\FacilityCardDefinition.cs`、`G:\NoMadCity\Assets\YC\Domain\CityStyles\CityStyleDefinition.cs`：现有费用、颜色、图案及分数序列化依据；不得自创另一套同义字段。
- `G:\NoMadCity\游城拓荒\企业扩\卡面效果与Effect式.md`和`素材清单.md`（同目录）；`G:\NoMadCity\游城拓荒\感染者扩\卡面效果与Effect式.md`和`素材清单.md`（同目录）：逐卡数据唯一来源。

## 装配与目录

本组继续使用一个已安装内容根`G:\NoMadCity\Assets\StreamingAssets\Content\core\`，扩展归属由每个definition.expansionId表达；不擅自新建第二套全局加载器。packId保留core，正式manifest schemaVersion升3，兼容只读schema2。enabledExpansionIds保留基础默认`["core"]`；房间当前启用集合传给ActiveContentCatalogBuilder，**不能为开一局企业游戏而改磁盘pack.json**。

新增`ActiveContentCatalogBuilder.Build(ExternalContentPack installedPack, GameRuleConfiguration configuration)`，返回本局隔离的`ActiveContentCatalog`。后者固定`Definitions/Scripts/ContentPackHash/EnabledExpansionIds/RuleModeId`只读成员；实例配方、类型/操作域注册和replaces先校验再发布。外部定义缓存可复用不可变对象，本局活动集合不能使用一个全局可变Current覆盖另一场对局。

schema3新增manifest键：`requiredCapabilities`（string数组）、`expansionDependencies`（对象数组，每项expansionId及requires数组）、`setupRecipes`（配方相对文件路径数组）。能力ID固定`item_zones.v1/item_transfer.v1/deck_shuffle.v1/enterprise_rules.v1/character_lifecycle.v1/infected_rules.v1`；已声明但未全链实现则不开放组合。依赖固定enterprise→core，infected→enterprise；模式standard不增加组件，entrepreneur本轮不支持。

能力检查必须按本局启用集裁剪，不能因磁盘安装了未完成感染者内容就阻止基础或企业局。manifest顶层requiredCapabilities只列所有组合共同需要的底座；expansionDependencies每项另允许`requiredCapabilities`字段，规范片段为：

```json
{
  "requiredCapabilities": ["item_zones.v1", "item_transfer.v1", "deck_shuffle.v1", "character_lifecycle.v1"],
  "expansionDependencies": [
    {"expansionId":"enterprise", "requires":["core"], "requiredCapabilities":["enterprise_rules.v1"]},
    {"expansionId":"infected", "requires":["enterprise"], "requiredCapabilities":["infected_rules.v1"]}
  ],
  "setupRecipes": ["recipes/standard.json", "recipes/enterprise.json", "recipes/infected.json"]
}
```

这是最终形状示例，013正式登记时只列已交付的企业定义与配方，018才追加感染者。装配先验证显式启用集合及依赖，再取这些扩展的能力并检查实际执行链；没有启用的内容不可进入本局实体配方。内容哈希与活动集合绑定，不能用“目录里有此Lua文件”代替能力可运行证明。

## 文件、ID与能力命名

下表每行是一个definitionId（实例数量另算）。新增定义JSON绝对路径统一为：

`G:\NoMadCity\Assets\StreamingAssets\Content\core\<contentType>\<definitionId>.json`

该表达式中的两个字段严格使用下表原值；禁止执行者翻译、缩写或加任务号。为避免自行拼错，下表同时给出相对文件；前置根固定。已有素材切片ID维持原值，不把切片ID、I19/E01来源编号当新定义名。I/E来源编号可以写在追溯元数据中。

Lua脚本路径规则固定：`lua/<category>/<definitionId>.<mode>.lua`；category映射character→characters、enterprise→enterprises、department→departments、facility→facilities、city_style→city_styles、event→events、award→awards、contract→contracts。component没有主动脚本。character必须strategy/tactic各1个；enterprise按level_1.special或level_3.reward等真实格；department按level_2.reward至level_5.reward；其他mode为entry/on_declared/special/cleanup/activate/resolve之一，依原卡实际时点选择，不能为了凑数全部创建空脚本。

能力ID固定`<definitionId>.<mode>`，subscriptionId固定`content.<definitionId>.<mode>`，如`operator.silverash.tactic`；不是EXP编号。script字段必须是上述实际相对路径，初始version为1.0.0。所有脚本`return function(ctx) ... return { Effect... } end`，只返回Spec，禁止读写Unity/文件/网络或保存跨调用Lua全局状态。

## JSON字段合同

所有定义沿现有envelope：`definitionId/contentType/version/displayName/expansionId/replaces/artwork/artworkSpriteId/tags/playerMarkerZones/abilities/data`。schema3新增可选`itemTypeId/cardZones`，原playerMarkerZones只作旧schema适配，不能两种字段同时声明同一载体区。

- `abilities[]`沿现有ExternalAbilityDefinition键：abilityId、mode、skillType、subscriptionId、script、version、completionHandlerId、cleanupScript、hasSpecialZone、specialZoneId。skillType固定normal/persistent/one_shot，与现有ExternalContentPack校验值一致，不按UI文本判断。角色每模式分别配置。
- 企业`data`新增`levels[]`，每项固定`level`(0—5)、`kind`(empty/reward/special/department_reward)、`abilityId`(空格为空串)。等级完整且不能重复；奖励与特效不同时占一格。莱茵科室奖励由departmentRewardPolicy引用，不在企业板重复抄三套。
- 科室`data`新增`enterpriseRuntimeId="enterprise.rhine_lab"`及`rewards[]`，每项level/abilityId，level2—5完整；不补1级奖励。
- 角色`data.templateId/cardId/name`由loader按RuntimeId及displayName统一；新增`acquisitionRole`固定initial/operator_deck/generated，`instanceTypeId`引用05类型。不能使用“注册了就发初始牌”的旧目录循环。
- 设施/样式/事件的原字段名按上列现有Domain类型及现有JSON使用；费用不得另造costText或用显示字符串解析。企业三色设施每色独立定义，临时聚居点一个定义生成3实例；唯一组新增`data.uniqueGroupId`，三个罗德岛办事处同组`infected.facility.rhodes_office`，临时聚居点组为其definitionId。
- 样式图案固定复用`declarationRequirement.requiredPatternCells`中的rowOffset/columnOffset/allowedFacilityColors；原规格(x,y)转columnOffset=x、rowOffset=y。不要写第二套patternXY再让UI猜方向。
- 奖励/合约`data`固定`instanceTypeId/acquisitionRole="reward_pool"/lifecycle`，lifecycle为held_quick_action/immediate_retired/persistent/contract；具体效果仍用abilities。component固定`data.instanceTypeId/quantityPolicy`，finite数量来自配方，infinite只允许已注册公路能力。

替换声明必须精确：

```json
{"expansionId":"enterprise","contentType":"enterprise","definitionId":"enterprise.rhodes_island"}
```

这是感染者罗德岛的replaces对象，RuntimeId仍`enterprise.rhodes_island`；其definitionId为`infected.enterprise.rhodes_island`。企业事件replaces分别是`{expansionId:"core",contentType:"event",definitionId:"event_red_03"}`对应采集平台、`event_yellow_02`对应洞穴，不能反过来。旧定义退出活动集但保留安装源。

## 配方与目录交付

新增配方文件绝对目录`G:\NoMadCity\Assets\StreamingAssets\Content\core\recipes\`，文件固定`standard.json/enterprise.json/infected.json`。每entry固定`entryId/definitionId/quantity/perPlayer/initialZoneRole/condition`；entryId是业务键如initial_amiya/operator_silverash，不能任务号。quantity非负int，perPlayer bool；condition只接受已注册`always/enterprise_selected/ability_granted`，附对应runtimeId/abilityId，禁止执行JSON中任意脚本表达式。

standard仍基础5手牌；enterprise每人加2后裁2；infected每人加阿米娅后从8裁2留6。干员共享16与流形3不依赖罗德岛入选；公司/合约/授勋按相应企业准备，未创建组件不虚构入盒，已创建但本局未选使用的组件移盒储备。

内容任务提交登记清单，每行必须填完整JSON/Lua/素材路径、definitionId/runtimeId、来源章节/图号、实例配方、所需API版本和验证结果。不得把未完整脚本写入可启用正式manifest。正式pack/素材清单由013（企业）和018（感染者）串行登记；在此之前用显式列举真实定义的测试装配验证，禁止用空占位让能力门禁放行。

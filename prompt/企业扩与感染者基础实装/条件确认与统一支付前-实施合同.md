## 一、最终行为

1. 规则正文的条件式在左侧开始前可选择执行或放弃；放弃不执行左侧和右侧，已完成的其他节点不回滚。内部成功门控、来源消费门控不因此获得额外拒绝权。原本免费且无左侧规则条件的效果直接挂正文，不保留空 Condition 来制造确认；减免后费用为零与原本没有条件不是一回事。
2. 同一笔非分数混合资源费用沿现有 `Effect.PayResource({player, cost=...})`/`effect.resource.pay` 表达一次，沿 `ResourcePaymentRuntimeState.PaymentId` 管理完整费用和本笔总替代预算。分数、移除影响力及多笔独立交易不合并。锡人两次购买仍两笔，警备队辖区两次替换仍两笔。
3. 新增统一真实规则事件 `BeforeResourcePayment`，沿现有 EffectRegistry、EffectEventRequest、DispatchReceipt 分发。发布者为已确定同笔费用的付款准备/执行上下文，不是 UI 更新或纯报价查询。条件确认本身不另发一个“条件确认 Event”。普通事件自动响应，异客计谋可选来源的正文仍由玩家点击才挂链。
4. 支付前事件、原价、替代计划、剩余费用、来源和最终提交必须对应同一笔付款。替代分配页确认只保存 `SelectedSubstitution`，不得设置最终扣款意图；恢复原付款宿主后，用户原确认操作才令 `IsCommitRequested=true`。最终校验和扣款仅一次，重复命令/回执不得重复消耗资源或标记。
5. 原价不足不能屏蔽合法替代入口。例如整笔 2源岩/2碎片/3异铁、本人持有 2/2/2，替代1异铁后原支付按钮应可用；确认之前余额、来源标记和主要行动次数不变。仍坚持剩余费用足额；不以 LoseResource 代替 Pay。

## 二、准备费用的职责与预选边界修订

“准备费用”是同笔付款的内部生命周期，不新增游戏阶段、不新增公共最小 Effect，不增加用户必须理解的新流程名。

- 正式内容/业务定义给出完整原价、实际实例和来源约束；UI 不提供可信金额。
- 领域付款服务维护付款身份、原价、替代草稿、剩余费用和可支付性；只读报价没有事件或写入副作用。
- 内核在真实付款准备被正式接受后调度一次支付前事件及必要响应，保持等待/恢复/取消/提交一致。
- UI 显示当前投影、收集选择，沿正式命令和准确 Applied/Rejected 回执更新，不每帧运行 Lua 或重做全规则校验。

为满足用户明确要求“确认前出现真实支付前事件和异客入口”，**建设及主要行动城市移动允许建立可取消的规则端付款准备上下文**。本条准确替换《主要行动预选择与逐牌快捷入口-实施合同》中城市移动在该区间“绝无权威操作、Effect、InteractionRequest或费用上下文”的旧约束；保留其实际用户行为：主要行动本体在原最终确认成功受理后才挂链，确认前不扣款、不取牌/补牌/迁城、不消耗行动，不阻塞改选其他合法主要/快速行动。不能先挂整条主行动、隐藏其选择节点来冒充准备。

准备关联当前真实操作窗口和付款身份。切换行动、取消、换设施或导致报价变化的改选，正式撤销旧准备/旧替代草稿和来源入口；保持已提交的其他结果。不是静默重签旧选择。旧请求/旧代次/旧 PaymentId 不能作用于新准备。来源可见时不可因原价不可付而漏掉入口。准备命令准确回执期间保防重复提交，不能把准备等待等同已挂必结主行动而永久锁死切换。

当前新增支付前处理只负责同笔准备和正式可选来源，不借取消去回滚任意已执行规则。如果发现已有必结响应会产生不可撤销业务结果并与预选可取消相冲突，记录准确来源和时序给协调者解决，不能自行增加整段回滚规则。

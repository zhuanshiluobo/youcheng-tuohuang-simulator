# Room UI v1.1接入合同

源：[Guide](../../游城拓荒/UI素材/Room-UI-v1.1-VerticalMaps-Guide.md)、[ZIP](../../游城拓荒/UI素材/Room-UI-v1.1-VerticalMaps.zip)。由EXP-004负责权威配置，EXP-005负责房间资产和绑定，EXP-009消费不可变启动快照。以下是未来实施要求，素材尚未导入或覆盖。

## 数据映射

| 素材示例 | 项目合同 |
| --- | --- |
| `mapId=three-player/four-player` | 显式映射当前`map-three-players/map-four-players`；只在入座满4时强制四人图，其他人数保留所选地图 |
| `modeId=default` | 独立的规则模式字段，固定生产ID为`standard`，`entrepreneur`本轮不可用；按08实施；不能复用运输方式LaunchMode。本组企业家不可用，保存/恢复不能把默认值解释成企业家开启 |
| `base/expansion-01/expansion-02` | 分别绑定项目已有core及正式enterprise/infected归属ID；示例ID不进入生产。基础固定启用，感染者依赖企业 |
| `hostId/viewerId` | 使用稳定玩家身份，房主随玩家ID，不因换座变成座位1；本地热座和联网权限各按会话入口校验 |
| `seats[4]` | 四个固定座位，各有open/closed/occupied及占位者；玩家ID与座位ID分开，颜色由当前座位索引确定 |
| `roomNumber` | 字符串，复制和显示保留前导零；实际房间ID映射由房间服务提供 |
| `canStart/canReady` | 由Host/房间逻辑产生；包括人数、连接/同步、准备、配置版本、依赖、能力完整性，UI不凭贴图推断 |
| `isProtected` | 仅表现真实服务状态；密码请求成功后再切“修改密码”，不能只改本地标签 |

设置更改形成房间配置revision并广播，受影响准备状态应失效；开始时复验所有玩家已确认同一revision与内容指纹，冻结快照。具体准备策略由004写成一致合同，不能让旧准备沿用到新牌池。关闭企业时若感染者还启用，应拒绝非法组合并提示依赖或通过明确的组合操作关闭两者，不可静默开局成基础局。

## 地图、座位和按钮

- 三人图在上、四人图在下；少于4个实际占位者可选两图；第4人入座强制四人图，人数减少后保留四人图。热座/人机的真实占位计数，空座、邀请中、关闭座位不计数。
- 没有独立人数选择器，人数摘要只读。玩法中的初始资金、红区轮数、企业候选和裁牌人数由真实人数决定，地图拓扑由所选mapId决定。二人变体须在009完整接入后才能canStart。
- 座位颜色固定：1绿、2黄、3蓝、4红。换位移动占位者及身份，颜色留在座位；有人的座位通过请求交换，不能客户端直接交换他人。
- 移除与关闭分开：房主移除其他玩家后为空且开放；关闭只适用于开放空座，有人座位在Host也拒绝关闭。房主自己走原离开/移交流程。
- 房主开始；非房主准备/取消准备。非房主地图/模式/扩展只读，密码按钮隐藏；房间号、复制、说明仍可用。
- 邀请/热座/人机/密码/换位优先接现有服务。示例JS只作为状态转换参考，不执行生产网络逻辑。确无后台能力的可选操作保留真实不可用状态及缺口记录；本组不顺带实现完整AI策略或伪造联网成功。

## 素材与实际资产

核对实际入口[StartScene](../../Assets/Scenes/StartScene.unity)、[StartMenuRoot](../../Assets/YC/Presentation/Prefabs/StartMenu/StartMenuRoot.prefab)、[StartMenuRoomPanelView](../../Assets/YC/Presentation/StartMenuRoomPanelView.cs)及[StartMenuController](../../Assets/YC/Presentation/StartMenuController.cs)。只改房间子树、必要房间说明/密码弹窗和绑定；保留开始页其他模块、收藏室及局内HUD。明确改的是场景覆盖还是源Prefab。

正式PNG不含文字；preview整页、示例人物、HTML、JS、QA和ZIP不得作为运行底图或直接整包导入Assets。按assets.json筛选需要的157项语义资源中的实际使用项，优先复用同哈希已有图片。1×/2×选一套用途；@2x切片像素及PPU成倍，逻辑尺寸不变；source slice顺序左上右下转Unity左下右上。透明框中心、背景填充和完整按钮/拆分fill-frame不能重复叠加。

1920×1080参考：成员区(16,84,1004,912)，设置区(1032,84,872,912)，地图列(1044,154,414,832)，右侧模式/扩展/摘要列x=1470；地图视口326×326，Contain且不裁切/不旋转/不拉伸。精确源参数读layout.json及Guide，不把它们写成冻结用户资产坐标的测试常量。

扩展列表标题固定，只有内容滚动，长名换行增长；溢出显示内部滚动条，否则隐藏。说明页标题及关闭固定、正文单独滚动。密码输入四态、遮蔽/显示、取消不提交；静态文字由检查器配置，动态房间号/玩家名/状态按真实数据绑定。项目现有字体与原生布局规范优先，不能运行旧生成器顺带重建其他页面。

## 验收分界

005验证房间实际画面和操作；009验证其配置到达对局；013/018验证所选组合确实生效。至少检查3人选两图、4人强制后减员保留、非房主权限、换座色/房主身份、关闭与移除、准备随配置变化、依赖失败、长名称滚动、字符串房号、实际截图及对应Prefab来源。功能通过、素材包QA通过和游戏实际画面通过分别记录。

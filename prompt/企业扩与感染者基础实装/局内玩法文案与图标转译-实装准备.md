# 局内玩法文案与图标转译实装准备

初版：2026-10-09。本文是接口与迁移合同，不是完成报告。2026-10-10共享底座、独立转译器及HUD已分批实施并有对应离线证据，企业/选择/次数式等完整文案迁移仍未完成；实际状态与写入授权见[执行协调台账](执行协调台账.md)。本合同本身不授权运行生成器或覆盖既有场景/Prefab。

目标是让 Lua/JSON 内容包决定卡牌规则文字与结算提示，C# 内核只提供规则事实与通用协议，UI 只负责显示。DIY 作者添加卡牌时，应能一并提供效果、提示、选项文字、详情和图标引用，不再修改游戏控制器的中文字符串。

## 1. 范围与不变边界

| 显示位置 | 本次准备迁移的内容 | 继续由原界面资产持有的内容 |
| --- | --- | --- |
| 底栏 | 当前效果待操作、进行中、完成、停止、失败及进度的玩法提示；可选来源按钮的名字、图标和说明 | 固定标题“结算提示”、结束行动/撤销按钮及布局 |
| 企业合作板、科室板 | 企业名、卡面效果、等级说明、实际科室参与后的整体详情、动态费用及限制 | “企业合作板”等页面标题、返回/确认按钮、框体标题和布局 |
| 选择式 | 每个业务选项的名称、说明、不可选原因，本次具体选择的提示 | 固定页面标题、确认/取消、滚动控件及既有计数框样式 |
| 次数式、资源分配 | 本次分配目的、行名称/图标、单位、限制及动态进度提示 | 加减按钮、确认、布局、数值控件样式 |
| 玩家明细、卡牌辅助说明 | 来源名称及完整技能效果、动态状态 | 两个固定文本框的结构与尺寸；都左对齐，标题在上、正文在下，放不下时同步缩小字号 |
| 事件、设施、城市样式、角色等玩法入口 | 对应规则文字、候选说明、费用描述、效果反馈 | 固定 UI 导航文字、装饰、资源库存控件和操作按钮标签 |

“选项里的玩法文字”与“通用确认按钮上的文字”不是同一类。数量上下限、候选是否合法、是否允许停止、费用、公开范围继续由规则状态决定；Lua 的显示声明不能改这些事实。动态结算来源按钮的 icon/文字是用户本轮明确要求，按[逐项清单](结算区域按钮-图标与文字清单.md)落实。

不把所有游戏里的中文都搬走：网络断线、存档损坏、素材加载失败等非玩法系统消息继续使用系统文案资产。禁止把固定标题也改成 Lua 每次运行重赋值。企业家模式仍单独审阅，本批覆盖基础、企业扩、感染者基础。

## 3. 最终数据流

```text
内容 JSON 的文本模板、名称、图标目录 + Lua 的文案引用/纯显示函数
    ↓ 内容包装载时编译并缓存
Effect / Interaction 的显示描述（key + 有类型的参数）
    ↓ Host 按请求可见性裁剪、投影；不发送隐私名称和隐藏候选
GameplayTextResolver：模板 → 文本段 / 数字段 / 图标段 / 换行
    ↓
GameplayTextView：按原框体尺寸、字体角色和溢出政策显示
```

内核提供 `EffectId`、结果码、数值、目标 ID、进度等事实。内容层把事实转成 `GameplayTextRef`。UI 不从卡名猜规则，不从效果树反推完整自然语言，不对“金券”等普通中文做全局字符串替换来塞图标。

**显示协议不负责交互路由。** `InteractionTypeId`、`AnswerSchema`、候选类型和地图高亮语义决定企业/地图/卡牌/次数式等页面；文案 Key 只负责说什么。当前借 `PromptKey` 判断语义的旧分支先显式映射为交互语义，再迁移文字，不能改一个提示 key 就把企业升级退回普通列表。

### 4.1 唯一文案引用类型

拟新增纯数据类型，放 `G:\NoMadCity\Assets\YC\Domain\Presentation\GameplayTextContracts.cs`；这里的 Presentation 是无 Unity 依赖的内容描述 DTO，不处理布局：

```csharp
public sealed class GameplayTextRef {
    public string Key;
    public List<GameplayTextArgument> Arguments;
}
public sealed class GameplayTextArgument {
    public string Name;
    public string Kind; // integer / text / player / item / definition / resource / location
    public NormalizedValue Value;
}
public sealed class GameplayOptionPresentation {
    public string CandidateId;
    public GameplayTextRef Label, Description, DisabledReason;
    public string IconKey;
}
public sealed class GameplayQuantityRowPresentation {
    public string RowId;
    public GameplayTextRef Label, Description, Unit;
    public string IconKey;
}
public sealed class GameplayInteractionPresentation {
    public GameplayTextRef Prompt, Progress;
    public List<GameplayOptionPresentation> Options;
    public List<GameplayQuantityRowPresentation> QuantityRows;
}
public sealed class EffectPresentationDefinition {
    public GameplayTextRef Started, Waiting, Succeeded, Failed, Stopped;
    public GameplayInteractionPresentation Interaction;
    public string PresentationScript;
}
```

JSON/Lua 用 camelCase，C# 用上述 PascalCase。nullable 字段表示无该覆盖，空字符串不表示“展示一个空 key”。`GameplayTextRef` 新合同只使用 Key+Arguments，不再让 `Label` 同时可能是中文、Key 或 markup。

Lua 拟提供纯构造器 `Text.Ref(key, arguments)`、`Text.Player(playerId)`、`Text.Item(itemId)`、`Text.Definition(definitionId)`、`Text.Resource(resourceTypeId)`、`Text.Location(locationId)`；数字/字符串参数分别归一化为 integer/text。构造器不查询状态、不挂 Effect、不能产生命令。引用对象转换到上述 DTO，序列化不保存 Lua table/function。

内容入口的类型也固定下来：`ExternalContentDefinition.Presentation` 使用 `ContentPresentationDefinition { Name, Description: GameplayTextRef; DetailScript: string; }`；`ExternalAbilityDefinition.Presentation` 使用 `AbilityPresentationDefinition { Description: GameplayTextRef; Effect: EffectPresentationDefinition; }`。Lua 的 `Effect.WithPresentation`、`EffectSpec.Presentation` 和保存后的节点元数据都使用同一个 `EffectPresentationDefinition`，不复用内容名称 DTO。JSON 为 `abilities[].presentation.description` 与 `abilities[].presentation.effect`；后者的 `presentationScript` 对应动态效果显示脚本。

显示元数据用 `Effect.WithPresentation(effectSpec, presentation)` 装饰已有 spec。它返回保留同一业务字段/子树的 spec，不创建一个新 Effect 节点。Lua 编译器、克隆、节点/待创建 spec 持久化与恢复必须保留 `Presentation`；不要把文字混进业务 `NormalizedArguments` 后让执行器解析。

需要真实结果数值时用下一节的显示函数接收提交后的事实，不从当前库存反算“这次获得多少”。完成状态下只显示已经提交的事实；无效/失败不能冒充成功。

### 4.2 Lua 动态显示函数

效果显示定义的 `presentationScript` 指向本包内脚本，唯一入口为 `Present(context)`。只允许返回 `GameplayPresentationResult` 对应表：

```text
GameplayPresentationContext
  Purpose: resolution / interaction / enterprise_detail / card_detail / settlement
  SourceDefinitionId, SourceItemId, AbilityId, EffectId, InteractionId
  ViewerPlayerId, StateRevision
  Facts: NormalizedValue（该用途允许、该查看者可见的事实）

GameplayPresentationResult
  Resolution: GameplayTextRef（可省略）
  Interaction: GameplayInteractionPresentation（可省略）
  Details: List<GameplayTextRef>（可省略）
```

Facts 由用途合同提供：结算有 `outcomeCode/actualAmount/completedCount/totalCount`；交互有当前合法 `candidateIds/minSelections/maxSelections/minAmount/maxAmount/rowIds/rowMaximums`；企业详情有 `level/currentCooperationLevel/activeDepartmentDefinitionId/activeDepartmentLevelDescriptions`。只提供该用途需要的字段，不把完整 GameState 传入。不适用的字段缺席，不用 0 冒充事实。

脚本不允许读写文件、调用 Effect、抽牌/随机、提交命令、调用 Unity；也不增加新阶段或事件结算窗口。它在已有 Effect 返回/交互建立、事实变更、详情首次打开或相关状态版本变化时调用，绝不每帧、每次 hover 或每个字调用。静态引用无需跑 Lua。

覆盖优先级：本次 Effect 的显式声明 → 能力/内容定义的 presentation → `defaults.json` 对应通用原语声明。存在显式错误声明时报该错误，不假装成另一个能力；没有覆盖才回退。`PresentationScript` 的输出只能填显示字段，选项 ID 和行 ID 必须来自当前合法集合，不能生成新业务候选。

`defaults.json` 固定为 `schemaVersion` 加三个按键索引的对象：`effectTypes`（EffectTypeId → EffectPresentationDefinition）、`interactions`（InteractionTypeId → GameplayInteractionPresentation）、`outcomes`（稳定 outcomeCode → GameplayTextRef）。模板所需实际数量由事实参数填充；不能把业务枚举的英文拼进屏幕文字。

下面是未来多萝西/异客初始装入标记所用次数式提示的写法示例；它只改变提示，不创建次数式、更不增加 Choice。`maximum` 必须来自本次权威请求的 maxAmount，包含当前可用标记数量限制，而非另写死 4/5：

```lua
function Present(context)
    return {
        interaction = {
            prompt = Text.Ref("core:character.store_markers.prompt", {
                maximum = context.facts.maxAmount,
                source = Text.Definition(context.sourceDefinitionId)
            })
        }
    }
end
```

与它配套的文本模板声明为 `parameters={maximum:"integer", source:"definition"}`，正文为“选择在{source}上放置的玩家标记数量，至多 {maximum} 个。”。Context/Result 在 Lua 中全用 camelCase，C# 层使用表列的 PascalCase，NormalizedValue 在边界转换为对应只读 Lua 数据；函数不能修改输入。

### 4.3 选择式与次数式

`InteractionRequest` 和 `InteractionRequestProjection` 拟增加 `GameplayInteractionPresentation Presentation`。同步经过 `VisibleInteractionRequestSource`、`CharacterCardPanelPresenter` 等复制路径；UI 回答继续只提交原候选 ID/数量，不提交 label 作为答案。

每个 Choice 候选须有显示定义或由内容声明的通用命名模板覆盖。候选对应公开卡牌时用其内容名称；玩家候选用合法玩家显示名；不能把 `pay|zone|rock|shard|iron`、`originium|p2`、`activate/decline` 原样塞给玩家。未知可见实体用内容包通用兜底“未知对象”，内部 ID 只进诊断日志。

次数式的 `RowId` 固定来自业务分配行，不从显示文字反解资源类型。上下限、总量和是否互斥继续取业务字段；显示函数只为它们写提示，不自行另算一套。异客/多萝西初始装标记仍使用次数式；异客付款使用各基础资源分配行，不能退回枚举所有组合的选择列表。

Prompt 只指页面正文提示，不覆盖静态页面标题。`Progress` 是可变进度文字；原固定计数框由原序列化格式及数值更新维持，本次不重写其标题、字号和边框。说明变短不能删掉上限、对象归属、代价或是否可停止等必要条件。

### 4.4 底栏提示的来源与优先级

**2026-10-10 用户明确外层布局优先级：按钮布局优先于动态提示布局，两者不共存。** 当前存在应显示的结算按钮时隐藏动态提示布局（pending/disabled 按钮也计入）；没有按钮时才显示当前合法提示。撤销左右分区并存方案。显隐只影响展示，不取消请求、不改变候选或执行顺序；提示数据可随状态正常更新，恢复时不显示旧窗口瞬时反馈。既有静态文案不迁移、不由运行时重写；共用框体与对应布局的具体引用由界面负责人按真实Prefab及场景覆盖接线。

拟新增 `ResolutionMessageView`：`OwnerEffectId`、`InteractionId`、`ViewerPlayerId`、`StateRevision`、`Message: GameplayTextRef`。它是显示投影，不是第二套主链。

以下仅是提示布局内部的消息来源优先级，不覆盖上面的按钮优先规则。由现有交互路由/主链当前节点选择来源：当前对该玩家开放的阻塞交互提示优先；无该请求时用当前活动 Effect 提示；再用最近一次本人操作的完成/停止/失败反馈；最后才显示内容包主链当前阶段默认提示。窗口切换清除上个窗口的瞬时反馈。只读看企业/城市/卡牌不抢走底栏的正在结算来源，关闭查看后恢复原消息。

纯本地预选/路费草稿提示继续即时更新：原工作流提供 `selectedCount/selectedTarget/quotedToll` 等允许字段，本地解析同一内容模板，不额外发命令、不跑规则 Lua、不做全局合法性检查。Host 实际结算结果覆盖草稿。不能为“Lua 决定文字”把原来一帧完成的选点提示变成一次服务往返。

没有 Lua 的系统主链原语从 `defaults.json` 取内容模板；C# 只提交稳定 outcomeCode 和参数。代码内禁止继续新增“某角色效果已完成”“获得 N 金券”等玩法字符串。

## 5. 文本和图标转译语法

“转译器”指显式模板解析，不是翻译模型，也不是从自然语言猜图标。V1 只实现以下语法；其他富文本标签都不作为指令执行。

| 写法 | 含义 |
| --- | --- |
| 普通文字 | 保留原文；模板中的“策略”“计谋”和连续数字自动识别字体角色，无需手写字体标签 |
| `{amount}` | 使用模板声明的具名有类型参数 |
| `[icon:core:resource.gold_voucher]` | 插入已登记的语义图标 |
| `[icon:core:resource.score\|value=2]` | 分数图标内部叠加数字 2，整体占一个内联片段；模板实际写法不含表格转义用的反斜杠 |
| `[icon:core:resource.score\|value={amount}]` | 数字来自 integer 参数 amount，覆盖在分数图标上 |
| `[color:#E0B85A]文字[/color]` | 指定这一段文字颜色；接受 `#RRGGBB` 或 `#RRGGBBAA`，大小写均可，缺省 alpha 为 FF |
| `[b]文字[/b]` | 这一段明确加粗；解析为粗体字重并切换到对应粗体字体资源，不使用 Unity 伪加粗 |
| `[normal]文字[/normal]` | 这一段明确使用常规字重；可以在外层加粗中局部取消加粗 |
| JSON 中 `\n` | 硬换行 |
| `{{`、`}}`、`[[`、`]]` | 输出字面量花括号/方括号 |

### 5.1 自动识别与显式格式

2026-10-12 用户明确条件式写法为 `A[icon:core:syntax.condition]B。`：图标放在完整条件 A 和结果 B 之间，替代原 `[icon:core:syntax.condition]A后，B。`。等级、前置步骤保留；复合条件内部的“再”等顺序词及结果中的费用、范围、可放弃条件保持原义。只修改内容模板，不让解析器从自然语言推断规则，也不全局删除其他“后”字或标点。

同日用户追加影响力文案规范：无额外目标、位置等限制的任意玩家影响力移除，用对应个数的 `[icon:core:rule.remove]`；无额外限制的本人影响力放置，用对应个数的 `[icon:core:rule.deploy]`。数量、至多、费用、前置步骤及可停止性保持原义，不用非分数图标叠数。有限制的移除（包括仅本人、仅对手、指定区域或类型）保留文字，不能用通用图标掩盖限制；仅本人移除统一写“移除自己的n个影响力”，原为至多时写“至多移除自己的n个影响力”。指定航道放置、公司影响力、卡牌标记、移动及替换不按上述通用放置/移除替换。通用高亮点选操作指导和图标alt文本不机械改为图标；尚走Literal的旧字段不直接写入无法解析的标记。

用户随后补充：无明确额外限制的本人影响力移动/调度使用 `[icon:core:rule.dispatch]`，固定数量对应图标个数，动态数量保原参数写作 `{count}[icon:core:rule.dispatch]`，不新增图标重复语法。指定资源点或公司影响力的移动等仍保文字。`core:rule.city_move` 是城市移动，`core:rule.operator_dispatch` 是干员特派，不与影响力调度混用。仅图标直接相邻之间、没有其他语义的“，再”可删；分支、条件、目标选择与顺序要求仍保留，不全局删除连接词。

“策略／计谋”的特殊字体是已有排版约定，应由转译器自动处理。内容作者直接写“策略”“计谋”即可；撤销上一版要求填写 `[style:special]策略[/style]` 的方案。自动识别只改变字体角色，不加颜色、不增加效果语义，也不改变技能类别。

识别词表放在拟新增 `GameplayTextStyle.asset` 的 `SemanticKeywords`，初始两项为 `策略 → SpecialWord`、`计谋 → SpecialWord`。它是排版配置，不是逐卡必填字段。按最长匹配识别完整词，不把“策”“略”各拆成一个特殊物体；后续扩词只改词表。词表版本加入样式版本，不每帧扫描全部卡牌。

颜色、加粗是作者按需要选择的显式格式，可组合并嵌套，必须正确闭合：

```text
策略：选择 1 家企业。
[color:#E0B85A]获得 {amount}[icon:core:resource.gold_voucher][/color]
[color:#D95745][b]必须移除自己的2个影响力。[/b][/color]
[b]整段加粗，[normal]只有这里使用常规字体[/normal]，这里恢复加粗。[/b]
```

作用域规则：未指定属性时继承外层，最外层继承当前文本宿主；内层只覆盖自己指定的属性，关闭标签后恢复外层。`[normal]` 只取消字重，不取消外层颜色；颜色标签只影响 TextRun/NumberRun，不给图标、企业 logo 或玩家标记染色。图标维持自己的资源颜色与状态。

不开放文字字号、材质或任意字体路径标签；作者可写颜色和是否加粗，具体字体资源仍由项目配置解析。颜色及字重标签不传给 Unity RichText/TMP 再解释，转译器必须先消费它们。标签格式错误在内容加载时定位到 key 和字符位置；不靠多轮正则猜测或逐帧修复交叉嵌套。

模板必须声明全部参数；图标 Key 必须在声明目录中。玩家姓名和其他参数值当纯数据插入，不二次解析其中的 `{}`、markup、Unity RichText。整数使用现有数字字体；不靠正则扫描所有玩家姓名里的数字来决定业务含义。标点、换行、图标基线由 renderer 处理。

模板作者直接写的常量数字（如“选择 1 家”中的 1）在模板编译时生成 NumberRun；连续数字为一段。参数 `Kind=text` 和实体显示名保持整体纯文本，不把姓名里的数字/关键词再次当语法处理，但它们继承占位符位置的颜色和字重。例如 `[b]{player}[/b]` 能加粗玩家名称，名称中自带的 `[color:...]` 仍只是字面文字。图标 Key 不允许由任意字符串参数拼接；需要动态资源符号时由有类型的 resource 参数按登记映射解析。

### 5.2 实际字体切换合同

`GameplayTextStyle.asset` 拟增加 `FontBindings`，以 `(SemanticRole, WeightMode)` 索引实际 Font 引用；角色使用现有 `Regular/SpecialWord/EffectNumber`，字重使用 `Inherit/Normal/Bold`。`Inherit` 表示沿当前宿主或角色默认，不等于强行常规；明确 `[normal]` 则必须使用常规字体资源。

下面按当前 `G:\NoMadCity\Assets\YC\Presentation\CommonUi\Content\UiFontRoles.asset` 的真实绑定确定首版接线，不要求导入另一套字体：

| 内容角色 | 无显式字重时的角色默认 | `[normal]` | `[b]` |
| --- | --- | --- | --- |
| 正文 Regular | `UiFontRoles.Regular` | `UiFontRoles.Regular` | `UiFontRoles.Emphasis` |
| 自动识别的策略／计谋 SpecialWord | `UiFontRoles.SpecialWord` | `UiFontRoles.SpecialWord` | `UiFontRoles.Emphasis` |
| 规则数字 EffectNumber | `UiFontRoles.EffectNumber` | `UiFontRoles.UiNumber` | `UiFontRoles.EffectNumber` |

真实资源均在 `G:\NoMadCity\Assets\YC\Presentation\CommonUi\Fonts\`：Regular=`FangZhengHeiTiJianTi-1.ttf`；Emphasis=`HanYiCuHeiJian-1.ttf`；SpecialWord=`MicrosoftYaHei-Regular-face0.ttf`；EffectNumber=`Novecento NarrowBold.otf`；UiNumber=`Novecento wide Normal Regular.ttf`。这只是当前字重映射的明确来源，控制器不能按文件名硬编码；用户以后调整字体配置时读取新引用。

显式字重优先于自动特殊词的默认字体，因此 `[b]策略[/b]` 用 Emphasis，`策略` 不加标签时用 SpecialWord。规则数字默认字体本来就是实际粗体；再包 `[b]` 可以仍命中同一个粗体资源，不能重复做一次加粗。数字包 `[normal]` 则切换到已登记的常规数字字体。

渲染顺序固定为：解析格式与参数 → 自动确定模板文字的语义角色 → 应用字重映射取得 Font → 用该 Font 测宽、换行 → 显示。切换字体后重测宽度和基线，不能按常规字体排完版再换粗体导致挤压或裁切。实际 Text 使用 `fontStyle=FontStyle.Normal`、关闭 Unity 自行解释富文本；禁止 `FontStyle.Bold`、额外描边、叠字或位移来模拟加粗。

缺字使用与最终字重相符的已登记字体回退；当前 `MissingGlyphFallback` 为常规字体，并不能证明粗体回退已配置。遇到粗体缺字应登记对应字体缺项，不能静默换成常规字体并宣称加粗成功。本轮只指定准备合同，不导入字体或修改现有字体资产。

### 5.4 分数图标叠加数字

用户明确要求分数值写在图标上。采用 `core:resource.score` 对应的 `G:\NoMadCity\游城拓荒\icon\分数.png`（207×184，透明 PNG）；数值为运行时文字，不把不同分数烘焙成多张图片。

唯一参数语法为 `[icon:图标Key|value=整数或具名整数参数]`；例如 `获得[icon:core:resource.score|value=2]` 和 `失去[icon:core:resource.score|value={amount}]`。常量接受十进制有符号整数，动态参数必须声明为 integer；这里不允许 Lua 表达式。外部 Effect/模板决定“获得/失去”及数值，图标渲染不自动加负号、不扣分、不把数值当成最新总分。

`GameplayIconDefinition` 增加 `RenderMode`（sprite / number_overlay）、`ValueRequired`、`ValueAltTextKey`、`NumberOverlayStyleKey`。分数固定 `number_overlay`、`ValueRequired=true`；没有 value 的裸分数图标引用视为内容缺项，不能偷偷显示0。其他图标默认 sprite，不因文件名含“分数”就叠数字；`分数结算时.png` 是独立正文图标，不叠分数值。

`IconRun` 增加 `NumberValue: int?` 与 `OverlayTextStyle: GameplayTextRunStyle`；解析器把 value 参数绑定为数字，不把 `{amount}` 残留到 UI。分数图及数字构成一个不可拆开的布局片段：一张 Image 上叠一个池化 Text，换行、基线、缩放和点击穿透按整体处理。数值不能变成图标左边或右边的第二个独立 NumberRun。

`core:score_number_overlay` 的拟 UI 样式用归一化矩形登记数字区域。根据本图中央六边形，初始 `OverlayRect=(x:0.22,y:0.25,width:0.54,height:0.56)`，原点为图像左下角，坐标相对完整图片；实际接线时以六边形中央显示校对。数字水平/垂直居中，默认字体 `UiFontRoles.EffectNumber`，默认颜色白色，`fontStyle=Normal`；字号跟随内联图标尺寸，位数增多时只缩小内部数字以容纳，不拉伸图标、不改变整行高度、不截断负号。上述几何值为准备初值，不是不可修改的视觉测试常量。

外层显式 `[color]`、`[b]`、`[normal]` 可作用于覆盖数字，字体按第5.2节映射；未显式指定时用覆盖样式自己的字体/颜色，图标底图始终保持原色。同时按最终字体重新测量内部数字，沿用真实字体加粗合同。缩放和切换数值不得留下旧数字或创建重复 Text。

分数的 `ValueAltTextKey=core:resource.score.value_alt`，对应模板为 `{value} 分`；例如上面的图文“获得[分数图内的2]”复制成纯文字就是“获得2 分”。普通 `AltText` 仍为“分数”，value 图示输出完整数值替代文本，不能只剩“获得分数”。数值变化进入文档/绑定缓存身份；只更新该片段，不为1、2、3等每个数值建立一张新贴图。

## 7. 渲染器与性能合同

拟新增文件：

| 绝对地址 | 接口 |

`GameplayTextDocument` 为不可变段列表：`TextRun, NumberRun, IconRun, LineBreak`。文本/数字段携带 `GameplayTextRunStyle { SemanticRole, WeightMode, ColorRgba }`；`ColorRgba` 为可空的 8 位 RGBA 四字节值，null 表示沿宿主颜色；纯数据层不引用 Unity Color/Font。闭合标签的样式作用域先折叠到每段，不留给 View 猜测。UI 依据字体配置解析 Font，字重、颜色和最终字体都相同的相邻段才合并。换行时依据实际字形宽度拆为行片段，**不按每个汉字生成 GameObject**。使用当前 Unity UI Text/Image 能力即可，不把全项目迁到另一种字体系统当作前置工作。

现有 `UiSemanticLabel` 的缓存能避免相同字符串重复拆分，但长内容仍产生大量子 Text；`UiInlineTextLayout` 在布局阶段反复查询子物体宽高。后续只把已迁移的玩法文本宿主改接新 View，并关闭该宿主旧分段器，不能两个渲染器同时显示/同时重建。其他计数、静态标题仍保留原组件。

文本布局可计算字符级测量数据，但 UI 物体数按“可见行片段+图标”增长。复用 Text/Image 池；相同文档不重新绑定。池化片段每次绑定必须应用本段 Font、颜色与字重结果，不能把上一条红色粗体残留到下一条普通文本。禁止每次刷新 Destroy/Instantiate 全文、每字 MarkLayoutForRebuild、每图标同步读盘。窗口尺寸/字体/文档变化才重新布局，同帧合并一次布局请求；只变颜色可直接更新颜色，不必重新测字宽。

缓存分别按 `(ContentHash, Locale, TextKey)` 保存编译模板，按 `(TemplateId, VisibleArgumentsHash, ViewerPlayerId, SemanticKeywordsVersion)` 保存解析文档；文档身份必须包含有效颜色与字重，布局另按文档的测量身份、宽度、字号、字体/样式版本缓存，测量身份可忽略纯颜色变化。使用宿主默认字重/字体的片段，也须把宿主最终字体版本计入布局键，避免缓存拿常规字宽绘制粗体。动态企业详情/纯 Lua 显示结果按查看对象及相关状态版本缓存。可使用已存在 StateRevision 使缓存失效，但同 revision 多个控件不得重跑一份 Lua；缓存清理限制条数，不随整局历史无限增长。

预加载本局启用内容的目录及实际需要的图标。普通单击即时处理，不等待双击，不为文案新增全局状态校验/全历史遍历。Host 原提交合法性检查仍存在，文案刷新不复制它。无关状态变化不得强制全局文字重排。

图标沿字体基线、按当前字号等比缩放；名称不得粗暴裁掉关键条件。各宿主沿自己的原溢出政策：企业正文可在既有纵向正文区排版；玩家明细固定框完整正文并同步缩字；底栏提示在原边界内显示；按钮单行超长说明沿按钮准备稿。不要因为新文案多就拉长固定条目、增加未授权横向滚动条或改变框体大小。

## 8. 企业与莱茵生命的整体详情

`enterprise/*.json` 的 `data.levels[]` 拟新增 `description: GameplayTextRef`；`department/*.json` 的相应等级数据提供 `description`。实际规则依旧由能力 Lua 执行，描述不用于驱动升级或奖励。

企业定义 `presentation.detailScript`（字段名固定）可引用上一节同签名 `Present(context)` 的脚本。普通企业可直接按 level 顺序返回各级描述；莱茵生命根据公开 `activeDepartmentDefinitionId`，把一级企业特效与二至五级当前科室奖励组成一个整体的 `Details`。UI 只显示返回的有序段，不能拼“企业特效X”或把当前科室名尾加在未替换的通用奖励文字后。

统一字段含义：通用 `EffectPresentationDefinition.PresentationScript` 服务效果/交互；内容定义 `presentation.detailScript` 只服务详情。两者都调用 `Present(context)`，不能为了同一文本再建第三种 Lua 回调协议。

无当前科室时显示内容声明的对应状态；一级无奖励的企业按已批准规则说明，不虚构奖励。详情本身不触发企业特效。企业选择、特效选择、主界面查看调用同一详情提供者，读取同一绑定状态。科室选择候选不得包含已装科室，这仍是业务集合规则，不能靠描述藏掉。

企业名统一取当前正式内容的 `displayName`，包括“富森银行”。不再维护 UI 的第二套可漂移名字。

## 9. 旧接口兼容与禁止再次出现的分支

旧 `PromptKey/PromptParameters` 在迁移期保留恢复能力；用 `LegacyGameplayTextAdapter`（拟新增于 Application/Presentation）只适配旧内容/旧存档，显式区分原字段是文本还是 key，不用“含中文就是文本”这种启发式。已迁移内容只走新协议；没有新字段的旧内容才查旧目录。

实体参数只从该查看者已经获准的投影中解析；不能为取得卡名回到全局 ItemRegistry 读取隐藏牌。Host 投影必须同时裁剪正文、参数、选项说明和图标来源，不能只清空 CandidateIds 却留下提示中的隐私。缺 Key/参数的正常可读兜底使用 `core:presentation.unavailable`（“此项说明暂不可用”），未知实体使用 `core:presentation.unknown_entity`（“未知对象”），都在内容目录声明；目录本身损坏则走系统加载错误。诊断按内容哈希与缺项去重，不逐帧刷日志。

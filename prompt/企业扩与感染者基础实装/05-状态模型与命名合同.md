# 状态模型与命名合同

状态：**本组固定的目标接口，尚未实现**。以下名称从原设计建议提升为实施要求。001负责验证与现有生产路径相容，不再自行换名；发现同名冲突时先修改本文、全部消费者和接口核验记录，再继续。规则以已审核卡面和本组审阅纠正为准。所有路径见[04](04-路径索引与实施文件归属.md)。

## 命名硬约束

- 严禁用任务编号或执行步骤编号命名新脚本/文件夹、C#类/接口/命名空间/成员、Lua模块/变量、测试类/方法、Effect/事件/候选/内容ID、Unity GameObject/组件实例/Prefab/场景、日志类别、临时工具和构建产物。例如`EXP003Transfer.cs`、`NMC016Manager`、`Task015Button`、`Step7Panel`、`exp_006_upgrade`全部禁止。
- 用职责和业务含义命名：`ItemTransferService`、`EnterpriseSpecialSelectionExecutor`、`CharacterSettlementSlotView`、`RoomConfigurationTests`。数字只有真实业务含义才可使用，如等级5、槽位索引、schema版本；不能伪装任务编号。
- 任务编号只留在计划文档标题、依赖表、任务状态及交付记录的任务元数据。历史已有`NMC...Tests`作为读取依据可以引用，本组不新增同类命名，也不为改名清理而扩大修改范围。既有`nmc.stable-id.v1`是项目协议名，保留。
- C#类型/公开字段PascalCase，局部变量/参数和Lua/JSON键camelCase，协议枚举值snake_case，文件名按类型/语义。不要并用`zoneId/areaId/containerId`表示同一概念。
- `Zone`专指容纳区域；`Region`只指地图计分区块。`ItemId`是本局物品实例，`DefinitionId`是内容定义，`RuntimeId`是替换链稳定槽；`CardInstanceId`沿用现有角色使用入口，值必须映射同一ItemId，不再生成第二个卡实例。

## 外部定义许可

外部字段固定为`typeId/physicalKind/baseTypeId/operationProfileIds`及`cardZones[]`。卡载声明键为`localZoneId/zoneTemplateId/acceptedItemKinds/acceptedTypeIds/entryPolicyId/exitPolicyId/capacityPolicy/capacity/orderingKind/visibilityPolicyId/carrierExitPolicyId/displayAnchorId`。

`capacityPolicy`只能`bounded`或`unbounded`，bounded必须capacity≥0，unbounded禁止同时传capacity，内核映射Capacity=-1。acceptedItemKinds不得含Zone/Any，acceptedTypeIds若非空必须同时满足kind和已注册子类型。外部不能填parentId/parentKind/acceptsZones/rootId；加载时作为不支持字段拒绝。只允许填已注册模板允许收窄的范围，不允许扩大模板接纳类型或绕过entry/exit政策。

固定操作域ID：`core.cube_storage`、`core.player_marker_storage`、`core.influence_cube`、`core.facility_card_transfer`、`core.character_card_transfer`、`core.character_card_use`、`core.deck_shuffle`、`core.mobile_city_move`、`core.adjacent_location_token_move`。DIY只继承许可组合；不能自造ID获得能力。对局内注册表只读且进入ContentPackHash。

002在指定的ItemTypeRegistry.cs中定义`ItemTypeDefinition`：`string TypeId,BaseTypeId`、`ItemPhysicalKind PhysicalKind`、`List<string> OperationProfileIds`；注册器公开`bool TryRegister(ItemTypeDefinition definition,out string reasonCode)`、`ItemTypeDefinition Find(string typeId)`、`bool IsAssignableTo(string typeId,string baseTypeId)`、`void Freeze()`。同ID重复、缺父类、成环、物理类型不相容、未许可操作域分别返回`duplicate_type_id/unknown_base_type/type_cycle/physical_kind_mismatch/operation_profile_rejected`；Freeze后任何注册返回`registry_frozen`。Find只返回隔离副本。注册器不持有某一局物品的位置。

ZoneTemplateRegistry.cs定义内核用`ZoneTemplateDefinition`，固定成员`string TemplateId`、`List<string> AllowedParentTemplateIds,AllowedCarrierTypeIds,AllowedChildTemplateIds,AcceptedTypeIds`、`List<ItemPhysicalKind> AcceptedItemKinds`、`ZoneOrderingKind OrderingKind`、`int Capacity`、`bool AllowExternalCardBinding`；这些结构字段**不进入Lua/外部JSON可调用接口**。内核入口为`internal void RegisterBuiltIn(ZoneTemplateDefinition definition)`，启动重复ID或结构错误直接拒绝装配。外部卡载声明类型`CardZoneDefinition`在同文件定义，成员按上文声明键逐项PascalCase映射，其中Capacity为nullable int，列表为List，OrderingKind为枚举。只暴露`bool ValidateCardZoneDeclaration(string carrierTypeId,CardZoneDefinition declaration,out string reasonCode)`、`ZoneTemplateDefinition Find(string templateId)`、`void Freeze()`；外部不能调用RegisterBuiltIn，也不能通过反序列化添加AllowedChildTemplateIds。Host依据已验证的声明创建区，查询层不得懒创建。

## 续接字段与隐藏规则

## 房间配置模型

新增`G:\NoMadCity\Assets\YC\Domain\Rules\GameRuleConfiguration.cs`，namespace `YC.Domain.Rules`，序列化类字段：


`RuleModeId`只接收`standard`；`entrepreneur`是保留模式ID，本轮返回`rule_mode_not_implemented`，不默认为standard。基础固定core；企业enterprise；感染者infected且要求enterprise。保留现有LaunchMode.Local/Host/Client，不能加LaunchMode.Entrepreneur。

`RoomState`新增`GameRuleConfiguration Configuration`和`List<RoomSeatSlotState> SeatSlots`；4项SeatIndex=0/1/2/3。新增模型放`G:\NoMadCity\Assets\YC\Infrastructure\Multiplayer\Core\RoomConfigurationCommands.cs`或同目录`RoomSeatSlotState.cs`，namespace沿用`YC.Infrastructure.Multiplayer`。

`RoomSeatSlotState`固定字段：`int SeatIndex`；`string Status="open"`（open/closed/occupied）；`PlayerSeat Occupant`（open/closed必须null）；`bool IsUserReady=false`；`int ReadyConfigurationRevision=-1`。已邀请未入座仍open，不伪造Occupant。`PlayerSeat.PlayerId`身份不随换位改变，Color从SeatIndex映射。

SeatSlots是唯一座位权威。既有`RoomState.Seats`只作为occupied项的旧接口投影，按座位排序；旧代码修改Seats/Add/Remove的路径全部迁移至RoomConfigurationService，不继续双写。RoomState.PlayerCount只派生occupied数量，配置PlayerCount在配置修订和冻结时拷贝该值，三者必须一致。RoomState.Clone和TryLocalizeAuthoritativeSnapshot同时支持SeatSlots，空位不得被当成null玩家错误。

**两种就绪不能混用**：现有`PlayerSeat.IsReady`由`WaitingRoomReadiness.cs`和`NetworkRoomService.SetTransportReadiness`表达连接/身份校验就绪，保留其含义与真实连接回调写入路径。新增`RoomSeatSlotState.IsUserReady`才是玩家点击“准备”的状态。配置变化只清除IsUserReady并将ReadyConfigurationRevision设为-1，不清除TransportConnected、IdentityVerified或旧IsReady。两类状态都进入快照，但前者不能代替后者。

## 房间请求、服务和错误

请求模型固定在`RoomConfigurationCommands.cs`，所有请求含`string CommandId,RoomId`、`int RequestingPlayerId,ExpectedConfigurationRevision`：

| 请求类型 | 其他字段 | 权限/结果 |
| --- | --- | --- |
| `ChangeRoomConfigurationRequest` | `string MapId,RuleModeId`；`List<string> EnabledExpansionIds` | 仅Host；整组校验后一次变更revision，所有占位玩家IsUserReady清零 |
| `SetRoomReadyRequest` | `bool IsUserReady` | 本人；准备时设true并记录当前revision；取消设false和-1；不修改PlayerSeat.IsReady |
| `SetRoomSeatStatusRequest` | `int SeatIndex`；`string Status` | Host只可空位open↔closed；occupied不可关闭 |
| `RequestRoomSeatSwapRequest` | `int TargetSeatIndex` | 玩家请求；目标occupied时创建换位请求而非直接交换，权限/同意沿Guide与真实服务 |
| `ConfirmRoomSeatSwapRequest` | `string SwapRequestId`；`bool Accepted` | 指定被请求玩家；Host原子处理、过期拒绝，不能换给第三人 |
| `StartConfiguredGameRequest` | 无 | 仅Host；准备、人数、版本、能力完整性复验，冻结配置 |

`RoomConfigurationResult`固定`bool Success,string ReasonCode,RoomState Snapshot`。`RoomConfigurationService`公开签名：

```csharp
RoomConfigurationResult ChangeConfiguration(RoomState room, ChangeRoomConfigurationRequest request);
RoomConfigurationResult SetReady(RoomState room, SetRoomReadyRequest request);
RoomConfigurationResult SetSeatStatus(RoomState room, SetRoomSeatStatusRequest request);
RoomConfigurationResult RequestSeatSwap(RoomState room, RequestRoomSeatSwapRequest request);
RoomConfigurationResult ConfirmSeatSwap(RoomState room, ConfirmRoomSeatSwapRequest request);
bool TryFreezeForLaunch(RoomState room, StartConfiguredGameRequest request,
    out GameRuleConfiguration configuration, out string reasonCode);
```

服务修改前做完整校验，不成功不部分改房间；成功Snapshot是隔离副本。CommandId去重沿房间已有命令机制，无则同服务补有限去重记录，不能把整场记录放UI。身份RequestingPlayerId从已验证连接比对，不能只信任请求字段。

固定ReasonCode：`not_room_host`、`configuration_stale`、`unsupported_player_count`、`map_requires_four_player`、`missing_enterprise_dependency`、`rule_mode_not_implemented`、`content_not_ready`、`content_version_mismatch`、`player_not_ready`、`seat_occupied`、`seat_swap_stale`、`service_unavailable`。中文提示存在配置化映射，代码只返回键，不覆盖编辑器静态按钮名。

配置改变/入座离座/换座在同次提交增加ConfigurationRevision并使人工准备失效。达到4人MapId必须为`map-four-players`；减至3/2不自动改图。初建可用`map-three-players`默认，之后禁止根据人数覆盖已有选择。重复的同值配置请求不增加revision，重复CommandId不二次清准备。不能接受超过4人的配置。

Room Guide新增的人工准备合同为：Host点击开始即确认当前配置，不要求Host再点击准备；其他在线占位者必须IsUserReady=true且ReadyConfigurationRevision等于当前ConfigurationRevision。Steam开局还必须通过既有连接/身份校验；本地模式和LocalMirror沿真实适配器的认证规则验证，不能为了复用Steam检查而伪造SteamId。Host本机控制的真实热座玩家由Host开始统一确认；只有后端实际存在的占位者才能走该分支，邀请和示例AI不算。人机/热座添加尚无后端时返回service_unavailable，不创建占位对象凑数。Guide的开始按钮依赖这些完整条件所得canStart，不能只绑定旧IsReady。

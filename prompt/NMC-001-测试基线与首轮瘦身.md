# NMC-001：EditMode 测试基线与首轮瘦身

## 任务提示词

你负责为 Lua Effect 树架构改造建立可信的 EditMode 测试基线，并先完成一轮不依赖新架构实现的低风险瘦身。先完整阅读 `prompt/00-共同执行约束.md`，再执行本任务。

## 前置任务

无。本任务可以与 `NMC-002` 并行，但不得同时运行两个 Unity 实例。

## 目标

1. 用指定 Unity 得到实际发现、通过、失败、跳过和耗时，而不是依赖静态属性计数。
2. 建立按规则风险和测试层分组的测试资产清单，找出同构复制、跨层重复与纯字段赋值测试。
3. 通过参数化、共享 fixture/builder 和上移权威断言完成首轮精简，同时保持行为覆盖。
4. 形成后续任务可持续维护的 `docs/测试/EditMode测试治理.md`。

## 实施范围

- `Assets/YC/Tests/EditMode/**`
- EditMode 测试 asmdef、共享测试工具与 `tools/Run-EditModeTests.ps1` 的读取和必要修正
- 仅在确实妨碍测试合并时，允许做不改变业务行为的小型可测试性重构

## 执行要求

1. 执行完整 EditMode 基线，保存 XML/日志位置并读取真实结果。若已有失败，先判断是稳定失败、偶发失败还是环境失败；不要把已有失败算作本任务回归。
2. 至少按以下类别统计文件数、发现用例数和耗时：Domain 规则、Application/Command、Interaction/Presentation、EditorAsset、Network/Multiplayer。
3. 为每类建立行为覆盖矩阵，标明：被保护的不变量、最低成本权威层、重复测试、合并方式和保留理由。
4. 优先合并：
   - 只替换玩家、ID、资源种类或枚举值的复制用例；
   - Domain 已完整覆盖而上层逐项复述规则的用例；
   - 每个 Prefab/卡牌/配置各写一份、可由目录或数据表统一验证的 EditorAsset 用例；
   - 重复构造 `GameState`、玩家和命令的 fixture。
5. 不删除独特的事务、权限、隐私、序列化、故障恢复和边界条件覆盖。不得通过 `[Ignore]`、改名或减少断言制造数量下降。
6. 删除测试文件时先用 `rg` 核对其覆盖已被替代，再逐个删除明确文件及对应 `.meta`；禁止目录级或通配符删除。
7. 完成后再次运行完整 EditMode，并用同一口径比较前后数字。

## 数量目标

- 首轮争取让 Unity 实际发现用例数下降至少 15%。
- 如果安全合并不足 15%，不要硬删；在治理文档中按测试组列出受保护的独特风险，并给出后续迁移任务中可继续合并的位置。
- 即使发现数下降，也必须保证最终完整 EditMode 无新增失败。

## 非目标

- 不实现 Effect 树、Lua Host、回合主链或业务内容迁移。
- 不为了方便测试而改变规则语义。
- 不把 EditMode 测试迁移成不执行的文件或依赖手工步骤。

## 验收标准

- `docs/测试/EditMode测试治理.md` 包含基线、分类、行为覆盖矩阵、前后数字和后续规则。
- 共享测试基础设施减少了重复构造，测试名称仍能定位失败场景。
- 每个被删除或合并的旧用例都有可定位的替代测试或参数化数据行。
- 完整 EditMode 通过，或仅保留经复现确认的任务前既有失败且无新增失败。
- `git diff --check` 通过，没有修改无关用户文件。

## 交付报告

报告测试文件数、发现/通过/失败/跳过数、总耗时、净减少数与比例；列出主要合并组、保留的高价值测试、既有失败，以及供 `NMC-003` 之后沿用的 fixture 和命令。

## 1. 必须同时满足的要求

1. **原生布局适用于所有局内普通结构。** 顶底栏、三列、列内分区、玩家明细、普通行、页头／正文／页脚用 VLG／HLG／LayoutElement 与 stretch，不能以自定义 LayoutGroup 的类名或挂载状态代替。卡牌网格优先 GridLayoutGroup，局部辅助器只更新其参数；自定义仅保留原生无法表达的内容映射／语义计算并逐项说明。
2. **1920×1080 下正常 UI 的屏幕位置保持不变。** 使用当前实际源／覆盖与同状态有效基准；已有 UI-007 开工矩形可复用，但先核实对应当前资产。父子关系、锚点和局部坐标允许改变，正常构图不借重构重新设计；旧 UI 删除、非法分页结构及已知越界修复单列差异。
3. **所有支持比例使用同一主三列结构。** 16:10 与其他比例都不按阈值隐藏主列、变成单列、添加导航或平移整张 HUD。正文内部换列、滚动和原有手牌内容分页允许；右下三个真实业务页签与 effect 收起恢复保留，不能将它们用作比例切页。
4. **生产命名按功能，旧 UI 真正移除。** 实际文件、目录、物体、类型、配置、长期测试和工具按基础修正映射去掉任务号，保留 GUID/fileID 所需的身份；旧翻面／查看提示变体、旧资源计数器、旧固定弃牌及旧盖牌拖放不作为布局兼容分支保留。

这里的“绝对位置不变”是基准画面要求，不是要求继续用固定 `anchoredPosition` 实现。参考尺寸、间距、最小／首选／最大尺寸应保存在资产配置中，由布局关系复现既有构图。保持现有贴图、字体角色、正常尺寸与样式，不能借本项重新设计 1920×1080 界面。

已报告的“其他玩家明细展开把城市挤到底栏下方”单列为待修缺陷，不能把越界结果固化为正确基准。优先通过明细高度分配和内部滚动修复，保留正常基准位置。若某一实际状态的既有位置本身与内容区边界冲突，记录对象、前后矩形和冲突原因，不得悄悄移动整套基准构图来声称位置未变。

## 3. 布局职责与组件

| 区域 | 结构与职责 |
| --- | --- |
| 根与安全区域 | SafeAreaRoot 的 VLG 只分顶栏、ContentRoot、底栏；安全区域适配器只设置根边界。栏高和间距由此扣一次，不保留另一套手动 offset 算法；栏根独立排序／Raycaster 保持最高交互 |
| 顶栏、底栏 | 父 VLG 分配矩形，LayoutElement 提供原基准栏高、flexibleHeight=0；内部 HLG 分固定功能块与指定伸缩组。两栏不被内容 CanvasGroup 锁定，不能按比例变成隐藏入口 |
| 主界面分区 | ContentRoot 的 flexibleHeight=1；其中 MainColumns 四向填充，用 HLG 分持续同屏的三列，三列高度填满父区；PageHost 为同一区域覆盖层，不参与三列排布 |
| 玩家列表与城市 | 左列 VLG 分玩家区和城市，标题／单项明细提供合理布局输入，城市取得剩余高度；明细自己的 ScrollRect 承担超量内容，不能撑长整列 |
| 中列与右列 | 中列 VLG 分地图、状态和手牌；右列 VLG 分合作、新版牌区、业务页签与正文。标题／页签保留高度，应伸展主体明确 flexibleHeight>0，并传递到背景、框和 Viewport |
| 列表、效果行、资源、按钮组 | 普通行由 HLG，标题与说明由内层 VLG；列表 Content 用 VLG，文字测量提供高度。右侧状态／执行按钮保留宽度，正文承担剩余宽度，不自行逐项设置坐标 |
| 卡牌候选 | 原生 GridLayoutGroup 配置 cellSize、spacing、列数；只在必要时用局部辅助器由可用宽度更新参数，辅助器不排窗口或主界面。超量 Content 在正文内滚动 |
| 所有窗口、抽屉、详情与查看器 | 外壳受 PageHost 约束，VLG 分页头、正文、页脚，正文 flexibleHeight>0、操作区为0；并排区及按钮组用 HLG。窗口不能拖动，正文只在自身 Viewport 内滚动 |
| 城市原图、卡图、装饰及叠加标记 | 用比例约束、相对锚点或等效的局部映射保持原图比例和视觉位置；源图内部坐标可以沿用，不能把它们当作整个屏幕的固定坐标 |

实施要求：

- 每个 RectTransform 的每个尺寸／位置维度明确一个驱动者。不能让 LayoutGroup、ContentSizeFitter 和控制器同时写同一轴，也不能在 `Update`／`LateUpdate` 中把布局结果改回固定坐标。
- 根、列、面板 VLG：childControlWidth/Height=true，childForceExpandWidth=true、childForceExpandHeight=false；中间 HLG：childControlWidth/Height=true，childForceExpandWidth=false、childForceExpandHeight=true。关闭 childScaleWidth/Height；按 07 规范明确各列横向余量和各主体纵向余量，不能依赖组件默认 ForceExpand 让固定项也拉大。
- `ContentSizeFitter` 只用在确需按内容伸展且不会形成父子反馈循环的轴；滚动列表的内容可按内容增高，Viewport 自身必须受父容器约束。`ScrollRect` 和 `RectMask2D` 用于合法的内部滚动，不掩盖整个面板已出界。
- `AspectRatioFitter` 或等效比例布局用于图像区域，避免与父布局争抢同一尺寸；素材 9-slice 的角区和边框仍按 3.5 参数处理。
- 组件挂载后必须实际负责布局。不能保留完整固定坐标脚本，再添加不生效的 Layout 作为交付；也不要求每个装饰图都单独挂 LayoutGroup。
- `CanvasScaler` 负责基础缩放。整套 1920×1080 坐标乘比例、平移整张 HUD 或为每个分辨率加坐标表，不能作为主适配方案。局部可滚动内容、地图和图片自身的导航独立保留。
- 原始绝对坐标可以用于读取基准、推导初始 padding／spacing／preferred size；完成后关系保存在资产配置中。保留必要的局部图像坐标，清理已被布局接管的运行时写入路径。
- 仅在内容、展开状态、安全区域或尺寸改变时触发布局失效。`UiHudColumnsLayout`、`UiPlayerCityLayout`、`UiActionsColumnLayout`、`UiHudBarLayout`、`UiPageSectionsLayout` 等普通结构职责由原生组件接管后删除被替代实现，不能只改类名保留算法。`UiFlowLayoutGroup` 等混排组件只有明确内容语义用途且原生组合不能表达时才保留，写明输入输出和唯一轴责任。
- 全链核对 ContentRoot → 主列 → 分区 → 正文／Viewport → 背景框体；最终需填充的层不能保留阻断高度传递的首选／最大高度或第二驱动器。LayoutElement 配置必须被实际父 LayoutGroup 采纳，不以新增组件数量作为完成依据。

## 4. 玩家明细展开与城市边界

1. 玩家明细仍最多展开一项。展开是主界面内部布局变化，与顶栏的 effect 页面收起／恢复按钮分开。
2. 以当前内容区和所在列的实际高度分配空间：可用明细高度受“列高减玩家标题、间距、城市最小可用高度及其他固定内容”限制。素材中的 224／330 等数值是基准参考，不能直接作为任意屏幕上必然可容纳的高度。
3. 明细超出分配高度时在明细内滚动，预留滚动条空间。城市在剩余区域等比显示；顶端可以按合法展开布局变化，底端始终留在内容区内且不与底栏相交。
4. 先计算标题、页脚、间距与城市／明细最小高度之和，确保支持尺寸可容纳；压缩非必要留白并让明细内部滚动。不能隐藏整列、添加主分区分页、使城市出界／被底栏遮住或裁掉整个城市。低于实际可读下限的尺寸登记未支持，不能擅自换交互结构。
5. 开闭明细、切换玩家、空内容／长内容、明细打开期间改变窗口大小，再恢复 1920×1080，布局须从当前容器重新计算，不能依赖 `Awake` 保存的一套位置／高度继续累加偏移。
6. 用同一坐标空间检查城市、玩家列、内容区和底栏的实际矩形。仅证明 `anchoredPosition.y - sizeDelta.y` 不变、城市高度大于某个固定数，不能证明城市没有越界；还要考虑所有父级缩放与偏移。
7. 城市图像、格位和点击映射使用最终显示矩形及等比留白。世界地图继续承接实际 `mapRegion → SetScreenViewport` 接口；俯视相机改造和 UI-004 最终地图验收依旧按 [05 任务安排](05-地图俯视改造期间的任务安排.md)交接。

## 5. 执行顺序与验证门槛

### A. 先改结构，保持基准位置

完成全量清单和正常 1920×1080 基准后，按基础修正阶段先改根 VLG、常驻栏、三列 HLG 和列内 VLG，再迁移共用行、列表与全部局内页面。同步去掉尺寸触发的主分区导航及其必需引用／测试前提。素材从搭建起放入最终结构，用 padding、spacing、min／preferred／flexible 和内部图像比例复现基准；不先用固定坐标完成整页再补布局。

逐区核对实际资产与当前页面所需素材，确认正确版本、层级、字体和尺寸驱动关系。发现基准位置漂移就先修该区域。完成布局结构、城市边界及基准位置核对后，再推进 UI-007 原有的通用卡牌／选项窗口迁移和新增业务接线；原有行为随结构迁移保持可用。

### B. 适配实现完成后再测尺寸

开始多尺寸验证前，必须已有实际生效的原生结构、尺寸约束、局部换列／滚动及低高度处理；普通结构无手写逐项坐标驱动，主界面没有尺寸换页路径。清理与命名结果按基础修正清单完成，不重新运行历史生成脚本。

先做基准 → 1920×1200 → 一个宽度变化 → 回基准，再检查必要低高度；三主列无需导航保持同屏，布局边界由真实矩形核对。若仍未适配，回到实现阶段，不持续批量截取错误画面。正式图还需当前必需素材、字体与业务状态就绪；布局、删除和命名缺陷不能推给 UI-012 后宣称本项完成。更广的综合业务／设备矩阵按计划交 UI-012。

### C. 验收要证明什么

- **全量结构：** 每个实际局内 UI 有原生层级、每轴驱动者、布局输入与结果；根 VLG／中间 HLG／列内 VLG 真实生效。按比例隐藏列、分区导航及其状态／引用／测试前提均已移除；仅有自定义 Layout 或新共用组件不算完成。
- **1920×1080 基准：** 相同入口、数据、展开状态下比较迁移前后屏幕位置；再验证缩小／放大后回到基准的结果。锚点与局部坐标允许变化，屏幕位置保持一致。截图中的抗锯齿差异不能代替几何比较，也不能以宽松容差掩盖整体位移。
- **动态边界：** 明细展开／切换／关闭、长列表和长文本下城市仍位于内容区内、与底栏无交叠；布局稳定后在同一屏幕或根容器坐标空间检查。只对必要功能边界写测试，不锁死所有可编辑样式；本轮位置保持以用户明确要求的基准为准，不固化内部锚点实现。
- **交互回归：** 两栏始终可交互，唯一页面／effect 收起恢复、草稿、滚动、焦点和事件归属正确；没有重复提交、透明遮罩挡栏或隐藏页拦截输入。所有窗口仍不可拖动。
- **画面与证据：** 在实际使用的同一场景资产／覆盖上验证。截图前确认必需资源和布局就绪；测试通过不替代实际看图。既有多比例截图作为历史证据保留，不能替代本次结构重构后的验收。

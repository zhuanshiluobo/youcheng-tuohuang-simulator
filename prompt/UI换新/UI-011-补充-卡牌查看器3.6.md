## 3. 资产与组件结构

使用按功能命名的 `CardViewer`／`CardViewerView`／`CardViewerProfile` 等现有或最少新增组件，不建立 `Ui011` 生产目录。窗口外壳受 PageHost 限制；图片展示区域、Header、CardViewport、Footer 采用原生布局和明确比例约束。控制器负责模式、数据、事件与页面生命周期，不每帧重写所有子物体坐标。

按钮源 PNG 为1983×793，源可见矩形为(35,102,1916,582)，参考命中区为280×84。按源参数裁切或映射透明边距，使点击区域与可见按钮一致；不能把整张透明画布作为命中范围。普通／悬停／按下／不可用使用配置着色，源包并未提供全套新状态贴图；焦点轮廓独立配置。

静态标题“使用角色牌”“卡牌详情”和按钮／关闭提示存于配置；计谋／策略使用 msyh，其他文字和数字按既定五类字体。汉仪不额外 Bold。不新增卡下编号、重复效果正文、勾选框或素材中没有的选择槽。

## 4. 入口与事件

1. 从快速行动的“使用角色牌”进入 `use-character`。调用方明确传入模式与本机合法卡图、计谋／策略各自可用性和原因；不能根据点击的卡牌类型猜模式，也不能只有一项可用时自动执行。
2. 从设施卡、手牌、弃牌、盖放区查看进入 `inspect`。隐藏操作按钮的显示、焦点和命中；不暴露使用能力。隐藏牌的图像、名称、替代文字及 ID 必须已经过权限处理，不预加载无权查看的正面。
3. 卡面点击本身不选择、不使用、不翻面。点击窗口外、Esc、系统返回及取消按来源返回原正常页面，恢复有效滚动、分页和焦点；窗口不可拖动。
4. 使用按钮复核当前卡 ID、会话状态、真实策略／计谋资格和 pending，调用现有正式角色牌使用／目标选择路径。包内 `plot` 对应计谋、`strategy` 对应策略，明确映射到工程真实符号，不能按按钮索引猜测。
5. 单次使用只走一个事件通道。浏览器回调／DOM 双事件仅为示例，在 Unity 不复制两套命令监听；成功发起后进入真实后续选择或结算，不能把发出事件当成结算成功。
6. 普通取消／关闭只退出查看，不结束一个必须处理的 effect，不等同于第二效果的“结束使用”。第二效果结束／继续仍走其新版选择步骤。过期回包不得关闭新查看页或复活旧流程。
7. 通过唯一页面宿主切换。由 effect 选择页查看卡牌详情时保留有效预选，返回恢复原步骤；已结束请求不恢复。隐藏页释放遮罩、焦点和地图提交输入，两栏保持最高。

## 5. 替换与清理

逐入口登记旧查看路径→本查看器，切换设施卡、手牌、弃牌、盖放及角色使用来源。替换后删除仅为旧卡牌查看服务的重复外壳／监听／配置，不删除规则书或其他图片浏览仍需的通用图片组件。旧翻面、查看提示、上下文按钮已由基础修正清除，不能为本项重新引入。

## 6. 有序验收

1. 先核对源图身份、透明边距和原生布局层级；在1920×1080完成素材呈现与模式对照。普通查看和使用模式的卡图矩形保持一致。
2. 从实际五类入口分别打开，确认按钮显隐和权限；完整卡图、横／竖图都不裁切。两个使用按钮分别验证可用／禁用原因、取消与返回。
3. 经正式角色使用入口发起一次合法操作与对应后续选择，验证 pending、防重入、拒绝／失效处理和返回状态。详情查看不产生业务命令。
4. 布局完成后检查16:10、超宽、低高度及恢复基准：顶底栏可交互、主界面无分区分页、窗口内容可读，内部参照区域和按钮点击边界正确。
5. 记录实际源资产／场景覆盖、素材哈希复用、旧新入口、模式与事件结果、几何／截图证据及规则缺口。原包 QA 中浏览器交互和游戏接入未测试，不能沿用其声明当项目验收。

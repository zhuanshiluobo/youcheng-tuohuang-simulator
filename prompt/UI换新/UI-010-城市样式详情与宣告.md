# UI-010：城市样式详情与宣告

请执行本任务。先读 [共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md)、[05 任务安排](05-地图俯视改造期间的任务安排.md)及 UI-006／007 交付。UI-004 暂缓不阻挡本项独立界面工作；正式宣告前须复用或完成当前城市显示容器的格位映射验证。实际依赖待改地图相机的部分保留待验。

## 目标与范围

将城市样式查看、宣告、标记轨道与城市设施预览迁到新版窗口。处理实际 `CityStyleDeclarationPreviewDialog`、View／输入处理、对应 Prefab、卡图配置与正式入口；保持规则与正式内容定义。

## 阅读入口

- `CityPattern-Layout-v1.0.md`、整理版 `pattern-card-map.json` 及相关状态安全区。
- `CityStyleDeclarationPreviewDialog`、`CityStyleDeclarationPreviewView`、格位与板面输入处理。
- 当前城市样式候选、匹配组合、宣告资格及特殊行动的正式投影／命令路径。

## 工作步骤

按[视觉搭建优先规范](03-视觉搭建优先与分阶段验收.md)先完成整页外框、原卡、状态槽、城市区域、标题和操作区，保证素材完整可见，再核对层级与适配，随后接宣告逻辑。正式截图在素材与布局就绪后进行。

1. 区分 `view` 与 `declare`：查看不建立业务提交，宣告允许预选样式与合法设施后确认。宣告入口和使用样式特殊行动的入口独立，确认不自动发动特殊行动。
2. 卡列表来自当前正式内容与版本，不能写死素材演示中的六张组合。卡面、裁切、状态安全区和版本成组配置，完整 930×600 原图不裁去右侧内容。
3. 按真实投影显示各玩家标记及状态轨道。主动Ⅰ类未使用／已使用两槽、Ⅱ类五槽与额外宣告带的映射需要明确；记录源参数 `zero` 与预览 `exhausted0` 的对应，不修改源文档。
4. 数量标记不误当剩余次数；后续宣告标记不重置使用轨道。若正式状态模型与图包示例不同，保留规则语义并记录映射差异。
5. 城市格位复用当前统一坐标来源，核对本窗口中的实际格位、合法设施、方向及组合；UI-004 未执行时可复用 UI-005／008 的映射证据并补查本窗口变换。确认前不真实旋转设施、扣标记或发奖励；高亮不是规则通过的依据。
6. 确认时复核当前候选、请求、设施可用性、首次／再次宣告条件；处理过期选择、拒绝、取消与返回，后续结算交给共用上下文。
7. 宽屏支持样式与城市并列，紧凑屏使用分段／滚动，保留当前预选和可达确认入口。详情放大保留玩家标记与额外宣告带，低于顶底栏。
8. 样式与城市并列属于同一页面内部区域；完整详情、独立抽屉或子选择通过唯一页面切换，不能再叠开窗口。effect 唤起的页面收起时保留有效预选并停止宣告选点，展开关闭资料页并校验当前请求后恢复；普通查看模式不冒充待结算 effect。
9. 套用五类字体角色，效果使用次数、条件和资源数量使用 NarrowBold，纯 UI 页码使用 wide；普通／强调文字分别用方正／汉仪（关闭 Bold），特殊词用 msyh。

## 验收

- 正式查看、宣告和特殊行动入口职责正确；预览不会提前改变游戏状态。
- 当前实际存在的首次／再次宣告、已使用／未使用与数量组合显示正确，示例中未被规则实现的状态明确标注。
- 城市命中与高亮在不同尺寸、滚动和放大情况下准确，返回后保留仍有效的选择。
- 0／少量／多样式、长说明、多个玩家标记可用；窗口和工具提示不盖住或锁死两栏。
- 同时最多一页；收起后查看其他资料不会改变宣告预选或产生规则提交，展开恢复当前有效步骤与字体角色。

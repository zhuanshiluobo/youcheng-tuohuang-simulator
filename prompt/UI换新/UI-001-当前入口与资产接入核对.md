# UI-001：当前入口与资产接入核对

请执行本任务。先读 [共同约束](00-共同执行约束.md) 和 [实施计划](01-UI更新实施计划.md)。本项只核对并新增报告，不修改 Unity 场景、Prefab、运行时代码或原文档。

## 目标

把“素材是什么版本、游戏从哪里使用界面、业务能力是否已提供、需要改哪份资产”核对到可实施程度，为 UI-002～UI-012 建立基线。

## 阅读入口

- `游城拓荒/UI素材/整理版-2026-09-24/` 的 README、版本关系、资产目录、预览索引、新版组件索引和源包文件索引。
- `Assets/Scenes/SampleScene.unity`、`Assets/Scenes/ThreePlayerScene.unity`、当前构建场景及实际对局加载路径。
- `GameplayInteractionHud.prefab`、`GameplayInteractionHudView`、`GameplayDialogRegistry`、`TabletopCanvasLayout`、`MapCameraGeometry`。
- `ActionPanelController`、`BuildFacilitySelectionController`、`InteractionRequestRouter` 及对应 renderer。
- `docs/设计/基础内容迁移与UI接入边界.md` 和近期实际工作记录；不能只根据旧提示词判断完成情况。

## 工作步骤

1. 记录当前工作区状态和 Unity 版本，区分用户未提交改动。本项的运行检查不得触发任何 UI 重建或保存覆盖。
2. 列出全部对局 UI：常驻栏、主模块、卡牌／选项、建设、企业／科室、城市样式、事件／调度／特殊行动、设置及查看器。每项写出源 Prefab、嵌套资产、场景覆盖、实例化入口、控制器、数据源和当前可操作路径。
3. 建立素材映射：旧角色 → 新组件 ID → 整理文件 → Unity 目标或沿用资产。记录尺寸、九宫格、裁切、透明留白、缺失状态和仅有旧主题的窗口。预览图不作为正式控件素材。
4. 审计实际激活的 Canvas／相机层级、Raycaster、CanvasGroup、遮罩、焦点与拖拽排序。尤其检查扫描所有 Canvas 后取最高值加一的逻辑，列出可能覆盖或锁住顶底栏的入口。同时清点窗口移动组件、标题／背景拖动事件、历史位置恢复及运行时启用路径，包括 `EffectDialogDragHandle` 与 `EffectDialogShellView` 的引用校验，列入后续停用范围；区分需要保留的卡牌拖拽、滚动及地图平移。
5. 跟踪真实操作链：谁提供候选、谁拥有当前请求、谁算报价、谁提交、如何取消／恢复；区分旧主要行动预选和新交互请求。确认两者不会被新入口同时唤起。
6. 逐项核对结算链、可选效果、撤销、企业／科室所需能力。给出“已有可复用接口／需表现适配／缺少规则能力”的证据，不能把演示 API 记成已实现接口。
7. 在安全的既有启动方式下记录两场景基准画面及实际渲染尺寸；条件不具备就明确未运行。测量关键内容最小可读尺寸，形成宽／标准／紧凑布局建议和支持下限候选，不猜测验收通过。
8. 给后续每项列出具体修改目标及共享源／场景覆盖归属。若入口与本计划示例路径有差异，记录真实位置和原因，供后续沿用。

## 交付

新增 `执行记录/YYYY-MM-DD_UI-001_接入基线.md`，至少包含：

- 当前场景与构建入口表，实际资产及覆盖表。
- 素材版本和控件映射表，缺失素材／状态表。
- 层级及输入风险表，旧工作流与新请求的接线图或表。
- 业务能力表、尺寸基线、后续任务目标清单。
- 运行／截图是否完成、证据位置和未验证事项。

## 验收

每个主要窗口都能追溯到真实入口或明确的未实现项；每个后续任务知道要改哪份源资产。原素材、原文档和 Unity 资产内容不变。此任务通过只代表核对完成。

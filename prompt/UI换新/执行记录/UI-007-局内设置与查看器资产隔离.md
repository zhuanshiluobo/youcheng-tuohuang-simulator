## 共享运行时代码复核

- `GameSettingsMenuController.ResetLegacyPanelPosition` 在旧资产父级没有 `UiBoundedPanelLayout` 时，执行本轮前同样的初始化、打开和关闭居中。新引用不是必填项，开始页旧资产没有被要求迁移。
- `ZoomableImageViewerController` 的尺寸、位置保存与恢复都按是否存在 `UiBoundedPanelLayout` 分支；旧分支与本轮前相同。`RefreshViewportGeometry` 仅由局内副本上的 `UiViewerViewportLayout` 调用，原查看器没有这个组件。ActionLog 与 Rulebook 控制器本轮没有源码变化。
- `PromptPresenter` 和 `GameplayDialogRegistry` 的脚本 GUID 在正式序列化资产中只出现于 `GameplayInteractionHud.prefab`。ActionPanel、BuildInfoPanel、CharacterHandPanel 和效果弹窗相关变更也只接入局内资产；没有发现这些变更通过现有 Start / Loading / Collection 资产生效的路径。
- 普通转场虽然使用 Additive 加载，但 `LoadingSceneController.Start` 先等待 `UnloadSourceScenes` 完成，再加载目标场景；旧 `GameplayHudFrame.Active` 在销毁时清空，新设置 Awake 重新注册自己的 Zoom Prefab。正常转场下不会同时使用两套设置来源。

已确认的兼容边界：旧 `GameplayPromptView` 缺少 `UiPromptLayout` 时仍可绑定，但长文本不再执行原代码的高度计算；旧 `GameplayDialogRegistry` 缺少 `effectRowPrefab` 会直接校验失败。当前仓库非局内正式资产不使用这两个组件，因此这不是现有开始页／加载页／藏品室回归；也不能据此声称所有未迁移的自定义局内 HUD 都兼容。另，Zoom 的动态实例注册仍是单个静态 Prefab，手动同时打开多套设置场景时由最后 Awake 的来源决定，这种编辑器多场景共存不在本次正常转场验收范围内。

## 构建前检查的实际来源

复核发现隔离后 UiTheme、EventCharacter、CityStyleSpecialAction 三个 readiness 仍以原 Settings GUID 校验 SampleScene，会把正确的局内副本误报为缺失；Facility readiness 也只检查原共享源。经 root 授权已修复：新增只读 `GameSettingsAssetSources` 映射 Start → 原源、Sample / ThreePlayer → 局内源；四个 gate 均检查两套 Bootstrap，三个场景连接检查跟随实际来源。原来的场景启用、组件删除、组件禁用和目录覆盖拒绝规则保留。

新增 4 个 `Ui007InGameAssetIsolationTests.BuildReadiness_AcceptsSeparatedSceneSourcesWithoutSavingAssets` 用例，实际调用四个只读 gate，并比对前后 8 个 Prefab 与 3 个场景字节。未调用生成器或保存接口。这 4 个新增用例已在最终统一 EditMode 中全部通过。

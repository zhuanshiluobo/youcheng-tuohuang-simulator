## 条目与数据接线

`UiEffectRowView.Binding` 接收稳定条目 ID、请求 ID／版本、模式、右侧状态、显式 enabled、pending、标题说明、来源、资格、费用影响、不可用原因、报价状态和 0～2 个标记。报价分等待、有效、不可支付、失效、需补目标；没有正式费用值时显示等待状态，未写成零费用。正文按钮和右侧操作按钮拥有独立监听：仅 `Status.Use`、显式 enabled、未 pending、请求仍有效且存在执行回调时可执行；复用时清理旧监听。单色标记使用绿 1／黄 2／蓝 4／红 8 的 mask 1～15，数量 0 保留；组合色说明并入详情。该行只负责表现和守卫，**目前没有把三种模式全部接入正式规则数据和命令**。

`GameplayMainModules.Render` 仍优先使用 `GameStateView.Players` 的玩家可见投影，沿用公开姓名、分数、手牌**数量**和已宣告城市样式**数量**；不显示对手暗牌 ID。明细宿主通过 `GetOpponentDetailHost(playerId)` 和 `SetOpponentDetailCount(playerId,count)` 留给今后的可见效果投影适配器。席位换人时清理旧动态行。当前 `GameStateView.Players` 没有永续效果条目列表，因此真实对局只出现“暂无可查看的永续效果”，不能把组件诊断图中的合成公开席位视为实际对局数据。空态展开量 108；有条目预留 224，并以城市最小高度 330 限制。城市下缘保持固定，板图等比缩放；明细使用独立 ScrollRect、Viewport 和滚动条。

快速行动 `使用角色牌` 使用 UI-005 原 Button 和 `TurnActionPanelPresenter` 可用性，**未新增第二个命令入口**。`EffectDialogOptionRowView` 仍沿用原整行草稿选择／确认回调，3.4 右图仅装饰；不能据图标将原确认流程改成立即执行。设施、角色、事件等现有 renderer 继续保留各自业务语义。

## 结算上下文与收起恢复

`GameplayHudFrame` 订阅 `InteractionRequestRouter.RequestRouted`，从真实 `InteractionRequestProjection` 取 `InteractionId`、`StateRevision`、`OwnerEffectId`／`SourceNodeId`、`MinSelections`、`MaxSelections` 和 `AllowDecline` 更新底栏摘要。`AllowDecline` 仅显示“可跳过”，不推断此请求属于可选效果。请求版本降低的旧投影被忽略；同一流程切换下一步骤时 effect 页继续保持收起，展开时恢复当前步骤；请求结束清理恢复目标。收起／展开只改变页面可见性和焦点，不发送规则命令。资料页、设置页与 effect 页沿用 `GameplayHudFrame` 的唯一页面管理。摘要语句配置为可序列化字段，动态数字由请求投影生成。

当前 `InteractionRequestProjection` 只有单个请求及候选集合，**没有全局必要链、可选效果列表、来源／资格／通用报价、跨请求 pending 或撤销能力投影**。因此本次没有把候选 ID 伪装成两条效果列表：独立结算抽屉、两组正式独立滚动区、多步骤链总览、通用效果报价、复杂子选择回返及拒绝回包的端到端测试均尚未接入。现有效果页和结算摘要槽可继续使用，但不能认定 UI-006 的完整结算业务已完成。`BuildFacilityOptionQueryService` 仅对设施建设提供报价，不能当作通用效果报价。

UI-005 原 `Undo Button` 的 3.2 外观和禁用状态保留。Domain／Application／Presentation 未发现撤销命令、能力或正式回包；按钮未启用，也未修改本地 `GameState` 伪造回滚。原 `结束本回合 Button` 仍由 `EndCurrentAction → TurnActionPresenter` 正式提交，可用性受原规则投影控制。撤销的可用／成功／拒绝分支目前无法实测。

## 后续接口约定

1. 规则／会话先提供玩家可见的结算链、可选效果、稳定条目 ID、来源／资格／费用、正式 Quote 状态、统一 pending／拒绝及撤销能力和结果；客户端再把它们适配到 `UiEffectRowView.Binding`，不能从素材样例或当前候选 ID 推断规则。
2. UI-007 可经 `GameplayDialogRegistry.InstantiateEffectRow(parent)` 复用选择条目，但保留现有草稿／确认语义，并在更换 renderer 时移走旧提交监听。UI-011 处理其余专用效果窗口；UI-008～010 按各自的目标和费用语义接入。卡牌网格和资源数量编辑器保留自己的控件。
3. 投影增加公开永续效果后，在 `GetOpponentDetailHost` 中实例化只读行并回填数量；不能从本地完整 `GameState` 给客户端对手明细补秘密信息。通用结算区接入前，需要确定必要链与可选效果的真实归属以及两个滚动宿主，之后再做长列表／报价／取消／拒绝／旧响应端到端验收。

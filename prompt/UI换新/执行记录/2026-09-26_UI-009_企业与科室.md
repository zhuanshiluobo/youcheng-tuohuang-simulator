两个新窗口不是旧窗口改位；项目此前没有其运行基准。素材示例窗口 `(88,68,1744,944)` 原本侵入常驻栏，因此以实际 `ContentRect` 为边界：页根 VLG 控制 Panel，Panel VLG 分 Header／Body／Footer；窗口宽度首选1744，由父容器约束，高度使用内容区余量。原主界面三列没有移动。

## 草稿、提交合同与生命周期

`Workflows/EnterpriseSelectionDraft` 是表现草稿，不是规则状态机。查看与选中分离；稳定目标 ID 在同请求刷新和重排后保留，删除或失去资格后清理；点击不可用目标更新原因并清空待选。普通升级行不生成特效目标，科室2～5级仅原图说明与只读等级。

`EnterpriseSelectionDialogView.BindSubmission` 仅为后续真实 adapter 留出接点：提供“当前投影查询／提交意图／合法取消”。确认必须同时具备 `SubmissionAvailable` 和实际提交委托，点击时再次查询请求 ID、版本、模式及目标；版本变动后先刷新，要求用户重新确认。没有宿主时显示资产中的缺规则提示，确认禁用。组件不计算费用、不扣资源、不发奖励、不关闭为假成功。

`TryBeginSubmit` 防重入；`Complete` 按同一意图对象、请求 ID、版本和代数接收回包。拒绝使用新投影刷新；旧请求回包不能关闭新页面。隐藏的 page 不接受选择或确认。`GameplayHudFrame` 继续负责唯一页面、effect 收起和两栏输入；新增 `ReleasePage` 仅解除指定已结束页的恢复引用，不改当前规则请求。普通查看不登记 effect；同请求刷新不强制弹回，展开时复核绑定投影。原板详情明确返回后恢复草稿和有效焦点。

## 后续正式接入所需交付

规则层需要先提供企业／公共科室的稳定身份与公共状态、企业合作等级、玩家可见候选、可触发特效及原板目标映射、资格／原因／支付投影、请求所有者和版本、取消权限、正式回答／拒绝及复杂子步骤。接入时继续沿用 `InteractionRequestRouter`／Host AnswerInteraction 和现有结算上下文，不能把本项诊断投影或素材 demo ID 当作领域 ID。

四种模式均未执行“真实入口→查看→预选→详情→返回→正式支付／确认／取消”，因为这些正式入口和宿主规则当前不存在。多人回包、重连、真实开局科室、企业升级奖励、特效目标子步骤、公共科室奖励、设备触摸／手柄也未验证。组件测试和实际运行截图不能改变这些边界。

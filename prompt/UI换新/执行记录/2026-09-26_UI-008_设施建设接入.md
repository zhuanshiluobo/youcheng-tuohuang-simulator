## 盖牌选择

- 实际入口：`MobileCityInteractionController.RefreshCharacterCoverSelection` 在真实 `CharacterCover` 阶段调用 `CharacterCardPanelPresenter.BuildView`，只投影本机有资格盖放的手牌；`CharacterCardEffectChoiceDialog.ShowCoverSelection` 使用 UI-007 共享 `EffectDialogShell` 的卡牌选择、选中、详情和确认流程。
- 正式提交：确认时重新检查阶段、玩家、卡牌 ID 和 `CanCover`，再用 `CreateCoverCommand` 经 `SubmitCoverCharacterCard` 提交。拒绝／本地应用／权威快照会按命令 ID 解除提交锁；迟到的其他命令回包不能解除当前锁。阶段、回合、游戏或候选上下文变化会使旧回调失效。预选、详情和空候选不写游戏状态。
- 页面管理：盖牌使用独立阶段页面登记，不冒充 effect；详情返回及关闭其他资料页后恢复阶段页。重复刷新保留当前页面及有效预选。
- 清理：移除 `CharacterCardCoverDragCoordinator` 及其 `.meta`、手牌盖牌拖放接线、旧命中区／悬停盖牌入口和待提交鬼影流程。手牌内部排序、查看与其他拖放职责保留。
- 资产来源：实际对局使用的 `GameplayInteractionHud.prefab` 中角色手牌面板实例；没有调用编辑器生成器。两张对局场景只清理已移除资源板的序列化引用，没有重排场景结构或坐标。

## 右栏高度（按左栏做法修正）

- 根因：左栏 `UiPlayerCityLayout` 每次读取实际列高并分配子区；右栏原来用固定最小高度叠加出 906，再用整列 ScrollRect 裁切。2560×1080 时右列可用逻辑高度约 761.31，因而底端超出；把整列滚到底只会改为遮住合作标题，这个结果不算通过。
- 已在实际 `GameplayInteractionHud.prefab` 移除整列 ScrollRect、纵向 ContentSizeFitter／临时 UiFlexibleCanvasContent 与旧 VerticalLayoutGroup。中间容器直接上下拉伸至父列，由 `UiActionsColumnLayout` 按当前高度分配合作、牌区、页签、行动区；没有通过移动整列解决遮挡。
- 合作正文、行动页签正文各用自己的 ScrollRect／Viewport；页签、分区标题、牌区及行动背景留在固定分区中。高屏余量交给行动主体；短屏先压缩合作正文与预留空间，必要时使用分区内滚动。弃牌／盖牌缩略图复用左栏同一个 `UiAspectContentLayout`，保持卡图比例。
- 先检查了两场景 1920 → 2560 → 1920 的 6 组修正截图。2560 下企业合作标题、牌区、页签、全部三排行动按钮同时可见；原 1920 的右列、合作区、牌区、页签、行动区、两张卡槽及合作空态矩形与首轮基准的最大差值均为 0 像素。
- 逐图复核还发现提示卡 RawImage 随主体任意拉伸。已让 UiActionCardContentLayout 按实际纹理比例居中适配，实际 HUD 绑定 cardImage 引用；两场景 1920 → 2560 → 1920 的 6 组 `UI008-RightColumn-HintAspect-*` 取证已完成并检查宽屏画面。提示状态以此组为最新证据，早期 Verified 中的提示截图仅保留布局边界记录。
- 早期 `UI008-RightColumn-Final-*` 整列滚动截图已判定不满足要求，不作为通过证据。有效修正预览为 `UI008-RightColumn-Corrected-*`，后续完整取证使用 `UI008-RightColumn-Verified-*`，捕获前强制检查各分区均位于右列内、列内容高度等于可用高度且没有整列 ScrollRect。
- 截图加载实际场景和实际源 Prefab，采用右卡 smoke 状态检查布局；它不替代真实盖牌或正式建设成交的业务验证。没有运行 UI 资产生成／保存工具。

## 旧控件迁移与清理

### 资源计数器

- HUD 顶栏 `Resource Values` 原有五个资源 chip（源岩、源石碎片、异铁、至纯源石、金券）现在由 `GameplayMainModules` 接收本机资源状态并更新数字；`RefreshResourceCounter` 不再在旧资源卡板为空时提前退出手牌、盖牌与建设刷新。
- 从局内 HUD 移除旧 `ResourceCounterBoard` 嵌套实例和控制器／场景字段引用；其独立源码、Prefab 和布局资产保留，因为编辑器素材构建代码仍引用它们。此保留不代表局内仍显示旧计数器。

### 翻转按钮

- 原卡面翻转控件改为上下文操作按钮，资产对象名及自动化 ID 改为 `Action Panel Context Button` / `action.context`。文案从 `ActionPanelLayoutProfile` 读取：主行动面“查看提示”、卡牌面“返回行动”、第二效果决策“结束使用”。结束动作仍走原 `FinishCharacterUseButtonClicked` 正式决定流程，没有自动结束或自动继续。

### 弃牌区

- HUD 的 `Discard Region` 现显示本机弃牌数，并提供只读预览入口。数量来自 `CharacterCardPanelPresenter.BuildView` 的本机 `DiscardCards`；详情仍由现有只读卡牌预览和大图查看器展示，并保留原本的权限范围与页面关闭顺序。
- 删除手牌面板内旧弃牌按钮、角标、Icon 和 Count Badge 节点，移除对应布局字段、View 引用和无效 HUD 覆盖；预览窗口本身保留为新 HUD 入口调用的只读页面，不再作为手牌区固定控件出现。

## 建设与报价

- 主要行动建设入口现在按“正式候选 → 城市槽位 → 支付方式 → 只读报价确认”呈现。设施候选来自 `BuildFacilityDraftViewModel` / `BuildFacilityOptionQueryService`，不可建设候选可查看但不能选；旧外部供应区在新流程期间隐藏，城市板继续作为位置预览。
- 位置、资源／金券支付状态和当前 `EffectiveResourceCost` 均来自正式建设草稿与查询；报价显示设施原始资源成本、当前调整后成本、金券费用和错误／有效状态。确认前复核当前玩家、行动阶段、草稿、槽位和支付资格；支付能力失效时停留在支付步骤，放置失效时回到槽位选择。提交仍走 `TurnActionPresenter` / `BuildInteraction` 的正式建设命令，并遵循原 pending、拒绝及同步处理。
- UI-007 的城市格位资产记录确认底图与原 12 个城市板格位位于 `GameplayInteractionHud` 的 `Player City Column/City Region/City Board Artwork`，槽位使用 `CityBoardSlotIndex`。新窗口枚举正式查询返回的索引，不改地图相机或另外推导一套格位映射。
- **其余建设入口边界**：设施入场效果授予建设及储备／延伸枢纽保留现有 `FacilityInteractionUiCoordinator` / 正式效果请求与回答链；它们不进入本次主要行动建设草稿，也没有在本记录中改写规则费用或效果次数。未运行实际效果赠建与储备路径，因此其与新主要行动页的统一视觉和端到端状态仍待对局验证。

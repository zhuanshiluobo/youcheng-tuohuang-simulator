两场景各只有一个 `EventSystem`；常驻栏有独立 `GraphicRaycaster`，主界面有自己的 `GraphicRaycaster`。外框、标题装饰和卡槽边框不拦截点击；主区域底图和地图外侧遮挡层阻止指针落到旧桌面。`UI003 Main Surface` 内的绘制顺序为地图外侧底图 → `Outer Frame` → `Main Regions`，使对手席位、我的城市及右侧模块边框完整盖在外框之上。地图相机的 `pixelRect` 随中央地图区域更新；两张地图源预制体分别保存 `framedViewportZoom: 1.2`，恢复用户要求的初始缩放。旧设施供应槽显示时使用全屏 UI 射线模式，避免中央地图相机的 `pixelRect` 排除左侧槽位。

布局按安全区域和实际栏高扣除 `ContentRect`。阈值在 `GameplayHudFrame` 序列化配置：宽屏阈值 1540、紧凑宽度 1060、紧凑高度 670、回滞 24；宽／标准／紧凑采用不同栏高和摘要长度。1920×1080 保持 Frontier 基准构图；1024×768 等宽度受限且高度足够时，用下方“左侧信息／地图／行动”分区导航横向移动整页，让各区以较大尺寸分别可达；900×600 高度受限时保持三列整体缩放，不裁掉任何区域。分区导航三按钮的实际射线命中和左右两态截图均已核对。

## 3. 阶段 C：主框架逻辑复核

- 顶栏回合、总回合、阶段、红区开放轮次、当前玩家旗标与底栏行动摘要使用已有 `GameState`／`ActionPanelViewModel`。结束行动按钮与原 `ActionPanelView.EndRoundButton` 是同一实例；撤销因没有规则能力持续禁用并显示原因。
- `GameplayHudFrame` 保留当前 effect 请求 ID／revision 和被收起页。资料 A 切到资料 B 时仅保留一张可见页；同一请求刷新不自动弹回 effect；展开时调用设置、日志、查看器或弃牌页的关闭入口，避免控制器只隐藏画面却保留“打开中”的内部状态。实际 effect 壳 → 设置 → 日志 → 展开的 PlayMode 用例检查日志控制器真正关闭、effect 壳恢复。
- `EffectDialogDragHandle` 和折叠面板的外窗拖动不改变面板坐标；内容内卡牌拖拽、列表滚动、图片平移仍由原交互负责。顶底栏在实际 effect 壳和设置／日志页上仍可被射线命中。收起 effect 时保存其选项焦点，展开后返回原选项；键盘选中顶栏设置按钮及焦点返回的测试通过。
- 两场景 HUD 来源核对见[场景来源审计](证据/UI003-场景来源审计.txt)。UI-003 没有保存两张场景的覆盖。地图视口缩放修改分别落在 `MapView.prefab` 与 `map-three-players.prefab` 两个源资产；三人地图场景已有的缩放覆盖保持原样。

建设回退的早期诊断测试在非建设状态跨帧强行打开旧 View，下一帧被正常同步隐藏，因此留有失败的诊断 XML。随后确认旧设施供应槽在可见当帧可命中，并把正式显示条件改为“存在可拖动设施候选或已有建设草稿”；最终四项验收通过。旧 View 只是迁移期入口，不能作为新版建设视觉完成的证据。

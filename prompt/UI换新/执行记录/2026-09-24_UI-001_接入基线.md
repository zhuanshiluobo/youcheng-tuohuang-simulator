## 7. 尺寸基线与运行证据

- **实际画面／渲染尺寸：未取得。** 本轮没有启动 Unity、没有两场景截图、没有窗口尺寸切换或 DPI 测量；没有可声明的最小可读字体／命中尺寸实测结果。`ProjectVersion`、场景 YAML、Prefab YAML、素材 PNG 和预览都不是运行截图。未运行原因是当前无 Unity 实例及经过核验的不执行 UI 重建／保存覆盖的图形启动与截图流程；为遵守 UI-001 的资产只读范围，本轮只做静态核对。
- 静态参考：现有屏幕 Canvas `CanvasScaler` 为 1920×1080，match 0.5；Frontier 顶栏位图 72 高、底栏 96 高。若直接按 1920×1080 构图，未计安全区／栏间距的内容高度为 `1080−72−96=912` 逻辑像素；这只是**布局预算草算**，非当前实际 UI 占位或可读性测量。旧专用弹窗外框到 y=1012，而新版底栏从设计 y=986 起，存在至少 26 像素设计重叠，需要重排。
- UI-003 的模式建议：宽屏按内容区能容纳全部首选尺寸判定；标准按地图、两侧模块和窗口最小尺寸之和判定；任一轴不足即紧凑，侧栏折叠成可访问入口，弹窗分段和内部滚动。阈值应由 UI-003 的序列化布局配置在实际画面测量后确定，不能从 1920×1080 预览硬编码。初始支持下限**候选**为 1280×720，仅供 UI-012 首轮检验；若中文、按钮或地图内容不能可读且可达，应提高下限或进一步重排，尚未承诺通过。建议以 1920×1080、1280×720、1024×768、2560×1080 和 960×540 压力样本记录实际渲染矩形、DPI、最小文字及命中框。
- 图片比例应按原图：设施 12:17、企业 13:37、科室 129:250、城市样式 31:20。城市板 2059×3801 的 12 格按源内容坐标（列起点 100/730/1360，行起点 156/1036/1916/2796，每格 600×850）映射；等比留白、实际 Rect 和相机转换需由 UI-004 真实画面验证。

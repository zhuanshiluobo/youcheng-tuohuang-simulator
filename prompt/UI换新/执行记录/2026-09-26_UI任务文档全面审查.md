# UI 任务文档全面审查与执行顺序修订

日期：2026-09-26。范围：`prompt/UI换新` 当前全部任务文档及 `prompt/README.md`。依据：用户本轮关于原生布局、任务编号命名、旧 UI 清理和移除比例换页的四项纠正，以及此前的素材优先、单页面、窗口不可拖动、字体与正常 1920×1080 位置保持要求。

本记录是文档审查结果。当前代码与实际 Prefab 只用于定位问题，没有在本次审查中修改 Unity 资产或执行游戏测试。

## 1. 结论与下一步

原任务文档确实允许了不符合最新要求的实现：只说“使用布局组件”却未限定普通结构的原生行列关系；共同方案允许紧凑模式隐藏主列并导航；旧 UI 清理允许因仍有调用而继续保留。后续测试又维护了这些行为，造成反复修局部高度和截图入口，而根结构与清理范围没有统一。

当前先执行[局内 UI 基础修正提示词](../局内UI基础修正执行提示词.md)，完成后继续 UI-009～UI-011。原 12 个任务编号与业务成果保留；UI-004 继续等待俯视改造。新增 CardViewer 3.6 归 UI-011，使用[详细补充](../UI-011-补充-卡牌查看器3.6.md)。

主结构明确为：根 `VerticalLayoutGroup` 排上／中／下；中间 `HorizontalLayoutGroup` 排左／中／右；每列内部再使用 `VerticalLayoutGroup`。左右并排需要横向布局组。原生组件还必须正确设置每轴 min／preferred／flexible 和扩展参数，并移除旧坐标写入者，不能靠添加组件自动解决所有溢出。

## 2. 只读审查发现

以下为审查时的实际路径与事实，后续实施若已改名，应通过映射查找；本表中的路径保留作为历史证据。

| 问题 | 依据 | 本次文档决定 |
| --- | --- | --- |
| 原适配方案主动允许改变主界面结构 | 审查前 00／01 允许紧凑模式折叠侧栏或分段；04、UI-005／006 补充把“行动分区／4:3 分区”列入验证步骤 | 当前正文撤销这些条款，三主列在支持比例始终同屏，只允许真实业务页签与内容内部滚动／分页 |
| 主列按宽度只显示一列 | `Assets/YC/Presentation/Ui007/UiHudColumnsLayout.cs` 的 `compactWidth = 1440`、`IsCompact`、`SelectSection`、`RefreshVisibility`；后者按选中索引 SetActive | 删除整套阈值、显隐、导航及调用链，不能只为 16:10 打补丁或降低阈值 |
| 框架为主分区导航另扣高度 | `GameplayHudFrame` 的 `ApplyMainRegionLayout`、`compactNavigation`、`SelectCompactSection` 与导航事件 | 根原生布局只分配一次顶底栏和内容区；导航节点、字段、校验及额外高度全部退出 |
| 有布局计算，但普通结构仍由专用代码排坐标 | `UiPlayerCityLayout` 手算玩家／城市分配；`UiActionsColumnLayout` 手算合作／卡区／页签／行动高度。UI-008 记录明确写明移除旧 VLG 后换用该组件 | 普通列结构改回原生 VLG；内容测量只提供布局输入，地图映射、卡牌扇形等专用内容算法可局部保留 |
| 局部固定最小高度和实际可用高度冲突 | UI-008 记录右栏原最小高度总和 906，而 2560×1080 时实际逻辑高度约 761.31；整列滚动曾遮住合作标题 | 逐轴记录尺寸责任与最小值总和；正文取得余量并在本区滚动，禁止整列滚动／增高／平移 |
| 旧翻面改名后仍存在 | HUD Prefab 的 `Action Panel Context Button`；`ActionPanelController.Flip`、`OpenHintCardViewer`；ActionPanelView 旧引用与 `ActionPanelLayoutProfile` 的提示／返回文案 | 明确删除旧按钮、提示卡面、查看路径、占位、字段、监听与维护它们的测试。真正第二效果继续／结束迁入新版 effect 选择步骤 |
| 旧资源计数器独立资产仍保留 | UI-008 记录仅移除局内实例，因编辑器引用保留源文件和 Prefab；`Ui003VisualBuilder` 仍查找 ResourceCounterBoard | 同步清理废弃生成分支，迁移真实资源／手牌／建设刷新后删除独占旧表现依赖，不能以旧工具引用作为长期保留理由 |
| 新弃牌入口仍调用旧预览壳 | UI-008 记录保留 CharacterHandPanel 内 DiscardOverlayObject；旧 View 字段和 OpenDiscardPreview 路径仍承接新版入口 | 保留正式弃牌数据和新版 Discard Region／Count；新只读列表／详情承接业务后，删除旧嵌套壳、引用及监听 |
| 生产命名混入任务编号 | `Presentation/Ui002`、`Ui005`、`Ui006`、`Ui007`；HUD 的 `UI003 Main Surface`、`UI007 Prompt Frame` 等，以及 Editor／测试名称 | 按功能重命名生产文件、目录、类型、物体、工具和测试，保留 .meta／GUID、fileID、类型／字段兼容与实际场景覆盖 |
| 名称依赖已经干扰验收 | UI-008 记录捕获器找 `UI003 Main Surface`，SampleScene 场景覆盖为 `Main Surface`，导致误报未激活 | 名称迁移同时核对硬编码路径、场景覆盖、动画和自动化；测试读取实际绑定的同一资产来源 |
| 历史测试维护了错误入口 | `RuntimeUiLayoutTests` 验证 ContextButton 专用行；城市样式测试通过前先切“行动”分区 | 删除保护废弃表现的约束，验证真实新入口和三列同时可用，不删必要业务断言来换取通过 |

这里没有将“存在自定义 Layout”简单等同于完全没有效果：当前组件确实分配尺寸，UI-008 也修掉了部分越界。问题是普通结构未按用户要求采用可维护的原生布局，且主分区换页和旧控件仍被当作有效方案。新的完成标准必须同时覆盖结构、行为和清理结果。

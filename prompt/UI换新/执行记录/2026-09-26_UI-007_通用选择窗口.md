## 范围修正与回退

用户在执行中明确：只修改局内 UI，回退非游戏中界面的改动。已据此修正两份提示词。启动菜单、加载、房间大厅、收藏室不计入交付范围；本轮对它们的场景、预制体、控制器及专用布局代码撤回。开工前已有修改和 UI-006 历史证据保留。

共回退 8 个文件：5 个直接涉及非局内的场景／控制器／预制体，加 3 个共享窗口源。8 个文件均与已核实的开工基线逐字节一致，见 [回退哈希校验](证据/UI007-非局内回退校验.json)。StartScene 补回 34 条场景覆盖、保留原 81 条，合计 115 条；原有 3 条 Cover Frame 覆盖一并保留。原 Rulebook 源没有改动，不计入回退数量。

设置、日志、规则书、图片查看器同时存在局内和局外入口，因此局内迁移资产与原共享源分离。实际对局场景必须使用局内来源，启动场景继续使用原来源。之前生成的非局内截图及离线测量仅记录诊断过程，已撤出验收；其中零缩放 Canvas 得到的零矩形比较无效。

## 所有局内 UI 的布局重构

实际入口与尺寸驱动者逐项见 [UI 清单](2026-09-26_UI-007_UI清单审计.md)。清单中的 S01～S10 是已撤出本轮的历史审计项，不属于未完成交付项。

- 常驻栏、安全区域、内容区与三列分配由局部布局组件负责，CanvasScaler 只承担基础缩放；窄宽度使用分区导航，列表内部滚动。
- 玩家列从当前可用高度分配席位、展开明细和城市，最多展开一项；长明细内部滚动，低高度保留展开视口。城市原图和 12 个格位使用同一最终显示矩形。
- 城市格位仅解包共享 HUD 内的 BuildInfoPanel 嵌套实例，保留原对象、引用及交互；独立源与实际共享 HUD 内的设施供应均迁移，不能以未修改源替代实际实例验证。
- 手牌扇形、卡牌拖放、图片缩放平移保留局部内容交互。手牌预览、弃牌、设施和城市样式供应使用网格与受限滚动区。
- 行动组、效果行、动态提示、局内设置、日志、终局、调度、城市样式预览和事件窗口各有明确的页头、内容、操作区及尺寸驱动者。动态提示的滑入动画与静态外部容器分离。
- 终局页使用独立内容页 Canvas，首次激活后配置正确排序，保留旧回合轨道层级和窗口首选尺寸。摘要与详情均在新增透明 viewport 之后，详情返回不再被其拦截；玩家列表和计分公式在各自原槽内滚动。
- 迁移入口只在本轮明确资产修改步骤手动调用；普通启动、测试、捕获和构建不调用迁移、生成或保存覆盖入口。

## 基准、差异及资产归属

开工时已在两张实际对局场景采集 1920×1080 基准，文件为 `证据/UI007-Before-{SampleScene|ThreePlayerScene}-1920x1080-actual-1920x1080.{png,json}`。比较的是实际场景及有效覆盖。

最终复核见 [HUD 独立审查](证据/UI007-HUD布局独立审查.json)。两场景各有 399 个开工活动对象，395 个可唯一配对：316 个差值不超过 0.02，79 个差异逐项保留。79 个包括 Main Regions 父容器 1 个、城市原格位子树 27 个、设施供应 25 个、城市样式供应 19 个、旧桌面容器 7 个。常驻主 HUD 的内容区、地图框、城市原图和提示矩形未出现新增漂移。另 4 个同路径 Rivet 只能按矩形集合核对一致，不能冒充逐对象唯一配对。

两个场景从最终 1920 缩放至其他尺寸、再恢复 1920 后，各 420 个唯一配对对象全部无超阈值差异，另 4 个 Rivet 矩形集合一致。常态截图未显示旧供应；其中 50 个差异对象位于隐藏的 BuildInfo CanvasGroup，另一个只是 Tabletop Canvas 矩形。捕获 JSON 未逐项记录运行时 alpha，因此此可见性判断依赖源资产、正式调用流程和实图，不能写成逐节点实测结果。显式打开供应时，旧供应区移入 ContentRect 属于修复原遮挡最高栏的缺陷。

旧城市格位位于另一 WorldSpace Canvas，原图与输入不在同一显示矩形；迁移后的子树坐标改变作为缺陷修复明确记录，不冒充原叶节点位置全保持。地图继续使用 `mapRegion → SetScreenViewport`；本轮补布局完成后的视口及周围遮罩刷新。实际透视地图的取景与开工截图存在差异，边框同位不等于地图图像相同，不能宣称全画面像素保持一致；地图俯视方案和 UI-004 最终世界选点验收保持独立。

## 通用选择与正式请求

|入口|展示与提交语义|
|---|---|
|CharacterAbilityInteractionUiCoordinator|卡牌／普通单多选及资源出售；草稿与确认分离|
|FacilityInteractionUiCoordinator|设施目标、数量及普通选择；统一 AnswerInteraction 协议|
|MapEffectInteractionUiCoordinator|明确可立即执行的分支使用 UI-006 效果行右侧 use；整行不再重复提交|
|EventCardInteractionUiCoordinator|保留事件七模式及内部步骤；正文、付款路线、收款人和建设列表由局部布局驱动|

四个 renderer 与统一 router 使用同一可见请求来源。客户端有 `session.View` 时只消费 `View.Interactions`，不会回退隐藏主机 State；本地兼容路径先做玩家权限投影。当前请求的身份、revision、候选和权限参与点击及提交校验。

同一请求刷新或拒绝保留仍有效的草稿与滚动；新请求清理旧阶段。确认／取消共用提交锁，空或无关回包不能释放当前锁。详情按钮与选择分开，过期详情返回不能关闭新查看器或复活旧请求。effect 收起、资料页与恢复由唯一页面宿主协调。

出售数量为整数并限制在当前库存及候选允许范围，全零禁确认，明确结束允许零成交。预计收入使用正式 ResourceSaleService 价格；真实收入读取已完成效果的整数结果：`Revenue → EffectStepResult → GameStateView.Effects.NormalizedResult → session.View → UI`。只显示本人可见的最近真实成交，零收入显示 0，不从余额变化推算，也不把不完整历史称为本局累计。

## 窗口与字体

EffectDialogShell 使用受限外框、标题／说明、滚动内容、摘要和独立操作区。卡牌网格按可用宽度换列，详情操作独立，选中框按原透明留白映射卡面。资源编辑器可在窄宽度换行；普通选项禁用旧装饰箭头，立即执行使用独立效果行。

静态模式文案保存在 Profile／Prefab；正文方正、强调汉仪且不 Bold、特殊词 msyh、效果数量与收入 NarrowBold、纯 UI 数字 wide。窗口标题、背景和边缘不拖动，内部 ScrollRect 与卡牌拖放保留。

- 回归过程中修复了隐藏窗口销毁后的残留滚动回调、透明空槽的射线网格和旧供应区越过顶栏的问题。EditMode 拖放夹具补齐真实 Canvas 渲染与 Raycaster 注册生命周期，继续通过 EventSystem 检查实际首个命中；删除的旧样式断言只涉及用户可编辑的固定锚点／尺寸和已过时的入口结构，不替代交互断言。
- 通用组件完成 15 组画面与几何捕获，覆盖卡牌、资源和选项的 1920×1080、1024×768、900×600、末项及回到基准状态；已复核卡牌和选项末项、资源操作区代表图。这些使用明确标注的诊断数据，只证明实际资产布局，不代表正式规则结算或联机端到端通过。
- 局内设置、日志、城市样式预览已完成 1920→1024→1920 实图与恢复比较：85 个唯一对象四轴差为 0，6 组重复路径按矩形集合核对一致。空日志画面不代表长列表验收。

- 两张对局场景最终主画面完成 12 组捕获（五种尺寸及恢复基准），另有 5 组展开／窄屏分区状态；与开工基准及恢复后的几何差异见上文。历史或已撤销范围的截图不计入通过结果。

## 正式入口和提交所有者

```text
第三业务页 UiMainActionTabs.Select(2)
├─ BuildInfoPanel.CityStyleClicked(id)
│  → MobileCityInteractionController.OnBuildInfoCityStyleClicked
│  → TurnActionPresenter.OpenCityStylePreview → CityStyleInteraction.OpenPreview
│  → view 模式：选择卡 → 查看原卡/返回列表；不提供 ConfirmSelection
└─ ActionPanelView.DeclareCityStyleButton（保留原按钮与监听）
   → OnDeclareCityStyleClicked → BeginDeclareCityStyle → CityStyleInteraction.BeginDeclare
   → declare 模式：选择样式 → 点击/拖选有效城市设施 → 详情/返回 → 确认
   → CityStyleSelectionController.ValidateSelection
   → CommandGateway → DeclareCityStyle 正式命令 → 正式状态刷新

独立特殊行动：详情中的本方可用数量块 → 拖到该卡合法使用轨道
→ 可选的规则警告确认 → UseSpecialAction 正式命令
→ 正式 InteractionRequest → 统一请求路由/地图目标或材料支付 → AnswerInteraction
```

查看与宣告各只有现有同一实例的输入通道。宣告确认不自动发动特殊行动。取消预览只清展示草稿，不回滚已提交命令。

- 切样式清除旧组合，详情往返保持同样式选择，关闭返回第三页时保留业务页签；列表的滚动由各自 ScrollRect 持有。
- 确认前重新读取版本、候选、设施状态和正式匹配结果；版本改变时重新展示并要求再次确认。预览不写 GameState，不真实旋转设施、不扣库存、不发分数。
- 请求等待期间阻止重复发送，关闭并重开窗口也不能绕过；拒绝后刷新并保留仍合法槽位。回包以 CommandId 对应当前 receipt；旧回包不会解除新请求的等待。重连清理未决 receipt；玩家/对局/宣告轮次变化使草稿失效。
- 隐藏页停止选点/拖动，外部控制器持续刷新投影但不主动弹回。显示恢复时重新校验，失效设施从草稿移除。
- 复合动力的付款沿既有权威 Effect 处理：首次发动命令不提前携带本地虚构支付。补登记 `SpecialActionInteractionUiCoordinator` 到统一 `InteractionRequestRouter`，由可见请求来源选择同一交互；同步时保留有效支付页面，修复原先支付无法全局收起/恢复的问题。
- 普通查看不登记为待结算 Effect，浏览资料不会销毁已收起的支付页。实际支付测试先预选 1 份材料，再收起→浏览城市样式→状态同步→展开，保留请求 ID、页面和选择。

## 原生层级与每轴责任

| 区域 | 约束和实际驱动 |

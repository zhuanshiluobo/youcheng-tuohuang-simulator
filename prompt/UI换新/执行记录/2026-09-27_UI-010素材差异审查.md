# UI-010 素材差异审查

日期：2026-09-27。用户反馈 UI-010 已执行，但与 CityPattern-UI-v1.0、MainGameUI-v2.2 差异过大。本次对照原说明、原预览、最终真实截图、Prefab／控制器与交付记录，修正执行文档。没有运行 Unity、重建或修改场景／Prefab，没有向其他任务发送指令。

## 一、结论

**UI-010 已有正式业务接入，素材视觉尚未完成。** 主要偏差是第三页状态表被改成完整卡图网格，独立窗口六卡3×2总览被旧窄窗口限制为两列滚动，模式信息、固定纸底摘要和操作结构没有完整复现。

本聊天之前生成的提示词存在直接错误：将第三页写成卡列表 Grid，又没有区分已完成正常区域与本项待替换的旧窗口。“使用原生布局”“保持1920基准位置”因此被用于继续保留旧构图。执行验收着重功能、无越界和旧矩形保持，未用源预览逐区域阻止这些偏离。此次文档修正承担这一规划错误，不把问题仅归于执行者。

依据：[MainGameUI 第9节](../../../游城拓荒/UI素材/MainGameUI-Layout-v2.2.md)、[CityPattern 布局说明](../../../游城拓荒/UI素材/CityPattern-Layout-v1.0.md)、[UI-010 原交付记录](2026-09-27_UI-010_城市样式接入.md)。原交付所记162项测试不被撤销，但不证明素材构图符合。

## 三、具体差异与成因

### 1. 第三页用了错误的信息结构

源说明第9节（第358～397行）要求一整块浅纸底、弱行分隔、Ⅰ／Ⅱ类型、名称及独立状态列，点击名称看原卡。Ⅰ行动型保留未用／已用，`declared_only` 按规则显示已宣告；Ⅱ为五个独立状态列，各玩家纯色数量块独立显示。

实际 [GameplayInteractionHud.prefab](../../../Assets/YC/Presentation/Prefabs/Gameplay/GameplayInteractionHud.prefab) 的 `City Style Cards` 使用首选246×173.45、最多两列；[BuildInfoPanel.cs](../../../Assets/YC/Presentation/BuildInfoPanel.cs) 第716～755行克隆原卡模板并加载完整卡图。原交付第18、88行也记录了将既有列表迁入第三页的做法。

这使主界面状态摘要变成卡图浏览器。应保留正式数据和入口，改为独立状态表；不能只缩小卡图或增加滚动条。

### 2. 待替换旧窗口被当成不可改变的基准

CityPattern 源窗口1744×944，左区1234、右区404，六卡按3×2排列。原交付第114行明确保留旧窗口 `x=200,y=105,w=1520,h=900`，没有采用源较宽构图。

实际 [CityStyleDeclarationPreviewDialog.prefab](../../../Assets/YC/Presentation/Prefabs/Gameplay/Dialogs/CityStyleDeclarationPreviewDialog.prefab) 左／右首选宽908／500；卡片首选376×265。结合 [UiAdaptiveGridColumns.cs](../../../Assets/YC/Presentation/Layout/UiAdaptiveGridColumns.cs) 的按宽度取列数方式，旧左区在1920基准只能容纳两列。

这是旧尺寸／分配参数继续决定布局的结果，原生 VLG／HLG 并不要求两列。保持正常主界面1920位置应保护已正确完成的模块，不能冻结尚待换新的旧窗口。源窗口下缘与新版底栏有冲突时应在实际 ContentRoot 内调整高度，保留六卡总览、固定摘要与右城市关系。

### 3. 模式信息、摘要与候选状态缺项

CityPattern 说明第177～204行给出模式标题、说明、当前玩家及可用数量、摘要层次、页脚、可选／选中／不可用框与勾选／锁定图标。

实际界面使用统一标题“城市样式”，摘要缺少纸底和源文字层次；选中主要通过旧模板 Outline 表现，未完整绑定源状态框／图标。查看摘要与宣告摘要虽有业务内容，仍不能代替完整信息区域。

源窗口由模块框、暗底和摘要纸底组合，没有整张 `window.png`。当前使用新版 Frontier 组件有版本依据，但每种素材的职责仍要保留；不能把摘要纸底一起替换成暗底，或省略候选状态层。

### 4. 旧浏览导航保留为主要操作

实际 View 用 `ShowDetail` 隐藏候选区、显示单卡，Dialog 仍配置“查看原卡／返回列表”和前后箭头。源页脚则为查看模式“关闭详情”、宣告模式“取消＋确认宣告”，单卡放大有独立入口。

主动查看大图是合法能力；需要纠正的是默认信息组织及主要页脚。项目单页面约束允许在当前页内部切换放大视图，但应可返回总览并恢复选择，不能让逐张浏览替代六张同屏。

普通查看不直接宣告、确认不自动发动特殊行动都符合业务边界，不能一并删除。

- 基础修正已有[实际交付](2026-09-26_局内UI基础修正.md)，不重跑布局、命名和删除工作；检查本轮改动涉及部分即可。
- 保留当前正确的原生结构、正式宣告／首次及再次宣告、样式特殊行动、付款请求、单页面与 effect 收起恢复。
- 正式卡组和卡面版本由当前规则／内容提供。源预览是示例，不能为了像截图而篡改真实供应、军工版本或玩家数据。
- 原卡930×600和城市2059×3801的完整等比、正式卡图来源及现有状态映射有效部分继续复用。
- Frontier 新主题按[版本关系](../../../游城拓荒/UI素材/整理版-2026-09-24/文档/01_版本与替换关系.md)替换框体／背景／按钮有依据，图像哈希不同本身不能判错；内容组织和素材角色缺失仍需纠正。
- 空局没有放置标记是合法状态，但不足以验证多玩家同槽、Ⅱ五状态及额外宣告带。后续必须补明确的真实状态或诊断画面，不把示例数据当真实业务通过。

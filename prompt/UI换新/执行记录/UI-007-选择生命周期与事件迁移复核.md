## 本轮代码修复与依据

- 草稿按请求 ID 隔离；同请求更新保留有效候选并截断至 MaxSelections；非空匹配命令回包才释放提交锁。角色、设施、地图、事件 renderer 均由同一请求来源进行当前性检查。确认、取消／结束共享窗口提交锁。
- 修复空回包误解锁：网络确认可能隐藏他人命令本体（`AuthoritativeCommandDispatcher.cs:115`），`CommandSubmissionController.cs:117` 因此传空 ID。现在 Character／Map／Event 与 Facility 一样，只接受非空且精确匹配的 commandId。
- 修复远端请求缺口：`GameSession.ReplaceView` 的兼容 State 故意不含 EffectRuntime。新增 `VisibleInteractionRequestSource.Read`；有 `session.View` 时只取该 View 中本玩家可见且 open 的请求，禁止空列表回退 Host State。`MobileCityEventCardInteraction` 路由与四个 renderer 的 current 校验共用此来源。`InteractionView` 补投影 OwnerEffectId，保留流程身份。
- 旧详情返回先验证当前请求；延伸枢纽另以显示代次屏蔽旧详情按钮与返回。失效回调不会关闭新阶段查看器。收起由 HUD 隐藏页面，不清草稿；滚动值保存在壳并延迟到有效布局恢复。
- 出售四种数量均 Clamp 到正式候选上限和实时库存的较小值；标签显示实时库存，预计收入按 `ResourceSaleService` 的正式四种单价计算。最近成交仅取本人可见、Completed 出售节点的真实整数结果，含零成交；不用余额差、不声称累计。

新增必要测试：`VisibleRequestSource_UsesClientViewWithoutFallingBackToHostState`、`ClientVisibleChoice_RechecksCurrentPermissionAndIgnoresEmptyOrUnrelatedAcknowledgement`。出售 Clamp／价格测试覆盖四种资源；详情返回测试覆盖阶段切换。最终 103 项结果已包含这些测试并通过；这仍是组件／应用交互约束，不是网络端到端验收。

## Event 迁移的零缩放检查

`Ui007EventDialogMigration.cs` 不调用 GetWorldCorners、TransformPoint、lossyScale，也不读取隐藏节点的 rect 来反推几何。页头／内容／页脚取明确序列化参考 metrics；原图热点采用 850×600 局部比例；布局由运行时 LayoutGroup 读取最终可用 rect。因此没有其他迁移中“隐藏 Canvas scale=0 导致存入零尺寸”的同类测量路径。

该结论不证明最终画面正确。root 已运行 `Ui007EventDialogCapture.RunBaseline` 与 `RunNarrow`，下节逐项限定现有截图和几何数据能证明的内容。该入口仅组件诊断、真实 Registry／源 Prefab，诊断候选不提交规则命令。

17 份数据总计 13 个 ScrollRect 检查：只有 **EventText-1920 的 content 836 > viewport 653**，它在首屏看不到 Choice 10，设到末尾后 Choice 10 的完整矩形进入 viewport。其它 11 个含按钮列表在首屏已容纳末项；建设确认的另 1 个滚动内容无按钮。因此可以说明“这些样本末项可达”，不能写成“所有模式均验证了内容溢出后的滚动”。现有 PNG 均在恢复滚动顶端后截取；末尾证据来自 JSON，未单独截图末尾，也未验证滚轮／拖动滚动条的真实输入命中。

人工图像复核未发现窗口出界、原图拉伸或已展示同级按钮重叠，但有两点不能被 `issues=0` 掩盖：

- **900×600 可读性较弱。** 探索收款按钮实测约 51×17 物理像素，资源收款按钮约 21 像素高，文字明显偏小；建设详情与规则拒绝说明也较小。三个分辨率下列表的逻辑 content／viewport 高度相同（例如建设 472／519.2、探索付款 310／329），这些样本主要体现 Canvas 缩放，没有证明窄宽重排分支已实际执行。属于视觉可用性待确认，不能仅凭几何无越界宣布窄屏整体通过。
- **建设诊断不是可成交状态。** 捕获在入场阶段调用正式报价查询，所以两支付按钮显示 `Command BuildFacility is not allowed during phase Entrance.` 且被禁用，建成效果还显示规则值 `unique`。这是现有动态文案和当前诊断状态的实际画面，不代表正常可建造流程的最终体验；未在此只读审查中改产品或规则。

文字样本虽然描述“多行说明”，PNG 中每条实际仍为一行，故未验证真正超长文本换行后高度、长名称按钮宽度或极端数量。几何探针只检同级按钮重叠；末项检查优先检查竖直可达，不能替代全部文本遮挡、跨父级遮挡与真实射线命中验收。

## 仍需明确验证的边界

1. **联网端到端尚未运行**：本轮补齐投影入口和同源校验，但仍需真实客户端确认／拒绝／他人回包以及 Host 权限隔离验证。
2. **候选刷新合同**：角色／设施的重绘去重以请求 ID、StateRevision、库存为主。若外部调用在相同 revision 内单独改变 CandidateSetVersion，旧按钮会被当前性校验拒绝，但不会主动重绘；正式内核当前创建新的冻结请求版本，不应绕过此合同。
3. **出售候选目前连续**：正式 `ContentPrimitiveEffectExecutor.Sell` 枚举每种资源 1..库存。UI 由候选最大值构造数量；若未来规则改成不连续数量集合，须改为按合法数量步进，不能只沿用最大值。
4. **查看详情期间刷新**：同请求刷新会销毁旧壳并关闭其详情，HUD 保持收起状态并保存草稿；需实测此时再次展开和滚动恢复，不能只凭代码认为体验已验收。
5. **旧兼容设施出售**：全项目生产代码没有实例化或注册 `ResolveFacilityEffectCommandHandler`／`FacilityEffectInteractionUiCoordinator`；当前启动使用 EffectTree＋Lua 出售。旧 handler 丢弃 Revenue 不影响当前正式入口，但若重新启用兼容路径，必须补正式数值回包。

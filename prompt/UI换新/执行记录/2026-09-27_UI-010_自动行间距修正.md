# UI-010 自动行间距修正

日期：2026-09-27。用户指出城市样式列表应“不算上下的自动分配间距”。本条纠正统一验收报告中的处理方向，不修改主要行动按钮上下也参与分配的规则。

## 原因与修正

旧 `UiDistributedVerticalLayoutGroup` 把继承的 Spacing=4 当作最小间距，原生布局首选高度计入五段共20。`UiFlexibleCanvasContent` 因而将原本308高的视口内容撑到312，末行背景裁切4像素。问题不是应该减少固定间距，而是该列表不应该保留固定最小间距。

已修改布局组件：计算首选/最小内容高度时只计行与Padding，不预留行间距；纵向放置时将非负剩余高度全部均分给相邻行之间，顶部、底部不参与分配。序列化字段不被计算过程改写。当前六行高合计292、视口308，五处行间自动为3.2；视口增高时自然增大，行本身超过视口时行距为0并滚动，不压缩玩家标记。

没有修改字体、标记大小、行高、父容器8单位边距，没有保存或重建场景/预制体。主要行动按钮仍按上下及行间共同分配。

## 验证状态

已有布局测试补入较小可用高度及零剩余高度；新增 ScrollRect 内容高度与自适应布局的组合回归，覆盖宽余量、308高度、行高超过视口和恢复尺寸，避免只测宽松尺寸漏掉本问题。测试验证计算行为，不锁定实际资产样式。

当前项目已由用户打开的 Unity 编辑器占用，本轮没有关闭编辑器、另起同项目测试进程或切换其场景。未重新运行Unity测试或截图，新增测试与修正后实际画面待复核；原统一验收的通过计数和截图仅对应修正前版本，不作为此次通过证据。

## 三、阶段 A：主界面第三页按状态表搭建

### 3.1 结构

```text
CityStyleActions                  VerticalLayoutGroup
├─ Header                        HorizontalLayoutGroup：本局样式数量／既有入口
└─ StatusTableViewport           LayoutElement flexibleHeight > 0
   └─ StatusTableContent         VerticalLayoutGroup，整块纸底与弱行分隔
      ├─ TypeIActionRow          类型、名称、unused、used
      ├─ TypeIDeclaredRow        类型、名称、declared（按真实卡配置）
      ├─ TypeIIStateHeader       2／已用余1／1／已用余0／0
      └─ TypeIIRow               类型、名称、五个独立状态槽
```

此树表示可复用行类型，实例数量与顺序来自当前正式供应；不要写死某张演示卡。普通行用 HLG，类型／名称提供可读首选宽度，状态区取得明确余量；槽内颜色数字块用 HLG 或 2×2 Grid。外部 VLG、双轴填充、滚动 Content 所有权遵守 07。

### 3.2 必须呈现的信息

- 页头显示本局样式数量；类型、名称和状态独立绘制。不要把完整卡面文字缩成主界面上的两列小图。
- Ⅰ行动型有未用／已用两槽；`declared_only` 卡仅显示已宣告槽。两者按规则配置区别，不为奖励卡造未用状态。
- Ⅱ五列顺序固定为 `2 → 已用余1 → 1 → 已用余0 → 0`。记录它们与当前领域 `MarkerArea` 的明确映射；“已用余1”和“1”、两种余零状态不能合并。
- 同色同槽合并数量；不同玩家各有独立基础单色标记。Ⅰ槽横排四名玩家；Ⅱ槽用 2×2 保持四人可见。数量独立渲染，零值弱化但保留四个布局位置。
- 按用户2026-09-27追加要求，统一采用 `MainGameUI-CooperationMarkers-v1` 基础四色 `cooperation-{08,04,02,01}-64.png`（红、蓝、黄、绿），复用已导入的 `Assets/YC/Presentation/Effects/Sprites/EffectRows/markers/` 资源。撤销旧 `digit-base-*` 要求；不使用多色组合款，也不使用无 Sprite 的方框加染色替代。Ⅰ槽与Ⅱ槽的尺寸、间距由各自原生布局及实际空间确定。
- 源色值 Green `#5FD200`、Yellow `#FFBF00`、Blue `#006CFF`、Red `#EC0000`；数量是标记数，不能当剩余使用次数。数据与明暗状态遵循真实投影。
- 点击名称／详情进入查看模式，不直接宣告或发动特殊行动。当前宣告能力沿原正式入口保留；在页头或既有快速行动处承接，避免现有宽大页脚按钮挤占六条摘要的阅读空间。只调整表现归属，不增加重复命令监听。

### 3.3 基准与适配

Frontier 3.1 给出的右侧内容参考为 `(1352,654,552,324)`；采用当前基础修正后的实际父区与正常外部位置。根据同一源的行高、名称／状态比例和留白复现六条摘要。1920×1080 下当前正常六张供应应能直接读到六行及Ⅱ五槽，不以“滚到末项可见”代替基准构图完成。

真实超量内容或更低可用高度才在表内滚动；三个主列及上方企业合作、弃牌、盖牌区继续常驻。禁止把当前原卡 Grid 保留为表格的另一种默认模式。

**出口：** 实际第三页与源同类预览逐区域相符；六行、纸底、弱分隔、各类型状态和入口完整，没有原卡缩略网格及旧表的双重显示。

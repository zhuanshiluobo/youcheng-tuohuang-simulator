## 四、阶段 C：格位映射、规则与页面生命周期

1. 区分 `view` 与 `declare`。查看不建立业务提交；宣告允许预选样式与当前合法设施后确认。宣告确认不自动发动样式特殊行动。
2. 从正式可见投影更新各玩家标记和使用状态，明确主动Ⅰ类未使用／已使用两槽、Ⅱ类五槽与额外宣告带在当前规则中的对应。源 `zero` 与预览 `exhausted0` 的名称差异记在映射，不改源文档。
3. 数量标记不误当剩余次数，后续宣告不重置原使用轨道。候选、玩家数、设施状态变化后刷新映射，复用条目清理旧 ID、标记与事件。
4. 城市格位使用当前统一来源。复用先前证据前核对同一实际资产、父变换和最终显示矩形；本窗口新增变换需要补验。换算包含等比留白、父缩放、内部滚动和放大，不能以素材原始矩形直接充当屏幕命中区。
5. 高亮仅表现当前预选，最终资格由正式查询／命令决定。确认前不真实旋转设施、不扣标记、不发奖励；不得为预览直接写 GameState。
6. 确认复核请求／版本、候选、设施可用性和首次／再次宣告资格。pending 防重复；拒绝后刷新并保留仍有效草稿，旧回包不影响新请求。取消／返回／撤销各按现有规则，不把退出预览当已提交回滚。
7. 查看、宣告、独立详情与子选择通过唯一页面切换；页面内并列区域仍是一页。effect 收起保存有效预选并停止宣告选点，隐藏期间同步但不自动弹回；展开关闭当前资料页后校验并恢复当前步骤。普通查看不登记成待结算 effect。
8. 新入口接通后清理本项独占旧外壳、重复按钮、监听、必需引用和旧坐标写入路径。保留合法共用素材、正式城市数据及其他业务入口；按语义命名并维护 GUID／fileID、字符串查找及场景覆盖。不得引回旧翻面、hint/context 或比例分页。

**出口：** 各模式只有一个输入／提交通道，真实格位与状态映射有证据；地图相机依赖明确单列，不能据世界地图暂缓跳过本项已改城市容器的核对。

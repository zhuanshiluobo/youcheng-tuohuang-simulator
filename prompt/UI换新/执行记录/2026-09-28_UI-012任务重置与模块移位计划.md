# UI-012任务重置与模块移位计划

日期：2026-09-28。本记录只说明本次只读审查和文档重置，不是Unity实现交付或视觉验收通过记录。

## 1. 用户要求与当前入口

用户认可当前1080p主界面，要求保留模块内部自动布局，改为根据屏幕空间移动整个模块：宽屏时左侧玩家与城市分列，企业家位于玩家下方；右二放弃牌、盖牌、手牌，最右放企业与行动，中央地图尽量接近正方形。

同时加入三人局两名对手、企业／企业家模式开关及依赖、关闭模块后的回填。1080p仅关闭企业家时，手牌进入原企业家区域。自由页面有正常关闭；无页面及有效恢复目标时允许主界面收起，只保留地图、本人资源、顶栏和底栏。

当前唯一实施入口为[UI-012：主界面模块移位与模式适配](../UI-012-主界面模块移位与模式适配.md)，详细规则为[09：模块移位与收起](../09-主界面模块移位与收起规范.md)。旧UI-012文件保留跳转，不并行执行旧的全套综合验收。

## 2. 对实施方式的补充

- 外层选择有限的模块组合，设置宿主／顺序／LayoutElement输入，实际矩形仍由原生布局计算；模块保持同一实例及内部样式。
- 断点依据真实可用空间与最小尺寸，进入／退出条件分开；不因物理像素较大就切超宽，不在临界点反复搬移。
- 更高屏幕先延续当前填充；必要时增加可容纳全部模块的纵向组合。近方形地图与面积、可读性同时评估，不把正方形设成强制裁剪。
- 显隐分别来自正式模式、无效玩家席位和玩家主动收起；宽高比例不负责偷偷隐藏启用模块，仍不使用主分区分页。
- 页面动作优先处理effect和既有可收起必选阶段，再处理自由页正常关闭，最后切HUD。纯地图无窗口流程只要操作仍在保留区域，可以继续输入并收起HUD；不暂停、取消或提交该流程。
- 旧全局联机／设备／终局验收留存。新增模式字段的快照与客户端一致性需要本次验证，但不扩展为重跑全游戏。

## 3. 只读核实的实际接入点

| 发现 | 对新任务的要求 |
| --- | --- |
| 主HUD当前有原生根与三列，手牌／企业家在中列同一行 | 在当前资产中把完整模块归位，不推翻基础修正 |
| `GameplayMainModules.Render` 对缺少的对手只关闭Opponent Data，席位外框仍可能占60～108高度 | 让整个无效席位及明细退出布局，三人只留两名真实对手 |
| 企业家当前最小宽424，手牌／企业家共用行高172 | 新宿主不能机械继承旧硬下限；先测可读尺寸和内部自动布局 |
| 当前本人资源在Map Hand Column下的Self Summary Region，frame有五项resourceValueTexts | 收起保留真实模块和刷新所有者，不恢复旧资源板、不关闭复合根 |
| `CardPileView` 有固定slotScale、旋转、edgeOverhang | 右二窄列需检查实际卡边界与命中，不能仅验外框 |
| `UiMainActionTabs.Select` 会重置滚动 | 移位保持当前页签状态，不靠重新Select恢复 |
| `GameState`／`GameStateView`／`RoomState` 未发现企业／企业家正式启用字段 | 执行前复核；最小补齐现有启动、会话、投影和必要网络传递 |
| `EnterpriseSelectionProjection.Mode` 是企业选择弹窗模式；`ExternalContentPack` 仍限制企业内容接入 | 不误用弹窗模式，不绕过内容保护，不把模块开关当企业规则完成 |
| `GameplayHudFrame.ToggleEffectPage`／`UpdateFoldButton` 现只处理effect及可折叠stage | 扩展统一动作解析，HUD折叠状态独立于请求恢复 |
| 盖牌 `IsEffectPage=false`、`AllowStageFolding=true`，stage有自动重开逻辑 | 保留合法阶段收起恢复，不能将全部非effect页当自由页关闭 |
| `CardViewer.Close` 会合法返回来源，`Dismiss` 用于替换／失效 | 区分关闭、返回、替换；恢复effect时避免返回回调又弹旧页 |

以上定位以当前源文件为依据，执行时还须核对实际运行来源与场景覆盖。本次没有运行游戏，不把静态读取当成实际适配已通过。

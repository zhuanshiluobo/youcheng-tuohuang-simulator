## 2. 统一工作顺序

| 阶段 | 做什么 | 进入下一阶段前必须满足 |
| --- | --- | --- |
| A：依据与素材清单 | 按实际入口／模式确定源说明、布局参数、预览、角色映射和实际源资产；标注保留区／待换新区／缺陷区 | 每区有明确目标图与结构，旧壳不自动成为设计基准；缺项可追踪 |
| B：原生布局内的基准视觉 | 先按源图确定行列数、区域比例和内容，再用 VLG／HLG／Grid 将素材放入最终容器；在1920×1080逐区域看图 | 保留区正常位置一致，待换新区符合对应源构图，边界调整有依据；原生组件、素材完整及无越界仅是部分条件 |
| C：层级与填充核对 | 核对相机、Mask、Raycast、CanvasGroup、两栏和每轴驱动者；确认父子填充及内容最小尺寸成立 | 三列持续同屏，正文取得余量，局部内容可滚动；不允许尺寸触发分区换页 |
| D：业务逻辑接入 | 连接动态数据、请求、事件、effect 收起／恢复、合法提交等 | 正式入口正确、单一输入所有者、静态布局与文案仍归资产管理 |
| E：实际验收 | 从实际入口逐模式对照源图与当前画面，验证保留业务；视觉通过后做有限尺寸回归 | 有源图→实际图→区域差异／依据的记录，素材和构图缺项已清零；功能与未完成项分别报告 |

每个阶段完成后自行核对并继续，不增加逐阶段等待用户批准的流程。纯布局驱动、素材加载与必要渲染接线可以服务于 B／C；不要把“先视觉”理解为连显示图片所需的代码也不能写。新增业务逻辑在视觉与层级成立后推进。

搭建过程中允许看 Game View、预览或少量诊断图以定位缺图和偏差，标明“搭建中／诊断”。先修好1920×1080该模式的源图构图，素材与布局就绪后才做定向尺寸检查；源中六卡同屏却只显示四张、状态表变原卡网格或固定摘要缺失时，继续截图其他比例没有验收价值。综合矩阵在 UI-012 按风险选择，不要求每项任务跑全量。

## 3. 严格采用素材依据

主界面的依据按以下顺序使用：

1. 用户后续明确要求：两栏最高交互层、单页面、effect 页收起恢复、不可拖窗、五类字体、自适应。
2. [Frontier 3.1 增量说明](../../游城拓荒/UI素材/FrontierUI-v3-Incremental.md)、[布局补丁](../../游城拓荒/UI素材/整理版-2026-09-24/原包参数/FrontierUI-v3-Patch/layout-patch.json)、[角色映射](../../游城拓荒/UI素材/整理版-2026-09-24/原包参数/FrontierUI-v3-Patch/skin-patch.json)、[新版组件索引](../../游城拓荒/UI素材/整理版-2026-09-24/清单/新版组件索引.json)。
3. [新版主界面基准预览](../../游城拓荒/UI素材/整理版-2026-09-24/预览/FrontierUI-v3-Patch/main-idle.png)及[顶栏细节](../../游城拓荒/UI素材/整理版-2026-09-24/预览/FrontierUI-v3-Patch/topbar-detail.png)。原图展示的示例库存、玩家与可选效果只用于构图参考。
4. 未被补丁替代的 MainGameUI 2.2 内容与各窗口原包说明。

主界面上述优先顺序不能代替专用窗口的模式依据。每个窗口必须另读自身说明、参数与实际预览；补丁明确替代哪个角色，才采用该角色的新素材。“旧主题”不表示原内容组织、卡牌排布或固定摘要已废弃。外框／底图／按钮换肤与内容构图分别登记，不能只套通用壳后宣称完成。

从第一步就在原生布局容器内搭建素材，通过资产中的 padding、spacing、首选尺寸和图片比例复现**已判定有效的目标构图**。保留区对照已有正确画面；待换新区按对应源模式重建视觉关系；缺陷区只作必要边界调整并注明原因。旧1520×900窗口及其左右比例不因位置保持要求而冻结。不能先用绝对坐标拼整页再补布局，也不能借原生组件、统一主题或适配自行改变信息结构。

源 PNG 尺寸不等于显示尺寸：例如顶栏贴图高 72，基准布局目标高 64，底栏贴图高 96，基准目标高 82。依据布局参数设置显示区域，依据 Sprite 索引设置切片。用户后续允许编辑样式，测试不把每个像素坐标永久锁死。

严格对应的是可见组件、构图和资源角色。旧预览中的多窗口叠加、侧栏收起按钮语义、旧字体和演示规则由用户最新要求修正，不能为了复刻截图恢复这些旧交互。

## 5. 视觉完整性与层级检查

每个模式的每个区域建立核对记录，字段至少为：入口／模式、保留／待换新／缺陷分类、源说明及预览路径、素材 ID、Unity Sprite／GUID、实际源与节点、当前实际截图、数据／状态、结构差异／依据、结论。共享 Prefab 的间接引用也要追溯；只统计 GUID、看到某个Image有图或记录几何不越界都不等于符合构图。

视觉阶段检查：

- 实际使用的源 Prefab／场景覆盖正确，必需 Image 有正确 Sprite，卡图／图标不为空。
- 九宫格、透明边界、`preserveAspect`、内容内边距与图源匹配。
- 节点已激活、尺寸有效、颜色和父级 Alpha 正确；不被 Mask、相机 viewport 或其他面板意外裁掉。
- 框体、标题、图标、文字和内容分别存在，静态文案与五类字体保留在配置中。
- 对照同模式源图的区域顺序、相对比例、正常可见数量、固定摘要、页头与页脚。换肤只替换明示角色；因两栏／安全区所作尺寸调整不能顺带将状态表变网格、总览变轮播或删掉摘要。
- 未接规则的区域有明确表现状态，不能拿空白屏、错误贴图或大面积旧界面作为视觉完成。

层级阶段检查：背景 → 内容 → 边框／装饰 → 当前唯一页面 → 非页面提示／拖拽 → 常驻顶底栏；区域内部根据素材要求细分。主外框的显示可覆盖内部装饰边缘，但所有装饰关闭不必要的射线命中。实际 Canvas、相机、Mask、Raycaster 及焦点一并核对，不能只看排序数字。

## 6. 截图前的就绪条件

截图工具不能只等待固定若干帧就宣告视觉就绪。等待上限可以有，但放行条件必须对应实际加载状态：

1. 正式目标场景及本次要展示的页面／模块已激活，当前状态与待验收场景一致。
2. 本状态所需 Sprite、卡图、头像、地图和字体已加载，相关异步更新完成；动态空列表确实是合法空态。
3. 布局和文本测量已更新，实际渲染尺寸符合本次记录，画面稳定；不存在临时加载页、未完成的重排或错误覆盖。
4. 视觉清单没有未处理的必需素材缺项。缺图、错误、超时就输出具体缺项并记录诊断图，不能记录为完成截图。
5. 截图后将同模式源图与当前画面逐区对照，记录结构、可见数量、底图／框、标题、摘要、按钮和标记差异；分别说明真实数据、明示换肤、用户交互要求、必要边界调整及未完成项。没有这张对照表，不能把“已查看截图”写成“符合素材设计”，不能进入该页大范围尺寸验收。

无需新增庞大的截图系统；先修正当前捕获入口的就绪检查和报告语义。已有提前生成的图片保留为诊断材料，在新记录中说明其用途，不删除历史证据或改写旧报告。

## 7. UI-003 当时的继续方式（历史过程依据）

本节保留阶段方法，当前任务按最新计划及实际交付继续；基础修正和已完成UI不据此重新生成或从头执行。

1. 保存并盘点当前修改，保留已有逻辑、测试和用户改动；不回滚整个工作区，不重复生成覆盖 HUD。
2. 暂缓扩展业务逻辑、重复跑完整测试及批量截图，先完成本文件第 4 节的主界面视觉清单。已有编译错误或妨碍显示的问题可先修正。
3. 完成 1920×1080 基准视觉搭建，再核对层级、单页面容器、顶底栏输入及大小屏布局。
4. 随后检查已经写出的逻辑，接到新视觉节点上；消除指向旧面板的重复入口。保留可用代码，按实际差异调整。
5. 最后满足截图就绪条件并进行本任务需要的验证，区分“主框架视觉完成”“主框架交互完成”和留待 UI-004／005 的业务项目。

阶段出口由执行者依据清单自查，不需要用户反复批准。只有已有资产覆盖授权确实不包含某项操作时，按 `AGENTS.md` 处理；此规范不授权测试或截图调用 UI 生成器。

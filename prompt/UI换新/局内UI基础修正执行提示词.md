## 一、必须交付的结果

1. 主界面上中下由原生 VerticalLayoutGroup 排列，中间三列由 HorizontalLayoutGroup 并排，各列内部由 VerticalLayoutGroup 分配；需要填充的主体、背景与 Viewport 真正继承父区尺寸。
2. 所有支持比例使用同一主界面结构。删除主分区分页／导航／阈值切换，尤其验证 16:10 时左、中、右同时可见；保留右下三个正常业务页签。
3. 生产代码、目录、Prefab／场景物体、长期测试和工具去除实施任务编号，按职责命名；原文件 GUID、对象身份及场景覆盖正确迁移。
4. 删除旧资源计数器、旧翻转及“查看提示／上下文按钮”变体、旧固定弃牌控件与旧内嵌预览壳、旧盖牌拖放残留。必须保留的真实业务通过新版入口完成。
5. 两张实际对局场景能够从正常入口展示并操作修正后的 UI。1920×1080 正常基准位置保持，新要求明确删除的对象和缺陷修复单列差异。

本项只修改局内。StartScene、加载、房间大厅、收藏室及其合法共享源不因本项变化；设置、规则书、日志、查看器沿 UI-007 已隔离的局内来源实施。

## 三、阶段 A：先完成根结构和三列的原生布局

1. 按纠正规范第 2 节在实际共享 HUD 上建立 SafeAreaRoot 的 VLG，只排 TopBarRoot、ContentRoot、BottomBarRoot 三个子区。安全区域适配器只负责根边界，停止旧框架对三块区域再次扣栏高／写坐标。
2. 顶底栏提供可配置的 min／preferred 栏高，flexibleHeight 为 0；ContentRoot 的 flexibleHeight 为 1，承担剩余空间。设置父组控制子尺寸和扩展选项，防止三块被无差别等高分配。
3. ContentRoot 下的 MainColumns 四向拉伸并使用 HLG。三列矩形由 HLG 同时管宽高，使用实际基准的首选宽度与内容可接受的最小宽度，指定宽度余量归属。PageHost 与提示／拖拽层作为叠加层同样填满 ContentRoot，不参与三列分配。
4. 左列 VLG 分玩家区、城市区。玩家标题高度稳定，单项明细显示后由内容或 LayoutElement 提供高度；明细上限只能更新布局输入，由自己的 ScrollRect 承担超量内容，城市取得真实剩余高度。删除旧控制器逐项移动玩家座位和城市的代码。
5. 中列 VLG 分地图、自身状态与手牌。地图取得指定剩余空间，地图相机只读最终 MapRegion 屏幕矩形。手牌的局部扇形／排序可保留，不能反向修改整个中列。
6. 右列 VLG 分合作区、新版弃牌／盖放牌区、业务页签和当前行动区。卡区内部 HLG，合作与行动正文按约束取得伸展高度；标题、页签及必要操作不滚出区域。移除当前普通纵向分配自定义组件，不能再移除原生 VLG 换另一份手写高度算法。
7. 每个区域继续落实到背景、边框、标题、内容 Viewport；逐级检查布局输入是否被父 LayoutGroup 采用。图像等比约束放在已获分配的内层，不能和父布局争同一尺寸。
8. 逐列核对最小高度总和。布局不足时先处理留白和正文的最小／flexible 值，再配置区内滚动。禁止整列 ScrollRect、整列 ContentSizeFitter 增高、整列平移或隐藏整列来满足边界。

**阶段出口：** 1920×1080 的完整正常画面与基准一致；三个轴向层次可在 Inspector 直接看出；普通结构的矩形没有第二写入者；左城市、中央地图、右侧行动都在 ContentRoot 内。

## 四、阶段 B：删除所有尺寸触发的主分区换页

1. 审查 `UiHudColumnsLayout` 中 `compactWidth`、`IsCompact`、`selected`、`SelectSection` 和 `RefreshVisibility`；删除按宽度只激活一列的逻辑。不要只是调低阈值或为 16:10 增加例外。
2. 审查 `GameplayHudFrame` 的 `compactNavigation`、`compactSection`、导航按钮绑定、额外预留高度、必需引用校验及页面恢复；连同对应 Prefab 节点和场景覆盖一并移除。
3. 搜索 `Compact Region Navigation`、`SelectSection` 和按“地图／行动／玩家”切主列的测试、自动化和捕获步骤；改成直接验证同时存在的真实主区域，删除“先选中行动分区才可测按钮”的前提。
4. 保留 `ActionTabs` 的主要行动、快速行动、城市样式切换；保留真正由用户或请求驱动的页面／步骤。不得把它们的事件与比例切换共用。
5. 无弹窗覆盖的主界面在支持尺寸下三列同时有效、可见、可交互。尺寸变化期间也不能先隐藏两列再等待某个导航恢复。弹窗的正常单页面覆盖不属于此检查的比例换页。

**阶段出口：** 16:10 与基准用同一主层级；没有主分区导航节点、宽度分页状态、隐藏列路径及依赖这些行为的验收脚本。

## 五、阶段 C：落实到全部局内页面和内容组件

按当前实际局内 UI 清单逐个检查共用选择壳、效果行、建设页、城市样式页、事件／调度／结束页、局内设置、日志、规则书与查看器。此阶段纠正已存在页面的结构；后续专用素材与业务按 UI-009～UI-011 继续接入，CardViewer 3.6 的完整替换由 UI-011 承担。每页记录以下内容，不能只改公共框架后批量勾选完成：

1. 外壳受 ContentRoot／PageHost 约束，页头、正文、页脚采用 VLG；并排内容使用 HLG；按钮栏使用 HLG；普通列表使用 VLG／GridLayoutGroup。
2. 正文 Viewport 取得剩余空间，只有内部 Content 按内容增高。长中文、图标混排、费用数量和候选数变化后，实际行高由文本测量和布局输入更新。
3. 素材必须从开始就放入这些结构。padding、spacing、preferred size 与图片比例共同复现正常构图，不能先按绝对坐标拼完整页再补一层不参与计算的 Layout。
4. 卡片网格仅在内容内部换列，必要时用局部网格列数辅助器更新 GridLayoutGroup 的参数；不得让辅助器重排页头／主界面。记录仍需保留的内容专用组件及理由。
5. effect 页收起／恢复、单页面、窗口不可拖动、字体角色、合法提交及数据权限保持。动态状态脚本不设置固定标题，也不接管静态结构。

**阶段出口：** 实际局内清单逐页有原生结构、每轴驱动者和结果；任何普通结构仍需自定义布局计算的，都有明确尚未处理项，不能用“继承 UI-007”直接视作通过。

## 六、阶段 D：彻底清理旧表现与入口

### D1. 旧翻面、查看提示与上下文按钮

- 删除实际 HUD 的旧 `Action Panel Context Button`（原 Flip Button）、专用顶部占位、监听和 `action.context`／旧 `action.flip` 自动化入口；清理 ActionPanelView 的旧必需引用及 ActionPanelController 的翻面／提示面支路。
- 删除旧 `HintCardTexture`／提示卡专用布局与查看路径、为延续旧翻面设置的“查看提示／返回行动”文案；不能把它们再改成第三种名字或移动到另一区域。
- 将真正的第二效果“继续／结束”决定接入当前新版 effect 选择页／步骤，保持真实候选、资格和命令。新角色牌使用由正式快速行动进入新选择／使用页，操作完成回主界面，无需旧提示面。
- 用真实第二效果状态各验证一次合法继续与结束，关闭资料或取消查看不应触发该决定。原始内容素材是否共享需单独核对，不因为删除 UI 就直接删除原图档案。

### D2. 旧资源计数器

- 确认新版五类资源数值与其他原计数用途均有真实数据归属，资源、手牌、盖牌、建设刷新独立于旧资源板对象。
- 全项目核对 `ResourceCounterBoard`、View、LayoutProfile、VisualLibrary、Gear／Auxiliary Counter View、旧 Prefab 和独占配置。旧编辑器构建分支若只服务废弃 UI，一并移除；不能据其引用永久保留废弃依赖链。
- `RefreshResourceCounter` 若已承担主界面综合刷新，应按实际职责拆分／更名而非删除业务更新。完成后删除已确认无其他合法用途的旧表现文件及对应 `.meta`。

### D3. 旧固定弃牌区与预览壳

- 新版 HUD 的 Discard Region／Discard Count 与正式弃牌集合保留。把查看入口接到新版只读卡牌列表及详情页，保留玩家权限和返回时焦点／滚动位置。
- 从旧 CharacterHandPanel 嵌套实例及必要源中移除旧 Discard Preview／Overlay／Panel／Scroll／Close Button 等独占外壳和对应 View 字段、监听与必需校验。不要把新版按钮仍指向旧整套内嵌页当作完成。
- 不删除整个手牌组件或合法卡图；手牌排序和新版盖牌选择已交付的能力继续使用。旧盖牌拖放只清点残留，不重建其原入口。

**阶段出口：** 清理表每项目标实际退出资产与运行路径；旧构建／修复工具不会再生旧 UI；必要功能由新入口完成。未完成迁移就继续修，不以“改名”“停用”或“暂时还要用旧控件”提交清理完成。

**阶段出口：** 生产命名没有实施任务编号；每个移动／重命名项可从映射追溯；引用不依赖旧目录或旧节点名；历史命中单列，不通过重写历史记录隐藏残留。

# UI-012：多尺寸实际对局与联机验收

请执行本任务。先读 [共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md) 和 UI-001～UI-011 的执行记录。前置：各项交付及未完成清单齐全。

按[05 任务安排](05-地图俯视改造期间的任务安排.md)，可先验证独立 UI。世界地图的最终点击、导航及相关真实行动链在俯视改造后补齐，复用改造方和 UI-004 的证据；仍有相关待验项时不得把整轮任务标记完成。

## 目标与范围

验证实际对局入口、多尺寸布局、常驻栏交互及多人状态一致性，修复本轮 UI 迁移引入的问题。缺少业务接口的模块可做组件验收，但最终必须单列未接入项，不能报告整套 UI 已完整完成。

## 验证准备

0. 先核对[视觉搭建优先规范](03-视觉搭建优先与分阶段验收.md)及各页面素材完整性清单。主外框、分区框、底图、图标、字体或当前状态必需内容存在缺项时，先修复该页视觉；不能直接开始完整多尺寸截图矩阵。
   同时读取 [04 按钮增量规范](04-主界面按钮3.2增量规范.md)和 UI-005 的逐按钮接入表，核对 11 个按钮的 3.2 素材与现有状态。覆盖页签 selected-hover、禁用优先、按下时失效、pending 后重新校验以及旧功能迁移去向；UI-003 的旧按钮画面不能替代本轮验收。
1. 核对当前构建／启动入口、两个场景实际使用的 Prefab 与覆盖、Registry 引用及已有用户改动。生成器不在验证路径中。
2. 查看现有验证脚本后选择需要的入口，例如 `tools/tests/Run-EditModeTests.ps1`、`Run-PlayerJourneyEditor.ps1`、`Run-PlayerJourneyBuild.ps1`、`Run-LocalMirrorMultiplayerValidation.ps1`、`Run-LocalhostAutoplayValidation.ps1`、`Run-FontHealthCheckValidation.ps1`、`Capture-TabletopZoomMatrix.ps1`。确认参数和资产写入行为再执行，不假定它们已经覆盖新 UI。
3. 先做能证明引用与新增交互约束的定向测试，再进行实际画面和操作验证。只有发现具体风险或必要验收要求时才扩大测试；自动跑局不能替代窗口输入与画面验证。

## 必须覆盖的验证

### A. 常驻栏与输入

- effect 页、独立抽屉、子选择、设置和查看器按典型流程互斥切换；提示与拖拽展示不引入额外页面。整个流程包括过渡期间，可见且接收输入的页面最多一张。
- 实际点击顶栏及底栏合法功能，确认射线命中对象和响应；业务禁用按钮显示正确原因。
- pending、非当前玩家、断线提示和对局结束状态不把整条栏锁死。
- 透明装饰、内容遮罩、临时 Canvas 与相机合成无越层；UI 点击不触发地图动作。
- 已启用的键盘／手柄焦点能访问两栏，关闭窗口后恢复合理目标。
- 固定渲染尺寸下，逐个拖动窗口／抽屉／查看器的标题、背景及边缘，确认容器位置不变；关闭重开、切换模式／请求及尺寸适配后仍不能拖窗。检查运行时未重新启用窗口移动组件，同时验证列表滚动、卡牌／设施拖拽、地图／图像平移仍正常。
- 完成“effect 已预选 → 顶栏收起 → 主界面资料 A → 资料 B → 顶栏展开”：资料 B 关闭，当前有效 effect 步骤及草稿恢复。关闭资料页应回到主界面并保持 effect 收起；无 effect 时按钮不能折叠普通资料页或主界面。
- 检查设置等直接入口先收起 effect 再切换页面；隐藏页的遮罩、焦点、地图选点和拖放提交输入均释放，信息浏览不触发结算答案。

### B. 屏幕与画面

- 按计划矩阵检查 1280×720、1920×1080、2560×1440、1920×1200、1024×768 和至少一组超宽尺寸。
- 对 960×540、3840×1080、800×1000 做压力检查，明确支持下限及剩余问题，不将未检查的极端尺寸记为通过。
- 系统缩放按实际可用设备检查并记录；截图标明实际渲染尺寸、场景、模式和日期。
- 每次正式截图前确认当前页所需素材／字体已加载、布局已稳定、实际状态正确。固定帧数不是就绪证明；缺项或超时输出诊断与具体原因，不得写成视觉验收通过。截图后实际查看并逐区对照素材依据。
- 检查长中文、多位数字、超量候选、滚动末项、低高度弹窗、卡面等比及城市命中。
- 在模态、选中、报价等待和卡牌／设施拖拽中调整游戏应用窗口或渲染区域大小，确认没有状态丢失、误提交和焦点困死；游戏内窗口由布局自动适配，不能由用户拖动移位。

### C. 正式操作链

- 从实际入口完成代表性主要行动、快速行动、手牌操作、建设／支付、城市样式查看／宣告，以及可用的企业／科室模式。
- 验证草稿、取消、返回、合法确认、拒绝、防重入、报价过期、旧响应与当前请求变化。
- 摘要、结算链、可选效果及撤销能力显示一致；无撤销实现时确认禁用原因，不能伪造成功演示。
- 真实上下文完成前后，旧工作流无重复输入，旧窗口不会继续响应新请求。
- effect 收起期间验证同一请求刷新、pending 成功／拒绝、下一步骤、请求替换／失效和流程结束。不得自动弹回或重新提交，展开只恢复当前有效步骤；尺寸变化后使用当前布局，不能恢复旧窗口坐标。

### D. 多玩家与恢复

- 检查两实际场景及项目支持的玩家人数，当前玩家／旁观其他玩家状态分别核对。
- 用正式多人入口验证玩家可见投影：对手手牌、盖放卡、私有候选不通过详情或日志泄漏。
- 验证提交后客户端同步、切换回合、断线重连及未完成请求恢复；版本失效按现有规则处理。
- 无法运行真实多人／发布包时，明确区分已做的 EditMode、编辑器或本机模拟与尚未完成的发布级验收。

### E. 字体与数字语义

- 按[单页面与字体补充规范](02-单页面与字体补充规范.md)检查五类实际字体引用：方正普通文字、汉仪强调文字、msyh 特殊词、NarrowBold 效果数字、wide 纯 UI 数字。
- 汉仪不勾选 Bold、不使用 `<b>` 伪加粗；“策略”“计谋”明确使用 msyh 的正确字体成员。
- 资源 icon 前数字、“选择 2 次”等效果数字使用 NarrowBold，顶栏回合数使用 wide。检查混排基线、间距、换行、中文标点与缺字回退。
- 在页面切换、effect 收起／恢复、动态条目创建、应用重新聚焦及字体纹理恢复后复查角色；用户指定字体可以作为验收条件，不锁定可编辑字号与坐标。

## 问题修复与完成判断

对本轮 UI 改动造成的可复现问题，定位到具体源资产或控制器修复，并复验相关尺寸和状态。修复时继续遵守资产所有权；不能通过 Rebuild 覆盖用户界面，也不能删除行为测试来绕过问题。

新增 `执行记录/YYYY-MM-DD_UI-012_综合验收.md`，包括：

- 入口、资产来源和场景覆盖的最终表。
- 尺寸 × 窗口／交互状态的验收矩阵，标记通过、失败、未运行或不适用，并附原因。
- 单页面与 effect 收起／浏览／恢复的步骤证据，五类字体与混排实际显示证据。
- 真实截图／日志的位置、复现与操作步骤，测试命令及结果。
- 业务未接入、素材沿用、设备未覆盖、发布级多人未验证等清单。
- 本轮修复列表和最终建议；仅在必要范围全部完成后标记 UI 更新完成。

测试通过只代表受测行为成立。最终视觉结论必须基于当前实际场景显示，不能用原包预览或未应用场景覆盖的源 Prefab 截图代替。

# UI-003：常驻顶底栏与自适应框架

请执行本任务。先读 [共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md)、[视觉搭建优先与分阶段验收](03-视觉搭建优先与分阶段验收.md) 及 UI-001、UI-002 记录。前置：新版共用组件可用。

**2026-09-25 顺序纠正：当前先补齐主界面外框与全部主模块的视觉搭建，再核对层级和适配，随后接业务逻辑，最后截图验收。已经写出的逻辑保留；不以“组件已导入”或“顶底栏可点击”代替整页视觉完成。**

## 目标与范围

在实际对局 HUD 中先完成主界面外框、全部主模块框体／底图／标题／内容容器、顶底栏及其完整图标文字，再建立单页面管理和集中层级／适配配置。主要目标为 `GameplayInteractionHud.prefab`、相关嵌套模块的视觉节点、对应 View／布局和输入管理、实际两场景的相关绑定；明确哪些修改落在共享资产、哪些是场景覆盖。

本项必须形成完整新版主界面视觉结构，并解决“顶栏、底栏永远在所有对局 UI 之上且能交互”。地图／城市显示区域与必要视口约束在本项就位；精确命中和平移缩放由 UI-004 深入验证，主模块动态数据和行动流程由 UI-005 接入。本项不能只给旧桌面加两条栏，也不能以这些后续任务为由省略主模块视觉搭建。

## 阶段 A：先完成基准主界面视觉搭建

1. 盘点当前改动，保留既有逻辑和测试。暂缓新业务扩展与完整截图矩阵，建立“区域 → 文档依据 → 素材 ID／GUID → 实际节点 → 显示状态 → 缺项”的清单，检查嵌套 Prefab 的实际来源。
2. 按 1920×1080 设计基准，**先搭主界面 `outer-frame` 与整体背景**，核对四边、角部及透明中心；再搭所有模块的 `module-frame`、底图、纸面与标题。装饰与命中区分离。
3. 完整搭出左侧玩家信息／城市、中间地图／自身状态／企业家／手牌、右侧合作／弃牌／盖放／页签行动区，以及顶底栏的标牌、图标、文字、摘要槽和按钮。逐区采用文档规定的素材、切片、内边距与基准区域，不拿旧面板或纯色块替代已交付的新视觉。
4. 顶栏不能只有背景和文本，需包含品牌、回合块／刻度、阶段、行动旗标、红区分组及按钮图标；底栏需包含摘要槽、撤销底板／箭头、结束行动外观。字体按五类角色配置。
5. 把实际地图、城市板、卡牌和头像放进对应容器，必要的显示／视口接线可在此完成。未接业务的区域使用明确空态或隔离的预览数据展示结构，不在正式对局伪造库存／效果；动态空态不等于缺失整个分区。
6. 在编辑器／Game View 预览，逐区消除缺图、拉伸、错误 Alpha、Mask 裁剪和旧布局覆盖。允许少量诊断截图，注明“搭建中”；在必需视觉缺项清零前不能标记本阶段通过。

阶段出口：完整新主界面在基准尺寸实际呈现，与素材依据的构图和组件角色一致，差异已逐条说明。不能把此阶段留到 UI-005。

## 阶段 B：再核对层级与自适应

1. 核对每区的背景、内容、边框、文字／图标和命中区，再核对整体 Canvas、相机、遮罩、Raycaster 和焦点。顶底栏显示与输入最高，装饰不截获点击。
2. 建立唯一页面显示容器，窗口不得拖动；先检查结构及遮罩范围，再接 effect 状态逻辑。旧窗口／独立 Canvas 纳入统一规则。
3. 基准构图成立后，用可序列化锚点和布局约束适配大小屏。内容区扣除实际顶底栏高度，窄屏通过重排、折叠与滚动保持完整可达，不能靠裁掉素材实现。

阶段出口：基准及代表性窄／宽尺寸中，素材不越区、两栏不受遮挡，静态结构和层级成立。

## 阶段 C：视觉与层级通过后接主框架逻辑

以下步骤在阶段 A、B 完成后执行；已写出的代码按新视觉节点复核绑定，避免为了复用旧引用改变已核对的视觉结构。

1. 在共享 HUD 中建立屏幕安全区域、两栏和 `ContentRect` 的明确关系。两栏不随地图相机移动或缩放；内容区根据两栏实际尺寸扣除空间。
2. 将顶栏的回合、当前阶段、红区状态和设置接到已有数据与入口。“收起／展开”按当前 effect 页状态工作：收起保留有效请求和草稿，展开关闭资料页并恢复当前待处理步骤；无可恢复 effect 页时禁用，不用于收起主界面侧栏。底栏接入唯一结束行动入口及摘要／撤销状态承载；未提供撤销能力时禁用并说明原因。顶栏回合数使用 wide 数字字体。
3. 对顶底栏建立保留的最高层及独立输入分组。统一当前唯一页面、其内部结算／选择区域、拖拽和提示的层级分配；所有独立窗口、抽屉、设置和查看器必须经过同一页面管理。切换先隐藏旧页及遮罩，再显示新页，修正会取全局最高排序加一的路径，并审核相机合成顺序。
4. 内容遮罩限定在 `ContentRect`，内容模态锁定不影响两栏的 CanvasGroup。最高层根节点不能拦截整个屏幕。检查实际 EventSystem、GraphicRaycaster 和地图射线判定。框架中的窗口位置由资产及布局确定，不支持用户拖动移位；停用窗口移动入口及重新启用路径，窗口任务沿用此约定。
5. 实现宽／标准／紧凑三种布局策略与集中配置：伸缩侧区、可折叠内容、短摘要、必要时增加栏高；保留设置、撤销和结束行动的可达位置。阈值按可用逻辑宽高及组件最小尺寸确定。
6. 基础缩放与内容重排分别处理，确认低高度窗口的策略。静态布局关系由资产配置，运行时代码只应用模式和动态数据；避免每帧重建、互相驱动尺寸和模式抖动。
7. 处理模态中的焦点、关闭、pending、请求失效与栏内操作。收起时释放 effect 页及其地图提交输入，保留可恢复状态；同一请求刷新不自动弹回，隐藏期间同步合法性。展开复核请求与版本，旧流程失效就清理恢复信息。合法按钮保持可达，业务不允许的按钮显示禁用原因；不得为了可点而越过规则。
8. 接入两实际场景，保留后续待迁移模块的可用性，记录临时适配及退出条件；移交地图视口和其他模块的实际父节点与边界给 UI-004／UI-005。

## 阶段 D：资源就绪后验收

- 先核对主外框、各模块、完整顶底栏及当前状态所需素材；就绪条件包括资源加载、布局稳定、实际渲染尺寸正确与必需视觉缺项清零。固定等待帧数只用于超时控制，不能当作就绪证明。
- 查看实际截图并逐区对照素材文档，区分真实数据／最新交互带来的合理差异与缺陷。素材缺失时回到 A／B 修复，不继续批量截图宣告完成。

- 在各类页面、子步骤、拖拽和 pending 状态下，实际点击两栏合法功能，命中目标正确；页面切换全过程最多一页。
- 实际完成“effect 页预选 → 收起 → 资料 A → 资料 B → 展开”，确认资料 B 关闭、有效草稿恢复；关闭资料回主界面时 effect 仍收起，同一请求刷新不自动弹回。
- UI 上的操作不会落到地图；顶底栏以外的内容也没有被最高层整屏透明区域挡住。
- 固定渲染尺寸下，拖动窗口标题、背景和边缘不改变窗口位置；自动适配、列表滚动及合法内容拖拽正常。
- 基准 1920×1080、1280×720、1024×768、超宽和窄窗口检查边界，改变尺寸后无操作丢失；不能仅验证 Canvas 数值大小。
- 启用键盘／手柄导航的情况下，焦点能从内容窗口访问两栏并合理返回。
- 对独立排序、遮罩命中和动态尺寸变化补必要行为验证；不写死某一稿的栏高、颜色或标签文字。

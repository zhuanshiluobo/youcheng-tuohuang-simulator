## 3. 主框 3.5 实施约定

| 对象 | 源图 1x／2x | 源切片 1x／2x | 目标逻辑角区 |
| --- | --- | --- | --- |
| outer-frame | 1920×1080／3840×2160 | 四边 24／48 | 四边 24 |
| bottom-frame | 1920×96／3840×192 | 四边 12／24 | 四边 12 |
| chain-slot-frame | 1024×64／2048×128 | 四边 12／24 | 四边 12 |
| bottom-bar → bottom-bar-clean | 1920×96／3840×192 | 全 0 | 普通底图铺满 |

1. 三个框透明中心，使用九宫格且不填中心；底栏底图不透明，按普通图片铺满。旧白角来自底图的部分必须随底图替换，不能只在旧图上叠新框。结算槽原填充图可沿用。
2. 默认建议选 2x 框图并明确导入密度；1x 也可按实际清晰度选用。Sprite border 是源像素，实际角区是逻辑单位，2x 需配套 PPU／像素倍率。检查最终导入尺寸，避免纹理上限降采样后仍使用未换算参数。Unity border 顺序左／下／右／上，源清单为左／上／右／下。
3. 独立清单默认 1x；`catalog-overrides.json` 默认 2x，viewBox 与 slices 加倍、targetSlices 不变。不能把源边距 48 当作逻辑边距 48。描边宽约 1.25＋弱内线 0.65，切片角区不等于描边厚度。
4. 同一框只保留一个版本，整图九宫格与八片二选一。原始素材包和原文保留；用户已要求清理的旧局内节点及独占废弃资产按07删除，其他仍被合法使用的共享素材保留。不能只停用旧节点来代替本次清理。
5. 保持 UI-003 已修正的绘制顺序：主外框在主模块之下，不能遮盖左侧／右侧模块边缘。底栏自身按底图 → 框／结算槽 → 内容分层，两栏最高显示与输入约束继续有效。明确主框与底栏共享边的责任，不重叠堆出粗线。
6. 外框、槽框均为装饰，关闭射线。只改四项对应资产引用和必要的切片／局部间距；地图容器、按钮位置和模块结构不因这批边框素材被整页重建。

## 4. 三种共用行与权限

`prefab-contract.json` 是引擎无关数据说明，应在现有 uGUI 中搭实际 Prefab，并沿用请求路由。

| mode | 左标记 | 右侧状态 | 正式入口约束 |
| --- | --- | --- | --- |
| choice_execute | 空数组 | use | 只用于可映射到正式执行操作的选项；需要先选择再确认的请求保留草稿／确认流程 |
| persistent_detail | 0～2 槽 | none／unused／used／use | 其他玩家通常只读；可执行性由当前操作者的正式权限决定 |
| quick_action | 0～2 槽 | none／unused／used／use | 复用已有快速行动能力、候选和正式入口 |

- 层级：背景 → 独立边框 → 可选标记 → 标题／说明 → 右侧状态／使用按钮 → 焦点提示。字体按 02；效果次数、标记数量等用 NarrowBold，普通／强调中文用方正／汉仪且不额外 Bold。
- **仅 `right.status=use` 且规则显式给出 `enabled=true` 时允许执行。** 源组件遗漏 enabled 默认可用，项目适配不能采用这个缺省。none 回收区域；unused／used 只读，不进入执行按钮焦点序列。禁用 use 仍是操作图形，不改成 used。
- 点击派发当前稳定条目 ID 对应的正式意图；次数和 used 状态等规则回包后刷新。请求版本失效、pending、隐藏或权限改变均阻止旧提交，不能点击后乐观消费次数或直接标已用。
- 可选正文详情 `bodyAction` 与右侧使用区分别命中；详情不能触发执行，右侧点击不能再触发行正文提交。列表复用要清理旧 ID、回调、标记、数字、提示、模式和禁用状态。
- 当前 `EffectDialogOptionRowView` 只有整行 Button／背景／文字等引用。接新行需审计其 renderer 和绑定，明确旧整行选择、右侧执行和正文查看的不同语义，避免双重提交或绕过原确认流程。
- 源示例效果名、使用次数、企业家状态均不作为规则定义。公开明细数据若缺失，显示配置好的空态／不可用状态并记录接口缺口；隐藏卡 ID、暗牌内容不能为详情而泄露。

## 5. 标记与布局

- 每条最多两个槽，一个槽可以包含多个玩家色块。颜色掩码为绿 1、黄 2、蓝 4、红 8，显式映射项目颜色，不能强转项目枚举。只接受 1～15，隐藏用删除槽；mask=0 不是空标记。
- 单色非负整数 count 可见，显式 0 保留；多色不挤多个数字，提示／可访问名称描述每位玩家及数量，两个槽各自说明区域含义。
- 行高参考标准 76、紧凑 60，标记 28、右图标 32、左右留白 12；有多行文本可增高，不能横向压缩字体。隐藏左右插槽时同时回收其间距。选用素材索引对应的九宫格参数，不把源图 512×112 当固定显示尺寸。
- 行内操作与正文／相邻条目命中区域不重叠；触摸热区可扩展但不覆盖邻行。滚动条独立通道，不能覆盖右侧使用按钮。

## 6. 其他玩家明细展开与快速行动

1. 左侧实际玩家摘要增加查看／收起入口；同一时间最多展开一名其他玩家，再次点击收起、换玩家时切换。真实玩家的空列表也可展开显示空态；尚未入座的占位席位不伪造玩家或效果。
2. 明细插在该摘要下方，后续摘要顺次下移；“我的城市”保持下缘，使用剩余可读高度。1920×1080 参考：原城市 y=424、高 554、下缘 978；展开量 E=224 后 y=648、高 330。实际 E 由可用空间和最小高度限制，窄屏先限制明细高度并内部滚动，不能让城市高度≤0。
3. 城市原图在新视口中等比 contain，不拉扁，不改变格子／设施／标记数据。存在可交互城市或旧建设 View 时，检查新显示矩形下的坐标与遮挡；触及未交付相机依赖时明确留待验收，保留可用入口。
4. 明细为常驻模块内的展开区域，不新增独立页面；详情若打开单独页面仍走唯一页面管理。这个局部查看开关不复用顶栏 effect 收起／恢复按钮，也不影响已收起 effect 的请求草稿。
5. 快速行动组复用 UI-005 页签及已有“使用角色牌”等正式入口；先列出每条可见行动和原事件，再换成共用行。新行接通且核验后才停用相应旧入口，不复制监听或隐藏唯一可用功能。六个主要行动和底栏 3.2 按钮继续沿用。

**UI-004 暂缓，等待俯视改造交付；UI-005～UI-008 的独立局内工作已有各自交付。当前先做基础修正，继续遵守此地图边界。** 本安排优先于旧文档中“先完成整个 UI-004 才能做其他 UI”的顺序。历史记录保留，暂缓不记为验收通过。玩家明细与原生填充会改变城市视口，其实际显示／格位仍需针对改动核对，不能据地图暂缓跳过。

## 2. 已核对的相机接入事实

UI-003 的[交付记录](执行记录/2026-09-25_UI-003_常驻栏与适配框架.md)明确记录相机 `pixelRect` 跟随中央地图区域，并在两张地图源 Prefab 保存 `framedViewportZoom: 1.2`。当前代码也存在以下链路：

1. `GameplayHudFrame.ApplyMapViewport()` 读取中央 `mapRegion` 的屏幕矩形，交给 `MapDisplayController.SetScreenViewport()`。
2. `SetScreenViewport()` 保存归一化视口并调用 `FitCameraToMap(true)`；该方法设置 `targetCamera.rect`，按有效宽高比重新计算透视取景距离，尝试保留导航状态。当前实现还会设置 `targetCamera.orthographic = false`。
3. 当前 `MapCameraGeometry.TryScreenPointToPlane()` 先检查相机视口，再用 `ScreenPointToRay` 与平面求交；这说明当前命中也受视口契约约束。本次只读核对，未据此宣称所有点击已准确。

因此，“UI-003 只调了摄像头高度和位置”不符合完整实现。即使暂缓现视角回归，新俯视方案仍需承接中央地图框和输入边界；若采用正交相机，也要处理运行时重新设置透视的旧路径。这里不预先指定俯视必须使用哪种投影。

## 3. 给俯视改造交付的接口要求

- 记录实际相机、地图源 Prefab、场景覆盖、地图平面／坐标来源和运行时控制器，避免与 UI 的视口更新各自驱动一套相机参数。
- 保留中央地图区域到显示视口的配置接口，读取原生布局完成后的实际矩形；应用窗口改变大小时更新。主界面不再因比例隐藏地图列或切分区，合法页面覆盖时地图提交输入按统一页面规则停用。
- 新姿态／投影在启动、重新取景和尺寸变化后仍正确；不能只改编辑器参数，运行时又恢复旧姿态或投影。
- UI 对地图的输入阻挡、顶底栏最高显示与输入层继续有效；effect 收起后释放地图选点，展开只恢复有效请求。
- 世界地图改造以地图相关源资产为范围。共享 HUD 有并行 UI 换新时保留其按钮、字体、布局和静态文字；确需改接口时明确节点与引用。

## 4. 恢复 UI-004 与最终验收

俯视改造完成并给出资产／代码来源和验证记录后，再恢复 UI-004。先读改造结果，删除重复工作安排，仅对最终实际方案检查地图框内显示、中心／边缘点击、标记／高亮、缩放平移、选点以及变化尺寸后的命中。

城市板的映射证据若已由 UI-005／008／010 提供，UI-004 复用并核对相机改造是否影响它，不再重复搭建。若尚未迁移或存在相机依赖，补齐后才能通过对应功能验收。

UI-012 可以先收集独立 UI 证据；新地图交互及依赖它的真实流程未验收时，保留待验清单，不宣称整轮 UI 已全部完成。当前无需针对即将替换的倾斜视角展开完整地图测试。

本轮仅调整文档依赖并只读检查代码；没有运行 Unity、修改相机／场景资产，也没有向其他任务发送指令。

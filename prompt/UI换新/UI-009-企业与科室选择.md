# UI-009：企业与科室选择

请执行本任务。先读 [共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md) 和 UI-001 业务能力表、UI-006／UI-007 接入约定。前置：共用选择与上下文可用。

## 目标与范围

实现企业选择、企业特效选择和莱茵生命公共科室选择的新版表现与可用正式接入。处理对应窗口 Prefab、View、配置及已存在业务适配，不在此任务自行发明企业规则。

## 阅读入口

- `EnterprisePicker-Layout-v1.0.md`（实际 1.0.1）、`RhineDepartment-Layout-v1.0.md`。
- 整理版企业状态框、企业板和科室原板映射，以及 UI-001 查到的实际入口／业务接口。
- 当前正式内容与规则边界，不能仅根据旧计划认定企业扩展已完成。

## 工作步骤

按[视觉搭建优先规范](03-视觉搭建优先与分阶段验收.md)先依来源完成企业／科室页面外框、标题、原板、标记、详情与按钮，再核对层级／适配，最后接已具备的业务能力。组件预览、正式接入和正式验收分别记录。

1. 先复核正式候选、等级、可触发特效、公共科室、取消权限及提交接口。逐项标明已有、需表现适配或规则尚未提供。
2. 企业窗口区分 `company` 与 `effect` 模式：前者提交企业目标，后者提交企业与特效目标。确认企业不自动跳入特效选择，普通升级奖励不做成可点特效。
3. 企业板按 650×1850 等比展示，详情与各玩家等级分别更新；当前查看与当前选择明确区分。数量变化后重排或滚动，不把四张同屏当固定数量上限。
4. 不可选企业／特效按允许的可见数据提供原文和具体原因；确认时复核目标、资格、支付和请求状态。复杂目标由共用子选择承接，可选效果使用全局抽屉。
5. 科室窗口复用开局选择与中途切换两种模式，显示全体共享的唯一激活科室。开局可无当前科室；当前科室在切换中可查看但不可重复确认。
6. 科室板按 516×1000 等比显示，2～5 级内容是板上奖励信息，不拆成多个独立特效按钮。确认只提交正式科室目标，公共状态与奖励由规则结算。
7. 紧凑布局可将企业详情和候选分段切换；支持零／少量／超量候选、独立滚动和详情返回。整个窗口及查看器都位于两栏之下。
8. 如果所需规则尚未提供，完成可复用窗口与明确的适配接口说明，使用隔离的验证数据检查表现；不接入会伪报成功的正式按钮。报告组件完成与正式接入未完成，继续推进无依赖的后续任务。
9. 企业／科室页、详情和复杂目标选择统一占用唯一页面位置，父页与子选择不能同时显示。由 effect 唤起时支持收起保留有效草稿，展开关闭其他资料页并恢复当前有效请求；普通查看页不会成为顶栏 effect 恢复目标。
10. 套用五类字体配置，费用、奖励与效果相关选择数量使用 NarrowBold，纯 UI 数字使用 wide；特殊词用 msyh，常规／强调文字分别用方正／汉仪且不额外加粗。

## 验收

- 两种企业模式提交目标正确，查看不提前触发；科室模式不复制公共状态或错误给其他玩家补发奖励。
- 长板可完整查看，等级与候选状态清晰；详情返回、窗口调整和请求失效处理正确。
- 只使用玩家可见数据，合法性复核、防重入与两栏交互约束成立。
- 页面切换及 effect 收起／恢复期间最多一页，字体角色符合补充规范；业务未接入的模式仅报告组件验证。
- 每个模式分别标记真实业务验证、仅组件验证或缺少规则；不能用演示回调通过替代真实接入。

## 可直接交给执行者的提示词

请继续执行 UI-005，并将新提供的 MainButtons 3.2 补丁作为本任务的按钮素材依据。先读取项目 `AGENTS.md`、共同约束、实施计划、02／03／[04 按钮规范](04-主界面按钮3.2增量规范.md)、[05 任务安排](05-地图俯视改造期间的任务安排.md)、UI-003 的最新交付记录，以及[增量素材入口](../../游城拓荒/UI素材/整理增量-2026-09-25-按钮3.2/README.md)。保留相机改造范围；地图相关端到端验证明确留待俯视改造后补齐。

按钮补丁仅涉及三个右下业务页签、六个主要行动、撤销和结束行动，共 11 个。复用现有正确纹理和业务事件，在基础修正后的原生结构上核对；历史主框架中按比例切主分区的实现已撤销。保留其他界面的素材依据与用户调整；增量纹理和配置按功能目录存放，不覆盖源 ZIP、说明、旧整理目录或执行记录。

### A. 核对与完整视觉

1. 确认 `GameplayInteractionHud.prefab`、实际场景覆盖和当前按钮监听来源，声明编辑共享源还是场景覆盖。普通测试和截图流程不能调用生成器；执行本提示词不构成批量 Rebuild 整个 HUD 的授权。
2. 建立 11 行按钮映射表：用途 ID、当前节点／缺项、旧事件及去向、3.2 底板系列和图标、Unity 路径／GUID、状态配置、验证状态。读取整理索引中的逐状态路径，不能只凭同名文件或旧布局顺序映射。
3. 先查清“使用角色牌、宣告样式”及旧翻面中夹带的真实业务；新版主行动六格是部署、调度、探索、城市移动、建设、特殊行动。角色牌与宣告入口按语义迁移，不能按位置改名成建设／特殊行动。旧翻面及“查看提示／上下文按钮”必须删除；真正的第二效果继续／结束移到新版 effect 步骤，不能为了保留规则能力保留旧翻面结构。不用网页 `previewAction` 绑定规则。
4. 选定 PNG 倍率，仅导入所需素材。1x 底板为 256×80、切片 12；2x 为 512×160、切片 24，并配套 PPU／像素倍率。图标 64×64 或 128×128，等比显示。不要把预览截图或源包工具导入运行时资源。
5. 从搭建开始把底板、独立图标、文字、必要分隔线和焦点层放入最终布局。页签栏用 HLG；主要行动网格使用原生 GridLayoutGroup，必要时局部列数辅助器只更新网格参数；底栏按钮由栏内 HLG 分配。按钮内部图标与文字用 HLG 和 LayoutElement，底板／焦点层拉伸且不参与排布。用 padding、spacing、首选尺寸保持正常 1920×1080 位置；11 个按钮具备完整视觉，未接业务的显示禁用。
6. 字体继续使用五类角色；普通文字方正、强调文字汉仪且无 Bold，静态文字保存于资产。仅“图片和文字分层”不能成为运行时代码重写固定文案的理由。

### B. 层级与适配

7. 核对按钮内部绘制顺序、Raycast 与命中区域；底栏两按钮仍处于两栏最高层。选中描边、图标或焦点图层不额外抢输入，结算槽不遮挡按钮。
8. 沿根 VLG → 中间三列 HLG → 右列 VLG → 业务页签／行动正文检查实际尺寸传递。页签固定高度，行动正文取得剩余高度，列表超量在正文内滚动；三主列始终保留，不使用紧凑分区导航。按钮组只在正文内部换列，不能把整个行动区换成屏幕导航。按 07 规范显式配置 childControl／ForceExpand，防止所有按钮或页签无差别扩张；图标保持比例，背景填满分配区域。

### C. 状态与业务

9. 处理 `UiSharedButtonState.Refresh()`、旧主题 tint、Unity Button transition 与新 Sprite 状态的职责。为目标按钮绑定新配置，正常、悬停、按下、禁用和页签 selected／selected-hover 使用包内对应素材；不能运行几帧后回到旧 Sprite。其他共用按钮不应被全局改色或换图。
10. 选中与悬停／焦点分别保存，禁用优先于其他状态。按下后失效、隐藏或进入 pending 不得提交；pending 结束重新读取最新合法性。使用各底板的 recommendedInk 对应图标和文字对比度，避免重复染色。
11. 在原 UI-005 行动入口迁移中完成三个业务页签与各项真实事件。部署、调度、探索、城市移动沿用正式入口；建设和特殊行动先复核能力，没有明确接口的项保持禁用并登记。旧角色牌／宣告样式的真实操作迁至新版正式入口并验证，随后删除用户指定旧表现及重复监听。迁移未完成记待办并继续处理，不能用“旧翻面暂需保留”作为清理结论。
12. 撤销仍由真实规则能力决定，结束行动仍复用原 `EndRoundButton` 的正式路径。不能新增本地回滚、绕过必选结算或复制第二个提交按钮。资料入口遵循唯一页面管理；effect 收起后可查看资料，展开时关闭资料并恢复当前有效步骤。
13. 完成 UI-005 主提示词中的玩家、手牌、合作区等数据接入。本补充只补足按钮要求，不能把完成 11 个按钮等同于完成整个 UI-005。

### D. 验证与交付

14. 先检查引用完整、必要状态和单次提交；仅为新增状态／交互风险补必要测试，不锁定用户可修改的坐标、字号或颜色。
15. 原生结构、素材、字体和当前合法状态就绪后，有限检查两场景基准、1920×1200、一个宽度／低高度变化及恢复基准。三个主区域无需导航就同时显示；三业务页签均检查按钮末项、固定页签与可滚正文的边界。没有布局能力、缺素材或错层时先修复，不持续生成全尺寸图片。
16. 验证页签鼠标离开仍选中、selected-hover、禁用覆盖选中、按下时失效、键盘／已启用手柄提交、触摸禁用和动态尺寸切换。按项目实际支持的输入方式记录结果；无法操作的设备写未验证。effect 页收起和两栏合法操作不得回退。
17. 追加新的 UI-005 执行记录与按钮映射清单，附实际源／覆盖、GUID、原生父布局和尺寸驱动者、各状态证据、删除旧入口的结果、真实业务和未接入项。新生产路径、物体、组件与长期测试按功能命名；任务编号只留在提示词和历史记录。源 QA、组件截图、浏览器演示和素材哈希不能替代正式游戏验收。

按上述阶段连续执行并自查，无需逐阶段等待确认。若缺少规则定义或无法明确行动语义，只推进独立可交付工作并说明该缺口，不能凭素材图创设规则。

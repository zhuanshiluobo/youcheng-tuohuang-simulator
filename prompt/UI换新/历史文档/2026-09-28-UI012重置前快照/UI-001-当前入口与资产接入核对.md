# UI-001：当前入口与资产接入核对

更新日期：2026-09-26。先读[共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md)、[原生布局、命名与清理规范](07-原生布局命名与旧UI清理纠正规范.md)和项目根 `AGENTS.md`。本项只读核对并新增报告，不修改 Unity 资产、运行时代码、源素材或历史记录。已有 UI-001 结果可作为索引，实际资产与引用须按当前状态复核；后续基础修正不要求重新运行旧迁移器。

## 一、目标与范围

把素材版本、真实局内入口、资产所有权、布局驱动、业务能力及旧 UI 依赖核对到可实施程度。覆盖顶底栏、三列主界面、列表／卡牌／选项、建设、企业／科室、城市样式、专用效果、设置、日志、规则书、查看器与终局／断线页面。

启动、加载、房间大厅和收藏室不属于本轮改动范围。共享资产应记录所有引用者，并区分已隔离的局内副本和仍供局外使用的源，避免后续任务影响局外实例。

## 三、阶段 A：入口、素材与所有权清单

1. 记录工作区状态、Unity 版本和实际场景，区分本项前已有修改。任何只读运行、预览或截图不得调用 Rebuild、生成器或保存覆盖。
2. 从场景、Registry、序列化引用及运行时实例化路径交叉枚举所有局内页面。记录：功能、实际触发步骤、源资产绝对路径、GUID／fileID、嵌套来源、有效场景覆盖、控制器、数据投影、当前可达性。
3. 给各可见部件建立“用途 → 源包版本／素材 ID → 原文件 → 已导入资产／GUID → 实际节点”的映射。区分源像素、逻辑显示尺寸、九宫格、透明留白、卡图比例与状态图；预览截图不作为正式素材。
4. 查已有资源是否已满足新版用途。相同字节或相同职责的资产先核对复用，记录必要导入差额，不能为每个任务建立重复目录。3.6 仅替换卡牌查看／角色使用窗口，不推翻通用选牌、盖牌或全部快速行动列表。
5. 源文档中的全屏遮罩、固定画布缩放、拖窗和按尺寸换页若与当前要求冲突，写出项目采用规则；原文保留，后续任务不能直接照搬浏览器参考实现。

**出口：** 每个可见模块有来源和实际目标，缺少素材、尚未接入与合法空态分别标记；共享源／局内副本／场景覆盖没有混用。

## 四、阶段 B：结构、命名与旧 UI 审计

### B1. 布局与层级表

逐个记录实际对象的横轴驱动者、纵轴驱动者、父容器、原生组件、min／preferred／flexible、padding／spacing、滚动轴及其他 RectTransform 写入者。要求核对：

- 安全区域内上／中／下由原生 VerticalLayoutGroup 分配，中间三列由 HorizontalLayoutGroup 并排，各列内部再用 VerticalLayoutGroup。正文／城市／地图等主体获得剩余空间，背景和 Viewport 实际填充。
- `LayoutElement` 的输入确实被父 LayoutGroup 使用；有组件但被脚本覆盖、仅整列外壳伸展而子区固定、普通行列继续由自定义组件写坐标，均列缺陷。
- 列表 Content 可以按内容增高，Viewport 必须受限。检查整列 ScrollRect、整列 Fitter、缓存原坐标再累加偏移、尺寸阈值隐藏整列和分区导航。
- 顶底栏最高显示与输入，PageHost／遮罩受内容区约束；页面互斥，effect 隐藏释放输入但保留有效上下文；游戏内窗口不可拖动。
- 业务页签、手牌分页、规则书翻页、真实子步骤和用户主动展开明细与尺寸适配分开，不误列为应删除功能。

### B2. 生产命名表

搜索源码、类／命名空间、目录、Prefab／场景对象、配置、长期测试／工具、自动化 ID 中的实施任务编号。为需迁移项提出“旧路径／名称 → 按功能的新路径／名称 → GUID／fileID → 引用者 → 类型／字段兼容风险”，同时核对字符串查找、Resources／Addressables、动画、UnityEvent 和场景覆盖。历史提示词及证据中的编号允许保留，不通过改历史实现零命中。

### B3. 旧 UI 清理表

清点旧资源计数器、旧翻面及“查看提示／上下文按钮”变体、旧固定弃牌区与重复预览壳、旧盖牌拖放残留、尺寸触发的主分区导航。每项列实际节点／文件、运行时及编辑器引用、必需业务的新入口、独占资源与共享资源边界。改名、停用或移出屏幕不等于清理完成；本项只提出精确清单，不执行删除。

**出口：** 全量局内 UI 有实际结构记录；每个命名／清理目标可定位，普通行列的布局缺陷和生产残留有明确后续处理范围。

## 五、阶段 C：真实业务与基准

1. 逐入口跟踪候选来源、可见权限、请求所有者、报价、提交、pending 回包、取消／返回及失效恢复。区分主要行动草稿、阶段盖牌与 effect 请求，不能把普通查看误当确认。
2. 第二效果继续／结束、弃牌查看、资源及手牌刷新与旧 UI 的耦合单列。新入口必须保留必要规则决定，不能以删除按钮为由自动结束或绕过步骤。
3. 企业、科室、公开效果、全局结算链和撤销逐项标为“已有正式接口／需表现适配／规则未提供”，附真实符号或缺口证据；素材示例不构成规则。
4. 核实已有 1920×1080 基准是否对应当前真实资产与相同业务状态。必要时只采一组正常基准，记录实际渲染尺寸、安全区域、Canvas 缩放及关键屏幕矩形；隐藏或零尺寸对象不作为有效基准。
5. 已知越界和用户明确删除目标单列差异，不能固定为正确构图。结构未完成时不跑多尺寸矩阵，不提出把三列改为分页的下限方案。

## 一、盖牌阶段接入角色牌选择 UI

### 目标

游戏进入当前玩家需要盖牌的阶段时，使用 UI-007 的新版角色牌选择界面：**查看候选 → 单选一张 → 确认盖牌**。正式盖牌由这个入口完成，替换原来的拖动角色牌到放置区域的交互。

### 实施要求

1. 核对实际阶段与资格。当前阅读入口为 `GamePhase.CharacterCover`、`CharacterCardPanelPresenter.BuildView` 的 `CanCover`／手牌项资格，以及 `MobileCityInteractionController.SubmitCoverCharacterCard`。复用真实盖牌规则和 `CreateCoverCommand → CoverCharacterCard` 提交链，不把盖牌误接成使用角色牌、开局移出两张或 effect 的 `AnswerInteraction`。
2. 复用当前实际 `EffectDialogShell`、卡牌网格、选中态、详情、确认及模式配置；为盖牌提供明确的单选模式和接线。外壳页头／正文／页脚由 VLG 分配，底部按钮由 HLG 排列，网格与内部滚动占正文余量，不能再以自定义普通布局逐项写坐标。不能只造组件演示或另建外观相同但未被正式阶段调用的窗口。标题、说明和按钮文案放在资产配置，字体继续遵循五类角色。
3. 候选只来自本机有权查看的当前手牌与真实可盖牌资格，按稳定卡牌 ID 选择；未选不能确认，预选和查看详情不改变游戏状态。非当前玩家或不可盖牌时不能借打开窗口提交；候选为空时显示真实原因，不伪造卡牌或自动跳阶段。
4. 阶段进入、轮到本机、重新同步／恢复时能够打开正确选择页。相同阶段与上下文的重复刷新不能反复创建窗口、清空有效预选或抢占正在查看的详情。上下文变化、候选移除、已盖牌或阶段结束时清理过期选择；窗口回调复核当前阶段、玩家、资格及对应会话版本。
5. 确认仅提交一次，pending 期间防重复。以正式成功／拒绝／同步结果更新手牌和盖放显示，不能提前移除卡牌或直接写本地 `GameState`。拒绝后保留仍有效选择并允许重试；旧回包不能关闭新上下文的页面或解开新命令的提交锁。
6. 接入统一单页面管理，顶底栏仍可交互、窗口不可拖动。盖牌是阶段操作，不能伪造成待结算 effect 来复用顶栏恢复按钮。若原规则允许返回／关闭，必须有可达的重新打开入口，返回只影响预选和页面，不能绕过必须盖牌的阶段。
7. 当前交付已声明删除 `CharacterCardCoverDragCoordinator` 与盖牌拖放提交；开工核实其实际结果，检查 `CharacterHandPanel` 及旧放置区是否还有确认／取消、拖放提示、命中区域、待提交动画、快捷键或监听残留。已删除的类不重建，已经能走通的正式新版盖牌链不重做。手牌内部排序、卡牌查看和其他合法拖拽按各自职责保留。

### 验收

- 从真实对局的盖牌阶段进入新版选择页，选择本人合法手牌、查看详情、返回后确认，正式状态正确更新；不以手动打开壳或注入诊断候选代替正式接入。
- 未选／空候选、非本人阶段、手牌变化、已盖牌、重复点击、拒绝／迟到回包和同步恢复处理正确；取消权限与原规则一致。
- 旧拖动放置不再提交盖牌，只有新版确认是有效入口；盖牌后正常进入后续流程，角色牌使用与效果结算继续可达。

## 二、整个右栏按可用高度纵向填充

### 目标与审计范围

修复用户报告的“屏幕变宽后，右侧局部 UI 仍保持固定纵向尺寸”。检查**右侧整列及全部子分区**，包括身份／资源显示、正式角色操作内容、真实状态提示消息、操作区、页签栏及主要行动／快速行动／城市样式三个页签。状态提示消息由当前业务状态提供，不包含已要求删除的旧 HintFace／提示卡面。修复父级到最终背景、边框、Viewport 的高度传递，不能只改右侧最外层矩形。

当前审查起点已变化：`UiActionsColumnLayout` 现在继承 LayoutGroup，用 `cooperationPreferredHeight`、`deckPreferredHeight`、`actionsPreferredHeight`、`minimumActionFraction` 等自行分配右列高度；其 `SetLayoutVertical` 逐项 `Place` 写入子区矩形。不能继续把 UI-008 早期的 `UiActionRegionHeight.flexibleHeight = 0` 当作未经核对的当前根因。开工应读取实际 Prefab 和场景覆盖，连同 `UiHudColumnsLayout`、`UiActionGroupLayout`、`UiActionCardContentLayout`、GameplayHudFrame 的尺寸写入及当前布局组件逐级核对。

本次要求是把普通行列职责交给原生 LayoutGroup；不能因当前自定义算法已填满某个尺寸就继续沿用，也不能只把该类改成语义名。先列出两个轴的真实驱动者与尺寸来源，再明确删除哪段旧算法、由哪个原生父组接管。

### 实施要求

1. 根 `SafeAreaRoot` 的 VerticalLayoutGroup 只排列顶栏、ContentRoot、底栏，顶底栏高度只扣一次，ContentRoot 用 LayoutElement 取得剩余高度。ContentRoot 内 MainColumns 拉伸填满并由 HorizontalLayoutGroup 同时分配左／中／右三列的宽高。右列再用 VerticalLayoutGroup 分配合作区、卡区、业务页签和当前行动区；PageHost 与装饰为叠加层，不参与三列计数。
2. 按 07 规范配置父布局的 childControl、Force Expand 和各子项的 min／preferred／flexible。标题、页签与必要按钮按内容保留高度，主体和 Viewport 取得高度余量。右列 VLG 的 childForceExpandHeight 不应把所有块平均拉高，只有指定主体通过 flexibleHeight 伸展；三列 HLG 的 childForceExpandHeight 保证列高填满。卡区内并排对象用 HLG，不能继续由 `UiActionsColumnLayout.Place` 等普通坐标算法安排。
3. 三个页签的实际显示组分别验证。隐藏组不应继续占位；切换后父容器与当前组正确更新。快速行动的长效果行、城市样式现有入口、正式角色操作及真实状态消息均纳入；旧 HintFace 不保留、不作为验证状态。第三页布局问题在本项修复，不延到 UI-010。
4. 外壳、背景、框线、滚动视口沿分配区域填充；内容超出时在本区内部滚动，保留可达操作区。填充的是应伸展的布局空间，卡图保持比例，文字与按钮不靠任意拉高或整块缩放来填满。
5. 高度不足时先检查所有固定项、最小高度、padding 和 spacing 的总和，压缩可调整留白，正文在各自 Viewport 内滚动；高度充足时将余量交给允许伸展的区域。普通候选网格可在本区按宽度换列，但不得切换主分区页面、隐藏整列、缩放或平移整张 HUD，也不得给整个右列加 ScrollRect。避免把所有首选高度当硬下限，以及多个 Fitter、LayoutGroup 和每帧坐标脚本争抢同一轴。
6. 布局稳定后，用同一坐标空间记录父子实际矩形，证明右栏、各分区和 Viewport 在分配范围内并填满约定空间；底端不越过内容区、不被底栏遮挡。固定 padding 和设计留白允许存在，不能以大块非设计空白掩盖未填充。
7. 移除旧驱动者后检查尺寸变化、页签切换和下一帧，确认代码不会把布局结果写回。CanvasScaler 只负责基础缩放；宽度变化引起 Canvas 逻辑高度、换行变化时必须重算两个轴。窗口没有拖动能力，玩家不应靠移动窗口或按“地图／行动／玩家”导航才能访问三列。

### 验收顺序

先检查原生组件层级、驱动唯一性及完整的 1920×1080 基准，再定向验证 **1920×1080 → 1920×1200（16:10）→ 2560×1080 → 1920×1080**，最后检查低高度。记录实际渲染尺寸、Canvas 逻辑尺寸和同一坐标空间的实际矩形；覆盖三个业务页签、对手明细、正式角色操作状态和长列表，旧提示面不再是测试状态。每个尺寸三主列同时可见，不能通过选择某个主分区再截图。发现未适配区域就返回实现，不能重复批量截图已知失败布局；低于可读下限如实记录，不擅自增加分页回退。

## 三、移除旧资源计数器、翻转和弃牌区

### 清理原则

用户本次明确要求彻底删除这些**旧 UI**，包括后来改名保留的变体。本项先核对并迁移仍需保留的真实业务，再删除旧节点、事件、失效引用、独占旧表现逻辑以及会重新生成它们的废弃工具分支。资源、盖牌／用牌规则及弃牌数据继续由正式状态维护。不能把隐藏、移出屏幕、禁用、换贴图、改名或改文案当成删除完成。

| 对象 | 删除前必须完成的工作 |
| --- | --- |
| 旧资源计数器 | 新版 HUD 完整显示其应保留的资源与其他必要数值；资源、手牌、盖牌和建设刷新脱离旧板；删除旧板实例、独占表现和仅服务它的 builder 分支 |
| 旧翻转及其变体 | 删除旧 Flip、`Action Panel Context Button`、查看提示／返回行动切面及专用顶部占位；真正的第二效果继续／结束转到新版 effect 选择页，保持原命令和资格 |
| 旧弃牌区及内嵌预览 | 保留新版 HUD `Discard Region`／`Discard Count`，把查看接入新版只读卡牌列表／详情；删除旧手牌固定控件和 `CharacterHandPanel` 内的旧 Preview／Overlay 整套壳及监听 |

### A. 旧翻面与查看提示的具体清理

1. 审查实际 HUD 中的 `Action Panel Context Button`（原 Flip Button）、ActionPanelView 的 `flipButton`／`hintCardTexture`、必需配置校验，及 `ActionPanelController.Flip`、`ShowHintFace`、`ActionPanelFace.Hint`、`SetFace` 的旧切面分支、`OpenHintCardViewer` 和专属实例。删除按钮、提示面和其唯一用途的对象、字段及分支；调整正常行动显示，不能再次换名字迁到其他区域。
2. 从 `SecondaryLayoutProfiles`、`ActionPanelLayoutProfile.asset` 清理仅为旧切面存在的 `ViewHintButtonText`／“查看提示”／“返回行动”文案与占位布局。删除 `action.context`、旧 `action.flip` 自动化绑定以及按名称查找旧按钮的路径。正式查看器的返回行为仍可存在，但不得沿用这套旧切面控件或触发角色规则。
3. 第二效果决策改为新版 effect 选择步骤中的明确“继续／结束”操作，读取真实规则资格并复用当前正式决定链（审查 `SubmitSecondEffectDecision` 及原 `FinishCharacterUseButtonClicked` 的调用）。分别核对合法继续、合法结束、不能继续、pending、拒绝和上下文已结束的情况。不自动替玩家决定；普通查看器取消、关闭、返回、顶栏收起均不能提交结束使用。
4. 角色牌使用通过正式快速行动入口进入新版使用／选择页。CardViewer 3.6 的完整整合归 [UI-011 查看器补充](UI-011-补充-卡牌查看器3.6.md)，其 `inspect`／`use-character` 与 effect 的第二效果步骤职责分开；不得把旧翻面保留到 UI-011 作为基础修正完成的理由。
5. 更新依赖旧表现的测试与探针：`RuntimeUiLayoutTests` 中翻面查看提示、为上下文按钮保留顶行的断言，以及 `GameplayInteractionHudPlayModeProbe` 直接点击 FlipButton 的步骤，都应改为新版真实入口和业务行为验证。不能通过保留旧按钮使旧测试继续通过，也不能删除真实业务断言来掩盖新入口缺失。

### B. 旧资源板与刷新依赖

1. 当前 UI-008 交付已经删除局内旧资源板实例；重新检查两张场景和实际 HUD 的源／覆盖，保留该成果。核对 `MobileCityInteractionController.RefreshResourceCounter` 当前实现，确认资源板缺失不再提前返回并阻断手牌、盖牌和建设刷新；旧文档描述的是历史依赖，不据此重加对象。
2. 如果 `RefreshResourceCounter` 已承担更广的界面刷新，按真实职责拆分或语义化重命名，保持所有调用者与状态刷新；不能因为方法带 Counter 一词就删除整个业务更新。
3. 全项目审查 `ResourceCounterBoard`、`ResourceCounterBoardView`、`ResourceCounterBoardLayoutProfile`、`ResourceCounterVisualLibrary`、`ResourceGearCounterView`、`ResourceAuxiliaryCounterView`、旧 `ResourceCounterBoard.prefab`、布局资产及独占齿轮／读数素材。对只被废弃旧 UI 互相引用的文件形成最终精确删除清单；不能因为它们互相引用而全部永久保留。
4. 审查 `Ui003VisualBuilder` 等旧工具的资源板查找／构建分支。仅服务废弃 UI 的分支应一并移除，不因“编辑器仍引用”保留整条废弃链；合法工具的其他职责继续可用。移动或改名时不要运行旧生成器重新造资产。
5. 新资源数值与原有其他计数逐项核对数据来源。通过正常资源变化和一次盖牌／建设后刷新验证，确认数值、手牌与建设信息按真实状态更新。

### C. 旧固定弃牌区与内嵌预览页

1. 保留新版 HUD 的 `Discard Region`、`Discard Count` 与正式弃牌集合；不得按 Discard 关键词删掉全部资源。新入口只能展示当前玩家有权查看的弃牌数量与卡面。
2. 新入口应打开新版只读卡牌列表，卡牌详情复用新版正式查看能力，并由唯一 PageHost 管理页面。关闭后恢复有效焦点和列表位置；从 effect 中查看时遵守当前合法上下文，不触发用牌或结算答案。
3. 删除 `CharacterHandPanel` 原嵌套预览页的 `Discard Preview`／`Discard Preview Panel`／`Discard Preview Overlay`／`Discard Preview Scroll`／`Close Discard Preview Button` 等独占节点、视图字段与必需校验；清理初始化、Render、打开、关闭、销毁中的监听、页面注册和旧布局依赖。新版入口仍指向旧 Overlay 不通过。
4. 可复用的卡牌项渲染和只读数据可以提取为明确的共用组件，不能复制一套旧外壳后改名。不要删除整个 `CharacterHandPanel`，新版盖牌选择、手牌排序、合法查看和牌图继续保留。

### D. 删除清单与出口

删除清单逐项写出：旧对象／文件的绝对路径、源 Prefab 与场景覆盖、GUID／fileID、引用者、必要业务的新入口、独占或共享依据、实际删除结果及验证。共享字体、卡牌数据、原始素材包、说明和仍被合法局外页面使用的资产不在删除范围。原提示卡内容是否共享须单独审查，删除旧 UI 不等于删除原图档案。

涉及文件时先列出并核验每个项目内绝对路径和全项目引用，按根 `AGENTS.md` 使用明确目标删除并检查 Git 状态；禁止泛删目录。先迁移必需业务后删除旧表现。若替代入口未完成，该项必须继续标记未完成并处理，不能把“仍需保留旧控件”作为清理通过理由。

### 验收

- 两张实际对局场景使用的新旧来源一致，已清理旧节点不再显示、占位、接收射线或被运行时重新启用；新资源显示、手牌／盖牌刷新及建设面板正常。

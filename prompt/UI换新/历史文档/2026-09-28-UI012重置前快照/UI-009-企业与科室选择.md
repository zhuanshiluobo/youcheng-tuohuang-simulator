# UI-009：企业与科室选择

## 一、目标、范围与来源

实现企业选择、企业特效选择和莱茵生命公共科室选择的新版表现及现有正式接入。目标限于实际局内入口引用的窗口、View、配置、条目和必要业务适配。启动、加载、房间、收藏室及其共享源不改，不自行发明企业规则。

必读：

- `游城拓荒/UI素材/EnterprisePicker-Layout-v1.0.md`（实际 1.0.1）、`RhineDepartment-Layout-v1.0.md`，整理版企业状态框、企业板及科室原板映射。
- `GameplayDialogRegistry`、`InteractionRequestRouter`、当前企业／科室请求和实际 renderer、相关 Prefab／嵌套来源／场景覆盖。类或路径已按功能改名时使用基础修正映射，不恢复任务号目录。
- 当前正式候选、企业等级、可触发特效、公共科室状态、取消权限、支付与提交接口。逐项查当前实现，不能据旧计划或源预览认定规则存在。

## 二、阶段 A：接口与资产清单

1. 列出企业选择 `company`、企业特效 `effect`、开局科室选择、中途科室切换四种模式的正常触发步骤、请求所有者、可见投影、稳定目标 ID、允许取消／返回条件和正式提交路径。
2. 各模式标为“正式接口已有／需表现适配／缺少规则”，附实际符号与缺项。缺少规则时先做可复用组件和明确禁用／空态，不能绑定演示成功回调。
3. 逐项列源素材→当前资产／GUID→实际节点，注明旧源、局内副本及场景覆盖。先复用已有共用行／选择壳／图片，不为 UI-009 新建同职责主题、模态管理器或任务号目录。
4. 记录实际正常 1920×1080 的页面屏幕矩形、相同数据及必要展开状态。已有正确位置保持；新素材尚未接入的部分按来源构图补齐，并明确新增差异，不移动整套主界面。

**出口：** 各模式入口与能力可查，修改目标和布局基准明确；没有把隔离预览或素材示例当作正式游戏状态。

## 三、阶段 B：完整素材与原生布局

先在实际局内 Prefab 中搭结构，再放入全部图片、状态框、标题、标记、详情和按钮。每个普通行列使用原生组件，不能照抄绝对坐标后再挂一个不生效的 Layout。

| 层级 | 原生布局／轴向责任 | 实施要求 |
| --- | --- | --- |
| 窗口外壳 | PageHost／ContentRoot 限定外部矩形，窗口内 VerticalLayoutGroup | Header、Body、Footer 三段；窗口不可拖动，内容遮罩不覆盖顶底栏 |
| Header／Footer | LayoutElement 提供内容 min／preferred，flexibleHeight 为 0 | 标题和合法操作始终有空间；Footer 按钮用 HorizontalLayoutGroup，不被正文挤出 |
| Body | LayoutElement 的 flexibleHeight 大于 0，HorizontalLayoutGroup 组织既有并排内容 | 候选与已存在详情区域按基准宽度、合法最小值和 flexible 分配；纵向填满实际正文 |
| 候选列表 | 受限 ScrollRect.Viewport；Content 使用 GridLayoutGroup 或原生行列组合 | 列数／单元尺寸辅助器只更新网格参数；超量在候选区滚动，不改变整个页面的业务步骤 |
| 详情／等级区 | VerticalLayoutGroup，标题／状态留必要高度，正文 Viewport 取余量 | 长说明内部滚动；玩家等级行／标记用 HorizontalLayoutGroup；不固定一整列屏幕高度 |
| 企业／科室原板 | 内层比例容器，使用 AspectRatioFitter 或明确的原图映射 | 企业 650×1850、科室 516×1000 完整等比；外层布局分配空间，图像不争抢父容器尺寸 |
| 背景／边框／选中态 | 拉伸或相对内容叠加，不参与行列分配 | 图片版本、切片、透明安全区、命中与状态分别核对 |

每个轴仅一个尺寸／位置驱动者。父组控制子尺寸；垂直组只将高度余量交指定正文，横向组只将宽度余量交指定伸缩区域，具体扩展选项按 07。Fitter 只用于内部滚动 Content 的内容轴，不能使 Viewport 或整个窗口随内容增高。

**所有比例保持相同页面组织。** 禁止因为 16:10、窄屏或高度变化把候选和详情新增为两个适配步骤，禁止隐藏主界面列或操作区；原有用户点击“查看详情”所触发的资料页切换按唯一页面管理保留。内容网格换列、已有内容分页和区内滚动可以保留，不能作为主区域分页。

使用五类字体：方正普通、汉仪强调且关闭 Bold／`<b>`、msyh 特殊词、NarrowBold 费用／奖励／效果数量、wide 纯 UI 页码。字体与固定文字由资产配置，真实数据刷新不覆盖其语义。

**出口：** 1920×1080 完整素材和正常位置成立，候选／详情／操作区尺寸由实际原生布局分配，长内容的滚动边界明确。此时才接新增业务，尚不批量跑尺寸截图。

## 四、阶段 C：正式模式与请求接线

1. 企业 `company` 提交企业目标，`effect` 提交企业与特效目标。确认企业不自动进入特效选择；普通升级奖励仍由规则处理，不做成额外可执行按钮。
2. 查看企业或详情只更新查看目标；选择草稿按稳定 ID 保存。数量变化后保持仍有效的选择，移除非法目标；不以素材四张同屏为候选数量上限。
3. 不可选目标是否可见由当前投影决定，显示正式资格／费用／不可用原因。确认复核当前请求、目标、支付和版本，pending 防重入，拒绝刷新合法状态，迟到回包不关闭新页面。
4. 科室开局可无当前科室；中途切换时当前科室可查看但不可重复确认。全体共享唯一激活科室，不能复制成各玩家独立选择；板上 2～5 级奖励是信息，不拆成独立操作。
5. 复杂目标由现有真实子步骤承接，可选效果沿用已有结算上下文。步骤由业务请求决定，不由屏幕尺寸决定；父子页面不能同时显示。
6. effect 唤起的页面支持收起保留有效草稿、释放遮罩／焦点／地图输入；同一请求刷新不强制弹回。展开先关闭资料页，再校验并恢复当前有效步骤。普通查看不登记为 effect 恢复目标。
7. 接通新入口后删除本项被替代的独占旧窗口外壳、监听和必需引用；保留仍有合法用途的共用内容。同步旧字符串路径、长期工具及捕获引用，按功能命名并维护 GUID／fileID／序列化兼容。不引回旧翻面或 hint/context 控件。

**出口：** 每种有正式能力的模式从真实局内入口完成接线，一次意图只有一个提交通道；缺规则模式明确只交付组件，不伪报正式成功。

## 五、阶段 D：有序验收

1. 先核对实际加载来源、引用、完整素材及原生层级。记录 Header／Body／Footer 和候选／详情的同坐标系矩形；窗口根不越界之外，还要确认正文确实取得余量、长列表末项可达。
2. 从正式企业／科室入口分别走“查看→预选→详情→返回→确认／合法取消”；覆盖模式差异、空／少量／超量候选、长说明、状态变化和过期选择。不能只手动 Show 一个壳或用预览数据代替真实入口。
3. 布局成立后定向检查 1920×1080→1920×1200→一组超宽／低高度→恢复基准。候选与详情不自动换成步骤，三主列不因比例换页，已选 ID、滚动锚点与合法焦点保持。
4. 在效果选择页执行收起→其他资料→展开，验证互斥、有效草稿及两栏最高输入；窗口标题／背景拖动不移动窗口，区内滚动正常。
5. 测试只补新增状态／命令／布局风险；视觉以实际场景和有效覆盖为准。未具备条件的模式、多人回包或设备写明未验证，不扩大无关测试。

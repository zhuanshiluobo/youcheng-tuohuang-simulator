## 一、目标与范围

迁移尚未完成的局内事件、调度、特殊行动、角色／设施效果、回合详情、设置、规则书、日志、图片查看器和既有终局／断线提示；将 CardViewer 3.6 的普通查看与角色使用两种模式接入全部对应正式入口。

只处理实际游戏中的 UI。启动、加载、房间大厅、收藏室及其合法共享源排除；局内设置、日志、规则书、图片查看器继续使用已隔离的来源，不能为统一样式改变局外实例。已由前项正确接入的窗口复用，补其实际缺项，不重新生成整套界面。

### 必读实际入口

- `GameplayDialogRegistry`、`InteractionRequestRouter` 与实际引用的专用 Dialog／renderer、页面互斥与 effect 恢复控制。
- `EventChoiceDialog`、`DispatchDecisionDialog`、`SpecialActionChoiceDialog`、`CharacterCardEffectChoiceDialog`、`FacilityEffectChoiceDialog`。
- `GameSettingsMenu`、`RulebookViewer`、`ActionLogViewer`、`ZoomableImageViewer`、`RoundTracker` 的实际局内资产／控制器及终局、断线入口。
- 快速行动“使用角色牌”、设施卡、手牌、新版弃牌／盖放区域的详情入口，以及角色计谋／策略／第二效果决定的正式路径。
- [条目 3.4／主框 3.5 规范](06-效果条目3.4与主框3.5增量规范.md)、[CardViewer 3.6 补充](UI-011-补充-卡牌查看器3.6.md)列出的源文件和包内交互／数据说明。

上述名称是定位起点；基础修正改名后使用新语义路径和映射，不恢复旧任务号目录、旧对象名或旧字符串查找。

## 二、阶段 A：逐入口盘点和来源确认

1. 将 UI-001 清单与 UI-005～UI-010 的实际交付交叉核对，列每个局内页面的真实触发步骤、源 Prefab、嵌套资产、有效场景覆盖、打开／关闭方法、数据投影及当前输入所有者。
2. 为每页标明“已正确复用／素材需替换／结构需修／业务需接／缺规则”。未列出的真实局内入口继续补入，不能只检查 Registry 中的窗口而漏掉控制器直接 Show 或独立 Canvas。
3. 记录当前正常 1920×1080 的页面与主界面关键屏幕矩形、业务状态、来源和有效覆盖。新 3.6 替换窗口及用户已要求删除项明确列为变更，其他正常位置保持；零缩放／隐藏模板不可作为有效基准。
4. 逐部件确定素材：无专项替代部分用 3.1 共用框与已有内容，适用效果行用 3.4，主框四项保持 3.5；卡牌查看／角色使用使用 3.6。查同图哈希与已有导入设置，仅导入实需差额，不能整包复制浏览器资源或预览卡。
5. 列出旧查看／事件／独立遮罩／拖窗路径的清理目标，写明替代入口、引用者、共享用途和 GUID／fileID。源素材与历史记录保留；实际旧 UI 是否清除按 07 判断。

**出口：** 全量局内页面有唯一归属和具体迁移目标，3.6 有明确五类入口清单，既有业务与需要补齐的能力分开记录。

## 三、阶段 B：完整视觉与原生布局

各页面从搭建起使用最终结构，将素材放入布局容器，不能先写坐标复刻再挂无效 Layout。处理实际局内源及覆盖；普通运行、测试、截图不调用 Rebuild、旧迁移器或保存覆盖。

| 对象 | 原生布局与各轴责任 |
| --- | --- |
| 页面外壳 | PageHost／ContentRoot 限制外部矩形，内部 VerticalLayoutGroup 分 Header／Body／Footer；窗口位置由资产和布局确定，不可拖动 |
| Header／Footer | LayoutElement 提供内容高度，flexibleHeight 为 0；按钮用 HorizontalLayoutGroup，页脚不被正文长度推动 |
| Body／正文视口 | flexibleHeight 取得剩余空间；并排内容用 HorizontalLayoutGroup，非滚动轴跟随分配矩形 |
| 效果／日志／设置列表 | ScrollRect.Viewport 受限，Content 使用 VerticalLayoutGroup；长文本测量只提供布局输入，ContentSizeFitter 仅在内容滚动轴生效 |
| 候选卡／资料缩略图 | GridLayoutGroup 或原生行列组合；辅助器只更新内容网格参数，不重排主界面或更改业务步骤 |
| 卡牌／规则书／图片 | 内层等比容器，原图比例、缩放／平移只作用于内部图片；外壳、返回、关闭与页码保留在可达区域 |
| 背景／框／遮罩／焦点 | 独立拉伸叠加层，不参与行列数量；内容遮罩只覆盖 ContentRoot，装饰不抢射线 |

每个轴只允许一个驱动者，父 LayoutGroup 实际采用 LayoutElement 输入。扩展选项遵守 07，正文取得余量、固定功能块不被平均拉高；普通行列不再用自定义组件逐项写坐标。必要专用图文流、图片内部变换等算法逐项说明用途，不能越级重排窗口。

各比例保持同一页面组织。禁止按分辨率隐藏主列、增加主分区导航，或把候选／详情改成尺寸触发的分段步骤。保留用户点击造成的资料切换、规则书翻页、内容分页和真实请求步骤；长内容用本区滚动，不能整窗或整列滚动掩盖越界。

### CardViewer 3.6 视觉必须项

- 按补充搭同一个 `CardViewer` 的 `inspect`／`use-character` 显式模式，不建立 `Ui011` 目录或第二套页面管理器。
- 合并底图含分隔线，完整等比，不能当可独立九宫格边框；源 1920 画布与局部坐标只供内部构图参考，外层仍由 ContentRoot 和原生布局分配。
- 两模式共用同一卡图区域，隐藏按钮组时保持页脚占位和卡图位置稳定；计谋／策略／取消按顺序由 HorizontalLayoutGroup 排列。
- 使用源按钮可见区映射，透明 PNG 边距不计入点击范围；源包未提供的新状态用配置着色／焦点层，不冒称有状态贴图。
- 卡图按自身比例完整 contain，不叠加选中勾、卡下编号或第二份效果说明。真实卡图与隐藏信息来自有权查看的投影，源预览卡不能用于正式状态。

所有页面使用五类字体：方正普通、汉仪强调且无 Bold／`<b>`、msyh 特殊词、NarrowBold 效果相关数字、wide 纯 UI 数字。静态标题和固定提示配置在资产，控制器只更新动态数据；3.6 的计谋／策略明确使用 msyh。

**出口：** 每页完整素材在 1920 基准呈现，原生布局真实负责普通结构，图像比例、正文余量、操作边界和层级成立，再接新增业务。缺图／错层时先修，不跑正式尺寸矩阵。

## 四、阶段 C：正式入口、页面生命周期与清理

1. 所有独立页面通过同一互斥管理。设置从顶栏打开时，先按既有语义收起当前 effect；规则书、日志、查看器彼此切换先隐藏前页及其遮罩／焦点，再显示目标页。返回只保留导航状态，不叠开父子窗口。
2. 关闭资料返回主界面，effect 继续收起；顶栏展开关闭当前资料后校验并恢复当前有效步骤。隐藏页继续同步合法状态，同一请求刷新不强制弹回；已结束请求清理恢复目标。
3. 专用事件／调度／角色／设施效果保持各自请求、候选与确认语义。3.4 行只用于相符的执行／只读模式，不能把选中草稿自动变成 use 提交；正文查看与右侧执行不双触发。
4. pending 防重入，回包对应请求／会话版本；拒绝与失效刷新合法状态，迟到回包不得影响新页。资料点击、窗口关闭、图片平移不提交业务命令。
5. 终局和断线页面纳入统一内容层级，处理失效 effect 上下文；设置等合法功能仍可由最高栏访问。业务命令按会话状态禁用，不用整屏 CanvasGroup 锁死两栏。
6. 逐页删除被替代的独立最高排序、自增 Canvas、全屏内容遮罩、窗口拖动事件和历史偏移恢复路径。检查运行时重新启用／直接激活，不能只在 Prefab 上取消勾选。
7. 新入口接通后删除本项独占旧外壳、按钮、监听、必需引用和旧控制分支；长期工具／测试／自动化同步语义命名，维护文件 GUID、对象 fileID、类型／字段兼容和实际场景覆盖。仍有合法用途的共用图片组件保留并记录，不泛删目录。

### CardViewer 3.6 正式接入必须项

按 [3.6 补充](UI-011-补充-卡牌查看器3.6.md)完整执行，主任务至少完成下表：

| 实际入口 | 模式与行为 | 不能混同的流程 |
| --- | --- | --- |
| 快速行动“使用角色牌” | `use-character`，明确卡 ID 与计谋／策略各自资格，点击后走真实角色使用／后续选择链 | 不自动选择唯一可用效果，不把事件发出当结算成功 |
| 设施卡查看 | `inspect`，只读卡图与合法返回 | 不触发设施效果或建设 |
| 手牌查看 | `inspect`，保持原列表有效位置和焦点 | 不等于开局移出、多卡选择、盖牌确认或使用 |
| 新版弃牌区查看 | `inspect` 或来自新版只读列表的详情，数量／内容遵守权限 | 不复用旧手牌内嵌预览壳来宣称完整换新 |
| 盖放区查看 | `inspect`，无权查看的卡只传合法背面／公开信息 | 不预加载秘密正面、名称或 ID |

普通查看的按钮必须同时退出显示、焦点和命中。计谋／策略的映射按真实符号明确配置，不能按索引猜测。取消、Esc、点击内容区内的窗口外等退出方式按来源返回；普通关闭不结束必须处理的 effect，也不等于第二效果“结束使用”。

第二效果继续／结束仍由基础修正后的新版 effect 步骤承担。**旧翻面、查看提示、返回行动、万能上下文按钮及旧 hint 卡面必须已经退出，不能为 3.6 再引入，也不能以改名替代删除。** 真实角色使用与资料查看分别走明确入口。

**出口：** 清单内可实现的正式入口接通，3.6 的五类来源与两种模式明确，一次意图只有一个监听／提交者，旧替代入口不再运行；缺规则项只报告对应组件状态。

## 五、阶段 D：逐页实际验收

1. 先核对两张实际场景使用的源／副本／覆盖、资源就绪和当前页面状态；截图读取实际激活实例，不能拿原共享源或隐藏模板替代。
2. 各页从正常入口打开→完成代表性交互→合法关闭／返回，覆盖设置切换、规则书翻页、日志末项、图片内部缩放、终局摘要／明细及已存在断线状态。没有实际状态的模式明确未验，不伪造正式成功。
3. 3.6 分别从五类来源进入，验证普通查看无执行能力、卡图完整、两模式卡图矩形一致、透明边距命中正确。角色使用分别检查计谋／策略可用与禁用原因，并从正式入口完成一次合法发起及真实后续选择；普通查看／取消不发命令。
4. 对真实 effect 做预选→收起→设置／资料 A→资料 B→展开，验证有效草稿、旧请求失效、焦点和单页面互斥；所有窗口标题／背景均不可拖动，内部滚动／图片变换保留。
5. 原生结构和素材成立后，定向检查 1920×1080→1920×1200→一组超宽／低高度→恢复基准。窗口、正文和页脚在同一坐标系核对；正文真正取得剩余空间，长内容末项可达，主列不按比例分页。
6. 实际测试两栏合法按钮首命中，确认透明视口／独立 Canvas／终局层不会盖住或拦截；UI 点击不穿透到地图。图像在窗口内不越界不能单独证明实际可点。
7. 对命名与旧 UI 清理核对资产、代码和工具三处：没有任务号生产路径依赖，没有旧 hint/context 入口，没有运行时重建或重新启用。发现本项问题定向修复并复验，不删业务断言绕过失败。

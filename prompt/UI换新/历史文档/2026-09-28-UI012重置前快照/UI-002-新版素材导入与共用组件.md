# UI-002：新版素材导入与共用组件

更新日期：2026-09-26。先读[共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md)、[原生布局、命名与清理规范](07-原生布局命名与旧UI清理纠正规范.md)及 UI-001 的素材／资产清单。前置是所需素材映射和实际资产归属已核实；已有组件优先复用，不重新导入已接入的全部资源，不运行旧生成器重建实际 HUD。

## 一、目标与范围

只导入当前用途实际缺少的运行时素材及用户指定字体，建立或修正框体、按钮、卡槽、效果行、滚动控件和字体语义配置。目标是 UI-001 确认的 Sprite、字体、必要字体维护适配、配置和共用组件 Prefab。静态结构存在资产中，运行时只实例化已配置的动态条目并绑定数据。

本轮仅服务局内 UI。共享源若供局外使用，先检查局内隔离关系；不要为了共用组件修改启动、加载、房间或收藏室。实际 HUD／窗口结构迁移按[基础修正任务](局内UI基础修正执行提示词.md)及后续专用任务执行。组件导入不等于它已用于正式页面。

## 二、必读入口

- 整理版 `文档/03_Unity接入说明.md`、`清单/新版组件索引.json`、`清单/资产索引.json` 与对应原包参数。
- [按钮 3.2 规范](04-主界面按钮3.2增量规范.md)、[条目 3.4／主框 3.5 规范](06-效果条目3.4与主框3.5增量规范.md)和当前交付；[CardViewer 3.6 补充](UI-011-补充-卡牌查看器3.6.md)用于核对重复图片与后续用途，不在本项顺带接全部查看器。
- 当前字体／TMP、`CardVisualCatalog`、`CardInteractionLayoutProfile`、`EffectDialogLayoutProfile`、共用按钮与条目的实际资产和引用者。
- [单页面与字体规范](02-单页面与字体补充规范.md)、[字体来源清单](字体来源清单-2026-09-24.json)、当前 `FontUtility`／`FontRefreshDriver` 与真实 Text／TMP 使用方式。

## 三、阶段 A：按用途核对来源与导入差额

1. 列出用途、源文件／版本、现有 Unity 资产／GUID、引用者、采用倍率、确需新增或修改的绝对路径。按内容与实际角色核对复用关系；哈希相同的资源优先复用已有正确导入资产，导入设置确因用途不同才单列变体及理由。
2. 生产文件、目录、类型、配置和对象按功能命名，不建立 `Ui002` 等任务号目录；先查项目已有同职责目录与组件，避免平行主题／行模板。移动保留文件必须连同 `.meta` 保持 GUID，类型／字段变化另行维护序列化兼容，不能删后新建假装移动。
3. PNG／SVG、1x／2x、整图／拆片按实际需求选择一套；ZIP、网页、预览、QA 和源生成脚本留在素材来源目录，不整包导入。3.6 与旧选牌包同图应先核对，不因包版本较新复制一份同图。
4. 用途覆盖有明确边界：3.2 负责指定 11 按钮，3.4 负责指定效果行，3.5 只负责四项框体／底图；其他部件继续按各专用包与未被覆盖的来源。核对后续 3.6 窗口底图不能当独立九宫格边框。

**出口：** 本次导入差额和复用表明确，没有按任务复制资源或覆盖无关用途。

## 四、阶段 B：图片、字体与布局组件

1. 设置 Sprite、Alpha、过滤、最大纹理尺寸和压缩，以中文、细线及透明边缘实际显示为准；不同用途不强套一组参数。2x 源边距需配套 PPU／像素倍率，核对导入尺寸没有被纹理上限意外缩小。
2. 使用索引中的 `unityBorderLeftBottomRightTop` 设置九宫格。源数组为左上右下，Unity 为左下右上；切片与内容留白分开。透明中心、填充中心和普通底图各按实际资源定义。
3. 背景、框体和状态装饰四向拉伸或放独立叠加层，不占布局项；必要时显式 `ignoreLayout`。命中范围使用当前部件自身的可见区参数，不能全局套用旧按钮的 `visibleRect`。
4. 普通行和按钮组使用 HorizontalLayoutGroup；条目正文的标题／说明使用 VerticalLayoutGroup；父容器负责尺寸，LayoutElement 传递 min／preferred／flexible。图标与操作区保留内容宽度，正文获得横向余量；长说明只通过测量提供布局输入，不直接改相邻控件坐标。
5. 可复用窗口壳使用页头／正文／页脚的 VerticalLayoutGroup，正文 Viewport 取得剩余高度，按钮栏使用 HorizontalLayoutGroup。列表 Content 仅在滚动轴按内容增长，Viewport 不随长内容长出窗口；装饰和比例图放在内层，避免与父布局争同一轴。
6. 组件接口记录每轴驱动者、布局输入和实际父容器要求；原生组件扩展选项按 07 配置。不能添加无效 Layout、保留自定义脚本继续排普通行列，也不新增按宽高比隐藏整列或分段换页能力。原生组件不能直接表达的图文混排／源图坐标等专用算法需逐项说明。
7. 覆盖正常、悬停／聚焦、按下、选中、禁用及 pending。无专用新图时使用配置状态并记录；同一外观只由一处状态逻辑维护，防止 Button transition／主题刷新互相覆盖。装饰不抢射线，右侧执行与正文查看命中分开。
8. 静态标题／按钮／说明配置在资产中。五种字体依语义绑定：方正普通、汉仪强调且无 Bold／`<b>`、msyh 特殊词、NarrowBold 效果数字、wide 纯 UI 数字。资源 icon 前数字和选择次数用 NarrowBold，回合数用 wide；“策略／计谋”用 msyh。
9. 按清单核对已导入字体与成员，缺少时才导入或生成需要的资产。wide 的 `.woff2.ttf` 实际为 TrueType，msyh TTC 使用记录的 Regular 成员，不能通过改扩展名冒充转换。保留来源与生成设置。
10. 混排检查基线、换行与缺字；重新聚焦、字体纹理恢复和动态实例化保持原语义角色，不覆盖用户静态文案。沿用图层、按钮业务和事件语义，不让组件更新接管规则。

**出口：** 共用组件完整呈现，原生布局实际接管普通行列，引用和状态有单一归属；新增业务尚未接线的部分明确标记。

## 五、阶段 C：有范围的验证与交接

先以已授权的安全预览或实际使用入口，在 1920×1080 核对完整资源、字体、边框、留白与既有位置。修改已有组件时记录影响它的实际局内引用，不能只看独立模板。新增部件按来源构图搭建，不挪动现有正常构图来吸收差异。

布局实现成立后，定向改变该组件宿主宽高，覆盖长文字、空／超量条目和操作区边界；无须为资源导入批量跑整套屏幕矩阵。隐藏状态不占输入，长列表仅在自身 Viewport 内滚动。诊断样例明确标注，不能替代正式状态。

移动／改名后核对 GUID、序列化引用、实际场景覆盖及旧名称依赖。已被替代的本项独占表现分支按 07 的清单规则处理，共享图片与业务数据不随之删除；普通测试不运行任何重建或生成器。

## 六、交付与验收

- 共用资产按语义命名，可供后续 Prefab 直接引用；导入差额、复用原因、GUID／来源及类型迁移有记录，没有同用途重复资源。
- 边角、透明留白、文字、状态层和命中区域正确；卡面不拉伸，禁用状态可辨认，正文／执行互不串点。
- 普通行列由原生组件实际分配，布局输入可传到使用方；组件无主分区换页能力。测试不把可编辑字号、颜色或局部坐标冻结为常量。
- 五类字体与混排实际显示正确，字体刷新和动态实例化保持角色；汉仪无额外加粗，特殊词及两类数字可核对。
- 至少记录一组实际显示证据与宿主尺寸；未运行就写未完成视觉验收。只有组件可用、正式入口未使用时，不能报告页面迁移完成。

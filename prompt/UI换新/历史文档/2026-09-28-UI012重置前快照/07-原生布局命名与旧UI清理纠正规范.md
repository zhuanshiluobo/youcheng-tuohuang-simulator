# 原生布局、语义命名与旧 UI 彻底清理规范

日期：2026-09-26；视觉边界补充：2026-09-27。来源：用户要求纠正布局、任务命名、旧 UI 和未经同意的比例换页，随后指出城市样式画面偏离素材。原生布局与素材构图分别按本文和[08视觉约束](08-素材构图与视觉验收约束.md)核对。

本规范适用于所有**局内 UI**，优先于旧的适配、命名和清理描述。此前提示词已保存为[审查前快照](历史文档/2026-09-26-审查前快照/快照清单.json)，素材原文和历史记录保持原样。[基础修正](局内UI基础修正执行提示词.md)已有实际交付，后续按[最新计划](01-UI更新实施计划.md)复用并核对相关成果，不重跑整套阶段；本规范持续约束新窗口的实现方式。

## 1. 本轮明确决定

1. 常规行列结构直接使用 Unity 原生 `VerticalLayoutGroup`、`HorizontalLayoutGroup`、`LayoutElement` 和 RectTransform 拉伸。已有自定义 Layout 类不等于布局合格；普通行列不得再由一批自定义组件逐项写坐标模拟。
2. 上／中／下是纵向排列，使用 Vertical Layout Group；中间左／中／右是横向并排，使用 Horizontal Layout Group；各列内部再用 Vertical Layout Group。三个方向不能混用。
3. **彻底移除因屏幕比例／宽度变化而把主界面左中右三列切成分页的能力。** 16:10、16:9、4:3、超宽等使用同一主界面结构，不按阈值隐藏整列、切到单列、生成左右导航或平移整张主界面。
4. 原有“主要行动／快速行动／城市样式”三个业务页签保留；玩家主动展开一名对手明细、内容列表分页／滚动、规则书翻页、用户要求的 effect 收起恢复也保留。这些既有内容交互不能用作主界面整列分页的替代实现。
5. 生产文件、文件夹、场景物体、组件类型、配置、常驻测试及工具按功能命名，不再使用 `Ui002`、`UI003`、`Ui007` 等实施任务编号。任务提示词、历史执行记录及其证据可以保留编号以便追溯。
6. 用户要求清理的旧资源计数器、旧翻面及其“查看提示／上下文按钮”变体、旧固定弃牌区必须真正移除。重命名、隐藏、移出屏幕或换贴图继续保留不算清理。
7. 1920×1080 位置保持只保护已正确完成且本次需保留的区域；待换新的旧壳／内容按对应素材修正，缺陷区记录必要边界调整。对象先分保留区、待换新区、缺陷区，再比较正确的目标；不能冻结旧城市样式1520×900壳及其左右比例。锚点、父路径与局部坐标可变化，结果以真实屏幕矩形和目标构图判断。
8. 原生布局只规定实现方式，不授权重新设计素材。先确定每个模式的源说明、预览、区域和行列结构，再选择组件；主题更新只替换明示视觉角色。主界面紧凑状态表、独立六牌总览、主动单卡放大是不同组件，不能以“都能用Grid／列表”互相替换。

## 2. 标准主界面层级

下列名称是主界面骨架参考；执行时映射到当前真实资产，保持业务与 GUID 所需引用。它不代替各专用窗口的源构图；PageHost下的窗口需按自身模式推导区域比例、网格和摘要位置，不以通用骨架覆盖专用设计。

```text
GameplayHudCanvas
└─ SafeAreaRoot                         VerticalLayoutGroup
   ├─ TopBarRoot                        LayoutElement + HorizontalLayoutGroup
   ├─ ContentRoot                       LayoutElement（flexibleHeight = 1）
   │  ├─ MainColumns                    拉伸填满 + HorizontalLayoutGroup
   │  │  ├─ PlayerCityColumn            LayoutElement + VerticalLayoutGroup
   │  │  │  ├─ PlayerList               标题／明细容器；明细内可滚动
   │  │  │  └─ CityRegion               剩余高度 + 等比城市内容
   │  │  ├─ MapHandColumn               LayoutElement + VerticalLayoutGroup
   │  │  │  ├─ MapRegion                剩余空间，通知实际地图视口
   │  │  │  └─ PlayerAndHandRegion      既有状态／手牌区
   │  │  └─ ActionsColumn              LayoutElement + VerticalLayoutGroup
   │  │     ├─ CooperationRegion       标题 + 可伸缩正文／局部滚动
   │  │     ├─ CardZones               HorizontalLayoutGroup（新版弃牌／盖放区）
   │  │     ├─ ActionTabs              三个既有业务页签
   │  │     └─ ActiveActionRegion      剩余高度 + 当前页内容／局部滚动
   │  └─ PageHost                      拉伸填满，唯一页及内容遮罩
   └─ BottomBarRoot                     LayoutElement + HorizontalLayoutGroup
```

`MainColumns` 与 `PageHost` 是同一内容区中的基础层与覆盖层，不能让二者在一个行列布局中各分走一半空间。背景、边框、装饰和遮罩也不参与内容行列计数：放在独立拉伸层，或在确需同父时显式 `ignoreLayout`。

顶底栏占位与最高显示层可以在同一结构内分别处理：由根 VerticalLayoutGroup 分配栏位，栏根独立 Canvas／排序和 Raycaster 保证两栏最高。内容遮罩仅覆盖 ContentRoot；最高层不能放一个拦截整屏的透明底板。

### 2.1 各轴的唯一驱动者

| 对象 | 位置／尺寸的唯一责任 | 关键配置与禁止事项 |
| --- | --- | --- |
| SafeAreaRoot | 安全区域适配只设置根的安全边距；VLG 分配三个直接子区 | `childControlWidth/Height = true`；水平填满；纵向不强制把三块平均拉高，余量交给 ContentRoot |
| 顶栏／底栏 | 父 VLG 分配矩形；LayoutElement 提供原基准的首选／最小栏高、`flexibleHeight = 0` | 内部 HLG 管按钮、文字和伸缩区；不能在控制器中再覆盖父布局结果 |
| ContentRoot | 父 VLG 分配剩余高度；`minHeight = 0`、`flexibleHeight = 1` | 顶底栏只在根布局中扣一次；不能叠加旧的手动 offset 扣栏算法 |
| 三列 | MainColumns 的 HLG 分配宽度并拉满内容高 | 首选宽度取真实 1920 基准，最小宽度取内容需要，flexibleWidth 指定余量归属；不把三列首选尺寸同时当作不可缩小的硬下限 |
| 列内各分区 | 所在列的 VLG 管纵向顺序与分配 | 标题、页签等保留内容高度；城市、地图、正文 Viewport 等设置可伸展高度；每列先列清固定项和伸展项 |
| 面板内部 | 面板 VLG 分页头、内容、页脚；必要并排区域用 HLG | 正文取得余量，操作区可达；不要在外层尺寸不足时把整个面板内容继续增高 |
| ScrollRect.Viewport | 父布局或拉伸锚点提供固定可用矩形 | Mask 只裁剪本区的滚动内容；不能给整个左列、右列、三列主区加滚动后冒充适配 |
| ScrollRect.Content | 布局计算内容长度；只在滚动轴按内容伸展 | VLG + ContentSizeFitter 可用于纵向列表 Content；避免父布局与 Fitter 同时写同一对象同一轴，非滚动轴跟随 Viewport |
| 卡牌、城市图像及标记 | 已获分配的外部容器内使用比例约束／局部内容映射 | 原图完整等比；图像像素坐标、城市格位映射和手牌扇形可保留专用算法，不承担主界面结构适配 |

确定 min／preferred／flexible 前先标注区域分类：保留区采用已核实的正确构图；待换新区根据源模式的尺寸与区域关系推导；缺陷区列明为避两栏／安全区调整的部分。旧Prefab值不是待换新区的默认目标。素材声明“旧主题”只影响被新版明示替换的皮肤角色，未覆盖的内容结构继续有效。

LayoutElement 提供的 min／preferred／flexible 值必须能传到实际控制它的父 LayoutGroup。仅在物体上添加组件、将 flexible 改为 1，或父级填满而子级仍锁死高度，都不算完成。先移除旧驱动者，再检查新链条；不能让旧脚本在下一帧把尺寸写回。

原生组件配置明确如下，不能依赖新建组件的默认 Force Expand：

- 根、列和面板的 VLG：`childControlWidth = true`、`childControlHeight = true`、`childForceExpandWidth = true`、`childForceExpandHeight = false`。只有指定主体的 `flexibleHeight > 0` 取得高度余量，标题／栏位不会被强制拉高。
- 三列 HLG：`childControlWidth = true`、`childControlHeight = true`、`childForceExpandWidth = false`、`childForceExpandHeight = true`。横向余量按各列的 flexibleWidth 分配，纵向填满同一内容区。
- 栏内 HLG 的 `childForceExpandWidth = false`，固定功能块按首选尺寸，只让指定伸缩组取得横向余量；垂直分配按实际栏内对齐配置。
- 上述常规行列的 `childScaleWidth = false`、`childScaleHeight = false`；内容动画的缩放留在内层，不能让缩放参与外部区域排布。

### 2.2 尺寸不足时的处理

原生 Layout Group 也不会自动解决“子项最小尺寸之和大于父区”的矛盾。每列需核对标题、页脚、padding、spacing 与正文最小高度的总和，压缩可压缩留白，将可伸展空间交给主体，超量内容在本区内部滚动。

横向同理：三列使用可缩首选宽度、合法最小宽度和明确余量。卡图保持比例；源设计本就是卡牌网格时可在实际宽度不足的内容区内换列，不把源状态表改成网格。1920基准源设计要求六牌3×2同屏时，先修宽度分配与卡尺寸，不能靠滚动见到第五、六张就称符合基准。禁止隐藏整列；低于真实可读下限登记限制，不另造分页或单列信息结构。

`CanvasScaler` 只做基础缩放。保持相同主布局，尺寸变化由原生布局重算。宽度变化也可能改变 Canvas 的可用逻辑高度和文字换行，因此两个轴都要检查；不得维护按分辨率列出的坐标表。

## 3. 自定义组件的保留边界

- 常规主框架、栏位、行列、页头正文页脚、效果行、资源行、普通按钮组，用原生布局表达。审查 `UiHudColumnsLayout`、`UiPlayerCityLayout`、`UiActionsColumnLayout`、`UiHudBarLayout`、`UiPageSectionsLayout` 等当前组件，按职责移交后删除被替代实现，不能改一个类名继续同样的手写坐标分配。
- 可保留的专用计算限于原生组件无法直接表达的内容语义，例如手牌扇形、城市格位与源图坐标映射、实际地图 viewport 更新、图片内部缩放／平移、图标文字混排流。逐个写明用途、输入输出与为何不能用原生组合替代。
- 简单的内容测量组件可以提供 LayoutElement 所需值，但不能越级设置其他分区的 RectTransform、根据比例隐藏整列或逐帧重排整张 HUD。
- 状态控制器只控制真实内容、候选、可用性与合法业务页签；布局管理器负责排布。禁止通过 `SetActive` 隐藏侧栏作为尺寸算法的一部分。

## 4. 语义命名与迁移

### 4.1 推荐目录职责

| 当前类型 | 功能目录／名称示例 |
| --- | --- |
| 局内 HUD 与主模块 | `Assets/YC/Presentation/GameplayHud/`，如 `GameplayMainModules`、`ActionTabs` |
| 共用表现组件 | `Assets/YC/Presentation/Common/`，如 `EffectRowView`、`ButtonVisualState`、`SemanticText` |
| 必要的内容专用布局 | `Assets/YC/Presentation/Layout/`，名称描述真实内容用途 |
| 预制体与配置 | 既有 `Prefabs/Gameplay/`、`Content/` 按作用进一步分类；不为了追求目录统一再次移动已经合理的资源 |
| 编辑器工具与长期验证 | `Editor/Ui/` 或项目既有相同职责目录；如 `GameplayHudCapture`、`GameplayHudLayoutTests`，不用任务号 |
| 层级物体 | `MainSurface`、`MainColumns`、`ActionsColumn`、`CardZones`、`EffectRow`；不用 `UI003 Main Surface`、`UI007 ...` |

以上为命名原则与例子，执行者必须先检查现有名称和程序集，确定唯一目标路径；不能创建另一个同职责目录或重复类型。源码、类名、序列化类型、测试夹具、长期脚本及自动化 ID 一并审计。素材源包的版本号是素材来源信息，不等同于任务编号。

### 4.2 迁移必须保留的身份

1. 输出“旧绝对路径／对象路径 → 新路径／语义名 → GUID／fileID → 引用者 → 迁移方式”清单；改名之前核对无覆盖、无同名冲突。
2. Unity 文件／目录移动时保留对应 `.meta`／GUID；不得删后新建来取得同名对象。MonoBehaviour 类名与脚本文件保持一致；类型、命名空间或字段变化还需处理序列化兼容，不能仅靠 GUID 假定安全。
3. 同步字符串查找、Addressables／Resources 路径、Editor 工具、测试过滤名、捕获命令、程序集和必要配置。对嵌套 Prefab、场景覆盖、UnityEvent 与托管引用分别核对。
4. 用映射表比较迁移前后实际对象与屏幕矩形；不能因路径变了就漏掉基准比较。任务记录保留旧路径作为历史证据，新执行命令使用新名。
5. 全局搜索剩余任务编号，逐项分为“历史文档／证据允许”“待迁移生产引用”“确有其他语义”。生产残留必须处理，不能通过批量替换历史文档来制造零命中。

## 5. 旧 UI 必须删除到什么程度

### 5.1 明确对象

- 旧翻面按钮，以及被改为 `Action Panel Context Button`／`action.context` 的同一旧入口；“查看提示”“返回行动”等为延续旧翻面结构生成的按钮、旧提示卡面和切面状态。
- 旧资源计数器的局内实例、独占旧表现组件／配置及复活它的生成／绑定路径。不能以旧编辑器生成代码还在引用为由无限保留整条废弃链，应同步删除该废弃分支。
- 旧手牌区域固定弃牌控件及重复预览外壳、计数和事件。新版 HUD 的弃牌区域及正式弃牌数据属于保留目标，逐项按资产来源区分。
- 旧盖牌拖放提交区域、悬停提示、确认残留与无效待提交动画；新版盖牌单选／确认继续保留。
- 未授权的主界面分区换页按钮、状态字段、阈值、事件、键盘导航与相关旧布局控制路径。

### 5.2 业务能力与旧表现解耦

第二效果“结束使用／继续”的真实规则决定放到现有新版 effect 选择页或其当前步骤，明确提交原合法命令；不得把旧翻面按钮改成万能上下文按钮继续保留。关闭普通查看器、取消查看或返回资料均不应隐式执行“结束使用”。主行动和角色牌使用通过新版正式入口展示，不再依赖旧提示卡面来回切换。

资源、手牌、建设的刷新从旧计数器对象中解耦；删除旧对象不能使刷新函数提前返回。弃牌查看从新版 HUD 入口进入复用的正式只读页面；有复用价值的查看内容应迁成明确的共用组件，旧重复壳与旧入口仍须移除。

### 5.3 删除的出口

对每个目标列出物体、文件、引用、替代业务入口和验证结果；手工改资产前核对所有权。文件删除按根 `AGENTS.md` 核验项目内绝对路径和授权范围，逐项检查 Git；禁止泛删目录。非局内共享资源按既有隔离范围处理，不删除仍被合法局外入口使用的资产。

清理通过必须同时满足：实际局内资产不含旧目标；运行时不创建或重新启用；代码、Prefab、场景覆盖与长期工具没有生产依赖；必需业务经新版入口可达。若必要新入口仍未完成，该项记未完成并继续处理，不能用“旧入口需保留”替代交付。

## 6. 验证顺序与完成标准

1. 先做实际层级与驱动者审查：根 VLG、内容 HLG、列内 VLG 及 flexible 传递有效，普通结构未被自定义坐标脚本接管。
2. 先在1920×1080逐模式对照源说明／预览和实际画面：保留区位置保持，待换新区符合目标构图，缺陷区调整有依据。检查区域顺序、相对比例、正常可见数量、纸底摘要、模式页脚与全部标记；修好视觉后再验证1920×1200的三列同屏和填充。16:10不授权新页面结构，原生组件存在也不证明视觉符合素材。
3. 结构实现成立后定向检查超宽、低高度、恢复 1920×1080 以及已支持尺寸；覆盖明细展开、右侧三个业务页签和长内容。主列保持同屏，内部列表末项可达，两栏最高输入正确。
4. 新盖牌确认、建设付款确认、第二效果结束／继续和新版弃牌查看走真实正常入口。诊断状态可以排查问题，但不能替代正式流程；某个捕获入口未就绪就定位入口，不反复跑无效大矩阵。
5. 最后核对命名映射、旧 UI 删除与无 Missing Script／Reference，再进行受本次改动影响的定向回归。历史测试失败先定位关联；本次引入的失败必须修，不能为了通过去掉业务断言。
6. “已加组件”“编译通过”“画面在父区内”分别只证明部分条件。后续窗口还必须有源图→实际模式图→逐区域差异／依据的记录；内部布局有效、三列无换页、业务可达和旧 UI 清理不能抵消构图失败。基础修正历史结论保留，不把它自动扩展为后续所有专用窗口的视觉通过。

## 7. 后续提示词的详细程度

每项提示词必须列清：读取哪些实际入口和资产；改哪些对象及其源／覆盖；拟用的原生层级与每轴驱动者；素材来源及状态；业务调用和回包；需要删除与重命名的对象；严格有序的阶段与出口；正常入口操作步骤；可检查的通过条件；未提供规则或设备的具体缺口。

不得只写“做好自适应”“复用共用组件”“清理旧 UI”“适配各分辨率”。既有任务标题和编号保留用于文档管理；执行阶段和生产命名分开。后续新素材仍先读实际包、核对与本规范的冲突，再写明确接入说明。

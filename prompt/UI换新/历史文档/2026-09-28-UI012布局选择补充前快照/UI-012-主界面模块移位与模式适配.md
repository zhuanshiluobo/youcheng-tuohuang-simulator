# UI-012：主界面模块自动移位、模式适配与收起

重置日期：2026-09-28。请按本文件执行新版UI-012，先读[09最新规范](09-主界面模块移位与收起规范.md)、[00共同约束](00-共同执行约束.md)、[02页面与字体规范](02-单页面与字体补充规范.md)、[07原生布局](07-原生布局命名与旧UI清理纠正规范.md)及项目 `AGENTS.md`。

用户认可当前1080p布局。本次在当前实际资产上实现整模块自动移位、游戏模式回填、自由页面关闭和主界面收起。保留现有模块内部自动变化与最新样式，保留已接通业务。原UI-012全面联机／设备／终局验收不作为本次任务主线；旧记录与未验项保留，详见[旧入口说明](UI-012-多尺寸实际对局与联机验收.md)。

## 一、完成目标与范围

必须交付以下六项：

1. 当前1920×1080、当前模式、普通展开状态的主界面构图保持；返回该尺寸后也保持，不拿旧截图恢复已被用户调整的版本。
2. 宽度足够时，整模块组合为“玩家＋企业家／城市／地图／弃牌盖牌手牌／企业＋行动”五区；更高或偏窄时按09的可行组合自动排布。中央地图尽可能接近正方形，模块不出界、不过度压缩。
3. 真实三人局显示两名对手；企业／企业家模式控制整个模块与布局占位。企业家依赖企业；1080p无企业家时手牌占原企业家区域。
4. 自由打开的页面可以正常关闭，不提交或取消无关业务；effect收起、浏览、恢复保持正确。
5. 无页面且无有效effect／必选阶段恢复目标时，收起主界面到地图、本人资源、顶栏和底栏；再次展开按当前尺寸和模式复位。纯地图流程按09保留原合法输入。
6. 对受影响布局、命中、模式传递及页面生命周期做有限实际验证，交付矩形／截图、配置和未验事项，不用全套旧测试数量替代结果。

实际资产范围为局内HUD、模块宿主及其组合配置、现有页面协调器和必要模式数据链。游戏模式若尚无正式字段，应在现有启动／会话／投影及必要网络序列化中最小补齐；复用现有模式选项入口，确需新增开关时仅增对应控件与依赖约束，不重设计启动／房间界面。企业规则、地图相机姿态、专用窗口内部风格及其他业务缺口不在本次扩展。

## 三、阶段A：实现模块组合与原生布局

### 3.1 先建立资产配置

为当前基准、宽屏、必要纵向组合定义实际宿主、模块顺序和尺寸输入。配置使用语义名称，例如表示主界面布局、模块宿主和组合的名称；生产文件、类、GameObject和测试不使用 `UI012` 任务号。

保留根上／中／下布局及PageHost叠层。将整模块归位到原生VLG／HLG容器，背景与边框跟随所属模块，装饰不参与行列计数。允许一个专门组合器更新归属和LayoutElement输入；普通模块控制器不继续写外部矩形。

### 3.2 组合表必须落到真实对象

| 组合 | 必须落地的排列 |
| --- | --- |
| 基准 | 当前1080p实际排列；仅按模式执行下述回填 |
| 宽屏 | 从左至右：①其他玩家，企业家在其下；②本人城市；③地图；④弃牌、盖牌、手牌纵向；⑤企业／合作在上、行动及现有页签在下 |
| 较高／偏窄 | 先用基准纵向填充；必要时采用09中的上方玩家行、中央地图、下方城市／行动及牌区组合；只选能容纳全部启用模块的方案 |
| 主界面收起 | 地图、当前本人资源、顶栏、底栏；其余模块及空宿主退出布局 |

三人局少一名对手与企业开关都参与组合测量。若增加四区过渡，只增加确有收益的一种配置，并记录其完整模块归属，不能不断添加分辨率专用坐标分支。

### 3.3 自动选择与防抖

- 在同一Canvas坐标空间计算可用宽高、内边距和最小尺寸。先筛选可行组合，再比较地图比例、面积与模块可读性；1080p当前组合优先。
- 断点以实际模块需求决定并序列化，切入与退出分开，尺寸临界波动不能反复搬移。相同可用尺寸、模式和玩家数应得到稳定结果。
- 只在可用空间、模式、玩家集合或折叠状态实际改变时重新归位；一次批量更改后触发布局刷新，避免Update逐帧重挂父级与递归重排。
- 保持同一模块实例，保留选中、牌序、明细、滚动、焦点和pending。尺寸变化时停止无效本地拖放、恢复有效草稿，不能意外提交。
- `UiMainActionTabs.Select` 会重置滚动，移位不能靠重新Select恢复同一页签；`CardPileView` 的slotScale、旋转及edgeOverhang影响真实卡边界，放到右二窄列时要核对完整图像与命中，不能只测宿主矩形。
- 地图取得最终分配矩形后更新既有viewport和命中映射；城市原图与设施热点使用最终显示矩形。相机姿态不改，地图不拉伸；地图近方形不能以几乎不可见的面积达成。

**阶段出口：** 基准保持、宽屏五区正确、更高屏幕无挤出；启用模块各有唯一实例及位置，内层仍能自动填充，阈值切换稳定，尺寸恢复无累计漂移。

## 四、阶段B：游戏模式开关与布局回填

1. 从正式对局玩家集合得到对手数，排除本机；三人只显示两名。对手离场／替换／视角变化时沿真实投影刷新，不能只改数据文字而保留无效席位框。
2. 新增或复用两个独立模式标志，语义为企业启用、企业家启用；字段名按现有领域命名统一。配置层开启企业家时同时开启企业，关闭企业时同时关闭企业家；开局校验拦截非法组合。
3. 模式是本局一致配置。保证创建、单机／测试启动、Host启动、客户端首次快照及重连快照传递一致；HUD只读。旧入口缺字段时采用可追溯兼容默认值，不从有无企业内容推断。
4. 配置控件使用现有设置资产和检查器文案，模式依赖有明确反馈；不在对局HUD新增与正式状态脱节的临时开关。如果当前只有组件没有企业规则，布局仍按配置工作，业务缺口单独记录。
5. 1080p企业开、企业家关：手牌整体进入原企业家模块区域，原手牌宿主不留空位。企业／企业家全关：手牌继续回填，企业／合作整个模块退出布局，行动区使用其余量。
6. 宽屏企业家关时玩家区取得左一剩余高度，手牌保持右二；企业关时最右行动区域填满。空列仅在真的没有启用内容时释放，其余模块按当前配置重新归位。
7. 模块关闭同时撤销其显示、射线、键盘导航和无效入口；不停止必要状态同步、不销毁正式数据、不绕过规则。若某入口仍受模式限制，统一使用同一正式标志和合法性查询。

**阶段出口：** 三种合法模式均可从真实配置传到HUD，非法组合有一致处理；两名对手无第三个空位，各组合回填正确，展开HUD也不会显示已禁用模块。

## 五、阶段C：自由页关闭和两类收起

使用现有 `GameplayHudFrame` 的唯一页面协调能力扩展，禁止另造一套互不知情的页面管理器。精确状态表见09第6节。

1. 对自由打开的设置、日志、普通查看等登记正常关闭动作；明确详情返回与退出浏览。自由页关闭不自动确认、取消effect或结束行动。
2. 顶栏优先处理当前effect：显示时收起；已有有效恢复目标时展开并关闭当前资料显示。无effect时继续保留盖牌等AllowStageFolding阶段的收起／恢复优先级。无上述目标且有自由页面时执行正常关闭；无任何页面及恢复目标时才切换主界面展开状态。
3. 自由页自己的关闭按钮必须独立可用，尤其顶栏正在显示“展开effect”时。已接入的ESC使用单帧消费；同一按键／点击不同时触发关闭、打开设置和折叠HUD。
4. 盖牌等必选阶段页不因“非effect”被当成自由页面关闭。当前盖牌 `IsEffectPage=false`、`AllowStageFolding=true`，沿原阶段收起／恢复；防止宿主Update又自动重开被错误标记的阶段。自由查看器正常Close与被替换时Dismiss分别使用，不能统一清返回来源。不允许借主界面收起绕过强制选择。
5. 主界面收起隐藏地图／本人资源／顶底栏以外的全部主模块及空槽，释放空间；PageHost保留，使新强制请求仍能正常呈现。当前资源引用为frame的resourceValueTexts；核对实际五项而非重新造旧资源板。不能直接关闭MainSurface／MainRegions／ContentRoot等复合根，避免连地图、页面协调器或数据刷新一起关闭。若请求必须用隐藏模块，临时暴露所需模块并在流程后恢复折叠偏好。
6. 主界面折叠状态、effect恢复目标、当前资料页分别保存。收起期间打开／关闭顶栏资料、变更尺寸和接收同步都不抹掉折叠偏好；请求失效只清理该请求，不复活旧页面。
7. 展开按当前尺寸、模式和玩家数重新组合；模块隐藏不能执行OnDisable中的提交／取消，也不能重复注册按钮。迁移的静态文案留资产中，动作变化文案通过序列化配置切换。
8. 纯地图必选流程可能没有恢复窗口：如果操作都能在保留区域完成，允许收起HUD并继续原地图输入，不将它当成收起effect而暂停；需要其他模块时保留必要模块，无法保留才给不可收起原因。

**阶段出口：** 自由页可关、effect可独立收起恢复、无页可收起HUD且可还原；两栏始终最高合法交互，零个或一个页面，所有隐藏内容不抢输入。

## 六、阶段D：有限验证与实际画面

先完成实现和必要资源，再看实际画面。以下是覆盖目标，允许一个场景同时覆盖多项，不把所有模式、尺寸、窗口做全组合。

| 用例 | 检查重点 |
| --- | --- |
| 当前模式1920×1080→其他尺寸→恢复 | 同源同数据下保留基准，模块未复制、原绑定无丢失；以当前基准记录比较 |
| 一个实际能触发五区的宽屏，例如2560×1080或3440×1440 | 用户指定左右组合完整，地图比例／面积有前后数据，最右操作可达；不强行宣称某例必然触发 |
| 16:10及一个可行的更高窗口 | 先填充，必要时切纵向组合；无分页、没有整HUD滚动、地图不过长且模块不越界 |
| 每个实际组合断点两侧与往返 | 布局不抖动、不累计尺寸、输入和滚动有效，无瞬间双份模块 |
| 三人／四人真实启动 | 对手数为2／3；整席位和明细对应，城市不会被多余空位挤出 |
| 三种合法企业模式、一次非法配置 | 两个标志真实传递；依赖一致；无企业家时1080p手牌明确回填；企业关闭不留空框 |
| 无页收起→调整尺寸→顶栏资料→关闭→展开 | 仅保留四类内容，关闭后保持收起，展开按当前模式复位；模式关闭项不会复活 |
| effect预选→收起→资料A→资料B→页内关闭→顶栏展开 | 草稿／当前请求正确，资料关闭不提交，不误触发HUD折叠 |
| 收起HUD时新effect、pending回包、请求失效 | 必选交互仍可完成，不丢同步，不复活旧页、不重发命令；必要模块临时显示有恢复 |
| 移位后的地图／城市／手牌／页签实际点击 | 中心及边缘命中、等比留白换算、真实查看与合法拖放、两栏首命中及唯一页面成立 |

测试只针对新组合选择、模式依赖／传递、席位显隐与收起状态转换等真实风险。复用已有业务测试，不锁死用户可编辑的每个坐标、颜色或静态文案；1920基准保留用同一来源的几何记录和实际图核对。本任务明确要求的组合归属和模块数量可以验证。

模式数据若进入网络协议，需要验证序列化／首次投影／恢复快照一致；能运行局域或本机多客户端时补一次真实同步用例。若设备或真实网络不可用，单列限制，不能写成真实联机已验。旧版全游戏联机矩阵不因此全部恢复为强制范围。

测试、捕获、正常运行不得调用Rebuild、生成或保存覆盖界面。改动属于HUD源还是场景覆盖要写清，两个实际场景访问同一有效来源；不能只查未应用覆盖的源Prefab。

# 主界面模块自动移位、模式开关与收起规范

日期：2026-09-28。依据：用户认可当前1080p主界面，要求重置UI-012，保留模块内部自动布局，按屏幕空间和游戏模式移动整块模块；新增自由页面关闭和主界面收起。

**本规范是本次主界面组合与收起行为的最新依据。** 原“所有比例固定左中右三列”“不得自动改变模块所属列”“没有effect时收起按钮禁用”不再适用。原生布局、顶底栏最高、单页面、窗口不可拖动、正式规则权限和资产所有权继续有效。当前执行入口为[新版UI-012](UI-012-主界面模块移位与模式适配.md)。

## 1. 目标与保护范围

1. 当前实际场景中的1920×1080、当前模式、正常展开状态是本次保留基准。保留现有模块贴图、内容、字号和内部布局，不借本次适配重新设计已经认可的画面。模式变化引起的明确移位与用户主动收起单独记录。
2. 模块外层按空间选择归属容器和顺序，内层继续根据获得的尺寸自动填充、等比和局部滚动。新增规则负责整模块组合，不逐个给按钮、文字或卡牌写屏幕坐标。
3. 所有当前模式启用的模块在普通展开状态有实际位置；不能因比例增加“玩家页／城市页／行动页”等主分区分页。现有三个业务页签保持其业务含义。
4. 目标是让中央地图的实际可见区域尽可能接近正方形，同时保持足够面积、模块可读与操作可达。正方形是优化目标，不是要求强行裁成正方形、拉伸地图或把模块缩到不可读。
5. 模块移位由系统自动进行。用户不能拖动模块或窗口；本次没有新增可拖动工作台或手动保存位置功能。
6. 专用窗口内部继续采用各自最新规格。尤其UI-010已在后续任务中按用户要求删减文案、入口和额外宣告带，不能恢复旧素材中的已删除内容。UI-011已接入的查看器和真实手牌挂接也继续沿用。

## 2. 模块边界

执行前将以下语义映射到当前实际节点、组件、场景覆盖及数据所有者，不能仅按物体名称猜测：

| 模块 | 移位与显隐单位 | 保留内容 |
| --- | --- | --- |
| 其他玩家信息 | 整个列表宿主 | 实际对手列表、明细展开、玩家身份、局部滚动 |
| 本人城市 | 城市模块外层 | 城市原图、真实格位、高亮、设施交互和坐标映射 |
| 企业家 | 当前企业家模块 | 所属玩家及真实信息；若只有占位内容，不能伪称正式企业家业务已实现 |
| 地图 | 真实地图视口模块 | 当前相机方向／投影、缩放与导航状态、合法地图输入 |
| 资源 | 当前本人资源显示 | 实时资源与数量；不得恢复已删除的旧资源计数器 |
| 手牌 | 已接入的真实手牌宿主 | 卡序、选择、查看、分页及内部扇形／拖放规则 |
| 弃牌／盖牌 | 各自当前新版模块，可共用牌区宿主 | 公开数量、本人的合法查看、对手隐藏信息边界 |
| 企业 | 企业／合作模块及其合法入口 | 当前正式投影或已明确的组件占位，不擅自补企业规则 |
| 主要行动 | 当前行动页签及内容模块 | 保留主要行动／快速行动／城市样式三个业务页签与真实命令 |
| 顶栏／底栏 | 最高常驻层 | 当前合法按钮、回合和结算摘要等，不随内容模块一起隐藏 |

“企业家”和“企业／合作”是不同模块，不能把二者合并成一个显隐开关。“资源”不是所有玩家卡上的资源文案集合，保留的是当前本人资源模块；顶栏中的资源本就随顶栏保留。

## 3. 按屏幕空间组合模块

### 3.1 基准组合

1920×1080且模式未变化时，保持当前模块位置与尺寸关系。运行时先记录本次开工的实际矩形和截图，不采用数日前的旧资产值覆盖当前画面。

相同16:9的更高像素分辨率不应仅因物理像素数较大就切换为超宽组合；使用安全区、Canvas转换后的可用宽高与模块尺寸需求判断。

### 3.2 宽屏组合

宽度足够且能改善地图区域时，采用用户指定的五个并排区域。以下从左至右排列，“右二”即最右列内侧的一列：

| 左一 | 左二 | 中央 | 右二 | 最右 |
| --- | --- | --- | --- | --- |
| 其他玩家信息 | 本人城市 | 地图；保留当前资源模块的合法位置 | 弃牌区、盖牌区、手牌区 | 企业／合作、主要行动及现有业务页签 |
| 企业家位于玩家信息下方 | 城市等比填充 | 取得合理剩余空间 | 三个模块纵向组合，手牌继续内部自动布局 | 企业关闭时行动取得空出的空间 |

各列由HorizontalLayoutGroup分配宽度，列内用VerticalLayoutGroup分配高度。企业家、手牌等从当前容器整体移动，禁止复制另一套显示再逐帧同步。不能把旧企业家区域的硬最小宽度直接带入较窄的左一列，必须区分可调整的容器首选尺寸与内容真实可读下限。

宽度尚不足以同时容纳五区时，继续使用当前组合；如确有明显收益，可增加一个经过实际验证的四区过渡组合。过渡组合必须在配置表中明确每个模块的唯一去向，所有启用模块仍可见，不凭任意分辨率新增更多特殊分支。

### 3.3 更高、偏窄的屏幕

先保持基准组合，通过现有纵向填充消化增加的高度；16:10不必自动移位。只有基准组合压窄地图或侧栏、且替代组合能满足可读下限时，才采用纵向组合：

- 顶底栏仍固定，资源保持可见；其他玩家信息可作为上方短行，按实际两名／三名对手分配。
- 地图占独立主区域，优先给接近自身宽度的高度，不把多余高度全塞给地图形成过长视口。
- 地图下方按可用宽度并列本人城市与“企业／行动”；再将手牌、弃牌、盖牌及启用的企业家放入下方布局行。每个模块仍为原实例和原内部布局。
- 纵向组合只有在地图和全部模块的最小高度合计能放下时才可采用。不能把整个HUD放进长滚动页，也不能把必要行动移到屏幕外。

这是实施时可采用的补充策略，具体归位、首选尺寸和启用边界需要依据实际资产测量后写入配置。低于任何组合的可读下限时记录实际支持边界，不强行支持所有极端竖屏，不新增按比例隐藏模块的页面。

### 3.4 组合选择与稳定性

选择顺序固定：

1. 读取安全区实际可用尺寸、当前游戏模式、真实玩家数、模块最小／首选尺寸，以及用户是否已收起主界面。
2. 先排除会造成遮挡、最小尺寸冲突、操作不可达或启用模块无处安放的组合。
3. 当前1080p基准优先保留。其他尺寸在可行组合中比较地图实际矩形的宽高比和可用面积，选择更接近正方形且没有明显牺牲可读性的方案。
4. 使用可配置的切入／退出边界或收益差，防止临界宽度来回移动模块。尺寸抖动、文字换行和Layout刷新不能导致一帧一个组合。
5. 组合选择依据候选配置计算，不能反复把同一批对象搬来搬去试出分数；采用确定的计算输入，布局稳定后核验实际结果。

可用 `abs(log(mapWidth / mapHeight))` 比较偏离程度，但不能仅最小化该值而选出很小的地图。记录最终断点、进入／退出条件、适用模式和依据；具体数值是项目配置，不在文档里凭空指定一个屏幕像素宽度。

## 4. 游戏模式驱动的模块开关

### 4.1 合法组合

| 企业 | 企业家 | 合法性及显示 |
| --- | --- | --- |
| 开 | 开 | 两个模块均显示 |
| 开 | 关 | 隐藏企业家，企业保留；布局回填 |
| 关 | 关 | 两个模块都退出显示、命中和布局占位，其余模块重新组合 |
| 关 | 开 | 非法配置；开启企业家时同时开启企业，关闭企业时同时关闭企业家 |

开关来自当前对局的正式模式配置，不由当前有没有卡牌／字符串是否为空推断，不保存在各客户端互不一致的本地偏好中。UI不在刷新时修改正式模式。若当前尚无字段，最小补齐现有开局／会话／投影中的配置传递；缺少企业规则仍单独记缺口，不把UI开关当作新规则已完成。当前内容加载器尚有限制企业／企业家内容接入的检查，本次模块启用标志不能绕过该检查或强行加载未实现的内容包；区分模式要求显示模块与该业务是否已具备正式执行能力，沿现有禁用／占位边界显示真实原因。

配置入口按同一依赖关系约束，开局校验拒绝非法状态。旧存档或旧启动入口缺少字段时，兼容默认值应保持当前显示行为并记录依据，不能导致已有对局突然丢失模块。对局内没有现成规则时不新增玩家随时修改模式的功能。

### 4.2 玩家数与回填

- 对手列表来自正式可见玩家集合，排除本机玩家。三人对局显示两名对手，四人显示三名；不按场景名字写死，也不补空白第三名占位。旁观者如有现成模式，沿其权限单列处理。
- 在1080p仅关闭企业家时，**手牌移入原企业家区域并使用该区域**；原手牌宿主不再保留空白占位，释放的空间由相邻可伸展主体使用。其余正常模块位置尽量保持，不能顺带重排全部主界面。
- 同时关闭企业／企业家时，手牌继续承接企业家空出的区域；企业空出的右侧空间优先分配给现有行动模块，空宿主退出布局计数。
- 在宽屏组合关闭企业家时，玩家列由玩家信息取得空出的纵向空间；手牌仍位于右二。关闭企业时，最右行动模块填满对应余量。不能机械地跨组合套用1080p的回填位置。
- 三人模式只是少一名对手，应重新测量玩家区，释放余量；不能因此丢掉城市、手牌或合法行动，也不能向玩家展示不存在的占位身份。

## 5. 原生布局与模块归位的实现责任

| 层次 | 唯一职责 |
| --- | --- |
| 安全区、顶／中／底 | 保留当前根布局及顶底栏高度，ContentRoot取得余量 |
| 模块组合配置 | 在资产中定义各组合的宿主、模块次序、最小／首选／伸展输入和模式条件 |
| 模块组合控制器 | 只在尺寸、模式、真实玩家列表或收起状态变化时选择组合，并一次性更新父级／次序／布局输入 |
| 原生布局组 | 计算普通行列的最终位置和尺寸，每个轴只由一条有效布局链驱动 |
| 模块内部组件 | 继续处理内部内容、图片比例、合法滚动、手牌扇形和城市格位等专用映射 |
| 页面管理 | 独立维护当前页面与effect恢复目标；PageHost始终是内容覆盖层，不参与模块排成的一列 |

移动时用稳定对象引用维护注册，不依赖“左列第三个子物体”等位置或旧Transform.Find路径。保留GUID、fileID、UnityEvent、脚本引用和场景覆盖。允许布局组合器按资产配置为现有模块归位；不允许普通控制器逐帧写模块坐标、复制HUD、运行时保存Prefab或调用生成器。

需要更换父级时保留对象和业务状态，采用与布局一致的局部变换约定，统一归一化内部缩放，下一轮原生布局负责最终矩形。不要为了移动模块先整棵SetActive(false)触发OnDisable取消业务。确需隐藏表现时，明确谁负责CanvasGroup、布局参与和输入，业务订阅继续有效。

地图／城市显示矩形改变后刷新现有视口与命中映射。保留当前地图相机姿态和玩家导航意图，不用改摄像机角度假装布局变方；可见区域变化确需调整裁剪／视口时走既有接口，不能改变地图游戏数据。

拖放期间尺寸突变时可结束本地拖放表现并恢复有效选择，不提交命令；组合变更不丢失牌序、页签、明细展开、滚动、pending或effect草稿。布局刷新批量执行，避免递归触发和每帧重挂父级。

## 6. 自由页面关闭、effect收起和主界面收起

### 6.1 分开保存状态

至少分别维护：当前可见页面及类别、有效effect恢复上下文、主界面展开／收起偏好、当前模式／布局组合。主界面收起不等于effect收起，不能共用一个布尔值。

自由页面包含玩家自主打开的设置、说明、日志、普通查看等。自由页面必须有清楚的关闭入口，关闭不提交业务；详情的关闭／返回沿既有有效来源恢复上层，浏览根的关闭回到主界面。实际查看器的正常Close与用于被其他页面替换的Dismiss职责不同，不能为了关闭入口统一调用Dismiss丢掉来源。盖牌等强制阶段页、待回答的effect或提交中的流程，不能仅因不是普通effect窗口就当成自由页面随意取消。

### 6.2 顶栏按钮优先级

| 当前状态 | 顶栏动作 | 结果 |
| --- | --- | --- |
| 有正在显示的可收起effect页 | 收起 | 仅隐藏effect页并保留有效草稿，主界面保持原状态 |
| 有有效的已收起effect，不论是否打开资料页 | 展开 | 关闭当前资料显示，恢复当前有效effect；不额外切换主界面展开状态 |
| 无effect优先目标，存在允许收起的必选阶段页或其恢复目标 | 沿现有阶段收起／展开 | 例如盖牌按AllowStageFolding及有效阶段恢复，不改为自由关闭 |
| 无可见页面及有效恢复目标，纯地图流程全部操作位于保留区域 | 收起／展开主界面 | 继续原地图输入所有权，不暂停、取消或提交该流程 |
| 其他受规则控制且不允许收起的流程 | 当前流程合法动作或禁用原因 | 不能套用自由关闭，不能顺便收起整个HUD绕过必选流程 |
| 无effect／必选阶段恢复目标，当前显示自由页面 | 关闭 | 走该页面正常关闭入口；不改变主界面展开状态 |
| 无可见页面、无effect／必选阶段恢复目标、主界面展开 | 收起 | 收起主界面非保留模块 |
| 无可见页面、无effect／必选阶段恢复目标、主界面已收起 | 展开 | 按当前尺寸及模式恢复模块组合 |

自由页面仍提供页内关闭入口：当顶栏当前用于“展开effect”时，玩家也能只关闭资料，保留effect继续收起。若当前页面有内层返回语义，页面关闭与返回的去向分别登记，不能一帧触发两个动作。

按钮文案、图标、可用原因存于检查器配置或文案资产。每次点击只解析一次当前优先级、执行一个动作；effect在回包中失效时重新解析，不能先恢复旧effect再折叠HUD。

无可恢复窗口不等于没有待处理业务。纯地图流程仍可收起HUD，前提是合法操作可以在保留的地图、资源和顶底栏完成；若流程依赖将被隐藏的模块，保留必要操作模块，无法保留时明确不可收起原因。不能统一禁用所有无窗口的地图流程，也不能通过折叠暂停或回答它。

### 6.3 主界面收起后的保留内容

- 保留地图、本人资源、顶栏、底栏；其他玩家信息、本人城市、企业家、手牌、弃牌、盖牌、企业和行动模块整体隐藏，并退出布局占位和输入／焦点。
- 与隐藏模块有关的背景、外框、标题和空槽同时收起，不留空列。地图取得释放的可用内容区，资源保持可读可达；不得激活已删除的旧资源板。
- 顶底栏继续最高可交互，地图仍只允许当前规则合法操作。折叠不会自动结束行动、取消预选、提交请求或恢复不合法按钮。
- 主界面收起是玩家主动选择，不能由宽高比自动触发。改变尺寸、数据刷新、关闭普通资料页不自动展开HUD。
- 收起期间真实资源、玩家和请求继续同步。打开顶栏资料页不改变HUD收起偏好；关闭后回到同一收起状态。
- 新的强制交互按当前正式流程显示在唯一PageHost；不能因HUD已收起吞掉请求。若合法步骤必须操作已隐藏模块，临时显示所需模块并记录恢复意图，避免无法操作；流程结束后恢复玩家先前的收起偏好。不得用静默提交来解除阻塞。
- 再次展开按当前尺寸、模式和玩家数重算归位，不恢复旧屏幕坐标。已在模式中关闭的模块不因展开而复活。

## 7. 实施及验收顺序

1. 只读记录当前1080p实际资产、场景覆盖、模块矩形、可用模式字段和页面入口，保留当前视觉作为基线。
2. 先实现配置驱动的模块归位及可行组合，保持基准；再接模式开关和玩家数回填。
3. 接自由页关闭及三类收起状态，保留正式effect生命周期。
4. 功能与素材稳定后做有限尺寸、断点边缘、模式和状态组合核对；问题定位到模块后修复，不批量截图未完成布局。

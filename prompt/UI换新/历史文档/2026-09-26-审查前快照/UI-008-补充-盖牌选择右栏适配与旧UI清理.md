# UI-008 补充：盖牌选择、右栏纵向适配与旧 UI 清理

日期：2026-09-26。与 [UI-008 主提示词](UI-008-设施建设与报价联动.md)共同执行。本补充新增三项修复，原设施建设与报价联动继续保留。

## 范围与顺序

仅处理**局内 UI**。承接 [UI-007 交付](执行记录/2026-09-26_UI-007_通用选择窗口.md)及其[局内布局约束](UI-007-补充-布局结构与自适应重构.md)，使用实际生效的布局容器／组件，保留 1920×1080 下正常界面的现有位置。盖牌入口替换、旧控件删除及已知越界修复是本次明确变更，单列差异，不据此重新排版整套主界面。非局内页面及其共享源仍按 UI-007 的资产隔离结果保留。

执行顺序：读取实际资产与入口 → 修右栏布局并搭好新版盖牌选择界面 → 核对完整素材、层级和基准 → 接正式盖牌流程与旧功能替代入口 → 清理三类旧 UI → 完成原 UI-008 建设迁移 → 在适配和素材就绪后验证相关尺寸与业务。原 UI-008 中可独立完成的视觉搭建无需等待未提供的规则能力。

## 一、盖牌阶段接入角色牌选择 UI

### 目标

游戏进入当前玩家需要盖牌的阶段时，使用 UI-007 的新版角色牌选择界面：**查看候选 → 单选一张 → 确认盖牌**。正式盖牌由这个入口完成，替换原来的拖动角色牌到放置区域的交互。

### 实施要求

1. 核对实际阶段与资格。当前阅读入口为 `GamePhase.CharacterCover`、`CharacterCardPanelPresenter.BuildView` 的 `CanCover`／手牌项资格，以及 `MobileCityInteractionController.SubmitCoverCharacterCard`。复用真实盖牌规则和 `CreateCoverCommand → CoverCharacterCard` 提交链，不把盖牌误接成使用角色牌、开局移出两张或 effect 的 `AnswerInteraction`。
2. 复用 UI-007 实际 `EffectDialogShell`、卡牌网格、选中态、详情、确认及模式配置；为盖牌提供明确的单选模式和接线。不能只造组件演示或另建外观相同但未被正式阶段调用的窗口。标题、说明和按钮文案放在资产配置，字体继续遵循五类角色。
3. 候选只来自本机有权查看的当前手牌与真实可盖牌资格，按稳定卡牌 ID 选择；未选不能确认，预选和查看详情不改变游戏状态。非当前玩家或不可盖牌时不能借打开窗口提交；候选为空时显示真实原因，不伪造卡牌或自动跳阶段。
4. 阶段进入、轮到本机、重新同步／恢复时能够打开正确选择页。相同阶段与上下文的重复刷新不能反复创建窗口、清空有效预选或抢占正在查看的详情。上下文变化、候选移除、已盖牌或阶段结束时清理过期选择；窗口回调复核当前阶段、玩家、资格及对应会话版本。
5. 确认仅提交一次，pending 期间防重复。以正式成功／拒绝／同步结果更新手牌和盖放显示，不能提前移除卡牌或直接写本地 `GameState`。拒绝后保留仍有效选择并允许重试；旧回包不能关闭新上下文的页面或解开新命令的提交锁。
6. 接入统一单页面管理，顶底栏仍可交互、窗口不可拖动。盖牌是阶段操作，不能伪造成待结算 effect 来复用顶栏恢复按钮。若原规则允许返回／关闭，必须有可达的重新打开入口，返回只影响预选和页面，不能绕过必须盖牌的阶段。
7. 审计 `CharacterCardCoverDragCoordinator`、`CharacterHandPanel` 的盖牌拖放回调，以及旧放置区的确认／取消入口。新版实际链通畅后移除这条旧盖牌提交路径及拖放提示、命中区域、待提交动画依赖，保证不能通过残留快捷键或监听再盖一次。手牌内部排序、卡牌查看和其他合法拖拽按各自职责保留。

### 验收

- 从真实对局的盖牌阶段进入新版选择页，选择本人合法手牌、查看详情、返回后确认，正式状态正确更新；不以手动打开壳或注入诊断候选代替正式接入。
- 未选／空候选、非本人阶段、手牌变化、已盖牌、重复点击、拒绝／迟到回包和同步恢复处理正确；取消权限与原规则一致。
- 旧拖动放置不再提交盖牌，只有新版确认是有效入口；盖牌后正常进入后续流程，角色牌使用与效果结算继续可达。

## 二、整个右栏按可用高度纵向填充

### 目标与审计范围

修复用户报告的“屏幕变宽后，右侧局部 UI 仍保持固定纵向尺寸”。检查**右侧整列及全部子分区**，包括身份／资源显示、角色卡或提示内容、操作区、页签栏及主要行动／快速行动／城市样式三个页签。修复父级到最终背景、边框、Viewport 的高度传递，不能只改右侧最外层矩形。

当前 `UiHudColumnsLayout.SetLayoutVertical` 已向列分配实际高度，但 `UiActionRegionHeight` 仍以 `baselineHeight` 等提供首选／最小高度且 `flexibleHeight = 0`；`UiActionGroupLayout`、`UiActionCardContentLayout` 还各有内容高度约束。以上是审计起点，需结合实际 Prefab 中纵向布局、LayoutElement、锚点及其他写入者确定每一级原因，不能仅凭类名或挂有 Layout 判为已适配。

### 实施要求

1. 从安全区域扣除顶底栏后的 `ContentRect` 出发，右列及其需要填充的外壳／内容容器使用当前实际可用高度；宽度变化造成的 Canvas 逻辑尺寸、换行和换列变化也要触发纵向重算。不能缓存开工高度后只改宽度。
2. 明确各子区的最小、首选和可伸展部分：标题、必要按钮与间距按内容保留尺寸；主体容器和 Viewport 分配剩余高度。用纵向布局、LayoutElement 的 flexible 值或职责清楚的自定义 LayoutGroup 实现。1920×1080 复现正常既有位置，其他尺寸按约束分配。
3. 三个页签的实际显示组分别验证。隐藏组不应继续占位；切换后父容器与当前组正确更新。快速行动的长效果行、城市样式现有入口及卡片／提示状态均纳入，不把第三页布局问题延到 UI-010。
4. 外壳、背景、框线、滚动视口沿分配区域填充；内容超出时在本区内部滚动，保留可达操作区。填充的是应伸展的布局空间，卡图保持比例，文字与按钮不靠任意拉高或整块缩放来填满。
5. 高度不足时按配置紧凑、重排或滚动；高度充足时将余量交给允许伸展的区域。避免固定 `preferredHeight`／`maxHeight` 截断余量，也避免多个 Fitter、LayoutGroup 和每帧写坐标脚本争抢同一轴。
6. 布局稳定后，用同一坐标空间记录父子实际矩形，证明右栏、各分区和 Viewport 在分配范围内并填满约定空间；底端不越过内容区、不被底栏遮挡。固定 padding 和设计留白允许存在，不能以大块非设计空白掩盖未填充。

### 验收顺序

先完成上述高度约束及组件实现，再定向验证 **1920×1080 → 2560×1080 → 1920×1080** 的宽度变化、一个实际高度变化及低高度状态。记录实际渲染尺寸与 Canvas 逻辑尺寸，覆盖三个页签、角色卡／提示切换和长列表。发现未适配区域就返回实现，不能重复批量截图已知失败布局。完整矩阵仍在素材、布局和状态就绪后按计划验收。

## 三、移除旧资源计数器、翻转和弃牌区

### 清理原则

用户已明确要求在可行时删除这三类**旧 UI**。本项先核对并迁移其仍需保留的功能，再删除旧节点、事件、失效引用及独占的旧表现逻辑。清理对象是旧表现和旧入口，资源、盖牌／用牌规则及弃牌数据继续由正式状态维护。

| 对象 | 删除前必须完成的工作 |
| --- | --- |
| 旧资源计数器 | 确认新版 HUD 已完整显示原计数器承载的资源与其他必要数值；清点 `ResourceCounterBoard` 实例、View、控制器引用和刷新路径，将仍需显示的数据接到新版正确位置 |
| 旧翻转按钮 | 核对切换卡面、返回行动面以及结束第二效果选择等实际职责；将仍需玩家决定的操作接到新版对应按钮／选项，保持原命令及资格，不能删除后自动跳过、自动结算或使流程无法结束 |
| 旧弃牌区 | 明确旧手牌预制体中的弃牌按钮／计数／预览区与新版 HUD 弃牌区域的区别；把仍需保留的数量、查看入口和只读卡牌详情接到新版位置，保留原可见权限，然后移除重复旧区域 |

特别注意当前代码中的依赖：

- `MobileCityInteractionController.RefreshResourceCounter(bool)` 在 `resourceCounterBoard == null` 时直接返回，后面同时刷新角色手牌和建设面板。必须先拆分这些刷新职责，删除旧计数器后手牌、盖牌状态、建设和其他业务显示仍会更新；不能只把序列化引用置空。
- `ActionPanelController.Flip` 通过 `FinishCharacterUseOnFlip` 可能进入 `SubmitSecondEffectDecision(false)`，旧翻转不只是装饰。迁移后玩家仍能明确选择结束／继续，规则结果与旧合法路径一致。
- `CharacterHandPanel` 初始化、Render、关闭／销毁和页面管理仍引用 `DiscardButton`、`DiscardCountText`、`DiscardOverlayObject` 等。清理时调整其必需引用校验、事件注册／注销和刷新，避免空引用或隐藏旧页继续占用唯一页面。

删除范围必须落到实际局内资产：记录源 Prefab／场景覆盖、对象层级路径、引用迁移目标及专用代码变更，修改实际使用的同一来源。共享的素材、卡牌数据、其他页面仍使用的 Prefab／脚本不随旧节点一起删除。若清理确实涉及独占文件，先列出并核验每个项目内绝对路径和全项目引用，按根 `AGENTS.md` 执行，并检查 Git 状态；禁止泛删目录。

可独立移除的旧项直接完成。若某项仍有未迁移的必需功能，先完成对应替代入口；受真实规则／素材缺口阻挡时只对该项记录“保留及原因”，继续其他可完成清理，不能把暂时隐藏全部对象当作清理完成。

### 验收

- 两张实际对局场景使用的新旧来源一致，已清理旧节点不再显示、占位、接收射线或被运行时重新启用；新资源显示、手牌／盖牌刷新及建设面板正常。
- 原由翻转承载的必要操作有明确的新入口，完成角色牌操作和第二效果结束路径，不改变规则或产生双提交。
- 新版弃牌入口能访问原有权限范围内的数量和详情，关闭后页面管理与焦点正常；旧区域及其监听已清理，无 Missing Reference 或空引用。

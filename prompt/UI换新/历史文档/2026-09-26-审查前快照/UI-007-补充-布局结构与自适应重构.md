# UI-007 补充：局内 UI 的布局结构与自适应重构

日期：2026-09-26。与 [UI-007 主提示词](UI-007-通用卡牌与选项窗口.md)共同执行，并作为 UI-008～UI-012 的布局依据。

2026-09-26 用户范围修正：**只修改局内 UI。启动菜单、加载、房间大厅、收藏室等非游戏中界面全部排除，并回退本轮对这些界面的改动，保留开工前状态。** 下文“全量”“所有 UI”均仅指局内范围。共享设置、日志、规则书和查看器的布局改动必须限定在局内使用的资产来源，不能影响局外实例。

用户安排：本补充从下个任务 UI-007 开始执行。用户已确认 UI-006 运行结束；UI-007 承接其[最终交付记录](执行记录/2026-09-26_UI-006_结算与撤销.md)，先完成全局布局重构，再继续通用卡牌与选项窗口。UI-006 原提示词与交付记录保留，当前文档编写不代表已修改或验证 Unity 界面。

## 1. 两项硬要求

1. **布局容器和组件适用于所有局内 UI。** 不只修城市面板，也不只给 UI-007 的新窗口加 Layout。覆盖实际使用的顶底栏、对局主界面各分区、玩家明细、卡牌与效果列表，以及局内窗口／抽屉／详情／查看器。启动、加载、房间大厅和收藏室等非局内页面不修改；后续局内专用窗口换新继续复用同一要求。
2. **1920×1080 下现有 UI 的屏幕绝对位置保持不变。** 基准是 UI-007 开工时承接的实际场景／Prefab 及有效场景覆盖，包含 UI-006 最终交付。重构可以改变父子层级、锚点和局部坐标，但相同状态下实际屏幕上的位置不能因此改变。其他尺寸根据可用空间伸缩、重排或滚动。

这里的“绝对位置不变”是基准画面要求，不是要求继续用固定 `anchoredPosition` 实现。参考尺寸、间距、最小／首选／最大尺寸应保存在资产配置中，由布局关系复现既有构图。保持现有贴图、字体角色、正常尺寸与样式，不能借本项重新设计 1920×1080 界面。

已报告的“其他玩家明细展开把城市挤到底栏下方”单列为待修缺陷，不能把越界结果固化为正确基准。优先通过明细高度分配和内部滚动修复，保留正常基准位置。若某一实际状态的既有位置本身与内容区边界冲突，记录对象、前后矩形和冲突原因，不得悄悄移动整套基准构图来声称位置未变。

## 3. 布局职责与组件

| 区域 | 结构与职责 |
| --- | --- |
| 根与安全区域 | 安全区域内分配顶栏、内容区、底栏；集中计算实际栏高与间距，只扣除一次。布局分区和最高输入／显示层级分别负责，不能因加入 Layout 降低两栏层级 |
| 顶栏、底栏 | 横向布局、可伸缩中段及按内容约束的两端；用 `LayoutElement` 等表达尺寸、优先级和留白。窄／矮窗口按内容约束切换紧凑组织，仍保留合法操作 |
| 主界面分区 | 容器表达列、行及剩余空间分配，最小／首选／最大尺寸来自配置。主区域与唯一页面容器都受实际 `ContentRect` 约束 |
| 玩家列表与城市 | 同一受限列内分配玩家标题、可展开明细、间距及城市剩余空间；列表／明细使用真实布局组件，城市容器保留可用高度 |
| 列表、效果行、资源、按钮组 | 采用 `HorizontalLayoutGroup`／`VerticalLayoutGroup`、`LayoutElement` 等；文字换行与数量变化参与尺寸计算，右侧状态／执行按钮保留空间 |
| 卡牌候选 | 使用可变列数的网格／流式布局或职责明确的自定义 `LayoutGroup`，以可用宽度、卡牌可读尺寸及间距计算列数；超量内容滚动 |
| 所有窗口、抽屉、详情与查看器 | 页头、内容、页脚由容器分配；操作区保留空间，内容区承担滚动。位置由锚点及布局决定，游戏内窗口仍不可拖动 |
| 城市原图、卡图、装饰及叠加标记 | 用比例约束、相对锚点或等效的局部映射保持原图比例和视觉位置；源图内部坐标可以沿用，不能把它们当作整个屏幕的固定坐标 |

实施要求：

- 每个 RectTransform 的每个尺寸／位置维度明确一个驱动者。不能让 LayoutGroup、ContentSizeFitter 和控制器同时写同一轴，也不能在 `Update`／`LateUpdate` 中把布局结果改回固定坐标。
- `ContentSizeFitter` 只用在确需按内容伸展且不会形成父子反馈循环的轴；滚动列表的内容可按内容增高，Viewport 自身必须受父容器约束。`ScrollRect` 和 `RectMask2D` 用于合法的内部滚动，不掩盖整个面板已出界。
- `AspectRatioFitter` 或等效比例布局用于图像区域，避免与父布局争抢同一尺寸；素材 9-slice 的角区和边框仍按 3.5 参数处理。
- 组件挂载后必须实际负责布局。不能保留完整固定坐标脚本，再添加不生效的 Layout 作为交付；也不要求每个装饰图都单独挂 LayoutGroup。
- `CanvasScaler` 负责基础缩放。整套 1920×1080 坐标乘比例、平移整张 HUD 或为每个分辨率加坐标表，不能作为主适配方案。局部可滚动内容、地图和图片自身的导航独立保留。
- 原始绝对坐标可以用于读取基准、推导初始 padding／spacing／preferred size；完成后关系保存在资产配置中。保留必要的局部图像坐标，清理已被布局接管的运行时写入路径。
- 仅在内容、展开状态、安全区域或尺寸改变时更新布局；需要自定义组件时职责局部化，避免建立另一个逐帧重排所有 UI 的总控制器。先复核现有 `UiFlowLayoutGroup` 等组件可否复用。

## 4. 玩家明细展开与城市边界

1. 玩家明细仍最多展开一项。展开是主界面内部布局变化，与顶栏的 effect 页面收起／恢复按钮分开。
2. 以当前内容区和所在列的实际高度分配空间：可用明细高度受“列高减玩家标题、间距、城市最小可用高度及其他固定内容”限制。素材中的 224／330 等数值是基准参考，不能直接作为任意屏幕上必然可容纳的高度。
3. 明细超出分配高度时在明细内滚动，预留滚动条空间。城市在剩余区域等比显示；顶端可以按合法展开布局变化，底端始终留在内容区内且不与底栏相交。
4. 空间不足时采用配置的紧凑组织、减少非必要留白或明细内部滚动，确保详情内容仍有可访问方式。不能让城市出界、被底栏遮住，或把整块城市裁掉来通过检查。
5. 开闭明细、切换玩家、空内容／长内容、明细打开期间改变窗口大小，再恢复 1920×1080，布局须从当前容器重新计算，不能依赖 `Awake` 保存的一套位置／高度继续累加偏移。
6. 用同一坐标空间检查城市、玩家列、内容区和底栏的实际矩形。仅证明 `anchoredPosition.y - sizeDelta.y` 不变、城市高度大于某个固定数，不能证明城市没有越界；还要考虑所有父级缩放与偏移。
7. 城市图像、格位和点击映射使用最终显示矩形及等比留白。世界地图继续承接实际 `mapRegion → SetScreenViewport` 接口；俯视相机改造和 UI-004 最终地图验收依旧按 [05 任务安排](05-地图俯视改造期间的任务安排.md)交接。

## 5. 执行顺序与验证门槛

### A. 先改结构，保持基准位置

完成全量清单和 1920×1080 基准后，先改根、常驻栏、主界面分区及玩家／城市，再逐项迁移共用行、列表和全部现有页面。素材从搭建起就放入最终布局结构，层级、padding、间距和尺寸约束共同复现基准；不先用一套固定坐标完成整页再把适配留作收尾。

逐区核对实际资产与当前页面所需素材，确认正确版本、层级、字体和尺寸驱动关系。发现基准位置漂移就先修该区域。完成布局结构、城市边界及基准位置核对后，再推进 UI-007 原有的通用卡牌／选项窗口迁移和新增业务接线；原有行为随结构迁移保持可用。

### B. 适配实现完成后再测尺寸

开始多尺寸验证前，必须已有实际生效的容器布局、尺寸约束、重排／滚动及低高度策略；清单中不能还依靠整页固定坐标撑起页面。

先针对受影响区域做一次必要的窄宽度／低高度调整，检查真实边界与重排；如果仍未完成适配，回到实现阶段。不得持续批量截取已知没有适配能力的各种分辨率来当作工作进度。多比例正式画面与完整业务矩阵在布局、素材、字体和对应状态均就绪后执行，范围按 [实施计划](01-UI更新实施计划.md)选择，综合验收交 UI-012。

### C. 验收要证明什么

- **全量结构：** 每个实际 UI 有布局职责与驱动者记录，必要容器／组件实际生效；仅有新共用组件尚不算所有 UI 完成迁移。
- **1920×1080 基准：** 相同入口、数据、展开状态下比较迁移前后屏幕位置；再验证缩小／放大后回到基准的结果。锚点与局部坐标允许变化，屏幕位置保持一致。截图中的抗锯齿差异不能代替几何比较，也不能以宽松容差掩盖整体位移。
- **动态边界：** 明细展开／切换／关闭、长列表和长文本下城市仍位于内容区内、与底栏无交叠；布局稳定后在同一屏幕或根容器坐标空间检查。只对必要功能边界写测试，不锁死所有可编辑样式；本轮位置保持以用户明确要求的基准为准，不固化内部锚点实现。
- **交互回归：** 两栏始终可交互，唯一页面／effect 收起恢复、草稿、滚动、焦点和事件归属正确；没有重复提交、透明遮罩挡栏或隐藏页拦截输入。所有窗口仍不可拖动。
- **画面与证据：** 在实际使用的同一场景资产／覆盖上验证。截图前确认必需资源和布局就绪；测试通过不替代实际看图。既有多比例截图作为历史证据保留，不能替代本次结构重构后的验收。

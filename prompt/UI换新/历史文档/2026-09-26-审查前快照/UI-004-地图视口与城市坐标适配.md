## 目标与范围

让地图、城市板、格位与指针坐标在新布局和窗口尺寸变化后保持一致。处理实际 HUD 的地图／城市承载、相关相机与命中转换；不调整游戏地图规则或改写静态设计文案。

## 阅读入口

- `TabletopCanvasLayout`、`MapCameraGeometry`、`MapInteractionRouter`、`TabletopPointerClassifier`。
- 两场景实际地图 Prefab、相机、地图 Sprite 边界和桌面 WorldSpace Canvas。
- `BuildInfoPanel`、城市格位／设施拖拽处理和城市样式预览的坐标入口。
- 素材的城市原图及格位映射；现有 viewport／pointer／layout 测试。

## 工作步骤

1. 记录当前世界坐标、相机视口、屏幕点、Canvas 点和城市原图坐标的转换链。明确地图与 UI 的父子关系，避免旧桌面缩放和新屏幕布局同时控制同一对象。
   先确认地图与城市按 UI-003 的素材布局完整显示；若仍是旧桌面越区或原图缺失，优先修复视觉承载，再开展命中与导航逻辑。复用已搭建的模块框体与视口，不另起布局。
2. 根据现有渲染路径选择相机 viewport 或其他必要承载方案，说明选择依据。无需引入额外渲染纹理时保持简单；无论何种方式都以实际内容边界换算坐标。
3. 地图平移、缩放及边界限制按新视口有效范围计算。折叠侧栏、展开详情、切换紧凑模式和调整窗口大小时同步更新；不要仍用全屏宽高当地图可点击范围。
4. 城市板保持 2059×3801 原图比例。按源图列起点 100／730／1360、行起点 156／1036／1916／2796、格位 600×850 映射，核心位为第三行第二列；考虑等比留白、遮罩、滚动和父级变换。
5. 让设施位置选择、拖拽预览、城市高亮和宣告格位使用同一几何来源。拖拽显示留在内容层，越过常驻栏时不能遮住两栏或误提交地图操作。
6. 内容窗口阻挡其覆盖区域的地图输入；非阻挡区域是否可操作遵循当前流程。缩放／平移手势不得在 UI 上触发地图变化。
7. 处理拖拽中重排、请求失效和窗口大小变化：安全保留或取消草稿，恢复合法状态，不静默提交。

## 验收

- 在两个实际地图场景、基准／4:3／超宽／紧凑尺寸下，目标中心及边缘点击与高亮一致。
- 最大／最小缩放和地图边界处无明显偏移；侧栏收起展开后命中正确。
- 建设位置和城市样式预览对准实际格位，整张城市板边框不会被误算成格子。
- 顶底栏始终可操作；被 UI 拦截的点击不会穿透到地图。
- 复用或补充坐标变换、命中归属、视口边界的必要测试，检查实际画面，不把具体相机美术位置固定成测试要求。

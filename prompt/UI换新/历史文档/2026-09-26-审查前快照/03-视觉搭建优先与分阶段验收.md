# 视觉搭建优先与分阶段验收

日期：2026-09-25。来源：用户在 UI-003 执行期间指出主界面边框尚未搭建、素材未完整呈现就开始截图核对，要求调整实施顺序。

本规范制定于 UI-003 执行纠正阶段，后续界面任务继续适用。沿用[单页面与字体规范](02-单页面与字体补充规范.md)、常驻栏最高交互层、窗口不可拖动和资产所有权要求。原素材说明与已完成记录保留。

2026-09-25 进度补记：UI-003 已完成，见[交付记录](执行记录/2026-09-25_UI-003_常驻栏与适配框架.md)。第 7 节保留当时的继续要求作为过程依据；后续执行顺序见最新[计划](01-UI更新实施计划.md)。新到的 11 个按钮采用 [3.2 增量规范](04-主界面按钮3.2增量规范.md)，其余主界面素材依据继续沿用。

## 1. 当前应纠正的方向

UI-002 的组件预览证明共用资源可以使用，不代表整张主界面已经搭建。UI-003 必须先补齐主界面的整体构图、外框和分区素材，再接单页面管理及 effect 恢复等逻辑。

2026-09-25 检查到的现有截图仍是新顶底栏配旧桌面主体。此类画面可作为诊断证据，不能作为新版主界面视觉完成的证据。现有代码和测试保留，先处理视觉缺项，避免继续扩大功能和批量截图后再回头重排全部资产。

## 2. 统一工作顺序

| 阶段 | 做什么 | 进入下一阶段前必须满足 |
| --- | --- | --- |
| A：依据与素材清单 | 确认当前版本、基准预览、区域布局、角色映射、正式资源与实际源资产 | 每个可见区域有对应素材与目标节点；缺项明确可追踪 |
| B：基准视觉搭建 | 在 1920×1080 基准下，先主外框，再模块底图／边框／标题，再卡槽、图标、文字与状态 | 当前页面该有的视觉元素完整呈现，构图与来源一致，没有缺图、白块、旧面板代替新模块或整片内容不可见 |
| C：层级与适配核对 | 核对绘制顺序、相机、Mask、Raycast、CanvasGroup、单页面容器、顶底栏及自适应关系 | 视觉层级正确，所有内容落在正确区域；基准构图成立后再完成大小屏重排 |
| D：业务逻辑接入 | 连接动态数据、请求、事件、effect 收起／恢复、合法提交等 | 正式入口正确、单一输入所有者、静态布局与文案仍归资产管理 |
| E：实际验收 | 从实际场景／启动入口进行交互验证，待资源就绪后截图对照，并完成需要的多尺寸检查 | 截图与操作证据来自当前实际资产；视觉缺项已清零，功能与未完成项分别报告 |

每个阶段完成后自行核对并继续，不增加逐阶段等待用户批准的流程。纯布局驱动、素材加载与必要渲染接线可以服务于 B／C；不要把“先视觉”理解为连显示图片所需的代码也不能写。新增业务逻辑在视觉与层级成立后推进。

搭建过程中允许看 Game View、预览或截取少量诊断图，用于发现缺图、裁剪、遮挡及导入问题；这类图标明“搭建中／诊断”，不写“视觉验收通过”。完整多尺寸截图矩阵安排在该页面素材齐全之后。

## 3. 严格采用素材依据

主界面的依据按以下顺序使用：

1. 用户后续明确要求：两栏最高交互层、单页面、effect 页收起恢复、不可拖窗、五类字体、自适应。
2. [Frontier 3.1 增量说明](../../游城拓荒/UI素材/FrontierUI-v3-Incremental.md)、[布局补丁](../../游城拓荒/UI素材/整理版-2026-09-24/原包参数/FrontierUI-v3-Patch/layout-patch.json)、[角色映射](../../游城拓荒/UI素材/整理版-2026-09-24/原包参数/FrontierUI-v3-Patch/skin-patch.json)、[新版组件索引](../../游城拓荒/UI素材/整理版-2026-09-24/清单/新版组件索引.json)。
3. [新版主界面基准预览](../../游城拓荒/UI素材/整理版-2026-09-24/预览/FrontierUI-v3-Patch/main-idle.png)及[顶栏细节](../../游城拓荒/UI素材/整理版-2026-09-24/预览/FrontierUI-v3-Patch/topbar-detail.png)。原图展示的示例库存、玩家与可选效果只用于构图参考。
4. 未被补丁替代的 MainGameUI 2.2 内容与各窗口原包说明。

在基准尺寸先按文档搭好分区位置、比例、间距、九宫格、留白和必要图层，再以锚点／布局约束表达这些关系，扩展到其他比例。不能先设计另一套布局，再以“适配”解释它与基准图的差异。

源 PNG 尺寸不等于显示尺寸：例如顶栏贴图高 72，基准布局目标高 64，底栏贴图高 96，基准目标高 82。依据布局参数设置显示区域，依据 Sprite 索引设置切片。用户后续允许编辑样式，测试不把每个像素坐标永久锁死。

严格对应的是可见组件、构图和资源角色。旧预览中的多窗口叠加、侧栏收起按钮语义、旧字体和演示规则由用户最新要求修正，不能为了复刻截图恢复这些旧交互。

## 4. UI-003 先完成的主界面清单

以下项目均属于 UI-003 的视觉搭建范围。不能以 UI-005 负责模块数据为由把模块框体、背景、标题和内容容器留空。

| 区域 | 必须搭建的素材与视觉结构 | 核对重点 |
| --- | --- | --- |
| 主外框与整体底层 | `outer-frame`、按来源使用的背景层及边缘 | **第一步完成主界面外框**；四边及角部完整，没有被地图／旧桌面盖住，装饰不吞点击 |
| 顶栏 | `topbar-bg/frame`、品牌图标与文字、`round-plaque`、回合刻度、阶段、`turn-tag-refined`、红区分组、收起／展开图标与设置图标 | 不只贴长条背景；标牌、图标和独立文字完整，字体角色正确 |
| 左侧玩家信息 | 对手信息卡的 `module-bg/frame`、纸面、身份标记、头像、资源图标及文字槽 | 按玩家数量复用信息卡；没有玩家时按配置空态或隐藏条目，不伪造正式数据 |
| 我的城市 | 模块框、标题纸面及城市内容视口 | 城市原板完整等比，先把板放到正确容器；格位行为由 UI-004 深入验证 |
| 地图 | 中央地图区域、模块框、地图内容边界及图上已有控件 | 地图真正渲染在预定区域；不让整张旧桌面占据三列新布局，也不用一张截图伪装实际地图 |
| 自身状态、企业家、手牌 | 状态纸面、模块框、标题、卡槽、头像／卡牌内容与滚动容器 | 正式原图完整显示、比例正确；组件还未接数据时清楚记录其状态 |
| 合作区、弃牌、盖放区 | 模块底图、边框、标题、轨道／计数／卡牌区域 | 所有分区先落地，规则未提供的区域使用明确空态；不省略设计框体，不伪造合作等级 |
| 右下页签与行动区域 | 三页签、当前区域的模块框、各操作入口底板／图标／文字 | 新样式完整，选中和禁用状态可展示；业务切换在后续接入，旧行动面板不能覆盖新构图 |
| 底栏 | `bottom-bar/frame`、`chain-slot-bg/frame`、撤销底板与箭头、结束行动底板／文字 | 摘要槽和图标完整，旧结束入口后续正式切换，不能只保留一条背景 |

对应组件应来自 UI-002 已导入资产或经核对的沿用素材。无需把素材包所有图片同时摆上界面：按当前状态应出现的组件全部就位，备用状态通过单独状态预览核对。

UI-003 前置完成地图／城市的视觉承载和必要视口约束，避免把地图越界或整块缺失留到 UI-004。UI-004 负责准确命中、平移缩放边界及交互；UI-005 负责真实动态数据与行动流程，复用已搭好的视觉结构。

## 5. 视觉完整性与层级检查

每个区域建立一行核对记录，字段至少为：区域、文档／预览依据、素材 ID、Unity Sprite／GUID、实际节点路径、当前可见状态、差异／原因、待办。共享 Prefab 内的间接引用也要追溯，不能只统计根文件中的 GUID。

视觉阶段检查：

- 实际使用的源 Prefab／场景覆盖正确，必需 Image 有正确 Sprite，卡图／图标不为空。
- 九宫格、透明边界、`preserveAspect`、内容内边距与图源匹配。
- 节点已激活、尺寸有效、颜色和父级 Alpha 正确；不被 Mask、相机 viewport 或其他面板意外裁掉。
- 框体、标题、图标、文字和内容分别存在，静态文案与五类字体保留在配置中。
- 未接规则的区域有明确表现状态，不能拿空白屏、错误贴图或大面积旧界面作为视觉完成。

层级阶段检查：背景 → 内容 → 边框／装饰 → 当前唯一页面 → 非页面提示／拖拽 → 常驻顶底栏；区域内部根据素材要求细分。主外框的显示可覆盖内部装饰边缘，但所有装饰关闭不必要的射线命中。实际 Canvas、相机、Mask、Raycaster 及焦点一并核对，不能只看排序数字。

## 6. 截图前的就绪条件

截图工具不能只等待固定若干帧就宣告视觉就绪。等待上限可以有，但放行条件必须对应实际加载状态：

1. 正式目标场景及本次要展示的页面／模块已激活，当前状态与待验收场景一致。
2. 本状态所需 Sprite、卡图、头像、地图和字体已加载，相关异步更新完成；动态空列表确实是合法空态。
3. 布局和文本测量已更新，实际渲染尺寸符合本次记录，画面稳定；不存在临时加载页、未完成的重排或错误覆盖。
4. 视觉清单没有未处理的必需素材缺项。缺图、错误、超时就输出具体缺项并记录诊断图，不能记录为完成截图。
5. 截图后实际查看图片，逐区与对应源预览／文档核对，标明合理差异（真实数据、最新交互、适配）和缺陷。

无需新增庞大的截图系统；先修正当前捕获入口的就绪检查和报告语义。已有提前生成的图片保留为诊断材料，在新记录中说明其用途，不删除历史证据或改写旧报告。

## 7. 当前 UI-003 的继续方式

1. 保存并盘点当前修改，保留已有逻辑、测试和用户改动；不回滚整个工作区，不重复生成覆盖 HUD。
2. 暂缓扩展业务逻辑、重复跑完整测试及批量截图，先完成本文件第 4 节的主界面视觉清单。已有编译错误或妨碍显示的问题可先修正。
3. 完成 1920×1080 基准视觉搭建，再核对层级、单页面容器、顶底栏输入及大小屏布局。
4. 随后检查已经写出的逻辑，接到新视觉节点上；消除指向旧面板的重复入口。保留可用代码，按实际差异调整。
5. 最后满足截图就绪条件并进行本任务需要的验证，区分“主框架视觉完成”“主框架交互完成”和留待 UI-004／005 的业务项目。

阶段出口由执行者依据清单自查，不需要用户反复批准。只有已有资产覆盖授权确实不包含某项操作时，按 `AGENTS.md` 处理；此规范不授权测试或截图调用 UI 生成器。

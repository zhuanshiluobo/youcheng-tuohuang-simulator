# UI-010：城市样式详情与宣告

更新日期：2026-09-26。先读[共同约束](00-共同执行约束.md)、[实施计划](01-UI更新实施计划.md)、[原生布局、命名与清理规范](07-原生布局命名与旧UI清理纠正规范.md)、[基础修正执行提示词](局内UI基础修正执行提示词.md)及其实际交付，再读 UI-006～UI-008 的相关入口／城市映射记录。

**前置：局内 UI 基础修正已经完成。** 本项依赖实际原生布局、无尺寸分区换页、语义命名和旧 UI 清理结果；不能仅因旧任务已添加 Layout 就视作前置通过。UI-004 的世界地图验收仍按 [05 任务安排](05-地图俯视改造期间的任务安排.md)等待俯视改造；它不阻挡本项独立 UI，但正式宣告前必须核对当前实际城市容器的格位映射。

## 一、目标、范围与读取入口

完成右下第三个业务页签的城市样式列表、玩家标记／使用状态、详情，以及宣告选择／确认与城市设施预览的换新。第三页的外层高度适配继承基础修正，本项接其完整城市样式内容和业务。目标限于局内实际引用的 `CityStyleDeclarationPreviewDialog`、View／输入处理、Prefab、卡图／状态配置与正式入口；路径改名后按迁移表查找。

读取：

- `游城拓荒/UI素材/CityPattern-Layout-v1.0.md`、整理版 `pattern-card-map.json`、状态安全区及原卡／城市板格位说明。
- 当前 `GameplayDialogRegistry`、行动页签的城市样式入口、候选投影、匹配组合、宣告资格、首次／再次宣告和特殊行动正式命令。
- 当前城市板实际显示容器、`CityBoardSlotIndex` 及格位／方向／高亮输入来源；UI-005／008 与基础修正的有效映射证据。

只修改局内页面和其明确资产来源，不扩展到启动、加载、房间、收藏室或其他开发者负责的地图相机姿态／投影。规则与正式内容定义保持不变。

## 二、阶段 A：来源、状态与基准

1. 建立“第三页列表→查看→宣告→样式选择→合法设施组合→确认→后续结算”的实际入口图，标明查看与提交路径、输入所有者、所需正式状态。使用样式特殊行动另列入口，不与宣告混成同一个命令。
2. 列源图版本／卡牌 ID、Unity 路径／GUID、实际节点、状态轨道及玩家颜色映射。卡面版本、裁切和安全区成组配置，不写死源预览六张组合，不把图片中示例状态当真实局面。
3. 核对实际源 Prefab、嵌套实例、场景覆盖和共享内容。第三页已有按钮与监听先核对再迁移，避免新旧入口并存或事件按位置互换。
4. 记录正常 1920×1080 同一数据／模式／展开状态的屏幕矩形；继承已有正常位置与构图。新素材内容、用户明确删除目标和现有越界单列差异，不通过移动全部主界面掩盖问题。
5. 正式状态若未支持源轨道某种含义，写出现有投影及缺口，不伪造数量、使用次数或额外宣告资格。

**出口：** 列表、状态、详情、宣告和特殊行动职责清楚，素材及真实数据来源可追溯，城市映射依赖有明确归属。

## 三、阶段 B：原生结构与完整视觉

从最终结构开始放素材，先搭完整外框、原卡、标题、状态槽、城市图像与操作区；不先固定坐标拼页再添加不参与计算的 Layout。

| 区域 | 结构与尺寸责任 |
| --- | --- |
| 主界面第三页 | 填满已有 ActiveActionRegion，VerticalLayoutGroup 分必要标题／主体／操作；主体 ScrollRect.Viewport 取得剩余高度，卡列表 Content 使用 GridLayoutGroup 或原生行列 |
| 详情／宣告外壳 | 外部受 PageHost／ContentRoot 约束，内部 VerticalLayoutGroup 分 Header、Body、Footer；标题／按钮保留内容高度，Body 的 flexibleHeight 取得余量 |
| 并列样式与城市 | Body 使用 HorizontalLayoutGroup，按正常基准首选宽度、内容可接受最小宽度和 flexible 分配；两个子区纵向填满 Body |
| 样式区 | VerticalLayoutGroup 组织列表、既有详情及状态；长列表／正文只在区内滚动，不增长整页高度；标记轨道普通行列使用原生组件 |
| 城市区 | 外层由 Body 分配，内层城市原图保持比例；设施格位、方向、组合高亮相对真实原图显示区域映射 |
| Footer／状态按钮 | HorizontalLayoutGroup 分配合法确认／取消／返回入口；尺寸不由候选数或正文长度直接写入 |
| 底图／边框／标记装饰 | 拉伸或源图相对映射，不参与外部行列分配；装饰不接收无关射线 |

每个轴只有一个实际驱动者。普通行列按 07 原生组件配置，不能用自定义逐项定位器继续接管。Viewport 受父布局限制，Content 只在滚动轴按内容增高；卡图和城市图内层比例约束不能同时改父容器尺寸。城市样式使用完整 930×600 原图，不裁去右侧状态内容；其他原图使用自身真实比例。

**各屏幕比例使用相同的信息结构。** 不因 16:10、窄宽或低高度将并列样式与城市切成适配分页／分段步骤；可用空间由原生布局分配，长内容区内滚动，候选网格仅在自身内容中换列。原有“主要行动／快速行动／城市样式”业务页签及真实查看／宣告子步骤保留，步骤只能由用户操作和规则驱动。

五类字体按资产配置：方正普通、汉仪强调且关闭 Bold／`<b>`、msyh 特殊词、NarrowBold 效果次数／条件／资源数量、wide 纯 UI 页码。运行时只更新真实数值／状态，不重写静态标题和样式说明。

**出口：** 基准正常位置、素材完整性、各区剩余空间与比例正确；无旧面板替代新视觉，无尺寸触发的分段导航，再开始新增业务接线。

## 四、阶段 C：格位映射、规则与页面生命周期

1. 区分 `view` 与 `declare`。查看不建立业务提交；宣告允许预选样式与当前合法设施后确认。宣告确认不自动发动样式特殊行动。
2. 从正式可见投影更新各玩家标记和使用状态，明确主动Ⅰ类未使用／已使用两槽、Ⅱ类五槽与额外宣告带在当前规则中的对应。源 `zero` 与预览 `exhausted0` 的名称差异记在映射，不改源文档。
3. 数量标记不误当剩余次数，后续宣告不重置原使用轨道。候选、玩家数、设施状态变化后刷新映射，复用条目清理旧 ID、标记与事件。
4. 城市格位使用当前统一来源。复用先前证据前核对同一实际资产、父变换和最终显示矩形；本窗口新增变换需要补验。换算包含等比留白、父缩放、内部滚动和放大，不能以素材原始矩形直接充当屏幕命中区。
5. 高亮仅表现当前预选，最终资格由正式查询／命令决定。确认前不真实旋转设施、不扣标记、不发奖励；不得为预览直接写 GameState。
6. 确认复核请求／版本、候选、设施可用性和首次／再次宣告资格。pending 防重复；拒绝后刷新并保留仍有效草稿，旧回包不影响新请求。取消／返回／撤销各按现有规则，不把退出预览当已提交回滚。
7. 查看、宣告、独立详情与子选择通过唯一页面切换；页面内并列区域仍是一页。effect 收起保存有效预选并停止宣告选点，隐藏期间同步但不自动弹回；展开关闭当前资料页后校验并恢复当前步骤。普通查看不登记成待结算 effect。
8. 新入口接通后清理本项独占旧外壳、重复按钮、监听、必需引用和旧坐标写入路径。保留合法共用素材、正式城市数据及其他业务入口；按语义命名并维护 GUID／fileID、字符串查找及场景覆盖。不得引回旧翻面、hint/context 或比例分页。

**出口：** 各模式只有一个输入／提交通道，真实格位与状态映射有证据；地图相机依赖明确单列，不能据世界地图暂缓跳过本项已改城市容器的核对。

## 五、阶段 D：验证步骤

1. 从真实第三页打开列表和详情，检查少量／超量卡、长说明、多玩家标记、原图完整、使用状态及返回的页签／滚动位置。隐藏或无资格内容遵守当前权限。
2. 从正式宣告入口完成合法样式／设施预选→详情→返回→确认；分别覆盖当前实际支持的首次／再次宣告与已使用／未使用组合。确认前状态不变，提交后由规则结果更新。特殊行动入口另验，不以宣告通过代替。
3. 在实际页面检查城市中心／边缘格位、设施方向、组合高亮和滚动／放大后的命中；复用已有测试时说明覆盖的资产和新增变换，不重复搭一套城市坐标。
4. 原生布局和素材就绪后再检查 1920×1080→1920×1200→超宽／低高度→恢复基准。主三列始终同屏，样式与城市不自动换页；窗口根、Body 和 Footer 使用同一坐标系检查，正文取得余量，末项可达。
5. effect 收起→浏览其他资料→展开恢复，确认预选／版本正确、隐藏页不选点；两栏仍最高输入，所有窗口不可拖动。尺寸变化和长列表不产生重复提交或焦点丢失。
6. 缺规则分支只做组件／空态验证并记录，不用示例数据冒充真实宣告；只补本项改变带来的实际风险，适配未完成不批量截图。

## 必须覆盖的验证

### A. 常驻栏与输入

- effect 页、独立抽屉、子选择、设置和查看器按典型流程互斥切换；提示与拖拽展示不引入额外页面。整个流程包括过渡期间，可见且接收输入的页面最多一张。
- 实际点击顶栏及底栏合法功能，确认射线命中对象和响应；业务禁用按钮显示正确原因。
- pending、非当前玩家、断线提示和对局结束状态不把整条栏锁死。
- 透明装饰、内容遮罩、临时 Canvas 与相机合成无越层；UI 点击不触发地图动作。
- 已启用的键盘／手柄焦点能访问两栏，关闭窗口后恢复合理目标。
- 固定渲染尺寸下，逐个拖动窗口／抽屉／查看器的标题、背景及边缘，确认容器位置不变；关闭重开、切换模式／请求及尺寸适配后仍不能拖窗。检查运行时未重新启用窗口移动组件，同时验证列表滚动、卡牌／设施拖拽、地图／图像平移仍正常。
- 完成“effect 已预选 → 顶栏收起 → 主界面资料 A → 资料 B → 顶栏展开”：资料 B 关闭，当前有效 effect 步骤及草稿恢复。关闭资料页应回到主界面并保持 effect 收起；无 effect 时按钮不能折叠普通资料页或主界面。
- 检查设置等直接入口先收起 effect 再切换页面；隐藏页的遮罩、焦点、地图选点和拖放提交输入均释放，信息浏览不触发结算答案。

### B. 屏幕与画面

- 先查看实际层级和组件驱动，再看画面。原生根 VLG、三列 HLG、列内 VLG 与 LayoutElement 配置必须有效；保留的内容专用算法逐个有用途和范围说明，不接管普通行列、不隐藏整列。背景、边框、正文 Viewport 沿分配区域填充，正文超量仅在本区内部滚动。
- 1920×1080 相同场景、数据、展开状态下，实际屏幕位置与核实过来源的正常基准一致；切换尺寸再回到基准也成立。此次明确删除的旧 UI、取消的分区分页与已知越界修复单列差异，不能强行恢复错误基准。局部坐标／锚点可改变，不能用它们相等代替实际位置核对。
- 玩家明细展开、切换与关闭、长内容以及展开中改变尺寸时，城市实际矩形位于内容区内且不与底栏交叠；采用同一坐标空间核对父级缩放后的边界。只检查本地底边或固定最小高度不算通过。
- 整个右栏及合作区、新版弃牌／盖放卡区、三业务页签和当前行动内容分别检查。标题、页签、必要按钮仍可达，指定主体和其背景／框体／Viewport 取得真实剩余高度；宽度变化导致 Canvas 逻辑高度变化时同样重算。只测最外层右栏矩形不算通过，旧 HintFace 不再是合法验证状态。
- 先执行 **1920×1080 → 1920×1200（16:10）→ 2560×1080 → 1920×1080** 的定向回归。无弹窗覆盖时三主列在每个尺寸与尺寸变化过程中始终同时有效、可见、可交互；不能先选择某列再截取。不得存在比例触发的导航、单列模式、隐藏列、主区平移、整列 ScrollRect 或只是把切换阈值调低的旧分支。16:10 是验证取消分页的用例，不是新增交互模式授权。
- 代表矩阵覆盖基准 1920×1080、16:10、超宽、一个已支持的低高度尺寸及恢复基准；已核实来源和状态一致的有效证据可复用。其他尺寸仅在具体风险或实际支持目标要求下补验，先写明要验证的问题和停止条件，不强制把每个页面状态与每个尺寸做笛卡尔积。
- 不主动扩展全套极端尺寸压力探索。确需核对支持下限时，选择能暴露已知最小尺寸冲突的代表用例；低于内容可读下限如实记录未支持，不将未检查尺寸记为通过，也不擅自增加主分区换页或隐藏功能列来使压力用例通过。
- 系统缩放按实际可用设备检查并记录；截图标明实际渲染尺寸、场景、模式和日期。
- 每次正式截图前确认当前页所需素材／字体已加载、布局已稳定、实际状态正确。固定帧数不是就绪证明；缺项或超时输出诊断与具体原因，不得写成视觉验收通过。截图后实际查看并逐区对照素材依据。
- 检查长中文、多位数字、超量候选、滚动末项、低高度弹窗、卡面等比及城市命中。
- 在模态、选中、报价等待和卡牌／设施拖拽中调整游戏应用窗口或渲染区域大小，确认没有状态丢失、误提交和焦点困死；游戏内窗口由布局自动适配，不能由用户拖动移位。

### C. 正式操作链

- 从实际入口完成代表性主要行动、快速行动、手牌操作、建设／支付、城市样式查看／宣告，以及可用的企业／科室模式。
- 从正常对局推进到本机真实盖牌阶段，经新版单选、查看详情、返回、确认完成盖牌并继续游戏；旧拖动放置、旧命中区或残留快捷键不再提交。复核 pending、拒绝与状态刷新，不把仅手动打开壳的诊断状态当成正式入口。
- 经正式建设入口完成候选→城市格位→付款路线→报价→确认，检查正式资源和状态更新；同时核对真实规则支持的效果授予建设、储备等入口差异。UI-004 地图依赖与尚未验证路径如实单列，不能把缺少价格当免费。
- 在真实第二效果决策状态中分别走一次新版选择页的合法继续和结束；普通 CardViewer 取消、资料关闭、返回与顶栏收起不提交这项决定。旧 Flip／Context／查看提示入口不存在，不能靠它结束流程。
- 新版 HUD 弃牌入口打开新版只读列表与卡牌详情，数量、可见权限、返回焦点和滚动位置正确；旧 CharacterHandPanel 内嵌 Preview／Overlay 壳不再被调用。资源变化、盖牌、建设之后，新资源显示和手牌刷新仍独立工作。
- 验证草稿、取消、返回、合法确认、拒绝、防重入、报价过期、旧响应与当前请求变化。
- 摘要、结算链、可选效果及撤销能力显示一致；无撤销实现时确认禁用原因，不能伪造成功演示。
- 真实上下文完成前后，旧工作流无重复输入，旧窗口不会继续响应新请求。
- effect 收起期间验证同一请求刷新、pending 成功／拒绝、下一步骤、请求替换／失效和流程结束。不得自动弹回或重新提交，展开只恢复当前有效步骤；尺寸变化后使用当前布局，不能恢复旧窗口坐标。

### D. 多玩家与恢复

- 检查两实际场景及项目支持的玩家人数，当前玩家／旁观其他玩家状态分别核对。
- 用正式多人入口验证玩家可见投影：对手手牌、盖放卡、私有候选不通过详情或日志泄漏。
- 验证提交后客户端同步、切换回合、断线重连及未完成请求恢复；版本失效按现有规则处理。
- 无法运行真实多人／发布包时，明确区分已做的 EditMode、编辑器或本机模拟与尚未完成的发布级验收。

### E. 字体与数字语义

- 按[单页面与字体补充规范](02-单页面与字体补充规范.md)检查五类实际字体引用：方正普通文字、汉仪强调文字、msyh 特殊词、NarrowBold 效果数字、wide 纯 UI 数字。

- 资源 icon 前数字、“选择 2 次”等效果数字使用 NarrowBold，顶栏回合数使用 wide。检查混排基线、间距、换行、中文标点与缺字回退。
- 在页面切换、effect 收起／恢复、动态条目创建、应用重新聚焦及字体纹理恢复后复查角色；用户指定字体可以作为验收条件。位置按本轮明确要求核对 1920×1080 基准，不额外锁定内部锚点、可编辑字号与装饰样式。

### F. CardViewer 3.6 正式查看与角色使用

以 [UI-011 查看器接入补充](UI-011-补充-卡牌查看器3.6.md)和实际素材清单为依据，不能用旧 ZoomableImageViewer 已能显示卡图代替 3.6 接入完成。

- 核对原包哈希／复用记录、合并底图、透明边距和按钮命中范围。1774×887 合并底图完整等比显示，不当九宫格任意拉伸；页头、卡区、页脚的 VLG 和按钮 HLG 在分配区域中实际生效。窗口外层受 ContentRoot／PageHost 限制，遮罩不覆盖两栏。
- 分别从设施卡、手牌、弃牌、盖放区进入 `inspect`，从正式快速行动“使用角色牌”进入 `use-character`。调用方显式传模式、合法卡牌和资格，不按卡类型猜模式。隐藏牌图、名称和替代文字不泄漏未授权内容。
- 两种模式使用同一卡图容纳区，普通查看隐藏使用按钮的显示、命中和焦点但保留页脚空间，切模式时卡图不跳位；横／竖卡图按自身比例完整显示。角色模式按“计谋／策略／取消”的素材顺序，两个操作各自映射真实规则，不按数组位置猜策略和计谋。
- 查看卡面、关闭、取消及返回不选择或使用卡牌；两个使用按钮分别核对可用／禁用原因。至少经正式入口完成一次合法使用及后续选择，确认一次点击只发一个命令，pending 防重、拒绝可恢复、旧回包不关闭新上下文。
- 从 effect 选择页进入详情并返回后，有效预选、滚动和焦点恢复；过期请求不复活。普通取消不等于第二效果“结束使用”。全程最多一张可见页面，顶底栏可交互、窗口不可拖动。
- 在布局与素材完成后检查 16:10、超宽、低高度及恢复基准，确认主列无分页、查看器内容与点击区域正确。记录实际五类入口和两种模式结果，原包浏览器 QA 不能充当项目验收。

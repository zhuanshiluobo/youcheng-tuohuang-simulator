## 1. 本轮目标与适用顺序

- 对局界面已有基本功能，以实际场景、Prefab 和当前业务接线为基础替换素材、调整布局及补齐接入。
- 用户本次明确要求：**游戏场景内，顶栏和底栏处于 UI 最顶层，始终可交互；游戏内窗口不能拖动；实现应适应不同宽高比和屏幕大小。**
- 后续补充：**同时最多打开一个页面；有效 effect 页的收起／恢复优先，收起后可查看资料，展开时关闭资料并恢复有效结算页；无 effect 的自由页面可以正常关闭；无页面且无有效 effect／必选阶段恢复目标时，顶栏按钮收起主界面非保留模块，只留地图、本人资源、顶栏和底栏，再次点击展开。字体按指定的五种语义角色使用。**
- 此要求优先于旧素材说明中的弹窗层级、整屏遮罩、窗口拖动及固定坐标布局。保留旧文档，在本分类记录新的实施要求。
- 规则合法性、信息权限、命令结果以当前项目实现与正式内容为准；素材演示数据和浏览器回调不能成为新规则。
- 文档或素材没有交付的部分，要记录缺口与沿用方案；不能假定全部窗口已有 3.1 成品。

### 1.1 实施顺序与完成条件

- 每个入口的每种显示模式先明确源说明、参数和实际预览，再选最终原生层级。将素材放入容器复现该模式构图；先在1920×1080逐区域对照源图并处理偏差，再核对层级、填充与尺寸约束、接新增业务，最后做必要交互与有限尺寸回归。已有正确业务沿用，不为视觉纠正重写规则。
- UI-003 首先完成主界面外框及全部主模块的框体、底图、标题、图标和内容容器；UI-004／005 复用这些结构，不能把视觉完整性推迟到业务接线之后。
- 组件导入、GUID 存在、编译或测试通过，不等于画面已呈现。当前状态的必需素材缺失、被错误裁剪／遮挡或仍被旧布局替代时，先修视觉。
- 搭建预览和诊断截图可用于定位问题，不计为视觉验收通过。批量验收截图必须等待素材、字体、页面状态及布局就绪，不能只等待固定帧数。
- 已写的可用逻辑与用户改动保留；自查阶段出口后继续，无须逐阶段请求批准。最小显示、布局和资源加载代码可以服务于视觉搭建，业务扩展后置。

## 2. 场景与资产所有权

1. 已搭建的场景和 Prefab 是结构、位置、尺寸、样式及静态文案的实际存放来源。接入前查清运行中实例的源资产、嵌套 Prefab 和场景覆盖。资产所有权不意味着已授权换新的旧设计必须永久冻结；本项目标设计改在已核实的源／覆盖中，运行时不能另生成一套静态结构覆盖它。
2. 修改前说明本项会编辑的具体资产，以及改动落在共享源 Prefab 还是单场景覆盖。后续执行的任务范围是对应界面的换新，不能据此批量覆盖其他界面。
3. 普通测试、运行、构建检查不调用 `Rebuild`、生成器或保存覆盖方法。只有用户明确授权具体生成器覆盖具体资产时才手动运行；不得借测试间接运行。
4. 正式 UI 的静态对象在编辑器资产中搭建。运行时只绑定数据、管理状态、创建已配置的动态条目实例和按可序列化布局配置适配；不每次启动重新生成整套静态界面。
5. 静态标题、按钮名和说明保留在资产中；同一控件有多种固定提示时使用检查器配置或专门文案资产。动态数值、地图、房间号、请求状态、错误消息由代码更新。
6. 保留无关改动、原 ZIP、原素材说明和历史执行记录。当前用户已授权清理的旧 UI 及其独占废弃依赖按 07 明确清理，不能因旧生成器仍引用而永久保留；仍被非局内合法使用的共享源不删除。资产移动保留 `.meta`／GUID，并核对类型、字段、对象路径和场景覆盖。
7. 生产资产、目录、物体、组件、长期工具与测试按功能命名；任务编号只用于提示词、历史记录与证据。执行前提供旧新映射，不通过批量重建资产进行命名整理。

## 3. 顶栏和底栏的强制交互约定

- 两栏固定在屏幕安全区域的顶部和底部；不跟随地图相机平移、缩放。它们是对局界面最高显示层和最高 UI 命中层。
- 当前唯一页面及其内部结算区、子步骤、提示、拖拽卡牌和遮罩全部位于两栏之下。弹窗不能覆盖两栏，透明 Raycast 区域也不能截获两栏点击；设置、查看器、独立抽屉等都通过同一页面位置切换。
- 两栏使用不受内容模态锁定影响的层级及输入分组；不把它们放进会统一关闭交互的父级 `CanvasGroup`。最高层根节点不能用整屏可命中的透明 Image 把内容区也锁住。
- 显示顺序和输入优先级一并解决：检查独立 Canvas、`overrideSorting`、动态排序、相机合成、Raycaster、CanvasGroup、焦点及指针捕获。不能仅把某个 Canvas 数值调大。
- “始终可交互”表示不被其他 UI 遮挡或整体锁死。结束行动、撤销等命令仍按业务条件禁用并显示原因；不能为了可点而绕过权限、必选步骤或 pending。
- 有模态窗口时仍能访问两栏的合法功能。焦点导航不能把键盘／手柄永远困在内容弹窗；启用了相关输入方式就要验证。关闭内容窗口不应隐藏两栏。
- 两栏触发操作若会使当前请求失效，走统一上下文校验与关闭／刷新路径；旧选择、旧报价、迟到回调不得提交到新请求。

### 3.1 单页面与 effect 页收起恢复

- 所有独立页面互斥，切换时先隐藏旧页及其输入／遮罩，再显示新页；父子选择使用步骤切换或替换当前页。顶底栏、主界面常驻模块及普通无交互提示不计为页面。
- 顶栏按钮按当前有效状态只执行一个动作：effect 页显示时“收起”；有效 effect 已收起时优先“展开”，先退出当前资料显示再恢复结算；无 effect 且正在查看自由页面时按登记的关闭语义“关闭”；无页面且无有效 effect／必选阶段恢复目标时，在主界面展开与收起之间切换。完整优先级见[02](02-单页面与字体补充规范.md)和[09](09-主界面模块移位与收起规范.md)。不能一次点击既关闭资料又收起主界面。
- 自由页面始终提供页内关闭入口，因此有已收起 effect 时也能只关闭资料。页面“关闭”“返回来源”“被另一页替换”的清理和返回回调分别处理；恢复 effect 时不得因资料的返回回调又弹回旧页。盖牌等必选阶段页按原流程的合法收起能力处理，不因 `IsEffectPage=false` 就当作可取消的自由页面。
- effect 已收起时可通过主界面查看其他信息；查看权限与动作合法性继续遵循当前投影。为浏览而隐藏的 effect 不保留地图选点、遮罩、焦点或拖放提交输入；正式流程主动转入地图选点则由原输入所有者管理，不与自由浏览混同。
- 收起不提交、不取消、不跳过 effect；同一请求刷新不自动弹回。状态同步继续，恢复前复核请求与版本；原流程失效时清理恢复信息，不能重放旧草稿。
- 设置／查看器等直接入口也经过统一切换；当前 effect 页可先按同一收起语义保存，再显示资料。关闭资料回到主界面，使用顶栏“展开”恢复结算页。
- 主界面收起状态与 effect 恢复上下文、阶段页收起状态独立保存。只收起非保留模块及其装饰、布局占位和输入，保留地图、当前本人资源与顶底栏；资源、投影和请求继续同步。尺寸变化、普通页面关闭、effect 清理不擅自改动玩家的主界面收起偏好。
- 新结算按原请求生命周期进入唯一页面位置；不能因主界面已收起而吞请求、提交默认答案或复活旧 effect。必须操作已隐藏模块的合法步骤按09临时显示必要模块，流程结束后恢复原显示偏好；再次展开按当前尺寸、模式和玩家数归位。
- 独立展开的结算抽屉占用唯一页面位置；作为当前页内部区域时不另建一张可见页。完整状态表及验收见[补充规范](02-单页面与字体补充规范.md)。

## 4. 自适应实现约定

- **游戏内所有窗口、弹窗、查看器和抽屉均不支持用户拖动移位。** 位置由编辑器资产与自适应布局确定，标题、背景和边缘不提供移动手柄；重新打开时不恢复历史拖动偏移。
- 审计并停用窗口移动组件、事件绑定及运行时重新启用路径，包括 `EffectDialogDragHandle`；同步调整把拖动手柄视为必需组件的引用校验。不能仅在 Prefab 上取消勾选后又被运行时代码启用。
- 卡牌／设施拖拽、列表滚动、地图平移及查看器内部图像平移按各自交互保留；这些操作不得带动窗口容器移动。本分类中的“拖拽”指这些内容操作。
- “改变窗口大小”指游戏应用窗口或渲染区域变化后自动适配；游戏内弹窗的位置和尺寸由布局重新计算，不提供拖动移位操作。
- 1920×1080 位置保持按1.2节分类：保留区对照既有正确画面，待换新区对照目标素材，缺陷区记录必要调整。不能把旧城市样式1520×900壳或其左右比例自动当成必须保持的设计。其他比例依靠容器约束，不使用固定屏幕坐标表。
- 根 VerticalLayoutGroup 分顶／中／底；当前1920×1080正常展开组合继续保留。中间由 HorizontalLayoutGroup／VerticalLayoutGroup 承载09定义的整模块组合，各模块内部继续原生自动布局。按07配置 childControl、childForceExpand、min／preferred／flexible，避免默认 Force Expand 拉高标题或锁死正文。
- 顶底栏提供首选高度、flexibleHeight 为0，内容区取得剩余高度；栏高只扣一次。每个位置／尺寸轴仅有一个驱动者，普通结构不再由自定义 Layout 或逐帧坐标脚本代替原生组件。
- 移除因比例把主界面切成“地图／玩家／行动”分页、单列导航或整屏平移的旧适配。现在允许按09在原生容器中为整模块自动更换宿主和顺序，宽屏不再强制三列；正常展开时当前模式启用的模块均有可达位置，不以隐藏某列解决宽度不足。16:10无需仅因比例变化就切换组合。
- 允许正文内部滚动、内容网格按其源设计换列及原有三个业务页签；正式模式关闭的模块和玩家主动收起的非保留模块退出显示与布局占位，并由其余模块回填。模式显隐、用户收起、尺寸组合分开管理，不让比例变化自动收起整个主界面，也不新增主分区分页。达到实际可读下限应记录，不强行适配所有极端屏幕。
- 模块归位使用稳定的序列化引用和资产配置，保留原实例、业务订阅、选择、内部布局及场景覆盖。组合控制器只在必要状态变化时更新父级／顺序／布局输入，最终矩形交给原生布局；不逐帧写坐标、不复制另一套 HUD。资源、地图和页面宿主不能被复合父节点的统一隐藏误伤。
- 卡牌、城市板、图标等比显示；九宫格装饰可以伸缩。命中坐标使用实际显示矩形及相机换算，避免等比留白造成偏移。
- 窗口改变大小时保留请求、选择、报价上下文和有效焦点。若拖拽必须取消，安全恢复草稿并给出可理解反馈，不能偷偷提交。
- 可编辑视觉参数仍由资产作者调整。测试可以验证“不遮挡”“可达”“合法提交”等行为，不能把某一稿的文字、坐标或颜色变成永久常量。

## 5. 业务与联机边界

- 优先复用当前 `InteractionRequestRouter`、玩家可见投影及正式提交路径。每个请求同一时间只有一个输入所有者；迁移旧工作流时同步处理其启用、退出及恢复。
- 报价、候选合法性、支付、奖励、结束行动和撤销能力来自规则／会话层。客户端不依据图包演示公式自行结算，不伪造撤销，也不新建平行规则状态机。
- 草稿展示与已提交状态分开。按钮防重入，回复绑定请求／上下文版本；服务端拒绝、请求变化和重连时刷新合法状态。
- 对手手牌、盖放牌及隐藏候选必须从玩家可见投影读取；不能为缩略图、工具提示或查看器暴露完整内部状态。
- 企业、科室等能力如尚未提供正式接口，交付可复用表现组件和明确接入缺口；正式入口按实际能力可用，不把演示选择当真实命令成功。

## 6. 验证和记录

1. 先复用现有测试和验证脚本，只补本项真正新增的交互风险；不为纯素材替换编写镜像实现的测试，不以测试数量作为目标。
2. 测试引用完整性、输入归属、动态展示、合法提交、信息权限、恢复以及适配后的可达性；禁止通过运行界面生成器修复测试。固定渲染尺寸下，拖动窗口标题、背景或边缘不得改变窗口位置；验证这一行为，不把某个绝对坐标固化为规范。
3. 检查实际使用的场景实例和覆盖。共享源 Prefab 检查通过不能替代实际场景检查。
4. 视觉验收按入口／模式逐项保存“源说明段落与预览路径 → 当前实际截图 → 数据状态 → 区域差异 → 依据／结论”。必须检查内容结构、基准可见数量、比例、底图／框、标题、摘要、按钮和标记；仅看几何不越界、已挂原生组件或已查看截图不算符合素材。源预览和当前实际图要对应同类模式，素材预览本身、静态 YAML 和测试通过都不能代替真实画面。
5. 每项输出新增执行记录，区分“已实现”“仅组件可用”“业务未接入”“未验证”。没有执行的验证写明原因，不能写通过。
6. 收尾检查工作区差异，说明修改内容、实际入口、验证结果、剩余风险和下一步。中文沟通，中文记录。
7. 核对主界面没有旧的比例分区换页，09定义的整模块移位、模式回填和主动收起符合当前要求；生产命名已迁移，旧 UI 节点／代码／再生路径已清除。旧翻转改为查看提示或上下文按钮不得计为清理完成。按具体风险选择有限尺寸和状态验证，不穷举每种页面与每种分辨率的组合。

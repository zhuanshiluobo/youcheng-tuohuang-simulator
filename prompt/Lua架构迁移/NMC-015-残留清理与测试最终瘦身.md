# NMC-015：残留清理与测试最终瘦身

## 任务提示词

你负责新架构迁移的最终审计和收尾：证明生产调用已经切到新路径，逐项删除无调用方的旧状态/服务/分支/测试，压缩剩余重复 EditMode，并完成全套回归与迁移结案。不要只依据类型名称删除；每个删除都要有引用和行为覆盖证据。

## 前置任务

`NMC-014A` 已验收，且 `NMC-008` 至 `NMC-014A` 的交付记录可用。NMC-014A 尚未完成时不得开始迁移结案。

## 目标

1. 证明回合、内容、交互、网络和恢复都由新架构唯一驱动。
2. 清理旧调用链、过渡适配器、已废弃状态字段、内容 ID 特判和未使用依赖。
3. 对剩余 EditMode 做最终分层和合并，原则上把 Unity 实际发现数压到 700 以内。
4. 产出 `docs/设计/Lua新架构迁移结案.md`。

## 静态审计范围

至少用 `rg` 审计并逐个确认以下符号或同类实现：

- `RoundAdvanceService` 及所有直接 `Phase`/`CurrentPlayer` 写入；
- `PendingChoice`、`PendingCardSession`、`PendingCharacterEffect`、`PendingSpecialAction`、`DelayedCharacterEffects`；
- `CharacterCardDatabase`、设施/事件/城市数据库中的内容 ID 规则分支；
- `FacilityEntryEffectService`、角色/卡牌/特殊行动专用协调器、candidate provider、answer handler 与 presenter/router；
- 完整 `GameState` 客户端传输、客户端规则执行、未投影日志；
- 旧事件、旧 dispatcher、双 revision/日志提交和 Lua 失败 fallback；
- 未使用 asmdef 引用、包依赖、测试 helper、fixture、测试资源与对应 `.meta`。

符号仍存在不一定错误，但必须说明它是新合同的一部分、纯兼容读取投影，还是仍有生产调用。没有真实调用方且已被新路径覆盖的实现必须清理。

## 清理要求

1. 为每个候选残留记录：路径/符号、现有调用方、替代路径、替代测试、处理决定。
2. 删除前用 `rg` 核对引用和 Unity 资源 GUID；每次仅删除一个明确文件，再单独处理对应 `.meta`。严格禁止递归、目录和通配符删除。
3. 不保留“以后可能用”的旧生产代码、无限期 adapter、双写、双跑或 silent fallback。
4. 对仍必须保留的适配器说明唯一调用方、为什么不能现在删除、明确移除条件；若这意味着迁移未完成，则本任务不能宣告完成。
5. 检查 Domain/Application asmdef 仍为 `noEngineReferences = true`，Lua/Unity/网络依赖没有反向渗入。
6. 检查所有持久 DTO 无委托、接口实例、Lua/Unity 对象、任意 `object`/Dictionary；稳定 ID、版本/hash、可见性和上限仍满足文档。

## 最终测试瘦身

1. 先运行完整 EditMode 并记录实际发现数、分类耗时、失败和慢测试。
2. 使用 `NMC-001` 治理文档更新最终行为覆盖矩阵。每条关键风险指定唯一最低成本权威测试层，上层只保留跨层合同、序列化/恢复、隐私和少量冒烟。
3. 重点压缩：
   - 已被 Effect/Interaction 状态矩阵取代的旧命令调用细节；
   - 按卡牌、设施、城市样式逐项复制的测试，改为 catalog + 行为族数据表；
   - Domain 已覆盖而 Application/Presentation 再逐字段复述的断言；
   - EditorAsset 每资源一测，改为目录/schema/引用完整性表；
   - 仅验证已删除旧字段或适配器的测试。
4. 最终 Unity 实际发现数原则上不超过 700。若超过，必须在结案文档中用行为覆盖矩阵逐组证明超出的用例保护了不同风险；不能用 `[Ignore]`、不可发现目录或减断言达标。
5. 对关键模块按过滤器验证后，运行一次干净、串行的完整 EditMode。读取 XML 和 Editor 日志，不只看进程退出码。

## 架构验收场景

至少验证：

- Setup → RoundStarted → 红区响应/空响应 → 角色盖放 → 两轮行动 → 收取 → 逐玩家清理 → RoundEnded；
- Lua 零/多 Effect、条件式、玩家拒绝、子节点 Failed、完成响应窗口和 `paused_fault`；
- 影响力替换的失败、`removed_only` 与完全成功；
- 角色牌、事件牌、城市样式、特殊行动和设施各行为族代表场景；
- 每类 blocker/RuleCommit 的序列化恢复与 receipt 幂等；
- Host、目标玩家、非目标玩家和观战者可见性，无完整 GameState 泄漏；
- 外部命令失败后工作副本、revision、journal 和日志完全不发布。

## 验收标准

- 新架构是所有已迁移规则的唯一生产路径，没有未登记双推进、双事件或旧 pending。
- 所有无调用方残留和陈旧测试已按安全规则逐项清理；仓库无无效程序集/包引用。
- `docs/设计/Lua新架构迁移结案.md` 包含架构现状、迁移矩阵、残留审计、可见性/恢复结论、已知限制和测试前后数字。
- 完整 EditMode 无失败；实际发现数不超过 700，或有逐组、可审查的保留证明。
- `git status --short` 只包含预期改动，`git diff --check` 通过。

## 交付报告

先给出“可结案”或“不可结案”的明确结论，再报告删除的代码/测试/依赖、仍存阻塞、完整测试 XML 数字与耗时、从 `NMC-001` 原始基线到最终的净变化。只要仍有同一规则双路径或无法解释的隐藏信息泄漏，就必须判定不可结案。

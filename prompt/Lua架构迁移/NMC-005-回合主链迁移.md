# NMC-005：回合主链迁移

## 任务提示词

你负责把现有回合推进改为由持久化 Effect 主链唯一驱动，并把旧 `Phase`/`CurrentPlayer` 降为兼容投影。先完整阅读共同约束、权威 Lua 文档、当前 `RoundAdvanceService`/Setup/TurnOrder 代码及 `NMC-004` 内核实现。

## 前置任务

`NMC-004` 已完成。可与 `NMC-006` 并行，但必须协调 `GameState`、Effect 注册和共享测试 fixture 的修改。

## 目标

1. 为 `P` 名玩家构造长度 `3P + 4` 的确定性回合主链。
2. 让 Setup 第一回合正确进入 `RoundStarted`，之后由树推进覆盖、行动、收取、逐玩家清理和 `RoundEnded`。
3. 建立 `RoundExecutionProjector`，作为兼容 `Phase`、`CurrentPlayer` 等旧字段的唯一写入者。
4. 消除旧回合服务和新主链的双推进。

## 主链合同

按权威文档实现并命名节点：

1. `RoundStarted`
2. 一个统一的角色盖放主节点
3. 每名玩家两个行动轮节点，共 `2P`
4. 统一收取阶段
5. 每名玩家一个清理节点，共 `P`
6. `RoundEnded`

总数必须为 `3P + 4`；四名玩家为 16。`activeMainNodeId` 在任何时刻至多一个，主链节点 ID 使用 `NMC-003` 的完整 SHA-256 稳定方案。

## 实施要求

1. 建立纯 Domain 的主链 builder/验证器，覆盖玩家顺序、轮次和 ID 输入；不要依赖 Unity 场景。
2. 第一回合从 Setup 完成进入 `RoundStarted`，不能直接跳到角色盖放。
3. `RoundStarted` 允许分发订阅；没有订阅者或所有 handler 返回空 `EffectSpec[]` 时，必须直接进入下一个主链阶段，不制造空 pending。
4. `RoundExecutionProjector` 根据权威节点投影旧 `Phase`/`CurrentPlayer`；搜索并迁移其他直接写入者。若旧字段仍供 UI 读取可以保留，但不能反向驱动新树。
5. 下一节点/下一回合只由 EffectExecutor 的终态推进触发。旧 `RoundAdvanceService` 如保留适配器，只能委托新入口且不得自行判断阶段。
6. 主链完成、失败、`paused_fault` 和恢复后的投影都必须确定性一致。
7. 本任务只接上阶段骨架；角色盖放具体内容在 `NMC-010`，真实 Lua RoundStarted 红区响应在 `NMC-008`。

## 测试精简要求

- 使用一个场景表覆盖 2/3/4 人主链长度、顺序、首尾、每人两个行动轮和逐玩家清理，不为人数复制整套用例。
- 保留少量集成测试覆盖 Setup → RoundStarted、空响应直通、整回合 → 下一回合和故障不推进。
- 合并或删除旧 `RoundAdvanceService`、Setup、TurnOrder 测试中只复述同一阶段顺序的用例；业务阶段独特规则仍保留到对应迁移任务。
- 完整 EditMode 必须通过并报告发现数净变化。

## 非目标

- 不实现具体角色牌、设施、事件牌或红区内容。
- 不让 Lua 构造主链拓扑；Lua 只能向当前生命周期点添加响应/子节点。
- 不在本任务重做 UI 表现。

## 验收标准

- 2/3/4 人主链满足 `3P + 4`，四人精确为 16，稳定 ID 可重建。
- Setup 首次入口、空 RoundStarted 响应、整回合衔接均由新执行器工作。
- `activeMainNodeId` 唯一；旧 Phase/CurrentPlayer 只有 projector 写入。
- 没有新旧双推进或隐藏 fallback，完整 EditMode 通过，`git diff --check` 通过。

## 交付报告

给出主链节点表、旧字段投影规则、被替代入口和 `rg` 证据；列出仍保留适配器及删除任务，报告测试基线、结果和净变化。

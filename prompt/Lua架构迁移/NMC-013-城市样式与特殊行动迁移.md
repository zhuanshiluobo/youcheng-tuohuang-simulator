# NMC-013：城市样式与特殊行动迁移

## 任务提示词

你负责把城市样式能力与特殊行动流程迁移到版本化 Lua 内容、Event、通用 Effect 和 Interaction，并清理城市/行动 ID 驱动的 C# 分支以及专用 pending。重点是复用现有内核，不为每种样式重新发明流程。

## 前置任务

`NMC-006`、`NMC-007`、`NMC-011`、`NMC-012` 已完成。

## 目标

1. 建立城市样式 Lua 注册、订阅和内容版本合同。
2. 将“声明/触发特殊行动 → 候选 → 支付/效果 → 完成事件”接入 Effect 树。
3. 将行动次数、标记物、影响力和玩家清理阶段的相关能力改为通用 Effect/handler。
4. 在全部调用方迁移后移除 `PendingSpecialAction` 及旧协调服务。

## 必读补充文档

- `docs/设计/特殊行动实现规格与工作清单.md`
- `docs/设计/行动实现方案.md`
- 当前城市样式数据库、特殊行动命令/handler、玩家清理逻辑与 UI 路由

若补充文档与两份 Lua 权威文档冲突，以 Lua 文档为准。

## 实施要求

1. 把每种城市样式拆成声明式元数据和 Lua handler；C# 只保留通用 schema、注册、合法性原子与 Effect executor，不用 style/action ID 分支决定效果。
2. 特殊行动入口先创建 owning Effect，由它发 Event/Interaction 并等待子节点。客户端不能通过旧命令直接结算资源或标记物。
3. 候选池通过 `NMC-007` 管线构造；回答后重验 revision、玩家权限、次数/成本和 hard constraints。
4. 影响力变化复用 `NMC-011`，移动/探索相关能力复用 `NMC-012`；缺失通用能力先补明确 Effect 合同，禁止在 Lua Host 加任意写 API。
5. 明确特殊行动成功、玩家拒绝、候选耗尽、支付失败、子 Effect 失败的 owner outcome 与 Event 顺序。
6. `current`、每回合次数和 playerCleanup 等状态只由主链/Effect commit 修改。回合清理 handler 必须可恢复且不重复重置。
7. 按行为族迁移：被动订阅、主动声明、选择目标、资源/标记支付、影响力组合、移动相关、清理响应。每族迁移后切断对应旧生产入口。
8. 当所有调用方迁移后，逐项移除 `PendingSpecialAction`、专用 answer command、router/presenter/service 和只验证旧调用关系的测试。

## 测试精简要求

- 用城市样式 catalog/schema 一次性验证注册、版本、handler 引用和静态参数；按行为族保留代表性规则矩阵。
- 通用 Interaction、影响力、移动和事务语义不在每种样式重复测试；只验证脚本声明的组合与独特分支。
- 合并特殊行动 UI/command/service 的跨层复制用例，Presentation 保留一条通用成功和一条拒绝/失效冒烟。
- 清理阶段用玩家/状态参数表覆盖，不逐样式复制整回合测试。

## 非目标

- 不迁移设施内容。
- 不擅自改变城市样式或特殊行动规则文本。
- 不为旧 pending 保留无限期 fallback。

## 验收标准

- 城市样式/特殊行动生产规则由 Lua handler + 通用 Effect 唯一执行，C# 无内容 ID 特判。
- 主动/被动、拒绝、失败、恢复和玩家清理结果确定且可序列化。
- `PendingSpecialAction` 及旧协调链在零调用后被逐项清理，未迁移项有证据而非猜测。
- 完整 EditMode 通过，测试按行为族组织且数量没有随样式线性增长，`git diff --check` 通过。

## 交付报告

提供样式/行动迁移矩阵、Effect/Event 组合、旧入口删除表、清理阶段恢复证据、未决规则与测试净变化。

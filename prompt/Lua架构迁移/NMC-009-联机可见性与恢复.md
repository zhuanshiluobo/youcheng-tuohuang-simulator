# NMC-009：联机可见性与恢复

## 任务提示词

你负责让新 Effect 运行时在联机权威模式下安全投影和恢复。重点是 Host 唯一权威、按观察者生成 `GameStateView`、隐藏信息不泄漏，以及 snapshot/journal/receipt 恢复不重放。

## 前置任务

`NMC-003`、`NMC-004`、`NMC-006`、`NMC-007` 已完成。若 `NMC-008` 已完成，应把其纵向切片纳入恢复验证，但本任务不依赖其业务内容。

## 目标

1. 定义每个玩家和观战/未知观察者的 `GameStateView`，替换向客户端发送完整 `GameState` 的路径。
2. 为 Effect 节点、Event、Interaction、日志与卡牌引用建立明确可见性投影。
3. 完成 Host 快照加 append journal 的恢复、receipt 幂等和一致性校验。

## 实施要求

1. 盘点 `InitialGameStateDto`、`ConfirmedCommand`、广播、重连和本地 multiplayer transport，找出任何完整 `GameState` 或隐藏领域对象跨边界的路径。
2. 先按 viewer 构造投影，再序列化/广播。不得先序列化完整状态再在客户端隐藏；客户端不持有 EffectRuntimeState、handler receipt、隐藏候选或其他玩家私有卡牌正文。
3. Interaction 只投影给目标玩家必要选项，其他玩家只看到允许公开的“正在等待某玩家”状态；Host 保留完整权威请求。
4. Event/日志使用可见性标记和安全参数。不可见事件不能通过 type、ID、参数数量、错误消息或稳定内容 ID 侧漏隐藏牌。
5. Host-only journal 至少能表达 RuleCommit 序号、stateRevision、事件/节点/interaction 变化、脚本内容版本和 receipt；网络 DTO 不等同于 journal DTO。
6. 恢复时校验 snapshot revision、journal 连续性、内容 hash、active node 和 blocker 引用。缺段、重复冲突、未知 handler 或 hash 不一致进入 `paused_fault`，不猜测修复。
7. 对每个可能提交点做中断恢复验证：已写 receipt 的 handler 不重跑，未提交的外层命令不出现，已回答 interaction 不重复消费。
8. 修改调用关系后清理完整 GameState 下发和客户端规则执行残留；仍需要的单机适配器必须明确只消费 view。

## 测试精简要求

- 使用 viewer 角色表覆盖 Host、目标玩家、非目标玩家和观战者，不为每种 DTO 字段复制测试。
- 用序列化快照对比验证隐藏字段不存在，并保留少量恶意 payload/陈旧 revision 测试。
- 合并 NetworkDispatcher、Multiplayer 和 Presenter 中重复的广播/权限断言；Domain 权限规则只保留一份权威矩阵。
- 恢复采用 checkpoint 场景源统一枚举 commit 点，避免每个 Effect 手写一组近似用例。

## 非目标

- 不实现客户端预测或离线客户端权威执行。
- 不自动修复 `paused_fault`，只需提供可诊断信息和安全停机。
- 不批量迁移具体卡牌内容。

## 验收标准

- 所有客户端入口只收到对应 viewer 的 view；非目标玩家的序列化 payload 中不存在隐藏值或可反推 ID。
- snapshot + journal 可在各 checkpoint 恢复为同一权威状态，receipt/interaction 不重放。
- 损坏或版本不一致数据 fail-stop，Host 不继续主链。
- 完整 GameState 下发和客户端规则推进路径被移除或有明确受限理由。
- 相关及完整 EditMode 通过，`git diff --check` 通过。

## 交付报告

附可见性矩阵、网络 DTO 变化、恢复算法和 checkpoint 结果；列出删除的泄漏/双执行入口、仍存兼容层及测试净变化。

# NMC-002：Lua 运行时选型验证

## 任务提示词

你负责为 Unity 2022.3 LTS 项目选择并验证 Lua 运行时。目标是给后续实现一个可落地、可沙箱、可在目标构建后端工作的结论，不是只写候选库优缺点。先完整阅读 `prompt/00-共同执行约束.md` 与两份 Lua 权威设计文档。

## 前置任务

无。本任务可与 `NMC-001` 并行。

## 目标

1. 比较适合本项目的 Lua 运行时，形成 `docs/设计/Lua运行时选型ADR.md`。
2. 对推荐方案做最小接入验证：C# 传入只读调用上下文，Lua 返回可归一化的 EffectSpec 数据，不直接修改 `GameState`。
3. 验证程序集边界、沙箱、确定性、版本/内容哈希、AOT/IL2CPP 可行性和故障限制。

## 调研与验证要求

1. 基于候选库的官方仓库、官方文档、许可证和发布记录核实结论，至少比较：
   - Unity 2022.3 与当前 .NET profile 的兼容性；
   - Windows Editor 与项目目标构建后端，特别是 IL2CPP/AOT；
   - 原生插件需求、平台覆盖、维护状态、许可证和包体影响；
   - 沙箱能力、宿主对象暴露方式、执行取消或指令限制；
   - 调试、错误栈、热加载与内容版本管理能力。
2. 运行时程序集必须位于 Infrastructure/Adapter 层，不能让 `YC.Domain` 或 `YC.Application` 引用 Lua 库或 UnityEngine。
3. 最小 spike 只暴露确定性的只读 DTO/门面；禁止文件、网络、系统时间、随机源、进程、反射和任意 CLR 类型访问。随机数如需验证，必须由 Host 注入带状态的确定性服务。
4. Lua 返回值先转为受限中间 DTO，再由 C# 校验/编译；验证未知字段、错误类型、越界数值、递归/超深表、超量返回和脚本异常均能受控失败。
5. 给出执行预算方案：至少说明指令/时间/内存或等价限制如何实现。若所选库无法强制限制，必须在 ADR 中登记风险和补偿措施，不能假装已解决。
6. 定义脚本内容版本与哈希策略，说明快照/日志只保存哪些稳定标识，恢复时如何拒绝版本不一致。
7. 实际运行 Editor 测试；若项目已有可用构建配置，再做最小 IL2CPP/AOT smoke。不能完成构建时，要明确缺失条件和验证证据。

## 测试精简要求

- 使用数据驱动方式覆盖有效返回、非法类型、越界、禁止 API、异常、预算耗尽和版本不一致，不要为每个 Lua API 各建一个独立测试类。
- 运行时适配测试只验证边界合同；Effect 树业务语义留给 `NMC-004`，具体内容脚本留给后续纵向切片。
- 报告新增发现用例数；新增数量应与覆盖的失效类别相称。

## 非目标

- 不迁移角色牌、事件牌、城市样式或设施内容。
- 不实现完整 EffectExecutor、Interaction 或联网恢复。
- 不把 spike 直接变成可写 `GameState` 的脚本桥。

## 验收标准

- ADR 明确记录选择、拒绝项、许可证、支持平台、已验证证据、尚存风险和回退条件。
- 推荐运行时可在指定 Unity Editor 中执行最小脚本并返回经校验的 EffectSpec-like DTO。
- Lua 无法取得可写领域对象，也无法调用被禁止的宿主能力。
- 运行时依赖没有进入 Domain/Application asmdef。
- 相关 EditMode 通过，`git diff --check` 通过。

## 交付报告

报告推荐方案与版本、包接入方式、验证过的平台/后端、沙箱边界、预算机制、测试数字和仍需用户决定的许可证或部署风险。若没有候选满足底线，停止引入依赖并给出阻塞结论。

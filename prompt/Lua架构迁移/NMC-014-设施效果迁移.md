# NMC-014：设施效果迁移

## 任务提示词

你负责把设施入场及持续/触发效果迁移到版本化 Lua handler、通用 Event/Effect/Interaction，并移除设施 ID 特判、专用 pending 与重复表现层协调。迁移应优先复用此前已有合同，而不是为设施复制一套执行器。

## 前置任务

`NMC-006`、`NMC-007`、`NMC-011`、`NMC-012` 已完成。若设施依赖 `NMC-013` 的特殊行动能力，也必须先验收该任务。

## 目标

1. 定义设施内容注册、实例身份、脚本版本和入场/离场/响应订阅合同。
2. 将设施入场效果、候选选择、资源/影响力/移动等组合接入通用树。
3. 把设施私有状态归一化为可序列化数据并纳入可见性投影。
4. 当全部调用方迁移后移除设施专用 pending、effect service 和 ID 路由。

## 实施要求

1. 盘点全部设施并按行为族分类：无效果、即时状态变化、目标选择、资源交换、影响力组合、移动/探索关联、持续订阅、一次性/次数状态。
2. 设施实例使用稳定 `contentInstanceId`，Lua handler 通过注册和事件目标定位；C# 不根据 facility ID 选择规则实现。
3. 入场状态提交与入场 Event/响应顺序必须显式。业务子 Effect 失败是否影响 owning 节点，由设施合同明确处理，不能依赖异常传播。
4. 所有选择复用 Interaction/Candidate；影响力复用 `NMC-011`；移动/探索复用 `NMC-012`；资源/标记等若尚无 Effect，先定义小而通用的白名单合同。
5. 设施的计数、使用次数或脚本私有状态使用受限归一化 DTO，设置 schema/version/上限。不能持久化 Lua table 或字典形态的任意对象。
6. 明确每类设施信息对 owner、其他玩家和观战者的可见性，沿用 `NMC-009` 投影；日志不得泄露私有候选或隐藏内容。
7. 按行为族逐批迁移并立即切断旧入口。全量完成后核对并逐项清理 `FacilityEntryEffectService`、设施 pending、专用 answer command/router/presenter 及陈旧测试。

## 测试精简要求

- 用一份设施 catalog/schema 测试覆盖脚本、版本、订阅、静态参数和资源引用完整性。
- 规则测试按行为族/通用 Effect 组合参数化，只给真正独特的设施分支增加专项用例。
- 合并现有 Facility/FacilityEntry/Presenter/EditorAsset 中逐设施重复的构造、资源存在和选择提交测试。
- 保留入场顺序、持续订阅幂等、私有状态恢复与可见性专项测试。

## 非目标

- 不改变设施规则文本或美术资源。
- 不在 Lua 开放任意 GameState 写入或直接 UI 调用。
- 不保留设施旧服务作为脚本失败 fallback。

## 验收标准

- 所有现有设施已进入 catalog 并按行为族由新架构唯一执行。
- 入场/持续效果、交互、实例状态、恢复与投影符合合同。
- C# 无设施 ID 规则特判，已无调用方的旧 pending/service/router/test 被逐项清理。
- 完整 EditMode 通过，用例未按设施数量线性膨胀，`git diff --check` 通过。

## 交付报告

提供设施迁移矩阵、行为族/通用 Effect 对照、实例状态 schema、隐私规则、删除清单、未决项和测试净变化。

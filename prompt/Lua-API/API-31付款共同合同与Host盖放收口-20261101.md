## 代码交付

原生v4费用及已归一化v1/v3库存子集按同一explicit selector、真实源/目标、unordered、token profile及精确费用数量预检。有限旧输入先纯归一化，不把规范v4逆投影成旧语法；原参数记录只核一致性，不再作为另一套报价请求。普通移动的跨玩家开放保持，支付专用来源/许可、本人库存和数量规则继续独立核验。select/top、地图/轨道及其它非库存形状不能作为这里的费用子集，不创建选择或事件来猜报价。

资源替代的TryItemArguments现在直接创建规范v4。实际原供应按实例解析，数量/选择与来源规则不变；联合资源/多来源物品仍在一份工作副本中预演并一次提交。付款内部ItemTransferBatchRequest.ProtocolVersion=3及完整私有批次收据继续保留，它们复用与共同v4相同的Apply原语，属于付款联合事务，不是已退役公开MoveItem v3节点或旧保存通行证。不能为了形式统一拆成可部分成功的扣物品子树。没有调用者的旧v3等待意向检查已删除。

Host空参数盖牌准备也组织唯一共同main步骤；原本在CharacterCoverEffectExecutor内的独立选牌、回收、Cover调用、旧实体HandCardIds/DiscardCardIds赋值分支删除。内部准备只认Kernel实际创建的原始根ID、空来源、原轮次和列表创建索引，共同body绑定真实父任务及child身份；正常主链继续核验其主节点/调度组。公开Lua无版本盖牌及手工/嵌套直接v4借权仍拒绝，未新建公开“准备模式”。内部准备是隔离/Host能力，不计正常可见菜单流程。

Host准备没有主链coverIndex，按既有公开/私有事件默认0核验；正常主链的索引仍由MainCoverAuthority严格验证。事件由共同步骤拥有，完整收据与原有盖牌/回收/等待保持，准备父节点不记录第二份位置变化。

# API-38 分配页面与只读队列（2026-11-01）

对应计划4.15.3、6.15及[固定合同](API-36有序次数分配合同-20261030.md)。复用API-07已交付的共享出售数量页合同；API-07剩余正常对局覆盖仍保持部分，不据本轮组件验证替代。API-37后端保持apiVersion=1/执行定义1.0.0，当前core2.1.38。

## 实施范围

- 正式交互类型effect.effects.allocate及schema allocation_sequence_v1进入现有数量页的分配模式，优先于旧提示键或出售语义。每行解析原正式Text.Ref，显示当前次数与独立上限；同文不同ID独立。隐藏库存、单价、预计金券和出售资源身份图标。模式标题、按钮、进度、上限及草稿重置提示均来自EffectDialogLayoutProfile可序列化配置。
- EffectAllocationDraft以有序条目为唯一草稿，数量从队列重算。加号及直接输入的增量追加到右侧；减号或输入减量从右往左删除同ID最近条目，其余相对顺序及本地身份保持。非法/单项或总额超限输入恢复原有效值，不截断为另一份合法草稿；零上限行保留且禁止增加。普通刷新和同请求revision更新保留顺序，新请求/候选身份/玩家/局或内容变化同时清空数量与队列。重入后的空草稿显示初始化/重置提示，不猜顺序或自动提交。
- 分配展示复用当前实际场景引用下的SettlementEffectStripView、SettlementEffectChipView和原滚动容器。每次分配对应独立本地按钮；不进入真实SettlementEffectStripBinding或来源登记。显示态禁用指针使用、详情、长按、右键及键盘提交，拖动只可转交滚动、不改序。清理按本请求key，旧key不能清新请求；普通真实窗口刷新及清除不抹掉当前分配展示，清分配也不清其他真实来源。
- 普通确认须恰好分满，end_action仅在allowEndAction=true时按原队列提交，允许空队列。关闭/收起不提交，也不先结束回合。接受后草稿锁定，准确回执拒绝后允许用户显式再确认；接受回执先于新快照时也保持控件禁用。过期、重复或旧页面回调不能提交/串用下一请求，不自动重试答案。
- 补齐现有AnswerInteraction命令对四字段对象的必要运输：allocationSequenceV1专用编码只由当前正式类型/schema接收；重复/未知字段、错类型、混合旧答案拒绝。原expectedRevision、回答玩家、Host权威候选/来源校验及原子封存继续生效，其他schema不获得通用JSON入口。回答不增加主行动或先结束玩家回合。
- InteractionRequestProjector仅在正式分配类型/schema下以原候选ID保留自己的数量行，继续走原正式文案可见性投影；其他玩家仍无内容。真实付款、目标和必要响应继续由子效果原页面承担，林尚未改接本模式。

## 2. 当前代码核对

| 范围 | 核对结果 |
| --- | --- |
| 公开入口 | 当前 69 个 Effect／Flow 构造及装饰入口均在重写后的 Lua API 文档中覆盖；该数字不包含 GameData、Global 等查询方法 |
| 普通文字条目 | 在当前 Presentation／Editor 的 C#、prefab、unity 文件中检索 `Option Row Template`、`optionRowTemplate`、`executionRowTemplate`、`HasCardArtwork`、`CreateOptionRow` 均无匹配；不能借提示键恢复旧兜底页面 |
| 移动物品 | MoveItem v4 只执行明确目标；MoveFacilityCard v2／cycle_supply v4 与 ReturnCityStyleMarker v2 同样要求确定对象。旧选择输入不能继续作为当前编写方式 |
| 纯选择入口 | Choice.options、Choice.amountRange、SelectFacilityPanel 单列；说明页面语义、输入、结果与续接。逻辑 branches、次数分配及 Flow 仍按实际业务合同说明 |
| 结果判断 | 区分外层完成与业务成功；尤其注明条件未满足、无变化、未执行，以及 AllocateEffects 的 stopped_on_failure |
| Lua memory | 按同局同 Lua 入口共享，跨发动保留；不自动按卡／玩家分开，显式返回整份覆盖，进入存档 |
| 事件 | 按允许订阅、实际生产和响应分发分别核对；补齐完成续接、来源资格、payload、批次、候选及查询合同 |

一个需要保留的实现边界：`CharacterEffectCompleted` 在订阅白名单中，但当前角色生产者以 `ResponseKind.None` 发出，EffectKernel 对 None 直接跳过响应分发。当前正式 core Lua／JSON 未发现该名称消费者。新 Event 文档已明确此限制，不能据白名单名称承诺会执行 Lua。需要完成续接时按 `EffectCompleted` 的实际绑定合同使用；本次未修改事件生产行为。

# API-31 旧批次输入有限归一化为v4（2026-11-01）

对应计划4.13.1、4.13.4/API-31与API-29有限旧输入表；版本/恢复对应API-04，证据/文档/目录对应API-01/05/06/33。当前core2.1.45/MoveItem4.12.0：旧v2设施批次可表达子集已接入既有v1输入归一化路径；逐腿实例/源/目标/数量/插入/profile及完整端点顺序期望保留，caller operationId仅存原参数记录，实际收据身份由Host生成。40个不同全名最近通过；旧v1/v2节点/待执行规格及旧v4执行4.11恢复拒绝。API-31仍部分、API-32未完成，原7未关闭/6明确替代及正常验收缺口保持。39项仍32完成、6部分、1未完成。

## 实际交付

旧MoveItem v2设施批次先按原结构检查，再将各腿itemRefs映射为v4 transfer_batch的explicit selector。真实实例、源/目标、插入、profile、requiredCount和carrierPolicy保留，expectedOrders的digest/orderRevision/expectedTopItemId保留。旧v2仍要求所有腿端点都被顺序期望覆盖；混入其它参数、重复实例、非设施profile、数量不符或超出128值/深度8等不表示形状在创建/编译时拒绝，不偷偷降低数量或省略顺序保护。

caller填写的operationId仅保存在有界原参数与原摘要，不成为共同执行/恢复权限或收据ID。相同caller ID的两次真实Host操作各有独立收据，完成后恢复不重复操作。规范节点和待执行描述始终v4，原参数/规范摘要沿Lua顶层/嵌套、C#根/子/持久化描述以及克隆和恢复复验；结果使用当前v4摘要/真实收据及分页，不保留旧v2结果投影。

删除旧v2独立ExecuteBatch及其专用建设放行；普通/建设仍由当前共同v4和真实Host建设证明授权。关闭已失效的CanRestoreLegacy旧定义放行，清理无引用的旧类型检查类。保留仍被v3、付款或隔离准备使用的底层批次原语及共同角色生命周期，不按Batch或Execute子串删除真实能力。

## 空顶部与完整顺序

为承接旧v2合法的未指定顶部输入，执行定义4.12.0明确：expectedTopItemId为空表示没有额外顶部断言，不能跳过digest、orderRevision、绑定后完整顺序与真实来源复验；非空顶部仍须匹配共同有序区规则。要求目标区确实为空使用已有destination.mustBeEmpty。输入转换不读取当前牌序来填补未来顶部，也不替换调用者的原顺序期望。

相同语义用于提交前和共同收据恢复复验。测试证明空顶部在完整摘要/版本过期时仍零提交，保持顶部相同但底部新增真实牌也会拒绝；显式错误顶部仍拒绝。4.11的旧v4保存不按这项新语义解释，恢复前明确item_move_contract_version_unsupported，不改原件。公开字段合同仍item.move.v4.1，执行定义4.12.0/core2.1.45。

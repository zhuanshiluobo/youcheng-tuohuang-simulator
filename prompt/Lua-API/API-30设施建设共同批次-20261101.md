## 本轮实施

- MoveFacilityCard公开v2普通区域明确转移改为唯一共同v4 transfer；固定设施profile并复验实际类型，父无位置变化，三字段结果及零变化reasonCode=no_candidates从同一收据投影。v3供应组合参数和正常补槽/独立洗牌时机保持，当前设施执行定义统一4.0.0；旧无版本仍拒绝。
- 实体Build完成合法来源授权、付款/免付、取牌和选位后，落位组织公开MoveItem v4 transfer_batch。空槽为真实暂存牌进入已选格一段；覆盖为原顶牌top入本格覆盖层，再暂存新牌unordered进入格位两段。共同预演/提交替代旧v2 placement批次，没有删掉其它仍在使用的旧批次能力。
- FacilityPlacementProofV1只由Host根据真实父Build、实际孩子成员、已付款/已授权标志、原来源/内容身份、选位/层序和参数摘要生成。规划及提交复验原格，普通根或复制真实Build ID/参数不能免费入城、任意换层或取走城市牌。移牌不代替费用/来源/叠建查询规则，提交前变化失败不换实例，已付费及已取牌仍按原故障边界保留，不整组回滚整个Build。
- 共同事实正确记录设施进入城市/覆盖层后的真实控制者；原归属保留。expectedOrders同时支持实际有序区和无序区，无序revision=0/top为空且digest按真实成员；提交查当前前态，恢复按收据OrdersBefore复验，不要求后来区域保持原状态。
- Build评分和恢复从实际共同完成收据/证明读取，旧transferBatchReceipt不再作为本次建设评分依据。付款/评分、来源必做响应、原入场和完成等待保持，不重复落位、评分或发FacilityPlaced。类型化共同计划新增严格可空FacilityPlacement字段；raw缺字段、错布尔型、证明/期望摘要篡改拒绝，不扩大NormalizedValue预算。

当前core2.1.36、MoveItem4.10.0、设施专用4.0.0、Build2.1.0（公开Build仍v3、设施仍v2/v3）。旧Build2.0.0、设施3.0.0及MoveItem4.9.0执行定义在runtime/pending、snapshot/journal拒绝，原件不补写或升级。没有UI、静态文案/素材、场景/预制体或生成器改动。

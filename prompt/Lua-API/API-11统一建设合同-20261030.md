# API-11 统一 Build 合同 v3

2026-11-01 实施更新：公开v3字段和正常选择/费用/响应合同保持，Build执行定义2.1.0、MoveItem4.10.0；实际授权落位改共同批次，旧执行定义不升级，见[设施建设阶段](API-30设施建设共同批次-20261101.md)。
对应升级计划第 4.5.1～4.5.4、6.5 节及 API-11。本合同已实现；双模式、付款归属、取消重选、行动预算、原始恢复字段、结果篡改和必做响应／入场共 20 项隔离验证通过。API-12 承担正式调用／内部生产者迁移，API-13 承担旧 ChooseBuild 退役。

| 字段 | 合同 |
| --- | --- |
| apiVersion／targetMode | 必须为整数 3 及 select／explicit，互斥且显式声明；缺设施不能自动变选择 |
| player | 必须为执行玩家字符串；Lua ctx.playerId 归一化为十进制玩家 ID，须与节点玩家一致 |
| sourceKind | 必须为 supply／deck／reserve／authorized；不接受 sourceZone 第二套名称 |
| paymentMode | 必须为 auto／resources／gold／free；reserve 保留既有备用来源和真实资格复验，当前正式调用仅延伸枢纽，不因此扩大授权 |
| consumeMainAction | 必须明确布尔值；正常主要行动一次，原额外建设／塔／延伸枢纽为 false；reserve 必须 false |
| sourceKey／expectedSourceZoneId | 授权来源必须 sourceKey；其他来源禁止非空 sourceKey。可冻结实际来源区域，仍须实时授权复验 |
| facilityId／cityBoardSlotIndex | explicit 必须指定真实设施实例 ID；位置可省略或 -1，已指定须在 0～8；由 Build 冻结实际位置／叠建观察并在付款后复验，不能外传内部付款或观察证明；select 不接受这两个字段 |
| effectId／includeStoredFacilities／excludeRainbow／maxGoldVoucherCost | 选择过滤；includeStoredFacilities 仅 supply 可用，默认 true；费用上限为 0～Int32.MaxValue 整数并按卡面金券标价。explicit 只支持同义费用上限，不接受其余选择过滤 |
| allowDecline | 选择模式默认 false，只适用于选牌／付款确认前；准备取消回到原候选，确认支付后不可放弃。explicit 首版须 false，原可选直接正文继续由既有外层 Condition 承担 |

同一次选择式 Build 节点拥有候选、准备记录、取消重选、实际建设及完成续接，实际放置继续由同类型的显式子式使用既有建设执行链；不会构造旧 choose_build。显式模式跳过选牌并进入同一实际建设链。免费仍复验来源和位置，授权／备用来源不变，未知字段、别名混用、无版本新字段及不支持组合进入前拒绝。

完成结果统一为 outcome、builtItemId、definitionId、buildEffectId；仅实际建设及必要入场／叠建响应完结后 outcome=built。取消和无候选分别为 player_declined／no_legal_target，实例／定义／建设 ID 为空，不能冒充建成。显式构建的 buildEffectId 为自己，选择模式为实际建设子式；建设事实、付款、补供应、计分与来源响应仍绑定该实际子式，外层完成续接只发生一次。

规范化参数和控制字段在创建／保存／恢复时复验；新节点记录 facility.build.v3.1 参数来源摘要，原始字段缺失不能用 DTO 默认值补造。已付款／已取牌／已补供应／已叠建／已计分／待入场仍走现有事实和观察协议，不重扣费、不换同名牌、不吞故障。原合法直接 Build 及其 2.0.0 执行登记保留，新合同不借此封禁未受影响的旧显式调用。旧 choose_build 在 API-13 明确拒绝，不静默改写真实旧归档。

复用原选牌、支付准备／确认和位置／叠建消费者；只调整正式请求归属与语义识别，不增加页面或确认、重建或覆盖场景／预制体、修改坐标／样式／静态文案。当前工作为隔离规则验证，正常可见程序及联机另属 API-06。

验证原 XML：`Logs/LuaApiUpgrade/API-11/双模式叠建与完整归属复验/editmode-20261030_144352.xml`（20/20，59.20 秒）。实际输入为人工准备候选的隔离夹具，不计正常 GameId、可见程序、页面视觉或联机覆盖。此前失败与无 XML 的编译启动全部保留，详见实施记录。

API-13 补充：首次执行前，调度器真实提交的 Created／Ready／Running 都支持恢复；此时必须没有进度、结果、嵌套、子式或任何本节点交互。带进度却缺协议仍拒绝，不能用未开始状态重建曾经执行的建设。选择根的完成结果只负责统一续接，建成事件事实与按 Build 类型订阅的来源只消费实际建设一次。

# API-14 统一探索合同 v3

对应[升级计划](Lua-API升级计划-20261029.md)第 4.6.1～4.6.4、6.6 节和 API-14。统一合同及 29 项针对性隔离验证已通过；后续三处正式、正常／赠送命令与即时工厂已在 [API-15](API-15正式探索迁移对照-20261030.md) 迁移，旧入口已在 [API-16](API-16探索选择入口退役验证-20261030.md) 退役。扩展回归中的无效旧开始／采集夹具单独追踪，正常独立程序／多局／联机未验收。

## 公开参数

`Effect.Explore` 使用既有 `effect.exploration.resolve` 类型，公开声明要求 `apiVersion=3`。不新增公开节点类型；执行登记仍为 1.0.0，新合同与内容身份指纹为 `exploration.v3.1`。参数如下：

| 字段 | 合同 |
| --- | --- |
| apiVersion | 必填整数 3；不接受其他版本、浮点、字符串或整数回绕 |
| targetMode | 必填 select 或 explicit |
| player | 必填执行玩家，Lua 使用 ctx.playerId；归一化为当前执行者的十进制 ID，不能以另一玩家身份执行 |
| consumeMainAction | 必填布尔；true 沿正常探索资格并在结算后消费一次，false 沿原赠送探索资格且不消费；二者都按真实路线计算路费 |
| targetLocationId | select 可省略以使用当前合法范围，也可指定单个地点作为范围上限；explicit 必填。它不授权不合法目标，不自动换目标 |
| routeIds | explicit 必填去重字符串数组；只表达已确认路线意图。select 禁用；空数组仍须通过真实连通与免费路线规则 |
| recipients | explicit 必填数组，每项仅含 routeId、subject；subject 使用原选路主体键 bank／player:ID。每条路线至多一项，不接受金额；select 禁用 |

未知字段、混合模式和伪造的封存、会话、承诺、付款协议或托管收据均拒绝。客户端不能提供费用、奖励、付款成功证明或影响力资格。公开 Lua 与手写 Lua 规格按同一合同编译；旧的缺目标／缺计划声明不能开启任意探索。仍合法的内部原预付记录、现有封存选择结算记录按原支持边界继续恢复，不把它们开放给 DIY 伪造。

## 选择与结算归属

select 由统一 Explore 根拥有整次流程，内部直接创建现有 `effect.route_resource.select`，地图请求由该内部节点拥有；不创建 `effect.exploration.choose`。根严格绑定该子节点的执行者、来源、目标上限和行动政策。普通／额外采集继续使用同一选路服务，规则不因 Explore 合并改变。

explicit 跳过地图草稿，使用与正常命令相同的 Host 预选复验与封存方法。统一根拥有该选择会话，实际结算子节点引用该根的会话与承诺；不信任脚本自行填写的选择 ID。缺失、过期或非法计划失败，不退回任意选择。

选择及确认前仅编辑现有草稿，取消不扣费、不翻事件牌、不消耗行动。最终确认由 Host 按当前地图、资格、连通、收费和接收者复验；既有过期答案处理继续拒绝或重新等待，不改价、不换目标。顺序固定为：封存 → 预留路费 → 探索事件及全部必要响应 → 交付路费 → 按合同消费行动 → 外层完成一次。事件故障保留托管与原故障，不自动退款或提前成功。

## 结果与恢复

| outcome | 含义 |
| --- | --- |
| completed | 实际结算及全部必要响应已完成，路费收据已交付；targetLocationId、explorationEffectId、tollSettlementReceiptId 指向真实结算 |
| cancelled | select 在最终确认前取消；三个实际结算字段为空，不计实际完成 |
| no_legal_target | select 首次开启时无合法候选；三个实际结算字段为空，保留原可选包装的非失败续接 |
| failed | 已确定方案或内部流程失败；节点保持 Failed／Faulted 及真实原因，不能伪装 Completed。真实事件故障时外层可仍等待受故障阻断的必要子链，不强行生成终态 |

结果另含 failureCode。正常成功与取消／无目标的 failureCode 为空；实际失败按原内核失败状态处理，不吞掉响应故障。

新根保存 `exploreContractProtocolVersion=1` 及绑定效果 ID、玩家、来源与公开参数的摘要。首次执行前仅支持真实调度产生的 Created／Ready／Running 空进度状态；不能在缺协议时隐藏选择、请求、子节点或结果。选择会话、封存承诺、结算消费者、托管收据及完成结果分别复验，不能剥离模式后解释成旧结算节点。原始快照／journal 的字段先于 DTO 缺省值校验，不改写原件。

验证覆盖选择待答、封存但未预留、已预留待事件／响应、交付完成和故障保留；具体通过及失败以原始 XML 为准。正常菜单、独立程序、多局、视觉和联机证据仍按 API-06／6.6 另行积累。

原始验证：`Logs/LuaApiUpgrade/API-14/探索归属全阶段与真实候选复验/editmode-20261030_173223.xml` 为 29／29，52.83 秒。此前无 XML 的编译失败、26 项中的 16 项失败及最后 1 项失败均保留，29 项批次包含这些同名复验。原选路／托管隔离夹具保留工厂 GameId 以符合随机账本绑定，不放宽生产随机或 Host 校验。

API-16 的实际完成观察进一步区分统一流程根与真实结算：全局 completedEffectTypes 的探索观察只匹配实际结算，根的绑定续接仍发生一次；取消／无目标不触发实际探索观察，相关 7 项补充回归通过。

# API-44坎诺特累计台账漏项更正（2026-11-03）

本次处理新P2“累计台账漏项”，对应API-44、4.16.7、6.17及第7节交付记录完整性。补收坎诺特阶段六份原XML、39个不同全名与13个曾失败全名。累计XML **281→287**、曾失败全名 **551→564**；按全部已收XML的UTC合并，39个用例最近结果均通过，累计未关闭 **0**、历史明确替代 **24**保持。没有执行新测试或修改游戏实现，任务进度仍为40／44。

## 漏项原因与来源修正

API-41基线汇总脚本原先固定读取“API-41极境最少资源真实分支”的旧累计快照，跳过了后续坎诺特快照；后续派生台账又沿该错误起点接续。因此坎诺特自己的阶段报告虽然完整记录六批／39项／13个曾失败全名，现行累计记录却既没有六份XML，也没有13项失败历史。

已将源脚本的本阶段父快照改为坎诺特累计检查点，并增加六份XML摘要、39项阶段终态及13个失败全名的来源完整性检查。新增--output参数，可在新目录重建派生结果而不覆盖旧检查点；读入的原XML、日志及回调路径仍指向原始目录。

修正源脚本实际重建后，API-41当时的累计为283份XML／558个曾失败全名，原13项仍闭环；这与后来两个API-44阶段带来的四份XML、六个新增失败全名分层核对后，当前累计为287／564。该重建只是重新整理已有原件，没有重跑186项，也不回填旧派生文件。

当前唯一后续累计起点由[累计失败台账索引](../../Logs/LuaApiUpgrade/累计失败台账索引.json)指定。后续汇总先验证索引摘要和必收阶段，再合并结果并同步索引；此前缺项的旧派生快照保留为更正前历史，不再作为新的累计起点。

# API-25 玩家标记 v4 与当前权限合同

对应[计划](Lua-API升级计划-20261029.md)4.11.1～4.11.4、6.11，承接[API-29 共同合同](API-29共同区域物品合同-20261030.md)。本记录是 API-25 续作；旧阶段的 249 项结果仍保留于[第一阶段记录](API-25轨道状态基础与零标记处理-20261030.md)，不冒充本阶段通过。

## 当前实现范围

MoveItem 执行定义为 4.1.0，新增 apiVersion=4／item.move.v4.1 的显式玩家标记子集。当前接受 transfer 与 transfer_batch；每段使用 explicit selector、真实实例列表与 expectedSource，可指定源 slotId。destination 为真实 zoneId 或 original_supply，insertion 为 kind=unordered 或 kind=slot＋slotId，operationProfileId 固定 core.player_marker_storage，carrierPolicy 只允许 preserve，requiredCount 为0～99且不超过所选实例数。整组仍受128值／深度8限制，批次要求 expectedOrders=[]。未实现的类型、选择、取顶、地图、盖放及非空有序牌堆期望明确拒绝，不静默忽略字段。

普通标记移动支持其他玩家供应、卡上存放区、企业／宣告轨道，以及合法库存和真实效果暂存区。执行者保持实际上下文，物品原所有者／控制者不被改写；卡上类型／容量、轨道玩家、源格位、原供应归属、真实 custody 与暂存根继续验证。地图影响力须执行实际离场协议，积分轨道须保持派生计分；本子集不以库存移动越过这些规则。

Host 先用独立步骤封存实际实例、源格位、原供应及参数摘要，再进入真实依赖等待和提交。提交前再次复验。每段分别核足量，整组预演最终位置、容量和逻辑域互斥后一次发布；调换不因暂时占位而半提交。物理同格／同区无变化不计移动，requiredCount=1时不能冒充足量成功。

完整类型化 TransferReceiptV4 保存所选原事实、位置变化、区域成员及修订、轨道当前成员变化、实际结果及必要载体离场意向；归一化结果只返回 outcome、changed、movedCount、movedItemIds、receiptId、reasonCode，单枚另有 originalOwner=pN。完整收据不塞入128值结果，也不截断。API-30 的授权收据分页、其他类型策略及旧输入最终归一化尚未交付。

卡上最后一枚离开时，按实际载体配置执行必要等待及真实控制者的角色离场；父移动仍保留原执行者。恢复核对原收据、自动子步骤及原结果，不重新移动或重复发收益。原始缺失收据字段不能靠构造器默认值恢复为有效事实。

## 初始化凭证与当前成员

UsageTracks.Version=2.0.0。UsageTrackBinding 的 MarkerItemId／ZoneId保留初始化凭证；当前成员统一由 CurrentMarker 查询真实逻辑区域取得，UsageTrackView 分别暴露当前 MarkerItemId、ZoneId、SlotId。移动不覆盖旧初始化收据、宣告 InfluenceMarkerId、已用设施或本回合 UsageGroupReceipt。

第一条宣告区与对应 usage 区共享当前权限域。移出后无当前成员，权限失效；换实例或换同域承载区后按新成员发动／复位。重复宣告的历史计分记录独立，不能用另一条记录恢复第一权限域。正常返还、特殊行动候选与实际标记、清理事实、联机投影及旧 UI 只读适配均改读当前成员；已有静态文案和资产保持原来源。

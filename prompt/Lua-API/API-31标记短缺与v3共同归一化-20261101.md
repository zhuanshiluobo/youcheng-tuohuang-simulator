# API-31 标记短缺与v3共同归一化（2026-11-01）

对应主计划4.2.3/4.2.4、4.11、4.13.1/4.13.4/API-31，合同与版本为API-29/04，测试/文档/目录为API-01/05/06/33。当前core2.1.46/MoveItem4.13.0/合同item.move.v4.2：新v1/v2/v3有限输入统一生成v4节点并记录原参数与两摘要，公开旧v3独立执行移除；显式最低数量独立于实例数，空/不足为真实Failed叶且不补选、不降低数量。Condition和AbilityAction入口费核真实共同收据，混合原主/共享原供应保持。134个不同全名最近通过；原7未关闭/11明确替代，API-31仍部分、API-32未完成。39项仍32完成、6部分、1未完成。本轮不把一个消费者组的迁移当作API-31整体完成。

## 本轮代码

有限旧v3输入按真实itemIds、expectedSource、逐实例original_supply或明确目标、insertion、profile及requiredCount转换为同一v4 transfer。Lua顶层/嵌套、C#创建、子节点和持久化描述沿已有纯映射统一处理；原参数有界保存、原参数摘要/规范摘要恢复复验。旧v3执行分支ExecuteTokens删除，不复活旧token批次权限。内部付款/准备仍使用的底层v3原语暂留，不冒称已全部迁移。

正式内容的6个Lua文件/9个v3 MoveItem调用保留允许的输入语法；实际编译、运行及新保存均为v4.2，并不是把这些Lua字面量改成4。Lin旧源码摘要等既有冻结依据保留。当前执行版本4.13.0和core2.1.46明确拒绝旧v4执行版本、旧v1/v2/v3已保存节点与待执行规格；不升级原始存档，不热换运行内容。

Condition及AbilityAction入口费现在识别共同transfer/transfer_batch的token profile，核真实v4计划/完整收据、实际位置变化、实例与最低数量。Completed、伪造结果或缺收据不能充当付款；盖放/地图等非库存操作不进入该判定。混合玩家方块/公司方块按各自原供应原子归还，共享储备不强制等同玩家私有供应；原主/原供应仍保留，私有供应错归仍拒绝。普通库存请求从地图取走token时先按真实源区拒绝，不能因原供应缺失掩盖生命周期保护。

## 主计划优先的合同修正

主计划4.2.3要求每枚独立MoveItem requiredCount=1，4.2.4要求缺枚成为真实失败叶且不撤销已成功兄弟。后写的API-29/v4.1子合同却禁止explicit requiredCount大于itemIds长度，使合法短缺无法表达；本轮按主计划修正为v4.2。explicit最低数量为0..99，与显式实例数独立；缺枚/不足均Failed(insufficient_items)、整组零提交，不借其他供应实例补足，不降低requiredCount。select/top仍要求最低数量不超过selector.count。提交前及恢复均核数量，不允许短缺计划伪造成功。

旧v4.1的empty/count前置拒绝两用例在历史XML中确实有通过，但已不代表当前合同；保留原XML与历史结果，明确替代为当前真实Failed/零移动/不发收益验证。旧wrong_player负向断言与主计划4.11允许明确移动其他玩家标记冲突，改为新命名正向验证原主/原供应保持，并另验执行者错配仍失败；原负向失败不写成同名通过。另两个旧普通移动必须有carrier许可的负向测试与主计划4.11明示撤除门槛冲突，同样以新命名正向验证明确替代；支付专用预检仍检查原来源及许可，并只从已验证原输入记录读取原v3请求，不把旧门槛加回普通移动。系列明确替代6增至11，原7项未关闭不变。

## 原始验证与限制

原XML依次14/14、16/35、34/40、69/84、60/64、2/4、4/4；按全名去重后134项最近通过，另3个旧wrong_player/普通carrier门槛全名明确替代。首轮14项只覆盖新增短缺/归一化，过滤器误用了文件名并未匹配QY005实际类；随后按实际类执行。原始首次失败及复验均保留，记录真实数量，不把失败批次相加成一次全量通过。

保留整组原子性、混合原主/原供应、99真实实例、坏收据拒绝、历史收据重放不重复移动、Lua编译、Condition和入口费、真实Dorothy/T09等消费及恢复的业务断言；旧夹具的api3保存字段/版本/诊断按当前共同表示迁移。单纯原始Lua返回仍可为允许的v3输入，不能把原始返回当作已保存执行节点。

当次身份、冻结内容和输入快照按实际产物核验：原v3首轮的AgnesContentTests.QuickCommandCostRemainsTwo在XML为Passed，但当次case-result身份状态为Inconclusive，冲突原样保留，不能宣称身份一致通过；64项回归的MainCover_CommonBodyOwnsSelectionReceiptAndSinglePrivateEventAcrossRestore缺当次逐例身份记录。XML仍为134项最近通过的依据，两处身份限制分别列出，不回填原件。本轮全部属于隔离规则/正式消费者定位，不计正常可见独立程序的菜单/建房/开局、多局、视觉或联机验收；不改UI控制器、静态文案、场景、预制体或素材，不运行生成器。旧99请求上限实际42的原记录不回填，独立真实99证据分别保留。

## 本项能力及剩余任务的边界

按计划任务表，API-30负责可直接调用的共同区域物品能力；API-31负责专用名称、内部消费者和有限旧输入的归一化迁移；API-32负责迁移完成后的完整等价矩阵。前几轮阶段记录将后两项缺口一并列在API-30/31“部分”中；本轮以当前源码和实际用例逐项复核API-30验收条件，分别保留API-31/32缺口，没有删减合同或把静态审计当作运行通过。

## 本轮改动与原始结果

首批覆盖12个现有测试文件、70个方法的当前能力样本，原XML为160项中157通过、3失败。三项分页夹具仍按“全局只有一份共同收据”查找，正常准备接入共同步骤后出现多份，尚未进入其数量/权限断言。现改为从本次真实Lua续接的receiptId定位唯一业务收据，并复验对应能力和receipt_probe阶段；没有改成取第一份，也没有放宽原数量、严格99、权限、只读和恢复断言。

新增3项公开Lua/手写内核不洗牌负例，并复验原独立设施洗牌的0/1/9张真实实例与恢复合同。补充单批9/9通过，包含原三项分页同名后续通过。两份XML共166个不同全名最近通过，不能把它们相加为一次169项通过，也不能将首批160项写成全通过。原始失败XML/log保留，原8项未关闭及6项明确替代保持。

本次严格99用例仍实际移动/读取99项、13页（12×8＋3），实际记录见[本次99证据](../../Logs/LuaApiUpgrade/API-30共同能力交付复核/严格99本次实际记录.json)。原“上限99、实际42”的旧记录保持更正，不回填为当时完整99通过。分页协议探针使用私有冻结来源及必要配方/脚本覆写，属于隔离合同；其它夹具的安装内容/冻结副本身份按各自原件记载，不冒称正常游戏验收。

逐例证据存在明确限制：首批160项可关联149份当次逐例记录，其余11项仅保留原XML、批次输入和编译/启动记录，不补造其GameId或冻结身份；补充9项均有当次逐例记录。缺项全名见[身份覆盖核验](../../Logs/LuaApiUpgrade/API-30共同能力交付复核/逐例身份覆盖核验.json)，API-06仍部分完成。

## 已实施

1. Choice执行定义3.0.0。真实非空分支没有交互类型或仍用lua.choice时，Lua归一化与C#直接执行均走effect.choice.execute，并生成正式choiceIntent。显式设施卡牌等交互类型不覆盖；普通options及原amountRange合同保留。选中后实际子树、失败传播和必要等待保持。
2. 银灰策略明确使用逻辑分支页面，原每个资源＋玩家组合仍直接执行SellResource及得分。M05明确使用逻辑页面，原探索／两次有序Place和真实完成续接、原子蓝图交换不变。
3. 警备队辖区从“值→完成回调”改为两次独立真实分支：复合费用条件替换、放置＋碎片、移除＋异铁。保留两次选择、原费用和整行动轮角色锁，删除仅按字符串分派的完成处理器。
4. 防卫科四级从“值→完成回调”改为先支付12金券，再选含两个真实操作的有序分支；四个组合及放／移顺序、必要响应、库存和恢复不重放保持，删除纯值处理器。
5. 实际验证暴露复合费用在深层真实分支中被包装层计入返回表深度。PayResource.cost现按既有封闭费用DTO独立校验，执行器和Lua检查共用同一费用规则；不提高深度8／总值128等限制，普通同名对象和嵌套伪造费用仍拒绝。

当前core2.1.51；银灰定义1.0.3／策略1.1.0；马丁四份定义及全部同脚本绑定1.3.2；警备队辖区定义1.1.2／能力1.1.0；防卫科定义1.0.4／四级能力1.1.0。原移动合同保持，三个移动接口不新增选择。

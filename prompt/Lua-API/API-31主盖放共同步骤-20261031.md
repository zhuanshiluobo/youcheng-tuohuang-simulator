## 实施内容

- 正常主链仍创建原本人盖放任务，其唯一共同main子节点承接实际候选、请求、主槽、一次提交、收据及CharacterCardCovered。父节点投影原结果并等待完整必要响应；附加v3仍组织同一共同additional策略。
- main资格绑定真实主链节点、主节点运行ID、冻结玩家顺序、调度组、任务成员及规范稳定子身份。裸根、伪造来源/任务ID不能借用主链权限；main固定角色接受类型、不可复用、阻塞0及本人手牌。公共无版本CoverCharacterCard不能构造或手工/嵌套编译，原因normal_cover_host_task_only；Host主链工厂保留真实任务形状。
- 空手回收冻结实际弃牌ID，每步最多32张展开共同transfer，完整列表保存在MainCoverFlowV1；不扩大NormalizedValue预算或静默截断。每步等待真实子树，失败向上保留，完成后沿原候选页继续。已有覆盖牌则创建零变化收据，完成本人任务，不新增主盖放事件。
- 事件公开载荷保持hidden实例，Host载荷持真实实例。共同节点与收据绑定唯一主盖放事件，完整恢复核验规范参数、子身份、真实源/槽/事件及结果；冷恢复不重复回收/移动/发事件。旧4.6.0 MoveItem及2.0.0盖放保存不升级原件，节点、待执行规格和snapshot/journal均经既有严格版本门禁拒绝。
- 必要请求适配对应6.13：后端有效性、正常提交及主链恢复识别真正共同main所有者；生产UI只调整ProductionGameRoutePolicy对原character.cover.card的刷新归属判断。请求类型、现有提示及页面保持；没有生成器、静态文案、布局、场景/预制体或素材变更。

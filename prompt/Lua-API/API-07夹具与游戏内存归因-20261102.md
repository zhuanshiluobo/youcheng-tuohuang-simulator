## 指标与归因结论更正

16:38当前正常进程26856的工作集为4.602 GiB、私有提交量9.819 GiB。工作集是采样时驻留的物理页，私有提交量不能当作当前物理驻留内存；Mono保留堆也不能当作全部存活对象。此前9.275 GiB是另一已结束诊断进程55096的私有提交量，不是当前正常进程的工作集，不能用它回答“当前占用多少物理内存”。后续即时采样及口径更正见[更正记录](../../Logs/LuaApiUpgrade/内存归因对照-20261102/内存指标与归因结论更正.json)。

**撤回“高内存占用主要来自游戏自身”的因果结论。** A/B两组都是先带夹具完成读档，B才拆卸夹具；卸载后仍存在的大堆容量，可能包含卸载前产生的临时分配，不能据此判断其来源。86.35 MiB只是在当前静置、受控GC条件下与保留夹具相关的托管使用量差，不是夹具全部分配或峰值的上限。当前尚未完成“游戏自身还是夹具”的分配来源归因。原始数值、身份及对象回收检查保留；核验文件的passed仅表示所列检查成立，不表示该因果结论已获验证。

## 同档对照方法

两个独立开发程序使用同一二进制，首启前冻结到同一原core2.1.56的482份逐字内容。只从正常菜单、原存档列表及确认按钮读取同一正式档：GameId `abfa74ae4d2340ce8f30a5b60a381201`、revision11008、StepCount10071、1805个效果节点、15931条运行日志。原档SHA256为`ba05a5a49ef687cecbbbc09e4902768fe016279880b25e1c316974f9fd855605`；不替换状态、修改随机或执行后续游戏命令。见[冻结核验](../../Logs/LuaApiUpgrade/内存归因对照-20261102/同档对照冻结核验.json)。

A保留夹具；B将观察端口恢复为原端口、解除日志订阅、关闭夹具追加句柄、销毁独立夹具对象。两组均等待相同时间、执行相同受控GC并连续采样三次；B必须同时证明夹具组件消失、其托管弱引用失效。GC只用于这两个独立诊断进程，不能据此宣称真实运行中堆会立即收缩。

诊断包内Mono的Process内存计数返回0，该组原始字段不作为有效测量。有效托管／原生指标取Unity Profiler和GC计数；B另从外部PowerShell采集实际系统进程计数。若需要系统占用的严格A/B差值，应另补两组同阶段外部采样，不能拿A加载中的系统数值对比B静置值。

## 对照结果与结论

三个静置样本均保持原身份、revision11008、1805节点及15931日志条目。B组三个样本的夹具组件均不存在，托管弱引用均失效，确认没有夹具对象继续被强引用。两组后续游戏命令均为0。

| 有效指标（三次中位数） | A保留夹具 | B卸载夹具 |
| --- | --- | --- |
| 回收后托管使用量 | 0.803 GiB | 0.719 GiB |
| Mono保留堆 | 6.068 GiB | 7.836 GiB |
| Unity原生使用量 | 约0.111 GiB | 约0.111 GiB |

与保留夹具相关的托管存活量差约86.35 MiB，约占A组托管使用量的10.5%。B组卸载夹具后，外部系统采样的私有提交量仍为9.275 GiB、工作集约8.442 GiB。两组保留堆容量不同，不能用reserved或private直接相减求夹具大小；A缺少同阶段系统采样，不报告进程私有量A/B差值。

这次证据仅支持：B的驱动对象已被回收，A/B回收后的托管使用量相关差约86.35 MiB。B的回收前托管使用量约4.000 GiB，回收后约0.719 GiB，说明临时对象与堆容量必须区分。两组读档时均有夹具，不能把卸载后保留的堆归因于游戏自身，也不能据此排除夹具的临时分配或宣称已定位泄漏。

见[A原件](../../Logs/LuaApiUpgrade/内存归因对照-20261102/A-保留夹具/内存归因结果.json)、[B原件](../../Logs/LuaApiUpgrade/内存归因对照-20261102/B-移除夹具/内存归因结果.json)、[B外部进程采样](../../Logs/LuaApiUpgrade/内存归因对照-20261102/B-移除夹具/操作系统内存采样.jsonl)、[逐样本身份及回收核验](../../Logs/LuaApiUpgrade/内存归因对照-20261102/内存归因核验.json)。

结论仅覆盖读档后静置时的相关托管使用量差。长时间运行中截图、日志、决策查询等临时分配与操作内部耗时仍须独立测量；原长期运行进程私有提交量约9.8 GiB，并不代表当前物理驻留量或已完成分配来源拆分，不能将其映射到某个游戏子系统。CPU卡顿的内部调用耗时仍待定位，当前数据不足以认定卡顿来自游戏或夹具中的哪一部分。

采样完成后，两个诊断进程的Application.Quit被原存档离开确认拦截，因此核验执行路径后结束这两个只读诊断进程以释放资源；不计正常退出验收，正常进程26856未被停止。见[结束记录](../../Logs/LuaApiUpgrade/内存归因对照-20261102/只读诊断进程结束记录.json)。

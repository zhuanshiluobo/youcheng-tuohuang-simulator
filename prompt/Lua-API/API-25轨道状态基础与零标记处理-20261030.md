# API-25 轨道状态基础与零标记处理

本记录对应[计划](Lua-API升级计划-20261029.md)4.11.2、4.11.4、6.11，并承接 API-29 共同合同。API-25 为部分完成；API-26 及后续任务未因此标记完成。实现、隔离验证、正常游戏验收分别记录。

## 本阶段实现

| 计划条款 | 实际行为与边界 |
| --- | --- |
| 4.11.2.1、4.11.2.3～5 | ItemZoneQuery 共用 PlayerMarkerTrackPolicy：企业公开区中同一企业载体、同一标记所有者的所有 board_marker_track 合计至多一枚。更换等级格或新增承载子区不增加容量；不同企业、不同所有者独立。真实轨道 owner、格位和结构容量继续校验。零枚合法，不补发标记。 |
| 4.11.2.2 | 有 public_declaration UsageTrackDeclaration 时，实际载体的 CardZoneLocalId 区与 declaration_玩家_0 区归入该 trackId／所有者的同一权限域。declaration_玩家_1 等后续计分记录各自独立；其他独立轨道也保持各自域。此项是位置互斥基础，不代表已完成移动后的权限重建。 |
| 4.11.2、4.11.4 | 共用校验进入普通转移预览及 Host snapshot／恢复；重复标记拒绝，不静默顶替、归还、丢弃或修存档。另保留错供应、错轨道所有者的拒绝。 |
| 4.11.4 | 企业 GetCooperationMarker 对零枚返回空，GetLevel 返回 MissingCooperationLevel=-1；结构缺失、重复或错误类型／所有者仍为非法状态。候选不能用 levelDelta 将缺标记变成可用零级或特效。 |
| 4.11.4 | 明确升级缺标记时返回完成、无变化及 enterprise_cooperation_marker_missing；切部门不改关系或发奖励。范围选择按原冻结集合收窄。集体升级中缺标记玩家完成无变化，其他玩家正常结算。奖励响应中标记离开时，保留已经结算的奖励及到达收据，停止余下级数。恢复只在对应缺失原因下接受 -1，不全面放宽负等级。 |
| 4.11.4、6.11 显示要求 | GameplayExpansionUi 将实际公开轨道缺失值与可序列化 MissingCooperationMarker 文案配置送入同一企业投影。已有文字引用显示该配置，图形标记隐藏；详情使用同一缺失值与文案。只改必要动态数据，不改场景、预制体、布局、样式或已有静态文字。 |
| API-04、4.11.4 版本要求 | core 2.1.20；升级、内部改等级、切部门和集体升级执行定义 v2.marker_state。旧执行绑定不以同版本静默续接。未改正式 Lua 或增加公开 API／编译类型。 |

## 尚待实施

- MoveItem v4 的正式格位、同区及整组最终状态提交合同；公开选择、真实来源冻结、完整类型化收据与重复提交保护。
- 撤除普通玩家标记移动中的跨玩家、载物来源、旧执行器及轨道黑名单限制；支付、地图离场、真实依赖和生命周期保持业务校验。
- 宣告历史、初始凭证与当前实例／资格分离；移出失权，换实例／移回同步绑定，回合重置不拉回移出的标记。不得把当前仅有的位置互斥写成已完成此项。
- API-26 诗怀雅、林迁移、originalOwner 结果及旧 Store/Return 退役；API-27／28 指定目标玩家升级与后继迁移。
- 正常可见独立程序、菜单／建房／合法行动、多局、实际视觉和联机验收；本阶段的隔离轨道装配、预制体克隆及公开投影不计为这些验收。

## 验证与追踪

原始 XML、首次失败、同名复验、逐文件条款与前后字节 SHA、静态审阅和运行身份记录位于 `Logs/LuaApiUpgrade/API-25`。结果以封存后的原始证据为准。API-24 的 320 项通过仍属于旧阶段，不冒充本阶段通过。

旧 `MissingCooperationMarkerFailsInsteadOfReturningZero` 用例保留全名，但按本计划将“抛异常”迁移为“明确 -1／可处理无变化”，并修正隔离位置成员表；此处记录合同改变，不把旧断言声称仍通过。原有七项未闭环与两项明确替代关系继续保留。

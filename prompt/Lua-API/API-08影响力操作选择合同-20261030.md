# API-08 基础影响力操作选择合同

对应[升级计划](Lua-API升级计划-20261029.md)第 4.4、6.4 节及 API-08。本项实现与隔离验证已完成，通过记录见[实施记录](Lua-API升级实施记录-20261029.md)；正常独立程序画面和联机未覆盖，API-09 调用迁移及 API-10 旧入口退役仍未完成。

## 版本与模式

| 入口 | 显式目标合同 | 新交互选择合同 |
| --- | --- | --- |
| `RemoveInfluence` | 保留原单目标／目标列表合同；严格 `apiVersion=2, targets, requiredCount` 不变，缺 targets 不自动转选择 | `apiVersion=3, targetMode='select'` |
| `MoveInfluence` | 保留原指定影响力及指定／待选目的地合同 | `apiVersion=3, targetMode='select'` |
| `ReplaceInfluence` | 保留原指定目标、替换来源／所有者及 `keep_removal` 合同 | `apiVersion=3, targetMode='select'` |

v3 只提供明确的选择模式，不提供 `targetMode='explicit'`。新字段不能与旧显式目标字段混用；没有 targetMode 的 v3、没有版本的 targetMode、错误版本或错误类型都拒绝，不按缺键回落。旧合法显式调用不被迫增加选择页。

新模式由实际操作节点拥有请求和状态，内部调用原显式操作；不创建 `effect.influence.select_action`，不创建 Repeat、公开同义选择 API 或新重复节点。旧 SelectInfluence 暂时仍可执行，供 API-09 迁移前的正式内容使用；它与基础操作复用同一内部选择逻辑，API-10 再禁用其入口。

## 唯一参数表

下表之外的业务字段拒绝，公共完成处理器、WithContext、WithPresentation 仍按现有合同处理。公开字段不并存两种玩家／主体别名。

| 字段 | 类型／默认 | 含义及不适用组合 |
| --- | --- | --- |
| `apiVersion` | 必填整数 3 | 新选择版本 |
| `targetMode` | 必填字符串 `select` | 不通过遗漏显式目标推断 |
| `executingPlayer` | 必填玩家引用 | 规范化为真实玩家稳定引用，与实际执行节点及授权作用域一致 |
| `subjectFilter` | `self`／`player`／`opponent`／`any`，默认 `self` | 使用原主体判断；opponent 表示非本人主体，包含合法公司影响力，不将公司伪装为另一玩家 |
| `excludedSubjectKeys` | 唯一主体键数组，默认空 | `player:<正整数>` 或当前已支持的 `company:stonehoove_security`；候选和真正提交均检查 |
| `selectionScope` | `''`／`resource_points`／`routes`，默认空 | 约束原影响力所在范围；移动后每次重新生成合法候选，不要求移动终点属于原来源范围 |
| `candidateIds` | 唯一字符串数组，可为空 | 首版只支持严格移除一枚：remove、count=requiredCount=1、requireCompleteSelection=true；承接保罗的精确候选。其他组合明确拒绝，不默默忽略 |
| `distinctPolicy` | `none`／`instance`／`subject`，默认 `none` | 普通模式排除本流程已处理的实例／原主体；完整选择校验整个所选集合的主体唯一性。旧 owner 别名不在新合同中接受 |
| `count` | 整数 1～16，默认 1 | 本流程最多操作次数 |
| `requiredCount` | 整数 0～count，默认 0 | 普通模式完成所需的最低次数；它不自动赋予整组原子性 |
| `requireCompleteSelection` | 布尔值，默认 false | true 必须 requiredCount=count；先选齐目标。移动不支持该组合并明确拒绝 |
| `allowDecline` | 布尔值，默认 false | 沿原可选效果的开始确认／放弃合同；不新增执行一半后的停止按钮或统一确认弹窗 |
| `promptKey` | 字符串，默认当前操作的既有提示 | 作者提示不参与操作模式识别 |
| `nextPromptKey` | 字符串，默认沿用 promptKey | 普通逐次操作后续提示 |
| `interactionType` | 可选字符串 | remove／replace 保留作者请求类型并携带权威操作语义；move 仅接受空、lua.choice 或 character.ability.choice.move，统一走原完整移动候选路由，其他值拒绝 |

旧 `player`、`ownerFilter`、`distinctPolicy='owner'`、字符串范围 `candidateScope` 由 API-09 逐调用映射到新字段。原 Remove 的 candidateScope 仍表示显式目标列表，不改义；新选择不能同时带 targets、targetInfluence、targetSlotId、replacementOwner、replacementSource 等显式字段。选择替换继续使用原选择器的执行者所有权及来源默认值；有专门替换来源／所有者需求时使用原显式替换合同。

严格 Remove v2 仅接受已实现的目标、数量、执行者、reasonId、主体筛选及排除字段；destination／causeKind 在该版本未实现，明确拒绝，不再丢弃；reasonId 必须为字符串。原无版本单目标合同的已实现字段不受此限制。

参数类型、唯一性、主体键和数量边界在 Lua／编译／内核校验。手写 C# 规格还须令 PlayerId 及 AllowDecline 控制字段与参数一致，不能伪造执行者或绕过开始确认。既有 Lua、归一化值及内核预算不提高。

## 执行、筛选与结果

普通模式每次只提交一个真实操作，完成相关子树和必要响应后更新候选，再执行下一次。候选耗尽且已达到 requiredCount 时完成；不足则普通失败，保留已经发生的合法操作，不把普通模式改成整组付款。

严格移除选齐后只创建一个原严格 Remove v2 子式，由它对全部目标预演并原子提交。主体／排除条件直接保存在子式参数中，来源范围及主体去重在实际提交时从所属选择节点再核验。目标不足、重复、真实离场、位置／类型／主体／范围不符时，本批移除数为 0；不能先逐枚移除再检查总数。候选不足的主体去重也按不同主体数判断，不把同一玩家的两枚算作两个主体。

完整选择的 replace 只保证先选齐目标，随后仍逐项按原规则替换；没有整组替换回滚。每次替换等待原影响力离场响应，再尝试放置。放置失败保留实际移除及原 `removed_only` 事实；完整替换流程可以因此失败，不能伪造替换成功。

| 结果字段／状态 | 含义 |
| --- | --- |
| `completedCount` | 普通模式已完成的操作次数；严格成功为 count。它不是任意替换收益的成功数，实际替换结果仍查看对应子式 |
| `requestedCount` | 原 count |
| `actualRemovedCount` | 本流程实际直接操作子式产生的离场事实数；失败后已提交的事实也保留，不声称全链回滚 |
| `changed` | 是否实际发生变化；失败保留先前变化 |
| `operationEffectIds` | 成功终态中各次真实子式身份，顺序与执行相同 |
| `originalSubjectKeys` | 成功终态中来自实际子式的原主体事实，不从新所有者或卡牌 ID 猜测 |
| `removedInfluences` | 保留精确 candidateIds 严格移除一枚的原位置／离场身份事实，供既有保罗完成消费者迁移 |
| 失败 | 保留原 insufficient_items、incomplete_influence_payment、player_declined 及基础操作的实际原因；开始放弃仍沿通用门禁终止，不伪造业务收据 |

严格移除的原子性只到本批地图变更提交。离场托管、响应、后续 Condition 或整场流程都不自动回滚。实际条件不成立和真实 Faulted 分开处理；requiredOutcome 仍在内核原位置校验 completedCount 等已承担结果。

## 请求、UI 与恢复

新请求的正式操作语义优先于旧提示键和其他页面类型分支；请求发现、CanRender 和实际渲染都按同一语义识别，不只改提示标签。新请求携带 `interactionSemantic='influence_selection_v3'`、`selectionApiVersion=3`、`influenceOperation` 及真实 `ownerEffectTypeId`。remove／replace 由这些正式字段或相应基础目标类型进入原地图路由；提示键和卡牌身份不负责分流。move 继续使用原 move|实例|槽位完整候选及两步地图选择。

严格多选继续逐目标确认、选满提交；精确一枚沿原单目标协议。保留候选集／版本、请求修订、回答玩家、原权限、防重复和真实子式复验，不增加统一确认页，不改场景／预制体的结构、静态文案或样式。

选择状态使用 `influence.selection.v3.1` 协议，记录原参数／来源摘要、推进序号、已选实例、已处理原主体；事件观察者／完成响应保持自己的来源范围，不继承选择操作的筛选，也不算作已选操作次数；其挂接身份沿原派发收据核验。恢复核对正式已答请求、实际子式的目标与完整参数、控制字段、推进位置及结果。不能只检查 args 合法便接受伪造进度，也不能丢失外层筛选后续跑。

未提交地图草稿不扩展为权威答案。已接受答案、独立子式及必要响应按现有内核保存，冷恢复不重复操作。API-09 已完成正式消费者迁移；API-10 对旧 select_action 的公开、编译、执行和保存规格明确拒绝，原因 influence_selection_api_retired。合法显式目标仍保留原支持边界。

执行合同加入活动内容身份摘要，core 包升为 2.1.5。API-09 正式脚本与定义迁移时另按实际装配协调版本／哈希，不能拿本次宿主版本更新代替逐调用迁移证据。

基础操作的原 EffectRegistration.DefinitionVersion 仍为 `2.0.0`，不以统一升执行版本的方式封禁未受影响的显式目标合同；新增路径由 apiVersion=3、持久化 selectionProtocolVersion=1、influence.selection.v3.1 内容合同指纹和原参数／来源摘要共同识别。归档原始字段缺失不得依靠 DTO 默认值重建。

`kind`、`effectTypeId` 是规范化声明的内部元数据，不属于三类公开构造器的业务参数，调用者不得覆盖。合法原始 effect_spec 必须携带相符的元数据并通过同一参数／控制合同校验，不能由此绕过基础操作模式。

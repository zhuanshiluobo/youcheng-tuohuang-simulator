# API-19 共同角色牌移动与转交

对应[计划](Lua-API升级计划-20261029.md)4.8.1～4.8.3、4.13.1、6.8。基于API-29合同，先落地角色显式转移所需的共同策略，不把尚未实现的完整MoveItem v4写成已可用。当前公开形状继续使用MoveCharacterCard v2／直接MoveItem v1的明确实例、expectedSource、destination、insertion、core.character_card_transfer和requiredCount。

[CharacterCardMovement](../../Assets/YC/Domain/Cards/CharacterCardMovement.cs)是两个入口的共同执行策略，不调用旧TransferCharacterCard：复验真实类型、当前控制者、准确源区／格位和足量；等待原在途使用／载体离场依赖后，按既有政策在工作副本归还载物并校验完整目标，成功才一次提交。保留OwnerSubject，按目标手牌区更新ControllerSubject；不按卡名补选，也不以角色专用节点取得额外权限。普通卡牌／Token其他profile仍沿原路径；玩家标记开放轨道及完整v4留后续任务。

共同策略按实际MovedItemIds交付changed/movedCount/movedItemIds，实际跨玩家才发一次character.transferred；公开正文只有recipientPlayerId，HostOnly含itemId，移动根及其规格／结果为owner可见。旁观投影不能看到转交牌实例，接收者能看自己的真实手牌。同玩家移动、无变化或失败不发跨玩家转交；原权限失败继续使用transfer_permission_denied。

复用CharacterLifecycleService原载物退出预演，提取共同PrepareCardCarrierExit，方块返真实供应、设施牌回真实牌堆底，未知去向失败；不直接清空内容。盖牌槽、离场订阅／设施绑定和最后载物离场处理保持。原CharacterUse.ExecutingPlayerId不改写；FinishUse看实际新持有人和区域，不能再次收走已经转交的牌。必要事件响应未结清时根不提前完成；恢复后不重移、不重复返还或发事件。

版本为character_move.v2.1：MoveCharacterCard执行定义2.1.0，共同MoveItem执行定义3.1.0，core2.1.15；活动指纹包含新语义。原始及类型恢复对旧明确角色移动定义报character_move_contract_version_unsupported，不改原档案或把旧收据重解释为新事件语义。尚未退役的无版本角色回收及正常主盖牌任务不因该检查误禁；各自旧签名退役属于API-35。旧Transfer入口本身在API-20禁用。

所有验证是隔离规则／投影检查，不计正常独立程序、页面视觉或联机：

- 首轮因HostRecovery缺命名空间限定而编译失败，无XML；补全限定名后14／14通过。
- 共同生命周期和转移回归226项，224通过／2失败：一个是新策略返回不同权限错误码，已恢复原代码；另一个旧测试明确断言“只能有EffectCompleted”，须按4.8.2迁移为准确一次公共转交事实。原始XML保留，不把此断言改动当作未发现失败。
- 补正后24／24同名复验通过，包含22项新增共同角色移动用例及上述两个原失败；226个不同用例最近结果均通过，并非同一批次全绿。

新增覆盖包括两个真实Lua入口、同实例与原归属／新控制者、旁观／接收者可见性、必要转交响应及完成后恢复、同玩家／无变化、整组错误零提交、来源／控制者／类型变化、旧定义原始恢复拒绝、使用中转交后原FinishUse、方块和设施载物实际返还。原始XML、逐文件条款与摘要位于Logs/LuaApiUpgrade/API-19；本项没有UI、场景或预制体改动。原有七项未闭环不因此关闭。

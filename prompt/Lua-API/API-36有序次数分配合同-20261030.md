# API-36 有序次数分配合同 v1

对应[升级计划](Lua-API升级计划-20261029.md)第 4.15、6.15 节及 API-36。本文件固定 API-37～39 的实现合同；本合同于core2.1.7冻结；当前core2.1.39已实现API-37后端、API-38分配模式和API-39林迁移；见[后端](API-37有序分配执行-20261101.md)、[页面](API-38分配页面与只读队列-20261101.md)及[林实施](API-39林有序交易-20261101.md)。正常UI/视觉/联机验收保持独立缺口。

## 标识、边界与预算

| 项目 | 唯一合同 |
| --- | --- |
| Lua 构造名 | `Effect.AllocateEffects` |
| 节点类型 | `effect.flow.allocate_effects` |
| 参数版本 | 必填 `apiVersion=1`，不接受无版本或其他版本 |
| 交互类型 | `effect.effects.allocate`，由正式类型及投影识别，提示键不参与分流 |
| 答案 schema | `allocation_sequence_v1`，不能按普通 Choice 或出售答案解释 |
| 完成结果版本 | `allocation_result_v1` |
| 数量边界 | 选项 1～16；每项一次的根效果 1～16；单项上限 0～99；总次数 1～99；正式队列最多 99 项 |

它只负责分配、封存顺序及依次等待子树，不增加离场批次、整组预留、费用豁免、交易合并或事务回滚。执行时不得创建 `effect.flow.repeat`；旧 Repeat 的名称、别名、嵌套及恢复继续拒绝，不转换为新节点。

数量上限不取消原有 Lua 指令／耗时、脚本长度、表深度／表项、归一化值、子式、内核深度／节点／事件／派发预算。每项规格及嵌套都按原规则检查；当前合法选项规格只保存一份，不提前展开为 99 份子树。超预算或非法嵌套在打开必答交互前拒绝，不临时扩大预算。首版禁止在选项正文的任何深度嵌套 AllocateEffects；普通有限数组、Condition、Choice 及其他合法操作保持各自合同。

## 构造参数

参数对象只接受下表业务字段和既有 Effect 公共元数据。字段重复、未知字段、稀疏数组、混合字典数组、非法数值及类型不匹配均拒绝；数字不从字符串或小数静默转换。

| 字段 | 必需及默认 | 校验与含义 |
| --- | --- | --- |
| `apiVersion` | 必需 | 整数 1 |
| `player` | 必需 | 真实决策玩家，沿现有玩家引用规范化；Host 核对当前来源及执行作用域的合法授权，填写字段本身不授予权限 |
| `options` | 必需 | 连续非空数组，1～16 项；定义顺序只决定数量行顺序，不决定执行队列顺序 |
| `options[i].id` | 必需 | 非空、唯一、区分大小写；1～64 字符，使用 `A-Z a-z 0-9 _ . : -`，不使用翻译文本或数组位置代替身份 |
| `options[i].effects` | 必需 | 连续非空 Effect 数组，1～16 个根效果；一次分配执行整个数组一次，数组内各根不另占分配次数；递归编译、来源、预算及退役检查全部适用 |
| `options[i].text` | 必需 | 正式 `Text.Ref(...)` 及类型化参数；装配时核对键和参数，沿已有富文本／实体可见性解析；同一声明用于数量行和队列条目 |
| `options[i].maxExecutions` | 必需 | 整数 0～99；0 仍显示该行，但不能增加；各项可以不同 |
| `totalExecutions` | 必需 | 整数 1～99；普通确认所需的准确总数，同时也是队列总上限 |
| `allowEndAction` | 必需 | 布尔值；true 允许按当前队列提前提交，包括空队列；false 必须分满，不接受结束提交 |
| `completionHandlerId` | 可选，无默认处理器 | 仅使用原有、已注册且属于合法来源的完成处理器，不授予调用其他来源的权限 |

`WithContext` 与 `WithPresentation` 继续按既有公共合同处理；它们不能省略每项 `text`，不能替代答案中的有序队列，不能扩大玩家或脚本权限。外层提示与选项规则文本分别归属各自声明。

若 `allowEndAction=false` 且各项上限总和小于 `totalExecutions`，构造／编译拒绝，不能发出无法完成的必答请求。true 时允许较小容量，包含全部上限为 0。预算溢出、非法正文等声明错误即使允许空提交也不能隐藏。

不依据初始库存删除可能依赖前项收益的选项。Host 只校验分配合同，实际费用、目标和收益由轮到该项时的业务子式按当时状态判断。

## 草稿与正式答案

草稿为有序条目队列。每个条目有本地独立身份及 `optionId`；同一选项的多次出现不能合并。本地身份不进入业务效果、不充当结算来源，也不作为 Host 的可信执行标识。

- 加一次：在当前队列最右侧追加该选项，检查单项和总上限。
- 减一次：从右往左删除最近的同选项条目；其余相对顺序不变。
- 直接输入数量：增加量按右侧追加处理，减少量按右侧同项删除处理；非法或超限输入恢复到原有效草稿，不截断为另一个合法值。
- 次数始终由队列重算；禁止从无序次数向量重新排序生成队列。相同文本的不同 ID 仍独立处理。

正式提交沿现有交互命令提供 `interactionId`、`expectedRevision` 及原操作窗口／授权合同。答案对象仅含以下四个字段，不另接受客户端计数：

| 字段 | 合同 |
| --- | --- |
| `sequence` | 连续的有序选项 ID 字符串数组，长度 0～99；Host 根据它重算每项次数 |
| `submitKind` | 仅 `confirm` 或 `end_action` |
| `candidateSetId` | 当前请求实际发布的候选集身份，不接受其他请求的身份 |
| `candidateSetVersion` | 当前请求的候选版本整数，不接受旧版本 |

`confirm` 必须准确分满 `totalExecutions`。`end_action` 必须有 `allowEndAction=true`，可在 0～总上限间提交，分满时也可以使用；业务意义仍为主动结束本次分配。Host 复验回答玩家、交互归属、状态修订、候选身份／版本、ID、次数、来源与内容身份，全部通过才原子封存答案。

失败提交不关闭请求、不扣费、不创建业务子节点，也不修改上次有效草稿。请求过期后不得用旧草稿自动提交到新请求。关闭窗口、收起、Escape、断线均不是提交；结束入口在此处只提交当前队列，不能先结束玩家回合或另外扣主行动额度。

## 封存和推进

持久状态由当前节点拥有，首版固定保存：版本、原交互及候选身份、决策玩家、来源／内容版本与摘要、选项声明的独立快照、封存的 `sequence`、重算的计数、`submitKind`、下一序号、在途一次执行的根节点 ID 及已结束收据。选项文本也纳入原声明身份，不在恢复时换成当前其他版本的选项。

1. 等待分配时不创建业务子效果，不做真实付款或查询后变更，不登记可执行草稿按钮。
2. 接受答案后先封存，再产生第 1 次执行；每次按封存序号和选项 ID 派生独立稳定节点身份，重复选同一项也不共享可变执行状态。
3. 一次执行包含该项全部根效果，保持原数组顺序。等待完整业务子树、相关响应及必要完成续接结束后，才推进下一项；不能只等最外层声明已创建就并行推进。
4. 每次执行按当时资源、位置、来源和权限复验，不把预览当作已付费或已完成，不强制收拢无关玩家的合法窗口。
5. 记录收据后才推进序号。保存恢复复用原节点及收据，不重建已执行项，不按当前候选或文本重新解释旧队列。
6. 空队列合法结束时直接完成，尝试／完成数均为 0。正常耗尽或普通失败终止时，外层完成回调只交付一次；Faulted 保持原故障处置，不伪造正常完成回调。

## 结果、失败和预算表示

`Condition` 返回 `condition_not_met` 仍是合法完成的一次尝试；分配器不把它解释成支付成功。根效果的普通 Failed 停止尚未开始的后缀，保留此前实际变化及当前失败，不回滚、不自动跳过、不补足次数。Faulted 保留首次现场，沿主链故障处理。

完整结果使用节点内专有、有界的 `allocation_result_v1` 类型记录。不能把最长 99 项队列、16 项计数和所有嵌套结果一起塞入已有上限 128 元素的通用 NormalizedValue，也不能为此提高其全局上限。

| 完整结果字段 | 唯一含义 |
| --- | --- |
| `version` | `allocation_result_v1` |
| `ownerEffectId, contentIdentity, resultDigest` | 实际所有者、封存来源／内容身份和确定性结果摘要，不能由客户端提供 |
| `sequence` | 原封存的全部队列，包含未执行后缀，不重排 |
| `allocatedCounts` | 按选项定义顺序保存 `{optionId,count}`，包括 0 次项；与队列逐项重算一致 |
| `submitKind` | 原 `confirm/end_action` |
| `allocatedCount, attemptedCount, completedCount` | 分配、已经开始、全部根效果合法完成的次数；不提供通用“交易成功数” |
| `executions` | 按实际尝试顺序的记录，含从 1 开始的 `ordinal`、`optionId`、终态／在途状态，以及每个根效果的独立 ID、状态、失败原因和原规范化结果；子树身份沿已有节点关联保留 |
| `failedOrdinal, failureReason` | 首次普通失败的位置及原因；没有时为 0／空字符串 |
| `unexecutedFrom` | 第一个尚未开始的封存序号；无后缀时为 `allocatedCount+1` |
| `outcome` | 正常耗尽为 `completed`，普通失败停止为 `stopped_on_failure`；故障状态按原运行时保存，不写成这两个正常终态 |

`NormalizedResult` 只发布小型摘要：`version/resultRef/resultDigest/submitKind/allocatedCount/attemptedCount/completedCount/failedOrdinal/failureReason/outcome`。`resultRef` 指向本所有者的完整结果，恢复时必须核对原记录和摘要，不接受伪造引用或缺失记录。

完成回调通过事件专属只读视图 `ctx.payload.allocationResult` 读取上述完整结果；原 `ctx.payload.normalizedResult` 仍为小型摘要。该视图仅绑定当前完成节点与原合法来源，不增加跨局／跨来源任意读取接口，不授予隐藏子结果的查看权；权限不足字段沿现有可见性规则裁剪。Host 保存完整权威记录，Lua 修改本地视图不能改变它。返回给后续 Effect 的数据仍遵守原归一化预算，不能借该视图转存任意大对象。

完整记录每次最多 99 条执行、每条最多 16 个根结果；根节点及子树同时受原全局节点上限约束，各规范化结果保留原深度／元素预算。恢复逐项核对队列、计数、推进位置、实际节点、终态和首次失败，不用摘要中的数值代替权威收据。

## UI 的必要适配范围

API-38 只在现有通用出售数量页增加由正式交互类型选择的“效果次数分配”模式。每行显示本项正式文本、次数和上限；数量、可确认状态和队列由同一草稿驱动。出售库存／单价／预计金券不进入该模式；原 SellResource 累计和零出售结束合同不变。

队列沿现有插入结算按钮视觉组件及滚动容器显示，每次出现一枚按钮，使用同一项正式文本。按钮禁用点击、详情、长按、右键、键盘执行及拖动改序，不登记为真实来源。确认后草稿只读，真实付款、目标、响应仍转入各子效果现有页面。切换、完成或新请求只清除本请求的展示，不能清理其他来源。

提示、进度、模式名称及必要按钮文案使用正式文本资产或可序列化配置。现有场景／预制体仍是结构、位置、尺寸、样式和静态文案来源；本合同不授权生成器重建或覆盖资产，也不要求新建林专用页面、浮层或悬浮文字。

未提交草稿至少在同请求的普通刷新期间保留完整顺序。若重连／重载不支持恢复草稿，必须同时重置数量和队列并明确显示已重置，不猜顺序、不自动确认。已封存答案及推进状态必须冷恢复，不作为 UI 草稿处理。

## 林的首个消费者与验证责任

API-39 沿计划保留八项交易、每项上限 10、总额 10、允许主动结束，以及现有出售／购买行文案和购买付款提示。计谋不随策略迁移改动。成功数逐次检查实际交易 Condition 的 `conditionMet`／`condition_met`，不得使用分配数或 Completed 次数代替。

普通确认后还有成功额度时，可用原合法完成续接打开剩余额度的新分配；新总额和单项上限收窄，旧成功项不重放。`end_action` 本批执行结束即停止本次策略，不再补弹。初始 1 源岩／0 金券的卖后买应净增 2 金券，反序按付款不足的实际条件结果处理，不能重排。

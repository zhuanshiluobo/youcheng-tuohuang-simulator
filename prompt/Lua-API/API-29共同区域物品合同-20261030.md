## 唯一共同版本及字段

共同入口仍为 `Effect.MoveItem`／`effect.item.move`，新公开 `apiVersion=4`，执行／恢复合同标识 `item.move.v4.3`。v1／2／3 现行输入在迁移期间保持现有语义，不通过缺版本或未知模式猜测新合同；完成 API-30／31 后的新生产者统一归一化为 v4，旧保存结构不能被静默解释为新策略。专用公开名称保留类型约束与参数补全，不再以自身节点身份取得额外移动能力。

最终输入支持边界：明确MoveItem v1单组／v2批次／v3Token形状可以作为**有限输入归一化**保留，只映射其可表达的v4子集，先校验各自互斥字段，再用同一共同策略执行；不保留旧专用执行分支、来源白名单或另一套轨道权限。它们在新内容身份下创建的规范节点必须是v4并保存原参数摘要，不能继续保存旧协议节点。已经落盘的旧执行定义／旧批次或Token收据不升级为v4，新版本恢复前明确报item_move_contract_version_unsupported并保持原件；需要旧规则时只能用原版本。旧无版本MoveFacilityCard／MoveCharacterCard、CoverCharacterCard v2及整体退役项不属于这张有限归一化表，仍按各自退役任务拒绝。正常内部无版本盖牌任务不是这些公开旧签名，不能误禁。

共同必需字段为 `apiVersion=4, player, operation`。player 是存在的真实执行者，与节点一致；不替换物品原所有者或历史角色执行者。operation 仅允许下表五种。通用 WithContext／WithPresentation 元数据继续走现有包装；不开放 Lua 回调、任意状态写入、任意事件名、随机排列／种子或可伪造的 Host 收据字段。

| operation | 必需及允许字段；未列字段拒绝 |
| --- | --- |
| transfer | selector、destination、insertion、operationProfileId、requiredCount；carrierPolicy可省略且只允许preserve；角色 profile 另允许reveal布尔值（默认false） |
| transfer_batch | transfers非空数组、expectedOrders数组；每段仅允许显式selector、destination、insertion、operationProfileId、requiredCount、carrierPolicy；不能混入选择、top、盖放、地图移动或洗牌。operationId由Host按节点生成，不信任外部幂等键 |
| cover_character | selector、cover；destination、insertion由共同盖放策略解析，不接收调用者伪造槽或使用记录 |
| move_map_token | selector（仅单个明确Token）、destinationLocationId、operationProfileId='core.adjacent_location_token_move'；实际地图区域由Host解析，不同时接收destination.zoneId |
| return_city_style_marker | selector必须为单个显式实例；省略时拒绝，不默认选择；固定类型core.player_marker、按真实原供应解析目标，固定unordered，不接受覆盖供应所有者或重置使用历史的参数 |

selector 只接受以下两种确定移动形状：

- explicit：`{mode='explicit', itemIds={真实实例字符串...}, expectedSource={zoneId, slotId?}}`。保持调用顺序、实例去重，不接收定义ID替代；空数组可声明requiredCount>0并在执行时以insufficient_items真实失败，整组零提交。source.slotId提供即复验。
- `select`已撤销，返回`item_move_selection_not_supported`。上层选择确认后提供explicit；MoveItem不拥有候选、答案或取消状态。
- top：`{mode='top', zoneId, count, itemTypeId}`，仅transfer、实际有序牌堆，count为1～99；Host在本步骤开始时取得真实顶部实例及顺序期望并封存，允许不足与否由requiredCount决定。Lua不提供未来实例、牌序或expectedTop替身；等待后来源变化失败，不另抽同定义牌。

选择请求由上层业务／Lua选择步骤拥有，复用现有候选与确认组件；MoveItem不生成选择请求，不增加对应UI路由。主盖放仍用character.cover.card，上层供应回底与样式返还使用现有lua.choice候选显示。

当前v4.3：explicit的requiredCount为0～99，独立于itemIds长度；不足时整组零提交并Failed(insufficient_items)，不补选、不降低数量。top为0～count。显式及top保留解析顺序；上层取消不创建MoveItem，不存在MoveItem的cancelled/no_legal_target选择结果。

cover_character、move_map_token和return_city_style_marker固定单个explicit实例，不能带requiredCount、selector.select或selector.top。主盖放任务先处理已有盖牌／空手回收，再选择；确定目标后才创建共同盖放子节点。top只取连续真实顶部，不跳过类型不符的顶牌。

destination为`{zoneId}`或`{kind='original_supply'}`，二者互斥；original_supply仅限有真实原供应记录的标记／Token，逐物品解析，玩家私有供应必须匹配原主，共享储备按真实原供应记录归还且不改变原主。insertion为`{kind='unordered'|'top'|'bottom'}`或`{kind='slot',slotId}`，与真实区域OrderingKind严格匹配；同区换格是合法移动，同位置unordered为无变化。requiredCount不把未变化物品伪算成新移动数。

transfer只允许现有登记的设施牌、角色牌、奖励牌、方块、玩家标记和普通Token库存profile；实际类型、区域政策和生命周期仍逐项复验。地图相邻Token使用独立operation；奖励取得、计分、影响力部署／离场、企业带奖励升级不由普通转移猜测或触发。transfer_batch只组合明确、同一profile的卡牌或库存／标记转移；整组最终状态验证轨道互斥、层序与容量，不先提交前半组。涉及真实已付建设的城市层变更须有真实建设授权事实及层序收据，不能用新入口免费建设；校验事实，不校验“只能是专用移动节点”。

## 共同行为策略

角色转移必须等待相同在途使用／必要响应，按既有载物退出政策预演并一次提交；保留OwnerSubject、按目标角色区域更新ControllerSubject。本次CharacterUse.ExecutingPlayerId不改写；牌已转给别人时原FinishUse不再收走。实际跨玩家角色转交由共同策略只发一次character.transferred，公开仅接收者，HostOnly含实例；普通同玩家移动、失败和无变化不误发。reveal=true仅角色策略允许，保留原公开展示与必要响应，不新建确认页，不用公开结果泄漏其他手牌。

cover为`{mode='main'|'additional', acceptedTypeId, reusable, blockedActionRoundSequence}`。main只在真实正常盖放主链／本人任务资格下执行，接受基础角色类型、reusable=false、blocked=0；主盖放任务处理空手回收、选择及已有盖牌无变化；MoveItem只执行确认后的盖放。不能由任意DIY阶段绕过主链。additional复用真实声明来源／槽规则：acceptedTypeId仅core.character_card或core.generated_character_card；reusable=true时只能从本人手牌且blocked=0，按真实来源复用空槽；false时blocked必须是当前行动轮序列，原手牌／弃牌来源规则保持。共同策略取得／创建槽、登记接受类型和阻塞、处理离场／回收及盖放公开／私有事实，最后才完成；MoveItem与CoverCharacterCard得到同一规则结果。

玩家标记按4.11开放跨玩家供应和存放区、企业与宣告轨道，不要求旧Store/Return包装或执行者就是所有者。同一企业实例的同一玩家合作轨道所有等级合计最多一枚；同一宣告权限逻辑域跨declaration子区／状态格合计最多一枚，同实例换状态不增加。按标记所有者计算互斥，零枚合法；物品位置、使用绑定、显示和资格共同提交。普通移格只改变真实等级／状态，不自动授予升级奖励、补标记或重置历史分数／使用次数。返回样式的候选保持本人二级标记语义；无候选沿原失败结果，不吞为成功。

地图Token复用相邻／开放位置、类型profile、控制者、锁绑定与目标真实区域检查，提交后发同一token.moved与必要响应；不得复制、替换Token或用普通库存profile绕过地图规则。库存Token不因此获得创建锁、生成Token或奖励取得权限。

## 收据、结果与恢复边界

[NormalizedValue](../../Assets/YC/Domain/State/EffectRuntimeState.cs) 的限制是**整体128个值节点、深度8、字符串1024字节**，不是每个嵌套数组可再放128份完整对象。输入与结果均先经过该校验；显式IDs及所选数量最多99，批次还受完整输入元素总数限制。不能为方便把候选全集、完整位置变化、嵌套旧结果或所有事件复制进ContinuationData／NormalizedResult；也不能截断移动名单或隐去必要收据。候选全集留在现有类型化CandidateResolution与请求中，不按128静默裁剪页面候选。

统一结果为`{outcome, changed, movedCount, movedItemIds, receiptId, reasonCode}`，outcome为completed／cancelled／no_legal_target／failed。movedItemIds只列实际变化实例，最多99；实际无变化为changed=false/movedCount=0，不伪造成功变化。单枚玩家标记另提供originalOwner（pN）；盖放另提供coveredItemId/coverSlotId；地图Token另提供tokenItemId。专用接口可确定投影这些事实，不另算一份结果。空堆补牌无变化，非空目标槽失败；同位置合法无变化可completed且reasonCode=no_change。失败保留实际原因，取消不计执行成功。

完整源／目标位置、原所有者与控制者、实际顺序、Host解析实例、相关轨道／生命周期变化和一次性事件ID，记录在节点拥有的类型化**TransferReceipt v4.2**，请求摘要绑定节点、执行者、原始参数、选中实例、顺序期望与策略版本。它不依赖某专用接口名，不能被公开参数传入或从其他节点挪用。收据ID只指向当前真实提交，不等于调用者可修改的operationId。

为Lua完整读取这些事实，API-30须实现只读`SourceData.GetTransferReceiptPage({receiptId, offset, limit})`，limit=1～8、offset为非负整数。只允许本次授权来源／续接可见的收据；每页行采用扁平itemId/fromZoneId/fromSlotId/toZoneId/toSlotId/originalOwner/controllerBefore/controllerAfter，附nextOffset/total，整体仍过128限制。Host保存完整证据，公共／旁观投影按原可见性遮蔽，不能借分页获取隐藏牌身份或牌序。这是结果读取，不是新Effect或状态写入入口；未实现前不列入可用查询。

移动状态机为initial→bound→waiting_dependencies→committed→waiting_responses→completed。上层回答确认后才创建显式移动；Host确定取顶／显式实例后一次封存；提交前重验来源／目标、顺序、真实规则与必要依赖，提交后复用原收据，不从移动后的源区重新规划。上层取消则不创建MoveItem；已提交故障保留现场，不普遍回滚。单组／批次沿现有整组预演提交，刷新等组合逐步骤提交，不为统一制造全流程事务。非法字段、缺收据、摘要不符、重复实例、越权收据、来源变化和不支持的旧专属续接在回答／执行／恢复前拒绝，原档案不改写。

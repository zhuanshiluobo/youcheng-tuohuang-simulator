# API-23 统一角色牌区域移动合同

对应[计划](Lua-API升级计划-20261029.md)4.10.1、4.8.2、4.13.1、6.10，并复用[API-19共同策略](API-19共同角色牌移动与转交-20261030.md)。本项先补齐统一能力，5文件／7处旧调用及旧入口退役在API-24另行实施；完整MoveItem v4仍未实现。

MoveCharacterCard继续使用公开apiVersion2的itemRefs／expectedSource／destination／insertion／core.character_card_transfer／requiredCount；直接MoveItem apiVersion1的角色profile使用相同参数和CharacterCardMovement。新增可选reveal布尔值，默认false，仅角色profile接受；其他类型、字符串／整数及旧无版本分支不得吞掉它。

同玩家移动、合法公开流形来源和跨玩家转交都走同一策略。流形取得验证真实实例、公共原区及合法目标，不要求旧事务节点身份或伪造SourceFacts；OwnerSubject保持，ControllerSubject按目标角色区域更新。来源／控制者变化、对手私有来源、重复和错误类型仍失败，不按定义另选。依赖等待、载物返还、盖牌槽、绑定／订阅退出及原使用结束复用API-19实现，不另起包装。

实际提交有变化且reveal=true时，共同策略只发一次character.cards.revealed并等待必要响应；公开正文只包含实际movedItemIds及对应definitionIds，字段名为itemIds／definitionIds。单实例另保留罗德岛原recoveredItemId／discardedItemIds；多实例不复制这些单例兼容字段，避免重复数组突破归一化128值限制。明确展示不额外公开其他手牌；默认／false、无变化和失败都不展示。跨玩家转交仍发原公共接收者事实，不把展示默认打开。

changed／movedCount／movedItemIds均取实际提交。requiredCount沿既有“最低实际移动数量”检查：允许同位置零变化须声明0；要求1而实际移动0则insufficient_items，不将未移动转交算成功。新展示结果与事件接受同一NormalizedValue整体128值限制，不截断名单；50张合法输入与全部结果／事件恢复有专门覆盖。

共同语义升级为character_move.v2.2，MoveCharacterCard执行定义2.2.0、MoveItem执行定义3.2.0；API-23阶段core2.1.17。活动指纹沿已有共同Version生成；旧2.1.0／3.1.0明确角色移动保存状态在原始及类型恢复门禁拒绝，不改原档案或按新展示语义重解释；无版本旧回收仍留API-35。

原始证据位于Logs/LuaApiUpgrade/API-23：首轮测试把IEnumerable传给要求IList的方法，编译失败且无XML；只补ToList。随后46项44通过／2失败，新零变化夹具误声明requiredCount1；改为明确0，并保留requiredCount1必须失败的两入口对照，不改生产规则。最终零变化数量合同与共同回归复验/editmode-20261030_223349.xml为48／48，7.48秒，前两失败全名均后续通过。

28项新用例覆盖两个真实Lua入口的收回／弃置展示、默认隐私／显式false、合法零变化／严格不足、公共流形、必要展示响应恢复、上版共同定义拒绝、参数类型／非角色profile及50张完整名单。另20项既有角色转移／载物／使用结束回归同批通过。全部仅隔离规则和投影验证，不计正常可见独立程序、多局、视觉或联机；本项无生产UI、场景／预制体改动，未运行生成器或访问受限原素材。

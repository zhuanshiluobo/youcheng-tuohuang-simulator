# API-31设施共同步骤与API-35收尾

对应4.13.1/4.13.2/4.13.4、4.14.3/4.14.4和API-30/31/35；恢复、文档及证据对应API-04/05/06/01/33。按用户要求优先实现，仅对受影响路径定向验证，完整批量回归、原暂停正常独立程序/多局/视觉/联机及API-25正常界面权限验收不恢复。

MoveFacilityCard新增有效v3：apiVersion=3/player/operation='cycle_supply'，公开形状固定；v2明确实例保留原语义，不自动补槽。v3仅限定当前供应顶牌、补齐真实供应区域及设施牌堆、组织共同v4 select回底，完成及必要响应后从真实收据取得原槽，只在该槽为空时组织RefillSpec；原槽仍有下层牌则不补，无目标直接结束。禁止旧定义ID猜测或任意旧路由字段。结果为changed/selectedItemId/selectedDefinitionId/originalSupplySlotZoneId/refilled/reasonCode，旧字符串结果不保留为新合同。

RefillFacilitySlot公开v1及Host内部slotZoneId工厂改为一个公开MoveItem v4 top/count=1/requiredCount=0，执行时绑定实际顶部及源顺序，不读取未来ID。新增公开destination.mustBeEmpty布尔约束，规划及提交前复验，收据恢复验证OrdersBefore；无候选/取消的零移动不补造未触及区域事实。原已占槽拒绝边界保持，空堆零变化，父结果从共同收据投影，不另做搬运。正常建设与设置的现有RefillSpec自动接入；自动化准备及旧PlayMode夹具的最后两个直接服务调用也改为等待共同子步骤，不计正常验收。原FacilitySupplyService.RefillSlot专属算法移除，初始化/旧列表业务不借此改写。

RefreshFacilitySupply按真实供应层序逐张共同explicit回底，完整等待后执行独立ShuffleDeck，再按槽顺序组织共同top补牌。原源实例/定义/区域保存到FacilitySupplyFlowStateV1，未塞入NormalizedValue，仍遵守128值/深度8及现有总执行预算。不会在洗牌前冻结未来补牌、吞子失败或把随机重排塞入MoveItem。父节点没有自己的PositionChanges，实际转移与收据在共同子节点。

德克萨斯策略和martin_rounds两处正式旧无版本调用迁v3，保留12金券、插入后重新选择全部实际供应顶牌及既有顺序。马丁调用者的WithPresentation正式提示传至共同步骤；不硬编码卡名判断，不改静态UI文案/控件。API-35所列三个旧签名现均拒绝；ShuffleFacilityDeck两处显式v1此前已迁移，独立洗牌保持。设施旧签名在Lua/别名/嵌套/编译/内核、snapshot/journal及既有待执行规格恢复前返回facility_move_unversioned_signature_retired；正常内部无版本刷新/补槽形状仍允许。

### 3.2 2048 坐标与项目地图的转换

交付坐标以完整 **2048×2048** 原图为基准，原点在图片左下边缘，X 向右、Y 向上。坐标包含外框和计分轨，不是内部地形区域坐标。优先使用 JSON 中的 x、y，避免复制 Markdown 表格时丢失精度。

项目当前两张地图源纹理为 5000×5000；不能将 2048 像素坐标直接当作项目原图像素或世界坐标。先确认交付参考图与工程底图只是完整等比例缩放，没有裁边、位移或内容改版。对照交付 source 指纹、多个分布在四角与中心的锚点及实际叠图；文件哈希因分辨率不同而不一致时，不可宣称原文件一致。

当前 `MapCoordinateSpace` 使用左上原点的归一化坐标，因此导入时：

```text
normalizedX = x / 2048
normalizedY = 1 - y / 2048
worldPosition = MapCoordinateSpace.ToWorldPosition(normalizedPosition, 0)
```

这是图片边缘坐标，不能写成 `2047-y`，也不要额外补半个像素。pivot 统一为 `(0.5, 0.5)`，透明留白是对称的，不另加中心补偿。

按钮本地尺寸按 Sprite 实际边界换算：

```text
localWidth  = logicalWidth  / 2048 × mapSprite.bounds.size.x
localHeight = logicalHeight / 2048 × mapSprite.bounds.size.y
```

再继承地图 Transform 的缩放、平移和旋转。不要再乘一次 5000/2048 或 4× 采样倍率。现有地图 1.5 倍缩放应由父级变换统一处理。

如果底图并非等比例版本，应记录差异并校准坐标来源，不用随机偏移或局部手调掩盖整图配准错误。

### 3.3 中心定义与贴地要求

- 资源点按钮中心是整个阶梯形外轮廓的包围盒中心，不是右侧灰色区域、资源图标或城市棋子锚点。B-01 的上方入场奖励不计入轮廓尺寸。
- 航道按钮包住三角标、字母条和槽位底条，不沿整条白色连线绘制，也不能以其中某一个槽位代替整个航道按钮。
- 保留不同语义的锚点：资源点按钮中心、资源标记位置、城市位置、影响力槽位不能无条件共用一个中心。不要因为更新按钮中心把城市和资源标记一起移错。
- 新二维按钮及其状态表现与地图局部 `Z=0` 共面，使用明确的渲染排序保持可见，不靠前移 Z 值制造选中效果。检查并移除对这批新按钮仍生效的旧热点深度偏移。
- 不再沿用旧热点选中时整体放大两倍的行为；两种状态共用中心、尺寸和命中轮廓，仅切换对应贴图，避免新外轮廓偏离底图。

## 4. 点击范围和三类目标分发

点击范围与发光留白分开：资源点、航道读取 `polygon_top_left` 生成实际轮廓命中范围；影响力槽位使用 **34×34** 逻辑矩形，不使用 58×58 含光晕画布作为按钮范围。

原包多边形以图案轮廓左上为原点，转为以中心为原点、Y 向上的局部点：

```text
localX = polygonX - outlineWidth / 2
localY = outlineHeight / 2 - polygonY
```

随后按地图逻辑比例换算。对当前允许点击的按钮，点击应覆盖轮廓内部，即使素材中央透明也能点击；不能使用只允许命中不透明像素的检测，让按钮变成只能点亮边。采集尚未连通资源点属于只显示贴图的例外，不启用其点击交互。

- 选择资源点时，命中资源点按钮；内部两个影响力槽位不抢事件。
- 选择航道或采集支付时，命中整个航道按钮；双槽航道只打开一次窗口，不因点中不同槽位产生两条航道支付。
- 选择影响力时，命中具体槽位／其中的影响力，父级资源点和航道不同时触发。
- 依据当前工作流及合法候选集合启用命中目标，不能只靠贴图是否可见判断可点击性。selected 状态依然有命中入口。
- 关闭旧圆形热点、旧大范围 Collider 或遗留的重复输入入口，避免图像已替换但实际仍使用旧点击范围。
- 地图拖拽、缩放、上层窗口、下方结算区域、UI 遮挡与非本地玩家操作继续遵守现有输入路由。一次点击只交给一个有效目标，不穿透支付窗口触发地图。

## 5. 状态语义：采集已选与临时待确认分开

不要用一个“已选目标”变量同时保存采集集合和二次确认目标。表现状态可以统一，但业务来源必须区分。

| 场景 | 表现 | 点击语义 |
| --- | --- | --- |
| 采集：属于可采集候选，但尚未通过航道连通的资源点 | resource-available | 无点击交互，只提示候选位置 |
| 采集：已经连通，且按现有逻辑处于未选／取消状态的资源点 | resource-available | 沿用现有重新加入逻辑；仍须满足点击资格 |
| 其他当前可交互但未选择的资源点／航道／影响力槽位 | 对应 available | 交给当前工作流 |
| 采集：准备采集的资源点 | resource-selected | 保留按钮，允许按规则取消／重新选择 |
| 采集：已确认支付对象的航道 | 对应 route-selected | 保留按钮，可再次打开支付对象窗口 |
| 采集：尚可选择支付的航道 | 对应 route-available | 一次点击直接打开支付对象窗口 |
| 非采集：首次点击的合法目标 | 对应 selected | 临时待确认，再次点击同一目标确认 |
| 无当前操作、非法目标、已结束工作流 | 不显示操作高亮 | 不接受该操作的命令 |

一个目标一次只显示一种状态，不叠加 available 与 selected。正常情况下，仅采集流程维持成组的已选表现；其他操作使用 selected 表示当前步骤的临时预选，确认／取消／切换步骤后及时清除。

## 6. 采集交互

### 6.1 资源点选择

- 以现有正式规则查询返回的可采集目标、路径、支付条件和当前选择草稿为准，不改变“哪些资源点可以采集”的规则或查询算法。
- 属于本次可采集候选、但所需航道尚未连通的资源点，显示 resource-available，但禁用其业务点击入口。点击它不切换选择、不进入二次确认、不打开支付窗口，也不触发原有“请先支付”提示等点击回调；应通过可选航道按钮完成支付对象选择。不要将这些点隐藏，也不要为显示它们而错误地将它们纳入已选集合。
- 航道连通仍由现有路径／支付查询判定，不按屏幕上线条是否相接判定。可见状态、已连通状态、可点击状态和已选状态分别处理。
- 连通条件满足后，沿用现有自动纳入采集选择及用户取消记录的处理，准备采集的资源点显示 selected；不能额外要求用户逐点点击才能采集，也不能因为新贴图而改变默认选择行为。
- 点击已选资源点可以按现有规则取消；取消后仍合法可选的点恢复 available 并保持按钮，可以再次加入。不能恢复成无入口的隐藏状态。
- 对规则强制包含或不可取消的资源点，保留原规则约束，明确区分它与可切换选择，不因本次按钮调整改变规则。
- 支付对象确认、资源点增减、预算和候选变化后，沿用现有选择刷新流程，同步更新地图与下方结算预览。保留现有对用户取消记录的处理，不能每次刷新无条件把用户刚取消的点又加回来。若连通条件失效，仍属候选的资源点回到 available 且不可点击，并按现有规则移除无效选择。

### 6.2 航道支付对象窗口

1. 未选择支付、当前合法且可支付的航道显示 available。
2. 点击一次就进入该航道的支付对象选择窗口，不经过地图二次点击确认，不要求先点击槽位。
3. 打开窗口本身不代表已选择支付。只有确认合法的接收方／支付对象后，才将该航道记入本次采集草稿，显示 selected。
4. 显示 selected 的航道仍可点击，再次打开窗口时回显已选对象；修改后更新同一条记录，不能重复添加路费或重复累计支付。
5. 初次选择时取消窗口，保持原来的 available；编辑已选航道时取消窗口，保留打开前的已选对象与 selected。若现有流程支持撤销该航道支付，撤销后统一重新校验受影响资源点和预算，不留下不可兑现的已选状态。
6. 银行、唯一接收方、多个对手接收方均使用正确流程，不能因某类已选航道只有一个接收方就撤掉其按钮，也不能只给“向银行支付”显示已选。
7. 这里的“已选支付航道”是本次结算计划，不代表已经实际扣款。点击按钮／确认接收方不提前提交采集或重复执行支付，实际提交继续通过正式命令入口。
8. 可支付集合与已选集合分开处理，已选航道不能因为预算计算改变而失去查看／编辑入口。提交时重新校验当前权威状态。

### 6.3 全部可采集资源点已覆盖

在**下方结算区域**增加动态提示，文案为：

> 已选择所有可采集资源点

- 判断复用本次现有正式采集候选与可达／支付查询，并对资源点 ID 去重；不是全地图资源点数量，也不是当前可见高亮数量。只增加提示所需的派生判断，不为这条文案重写候选、支付或默认选择逻辑。
- 所有本次合法可采集目标均已进入选择草稿时显示。必须考虑继续选择合法支付航道后还能解锁的候选，不能仅因“当前已解锁的点都被自动选上”就提前提示完成。
- 对预算不足、无资源、规则禁止等目标按正式查询过滤，不把无法合法选择的点算成缺选。存在互斥支付计划时不能凭静态候选并集要求同时选择不可能共存的目标；使用规则层认可的当前计划与可继续扩展范围，并记录判断口径。
- 取消某个可采集点、修改支付使覆盖关系改变、收到状态刷新时立即重新计算；不满足条件时撤掉该提示。
- 无有效候选／尚未初始化、已提交等待结算、已退出采集，不显示这个提示；这些状态沿用各自正确文案。
- 只提示，不自动提交、不强制关闭选择，也不禁用已选按钮。金额、接收方和奖励预览继续保留。
- 文案作为可序列化的检查器配置或专用文案资产保存，代码只决定显示状态，不把固定字符串散落在控制器中。

## 7. 非采集操作：selected 作为二次确认中间状态

适用于当前步骤需要选择资源点、航道或影响力的操作，重点覆盖空槽部署，以及移动／探索目标、调度、移除／替换影响力和卡牌效果的相关选择入口。逐个核对实际工作流，不能只修改主按钮而遗漏事件／角色／设施效果入口。

1. 合法候选使用 available。第一次点击目标 A，A 切换 selected，记录当前动作、步骤及目标 ID，不执行落子、扣费或命令提交。
2. 后续独立点击同一目标 A，重新验证合法性，通过后仅执行一次确认。不要把同一帧内多个鼠标回调当作两次点击；不要求系统意义的快速双击。
3. 第一次点击后改点合法目标 B，A 恢复 available，B 进入 selected；不能直接执行 B。
4. 取消、返回、点击地图空白、切换操作／步骤、退出窗口、回合／阶段切换或目标失效时，清除临时待确认状态，并恢复当前候选表现。UI 内部点击按窗口路由处理，不误当地图空白。

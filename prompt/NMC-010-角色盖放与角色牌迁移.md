# NMC-010：角色盖放与角色牌迁移

## 任务提示词

你负责把角色盖放阶段与现有角色牌效果迁移到统一主链、Lua 内容和通用 Interaction 上，并清理被切断的角色专用 pending/调度代码。采用先代表性纵向切片、再按行为族批量迁移的方式，任何时刻同一规则只能有一条生产路径。

## 前置任务

`NMC-005`、`NMC-006`、`NMC-007`、`NMC-009` 已完成。

## 目标

1. 实现一个角色盖放主节点，其下按玩家顺序创建并等待角色盖放子任务。
2. 实现 `CoverCharacterCard`、隐私安全的 `CharacterCardCovered` 和有序的 `CharacterCoverCompleted` 生命周期。
3. 把角色牌 ID 特判/专用 C# effect 逐步改为版本化 Lua handler + 通用 Effect/Interaction。
4. 当最后调用方迁移后，删除 `PendingCharacterEffect`、`DelayedCharacterEffects` 等旧状态及对应服务/测试残留。

## 实施要求

1. 角色盖放主节点是回合主链中的一个节点；玩家盖放操作作为顺序子节点/交互执行。任一子节点合法失败只解除 blocker，主节点依据阶段合同继续处理，不自动传播失败。
2. 顺序、目标玩家和角色牌实例 ID 都稳定持久化；恢复后不得再次要求已经完成的玩家盖放。
3. `CharacterCardCovered` 默认不能向非持有者泄露隐藏牌身份；公开信息和 Host-only 参数分开投影。阶段全部完成后按确定顺序产生 `CharacterCoverCompleted`。
4. 先选择一张包含交互/响应的代表牌跑通 Lua 纵向切片，再按“无选择、单目标选择、多目标/资源选择、条件式、延迟/完成响应”等行为族迁移其余现有角色牌。
5. 牌定义采用数据/脚本注册，不在 C# 用 character/card ID 分支。无法用现有通用 Effect 表达的能力先补写明确 Effect 合同和测试，再接脚本。
6. 条件式严格采用权威文档：左侧与条件式同一节点，右侧才是子节点；左侧失败/拒绝和右侧子失败的结果不可混淆。
7. 每迁移一个行为族，立即切断其旧生产入口并核对旧 handler/service/presenter/tests 的剩余调用。只有全量迁移后才移除对应 legacy pending 字段。
8. 不保留“Lua 失败则跑旧 C#”的 fallback；内容错误应进入受控 fault。

## 测试精简要求

- 卡牌测试按行为族和数据表组织，不为每个卡牌复制完整 Arrange/Act/Assert。目录/注册/schema 完整性可用一份 catalog 合同覆盖。
- 规则结果在 Domain/Effect 层权威验证；Presentation 仅保留隐藏信息、通用交互绑定和少量代表牌冒烟。
- 把现有 CharacterCard/CharacterEffect/CharacterCover 重复测试映射到新矩阵，删除只验证旧调用顺序或旧 pending 字段的用例。
- 保留每种独特规则分支、权限、恢复和隐私风险，完整 EditMode 必须通过。

## 非目标

- 不迁移城市样式、设施或事件牌。
- 不改变现有角色牌规则文本；文档无法决定的牌先列出阻塞项，不猜规则。
- 不让客户端获得隐藏角色牌脚本参数。

## 验收标准

- 盖放阶段完全由一个主节点及顺序子任务推进，重连/恢复不重放。
- 现有角色牌已按行为族接入 Lua/通用 Effect/Interaction，C# 无 ID 特判生产入口。
- 隐藏牌身份和私有候选按 viewer 安全投影。
- 已无调用方的角色专用 pending、延迟队列、服务与测试逐项清理；暂留项有真实调用证据。
- 完整 EditMode 通过，发现用例数没有因逐牌复制而膨胀，`git diff --check` 通过。

## 交付报告

提供角色牌迁移矩阵（牌/行为族/脚本/Effect/旧入口状态）、隐私矩阵、删除清单、暂留调用方、恢复验证与测试净变化。

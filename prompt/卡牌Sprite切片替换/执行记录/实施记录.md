## 唯一映射与运行方式

- 七张原始 JPG 原样复制至 `Assets/StreamingAssets/Content/core/artwork/sheets/`；源图未修改，复制前后 SHA-256 一致。
- 唯一坐标来源是 `Assets/StreamingAssets/Content/core/artwork_slices.json`。七张整图共 101 格，跳过 7 格，登记 94 个稳定 Sprite 标识：城市样式 12、角色 7、设施 51、事件 24。
- 清单记录原图路径、哈希、实际尺寸、行列、原格子序号、左下角矩形、规则 ID、扩展归属、替换目标及核心塔份数。[切片映射.csv](切片映射.csv) 是该清单导出的审阅快照，不参与运行。
- 本项目继续支持构建后替换外部内容，因此采用文档允许的“完整整图 + 矩形 + 运行时缓存 Sprite”方案，没有另外维护 Sprite Editor 子资产。规则层仅保存整数矩形和字符串标识，不依赖 UnityEngine。
- 内容定义及设施模板展开使用 `artwork` 和 `artworkSpriteId`。整图、切片清单、启用配置均进入内容哈希；缺失、越界、重复、跳过格、错误尺寸或错误图片关联会拒绝加载。
- `ExternalContentRuntime` 按整图路径共享 Texture2D，按稳定切片 ID 缓存 `Sprite.Create(..., FullRect)` 的结果。切换播放、程序集重载、编辑器退出及应用退出释放自己持有的 Sprite 和纹理。
- 四类正面 API 返回 Sprite。既有 RawImage 组件通过 `CardArtworkView.Set` 显示 Sprite 的纹理区域；显示比例取单格矩形。采样限制在切片首尾像素中心，防止双线性取到相邻格。清空卡片同时清空纹理并重置 UV。
- 外部自定义内容仍可使用完整单图并创建完整 Sprite；基础内容全部明确引用切片，没有找不到切片时回退到已删除旧图的逻辑。

## 内存与平台

纹理按源分辨率解码，不经过 TextureImporter 的 2048 上限；无 mipmap、Bilinear、Clamp、CPU 不可读。设施整图保持 5400×5100。当前测试设备最大纹理尺寸 16384；较小上限的设备会明确报错，尚未覆盖其他平台。

最终可见 Windows 构建运行在 NVIDIA GeForce RTX 4060 Ti，七张纹理均报告 RGB24、`isReadable=false`。`Profiler.GetRuntimeMemorySizeLong` 合计 **210.55 MiB**，其中设施图 **105.06 MiB**，完整逐图统计见可见验收的 `result.json`。

编辑器初测合计约 348 MiB（设施约 184 MiB），与 Player 环境统计不同。这些数值是对应环境的运行对象统计，不能等同于精确显存、压缩文件大小或只计算 RGB24 像素。本次不宣称整图比旧图节省显存；其他设备和平台尚未验证。

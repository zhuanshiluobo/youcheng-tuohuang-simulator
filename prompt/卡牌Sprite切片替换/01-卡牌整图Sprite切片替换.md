## 1. 任务目标与范围

请在当前 Unity 项目中，将以下四类卡牌的正面图片替换为原始整图的 Unity Sprite 切片：

- 城市样式牌：I 级、II 级。
- 事件牌：绿色、黄色、红色。
- 设施牌：普通设施、三色延伸枢纽、四张核心指挥塔、三色企业办事处。
- 角色牌：基础角色及企业扩角色。

所有原图均位于 `游城拓荒/素材/`。使用完整原图与切片定义，不再为每张卡输出单独的 JPG／PNG。目标是实际消费 Sprite 切片，不得只改文件名或导入设置，也不得未经说明改成只使用 RawImage UV 的另一套方案。

本任务不包含地图、地图交互与高亮、地图坐标、牌背、城市面板、资源图标或其他界面换新。原有界面位置、尺寸、样式和静态文案继续以当前场景及预制体为准。

执行时重新读取尺寸；若原图已变更，先核对内容再更新切片，不要沿用错误尺寸。

对行号 r、列号 c（均从 1 开始），原图高 H、单格宽 w、高 h，Unity 左下角原点下的切片矩形为：

```text
x = (c - 1) × w
y = H - r × h
rect = (x, y, w, h)
序号 = (r - 1) × 总列数 + c
```

采用矩形完整切片，保留牌面全部内容。不要旋转、镜像、自动裁去文字区域或用紧边网格切掉边缘。保持稳定的 Sprite 名称和标识，重复导入不得打乱卡牌引用。

## 8. Sprite 接入要求

1. 为上述七张原图建立可维护的 Sprite 切片资源和映射。优先使用 Unity Sprite Editor／Sprite Mode = Multiple 的持久化子资产；需要把原图放入可导入目录时，复制完整原图并记录源路径，不修改源文件。
2. 与当前外部内容架构兼容：规则定义和扩展关系继续通过稳定 ID 关联视觉资源。若必须保留外部整图运行时替换能力，可以用“整图＋切片矩形”创建并缓存 Sprite，但须明确与编辑器持久化切片的关系、唯一映射来源及生命周期，避免两套数据漂移。不得只读取整图 Texture 却忽略切片区域。
3. 保留数据、Lua 规则与 Unity 表现层的边界，不向纯规则层引入 UnityEngine.Sprite。检查 artwork 字段解析、模板展开、内容校验／哈希、资源释放及构建后的实际加载路径。
4. 正面显示链路统一消费 Sprite，优先调整为 Image.sprite；同步迁移序列化字段、预制体组件和调用接口。特殊渲染入口若保留 RawImage，必须从 Sprite 正确取得切片区域，不能只取 sprite.texture 后显示整版图。
5. 全面覆盖卡牌列表、手牌、供应区、选择弹窗、卡牌详情、城市样式预览、设施预览、拖拽预览和事件选项界面。显示宽高比取切片尺寸，不再取整图尺寸；事件选项点击区域和卡面覆盖标记仍以单张牌面为坐标范围。
6. 同一张整图共享纹理；同一切片按稳定标识缓存。不在每次打开弹窗或每帧重新切图、复制纹理或创建 Sprite。运行时创建的对象必须正确释放。
7. 检查最大纹理尺寸、缩放、压缩和过滤，尤其设施整图为 5400 × 5100。不得套用单张卡图的 2048 上限后无意降低文字清晰度。核对缩放后的矩形、边缘串色、透明区域和目标平台内存，不直接宣称整图一定更省内存。
8. 旧拆图脚本不应继续参与新的卡图生产链路。完成引用迁移后，必须按第 11 节核验并删除本次被替代的旧单张正面贴图及其对应 .meta，再进行最终运行和构建验收。不能依赖旧图回退，也不能把旧图移到 Resources／StreamingAssets 的其他目录继续打包。

## 9. 企业扩归属与规则边界

- 明确登记：I 级城市样式第 5～8 格、II 级第 3～4 格、角色第 6～7 格、设施第 49～51 格、黄色事件第 12 格、红色事件第 7 格属于企业扩。
- 基础模式不混入企业扩独有牌。扩展开启时按现有扩展配置启用对应定义，并正确应用两组事件替换关系。
- 优先复用现有 expansionId、replaces 和配置入口，不新增孤立的界面布尔开关，不在多个控制器中硬编码扩展判断。
- 替换版本的图片与规则定义必须一致，不能展示企业选项版牌面却执行基础版本效果。
- 本任务未提供缺失扩展卡的完整规则。若某张扩展卡尚无有效规则实现，应完成切片与映射登记，明确记录未接入原因；不得凭牌名编造规则、默认复用另一张卡的行为，或将不可玩的卡悄悄混入牌池。资源切片完成与完整企业扩可玩必须分开报告。

## 10. 场景和预制体保护

- 仅对本任务涉及的卡图组件、字段和引用进行必要迁移，说明每项修改属于场景覆盖还是源预制体修改。
- 保留现有界面布局、大小、锚点、装饰样式、静态文案与交互流程。不通过运行时固定赋值覆盖用户编辑的静态配置。
- 不运行整套界面或弹窗 Rebuild／重新生成工具来代替定点迁移；测试、构建前检查不得生成或保存覆盖界面资产。

## 11. 验证与交付

### 旧单张贴图清理：最终验收的必做项

完成标准是：**四类牌面使用原始整图的 Sprite 切片；已被替代的旧单张贴图已删除；删除后实际游戏与新构建仍正确显示、交互。** 只有“新增切片”或“旧图零引用”均不算完成。

# NMC-003：事务、序列化与运行状态底座

## 任务提示词

你负责实现新架构最底层的权威运行状态、稳定 ID、可序列化 DTO 与外层事务发布机制。此任务必须保持现有命令行为可用，并为后续 EffectExecutor 提供底座；不要提前实现完整 Effect 树。先完整阅读 `prompt/00-共同执行约束.md`、Lua 权威文档和 `NMC-001` 的测试治理记录。

## 前置任务

`NMC-001` 已完成并有可复用的测试基线与 fixture。

## 目标

1. 在无 Unity/无 Lua 依赖的层定义 `EffectRuntimeState`、节点运行记录、规则事件/提交记录及受限归一化值类型。
2. 实现全量、可验证的 `GameState` 深克隆，为一次外部命令建立工作副本。
3. 让 `GameSession.Submit` 或等价权威入口只在外层命令成功时原子发布工作副本；失败时状态、revision 和日志序号都不泄漏。
4. 建立稳定 SHA-256 ID 生成规则与统一 `RuleCommit` 边界。

## 必读代码

- `GameState`、`GameSession`、`AuthoritativeCommandDispatcher`
- 当前 clone/copy/serialization、网络 DTO 与测试工具
- 所有直接递增 revision、追加日志或绕过 `GameSession` 修改权威状态的入口

## 实施要求

1. 运行状态最少支持设计文档要求的版本、`activeMainNodeId`、节点列表、待处理交互/continuation 引用、事件/分发记录、日志序号和 `paused_fault` 状态。持久字段使用显式类/struct 与 List，不存储接口实例、委托、`object`、Lua table、Unity 对象或不稳定字典。
2. 归一化动态值采用带 tag 的封闭 DTO，并限制深度、元素数量、字符串和数值范围；序列化后必须能够确定性比较或哈希。
3. 稳定 ID 使用完整 SHA-256 输入规范；明确命名空间、字段顺序、编码、空值和序号规则。不得使用 `GetHashCode`、随机 GUID 或截断哈希充当可恢复身份。
4. `RuleCommit` 表示一次内部逻辑提交并递增 `stateRevision`；在一个外部命令工作副本内可以发生多个 commit。若外部命令最终失败，工作副本中的 revision、事件、日志和节点变化全部丢弃。
5. `GameState` 深克隆必须覆盖现在和新加的所有权威字段，且集合元素不与原对象共享可写引用。建立会在未来新增字段遗漏时失败的完整性保护测试。
6. 迁移 `GameSession.Submit` 时保持旧命令成功/失败对外合同；不得让旧 dispatcher 与新事务包装各自提交一次。
7. 搜索直接状态写入、revision 和日志入口。只清理已被新入口完全替代且零调用的路径；仍被旧业务使用的适配器必须登记调用方和后续删除任务。

## 测试精简要求

- 用状态快照/场景表统一覆盖：成功原子发布、外层失败回滚、多内部 commit、序列化 round-trip、clone 隔离、稳定 ID 和非法归一化值。
- 合并现有 `GameSession`、命令 dispatcher、clone 与网络序列化中重复验证“成功提交/失败不变”的测试。
- 不为每个 `GameState` 字段手写一份 clone 测试；使用反射完整性检查加少量深层集合代表用例。
- 完成后运行相关过滤测试和完整 EditMode，记录用例净变化。

## 非目标

- 不实现 Effect 节点调度、事件响应、Lua Host 或业务 Effect。
- 不删除仍由现有生产链路真实使用的 legacy pending 字段。
- 不在 Domain/Application 引入 Unity 或 Lua 依赖。

## 验收标准

- 状态 DTO 可序列化 round-trip，稳定 ID 在相同输入下跨运行一致。
- 任意外部命令失败后，对提交前状态做深比较完全相同，包含 revision、日志序号和运行时状态。
- 成功命令只原子发布一次，现有命令回归无新增失败。
- clone 完整性机制能捕捉未来新增但未复制的权威字段。
- 清理清单与暂留适配器都有 `rg` 证据，完整 EditMode 通过，`git diff --check` 通过。

## 交付报告

说明权威状态形状、事务边界、ID 输入规范、序列化限制、被迁移的写入口、保留适配器及其后续任务编号，并报告完整测试数字和相对 `NMC-001` 基线的变化。

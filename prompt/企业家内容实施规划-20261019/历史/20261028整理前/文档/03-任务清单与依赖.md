# 任务清单与依赖

下列19项是可独立审查和派发的工作包，不是19个必须新建的类／界面／提交。预计规模较大，以依赖和证据分批，不编造工时或承诺单局覆盖全部内容。

## 推进阶段

1. **规则与合同**：QY-001冻结优先级、版本、API边界与实际歧义。RK-01—05已获用户直接确认，按01落实，不再设置相关规则审批门槛；J-Q01的49原图、追加塔、U05未选A面和帮派表现已按用户确认登记，既定表现接线与实际验收仍由017完成，不再把已确认用途当待批阻塞。
2. **公共前置**：QY-002统一来源与旧入口→QY-003区域／轨道／颜色→QY-004模式和正式实体。QY-005能力载体提供后续物品基础。
3. **通用机制**：QY-006离场／挂链，QY-007付款，QY-008重复收尾，QY-009采集／城市候选，QY-010分层建设，QY-011终局合约。按下表各自前置完成，不强迫无关接口串行重写。
4. **Lua内容**：QY-012第五号、013艾格尼丝、014蒂亚戈、015保罗、016马丁。选择第五号先贯通是降低集成风险的建议，不允许因它较简单就只交付这一位。
5. **页面与汇合**：QY-017完成内容/素材绑定与既有通用UI消费，按U链验收Lua组合结果，不继续按企业家补C#内核或专用路由；QY-018汇合各任务已同步实现的恢复和联机。素材盘点可早做，正式页面接线要等对应合同；不能先画新链路后要求内核适配。
6. **正常交付**：QY-019正常可见程序多局累积验收，核账全部来源和实际缺口。

## 共同完成标准

每项完成至少有：真实实现／内容文件、版本化接口或状态变更、主责来源逐条映射、必要隔离／回归检查、恢复证据和未覆盖记录。宣称“页面交付”另需正常可见程序证据与实际资产视觉检查。主责任务负责语义闭环，关联任务负责自己的接口，不可互相假设对方已做。

“依赖完成”须能指出接口、版本及检查结果，不能仅看上游创建了文件。未完整可执行的企业家模式在正式入口继续明确拒绝；内部隔离定位不等于开局可玩。全部卡面脚本、必要配件、U链路和要求的恢复／正常验收完成后才允许称完整交付。

任务编号不要求创建新的聊天；本次只交付提示词，未给任何执行者自动派发或启动实施。

# 卡牌资料表维护

主表：`ConfigTables/卡牌资料.xlsx`。

采用“效果说明＋Lua 脚本路径”。表格维护资料和执行脚本引用，Lua 文件独立维护。运行时继续读取现有 JSON 与 Lua，Excel 不进入玩家程序，也不由游戏运行时解析。

## 使用

1. 编辑相应工作表并保存。内部编号保持不变，允许调整列顺序，但不要改工作表名和表头。
2. 停止 Unity 运行，等待编译完成，执行 **游城 → 卡牌 → 导入项目资料表**。也可选择外部资料表导入。
3. 再次进入游戏，查看更新后的资料和效果。需要发布新资料时，导入后再构建。

导入只在手动执行菜单时进行。未列出的卡牌保留，不通过删除行移除内容。第一版维护已有卡牌；新增卡牌须先登记现有内容包清单及必要执行入口。表格管理的字段统一从表格修改，直接修改对应 JSON 后再导入旧表，会恢复为表内值。

## 工作表

| 工作表 | 用途 |
| --- | --- |
| 角色牌 | 名称、卡面图片、角色说明、策略／计谋名称与说明、执行脚本、版本、收尾脚本。 |
| 事件牌 | 名称、描述、卡面图片。 |
| 事件选项 | 根据事件编号和从 1 开始的选项序号维护选项说明；保留实际奖励与后续效果。 |
| 设施牌 | 每种设施一行，维护共用名称、描述、效果说明及脚本路径，沿用原设施模板和数量。 |
| 设施卡面 | 每张实体牌一行，维护图片引用。设施类型和颜色用于定位，名称列仅供查阅。 |
| 城市样式牌 | 名称、宣告说明、特殊行动说明、卡面图片、脚本路径及版本。 |

图片和脚本路径相对于 `Assets/StreamingAssets/Content/core`，例如 `artwork/character/elysium.jpg`、`lua/characters/elysium.strategy.lua`。

导入更新现有 JSON 的指定字段，保留编号、能力 ID、订阅 ID、选择结果处理入口、扩展和替换声明、费用、奖励、数量等其余配置。设施资料以清单组的差异字段覆盖模板，不修改共用模板文件。所有行在写回前校验；公式应先粘贴为值。

## 自行维护效果脚本

通过 **游城 → 卡牌 → 打开效果脚本目录** 找到 Lua 文件，使用文本编辑器编辑并保存为 UTF-8。导入器会检查引用文件及 Lua 语法，不生成或覆盖 Lua 文件。

例如极境策略文件 `lua/characters/elysium.strategy.lua` 中的 `amount = 4` 控制获得量。需要改成 5 时：

1. 在 Lua 中修改实际获得量。
2. 在角色牌工作表中同步修改“策略说明”，并更新“策略版本”。
3. 保持“策略脚本”引用该文件，导入并重新进入游戏。

新脚本也可放到内容包的 `lua` 目录中，再填写其相对路径。沿用已有能力的调用约定及 `PlayerData`、`Effect` 接口；复杂选择还要遵守原来的完成结果处理流程。新增宿主尚未支持的 Effect 仍需实现 C# 接口。

多个卡牌引用同一个 Lua 文件时，修改该文件会影响所有引用者。需要某张牌单独变化时，先复制脚本并在表中改为新路径。部分通用设施脚本从既有卡牌数据读取参数，修改说明或改路径不会自动改变模板中的奖励、费用等数据。

事件牌目前通过 JSON 的奖励和后续效果执行，本版只维护事件资料及选项说明，不新增事件 Lua 入口。

## 展示和存档边界

名称、已有动态描述、事件选项以及卡面图片引用使用导入后的资料。角色说明、策略／计谋名称和说明保存为 JSON 资料字段；当前角色查看器展示整张卡面图片，没有新增文字控件。

卡面图片中的文字不会因修改表格而自动重绘。需要同步修改卡面时，另行修改图片并保留原版式。界面布局、静态标题和按钮名称继续由场景、预制体维护，导入不覆盖这些资产。

内容资料、脚本和图片均参与现有内容包哈希。修改内容后，原包未完成的对局须使用原包恢复。编辑器的语法检查只验证脚本可编译，实际选择、支付和结算行为需要进入游戏查看。

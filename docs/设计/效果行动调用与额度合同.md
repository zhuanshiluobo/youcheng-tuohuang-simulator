# 效果内行动调用与额度

`Effect.InvokeAction` 由正在执行的效果调用当前玩家可用的真实行动：

```lua
Effect.InvokeAction({
    apiVersion = 1,
    player = ctx.playerId,
    itemId = action.itemId,
    actionId = action.actionId,
    omitEntryCost = true,
    omitEntryAfterEffects = true,
    omitMainAction = true
})
```

三个 `omit` 参数均为可选布尔值，省略时为 `false`：正常支付入口费用、执行入口后置效果，并在目标行动需要时消费相应行动额度。只有规则明确豁免时才传入 `true`；它们不豁免目标的使用次数、实际来源、占用或其他合法性条件。调用时不需要在来源或目标上登记调用许可；旧的 `callPolicyRef`、`actionCallPolicies`、`directCallPolicy` 和 `action.invoke:*` 不再是调用合同，内容须迁移到效果参数。

`SourceData.GetCallableActions` 支持按 `actionId`、`itemId` 和 `sourceKey` 筛选，并使用 `nextCursor` 读取全部页。候选查询提供来源、次数和占用状态；实际调用会结合该效果的费用与行动消费参数再次检查，不能把查询结果当作已付费或已消费次数。保存中的调用保留这些参数及实际收据，恢复时不重新扣费。

授予主要行动额度时，`allowedActionTypes` 为空表示不限制类型；非空列表可组合 `deploy`、`dispatch`、`explore`、`move_city`、`build`、`special`。各批额度分别保存允许类型和剩余次数。执行时优先消耗允许范围最窄的匹配批次，范围相同时按授予顺序消费；不存在匹配批次时不能发动对应行动。

离场响应的挂载类型由来源定义的 `responseKinds` 声明，取值为 `response.destination`、`response.self`、`response.optional_effect`、`response.batch` 或 `response.required_effect`；它们是响应调度信息。行动调用不使用该字段授权。

本次移除的是行动调用相关的 `action.invoke:*` 登记。`allowedOperations` 中其他用途的声明仍供相应机制使用，例如载体内物品转移、奖励创建和计分；它们不再参与 `Effect.InvokeAction` 的调用许可判断。

此合同改变了内容和执行器身份。旧版存档中的行动调用记录，包括已完成的历史记录，不会自动补写新费用参数；旧 `callPolicyRef` 调用也不会按新合同解释。旧存档能否恢复须使用匹配的内容和执行器版本验证，不能直接假定兼容。

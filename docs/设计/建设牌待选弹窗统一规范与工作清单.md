# 建设牌待选弹窗统一规范与工作清单

- 文档状态：实现中，规则与表现层修改已落盘；自动化与构建验收待完成
- 编写日期：2026-07-22
- 范围：默认供应区 `building_001`～`building_041`

## 1. 目标

建设牌产生玩家选择时，必须先建立 Host 权威的待选会话，再由统一弹窗组件收集输入。不能因为当前没有某一类地图目标而静默跳过整张卡，也不能让表现层自行决定规则分支。

## 2. 需要待选交互的建设卡

默认供应区共有 9 个牌族、23 张卡需要玩家输入：

| 弹窗类型 | 建设卡 | 卡号 | 输入内容 |
| --- | --- | --- | --- |
| 通用选项 | 附属能源设施 | 004～006 | 选择十字相邻设施 |
| 建设工作流 | 简陋工程营 | 010～011 | 选择设施、槽位与资源/金券支付 |
| 卡牌选择 | 物流枢纽 | 012～013 | 选择延伸枢纽或放弃 |
| 资源分配 | 贸易街区 | 019～021 | 选择出售数量或放弃 |
| 地图目标 | 高性能动力设施 | 025～026 | 选择免费移动目标 |
| 资源分配 | 开采电铲 | 029～031 | 在三种基础资源间恰好分配 5 个 |
| **互斥分支** | **佣兵指挥部** | **034～036** | **替换 1 个影响力，或放置 1 个影响力** |
| 地图多选 | 护航调度中心 | 037～038 | 选择两个合法部署槽位 |
| **互斥分支** | **载具仓库** | **039～041** | **移除后调度，或探索** |

其余建设卡为即时奖励、唯一性、被动费用或收尾效果，不创建玩家待选弹窗。

## 3. “或”选项的统一规则

### 3.1 互斥分支

佣兵指挥部和载具仓库必须共用 `ShowOrBranchOptions`：

1. 一级弹窗始终展示牌面上的两个分支。
2. 当前不能执行的分支保留显示但置灰。
3. 选择分支后，才进入地图目标或探索子流程。
4. 子流程允许返回一级分支，不能清除权威待选会话。
5. 两个分支都不可执行时，显示两个禁用选项与“关闭”；关闭通过权威 `skip` 选项完成结算。

### 3.2 数量组合

开采电铲牌文中的“或”表示三种资源可以任意组合，总量必须恰好为 5，不是互斥二选一，因此继续使用共享资源分配弹窗。

### 3.3 建设费用

默认供应区 41 张建设牌均支持资源/混合费用或纯金券支付。支付仍属于建设草稿工作流，不转换成设施入场待选会话；普通建设统一由建设聚焦弹窗处理，简陋工程营的额外建设复用相同的支付方式语义与权威校验。

## 4. 佣兵指挥部权威协议

- 保留 `ChoiceType = ReplaceOneInfluence`，避免无必要的序列化协议迁移。
- 一级 `OptionIds` 只允许 `replace_influence`、`deploy_influence`；两者都不可执行时只允许 `skip`。
- 地图槽位不再塞入一级 `OptionIds`，统一使用 `targetInfluenceSlotId` 参数。
- 替换目标必须是当前存在的对手影响力；放置目标必须通过 `InfluenceService.CanPlace`。
- Host 在提交时重新校验分支和目标。非法分支、缺失目标、已过期目标均不得清除待选会话或部分写入状态。
- 替换沿用“先移除，再尽量在原槽位放置”的规则；因供应或对手城市阻挡无法放置时，已完成的移除不回滚。

## 5. 本次根因

运行时 manifest 把佣兵指挥部牌面的“替换或放置”错误简化为“替换 1 个影响力”。领域层又只枚举对手影响力，并在候选为空时不创建 `PendingCardSession`。因此没有对手目标时，即使存在合法放置槽位，也不会生成弹窗；这不是单纯的样式遮挡问题。

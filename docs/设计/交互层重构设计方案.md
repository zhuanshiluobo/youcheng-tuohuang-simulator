# 交互层重构设计方案

- 文档状态：设计提案（待审批后实施）
- 编写日期：2026-07-27
- 目标：统一交互编排架构 + 改善关键动作操作体验
- 范围边界：仅重构 `Assets/YC/Presentation` 交互编排层；不改动 `Domain` 规则、命令处理器与联机快照契约

## 1. 现状诊断（带证据）

当前交互层约 2.8 万行，分层意图良好（Domain 纯净、命令模式、Workflow 程序集无引擎依赖），但**交互编排存在两套并行状态机，靠主控制器手工缝合**。

### 1.1 两套互不知情的交互系统

- 系统 A：`InteractionFlowCoordinator` + `IInteractionWorkflow`，管主要/快速行动。`MapInteractionRouter.OnLocationClicked` 按 `coordinator.CurrentMode` 做 switch（`MapInteractionRouter.cs:88-97`）。
- 系统 B：一组 `*UiCoordinator`（设施/特殊行动/角色牌待选），由领域 `PendingSpecialAction` / `PendingCardSession` / `PendingCharacterEffect` 驱动，各自实现 `IsActive` / `TryHandle*Clicked` / `Synchronize`，**未注册进 flowCoordinator**（`SpecialActionInteractionUiCoordinator.cs:75-192`）。

两套系统靠 `MobileCityInteractionController` 手工链条缝合。`OnHotspotClicked` / `OnInfluenceSlotClicked` / `OnMobileCityClicked` 各硬编码一条固定优先级责任链（`MobileCityInteractionController.cs:268-323`）：

```csharp
if (specialActionInteraction.TryHandleLocationClicked(id)) return;
if (characterMapInteraction.TryHandleLocationClicked(id)) return;
if (facilityEffectInteraction.TryHandleLocationClicked(id)) return;
mapInteractionRouter.OnLocationClicked(id);
```

**新增一个可交互协调器，就要改三个点击入口。**

### 1.2 `IInteractionWorkflow` 抽象过薄 → Presenter 变上帝对象

接口只有 `Mode / Activate / Cancel`（`IInteractionWorkflow.cs:3-11`），不承载点击处理、能否开始、内部状态。结果 `TurnActionPresenter` 膨胀到 **1461 行**，一类塞入移动、探索、部署、调度、建设、样式宣告、特殊行动、结束行动、入场选点、采集委托。仅"建设"就有 **13 个方法**（`TurnActionPresenter.cs:364-600`，含 `BeginBuildAction` / `TryOpenBuildDraft` / `BeginBuildFacilityDrag` / `DropBuildFacility` / `RejectBuildFacilityDrop` / `BeginGhostBuildFacilityDrag` / `HandleBuildFacilityEscape` / `SelectBuildFacilityPayment` / `BackToBuildFacilityPayment` / `CancelBuildFacility` / `ConfirmBuildFacility` / `BuildBuildFacilityDraftViewModel` / `BuildBuildFacilityAvailabilityViewModel`）——建设本身是独立的多步草稿状态机，却寄生在回合行动 Presenter 内。

### 1.3 `InteractionMode` 扁平枚举，三类职责混杂

15 个值（`InteractionMode.cs:3-21`）混合了：动作选择态、单动作内部子步骤（`ResolvingBuild*` ×3、`ResolvingDispatch*` ×3）、阶段等待态。新增多步动作要往全局枚举加子步骤，所有 switch 跟着改（如 `TurnActionPresenter.cs:1411-1423`、`MapInteractionRouter.cs:88-96,215-237`）。

### 1.4 每个 Presenter 各造 View 接口，ViewModel 塞满回调

`WorkflowPorts.cs` 中 `IResourceCollectionView` / `IInfluenceActionView` / `IExplorationEventView` / `ITurnActionView` 四套接口重复定义 `RefreshActionPanel` / `RefreshFromState` / `ShowPrompt` / `CompleteAction`。ViewModel 变回调口袋——`BuildFacilityDraftViewModel` 构造吞 9 个 `Action`（`WorkflowPorts.cs:129-186`）。

### 1.5 命令提交样板到处复制

`commandPort.Submit(...)` 后重复 `!Succeeded→ShowPrompt` / `!AppliedLocally→"已发送给主机"` / else 刷新。仅 `TurnActionPresenter` 就出现 6+ 次（行 155、198、266、502、948、977）。

### 1.6 本地玩家归属不清

`SynchronizeLocalPlayerForHotseat()` 在近 10 个方法开头防御性调用，"当前谁是本地玩家"无清晰所有者。

### 1.7 高亮构建重复

`SpecialActionInteractionUiCoordinator` 自建 `BuildInfluenceHighlights` / `BuildLocationHighlights`（`.cs:360-394`），与工作流层的高亮语义重复。

## 2. 目标架构

核心：**把两套状态机合并为一套，让"交互"成为一等公民，由单一路由器 + 注册表驱动。**

### 2.1 统一交互契约

```csharp
public interface IInteraction
{
    string Id { get; }
    InteractionPriority Priority { get; }          // 待选结算 > 进行中动作 > 默认路由
    bool IsActive { get; }                          // 由领域状态或自身草稿派生

    InteractionResult OnLocationClicked(string locationId);
    InteractionResult OnInfluenceSlotClicked(string slotId);
    InteractionResult OnMobileCityClicked();
    InteractionResult OnEscape();

    InteractionPresentation BuildPresentation();    // 高亮 + 提示 + 面板显示态，一次性产出
    void Cancel();
}
```

- `InteractionResult`：`Consumed` / `Passthrough` / `RejectedWithPrompt(reason)`。取代散落的 bool + 副作用。
- `InteractionPresentation`：`Highlights` + `PromptText` + `PanelMode`，纯数据。取代各协调器分别调用 `setHighlights` / `setPrompt`。

### 2.2 单一路由器 + 注册表

```csharp
public sealed class InteractionRouter
{
    // 按 Priority 排序的注册表；不再硬编码 TryHandle 链
    void Register(IInteraction interaction);
    void OnLocationClicked(string id);      // 遍历 active 项，首个 Consumed 即停
    void OnInfluenceSlotClicked(string id);
    void OnMobileCityClicked();
    void OnEscape();
    InteractionPresentation BuildActivePresentation();
}
```

`MobileCityInteractionController` 的三个点击入口收敛为直接转发给 `InteractionRouter`，**新增交互 = 注册一个 `IInteraction`，不动控制器**。

### 2.3 待选结算纳入同一契约

设施/特殊行动/角色牌/事件的待选，从领域 `PendingXxx` 状态派生 `IInteraction` 实现（`PendingResolutionInteraction` 家族），注册进同一 `InteractionRouter`，`Priority` 高于进行中动作。**消灭"两套状态机手工缝合"**。

迁移策略按协调器分工差异区分：

- `SpecialActionInteractionUiCoordinator`：直接包装为 `IInteraction`，`inFlightCommandId`+`inFlightSessionId` 在途追踪逻辑随之迁入；`NotifyCommandSettled` 方法必须保留（测试有断言）。
- `FacilityEffectInteractionUiCoordinator`：内含 13 阶段内部状态机与额外建设草稿分支，包装为 `IInteraction` 时保留其内部状态机，不强行拆平；`OfferSecondEffect=true` 注入路径必须保留。
- `CharacterCardEffectInteractionUiCoordinator` + `CharacterMapInteractionCoordinator`：两者是**分工关系**而非同构——前者管弹窗/非地图效果，后者管地图点击。迁移时将两者合并为一个 `CharacterCardInteraction : IInteraction`，内部委托给原有两个协调器；地图点击路由经 `OnLocationClicked` / `OnInfluenceSlotClicked` 转发给 `CharacterMapInteractionCoordinator`，弹窗/非地图效果由 `CharacterCardEffectInteractionUiCoordinator` 处理。锡人 pending 必须携带 `SourceCommandId`（测试约束）。

**在途命令追踪统一**：当前只有 `SpecialActionInteractionUiCoordinator` 有 `inFlightCommandId` 追踪，其余协调器无此保护。`IInteraction` 契约层应统一提供 `NotifyCommandSettled(string commandId)` 方法（默认空实现），需要追踪的实现类覆盖它；`InteractionRouter` 在命令结算时广播给所有注册项。

### 2.4 子步骤局部化，收窄全局枚举

全局 `InteractionMode` 缩为 4 个粗粒度值：`Hidden / ChooseAction / Busy / WaitingForNextPlayer`（仅供面板显示）。建设的 `Card→Focus→Confirmation`、调度的 `Source→Target→Decision` 下沉为各自 `IInteraction` 的私有状态。

### 2.5 CommandGateway 收敛提交样板

```csharp
public sealed class CommandGateway
{
    // Submit → 判 Succeeded/AppliedLocally → 统一提示 → 触发刷新回调
    SubmitOutcome Submit(GameCommand command, SubmitCallbacks callbacks);
}
```

调用点从 6 行降为 1 行；"已发送给主机等待确认"文案单点维护。

### 2.6 拆分 TurnActionPresenter

- `BuildInteraction`（建设草稿多步机，独立 `IInteraction`）
- `DeployInteraction` / `DispatchInteraction`（复用现有 `InfluenceActionPresenter` 逻辑，包装为 `IInteraction`）
- `MoveInteraction` / `ExploreInteraction`
- `TurnActionPresenter` 瘦身为纯动作分发 + 面板 ViewModel 构建，目标 ≤400 行。

### 2.7 统一 View 与意图通道

- 单一 `IInteractionView`（`SetHighlights` / `ClearHighlights` / `ShowPrompt` / `RefreshPanel`），特化能力用小接口按需组合。
- ViewModel 回调收敛为 `dispatch(Intent)` 单通道，Intent 为密封类型（`BeginDrag(id)` / `Drop(slot)` / `SelectPayment(mode)` / `Confirm` / `Cancel`…），取代 9 个裸 `Action`。

### 2.8 本地玩家归属单点化

引入 `LocalPlayerResolver`，热座切换逻辑集中一处；`IInteraction` 从 context 读取，去掉每方法开头的 `SynchronizeLocalPlayerForHotseat` 散调用。

## 3. UX 改善（第二目标）

依据 `docs/设计/建设交互流程需求.md`，把建设从"弹窗式"升级为"拖放 + 聚焦 + 本地虚影"：

1. 点击建设 → 进入本地建设模式，公共牌堆置灰非法卡并显示原因。
2. 拖动公共建设牌 → 己方面板合法槽位高亮，非法槽位显示禁止标识。
3. 落到合法槽位 → 建设聚焦态：卡牌放大、显示费用/分数/效果、支付提示。
4. 选支付方式 → 最终确认摘要（返回修改 / 确认建设）。
5. Esc 缩回虚影（不取消）；明确的 `× 取消建设` 按钮彻底取消。
6. 确认成功前全为当前玩家本地状态，其他玩家不可见；确认成功后一次性同步。

同步复核特殊行动拖拽落区视觉、无目标二次确认、弹窗遮挡、可收起地图提示（对应 `特殊行动实现规格` §8.1 未完成的人工验收项）。

## 5. 风险与约束

- **必须尊重** `MobileCityInteractionArchitectureTests`：控制器核心职责的架构预算 ≤1200 行；该预算统计 `MobileCityInteractionController.cs` 与 `.CharacterCards.cs`，明确排除 `.RightCardSmoke.cs`。被排除的 `RightCardSmoke` 仍实际参与生产编译，三个 partial 也都继续接受危险模式扫描。另须保持无 `new GameCommand`、不直接写 GameState、Workflow 程序集 `noEngineReferences: true`、`RefreshAllFromState` 不含 Begin/Activate/Reset/Cancel/Hide。
- 联机不变量不动：Host 唯一结算、`AppliedLocally` 语义、在途命令去重（`inFlightCommandId`）逻辑完整迁移，不得丢失。`IInteraction` 契约统一提供 `NotifyCommandSettled(string commandId)` 默认空实现，`InteractionRouter` 在命令结算时广播；标准建设、设施待选与特殊行动均已实现命令/会话双键追踪。
- 快照恢复路径（断线重连恢复待选步骤）必须在 `IInteraction` 化后保持等价。
- `FacilityEffectInteractionUiCoordinator` 内含 13 阶段内部状态机与额外建设草稿分支，迁移时保留其内部状态机，不强行拆平；`OfferSecondEffect=true` 注入路径必须保留（测试约束）。
- `buildFacilityInteraction` 已收口为设施待选协调器之后的唯一一次初始化，并由架构测试固定初始化顺序与构造次数。
- 每阶段独立可提交、可回滚；任一阶段测试转红即停止并诊断根因，不叠加补丁。

## 6. 预期收益

- 新增一个可交互动作/待选：从"改 3 处点击入口 + 加全局枚举值 + 改多个 switch"降为"实现并注册一个 `IInteraction`"。
- `TurnActionPresenter` 1461 → ≤400 行；建设逻辑内聚为独立单元。
- 提交样板、高亮构建、本地玩家归属各自单点化。
- 建设与特殊行动达到设计文档描述的目标操作体验。

## 7. 实施结果（2026-07-27）

- 统一 `IInteraction`、`InteractionRouter`、四值 `InteractionMode`、`CommandGateway` 与 `LocalPlayerResolver` 已落地；`BuildInteraction / DeployInteraction / DispatchInteraction / MoveInteraction / ExploreInteraction` 五类主要行动交互按优先级直接注册，`InfluenceActionPresenter / ExplorationEventPresenter` 仅保留被包装的流程逻辑，不再直接注册为交互；旧地图适配器只保留末级兼容转发。
- `TurnActionPresenter` 保持 400 行。Controller 架构预算口径为 1191 行（主文件 996 + `CharacterCards` 195）；`RightCardSmoke` 358 行作为开发展示适配被门禁特例排除，因此所有实际编译 partial 的原始合计是 1549 行，不能把 1191 表述为生产编译总量。
- 角色牌设施供应选择已纳入活跃判断和统一 Esc；标准建设与设施待选等待 Host 时均防重复提交，并在匹配结算、新会话、无结果、拒绝或异常时正确解锁。
- 行动按钮具备 0.08 秒缩放至 0.92 与青色描边反馈；地图合法目标使用 0.6 秒、alpha 0.4～1.0 的青色边框脉冲；确认落点播放 0.15 秒 1.2→1.0 闪光与向外扩散圆环；地图桌面使用 `(0.08, 0.10, 0.12, 1)` 深石板灰。
- 完整 EditMode 基线为 `813/813 Passed`（`Logs/EditModeTests/editmode-20260727-interaction-split-final.xml`）：架构 `28/28`、影响力交互 `10/10`、探索交互 `12/12`、回合交互 `39/39`、地图路由 `7/7`、设施待选 `21/21`、部署反馈 `5/5`。

# 行动实现方案

本文档维护“主要行动、快速行动、待选与结束行动”的规则和表现层契约。当前实现状态以 `docs/概览/项目总览.md` 为准。

## 1. 规则目标

在玩家行动阶段，每名玩家在自己的行动轮中：

- 初始拥有 `1` 点主要行动预算，通常必须完成 `1` 个主要行动。
- 可以在主要行动前后执行任意次数快速行动。
- 主要行动进行中不能插入快速行动。
- 主要行动只有在完整结算后才消耗 `1` 点预算；多步行动在最后一步完成时消费。
- 源石工业中枢先消耗原有 `1` 点预算，再授予 `2` 点额外主要行动预算；两次额外主要行动之间允许快速行动。
- 完成至少一个主要行动后，玩家可以提交 `EndAction`，放弃尚未使用的额外预算。
- 玩家提交 `EndAction` 后，行动轮才推进到下一名玩家或下一行动轮。
- 快速行动执行后，不推进当前玩家。

基础版主要行动包括：

- 部署。
- 调度。
- 探索。
- 城市移动。
- 建设。
- 特殊行动。

基础版快速行动包括：

- 使用角色牌。
- 宣告城市样式。

## 2. 核心区别

主要行动和快速行动的区别应由规则状态控制，而不是只靠 UI 禁用按钮。

| 类型 | 是否必须 | 是否消耗预算 | 是否受行动轮限制 |
|---|---|---|---|
| 主要行动 | 通常至少完成 1 次 | 完整结算后消耗 1 点 | 受剩余主要行动预算限制 |
| 快速行动 | 否 | 否 | 按具体规则限制次数 |

因此：

- 主要行动成功结算后，由统一预算服务消费次数，不立即推进玩家。
- 仍有额外预算时继续显示主要行动入口；玩家也可以提前结束并放弃剩余额外预算。
- `EndAction` 成功结算后，才调用回合推进逻辑。
- 快速行动成功结算后，只刷新当前状态和 UI。
- 存在待选择项时，只允许提交对应待选类型的结算命令，不允许开始新行动。

## 3. 状态字段

当前工程以以下字段作为玩家行动轮事实源：

```csharp
GameState.Phase
GameState.CurrentPlayerId
GameState.PendingCardSession
GameState.PendingCharacterEffect
GameState.PendingSpecialAction
PlayerState.RemainingMainActionsThisTurn
PlayerState.CompletedMainActionsThisTurn
PlayerState.UsedCharacterThisTurn
PlayerState.CharacterCardLockedThisTurn
PlayerState.ActedMainActionThisTurn
PlayerState.UsedCharacterThisRound
PlayerState.UsedSpecialActionIdsThisRound
```

`ActedMainActionThisTurn` 是兼容既有 Guard 和显示逻辑的派生兼容字段，不再单独决定主要行动是否可用。`MainActionBudgetService` 统一开始行动轮、消费预算、授予额外预算、提前结束和重置角色牌轮内状态；特殊行动多步会话由可序列化的 `PendingSpecialAction` 保存。

建议 UI 层额外维护一个只用于表现的模式枚举：

```csharp
public enum ActionPanelMode
{
    Hidden,
    ChooseAction,
    ResolvingTarget,
    PendingChoice,
    WaitingForNextPlayer
}
```

该枚举不进入规则状态，只用于控制面板显示。

## 4. 命令处理原则

所有按钮点击都应提交 `GameCommand` 或进入目标选择模式，不直接修改 `GameState`。

主要行动命令：

- `DeployInfluence`
- `DispatchInfluence`
- `ExploreLocation`
- `MoveCity`
- `BuildFacility`
- `UseSpecialAction`

快速行动命令：

- `UseCharacterCard`
- `DeclareCityStyle`

通用命令：

- 对应待选类型的结算命令
- `EndAction`

主要行动 handler 成功后：

1. 修改规则状态。
2. 写入 `GameEvent`。
3. 在效果完整完成时调用 `MainActionBudgetService.SpendCompletedMainAction`；中途待选不提前消费。
4. 由预算服务同步维护剩余次数、完成次数与 `ActedMainActionThisTurn` 兼容字段。
5. UI 保持当前玩家；有剩余预算时继续允许下一主要行动，否则提示结束行动。快速行动仍按规则在主要行动之间或之后执行。

源石工业中枢属于即时完成的特殊行动：先消费本次主要行动，再调用 `GrantAdditionalMainActions(..., 2)`。其他多步特殊行动只在最后一步完成时消费主要行动，失败、提交前取消和 Host 拒绝均不消费。

`EndAction` handler 成功后：

1. 校验当前玩家至少已经完成一个主要行动。
2. 校验不存在任何未结算的待选会话。
3. 通过预算服务放弃剩余预算，再调用 `RoundAdvanceService.EndCompletedAction`。
4. UI 刷新为下一名玩家、下一行动轮或后续阶段。

快速行动 handler 成功后：

1. 修改规则状态。
2. 写入 `GameEvent`。
3. 更新对应次数限制字段。
4. 不调用当前玩家推进。
5. UI 留在当前玩家行动面板。

## 5. UI 方案

在地图右侧放置一个“行动面板”。

```text
当前玩家：蓝色玩家
阶段：第 2 回合 / 行动轮 1 / 当前行动

快速行动
[使用角色牌] [宣告城市样式]

主要行动
[部署] [调度] [探索]
[城市移动] [建设]

状态：
剩余主要行动：1
```

特殊行动不设置独立按钮。玩家单击公共样式卡打开共享预览，把牌面上己方可用影响力拖到绿色合法区发动：I 级拖到 `used`，II 级按当前次数拖到 `used_from_2` 或 `used_from_1`；普通后续宣告标记和物资中继站不可拖。

玩家点击快速行动后：

```text
快速行动
[使用角色牌 已使用] [宣告城市样式]

主要行动
[部署] [调度] [探索]
[城市移动] [建设]

状态：
尚未执行主要行动
```

玩家完成普通主要行动后：

```text
主要行动已完成
请点击结束行动
```

玩家点击结束行动后，系统切换到下一名玩家或下一行动轮。

源石工业中枢完成后，状态改为“剩余额外主要行动：2”，同时保留主要行动入口和“结束行动”。复合动力系统先在样式卡预览内选择源岩/异铁支付草稿；确认前可取消且零提交，首条 Host 命令原子支付。其余需要目标的特殊行动在 Host 接受后退出预览，通过精简提示、地图高亮和既有事件弹窗强制续接；源石工业中枢即时完成，不弹待处理框。

## 6. Unity UI 层级

建议新增或扩展 `ActionPanelController`。

```text
Canvas
  ActionPanel
    CurrentPlayerText
    PhaseText

    QuickActionGroup
      UseCharacterButton
      DeclareCityStyleButton

    MainActionGroup
      DeployButton
      DispatchButton
      ExploreButton
      MoveCityButton
      BuildButton

    StatusText

  CityStyleDeclarationPreview
    DraggableOwnedStyleMarkers
    SpecialActionLegalDropTargets
    CompositePaymentDraft
```

按钮行为：

- `UseCharacterButton`：提交 `UseCharacterCard` 或打开角色牌效果选择。
- `DeclareCityStyleButton`：进入城市样式宣告选择。
- `DeployButton`：进入选择影响力槽位模式。
- `DispatchButton`：先选择自己的影响力，再选择目标槽位。进入来源选择后，UI 只给确实存在合法移动目标的己方影响力显示高亮边框；点击已有影响力槽位自身即可选中来源，目标阶段可点击高亮空槽提交调度。
- `ExploreButton`：进入选择目标地块与路线模式。
- `MoveCityButton`：进入选择相邻地块模式。
- `BuildButton`：打开设施供应区。
- 城市样式预览标记：仅本方拥有、位于可用区且通过 `SpecialActionOptionQueryService` 校验的正式标记可拖；非法落点不提交，无目标警告需要二次确认。

## 7. 按钮启用规则

行动面板刷新时，按以下规则控制按钮：

1. 当前阶段不是 `ActionRound1` 或 `ActionRound2` 时，隐藏或禁用行动入口。
2. `GameState.CurrentPlayerId` 不是本地/当前操作玩家时，禁用行动入口和样式标记拖拽。
3. 存在任一待选会话时，隐藏普通行动入口，只显示对应待选弹窗或地图高亮。
4. `MainActionBudgetService.HasAvailableMainAction(...) == false` 时禁用主要行动；快速行动仍按各自规则可在结束行动前使用。
5. `UsedCharacterThisTurn` 或角色牌自身回合限制成立时，禁用“使用角色牌”；`CharacterCardLockedThisTurn` 需要显示特殊行动造成的锁定原因。
6. 没有可宣告城市样式时，禁用“宣告城市样式”入口。
7. 每个样式标记的可拖状态由 `SpecialActionOptionQueryService` 单独计算；不能使用全局“本回合用过任意特殊行动”布尔值禁用所有样式。

## 8. 当前落地状态

- 部署、调度、探索、城市移动、建设与结束行动已接入真实命令。
- 三类地图点击统一转发到 `InteractionRouter`，由注册优先级处理待选结算、进行中动作和默认地图路由；主控制器不再维护多条协调器硬编码责任链。
- `InteractionMode` 仅表示四种面板粗状态；移动、探索、部署、调度和建设子步骤已下沉到交互局部状态。
- 工作流命令统一通过 `CommandGateway` 区分拒绝、等待 Host 和本地应用，热座玩家解析集中到 `LocalPlayerResolver`。
- 标准建设由 `BuildInteraction` 持有本地草稿；建设 ViewModel 只通过封闭的 `BuildFacilityIntent` 分派拖动、落位、支付、返回、确认和取消。
- 建设草稿支持拖动公共牌、合法槽位高亮、聚焦、支付摘要和本地虚影。非法或落空拖放会返回选择态而不取消；Esc 仅把聚焦/确认态缩回虚影；只有明确的取消按钮才清除草稿。标准建设等待 Host 时禁止重复确认、返回或取消。
- 城市样式预览与特殊行动标记提交已迁入 `CityStyleInteraction`，行动按钮启用、等待态和状态文案由 `TurnActionPanelPresenter` 统一构建。
- 入场放置与城市移动的局部阶段、高亮、命令和恢复已迁入 `MoveInteraction`；`TurnActionPresenter` 只保留动作分发和兼容薄委托，并由架构测试限制为不超过 400 行。
- 建设、部署、调度、移动和探索分别由五个独立 `IInteraction` 类承载并直接注册到统一 Router；`InfluenceActionPresenter` 与 `ExplorationEventPresenter` 仅作为流程逻辑被对应交互包装，资源采集仍以独立 Presenter 注册。角色牌设施供应选择可由统一 Esc 取消，设施待选等待 Host 时使用命令/会话双键防止重复提交。
- 行动按钮按下会在 0.08 秒内缩放至 0.92 并点亮青色描边；地图合法目标只显示青色边框，以 0.6 秒周期在 alpha 0.4～1.0 间脉冲；确认落点播放 0.15 秒闪光缩放和外扩青色圆环。相机背景统一为深石板灰，地图贴图本身不染色。
- 五张标准角色牌和城市样式宣告已接入真实命令；角色牌手牌、盖放卡背、效果选择和待选结算位于信息面板。
- 城市样式宣告已支持旋转匹配、轨迹选块、撤销和统一结算。
- 五种基础特殊行动已由 `SpecialActionDatabase`、`SpecialActionOptionQueryService`、`SpecialActionService`、`SpecialActionLifecycleService`、`MainActionBudgetService` 与 `UseSpecialActionCommandHandler` 完整结算。
- 样式卡拖拽、复合支付草稿、地图强制续接、事件恢复和 Host 确认前防重复提交均已接通；活动后续命令严格携带 `specialActionSessionId`。

## 9. 验收标准

当前实现应持续满足：

- 行动阶段能看到当前玩家和行动轮。
- 主要行动与快速行动分区显示。
- 快速行动按钮点击后不推进玩家。
- 主要行动成功后不立即推进玩家，而是提示点击“结束行动”。
- `EndAction` 成功后推进到下一名玩家或下一行动轮。
- 没有剩余预算时不能继续主要行动；源石工业中枢授予额外预算后可以继续或提前结束。
- 存在待选择项时，行动按钮不可用。
- UI 不直接修改 `GameState`，只提交命令或进入目标选择模式。
- 新增交互必须注册到统一 Router；控制器的地图点击入口只做一次转发。
- 多步动作的精确步骤必须由动作局部状态表达，不能重新向全局 `InteractionMode` 添加细粒度值。
- 建设确认成功前只存在本地草稿；Esc 保留草稿，显式取消清除草稿，最终确认只提交一条建设命令。
- 样式卡支付、警告和拖拽取消不提交；Host 接受后的多步行动不能取消或重复提交。

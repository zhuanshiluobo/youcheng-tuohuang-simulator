## 1. 依据与确认

依据：用户的 `F:\hby\游城拓荒基础效果.docx`、项目内 `游城拓荒/规则书/《游城拓荒：铸基者》规则说明书（新）.pdf`，辅助参考[规则总结](../规则/规则总结.md)和[项目术语表](../规则/项目术语表.md)。不回写原DOCX。具体扩展牌面数值仍须逐项按原图核准。

用户已确认：

1. 一级是最小规则操作，二级是复合流程；二级也可调用其他二级流程，二级不是嵌套深度上限。
2. 一级移动城市只改变位置；移动城市行动包含费用、位置改变、清除影响力、事件、放置影响力等步骤。
3. 所有效果经历触发、处理、结算。连锁为插入执行：父处理暂停，子效果完整结算后恢复父。
4. 一级效果在自己的结算阶段提交状态，后续效果立即可见；父流程只汇总、收尾，不重复执行子效果变化。
5. 移动影响力＝移除自己影响力→放置自己影响力；替换影响力＝移除对手影响力→原槽位放置自己影响力。两类组合不可被外部效果打断，保证完整成功或不留下部分变化。
6. **移动、替换只整体触发。内部移除、放置不单独触发外部效果，也不在组合完成后补发这些内部触发。** 以用户“只整体触发”的明确答复为准。
7. 允许的外部触发在发生时记录，保护范围结束后释放。明确规则/牌面顺序优先，未规定时由发动组合的玩家排序。
8. 调度角色牌＝从指定角色牌堆抽取角色牌加入手卡，包括罗德岛来源；不同于调度影响力。
9. 企业扩展纳入目录，未来支持自定义卡片和效果组合，本轮不实现扩展或编辑器。
10. 普通失败、尽量执行、条件前置、跳过和延迟等细分规则稍后加入。
11. 新系统需要异常捕获与恢复，避免效果故障使整局永久卡在待结算状态。

旧资料差异：规则总结中动员配套体系仍写“先移除，再尽量放置”。新系统按本轮确认保证替换完整性，不能照搬为允许半成功；后续迁移时核对旧摘要及代码。现有移动直接改变槽位，不代表必须以破坏真实状态再恢复的方式实现新语义。

## 2. 三种职责

- **命令**：玩家/系统请求，如发动行动、提交事件选择；验证身份、阶段、目标和重复请求。
- **效果**：一级操作或二级流程，具有明确规则语义，不是任意字段赋值。
- **流程控制**：顺序、分支、有限重复、等待选择、暂停恢复、延迟/持续生命周期；不混入游戏操作目录。

结算事实与调用日志不同：内部一级效果可有生命周期和诊断记录，却不必向外发布触发。保留Host权威，不创建绕过校验的第二条状态修改入口。

## 4. 二级流程目录

本节箭头仅表示执行先后，不定义规则书中条件箭头的失败语义。选择和校验可提前收集以避免无效扣费，但不能改变规则规定的效果顺序。

| 编号 | 流程 | 拆解 |
| --- | --- | --- |
| 二01 | 部署行动 | 选择槽位→放置影响力→行动收尾 |
| 二02 | 移动影响力 | 选择起终点→整体校验→受保护执行移除自己影响力、放置自己影响力→整体移动完成 |
| 二03 | 替换影响力 | 选择对手影响力→整体校验→受保护执行移除对手影响力、原槽位放置自己影响力→整体替换完成 |
| 二04 | 调度行动 | 按规则至多执行两次移动影响力→收尾；单次移动保护不自动扩大为整次调度保护 |

| 二06 | 探索 | 选择已开放未探索地块与路线→付路费→翻事件牌→放置资源点→处理事件选项→目标地块放置影响力 |

| 二16 | 使用特殊行动 | 校验解锁/次数/限制→按牌面支付并执行复合效果→按牌面更新次数/标记；具体支付与标记时机按来源规定 |

| 二19 | 源石工业中枢 | 付费→增加主要行动预算→设置角色使用限制；后续行动仍从正常入口提出 |

| 二22 | 升级并触发企业特效 | 企业升级→来源明确要求时调用发动企业特效；不能将所有升级都视为此流程 |

| 二24 | 罗德岛干员特派 | 按人数/牌面抽候选→查看选择或放弃换分→选中牌加入手牌→按规则展示并移除原角色→处理剩余候选；数量、去向与细节逐项核准 |
| 二25 | 购买/出售/交换资源 | 选择种类数量→支付至明确接收者→获得资源/金券；比例、限额与保护范围按来源定义 |
| 二26 | 回合收尾 | 执行收尾效果及规则回收→复位样式标记→传递起始玩家→推进回合；第8回合后最终计分 |
| 二27 | 红区开放 | 开放区域→企业扩展启用时按规则顺序企业升级→继续角色盖放 |
| 二28 | 最终计分 | 读取区控、现有分数、剩余资源和牌面修正→计算分项→提交最终结果→判定平局；不重复加已计入分数 |

关键边界：

- 免费移动/建设是完整二级流程的费用变体，不是仅移动位置/设施入城，不能漏掉事件或入场效果。
- 城市进入未探索地块复用翻牌—资源点—事件片段，不调用带探索路费和目标放置影响力的完整探索行动。
- 企业多人升级已有顺序：发动者先、其他顺时针；不由通用排序规则覆盖。收尾效果按规则由对应玩家排序。
- 主要行动中不能任意插入快速行动；系统要求的子效果不等于玩家优先权窗口。

## 5. 三阶段、栈与整体触发

### 5.1 阶段含义

- 触发：建立唯一效果实例，记录来源、玩家、父效果和依据。生命周期触发不等于向外广播。
- 处理：确定参数、目标及选择；创建必要子效果并暂停自身。
- 结算：提交本效果自身变化，记录完成，发布允许的事实，再返回父效果。

一级已结算结果对后续子效果可见；父流程结算不得再扣一次费用或再发一次奖励。不可打断组合建议使用局部投影/检查点：内部步骤可读到前序变化，完整成功后才向外提交整体状态和事实。

```text
效果1触发→效果1处理（暂停）
  探索触发→探索处理（暂停）
    事件卡效果触发→事件卡效果处理→事件卡效果结算
  探索恢复剩余步骤→探索结算
效果1恢复剩余步骤→效果1结算
```

父帧记录下一步骤，不从头重放。待选与执行子效果都是暂停原因，但只有前者需要玩家答案；关闭弹窗不能直接让效果出栈。

### 5.2 新情景：两张卡监听同一次整体移动

以下为说明用自定义卡片，不是正式牌面：甲“完成影响力移动后获得1金券”；乙“完成影响力移动后可以探索一次”。

1. 内部移除旧位置、放入新位置，此时两张卡都不能插入。
2. 整体成功，发布一次移动完成；记录甲、乙在此时满足的触发与来源。
3. 没有更明确顺序时，发动移动的玩家排序，假定先甲后乙。
4. 甲入栈，获得1金券结算后出栈。
5. 乙入栈；若玩家选择探索，探索再入栈，事件需要时继续入栈。按事件→探索→乙结算返回。
6. 响应完成后恢复原父流程。

两张卡监听的是同一整体移动完成，**不是移除触发甲、放置触发乙**。另一张写“放置影响力时获得1分”的卡不会因内部放置发动。替换同理，仅发布替换整体事实。

建议按选定顺序逐个安排响应，避免正序全部压栈造成倒序执行。重试/重连不能重复发布同一次事实或响应。记录时确认触发依据；执行时仍需校验目标和费用，目标后来失效的细则留待后续确认。

## 6. 自定义效果与流程能力

最小能力：顺序、明确分支、有限重复、一级/二级调用、待选、栈暂停恢复、不可打断组合、随机结果记录、延迟/持续注册与解除的预留能力。延迟及持续的具体时机不在本轮定稿。

建议定义数据：稳定标识、版本、参数约束、触发条件、步骤、可见范围、保护范围。建议实例数据：实例/根命令/父实例标识、来源、玩家、阶段、下一步、选择、随机结果引用、等待标识、完成记录。

以引用已注册效果和受约束参数组合卡片，中文牌面描述只用于显示，不解析为运行脚本。不开放任意C#执行，不先建大型DSL或通用事件平台。加载时检查效果引用、类型、范围、目标、循环与数量边界；运行时仍需动态连锁保护。

## 7. 异常捕获与恢复（新增需求，以下是建议实现方案）

### 7.1 原则

防止永久卡死不等于任何错误都自动跳过。必须区分：规则拒绝、合法等待、程序异常、表现/联网失败。状态不一致或提交结果不明时暂停保护并提供恢复入口，不伪造结算成功。

| 边界 | 故障与处理 |
| --- | --- |
| 命令入口 | 非法输入/越权/过期选择明确拒绝；重复已完成请求返回已有结果，不再次执行 |
| 效果执行 | 捕获处理器异常并记录阶段/步骤，进入恢复状态；父效果不能继续假装成功 |
| 局部组合 | 提交前校验完整性；后半异常则丢弃投影或恢复检查点，不产生整体成功触发 |
| 待选恢复 | UI丢失则从权威等待帧重建；帧损坏则恢复处理，不直接清空所有Pending |
| 连锁调度 | 可配置深度、执行步数和无进展检测，阻止动态无限连锁；正常玩家等待不计作执行超时 |
| UI/网络 | 与规则提交隔离；重建显示或重连，不重复执行已经结算的效果 |

不能用空catch吞异常。最外层捕获只是兜底；诊断写入失败也不能再次递归触发游戏效果，应保留内存故障状态。

### 7.2 安全边界与去重

1. 保存最近安全边界所需的游戏状态、栈、等待、触发和随机/抽牌结果；现有公开行动日志快照不能直接当完整恢复快照。
2. 未提交一级操作和局部组合可恢复后重试；已经结算的子效果不得重复执行，父后续故障优先从失败步骤恢复。
3. 提交状态不明时先查权威完成记录与状态版本，不盲目重试。状态变化、完成标记和待发布事实需作为同一逻辑提交，防止已扣费却没有完成记录。
4. 随机与抽牌恢复重用已有结果，不重掷、不换牌；不能撤回玩家已见信息。
5. 恢复同时修复对应帧、等待和触发记录，不能只恢复余额却遗留旧执行位置。
6. 同一异常不无限自动重试；状态无法确认时进入人工恢复，不自动跳过有副作用步骤。

### 7.3 可见恢复入口

显示“当前效果执行异常，对局已暂停保护”，按安全条件开放：

- 重新显示待选：权威等待帧仍完整时。
- 从安全步骤重试：尚未提交或可明确去重时。
- 恢复检查点：保证状态、已提交结果与公开信息一致时。
- 导出故障记录：公开诊断默认脱敏，私有手牌/牌堆不发送给无权客户端。
- 保存故障对局并退出：无法继续时保留修复材料；这是后续新增能力，不表示当前已有完整存档。

强制跳过/终止不作为默认恢复按钮。只有证明尚无写入或具备针对性安全收尾方案时，才考虑由Host人工裁定，并明确记录；是否授权这种裁定留待用户确认。客户端不能自行恢复或改写结算结果。

### 7.4 故障情景

- 替换影响力移除后放置报错：恢复组合，原影响力及双方供应不变，不触发替换奖励，之后从组合安全边界重试。
- 探索路费已付、事件已翻，选项处理报错：保留费用和该事件，恢复失败步骤，不重复收费或换抽事件。
- 获得1金券已结算，UI刷新报错：只重建UI，不重新奖励。
- 自定义卡“获得分数后再获得分数”循环：超过运行限制后暂停并保留链路，不清栈假装完成。

诊断最小记录：故障标识、时间、命令/效果/父实例、定义版本、阶段/步骤、状态版本、异常与调用栈、提交状态、等待标识、检查点、恢复操作和操作者。公共行动日志只显示简要原因。

## 8. 项目对接与后续事项

后续对接：`GameCommand`保留请求身份；`GameSession`连接执行器与待选/异常恢复；`AuthoritativeCommandDispatcher`保持Host权威；`GameState`逐步整理分散Pending；影响力服务复用整体校验和投影；城市移动服务拆开一级位置变化和完整行动；`CardFlowService`复用合法选项校验，不另建无关联弹窗。

建议落地顺序：资源/分数一级效果→栈与待选→移动/替换保护组合→探索事件嵌套→恢复入口→逐项迁移其他流程。异常边界和完成记录随执行器一起建立，不在全部迁移结束后补救。

待后续确认：普通失败/箭头条件/延迟与持续细则；公路和交换等组合的保护及触发粒度；扩展独立组件与具体牌面参数；人工强制跳过授权。本准备稿不替这些规则作最终决定。

# 建设界面与结算流程

更新：2026-09-28。本版替代旧拖放目标说明。后续修订已获准进行建设支付与放置的定向测试，不运行全量测试；资源支付与金券支付两项场景测试已通过，详见 `docs/测试/2026-09-28-建设支付定向回归.md`。

## 界面资产

- 正式页面：`Assets/YC/Presentation/Prefabs/Gameplay/Dialogs/FacilityBuildDialog.prefab`；修改应用于源预制体，注册表仍实例化该资产。
- 建设面板左右百分比锚点为 0.05 / 0.95，占宿主宽度 90%；1920 宽宿主对应面板宽 1728、两边各 96。面板上下锚点为 0 / 1，上下各留 22 单位，移除写死的 880 高度，始终限制在页面宿主的可用高度内。删除原固定宽度驱动，用源预制体锚点直接控制。
- 新增 Effects Column / Supply Column / City Column：左右栏固定为基准布局的 391.5 / 408.9，中栏拉伸承担横向宽度变化，底部按钮组按按钮内容计算宽度并靠右，左侧说明占用剩余宽度。三个 Header 水平靠左、竖直居中。
- 页面名称为“建设”，三栏为“结算效果与支付”“设施供应区”“城市面板”。其他规则明确提供非供应区候选时，候选栏显示“可选设施牌”。
- 三栏使用 `CommonUi/Sprites/Frontier31/module-frame.png` 和 `module-bg.png`。主界面卡牌的框不能用于模块框。
- 两个支付按钮固定保存在建设源预制体中，保持原支付选项按钮底图，每单位像素乘数为 2；移除两个支付按钮的 `3.4 Row Frame`；仅清除按钮外层区域的旧褐色底层。进入页面即显示，未选牌时禁用；刷新选择时不重建按钮。支付区域使用普通 Payment Area / Payment Buttons 纵向布局，已删除 ScrollRect、Viewport 裁剪层、Scrollbar、禁用的旧网格/模板和 ContentSizeFitter；两个固定支付按钮与原价、减免说明共用同一纵向布局，删除 `Empty Effects`。第一个按钮显示规则返回的完整混合费用（四种资源及金券），第二个按钮显示纯金券费用；第一种支付的金券同样参与原价比较配色，五项费用由现有布局自动换行。按钮直接显示规则返回的实际资源费用或金券费用，资源名称替换为主界面同源去背景图标；未选牌显示图标和占位数字并禁用。按钮下面分成“原价：”标题行、费用图标行、“减免：”标题行和减免图标行；零费用显示“免费”，无减免显示“无减免”。支付按钮各项数字独立与对应原价比较：低于原价为绿色，高于原价为红色，相等为黑色；减免到零仍保留绿色数字 0，未选牌的占位数字恢复黑色。颜色保存在源预制体，仅支付按钮启用比较，原价和减免说明保持自身颜色。资源减免取原价与实际资源费的差值，金券按规则定义价显示，不虚构金券减免。
- 两个支付按钮通过 `UiContentHeightLayout` 按内部标题、费用行及内边距测量高度，取消固定 124 高及 88 最小高；费用换行时才增加按钮高度。按钮内容上下内边距为 6、标题与费用间距为 2，左栏项目间距为 10。左栏内容使用 `UiFitContentHeight` 保持自然排版高度，宿主高度不足时整体等比缩小并水平居中，高度恢复后回到原大小；不新增滚动或裁剪，不让下方报价超出左栏。
- `CardSelectionSlot.prefab` 从卡牌选择页原卡槽提取，保留卡面、底图、已修正的选中框和 `CardPickerCardButton`。卡牌选择页与建设页共用它，建设页只有供应区的候选设施卡使用该预制体。城市面板的已有设施和预放设施通过原有 RawImage 显示原卡面，不使用选择卡槽。
- 单击选择；长按、双击或右键打开卡牌查看。查看后返回原页面。没有独立详情按钮，查看不会提交选择或支付。
- 设施供应区使用 `UiWrappingRowLayout` 自适应分行，以 1080p 的 216.74625 首选完整槽宽（原始 188.475 的 1.15 倍）为起点，已移除固定像素尺寸及 CanvasScaler 反向补偿。普通宽度下，变宽增加列数；变窄时牌数足够则保持至少 3 列，卡槽和卡面等比缩小（少于 3 张按实际数量）。保持顶部及最后一行列对齐，各行按最高供应位计算高度。只有一行时，卡槽等比放大或缩小到视口可显示高度；一个供应位有多张牌时以最高手位适配，避免超出高度。
- `UiResponsiveSupplyScroll` 在屏幕宽高比达到 21:9 或候选按当前宽度只需一行时切换单行横向滚动，容器宽度取完整牌列的实际宽度，支持拖动或滚轮横向访问；回到普通比例且需要多行时恢复分行纵向滚动，并清除上一方向的滚动偏移。阈值由源预制体的 `horizontalAspectThreshold` 配置。
- 底部信息区参考城市样式界面，与中间模块相隔 12 单位，说明和操作按钮由水平布局分配空间。提示分两行，追加“价格减免须点击结算按钮”；建设页面不再同时使用全局最下方的重复提示。静态提示保存在源预制体。
- `Options Scroll` 上沿提高 25 单位，下沿保持不变；垂直滚动条以高度减 25、中心下移 12.5 补偿，使其上下端点不随这次上沿调整移动。可显示区域沿用原下沿。
- 每个供应位使用 `FacilitySupplySlot.prefab`，内部纵向排列共享的 `CardSelectionSlot.prefab`，可容纳多张牌，下一行避让完整供应位高度。当前规则仍返回平铺设施候选，每个来源条目对应一个供应位；本轮未按卡名或类型擅自分组，也未修改规则数据。
- 候选卡面保持等比适配；建设供应区的 CardSelectionSlot 宽高取其内部 `Card Face/Card Slot` 底框的完整尺寸，包含超出 Card Face / Artwork 的外扩部分；按底框完整宽度适配供应位，卡面保持原比例，避免底框溢出或相邻行重叠。尺寸从底框 RectTransform 的锚点跨度与 sizeDelta 计算，保留预制体配置的底框范围；纵向间距设为 0（分行布局的行间距、单个供应位内多张牌的间距均为 0），横向间距保持 16；滚动条继续按内容是否超出视口自动显隐。城市内设施沿用原城市槽位的卡面显示比例。设施供应区滚动容器不再叠加旧褐色底层，使模块背景直接显示。
- 合法城市格的绿色高亮位于建设面板，不再使主界面“我的城市”进入普通建设选槽状态。付款前提示空位，但不能提前放置；付款后才允许选槽，未选中的合法位置保留原圆角绿色半透明遮罩（原 `row-bg-default` 底图，Sliced 九宫格填充）；选中槽位显示预放卡牌，并将该位置遮罩设为透明，移除棕色遮挡，不把其他合法位置的绿色遮罩改成边框。

## 主界面查看入口与供应状态

- 主界面 Map Title 在自身文本框内水平、竖直居中，配置保存在 `GameplayInteractionHud.prefab`。
- 本机玩家主要行动次数用尽、尚未轮到本机或当前不在主要行动阶段时，建设入口显示“查看设施供应区”并允许点击；恢复主要行动机会后显示“建设”。动态按钮文案由行动面板的序列化配置提供。
- 查看模式复用正式建设源预制体，可选择设施查看费用，并沿用长按、双击、右键查看完整卡牌。该模式不启动建设草稿、不提交支付或放置命令；支付禁用、确认放置隐藏、城市不显示可选高亮。关闭后返回主界面；主要行动恢复时退出旧查看页。
- 设施供应区 Header 右侧分两行显示信息：第一行为“设施牌堆·数量”，只统计尚未翻出的 `FacilityDeck`，不计已在供应区的牌；第二行为红、黄、蓝三个“延伸枢纽”，以“·”分隔。按正式规则使用全体玩家的已建造设施记录判断可选性：相应枢纽建造后直接移除该颜色的名称，只显示剩余可选枢纽；三个均用完时仅显示一个灰色的“延伸枢纽”，不保留多余分隔点。文案格式、颜色和文本引用保存在建设源预制体。
- 左栏支付按钮上方增加“资源：”，与支付选项共用纵向布局；以主界面同源图标及数字显示本机玩家当前持有的四种资源和金券，零数量也保留。正常建设、付款补牌后的放置页和仅查看供应区都刷新持有量及供应状态。

## 正式顺序

```text
点击建设
→ 选择设施牌
→ 点击资源或金券支付按钮，直接提交正式支付（不再二次确认）
→ Host 校验并实际扣费
→ 从原供应位取走所选牌，翻补新牌
→ 展示补牌后的设施供应区
→ 在建设面板的城市面板选择合法空位，确认放置
→ 设施入城，获得牌面分数，消耗一次主要行动额度
→ 结算设施入场效果
→ 建设子树结束
```

付款前选择属于本地草稿，可以取消和改选。付款后补牌公开了新信息，此时禁止取消、退费、换牌和重复支付，只能完成放置。收起与查看卡牌不代表取消，强制待办仍通过顶栏恢复。

供应牌堆为空时不创造新牌；沿用供应服务的空槽处理。免费备用设施不支付、不翻补公共供应区，保持其专用规则。

## 命令与恢复

- 新界面的 `BuildFacility` 命令只携带设施 ID 与 `paymentMode`，不提前传城市槽位。
- `facility.build` 定义版本为 `1.2.0`。付款及补牌完成后，Effect 进入 `awaiting_placement`，创建 `facility.build.placement` 请求，`AllowDecline = false`。
- 请求归建设玩家所有，候选是合法城市槽位 ID；待放置牌 ID 与支付方式保存在 Effect 参数及请求参数中，不能仅存于临时 UI 对象。
- 后续使用统一 `AnswerInteraction` 命令提交一个城市槽位，校验交互 ID、版本、候选和空位。此阶段调用 `PlacePaidFacility`，不能重复调用扣费或供应补牌。
- 断线恢复或场景重建从玩家可见请求投影恢复待办；页面回调检查当前请求及候选版本，提交期间禁止重复操作。
- 付款阶段只报告支付与补牌。设施实际落位后才报告 `FacilityBuilt` 与牌面得分。
- 已指定槽位的旧调用仍能一次完成，但规则内部顺序同样为支付、补牌、放置、得分、入场。无 EffectRegistry 的旧服务入口仍要求显式槽位。
- 本轮没有提供旧版本进行中存档的迁移保证；恢复必须遵守项目既有 Effect 定义版本校验。

## 后续验证范围

本轮仅定向覆盖两种支付按钮至放置完成的链路；其他待覆盖范围包括两种支付、取消付款前草稿、补牌可见后放置、空牌堆、无空位、费用不足、唯一设施、过期槽位、重复答案、放置待办存档恢复与远端玩家投影，以及入场效果结束前不能结束行动。界面检查应使用正式注册表实例化的建设源预制体；测试不得重建或覆盖页面资产。

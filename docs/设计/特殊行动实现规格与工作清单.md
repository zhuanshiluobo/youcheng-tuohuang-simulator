## 1. 目标与事实源

本模块把城市样式牌上的特殊行动补成完整的 Host 权威流程，覆盖五张基础城市样式牌的规则结算、样式卡拖拽、地图交互、次数标记、额外行动、联网快照、自动跑局和测试。

规则依据按以下顺序使用：

1. `游城拓荒/规则书/《游城拓荒：铸基者》规则说明书（新）.pdf` 的规则正文第 8～13 页（PDF 第 10～15 页）。
2. `Assets/YC/Presentation/Resources/CardImages/CityStyles/` 下的六张基础城市样式牌图。
3. `docs/规则/规则总结.md` 与 `docs/规则/项目术语表.md`。
4. 当前代码和测试只用于判断已有能力，不用于反向覆盖牌面规则。

## 2. 当前实现盘点

### 2.1 已落地的规则与命令

- `SpecialActionDefinition`、`SpecialActionDatabase`、`SpecialActionOptionQueryService`、`SpecialActionLifecycleService` 与 `SpecialActionService` 共同承载五种定义、可用性、目标、支付和 I/II 级生命周期。
- `UseSpecialActionCommandHandler` 处理首条 `UseSpecialAction` 与后续 `ResolvePendingChoice`。Host 会重新校验标记、费用、目标和活动 `specialActionSessionId`；过期、缺失或不匹配的会话不会写回状态。
- `MainActionBudgetService` 统一维护 `RemainingMainActionsThisTurn`、`CompletedMainActionsThisTurn`、`UsedCharacterThisTurn`、`CharacterCardLockedThisTurn` 与旧兼容字段，支持源石工业中枢先消耗原预算、再增加两点预算。
- `PendingSpecialActionState` 已进入 `GameState` 与快照；复合动力系统的移动事件/航道放置、高效移动管理体系的两段移动/事件均可按步骤恢复。损坏快照中的未知步骤、行动类型不兼容步骤、孤立移动事件、不存在玩家、错误归属标记和非法次数/航道/支付上下文会在载入时清理。
- `RoundAdvanceService` 在收尾阶段推进 I/II 级标记、清空每回合使用记录，并重置行动轮预算与角色牌锁。

### 2.2 已落地的交互与复用

- 特殊行动没有独立行动面板按钮。玩家单击公共样式卡进入预览，再把己方可用影响力拖到绿色合法区发动；I 级落到 `used`，II 级依当前剩余次数落到 `used_from_2` 或 `used_from_1`。物资中继站标记不可拖动。
- 复合动力系统先在本地复用共享资源分配组件选择源岩/异铁；确认前不提交，取消、Esc、右键返回或关闭预览均不消耗状态，警告/支付模态期间不能切换背后的样式卡。首条命令携带支付数量并由 Host 原子扣费、移动标记和建立后续步骤。
- 源石工业中枢在 Host 接受后即时完成，不显示待选弹窗；其余多步行动由 `SpecialActionInteractionUiCoordinator` 使用可收起提示和地图高亮继续结算。联网后续命令按 `CommandId` 锁定，匹配的 Host 确认或拒绝返回前不会重复发送。
- 军工化区域复用影响力槽位多选，动员配套体系复用对手影响力选择，两个移动类行动复用受授予移动、普通事件选择和地图刷新。
- `LocalhostAutoplayRunner` 会正式宣告并完成一种 I 级与一种 II 级行动，输出标记区域、预算、待处理步骤和完成命令证据，并继续推进到最终计分。

## 3. 通用规则冻结

1. 特殊行动是主要行动，只能由当前玩家在 `ActionRound1` 或 `ActionRound2` 发动。
2. 玩家必须在对应城市样式牌上有一个处于可用次数区的标记；位于 `0`、`已使用` 或普通 `已宣告` 区域的标记不能发动行动。
3. 对每一个特殊行动 ID，每名玩家每回合最多使用一次；不同特殊行动互不占用彼此的回合内次数。
4. I 级样式首次宣告的标记从“未使用”开始。发动后进入“已使用”，收尾时回到“未使用”。
5. II 级样式首次宣告的标记从 `2` 开始。每次发动后进入对应的“已使用”区；收尾时结算扣减一次剩余次数，并移动到下一个次数格。源石工业中枢提供的额外主要行动不能重复执行源石工业中枢自己的特殊行动。剩余次数到 `0` 后永久不可再用。
6. 同一城市样式的后续宣告标记只放在普通“已宣告”区，不额外增加特殊行动次数，但仍计入牌面要求统计的“此样式上你的玩家标记数量”。
7. 发动前必须完整满足箭头左侧的条件式费用；数字实现中，支付失败直接拒绝命令，不消耗主要行动、样式标记或资源。
8. 效果按牌面从左到右、从上到下执行。已接受命令后，非条件式步骤不能由玩家主动放弃；某一步因合法目标、槽位或玩家影响力不足而无法执行时，跳过该步并继续后续步骤。
9. 玩家取消本地草稿、关闭弹窗、按 Esc 或右键返回时不提交命令，因此不消耗任何状态。首个命令被 Host 接受后，强制后续步骤只能继续完成，不能回滚已经支付的费用、已经移动的标记或已经揭示的事件牌。
10. 单条命令必须原子结算。多步行动以每个 Host 接受的命令为提交边界；后续目标失效时拒绝该步并保留待处理状态，不重复扣费，也不清除待处理会话。

## 4. 五种特殊行动规则矩阵

| 城市样式 | 等级 | 冻结效果 | 目标不足与顺序 | 角色牌限制 |
| --- | --- | --- | --- | --- |
| 军工化区域 | I | 放置 `X` 个影响力，最多 3 个；`X` 为该样式牌上本方全部玩家标记数量 | 目标沿用部署的合法槽位；必须放置当前状态下尽可能多的数量，数量为 `min(X, 供应堆数量, 合法空槽数量)`；由 Host 原子校验全部选中槽位 | 无 |
| 动员配套体系 | I | 替换 1 个对手玩家影响力 | 先移除目标影响力，再尽量在同一槽位放置自己的影响力；若对手移动城市阻挡或本方供应不足，只执行移除；目标在提交前已失效则整条命令拒绝 | 无 |
| 复合动力系统 | I | 支付 1 个源石碎片，再支付源岩与异铁合计 3 个；免费执行 1 次完整的移动城市；移动及其事件全部结算后，在本次通过的航道放置 1 个影响力 | 支付时显式选择源岩/异铁组合；免费只免除普通移动的 3 源石费用，移动目标、红区、清除对手、事件、出发地影响力等普通规则继续生效；航道无空槽或供应不足时跳过最后的放置 | 无 |
| 源石工业中枢 | II | 支付 6 金券；本玩家行动轮内可以额外执行至多 2 次主要行动；两次主要行动之间允许快速行动 | 特殊行动本身先消耗原有主要行动预算，再增加 2 点额外预算；每个后续主要行动成功后才消耗 1 点；玩家可提前结束行动轮并放弃剩余预算；失败或取消不消耗预算 | 发动前若本行动轮已使用角色牌则不可发动；发动后锁定角色牌至本玩家行动轮结束 |
| 高效移动管理体系 | II | 支付 3 个源石碎片；连续执行 2 次免费移动城市 | 两次移动各自执行完整普通移动与事件流程，中间不能插入快速行动或其他主要行动；若下一次移动没有合法目标则按“尽量执行”跳过并完成行动；事件待选结束后必须恢复到下一次移动步骤 | 发动前若本行动轮已使用角色牌则不可发动；发动后锁定角色牌至本玩家行动轮结束 |

物资中继站可多次宣告，每次宣告均给予 `1 源岩 + 1 源石碎片 + 1 异铁`，不生成特殊行动入口。

### 4.1 无目标时的数字化呈现

规则允许非条件式效果因自身条件不足而跳过，因此军工化区域、动员配套体系或免费移动在没有合法目标时，不应伪造目标或卡死会话。默认交互策略如下：

- 列表仍显示该行动，但标注“当前没有可执行目标，发动后对应步骤会跳过”。
- 玩家必须二次确认，避免误触后白白消耗主要行动和样式次数。
- 一旦地图上存在合法目标，玩家不能主动选择“跳过”，必须按“尽量执行”完成可执行数量。

## 5. 建议的数据与命令契约

### 5.1 静态定义

新增 `SpecialActionDefinition` 与 `SpecialActionDatabase`，至少包含：

- `SpecialActionId`、`CityStyleId`、显示名、等级和效果类型。
- 固定费用、组合费用规则、重复次数和最大目标数。
- 是否锁定角色牌、是否产生免费移动、是否产生额外主要行动。
- UI 说明文本只从定义和当前状态组合生成，不在控制器中重复硬编码规则。

### 5.2 可用性查询

新增 `SpecialActionOptionQueryService`，返回每个已解锁行动的：

- 可用标记 ID、标记区域、剩余总次数和本回合是否已用。
- 是否可发动、首个禁用原因、费用与当前可支付组合。
- 合法影响力槽位、可替换目标、可移动目标等当前目标摘要。
- “可发动但部分/全部效果将跳过”的警告，不与硬禁用混为一类。

样式卡预览逐标记消费查询结果，只有对应标记 `CanUse` 时才允许拖拽；不得根据 `UsedSpecialActionIdsThisRound.Count` 直接禁用所有城市样式。

### 5.3 玩家行动轮预算

不要为源石工业中枢在各个 Handler 中分别绕过 `ActedMainActionThisTurn`。新增统一的行动预算状态与服务，例如：

- `RemainingMainActionsThisTurn`：普通行动轮开始时为 1。
- `CompletedMainActionsThisTurn`：成功完成主要行动后增加。
- `UsedCharacterThisTurn`：本玩家行动轮是否已经使用角色牌。
- `CharacterCardLockedThisTurn`：本玩家行动轮后续是否禁止使用角色牌。

由统一服务负责：开始行动轮、成功消耗预算、增加两点额外预算、提前结束行动轮、重置角色牌轮内状态，并同步维护现有 `ActedMainActionThisTurn` 兼容字段。`MainActionCommandGuard`、城市移动/探索等领域校验、行动面板和 `RoundAdvanceService` 必须读取同一个预算口径。

### 5.4 多步待处理状态

新增可序列化的 `PendingSpecialActionState`，至少记录：

- 会话 ID、玩家 ID、特殊行动 ID、样式标记 ID、源命令 ID。
- 当前步骤、剩余重复次数、已经通过的航道 ID。
- 已确认的支付组合和继续结算所需上下文。

复合动力系统遇到移动事件时，顺序必须是“完成移动事件 → 选择/跳过经过航道的影响力槽位 → 完成特殊行动”。高效移动管理体系必须是“第一段移动及事件 → 第二段移动及事件 → 完成特殊行动”。

后续步骤继续使用 `ResolvePendingChoice`，并携带会话 ID。特殊行动 Handler 应在有活动特殊行动会话时先接管对应的事件结算，再委托现有 `MoveCityCommandHandler`，避免普通移动 Handler 抢先结束流程。

### 5.5 初始命令参数

`UseSpecialAction` 至少包含：

- `specialActionId`
- `declarationMarkerId`
- 目标 ID 或目标 ID 列表
- 复合动力系统的源岩/异铁支付数量
- 免费移动的目标地块及事件即时选择参数（如调用时已经具备）

所有目标和费用由 Host 重新查询并校验，客户端提交的可用性结果不作为可信依据。

## 6. 领域结算与生命周期

### 6.1 首条命令的原子顺序

1. 校验阶段、当前玩家、主要行动预算和全局待选状态。
2. 校验样式标记、剩余次数、本回合使用记录和角色牌轮内限制。
3. 校验费用、首个必要目标和参数格式。
4. 在投影状态或事务式服务上验证本条命令的全部变更。
5. 移动样式标记、扣减剩余次数、写入本回合使用 ID、支付费用。
6. 结算即时效果或创建 `PendingSpecialActionState`。
7. 效果完整结束后消耗主要行动预算；源石工业中枢改为“消耗 1 点并新增 2 点”。

### 6.2 收尾阶段

在角色牌收尾效果完成后、推进下一回合或最终计分前，统一执行特殊行动收尾：

- I 级：`已使用 → 未使用`，并恢复下一回合的一次可用次数。
- II 级：`已使用 → 1/0`，不恢复已经消耗的总次数。
- 清空所有玩家的 `UsedSpecialActionIdsThisRound`。
- 清理已结束玩家行动轮的额外预算和角色牌轮内锁定。
- 不改变普通“已宣告”区的后续宣告标记。

## 7. 表现层与联机方案

### 7.1 表现层

- 唯一发动入口是公共样式卡预览中的己方影响力拖拽，不新增独立“特殊行动”按钮，也不维护第二套全局可用状态。
- `TurnActionPresenter` 通过 `SpecialActionOptionQueryService` 生成每个正式样式标记的可拖状态、合法落区、禁用原因、警告和复合支付上限。
- `CityStyleDeclarationPreviewDialog` 负责拖动虚影、绿色合法落区、无目标二次确认和提交前支付草稿；Host 接受后退出预览。
- `SpecialActionChoiceDialog` 复用共享资源分配壳收集复合动力支付；`SpecialActionInteractionUiCoordinator` 恢复 Host 已接受的强制待处理步骤。
- 军工化区域复用地图影响力槽位高亮与多选；动员配套体系复用对手影响力目标选择；两个移动类行动复用城市移动目标、事件弹窗和地图刷新。
- 本地草稿可取消；Host 已接受的强制后续流程只能暂时收起，重新刷新时必须恢复相应提示和高亮。
- 额外主要行动期间，面板显示“剩余额外主要行动：N”，同时保留“结束行动”入口；角色牌按钮显示本行动轮禁用原因。

### 7.2 联机

- Host 是唯一结算方；客户端只提交命令和目标。
- `PendingSpecialActionState`、行动预算、角色牌轮内状态和标记状态必须进入 `GameState`，由现有确认命令快照同步。
- 补充 JSON 往返测试，特别验证 II 级次数格、多步移动阶段、剩余额外行动和角色牌锁定。
- 断线重连或客户端晚加入收到快照后，应能恢复当前待选弹窗、地图高亮和剩余步骤，而不是重新扣费或重复移动。

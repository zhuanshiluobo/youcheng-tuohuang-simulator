# 游城拓荒 2D Unity 模拟器项目总览

本文是项目设计资料的主入口和人工维护的事实源。若与旧工作记录或临时方案文档冲突，以本文和最新工作记录为准。

## 1. 项目定位

《游城拓荒：铸基者》2D Unity 模拟器优先服务于基础版规则模拟。当前目标不是完整复刻实体桌游美术，而是把规则转化为可运行、可验证、可扩展的数字规则系统。

当前阶段仍以本地 PC 热座和基础版规则闭环为主，先支持 3 到 4 人基础版游戏。同时项目已有 Steam Lobby + Mirror/FizzySteamworks 的 Host 权威命令传输与快照同步 MVP，并提供 Mirror + Telepathy 的显式本地多实例测试模式；联网继续作为扩展验证路径，不阻塞基础规则闭环。

## 5. 核心规则流程

基础版固定阶段：

```text
Setup
-> Entrance
-> RoundStart
-> CharacterCover
-> ActionRound1
-> ActionRound2
-> ResourceCollection
-> Cleanup
-> RoundStart 或 FinalScoring
-> GameOver
```

阶段要点：

- `Setup`：创建玩家、选择地图、准备牌堆与供应区。
- `Entrance`：决定起始玩家、选择初始地块、放置移动城市、处理入场默认选项。
- `RoundStart`：设置本回合起始玩家并重置回合状态。
- `CharacterCover`：每名玩家盖放 1 张角色牌。
- `ActionRound1/2`：每轮从起始玩家开始，每名玩家执行快速行动窗口、1 个主要行动、快速行动窗口。
- `ResourceCollection`：玩家选择可采集资源点并支付连接路费。
- `Cleanup`：当前已负责阶段推进；独立收尾效果仍待扩展。
- `FinalScoring`：当前结算基础分、区控分、资源分、设施分、城市样式分与平局判定。

## 6. 分层架构

```text
Presentation / Unity UI
  -> Application / GameSession
    -> Domain / Rule Engine
Application -> Infrastructure
Domain / Infrastructure -> Data
```

当前 Unity 工程主要目录：

```text
Assets/YC/
  Domain/
    Commands/
    Economy/
    Effects/
    Events/
    Facilities/
    Harvest/
    Maps/
    Rules/
    Scoring/
    State/
  Application/
    Gameplay/
    Logging/
    Sessions/
    Setup/
  Infrastructure/
    Replay/
  Presentation/
  Data/
  Editor/
  Tests/EditMode/
```

分层职责：

- `Domain`：纯 C# 规则核心，不引用 `UnityEngine`。
- `Application`：一局游戏生命周期、命令提交、阶段推进、日志与联机协调。
- `Presentation`：Unity 显示与交互，只读取状态并提交命令。
- `Infrastructure`：房间、快照同步、回放与后续存档扩展。
- `Data`：地图、卡牌、图标和图片引用。
- `Tests`：规则单元测试、状态机测试、命令测试与流程测试。

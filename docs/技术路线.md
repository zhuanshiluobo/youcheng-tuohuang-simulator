# 2D Unity 模拟器技术路线

本文件已去重。项目定位、MVP、阶段、架构、数据、测试和扩展路线统一维护在：

- `项目总览.md`

## 本文件保留内容

### 技术选型

- Unity：`2022.3.62f2c1`
- 初版形态：PC 本地热座。
- UI：当前使用 UGUI。
- 测试：Unity Test Framework / EditMode。
- 规则核心：纯 C#，通过 asmdef 与 Unity 表现层隔离。
- 玩家操作：Command Pattern。
- 流程：固定 State Machine。

### 当前技术实现

- `YC.Domain` 设置为 `noEngineReferences=true`。
- `YC.Application` 依赖 `YC.Domain`。
- `YC.Tests.EditMode` 覆盖 Domain 和 Application。
- `StartScene` 使用 `RawImage` 显示 16:9 封面。
- `SampleScene` 默认展示四人地图。
- 地图贴图通过导入后处理统一设置。

### 仍需技术决策

- 规则数据使用 JSON、ScriptableObject 还是混合方案。
- 地图热点坐标编辑方式。
- 具体 validator/resolver 目录结构。
- 存档和回放序列化格式。
- Debug UI 与正式 UI 是否分场景。

### 风险

- 规则书内容需要人工校对，无法完全依赖 OCR。
- 地图是图结构，不是格子系统，热点坐标需要单独维护。
- 路径费用存在玩家选择权，不能只做单一路径自动最短路。
- 卡牌效果过早硬编码会影响企业扩展版维护。

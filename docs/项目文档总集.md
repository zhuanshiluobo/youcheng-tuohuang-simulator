# 第一部分：项目概览与规划

## 1.1 项目定位

《游城拓荒：铸基者》2D Unity 模拟器优先服务于基础版规则模拟。核心是把规则转化为可运行、可验证、可扩展的数字规则系统。

> 本项目为个人学习版与规则模拟练习项目，仅用于学习、研究和开发实践，不涉及商业用途。

**核心目标优先级：**

1. 规则流程正确。
2. 玩家操作清晰。
3. 结算可追踪。
4. 状态可测试、可回放。

**当前产品边界：**

- 先支持 3 到 4 人本地 PC 热座。
- 先跑通基础版规则闭环。
- 暂缓 AI、联网、企业扩展版和高完成度视觉表现。

## 1.2 MVP 范围

MVP 必须能用占位界面或 Debug 工具跑通一局基础版 3 到 4 人热座游戏，输出可复查的结算明细。

**必须包含：**

- 开局入场。
- 基础版三人/四人地图图模型。
- 8 回合固定状态机。
- 每回合角色牌盖放、两轮玩家行动、采集、收尾。
- 部署、调度、探索、城市移动、建设。
- 快速行动、角色牌、城市样式的最小接入点。
- 资源采集、最终计分和平局判定。
- 命令、事件、日志、基础回放。
- EditMode 单元测试和关键流程测试。

**MVP 完成定义：**

- 可创建 3 到 4 人基础版游戏。
- 可从开局入场推进到最终计分。
- 五个主要行动可用。
- 快速行动和效果系统有最小可用接入。
- 采集、收尾、计分可测试。
- 操作日志完整。
- 至少一条 golden case 可重放。
- 核心规则测试通过。

**暂缓内容：**

- 完整动画、音效、高完成度牌面。
- AI、联机、企业扩展版。
- 完整新手引导。
- 地图热点编辑器和卡牌收藏浏览器。

## 1.3 分层架构

### 架构原则

- `Domain` 只表达规则，不引用 `UnityEngine`。
- 玩家操作统一通过命令系统进入校验与结算流水线。
- `GameState` 必须可序列化，支持存档、回放和自动测试。
- 地图、卡牌、效果、计分规则优先数据化。
- UI 只读状态并提交命令，不直接修改规则状态。

### 分层依赖

```text
Presentation / Unity UI
  -> Application / GameSession
    -> Domain / Rule Engine
Application -> Infrastructure
Domain / Infrastructure -> Data
```

### Unity 工程目录

```text
Assets/YC/
  Domain/
    Commands/  Economy/  Effects/  Events/  Facilities/
    Harvest/   Maps/     Rules/    Scoring/ State/
  Application/
    Gameplay/  Logging/  Sessions/  Setup/
  Infrastructure/
    Replay/
  Presentation/
  Data/
    Covers/    Maps/
  Editor/
  Tests/EditMode/
```

### 分层职责

- `Domain`：纯 C# 规则核心，不引用 `UnityEngine`。通过 asmdef 设置 `noEngineReferences=true` 与表现层隔离。
- `Application`：对局生命周期（GameSession）、命令提交、日志、回放、存档协调。
- `Presentation`：Unity 显示与交互，只读状态并提交命令。
- `Infrastructure`：存档、回放序列化、数据加载、Debug 工具。
- `Data`：地图、卡牌、效果、计分、图标和图片引用。
- `Tests`：规则单元测试、状态机测试、命令测试、回放测试。

### 架构硬约束

- 不把规则写进按钮点击事件。
- 不让 Unity 场景对象成为规则状态来源。
- 不绕过命令校验。
- 不让表现层直接写 `GameState`。
- `Domain` 不依赖 `Presentation`。
- `Domain` 不依赖 Unity 场景对象。

### 已建立程序集

- `YC.Domain` — 纯 C#，`noEngineReferences=true`
- `YC.Application` — 依赖 `YC.Domain`
- `YC.Tests.EditMode` — 覆盖 Domain 和 Application

### 架构缺口

- `Definition Database` 尚未实现。
- `RegionControlService` 尚未实现。
- `EffectService` 尚未实现。
- `ScoringService` 尚未实现。
- `Infrastructure` 具体程序集和存档/回放实现。
- 数据加载层方案未定（JSON / ScriptableObject / 混合）。
- 具体 validator/resolver 拆分规范。
- `Presentation` 到 `GameSession` 的正式绑定方式。

## 1.4 核心规则流程

基础版固定阶段流：

```text
Setup
-> Entrance
-> RoundStart
-> CharacterCover
-> ActionRound1
-> ActionRound2
-> ResourceCollection
-> Cleanup
-> RoundStart 或 FinalScoring
-> GameOver
```

**阶段要点：**

- `Setup`：创建玩家、选择地图、准备牌堆与供应区。
- `Entrance`：决定起始玩家、选择初始地块、放置移动城市、结算入场事件。
- `RoundStart`：设置本回合起始玩家并重置回合状态。
- `CharacterCover`：每名玩家盖放 1 张角色牌。
- `ActionRound1/2`：每轮从起始玩家开始，每名玩家执行快速行动窗口、1 个主要行动、快速行动窗口。
- `ResourceCollection`：玩家选择可采集资源点并支付连接路费。
- `Cleanup`：结算收尾效果、复位标记、传递起始玩家、推进回合。
- `FinalScoring`：区控、剩余资源、设施、城市样式和平局判定。

## 1.5 命令流水线

所有玩家操作都必须通过命令系统：

```text
UI / Debug / AI
-> GameSession.Submit(command)
-> Validate
-> Resolve
-> Mutate GameState
-> Emit GameEvent
-> Append Log
-> Refresh Presentation
```

**约束：**

- 非法命令返回明确原因，不修改 `GameState`。
- 合法命令只通过 handler/resolver 修改状态。
- `PendingChoice` 必须写入 `GameState`，直到玩家提交选择结果。
- UI、AI、联网都不能绕过命令校验。

**必备命令：**

- 入场：`ChooseStartPlayer`、`ChooseInitialLocation`、`ResolveEntranceEvent`。
- 回合：`CoverCharacterCard`、`EndAction`。
- 主要行动：`DeployInfluence`、`DispatchInfluence`、`ExploreLocation`、`MoveCity`、`BuildFacility`、`UseSpecialAction`。
- 快速行动：`UseCharacterCard`、`DeclareCityStyle`。
- 采集：`CollectResource`。
- 通用：`ResolvePendingChoice`。

## 1.6 地图、路径与费用

地图必须是结构化图模型，图片只作为表现层底图。

**结构化数据：**

- 资源点：id、颜色、区块、资源槽、影响力槽、事件槽、是否可停靠城市。
- 航道：id、起点、终点、影响力槽、费用属性。
- 区块：id、颜色或区域类型、包含资源点、计分值。
- 地图面：三人地图、四人地图和适用玩家数。

**服务边界：**

- `IMapQueryService`：相邻点、航道、区块、停靠点查询。
- `MapPathSearchService`：最短路径和有限步数内简单路径枚举。
- `TravelCostService`：路线费用与移动城市基础费用入口。
- 后续补 `RegionControlService`：区控统计、移动城市按 2 影响力计入、区块给分。

## 1.8 测试与验收

**测试分层：**

- `Domain` 单元测试：资源、影响力、地图查询、路径、费用、行动校验、效果、区控、计分。
- `Application` 流程测试：`GameSession`、命令流水线、阶段推进、入场、回合、采集、GameOver。
- 回放测试：固定 seed 和命令序列得到固定最终状态。
- 随机模拟测试：随机合法命令序列不产生非法资源、影响力丢失或状态机卡死。

**命令行入口：**

- 统一使用 `tools/Run-EditModeTests.ps1` 启动 Unity Test Runner。
- 脚本默认查找 Unity `2022.3.62f2c1`，也可通过 `-UnityPath` 或 `UNITY_EDITOR_PATH` 指定。
- 启动前检查同项目 Unity 占用和 `Temp\UnityLockfile`，避免 batchmode 启动失败后只留下“无 XML”的模糊结论。
- Unity 退出后等待 NUnit XML 非空并稳定，默认最多等待 `120` 秒。
- 最终判定以 XML 根节点 `<test-run>` 为准：`result=Passed` 且 `failed=0` 才视为通过。
- 同一个 Unity 项目仍不能同时被多个 Editor 或 batchmode 实例打开；脚本只提示，不自动结束已有进程。

**新增规则测试要求：**

- 1 个成功路径测试。
- 1 个失败路径测试。
- 失败路径必须验证不修改 `GameState`。
- 关键结算必须验证日志或事件输出。

## 1.9 多 Agent 开发顺序

**按波次推进：**

1. 第 0 波：主控契约，目录、程序集、基础类型、`GameState`、命令、事件、返回结果。
2. 第 1 波：地图规则基础与状态机/命令流水线并行。
3. 第 2 波：开局入场、五个主要行动、采集、收尾、计分。
4. 第 3 波：`GameSession`、日志、回放、Debug 驱动。
5. 第 4 波：卡牌与效果系统。
6. 第 5 波：正式 UI。

**当前可并行模块：**

| Agent | 写入范围 | 任务 |
|---|---|---|
| 地图 | `Domain/Maps`、`Data/Maps`、测试 | 真实四人图数据、三人图数据、区控服务、地图热点坐标 |
| 命令/玩法 | `Application`、`Domain/Rules`、测试 | 入场命令、部署、探索、城市移动、建设、采集、收尾、计分 |
| UI/工具 | `Presentation`、`Scenes`、UI 资源 | Debug 对局入口、地图交互热点、玩家面板、行动面板、日志面板 |

**并行约束：**

- 每个 worker 必须有明确写入范围。
- 地图、状态机、核心玩法、卡牌、UI 的写入目录要分开。
- 新增规则至少配 1 个成功测试和 1 个失败测试。
- 不回滚他人改动，不批量删除文件。
- 所有规则状态只能通过命令结算修改。
- Presentation 不直接写 `GameState`。

## 1.10 技术选型与风险

**技术栈：**

- Unity：`2022.3.62f2c1`
- 初版形态：PC 本地热座。
- UI：UGUI。
- 测试：Unity Test Framework / EditMode。
- 规则核心：纯 C#，通过 asmdef 隔离。
- 玩家操作：Command Pattern。
- 流程：固定 State Machine。

**仍需技术决策：**

- 规则数据使用 JSON、ScriptableObject 还是混合方案。
- 地图热点坐标编辑方式。
- 具体 validator/resolver 目录结构。
- 存档和回放序列化格式。
- Debug UI 与正式 UI 是否分场景。

**风险：**

- 规则书内容需要人工校对，无法完全依赖 OCR。
- 地图是图结构，不是格子系统，热点坐标需要单独维护。
- 路线费用存在玩家选择权，不能只做单一路线自动最短路。
- 卡牌效果过早硬编码会影响企业扩展版维护。

## 1.11 后续扩展

不进入 MVP 阻塞链路，但保留结构空间：

- 完整桌面 UI：地图热点、玩家面板、行动面板、费用预览、日志面板。
- AI：通过同一套合法命令和评分函数选择行动。
- 联机：依赖确定性命令序列、统一 seed、状态版本化。
- 企业扩展版：通过 `RuleSet.Basic` 和 `RuleSet.EnterpriseExpansion` 接入。
- 动画音效：由 `GameEvent` 驱动，不反向修改规则状态。
- 新手引导：基于阶段说明、合法行动、非法原因、费用预览和日志。

**扩展原则：**

1. 基础版规则闭环优先。
2. 日志、回放和测试。
3. Debug 或最小热座操作。
4. 正式 UI 和表现增强。

# 第三部分：游戏规则详述

> 本文根据 `游城拓荒/_pdf_extracted_images` 中的规则书页面图整理。OCR 对小字号卡牌说明存在少量误读，涉及具体牌面文字、事件选项和企业特效数值时，应以原图或原 PDF 复核。

## 3.1 游戏定位

《游城拓荒：铸基者》是一款结合区控、经营建设和轻 4X 探索的桌游。玩家扮演哥伦比亚拓荒运动中的企业家，通过探索地块、铺设玩家影响力、移动城市、建设设施和达成城市样式来获得分数。游戏结束时分数最高的玩家获胜。

## 3.2 基础版整体流程

一局基础版分为三个部分：开局入场 → 拓荒探索（共 8 个回合）→ 分数结算。

除特殊说明外，玩家从起始玩家开始按顺时针顺序执行操作。每回合结束后起始玩家标记顺时针传递。

## 3.3 基础版设置

### 3.3.1 公共版面

- 放置地图。四人游戏使用标有"四人用地图"的一面；三人游戏移除正面标有 `4` 的事件牌。
- 将事件牌按牌背颜色分为绿色、黄色、红色三个牌堆，分别洗混后牌背朝上放置。
- 将 6 张城市样式牌正面朝上放在地图旁。
- 从设施牌中取出 4 张"核心指挥塔"和 3 张"延伸枢纽"备用；其余 41 张设施牌洗混为设施牌堆，翻开 6 张作为设施供应区。
- 将 35 个至纯源石、70 张哥伦比亚金券放在地图旁作为资源供应堆。
- 将 22 个资源点指示物放在地图旁备用。
- 将回合数标记放在回合轨道 `1` 的位置。

### 3.3.2 玩家版面

每名玩家选择一种颜色，并拿取：

- 5 张对应颜色的初始角色牌作为手牌。
- 30 个对应颜色的玩家影响力。
- 1 个对应颜色的移动城市。
- 1 块城市面板。
- 1 个资源计数器（源岩、源石、异铁归零）。
- 1 张"核心指挥塔"，按规则放在城市面板指定位置。
- 1 个玩家影响力放在分数轨道 `0`。

玩家影响力、资源和未使用部件组成玩家供应堆。支付资源或拿取玩家影响力时，除特殊说明外都只能从自己的供应堆取用。

## 3.4 开局入场

### 3.4.1 决定起始玩家

用任意方式决定一名起始玩家，获得起始玩家标记。

### 3.4.2 决定初始地块

从起始玩家开始按顺时针顺序，每名玩家选择一个不同的绿色地块作为初始地块，并执行：

- 将自己的移动城市放在该资源点停靠处。
- 翻开一张绿色事件牌。
- 将对应资源点指示物放在该资源点。
- 选择事件牌上的一个事件选项并获得奖励。

### 3.4.3 获取初始资金

| | 三人游戏 | 四人游戏 |
|---|---|---|
| 第 1 位 | 10 金券 | 10 金券 |
| 第 2 位 | 12 金券 | 12 金券 |
| 第 3 位 | 18 金券 | 14 金券 |
| 第 4 位 | — | 18 金券 |

## 3.5 每回合结构

1. 角色牌盖放。
2. 玩家行动：2 轮。
3. 采集资源。
4. 收尾。

### 3.5.1 角色牌盖放

每名玩家从手牌中选择 1 张角色牌背面朝上盖放。本回合只能使用这张盖放的角色牌。如果盖放时已无手牌，则先将弃牌区中的全部角色牌回收到手牌，再盖放。

### 3.5.2 玩家行动阶段

包含 2 轮。每轮从起始玩家开始按顺时针顺序行动。每名玩家必须执行 1 个主要行动。执行主要行动前后可执行任意次数快速行动；主要行动进行中不能插入快速行动。

## 3.6 主要行动

### 3.6.1 部署

放置 1 个玩家影响力。从自己的供应堆拿取 1 个玩家影响力放到满足条件的影响力槽位：

- 该空格没有影响力。
- 如果该槽位在地块上，该地块必须已有资源点指示物，且没有其他玩家的移动城市停靠。

玩家影响力位于地图影响力槽位时参与区控、路费和采集等地图规则。

### 3.6.2 调度

移动 1 个自己的玩家影响力，至多执行 2 次。目标槽位必须满足"部署"中的放置条件。调度不会增加玩家影响力总数，但可改变区控、采集路线和阻挡关系。

### 3.6.3 探索

支付路费、结算事件，并在目标地块放置玩家影响力。

执行顺序：
1. 选择 1 个没有资源点指示物、且已开放的地块作为目标。
2. 从自己的移动城市所在地到目标地块建立一条经过若干航道的路线。
3. 支付路费。
4. 翻开与目标地块颜色对应的事件牌。
5. 放置对应资源点指示物。
6. 选择事件牌上的一个事件选项并获得奖励。
7. 在目标地块的资源点影响力槽位放置 1 个自己的玩家影响力。

路费计算：
- 每经过一条没有自己影响力的航道，支付 2 金券。
- 若该航道有对手影响力，向其中一名该影响力所有者支付 2 金券。
- 若该航道无对手影响力，向供应堆支付 2 金券。
- 有自己影响力的航道无需支付路费。

### 3.6.4 城市移动

支付 3 源石，移动城市，并在出发资源点放置影响力。

执行顺序：
1. 支付 3 源石。
2. 选择一个与当前移动城市所在地相邻的资源点。
3. 目标地块必须没有其他玩家移动城市停靠，且已开放。
4. 移动城市到目标地块（无需支付路费）。
5. 移除本次移动使用航道上以及目标地块上的所有对手玩家影响力。
6. 若目标地块没有资源点指示物，翻开对应颜色事件牌，放置指示物并结算一个事件选项。
7. 在出发资源点放置 1 个自己的影响力。

### 3.6.5 建设

支付费用，放置设施牌，获得分数并结算入场效果。

执行顺序：
1. 选择设施供应区中的 1 张设施牌。
2. 支付该牌的资源费用或金券费用。
3. 将设施牌放到自己城市面板的任意空位。
4. 获得设施牌牌面奖励分数。
5. 结算设施牌入场效果。
6. 若设施供应区的牌被拿取或移除且设施牌堆仍有牌，立刻补牌至 6 张。

常见关键词：
- **唯一**：若玩家城市面板上已有同名牌，不能再建设该牌。
- **免费**：执行对应操作时跳过支付。

### 3.6.6 特殊行动

特殊行动来自已宣告的城市样式，属于主要行动。玩家必须在对应城市样式牌上有自己的玩家影响力且未处于 `0` 或"已使用"区域。使用后将玩家影响力移至牌面指定的已使用/次数区域。

限制：
- 同一张城市样式牌解锁的特殊行动，每名玩家每回合只能使用一次。
- 使用特殊行动的行动轮不能再执行其他主要行动。
- 部分特殊行动有额外时机、次数或不能使用角色牌等限制。

## 3.7 快速行动

### 3.7.1 使用角色牌

只能使用本回合盖放的角色牌，每回合最多使用一次。

执行顺序：
1. 翻开本回合盖放的角色牌。
2. 结算角色牌效果。
3. 非特殊说明则将该角色牌正面朝上移至弃牌区。

角色牌通常有"策略"和"计谋"两个独立效果：
- 起始玩家可按任意顺序连续使用策略和计谋，也可只使用其中一个。
- 非起始玩家只能选择策略或计谋之一。
- 同时使用时中间不能插入主要行动或其他快速行动。

若本回合未使用盖放的角色牌，在收尾阶段将该牌和弃牌区中的角色牌一起回手。

### 3.7.2 宣告城市样式

玩家通过已建设设施的颜色与位置组合满足公共城市样式牌上的宣告条件。

规则要点：
- 彩色设施在组合时可视为任意颜色。
- 宣告条件可旋转，不能翻转。
- 每个设施只能用于一次城市样式宣告。
- 宣告后将用于宣告的设施牌旋转 180 度表示已使用。
- 从玩家供应堆拿取 1 个玩家影响力放到对应城市样式牌上。
- 获得城市样式牌的奖励分数并结算宣告效果。
- 同一张城市样式牌可被多名玩家宣告；同一玩家可多次宣告同一城市样式。

## 3.8 采集资源

两轮玩家行动结束后进入采集阶段。所有玩家同时从资源点获取资源。

执行方式：
1. 玩家选择任意数量的资源点；必须有自己的影响力或有自己的移动城市停靠。
2. 支付路费，将所有选择的资源点与移动城市所在地连接。
3. 路费计算与探索相同，但采集阶段每条航道只需支付一次。
4. 不能使用本次采集阶段刚获得的金券支付路费。
5. 若无法支付到某资源点的路费，则不能采集该资源点。
6. 每个资源点每次采集最多获得一次资源，不因多个影响力或移动城市停靠而重复。
7. 资源点指示物显示 1 或 2 个资源时，本次获得对应数量的资源。

## 3.9 收尾阶段

按本回合行动顺序结算：

- 结算收尾阶段效果。若同一玩家有多个收尾效果，由该玩家决定顺序。
- 复位城市样式标记：
  - I 级：位于"已使用"区域的玩家影响力放回"未使用"区域。
  - II 级：位于"已使用"区域的玩家影响力按牌面规则向下移动一格。
- 传递起始玩家标记给顺时针下一名玩家。
- 将回合数标记移到下一回合。

第 8 回合收尾后进入最终分数结算。

## 3.10 红色区域

| 模式 | 开放回合 |
|---|---|
| 四人游戏 | 第 4 回合开始 |
| 三人游戏 | 第 5 回合开始 |
| 二人变体 | 第 6 回合开始 |

连接红色区域地块的航道不受该限制。玩家仍可在任意回合以这些航道为目标放置或移动玩家影响力。

红色地块探索后放置的资源点指示物可能带有 `2`，表示采集时一次获得 2 个对应资源。

## 3.11 区块控制

地图上的资源点和航道按颜色分成若干区块：四人地图 8 个区块，三人地图 7 个区块。

最终结算时逐个判断每个区块中谁拥有最多影响力。移动城市在其所在区块中视为 2 个额外影响力。

得分：控制 A、B、C、D、G、R 区得 3 分；控制 E、F 区得 4 分。若影响力数量并列最高则无人获得该区块分数。

## 3.12 最终计分与胜负

最终分数包含游戏中已获得的分数以及：

- 区块控制分。
- 剩余资源分：
  - 每 1 个至纯源石得 1 分。
  - 每 6 个异铁得 1 分。
  - 每 8 个源石得 1 分。
  - 每 9 个源岩得 1 分。

平局判定顺序：剩余金券多者 → 剩余至纯源石多者 → 共同胜利。

## 3.13 底层规则

### 3.13.1 效果执行顺序

多步骤效果按牌面文字从左到右、从上到下依次执行。若某一项操作无法执行，仍应尽量执行后续操作。非条件式效果不能随意放弃执行，但可因资源、标记或目标不足而跳过不可执行部分。

### 3.13.2 条件式效果

条件部分必须完整执行后才能执行条件后的效果。若玩家选择不执行条件部分或条件无法满足，应按效果具体文字停止或跳过对应部分。

### 3.13.3 部件数量限制

哥伦比亚金券和至纯源石指示物不足时可使用替代品。玩家影响力有数量限制，供应堆中无足够玩家影响力时无法继续放置玩家影响力或宣告城市样式。

## 3.14 角色牌概要

基础版每名玩家起始 5 张角色牌，提供策略和计谋两类效果，覆盖资源获取、免费探索、影响力放置/替换、出售资源、设施供应区操作、回收弃牌等。

实现要点：
- 部分角色牌效果会在本回合收尾阶段移除自己的影响力。
- "替换影响力"通常先移除目标影响力再放置自己的影响力；若同一资源点停靠了对手移动城市，可能导致无法放置。
- 涉及出售资源的效果通常可对源岩、源石、异铁、至纯源石分别选择数量。
- 回收弃牌区角色牌时，正在结算的角色牌尚未进入弃牌区，不计入回收目标。

## 3.15 企业扩展版概要

在基础版上增加合作企业、公路、额外角色牌、额外设施、额外事件和额外城市样式。

### 3.15.1 扩展设置变化

- 使用扩展中 2 张事件牌替换基础版同名事件牌。
- 将 8 个公路指示物放在地图旁备用。
- 取出 8 张合作企业板洗混为合作企业板堆。
- 城市样式牌改为基础版与扩展共 12 张按等级牌背分堆：I 级抽 4 张，II 级抽 2 张。
- 扩展中 3 张设施牌洗入设施牌堆。
- 每名玩家将扩展中的 2 张初始角色牌加入手牌，初始手牌变为 7 张。

### 3.15.2 初始企业

决定初始地块前，每名玩家从合作企业板堆抽 2 张选择 1 张作为初始企业板。所有被选择的企业板排列在地图旁。三人游戏中随机选择 1 张未被抽取的企业板作为第四张。

之后每名玩家在每张合作企业板的 `0` 级位置放置 1 个标记，并将自己初始企业板上的标记提升 1 级并结算目标格奖励。若目标格是"解锁企业特效"，只解锁不触发。

决定初始地块后，每名玩家选择 2 张手牌背面朝上放回游戏盒，本局不再使用。

### 3.15.3 企业合作等级

提升等级时将标记前进一格。目标格不是企业特效则结算奖励，是企业特效则只解锁不发动。复数玩家同时提升时由发动效果者先获得奖励，之后顺时针顺序获得。红色区域开放时在角色牌盖放前每名玩家选择一家企业提升 1 级。

### 3.15.4 触发企业特效

触发企业特效独立于"提升企业合作等级"。必须从已解锁的企业特效中选择一个发动。不同企业特效包括资源、分数、免费建设、采集、刷新设施供应区、影响力操作、干员角色牌、莱茵生命科室板等。

### 3.15.5 公路

部分扩展角色牌可将航道变为公路：
- 放置公路指示物时移除该航道上的所有影响力。
- 公路指示物覆盖该航道所有航道影响力槽位。
- 之后不能在该航道放置或移动玩家影响力。
- 所有玩家进行探索或采集时使用该航道无需支付路费。

### 3.15.6 干员角色牌

干员角色牌使用方法与普通角色牌一致，但可能具有持续性效果（持续留在场上）或一次性效果（进入弃牌区时改为放回游戏盒）。

## 3.16 二人游戏变体

以三人游戏规则为基础，关键变动：

- 开局抽 4 张企业板选择 2 张，获得初始合作等级后每名玩家有 2 家企业处于 1 级。
- 不能选择 B-01 作为初始地块。
- 非起始玩家在决定初始地块后立即放置 1 个玩家影响力。
- 获取初始资金：起始玩家 10 金券；非起始玩家 18 金券 + 3 分。
- 每回合角色牌盖放前，每名玩家选择设施供应区 1 张设施牌放回游戏盒并补牌。
- 红色区域第 6 回合开始开放。
- 干员特派抽取 3 张干员牌（非 2 张）。

## 3.17 对模拟器实现的关键抽象

推荐将规则拆成以下核心对象：

- **GameSession**：玩家、回合数、起始玩家、阶段状态机。
- **MapGraph**：地块、航道、区块、开放状态、停靠点、影响力槽位。
- **PlayerState**：资源、金券、分数、手牌、盖放牌、弃牌区、城市面板、供应堆。
- **Influence**：玩家影响力在地图上的状态。
- **EventDeck**：按颜色分堆，探索时抽取并绑定资源点指示物。
- **FacilityMarket**：设施牌堆、供应区、补牌逻辑、建设限制。
- **PatternState**：城市样式宣告、设施占用、特殊行动使用次数。
- **ActionResolver**：部署、调度、探索、城市移动、建设、特殊行动。
- **HarvestResolver**：多资源点采集、共享航道路费、不能使用新获得金券。
- **ScoringResolver**：区块控制、剩余资源、平局判定。
- **ExpansionModules**：企业合作、公路、干员牌、二人变体等作为扩展模块接入。

# 第六部分：程序模块详细设计

## 6.1 模块总览

沿用当前工程分层：

```text
Assets/YC/
  Domain/          纯规则、纯状态、纯查询，不依赖 UnityEngine
  Application/     GameSession、命令分发、流程编排
  Infrastructure/  数据加载、存档、回放、随机种子
  Presentation/    Unity UI、地图显示、输入适配
  Data/            地图、卡牌、效果、图标、图片引用
  Tests/EditMode/  规则和流程测试
```

核心设计原则：
- 所有玩家操作都通过 `GameCommand` 提交。
- 所有规则修改都由 handler/resolver 修改 `GameState`。
- `Presentation` 只展示状态并提交命令，不写规则。
- 地图图片只用于显示；规则必须使用结构化地图数据。
- 每个规则模块都要能独立做成功测试和失败测试。

## 6.2 状态模块 (State Module)

**职责：** 保存一局游戏的完整可序列化状态，支撑存档、回放、测试断言和 UI 刷新。

**目录：** `Assets/YC/Domain/State`

**关键类型：**

| 类型 | 说明 |
|---|---|
| `GameState` | 全局状态、阶段、回合、当前玩家、地图、牌堆、日志、待选择项 |
| `PlayerState` | 资源、分数、城市位置、手牌、弃牌、盖放角色牌、城市面板、样式标记 |
| `MapRuntimeState` | 地块开放状态、玩家影响力、资源点指示物、公路、特殊标记 |
| `DeckRuntimeState` | 事件牌堆、设施牌堆、设施供应区、城市样式供应区 |
| `PendingChoiceState` | 事件选项、角色牌选项、企业特效等需要玩家继续选择的上下文 |

**建议补充字段：**
- `PlayerState.InfluenceSupply` 已按规则要求默认 30，表示玩家当前可用影响力标志物数量。
- `PlayerState.ActedMainActionThisTurn`、`UsedCharacterThisRound`、`UsedSpecialActionIdsThisRound` 用于行动轮限制。
- `MapRuntimeState.RoadRouteIds` 保存公路覆盖的航道。
- `MapRuntimeState.RemovedFromGameCardIds` 保存放回游戏盒的牌。

## 6.3 定义数据模块 (Definition Module)

**职责：** 管理静态规则数据，将卡牌、地图、设施、城市样式、企业板与运行时状态分离。

**目录：** `Assets/YC/Domain/Definitions`、`Assets/YC/Data`、`Assets/YC/Infrastructure/DataLoading`

**关键类型：**
- `DefinitionDatabase`：统一查询入口。
- `MapDefinition` / `LocationDefinition` / `RouteDefinition`：地图结构化定义。
- `CardDefinition`：基础卡牌字段。
- `CharacterCardDefinition`：策略、计谋、是否一次性/持续。
- `EventCardDefinition`：事件选项、资源点指示物、资源奖励。
- `FacilityCardDefinition`：费用、颜色、分数、入场效果、唯一限制。
- `CityStyleDefinition`：宣告图形、等级、奖励、特殊行动。
- `EnterpriseDefinition`：企业等级格、奖励、企业特效。

**数据原则：** 规则 id 使用英文稳定 id；中文名放在 `DisplayName`；图像资源可保留中文文件名但数据引用稳定 id；效果先用结构化 `EffectDefinition` 表示。

## 6.4 命令模块 (Command Module)

**职责：** 定义玩家所有操作的统一入口，对非法操作返回明确错误不修改状态。

**目录：** `Assets/YC/Domain/Commands`、`Assets/YC/Application/Commands`

**建议拆分：**
- `ICommandValidator<TCommand>`：校验命令合法性。
- `ICommandResolver<TCommand>`：结算合法命令。
- `CommandRouter`：按命令类型分发 handler。
- `CommandContext`：包含 `GameState`、定义库、随机数、事件收集器。

## 6.5 回合模块 (Round Module)

**职责：** 管理阶段推进、行动顺序、当前玩家、当前行动轮。

**目录：** `Assets/YC/Domain/Rules`、`Assets/YC/Application/Flow`

**关键类型：**
- `PhaseFlow`：阶段流转规则。
- `CommandPhasePolicy`：命令允许在哪些阶段提交。
- `TurnOrderService`：根据起始玩家计算顺时针顺序。
- `RoundAdvanceService`：推进回合、行动轮、当前玩家。
- `RoundStateResetService`：重置本回合角色牌、特殊行动和行动限制。

**实现要点：**
- `CharacterCover` 要追踪每名玩家是否已盖放。
- `ActionRound1/2` 每名玩家必须完成 1 个主要行动后才能推进。
- 快速行动不推进当前玩家。
- `Cleanup` 后若 `Round == MaxRounds`，进入 `FinalScoring`。

## 6.6 地图模块 (Map Module)

**职责：** 提供地块、航道、区块、相邻关系和路线/路径查询。规则文档称为路线，代码中的 `Path` 命名保留。

**目录：** `Assets/YC/Domain/Maps`、`Assets/YC/Data/Maps`、`Assets/YC/Presentation/Maps`

**现有类型：** `IMapQueryService`、`MapQueryService`、`MapPathSearchService`、`MapDefinition`、`StaticMapDefinitions`

**表现配置：** `MapRouteDisplayDefinition`、`FourPlayerRouteDisplayDefinitions` 只保存航道影响力槽位在地图图片上的归一化坐标，坐标使用左上角 `(0, 0)`、右下角 `(1, 1)` 的地图坐标系。

**建议补齐：** `RegionDefinition`、`InfluenceSlotDefinition`、`MapOpenRuleService`、`MapOccupancyService`

**核心查询：** 相邻判断、公路状态、探索开放状态、资源指示物状态、移动城市停靠、路径经过航道列表。

**边界：** 航道规则仍只来自 `StaticMapDefinitions.CreateFourPlayerMap()`；表现层航道坐标不参与相邻关系、寻路、路费或区控结算。当前不绘制航道线段，因为路线已由地图美术确定，只保留航道影响力槽位坐标以便后续显示和手动微调。

## 6.7 影响力模块 (Influence Module)

**职责：** 统一处理玩家影响力在地图上的放置、移动、移除、替换。

**目录：** `Assets/YC/Domain/Influence`

**核心接口：** `CanPlace`、`Place`、`CanMove`、`Move`、`Remove`、`Replace`、`CountInRegion`

**放置条件：** 目标影响力槽位为空；地块需有资源点指示物且无对手移动城市；航道不能被公路覆盖；玩家供应堆有可用玩家影响力。

**调度表现：** UI 选择调度后按 `CanMove` 遍历己方影响力和候选槽位，只高亮确实可移动的来源与目标。已有影响力使用独立边框提示可移动状态，避免改变棋子本体颜色。

**实现要点：** 替换影响力先移除旧再放置新；若移除后因移动城市等限制不能放置则新影响力不能强行落位；移除后标记回到所有者供应堆。

## 6.8 移动模块 (Movement Module)

**职责：** 处理城市移动和调度影响力移动。

**目录：** `Assets/YC/Domain/Movement`、`Assets/YC/Application/Gameplay`

**城市移动条件：** 当前阶段是行动轮；支付 3 源石；目标与当前城市相邻；目标无对手城市；目标已开放探索。

**城市移动结算步骤：**
1. 支付 3 源石。
2. 移动城市到目标。
3. 移除使用航道和目标地块上的对手玩家影响力。
4. 若目标未探索，触发事件牌并放置资源点指示物。
5. 在出发资源点放置 1 个自己的影响力。

## 6.9 路费模块 (Travel Cost Module)

**职责：** 计算探索和采集的路线费用，处理路费接收方选择。

**当前实现：** `Assets/YC/Domain/Travel/RouteTollService.cs` 统一负责航道影响力检查、路费接收者选择、支付计划构建和支付应用。`ExplorationService` 与 `ResourceCollectionService` 只保留各自业务流程，并通过 `RouteTollPaymentKeyMode.SharedRegion` 复用同区域 paymentKey 去重；服务也保留 `RouteTollPaymentKeyMode.RouteId` 以支持严格按航道计费的场景。

**目录：** `Assets/YC/Domain/Rules`、`Assets/YC/Domain/Travel`

**规则：**
- 无自己影响力的航道支付 2 金券（有对手影响力时付给对手，无对手时付给供应堆）。
- 有自己影响力的航道免费。
- 被公路覆盖的航道免费且不需要选择路费接收方。
- 采集阶段同一条航道只支付一次。
- 同一区域共享 paymentKey 时，同组航道在同一次支付计划中只收一次路费；命令和 UI 仍可用具体 routeId 指定接收方。
- 采集阶段不能用本阶段刚获得的金券支付路费。

## 6.10 行动模块 (Action Module)

**职责：** 实现六类主要行动和快速行动窗口，每个行动独立校验、结算、测试。

**目录：** `Assets/YC/Application/Gameplay`、`Assets/YC/Domain/Actions`

**子模块：**
- `DeployActionResolver`：部署，放置 1 个影响力。
- `DispatchActionResolver`：调度，移动 1 个影响力最多 2 次。
- `ExploreActionResolver`：探索，支付路费、翻事件、放资源指示物、放影响力。
- `MoveCityActionResolver`：城市移动，调用移动模块。
- `BuildFacilityActionResolver`：建设，支付费用、放设施、得分、入场效果、补供应区。
- `SpecialActionResolver`：城市样式解锁的特殊行动。

**通用校验：** 必须在行动轮阶段；当前玩家匹配；本行动轮尚未执行主要行动；存在 `PendingChoice` 时只允 `ResolvePendingChoice`。

## 6.11 事件模块 (Event Module)

**职责：** 管理事件牌抽取、资源点指示物放置和事件选项结算。

**目录：** `Assets/YC/Domain/Cards`、`Assets/YC/Domain/Effects`

**关键类型：** `EventDeckService`、`EventResolutionService`、`ResourceTokenService`、`PendingChoiceFactory`

**触发来源：** 开局选择初始地块、探索地块、移动城市进入未探索地块。

## 6.12 资源与经济模块 (Resource Module)

**职责：** 管理源岩、源石、异铁、至纯源石、金券和分数变化。

**目录：** `Assets/YC/Domain/Economy`

**规则：** 源岩/源石/异铁使用玩家资源计数器；金券和至纯源石来自公共供应堆不足可用替代物；支付给对手和支付给供应堆要区分；分数变化立刻体现在轨道中。

## 6.13 建设模块 (Facility Module)

**职责：** 管理设施牌供应区、建设费用、城市面板位置、入场效果和唯一限制。

**目录：** `Assets/YC/Domain/Facilities`、`Assets/YC/Application/Gameplay`

**建设条件：** 城市面板有空位；目标设施在供应区；能支付费用；唯一设施不能重复建设同名牌。

**结算：** 支付费用 → 放入城市面板 → 获得牌面分数 → 结算入场效果 → 补牌至 6 张。

## 6.14 城市样式模块 (City Style Module)

**职责：** 判断设施颜色与位置是否满足样式，管理持有和特殊行动。

**目录：** `Assets/YC/Domain/CityStyles`

**规则：** 条件可旋转不可翻转；彩色设施可视为任意颜色；每个设施只能用一次；宣告后旋转 180 度；I 级和 II 级样式标记复位规则不同；特殊行动每回合每张最多一次。

## 6.15 角色牌与效果模块 (Card Effect Module)

**职责：** 处理角色牌策略/计谋、设施入场、事件选项、城市样式、企业特效等效果。

**目录：** `Assets/YC/Domain/Effects`、`Assets/YC/Domain/Cards`

**效果执行原则：**
- 多步骤按定义顺序执行。
- 某一步无法执行时非条件式效果继续尽量执行后续步骤。
- 条件式效果必须先完整满足条件才能执行结果部分。
- 需要玩家选择时写入 `PendingChoice` 并暂停效果链。
- 收尾阶段效果保存为 `DelayedEffectState`。

## 6.16 采集模块 (Harvest Module)

**职责：** 处理采集阶段的资源点选择、共享路费、资源获得。

**目录：** `Assets/YC/Domain/Harvest`、`Assets/YC/Application/Gameplay`

**规则：** 玩家可选任意数量有自己的影响力或停靠移动城市的资源点；每个资源点每次只能获得一次资源；多资源点共用航道只支付一次路费；不能用新获得的金券支付路费。

**建议实现：** 生成选择集合 → 计算所需航道集合 → 生成路费报价并支付 → 发放资源。

## 6.17 计分模块 (Scoring Module)

**职责：** 处理最终计分、区控、剩余资源分和平局。

**目录：** `Assets/YC/Domain/Scoring`

**规则：** 区块内影响力最多者控制该区块（移动城市视为 2 个额外影响力）；并列最高时无人得分；A/B/C/D/G/R 区 3 分，E/F 区 4 分；剩余资源分按比例换算；平局先比剩余金券再比至纯源石。

**输出：** `ScoreBreakdown`、每个区块的控制者和影响力明细、平局比较过程。

## 6.18 扩展模块 (Expansion Module)

**职责：** 隔离企业扩展、二人变体、公路、干员牌等非 MVP 规则。

**目录：** `Assets/YC/Domain/Expansions`

**子模块：** `EnterpriseModule`、`RoadModule`、`OperatorCardModule`、`TwoPlayerVariantModule`

**接入方式：** `GameRuleset` 标识规则集；各模块注册自己的校验、resolver、阶段钩子；基础版测试默认不加载扩展模块。

## 6.19 日志、回放与随机模块 (Log Replay Module)

**职责：** 记录所有成功命令和关键事件，支持固定 seed 重放。

**目录：** `Assets/YC/Application/Logging`、`Assets/YC/Infrastructure/Replay`

**日志要求：** 记录命令 id、玩家、阶段、关键目标和结果；记录随机抽牌结果；记录资源/分数/影响力/城市位置变化；非法命令只记 Debug 日志不进入回放序列。

## 6.20 表现适配模块 (Presentation Adapter)

**职责：** 把 Unity 输入转换为命令，把 `GameState` 投影成 UI 展示模型。

**目录：** `Assets/YC/Presentation`

**子模块：** `MapDisplayController`、`ActionPanelController`、`PlayerPanelController`、`RoundTrackerController`、`LogPanelController`、`DebugGameController`、`Presentation/Maps` 航道影响力坐标配置

**约束：** UI 不直接修改 `GameState`；UI 不自行判断复杂规则；地图热点坐标与规则节点用稳定 id 绑定。

## 6.21 合法命令枚举模块 (Legal Action Module)

**职责：** 给 UI 和 AI 查询当前玩家可做什么，不改变状态。

**目录：** `Assets/YC/Domain/Rules`、`Assets/YC/Application/Queries`

**输出示例：** 当前可用主要行动列表；部署可放置影响力槽位；调度可移动玩家影响力；可探索地块及最低路费路线；可移动城市目标；可建设设施；可使用角色牌效果；可宣告城市样式组合。

## 6.22 推荐实现顺序

**第 1 阶段 — 状态和地图：** 修正玩家影响力数量 → 完成四人地图 → 完成三人地图 → 补 `RegionDefinition` 和区块数据 → 补 `MapOpenRuleService`。

**第 2 阶段 — 影响力/路费/移动：** `InfluenceService` → `TravelCostQuote` 和支付结算 → 部署 → 调度 → 城市移动。

**第 3 阶段 — 探索/建设/采集：** 事件抽取和指示物 → 探索 → 设施供应区和建设 → 采集阶段 → 收尾阶段。

**第 4 阶段 — 计分和完整基础版：** 区控 → 剩余资源分和平局 → 跑通 8 回合 Debug 对局 → golden replay 测试。

**第 5 阶段 — 卡牌与扩展：** 基础角色牌最小效果系统 → 城市样式宣告和特殊行动 → 企业扩展、公路、干员牌和二人变体。

## 6.23 模块依赖关系

```text
Presentation
  -> Application GameSession
    -> Command Handlers
      -> Action / Round / Harvest / Scoring Resolvers
        -> State  -> Definitions  -> Map  -> Influence  -> TravelCost  -> Effects

Infrastructure
  -> State serialization  -> Definition loading  -> Replay
```

**禁止依赖：** `Domain` 依赖 `Presentation`；`Domain` 依赖 Unity 场景对象；`Presentation` 直接改 `GameState`；单个 action handler 内硬编码所有卡牌效果。

## 2026-06-16 Host 权威快照同步与统一状态刷新

本轮针对多人模式下 Host 与 Client 状态不同步的问题，完成“最小快照同步 + 统一状态刷新”MVP。核心目标是让 Host 成为唯一规则结算方，Client 收到确认后只替换为 Host 快照，不再本地重放命令。

### 已完成

- `ConfirmedGameCommandDto` 增加 `GameState State` 字段，Host 每次命令成功后把当前 `session.State` 放入确认消息。
- `AuthoritativeCommandDispatcher.ApplyConfirmedCommand()` 改为只校验确认序号和快照有效性，然后执行 `session.ReplaceState(confirmed.State)`；客户端不再调用 `session.Submit()` 重放确认命令。
- 联网模式下 `MobileCityInteractionController.SubmitGameCommand()` 在 `commandTransport == null` 时直接返回“联网同步未初始化”，禁止 fallback 到本地单机提交。
- `MobileCityInteractionController` 将单个 `cityObject` 改为 `Dictionary<int, GameObject> cityObjectsByPlayerId`，新增 `RefreshCityViewsFromState()`，按 `session.State.Players` 创建、移动或隐藏每个玩家城市。
- 新增 `RefreshAllFromState()`，统一刷新城市、资源、影响力、行动面板、回合轨道和待选项/高亮；网络确认、初始同步和本地 Host 成功命令确认后都走同一入口。
- `RoundTrackerController` 新增 `RefreshFromState(GameState state)`，marker 由 `GameState.Round / Phase` 决定；联网模式禁用并忽略本地结束回合按钮。

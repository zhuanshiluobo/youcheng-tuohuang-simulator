# 事件颜色、回合盖放与弃牌查看修复

日期：2026-10-01。对应用户反馈：黄色资源点翻出绿色事件、第二回合盖放页消失、弃牌查看改为点击空白处关闭。

## 修复结果

1. **事件颜色**：城市移动完成后的 Lua 观察器原来固定传入 `eventColor = 'green'`，导致黄色、红色地点也抽绿色牌池。现读取目标地点的事件颜色。Lua 地图快照同时补充地点颜色，并使用正式三人地图；探索效果改为读取当前注入地图的颜色。基础事件定义、洗牌池及 Sprite 整图对应关系经过回归验证，没有发现基础 Sprite 的绿黄图源串用。
2. **回合盖放**：盖放页与角色、地图效果原来共用弹窗实例。状态刷新先打开新回合盖放页，随后旧效果的清理把同一弹窗隐藏。现由 `characterCoverChoiceDialog` 独立管理盖放页，旧效果只清理自己的页面；每轮选择和确认继续走正式规则。
3. **弃牌查看**：只读弃牌页不再创建取消按钮，点击卡牌外的页面空白处关闭；提示为“点击空白处关闭”。提示保存在 `EffectDialogLayoutProfile.asset`。卡牌详情、滚动条、拖动及右键不会误关；用于业务选择的弹窗仍按原规则确认或取消。移除按钮后还修正了页脚提示被隐藏的问题。

本次没有重新生成或保存覆盖场景、预制体。文案修改属于源配置资产；页面关闭行为属于运行时代码。保留工作区内原有地图任务与 Sprite 迁移改动。

## 中间失败记录

原始中间记录均保留在 `Logs/CardFlowFix/`，未覆写为成功：首轮新增测试的 NUnit API 不兼容、采集阶段测试错误使用 `CurrentPlayerId=-1`、弃牌提示页脚隐藏及 EditMode 立即销毁时的派发问题已修正后复跑。

最后审计发现，新增指针测试的 `.meta` GUID 长度不正确，导致原先 37 项通过结果中漏掉 4 项测试。修正 GUID 后补齐 EditMode 的 EventSystem 与 Raycaster 生命周期登记；期间测试代码直接调用内部 API 引起的编译错误也已修正。最终重新运行完整过滤范围，实际枚举并通过 41 项（`editmode-final-verified/editmode-20261001_011529.xml`）；交付证据使用这次结果。

旧玩家驱动依赖 `Camera.main`，现改用实际参与 EventSystem 的物理相机；地图预选后需要第二次点击确认，驱动已支持该可见交互。`journey-editor-2` 实际完成八回合和返回菜单、错误 0，但旧 `PJ-001` 仍因等待原来的取消/确认弹窗计数而记为 `REQUIRED_ACTION_MISSING`；保留该失败，不将其计为旧场景全绿。新的 `PJ-CARD-FLOW` 使用上述明确门禁，老 `PJ-001` 的取消要求仍保留。

## 后续：自动测试误启动的清理与修复

用户反馈普通打开游戏仍自动点击。排查发现 Unity Hub 进程仍携带 `journey-editor-2` 的旧测试启动参数；Runtime 原来仅凭输出目录参数启用，每次进入 Play 都可能重启测试，编辑器启动器也未检查旧输出目录。

已关闭核验过的残留测试启动进程，并修改当前源码：

- 自动测试必须显式传入 `--yc-player-journey-run-once`，普通启动及旧参数均不启用。
- 启动前原子创建输出目录中的 `.player-journey-started` 标记；同一目录即便中断、重新 Play 或重启编辑器，也不能再次运行。两个 PowerShell 启动脚本同步检查该标记。
- 编辑器启动器在打开场景和进入 Play 前检查有效启动条件；测试种子只在实际运行自动测试时覆盖正常随机种子。

已通过 `dotnet build Assembly-CSharp-Editor.csproj --no-restore --verbosity quiet` 编译（0 错误，41 条依赖版本/未赋值字段等警告）。本次没有再次启动自动点击流程。原玩家构建保留未重打包；今后用此源码构建后，上方直接启动示例需额外传入一次性参数，或使用已更新的启动脚本。

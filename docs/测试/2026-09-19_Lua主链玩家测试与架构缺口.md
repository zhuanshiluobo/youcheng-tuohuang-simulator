# Lua 主链玩家测试与架构缺口（2026-09-19）

## 本次修复

1. **盖牌后只有阶段投影、没有可执行行动窗口**：`CoverCharacterCardCommandHandler` 在内核完成盖牌后调用正式回合服务启动后继节点。测试不替游戏推进。
2. **使用角色牌被内部交互屏蔽**：角色面板不再把 `round.mainline.complete` 等内部主链等待判为玩家待选择项。
3. **雷蛇策略生成放置请求但外层路由漏接**：新增独立影响力 Interaction renderer，统一处理基础放置、移除。角色 UI 不再兼管基础放置。移除候选使用影响力实例 ID，展示时映射为公开地图槽位，回答仍提交实例 ID。
4. **部署 UI 先选完目标才挂 Effect**：点击部署即创建行动窗口下的 `action.main.execute`；该节点调用基础 `effect.influence.place`，由内核产生合法目标请求。主要行动预算由父节点在子树成功完成后扣除一次，失败或取消不消费。
5. **部署取消**：确认弹窗取消按钮或选择阶段 Esc 提交带交互 ID、版本号的拒绝答案。只允许尚未放置的主要行动子节点取消；雷蛇两次独立放置不允许借用此取消能力。取消节点留存为 `Failed/player_cancelled`，解除阻塞，供恢复、幂等与审计使用；不物理删除历史。
6. **未实现 Lua API 假报成功**：通用执行器不再对尚未实现的类型直接返回 `Completed`，改为明确内核故障停止，保留类型和原因。注册名称不等于已有规则实现。
7. **真实地图输入**：地图热点、影响力槽加入 EventSystem 指针点击路径；旧鼠标路径在已有 Physics2DRaycaster 时不重复触发。
8. **雷蛇收尾漏规则**：补入通用 `TimingHandlerRegistry` 的 `after_resolve_once/playerCleanup` 路径。来源 Effect 成功后保存一次性绑定，收尾在同一内核事务中调用 Lua、编译并挂载子树；版本和内容哈希不匹配则停止。Lua 从只读地图查询当前己方影响力，返回基础 `RemoveInfluence`，无己方影响力时返回空列表。克隆恢复和重复时点事件不重复移除。
9. **必须输入的提示被结算消息覆盖**：提示入口通过交互路由只读查询当前待处理提示，并在采集结果等消息之后保留操作说明；收尾阶段不再提示玩家手动结束。读取提示不会触发旧交互取消，避免提示更新时递归清除高亮。

## 玩家测试边界

`YC.PlayerJourney` 独立程序集仅依赖 Unity UI/EventSystem。运行期决策只读取可见文字、可 raycast 控件和实际绘制的高亮；不读写权威状态，不提交命令，不调用业务 Controller，不使用反射。静态门禁为 `PlayerJourneyBoundaryTests`。

Editor 启动器仅打开 StartScene、固定 GameView 为 1920×1080 并进入播放模式。Unity 2022 的分辨率设置通过 Editor 内部接口完成，独立于运行期玩家程序集；不能用这个入口检查或改变游戏业务状态。种子在点击本地游戏前配置。

脚本：

```powershell
& tools/tests/Run-PlayerJourneyEditor.ps1 -OutputDirectory 'G:\NoMadCity\Logs\PlayerJourney\新目录'
```

每次运行使用新目录。错误退出、超时和失败轨迹保留，不删除文件，不在失败状态上补状态后继续。

## 尚未完成的迁移与验收

| 项目 | 当前情况 | 后续验收要求 |
| --- | --- | --- |
| 调度、探索、移动、建设点击即挂载 | 仍有旧 UI 本地选择过程；确认后的结算已不同程度接入 Effect，尚未全部复用本次部署的前置交互生命周期 | 每种行动的开始、选目标、支付、确认、取消及断线恢复均在持久化子树内表达；不能只包一层成功日志 |
| Lua 占位 API | 多种名称已注册，但规则未实现；现在明确故障停止 | 逐项补合同、宿主原语与 Lua 组合，并通过真实流程验证，不能用空 Completed 填空 |
| 角色能力迁移 | 雷蛇策略已使用 Lua 组合基础放置；其他能力仍有 C# 专用执行和旧 Pending 兼容 | 逐张迁移为共用原语，逐步删除重复目标 UI 与专用规则分支 |
| 固定时点处理区 | 已实现一次性玩家收尾绑定、持久化恢复和版本校验 | 仍需补齐 `while_active` 枚举、多个收尾处理器的玩家排序及 `finalScoring` 处理区 |
| PJ-002 | 当前脚本接受场景名称，但仍共用基础策略，未达到分支丰富覆盖标准 | 自然覆盖探索、移动、调度、建设、付费采集、城市样式与多步骤选择，逐种子完整到终局 |

| PJ-004/PJ-005 | 本次未执行四客户端/断线恢复黑盒 | 正常房间流程、每端 UI 操作、公开分数一致、恢复不重复结算 |
| 既有 34 项红测 | 多数与旧阶段/旧 Pending 测试、设施目录资源漂移、UI 静态约束有关 | 按失败项分辨生产问题与过期测试，不能批量改断言或跳过来做绿 |

需要优先迁移的 Lua 占位合同包含流程循环/随机、资源折扣与出售、牌堆操作、角色牌移动/翻开、企业能力、下回合起始玩家覆盖以及各类主要行动入口。它们可能在旧领域服务中已有规则，但尚未等价封装到 Lua 宿主执行器；本次没有把“旧功能能用”当成“新 Lua 合同已完成”。

既有红测也不能统称为无害：例如旧 `GameplayCommandHandlerTests` 辅助方法在收尾已经自动推进后再次调用 `EndCompletedAction`，属于可定位的过期阶段假设；设施多步效果、采集路径和特殊行动待处理状态的失败仍需分别排查。本次针对雷蛇旧延迟列表测试暴露的真实漏规则补了新模型回归，没有恢复旧的 `DelayedCharacterEffects` 双轨状态，也没有删除原失败测试。

本记录描述实际已验证范围，不代表 Lua 架构迁移整体完成，也不替代正式多人发布门禁。

## 统一交互验收条件

1. 点击只提交激活意图，父节点挂在当前主链窗口下。
2. Effect 生成唯一交互请求，保存候选、回答者、版本及阻塞关系；展示层不提前征集相同参数。
3. 玩家确认通过 Application 命令入口提交答案；Host 复验身份、版本、候选和当前规则状态。
4. 成功提交后才更新权威资源、位置、牌区及结果；拒绝、非法或过期答案不发布变化。
5. 展示层根据已确认的投影刷新数字、卡牌、地图或动画；动画完成回调不能直接写规则状态或推进 Effect。
6. 下一项交互由内核新请求决定，不由 UI 自己模拟效果流程。已有牌面要求的前置付费、翻牌等仍按各自 Effect 提交边界执行，不能把整个复杂链伪装成单次原子提交。

### 只读快照参数的统一归一化（2026-09-20）

真实目录脚本回归暴露：`Effect.Choice({options=ctx.payload.candidateIds})` 的候选来自只读代理，直接遍历 Lua table 的 Pairs 会把它误读成空数组。宿主现在记录自己创建的只读代理与底层值的弱引用映射，归一化和返回值预算检查均读取这些宿主值；不执行脚本任意元方法，也不把可写表暴露给 Lua。脚本无需为了传递只读数组逐项复制，后续其他通用 Effect 同样适用。

## 验证内容

| 检查 | 结果 |
| --- | --- |
| 达到全图缩小下限 | 地图 Sprite 四角投影都处于相机视口内 |
| 观察框只收缩多余轴 | 相对最大 UI 区域的宽或高至少一个保持 1 |
| 相机与可见范围一致 | 独立 `Map Visible Bounds` 屏幕边界与相机像素矩形相差小于 1 像素 |
| 固定 UI 容器 | 缩放前后 `Map Viewport` 及全部子 RectTransform 的位置和尺寸保持不变 |
| 重新放大 | 相对观察框恢复到完整区域 |
| 拖动 | 正式导航方法根据指针位移改变焦点，并在拖动及释放时抑制地图点击 |
| 双指距离比 | 两指距离由 100 增至 150 时，目标缩放由 1 变为 1.5 |
| 缩放下限 | 目标缩放不会越过完整地图所需的最小值 |
| 地图隐藏 | 相机停用，并清除双指手势状态 |
| 背景 | 四块正式背景节点均保留原 Sprite 引用 |
| 建设文案 | 源预制体的序列化格式、组件默认值与设计文档均已更正为“延伸枢纽” |

滚轮步长在源 `MapView.prefab` 中由原始 0.1 改为 0.18（1.8 倍），原平滑时间保留。双指手势一旦在地图内开始，可在原最大地图区域内继续操作，不会因为观察框自行缩小而过早中断。

## 验证边界

- 导航测试通过调用正式的指针/双指处理方法传入坐标，未注入操作系统鼠标滚轮或真实多点触摸。双指触屏的设备兼容性、物理手感和触点生命周期仍需实机体验。
- 没有运行整局游戏或全量测试；没有把其他并行任务的测试结果计入本记录。
- 竖屏截图显示既有顶栏及右侧行动区域存在超出屏幕的情况。本次仅验证地图区域在竖屏下仍能完整显示，不代表主界面全部模块已完成竖屏适配。
- 地图标题和装饰边框仍按原素材绘制在地图区域之上；全图检查针对相机取景范围，不代表移除了 UI 装饰。

# 入场主链迁移与测试记录

## 实现范围

四人局第一回合主链前置四个 `player_entrance` 节点，之后衔接回合开始、统一盖牌和原有行动主链。其他人数使用实际玩家数；后续回合不重复入场。

每个入场节点由固有 Effect `flow.player.enter` 创建地图选点交互，落位后发布 `PlayerEntered(player, resourcePoint)`。世界 Lua 处理器挂载 B-01 的三种资源各 2，以及无资源点标记时的绿色事件牌 Effect。所有子树完成后才激活下一名玩家。开局金券在所有人入场结束后通过通用资源 Effect 发放。

入场不再创建旧 `PendingCardSession`。旧选点、入场选项命令只适配成通用交互答案；生产地图 UI 直接回答内核交互。活动玩家、阶段均投影自主链。

## 测试发现与修复

- Lua 编译器遗漏了 `iron` 小写资源标识，导致合法的异铁奖励编译失败，已补齐。
- 通用单选答案可能规范化为单项数组，入场执行器已按既有回答协议读取。
- 会话层把旧入场选点命令当成待交互期间的新行动拦截；只对当前玩家匹配的 `entrance.location` 请求放行，仍由内核校验候选。
- 入场奖励、抽牌的持久化子树必须完整结束后才推进；牌堆为空、规则缺失或子效果失败停止主链，不静默跳过。
- `NMC012` 的零选项测试修改了用于还原全局事件牌目录的同一实例，污染后续测试；替换夹具改用独立副本。
- 旧开发跑局器通过参数注入入场 Lua 注册器，保持 Application 不依赖 Infrastructure，并回答通用入场事件交互。该工具有预置状态，仅作诊断，不能代替玩家黑盒验收。

## 已验证场景

`PlayerEntranceMainlineTests` 覆盖四人节点和顺序、B-01 三种资源各 2、重复提交拒绝、开局金券只发一次、下一回合无入场前缀、事件牌阻塞下一人、克隆恢复不重复抽牌和发奖、通用答案防重放、普通移动不触发入场奖励、主链外调用入场 Effect 被拒绝、空事件牌堆不推进。

第一轮定向回归：`Logs/entrance-third.xml`，39/39 通过。

扩大回归：`Logs/entrance-expanded3.xml`，86 项中 81 通过、5 失败。新增入场测试、单人开局、联机确认命令同步、四人开发跑局均通过；5 项失败均来自原基线的旧收尾测试，仍在自动收尾结束后重复提交手动结束命令，后续改按真实主链推进验证。

最终扩大至 172 项（含 NMC003—NMC014、入场、角色流程、主机同步、多人回合、黑盒边界和控制器体积门禁）：`Logs/entrance-verified.xml` 中 170 项通过，剩余 2 项为修改后的测试在采集事务替换玩家集合时继续枚举旧集合。夹具改用索引、事务后重新取得玩家对象；`Logs/entrance-character-verified.xml` 定向复测 24/24 通过。两次结果合并覆盖的 172 项均已通过；没有重跑耗时较长且已经通过的四人八回合测试。

收尾测试现在依次完成主链行动窗口与各玩家采集任务，断言自动收尾后的返牌、角色标记复位、下一回合盖牌、第四回合红区和第八回合最终计分。不再靠修改阶段或重复提交旧结束命令代替流程。

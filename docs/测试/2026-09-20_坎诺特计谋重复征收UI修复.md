# 坎诺特计谋重复征收 UI 修复

## 原因与改动

点击计谋时，旧 `CharacterCardEffectInteractionUiCoordinator` 先显示征收资源预选，玩家回答后才提交角色激活。新的 `CharacterAbilityEffectExecutor` 接到激活后创建自己的 `character.cannot.tactic.choose_resource` 交互，因此玩家需要连续回答两次征收。

修复后，坎诺特计谋入口只提交激活，不预选资源、不打开旧征收弹窗。资源选择由主链下的 Effect 生成，由通用角色交互 UI 展示和回答。没有通过向内核补旧预选参数来绕过新交互，也没有改动征收数值规则。

## 回归证据

- `Logs/cannot-double-ui-before.xml`：新增 UI 入口测试在修复前失败，观察到提交次数为 0，证明旧预选截住了激活。
- `Logs/cannot-double-ui-fixed2.xml`：39/39 通过，覆盖角色 UI 协调器、NMC010、角色生命周期和玩家黑盒边界。
- 新增规则链路测试：仅产生一个征收请求；回答异铁后，两名玩家的 2/3 异铁分别变为 4/6 金券，发动者加 1 分并弃牌；无第二个征收请求，重复回答被拒绝且不重复结算。

## 真实玩家验收方式

黑盒增加 `cannot-tactic` 策略，仅依据可见手牌、按钮和弹窗输入：优先盖放坎诺特，发动计谋，统计征收选项点击次数。通过条件要求恰好一次征收选择，同时完成 16 次部署确认、一次取消和完整八回合，最终计分后返回开始菜单。默认雷蛇策略仍要求收尾移除，不因新增场景放宽其门禁。

实跑结果：`Logs/PlayerJourney/20260920-cannot-tactic/result.json`，成功，8 回合、100 次 UI 输入、16 次部署确认、1 次取消、1 次角色发动，`requisitionSelections = 1`，运行错误 0，显示最终计分并返回开始页面。轨迹第 8 步点击 `action.character.tactic`，第 9 步回答唯一的征收弹窗。种子 `2026091901`，1920×1080。

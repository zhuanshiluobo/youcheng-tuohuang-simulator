# 行动实现方案

本文档说明如何在当前 Unity 模拟器中实现“主要行动”和“快速行动”的区别，并给出一个可以直接落地的简单 UI 方案。

## 1. 规则目标

在玩家行动阶段，每名玩家在自己的行动轮中：

- 必须执行 1 个主要行动。
- 可以在主要行动前后执行任意次数快速行动。
- 主要行动进行中不能插入快速行动。
- 执行主要行动后，当前玩家进入“已完成主要行动，等待结束行动”的状态。
- 玩家提交 `EndAction` 后，行动轮才推进到下一名玩家或下一行动轮。
- 快速行动执行后，不推进当前玩家。

基础版主要行动包括：

- 部署。
- 调度。
- 探索。
- 城市移动。
- 建设。
- 特殊行动。

基础版快速行动包括：

- 使用角色牌。
- 宣告城市样式。

## 2. 核心区别

主要行动和快速行动的区别应由规则状态控制，而不是只靠 UI 禁用按钮。

| 类型 | 是否必须 | 是否标记主要行动完成 | 是否受行动轮限制 |
|---|---|---|---|
| 主要行动 | 是 | 是 | 每名玩家每个行动轮 1 次 |
| 快速行动 | 否 | 否 | 按具体规则限制次数 |

因此：

- 主要行动成功结算后，只标记当前玩家已完成主要行动，不立即推进玩家。
- `EndAction` 成功结算后，才调用回合推进逻辑。
- 快速行动成功结算后，只刷新当前状态和 UI。
- 存在待选择项时，除 `ResolvePendingChoice` 外不允许提交新行动。

## 3. 状态字段

当前工程已有字段可以支撑第一版实现：

```csharp
GameState.Phase
GameState.CurrentPlayerId
GameState.PendingChoice
PlayerState.ActedMainActionThisTurn
PlayerState.UsedCharacterThisRound
PlayerState.UsedSpecialActionIdsThisRound
```

建议 UI 层额外维护一个只用于表现的模式枚举：

```csharp
public enum ActionPanelMode
{
    Hidden,
    ChooseAction,
    ResolvingTarget,
    PendingChoice,
    WaitingForNextPlayer
}
```

该枚举不进入规则状态，只用于控制面板显示。

## 4. 命令处理原则

所有按钮点击都应提交 `GameCommand` 或进入目标选择模式，不直接修改 `GameState`。

主要行动命令：

- `DeployInfluence`
- `DispatchInfluence`
- `ExploreLocation`
- `MoveCity`
- `BuildFacility`
- `UseSpecialAction`

快速行动命令：

- `UseCharacterCard`
- `DeclareCityStyle`

通用命令：

- `ResolvePendingChoice`
- `EndAction`

主要行动 handler 成功后：

1. 修改规则状态。
2. 写入 `GameEvent`。
3. 标记 `PlayerState.ActedMainActionThisTurn = true`。
4. 调用 `RoundAdvanceService.MarkMainActionComplete`。
5. UI 保持当前玩家，并提示点击“结束行动”。在提交 `EndAction` 前，快速行动仍可按规则在主要行动后执行。

`EndAction` handler 成功后：

1. 校验当前玩家已经完成主要行动。
2. 校验不存在 `PendingChoice`。
3. 调用 `RoundAdvanceService.EndCompletedAction`。
4. UI 刷新为下一名玩家、下一行动轮或后续阶段。

快速行动 handler 成功后：

1. 修改规则状态。
2. 写入 `GameEvent`。
3. 更新对应次数限制字段。
4. 不调用当前玩家推进。
5. UI 留在当前玩家行动面板。

## 5. 简单 UI 方案

在地图右侧放置一个“行动面板”。

```text
当前玩家：蓝色玩家
阶段：第 2 回合 / 行动轮 1 / 当前行动

快速行动
[使用角色牌] [宣告城市样式]

主要行动
[部署] [调度] [探索]
[城市移动] [建设] [特殊行动]

状态：
尚未执行主要行动
```

玩家点击快速行动后：

```text
快速行动
[使用角色牌 已使用] [宣告城市样式]

主要行动
[部署] [调度] [探索]
[城市移动] [建设] [特殊行动]

状态：
尚未执行主要行动
```

玩家完成主要行动后：

```text
主要行动已完成
请点击结束行动
```

玩家点击结束行动后，系统切换到下一名玩家或下一行动轮。

## 6. Unity UI 层级

建议新增或扩展 `ActionPanelController`。

```text
Canvas
  ActionPanel
    CurrentPlayerText
    PhaseText

    QuickActionGroup
      UseCharacterButton
      DeclareCityStyleButton

    MainActionGroup
      DeployButton
      DispatchButton
      ExploreButton
      MoveCityButton
      BuildButton
      SpecialActionButton

    StatusText
```

按钮行为：

- `UseCharacterButton`：提交 `UseCharacterCard` 或打开角色牌效果选择。
- `DeclareCityStyleButton`：进入城市样式宣告选择。
- `DeployButton`：进入选择影响力槽位模式。
- `DispatchButton`：先选择自己的影响力，再选择目标槽位。进入来源选择后，UI 只给确实存在合法移动目标的己方影响力显示高亮边框；点击已有影响力槽位自身即可选中来源，目标阶段可点击高亮空槽提交调度。
- `ExploreButton`：进入选择目标地块与路线模式。
- `MoveCityButton`：进入选择相邻地块模式。
- `BuildButton`：打开设施供应区。
- `SpecialActionButton`：打开可用特殊行动列表。

未实现的行动按钮第一版可以保留显示，但点击后给出“暂未实现”的状态提示。

## 7. 按钮启用规则

行动面板刷新时，按以下规则控制按钮：

1. 当前阶段不是 `ActionRound1` 或 `ActionRound2` 时，隐藏或禁用行动按钮。
2. `GameState.CurrentPlayerId` 不是本地/当前操作玩家时，禁用行动按钮。
3. 存在 `GameState.PendingChoice` 时，隐藏行动按钮，只显示待选择面板。
4. `PlayerState.ActedMainActionThisTurn == true` 时，禁用所有主要行动和快速行动按钮。
5. `PlayerState.UsedCharacterThisRound == true` 时，禁用“使用角色牌”按钮。
6. 没有可宣告城市样式时，禁用“宣告城市样式”按钮。
7. 没有可用特殊行动时，禁用“特殊行动”按钮。

## 8. 最小实现步骤

第一版建议按以下顺序实现：

1. 新增 `ActionPanelController`。
2. 在 `SampleScene` 中放置右侧行动面板。
3. 读取 `GameState` 刷新当前玩家、阶段、按钮状态。
4. 接入已实现的主要行动：
   - 部署。
   - 调度。
   - 城市移动。
5. 未实现行动点击后显示“暂未实现”。
6. 主要行动成功后标记完成并提示点击“结束行动”。
7. `EndAction` 成功后刷新到下一名玩家。
8. 快速行动先只做按钮状态和提示，等角色牌与城市样式模块实现后再接入真实命令。

## 9. 验收标准

第一版完成后应满足：

- 行动阶段能看到当前玩家和行动轮。
- 主要行动与快速行动分区显示。
- 快速行动按钮点击后不推进玩家。
- 主要行动成功后不立即推进玩家，而是提示点击“结束行动”。
- `EndAction` 成功后推进到下一名玩家或下一行动轮。
- 当前玩家已经执行主要行动后，不能继续执行其他主要行动。
- 存在待选择项时，行动按钮不可用。
- UI 不直接修改 `GameState`，只提交命令或进入目标选择模式。

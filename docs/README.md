# 文档总入口

## 当前事实源与阅读顺序

当前状态只维护在以下三个入口，优先级从高到低：

1. [项目总览](概览/项目总览.md)：唯一当前事实源，记录当前支持范围、功能状态、测试基线、构建状态和已知限制。
2. [发布检查清单](概览/发布检查清单.md)：发布、交付或演示前的测试、构建、人工验收和已知问题收口记录。
3. 根目录 [README](../README.md)：面向使用者的简要状态；内容必须与项目总览一致，但不承载完整验收细节。

新开发者应先阅读项目总览、发布检查清单、[项目术语表](规则/项目术语表.md)和与当前任务相关的模块文档。不要从工作记录中的旧测试数量、构建时间、分支名、控制器行数或静态构造数量推断现在的状态。

## 文档分类

- [概览](概览/)：当前事实源与发布检查清单。
- [规则](规则/)：规则总结、术语、牌面与原始材料校验。
- [架构](架构/)：分层、约束、程序模块和技术选型。
- [设计](设计/)：交互、流程和专项实现规格。
- [计划](计划/)：阶段目标、依赖、里程碑和验收条件；计划完成后以项目总览为准。
- [指南](指南/)：测试、诊断、自动跑局和联机操作流程。
- [模块文档](模块文档/)：已实现模块的稳定契约和使用说明。
- [数据](数据/)：人工校验后的结构化参考资料。
- [工作记录](工作记录/README.md)：按日期归档的实现过程、当时的验证证据和历史决策。

## 专项设计入口

- [命令与效果系统准备规范](设计/命令与效果系统准备规范.md)：一级效果、二级流程、三阶段插入连锁与异常恢复准备稿；尚未实现，不代表当前功能状态。

## 历史工作记录规则

- 历史记录保留，不为追求“最新”而改写当时的结论或数字。
- 工作记录中的“当前”“最新”“基线”等表述仅对该文档日期有效；各归档文档应在开头说明其快照属性。
- 若历史文档与项目总览冲突，以项目总览为准；需要发布结论时，再以发布检查清单为准。
- 新增当前状态时，更新项目总览和必要的 README 摘要；不要新增另一份“当前总结”。

## 维护规则

- 当前测试数、构建时间、已知问题、支持模式和功能完成状态先更新项目总览，再同步根 README 摘要和发布检查清单。
- 架构文档只维护稳定结构和约束，不保留易过期的“当前”代码行数或构造数量。
- 移动或删除文档后，同步更新本索引、根 README 和受影响的交叉引用。
- 规则、牌面和地图数值若与原始材料冲突，以原始规则书、卡图或地图资料为准，并补充校验记录。

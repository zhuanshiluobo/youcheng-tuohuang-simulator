## 当前实际架构

Unity 工程当前采用：

```text
Assets/YC/
  Domain/
  Application/
  Infrastructure/
  Presentation/
  Data/
  Editor/
  Tests/EditMode/
```

其中：

- `Domain`：纯 C# 规则核心，不引用 `UnityEngine`。
- `Application`：命令提交、对局编排、入场 handler。
- `Presentation`：开始页、地图显示和后续 UI。
- `Data`：封面、地图贴图和后续规则数据。
- `Editor`：导入后处理。
- `Tests/EditMode`：规则与应用层测试。

## 已落地的程序集

- `YC.Domain`
- `YC.Application`
- `YC.Tests.EditMode`

## 仍需补齐的架构点

- `Infrastructure` 具体程序集和存档/回放实现。
- 数据加载层，后续决定 JSON、ScriptableObject 或混合方案。
- 具体 validator/resolver 拆分规范。
- `Presentation` 到 `GameSession` 的正式绑定方式。

## 架构硬约束

- 不把规则写进按钮点击事件。
- 不让 Unity 场景对象成为规则状态来源。
- 不绕过命令校验。
- 不让表现层直接写 `GameState`。

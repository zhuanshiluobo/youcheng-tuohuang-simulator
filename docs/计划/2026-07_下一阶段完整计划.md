## 3. 规则基线与待确认项

### 3.1 已明确的通用规则

实现与审查必须满足以下规则：

- 特殊行动来自已经宣告的城市样式，属于主要行动。
- 玩家必须在对应城市样式牌上有处于可用区域的玩家影响力；位于 `0` 或“已使用”区域时不可使用。
- 同一城市样式解锁的特殊行动，每名玩家每回合最多使用一次。
- 使用特殊行动的行动轮不能再执行其他主要行动。
- 快速行动只能在主要行动前后执行，不能插入一个尚未结算完成的主要行动；牌面明确允许的额外行动窗口另行建模。
- 城市样式 I 级标记在收尾时由“已使用”复位到“未使用”；II 级标记按牌面向下移动一格。
- 多段效果按牌面从左到右、从上到下结算。非条件式效果中某一步无法执行时，仍应继续尝试后续步骤；条件式效果必须完整满足前置条件。
- 玩家影响力是有限部件；供应不足时不能继续放置。资源和费用必须使用项目统一术语及支付服务。
- 非法命令、资源不足、目标失效或联网重放冲突必须返回明确原因，并保证状态不被部分写入。

## 5. 设计计划

### 5.1 规则矩阵

为每个特殊行动记录以下字段：

- `specialActionId`、来源城市样式、等级和可用标记区域。
- 使用时机、每回合限制、总次数/递减规则和收尾复位规则。
- 费用、可替代资源策略、支付失败原因和支付发生时点。
- 目标类型、目标数量、目标合法性、无合法目标和部件不足时的处理。
- 多段效果的结算顺序、条件式/非条件式属性和允许跳过的步骤。
- 是否允许角色牌、是否创建额外主要行动、快速行动窗口如何开放。
- 是否创建待选、待选能否取消、取消前后是否已消耗费用/次数。
- 事件、路径、建设供应补牌、影响力放置等既有规则的复用入口。
- 日志字段、命令参数、快照字段、回放字段和自动跑局决策参数。

规则矩阵评审通过后再冻结 `CityStyleDatabase` 中的效果定义；牌面原文、代码常量和 UI 文案使用同一术语。

### 5.2 命令与状态设计

- 新增可序列化的 `UseSpecialActionCommand`，只携带玩家选择，不携带 Unity 对象或表现坐标。
- 新增 `SpecialActionLegalQueryService` 或等价纯领域查询，统一返回可用行动、合法目标和不可用原因。
- 新增 `SpecialActionDefinition`/效果契约，避免把五种效果全部堆入一个大型 `switch`。
- 多步效果使用显式 `PendingSpecialActionState` 或可复用待选状态，不在 UI 控制器中保存规则真相。
- 额外主要行动使用显式行动预算/行动序列状态，不通过递归调用命令处理器或临时跳过 `EndAction` 实现。
- 免费移动城市复用现有移动服务，并通过明确的费用策略或效果上下文跳过费用；影响力替换复用既有替换服务，不复制第二套规则。
- 状态中明确记录样式标记区域、剩余次数、本回合已使用动作、角色牌禁用窗口、额外行动预算和进行中的待选。
- 所有新增状态都必须进入克隆、比较、快照和联网同步路径。

### 5.3 交互设计

特殊行动交互采用统一流程：

```text
点击“特殊行动”
-> 展示已解锁行动、费用、剩余次数和禁用原因
-> 选择行动并预览完整效果顺序
-> 完成必要的资源组合、影响力、移动城市和航道目标选择
-> 最终确认
-> 提交命令或进入服务端权威待选
-> 结算并刷新行动、样式标记、资源、地图和日志
```

交互约束：

- UI 只消费合法查询结果并提交命令，不自行判断费用和目标合法性。
- Esc、右键和取消按钮语义一致；未提交前取消不消耗费用、次数或行动。
- 一旦命令成功提交，后续强制待选必须存在至少一条合法完成路径，不能因关闭弹窗卡死阶段。
- 禁用项显示可执行的原因，例如“本回合已使用”“标记位于 0”“资源不足”“当前无合法目标”“本时段不能使用角色牌”。
- 复用现有地图高亮、移动城市、航道影响力和事件选择组件；特殊行动只负责编排，不复制交互组件。

## 7. 优化计划

### 7.1 架构优化

- `MobileCityInteractionController.cs`继续遵守不超过 1000 行的现有架构约束；新增逻辑放入工作流 Presenter、Coordinator 和 Adapter。
- `ExplorationEventPresenter`当前约 1282 行。复合动力系统执行的是免费移动城市，不得错误接入探索流程或继续向该 Presenter 加入特殊行动规则；后续独立扩展探索时再拆出路径选择、支付策略和事件目标子流程。
- 把普通行动与特殊行动重复的“费用策略、目标合法性、待选恢复、效果日志”下沉到可测试的纯 C# 服务。
- 避免并列维护 `UsedSpecialActionIdsThisRound`、样式剩余次数和标记区域三个相互矛盾的真相；确定一个领域主事实源，其余由查询派生或在单一服务中同步更新。
- 新增架构测试，阻止 Presentation 直接修改 `GameState`、阻止 Domain 引用 `UnityEngine`、阻止特殊行动绕过统一命令提交。

### 7.2 性能与稳定性优化

- 城市样式和特殊行动定义作为不可变数据复用，避免每次刷新 UI 重建图案和效果描述。
- 合法目标查询按状态版本刷新，不在每帧重复遍历全地图、全部设施和全部路线。
- 地图高亮、卡牌预览和信息面板更新合并到一次结算后的视图刷新，避免重复刷新和闪烁。
- 联网快照只传规则 ID、数值和选择状态，不传图片、组件引用或冗余派生文案。
- 自动跑局输出每种特殊行动的尝试、成功和跳过原因，防止“跑到终局但从未命中特殊行动”的假覆盖。
- 对连续移动、免费移动城市和额外主要行动增加循环上限与无合法目标终止保护，防止卡死。

### 7.3 体验优化

- 行动详情先说明收益，再说明费用、限制和结算顺序。
- 所有不可用状态显示中文原因；代码 ID 只进入诊断日志。
- 保持右键撤销、Esc 关闭、地图高亮和确认按钮在建设、宣告样式、探索与特殊行动中的一致性。
- 对 16:9 基准分辨率和常用缩放比例执行布局回归，避免长中文说明遮挡确认区。
- 角色牌禁用期间同时禁用入口并显示原因，不能只在提交后返回错误。

## 8. 审查与验收计划

### 8.1 规则审查

- 逐项对照 `docs/规则/规则总结.md` 的主要行动、宣告城市样式、收尾和底层效果规则。
- 对五张特殊行动牌逐字段核对费用、目标、次数、时机、角色牌限制和图标顺序。
- 对 `docs/规则` 无法解释的图标才回看 PDF；核定后把结论补回规则矩阵。
- 复核 6 张样式与 5 个特殊行动的对应关系，避免给 `物资中继站`创建错误入口。
- 复核所有玩家可见文案和日志使用项目术语表，不混用内部枚举名。

### 8.2 代码与架构审查

- Domain 纯 C#、Presentation 无规则写入、Application 统一命令入口。
- 每个失败路径均验证状态不变；支付、次数和主要行动必须原子提交。
- 免费行动复用既有服务，不复制探索、移动或建设规则。
- 强制待选有合法完成路径，快照恢复后可继续，取消语义无状态泄漏。
- Host 是联网规则真相，Client 不能自行消耗费用、次数或行动预算。
- 克隆、序列化、日志和重放字段完整；隐藏角色牌信息不进入非所有者视图。
- 控制器体积、循环依赖、重复查询、每帧分配和临时调试入口符合现有架构约束。

### 8.3 自动化测试矩阵

通用测试：

- 未宣告样式、无可用标记、标记在 `0`/已使用区、本回合已使用、错误阶段、非当前玩家。
- 资源不足、影响力不足、无合法目标、目标在提交前失效、命令重复、Client 非权威写入。
- 成功后费用、次数、主要行动、样式标记、地图/城市状态和日志一次且仅一次变化。
- 失败后资源、次数、行动、标记、牌堆和地图完全不变。
- I 级收尾复位、II 级逐格下降、回合切换、本回合使用记录清理。
- 快速行动窗口、角色牌限制、额外主要行动预算和连续行动中断。
- 快照往返、克隆一致性、断线重同步、重放/重复命令保护。

逐效果测试：

- 军工化区域：0/1/2/3/超上限标记、合法目标不足、供应不足和部分执行。
- 动员配套体系：不能替换本方影响力、目标不存在、对手移动城市阻挡、本方供应不足、成功后原槽位置换。
- 复合动力系统：缺少 1 个源石碎片、源岩与异铁合计不足 3 个、不同组合支付、免费移动合法性、普通移动事件结算、经过航道的影响力槽位占用。
- 源石工业中枢：准确获得 2 次额外主要行动、行动间快速行动、角色牌禁用、提前无合法行动、结束行动。
- 高效移动管理体系：准确支付 3 个源石碎片、两次免费移动、第二次无目标、事件触发、影响力移除/放置、角色牌禁用。
- 物资中继站：宣告奖励不回归，不出现在特殊行动列表。

### 8.4 人工验收

- 四人热座从开局跑至终局，至少由不同玩家使用 I 级和 II 级特殊行动。
- 五种特殊行动逐一执行成功路径，并各验证一个关键失败路径。

- 执行 Localhost 构建及右侧卡区、信息面板、特殊行动弹窗和地图目标冒烟。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 牌面图标解释不完整 | 写入错误费用、目标或时序 | 先查 `docs/规则`，仍不清楚再查牌图/PDF；M1 未冻结前不编码 |
| 当前工作区改动范围大 | 新旧缺陷混合、难以回归 | M0 先全量验证，按功能组修复并保持提交边界清晰 |
| 额外主要行动破坏阶段机 | 多执行、少执行或跳过快速行动窗口 | 引入显式行动预算与状态测试，不递归调用处理器 |
| 免费移动城市或影响力替换复制规则 | 与普通行动逐步分叉 | 复用领域服务，使用费用/效果上下文表达例外 |
| 多步待选在联网中断裂 | Client 卡死或重连后无法继续 | 待选进入权威状态和快照，提供合法查询与恢复测试 |
| 三个使用状态源不一致 | UI、规则与收尾结果冲突 | 选定单一主事实源，集中更新并用不变量测试约束 |
| 自动跑局只“尝试”未“成功” | 测试看似覆盖实际未命中 | 统计尝试、成功和失败原因，验收要求成功执行 I/II 级行动 |
| 真实 Steam 环境不足 | 无法宣称公网验收 | 与本地多实例结论分开记录，保留条件性验收项 |

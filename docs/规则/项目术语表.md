# 项目术语表

本文是项目文档的术语统一依据。后续新增文档和 UI 文案应优先使用本表口径。

规则术语以 `游城拓荒/规则书/《游城拓荒：铸基者》规则说明书（新）.pdf` 为依据；项目自定义的 UI、状态和联网术语不视为规则书原文。项目统一使用“设施卡”，对应规则书中的“设施牌”；“建设”是行动名称，不是卡牌类别。

## 地图与资源

| 推荐术语 | 含义 | 备注 |
|---|---|---|
| 地块 | 地图图结构中的节点，例如 `A-01`、`B-02`。 | 地图节点统一称为地块。代码中的 `Location` 可继续保留。 |
| 资源点 | 规则书对地图上可探索地点的称呼，包含尚未放置资源点指示物的地点。 | 项目状态/UI 为区分探索进度，也用“资源点”特指已放置指示物的地块；这是项目口径，不是规则书限制。 |
| 未开放 | 地块当前不能作为探索或城市移动的目标。 | 例如红区未到开放回合。 |
| 已开放 | 地块的开放限制已解除。 | 项目三态显示中的“已开放”简称“已开放未探索”；开放不等于未探索，也不保证满足某项行动的全部目标条件。 |
| 已开放已探索 | 地块已开放且已经放置资源点指示物，成为资源点。 | 可用于采集等资源点规则。 |
| 区块 | 同色资源点与航道组成的地图区域，用于区块控制计分。 | 不等于单个地块；四人地图 8 个，三人地图 7 个。 |
| 源岩、源石、异铁 | 三种常见资源。 | “源石”不写成“源石碎片”；代码 `OriginiumShard` 保留。 |
| 至纯源石 | 区别于源石的另一种资源。 | 代码 `PureOriginium` 保留，不与源石混用。 |
| 金券 | 哥伦比亚金券的简称。 | 代码 `GoldVoucher` 保留。 |
| 航道 | 地图边或超边，连接若干地块。 | 代码中的 `Route` 对应航道。 |
| 路线 | 玩家为移动、探索或采集选择的地块与航道序列。 | 面向规则与玩家说明使用。 |
| 路径 | 代码寻路结果或算法概念。 | `MapPath`、`MapPathSearchService` 等代码名保留。 |

## 行动与阶段

| 推荐术语 | 含义 | 备注 |
|---|---|---|
| 回合 | 一局游戏中的 8 个大回合之一。 | UI 可显示为“第 N 回合”。 |
| 行动轮 | 每回合玩家行动阶段中的第 1 轮或第 2 轮。 | UI 可显示为“行动轮 M”。 |
| 城市移动 | 移动自己的移动城市棋子的主要行动。 | 区分行动“城市移动”和棋子“移动城市”。 |
| 当前行动 | 某个玩家在行动轮中的一次操作窗口。 | 包含快速行动窗口、主要行动和结束行动。 |
| 结束行动 | 玩家确认当前行动结束并提交 `EndAction`。 | UI 按钮和文档统一使用“结束行动”。 |
| 主要行动完成 | 当前玩家已成功执行至少一次主要行动，但尚未提交 `EndAction`。 | 不等于行动轮结束；如仍有额外主要行动预算，可继续主要行动，也可按规则执行快速行动。 |
| 快速行动 | 可在主要行动前后执行的行动。 | 主要行动进行中不能插入快速行动。 |

## 影响力与槽位

| 推荐术语 | 含义 | 备注 |
|---|---|---|
| 玩家标记 | 每名玩家拥有的 30 个同色标记，可用于地图、计分轨道、城市样式牌和企业板等位置。 | 开局取其中 1 个用于计分；不将所有位置的标记统称影响力。 |
| 玩家影响力 | 放在地图影响力槽位中的玩家标记。 | 仅此类标记被视为影响力；移动城市在区控中额外计入 2 点影响力，不表示增加 2 个实体标记。 |
| 剩余影响力 | 玩家供应堆中尚可部署的玩家标记数量。 | UI 保持“剩余影响力”，属于项目简称；不等于地图上的影响力数量。 |
| 地块影响力槽位 | 地块上的影响力放置位置。 | 若地块已开放已探索，通常也可称为资源点影响力槽位。 |
| 资源点影响力槽位 | 已开放已探索地块上的影响力槽位。 | 面向 UI 时可使用。 |
| 航道影响力槽位 | 航道上的影响力放置位置。 | 文档中统一使用该术语。 |

## 费用、显示与联网

| 推荐术语 | 含义 | 备注 |
|---|---|---|
| 路费接收方 | 某条航道路费支付给的玩家或供应堆。 | 代码参数 `paymentRecipients` 保留。 |
| 航道槽位显示 | 显示航道影响力槽位。 | 航道本体显示不进入当前模块范围。 |
| 移动城市 | 玩家在地图上的城市棋子。 | 不简称“城市”，除非上下文明确是 UI 对象名。 |
| 多人房间 | Steam Lobby 或本地测试协调房间中的等待与席位阶段。 | 用于开始游戏前；当前正式链路不再使用 UGS Lobby / NGO。 |
| 联网同步 | 游戏内 Host 权威状态同步。 | 不改动既有“Host 权威快照同步”口径。 |
| 稳定席位 | Host 为某个 SteamID 或本地模拟身份分配的固定 `PlayerId`。 | 不能使用 Lobby 成员枚举顺序或 Client 自报身份替代。 |
| Host 权威就绪 | 由 Host 根据 Lobby 成员、Mirror 连接和身份映射计算的开局资格。 | Client 只能读取结果，不能写自己或其他席位的就绪状态。 |
| Lobby 成员存在 | `LobbyMemberPresent`，目标身份仍占用房间稳定席位。 | Steam 模式来自 Lobby 实际成员；本地模式来自信令连接席位。 |
| 传输已连接 | `TransportConnected`，Host 观察到目标 Mirror 连接仍存活。 | 断线或进入断开队列时必须清除。 |
| 身份已验证 | `IdentityVerified`，Mirror 连接身份与稳定席位唯一匹配。 | Steam 使用远端 SteamID；本地模式使用 Host 签发的信令身份凭据。 |
| 初始状态已同步 | `GameStateSynchronized`，Client 已应用 Host 初始快照并回传一致身份确认。 | 在进入游戏场景后完成，不是等待房间开局按钮的前置条件。 |

## 设施卡与待选

本节核对依据：规则书印刷页 02（PDF 第 4 页）的“准备设施牌堆和设施供应区”、印刷页 03（PDF 第 5 页）的“设置核心指挥塔”，以及印刷页 07（PDF 第 9 页）的“建设”。

| 推荐术语 | 含义 | 备注 |
|---|---|---|
| 设施卡 | 放置在城市面板上的设施类卡牌；通常通过建设行动支付费用、放置卡牌、获得分数并结算入场效果。 | 对应规则书“设施牌”。不称“建设卡”或“建设牌”；指卡牌类别或列表标题时，原“建设卡区”改为“设施卡”。 |
| 设施卡牌堆 | 开局从 48 张设施卡中取出 4 张核心指挥塔、3 张延伸枢纽后，将其余 41 张洗混形成的牌堆。 | 对应规则书“设施牌堆”。41 张是普通牌堆的卡牌数量，不是全部设施卡的数量，不再称“正式建设牌”。 |
| 备用设施卡 | 开局单独取出的 4 张核心指挥塔和 3 张延伸枢纽。 | 不进入上述 41 张普通牌堆，但仍属于设施卡。每名玩家设置时拿取 1 张核心指挥塔放在城市面板指定位置，并非仅为备用代码定义。 |
| 设施供应区 | 从设施卡牌堆翻开、正面朝上供玩家选择建设的公开区域，开局放置 6 张设施卡。 | 卡牌被拿取或移除后，若牌堆仍有牌，立刻补充至 6 张。指公开选牌区域时使用“设施供应区”，不称“建设卡区”。 |
| 设施供应槽位 | 设施供应区中保持位置语义的单个槽位。 | 项目 UI 补充术语：建设后只补充被取走卡牌所在槽位，不整体左移其他卡牌。 |
| 城市面板 | 玩家放置设施卡的个人版面。 | “建设面板”仅在明确指建设交互 UI 时使用，不替代实体版面名称。 |
| 建设 | 支付费用、放置设施卡、结算分数和入场效果的主要行动。 | 区分行动“建设”、卡牌“设施卡”和区域“设施供应区”。 |
| 设施待选 | 设施卡入场效果要求玩家继续指定资源、地点、影响力或分支时的强制选择会话。 | 项目实现术语：使用独立待选状态和 UI，不与普通事件牌待选混用。 |
| 效果契约 | 由 `effectId`、参数、关键词和结构化规则共同定义的设施效果。 | 项目实现术语：不以中文牌面描述字符串作为运行时结算依据。 |

## 文档使用边界

- 本表补充核对规则书印刷页 01—06（配件、设置、资源、影响力与探索）及 12（区块控制）。事件卡/角色卡是项目界面简称，对应规则书事件牌/角色牌，不表示新的卡牌类别。
- 文件名、素材目录、代码标识和历史 UI 对象名可保留旧词；正文叙述使用本表术语，不据此重命名资源或改写历史实现。
- 设施卡的实体数量、卡牌定义数量和图片文件数量分开统计：48 张实体卡包含 7 张备用卡；备用卡可仅有 4 个定义/卡图（核心指挥塔 1 个、不同颜色延伸枢纽 3 个）。

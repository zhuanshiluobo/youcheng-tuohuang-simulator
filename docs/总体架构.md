## 本文件保留内容

### 架构重点

模拟器架构的核心约束：

- 规则正确。
- 流程清晰。
- 数据可配置。
- 表现层和规则层解耦。
- 所有玩家操作可记录、可回放、可测试。

### 当前工程映射

原规划中的分层已经落到 Unity 工程：

```text
Domain        -> Assets/YC/Domain
Application   -> Assets/YC/Application
Presentation  -> Assets/YC/Presentation
Infrastructure-> Assets/YC/Infrastructure
Data          -> Assets/YC/Data
Tests         -> Assets/YC/Tests/EditMode
```

当前已实现：

- `GameSession`
- `GameState`
- 命令、事件、校验结果。
- 地图定义、地图查询、路径搜索、基础费用。
- 阶段流和命令阶段策略。
- 入场前两个命令。
- 开始页和四人地图显示。

### 后续架构缺口

- `Definition Database` 尚未实现。
- `RegionControlService` 尚未实现。
- `EffectService` 尚未实现。
- `ScoringService` 尚未实现。
- 存档、回放、日志详情仍需补齐。
- UI 仍处于开始页和地图底图阶段，尚未接入 `GameSession` 操作。

## 关键约束

- 规则核心不能依赖 Unity 场景对象。
- 所有状态必须可序列化。
- 所有玩家操作必须先校验再结算。
- 地图热点坐标和地图规则节点分离。
- UI 只负责展示和提交命令，不写玩法规则。

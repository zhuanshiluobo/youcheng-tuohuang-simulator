## 本文件保留内容

### 架构重点

模拟器架构的核心约束：

- 规则正确。
- 流程清晰。
- 数据可配置。
- 表现层和规则层解耦。
- 所有玩家操作可记录、可回放、可测试。

### 当前工程映射

原规划中的分层已经落到 Unity 工程：

```text
Domain        -> Assets/YC/Domain
Application   -> Assets/YC/Application
Presentation  -> Assets/YC/Presentation
Infrastructure-> Assets/YC/Infrastructure
Data          -> Assets/YC/Data
Tests         -> Assets/YC/Tests/EditMode
```

当前已实现：

- `GameSession`
- `GameState`
- 命令、事件、校验结果。
- 地图定义、四人地图结构化数据、地图查询、路径搜索、基础费用。
- 阶段流和命令阶段策略。
- 入场前两个命令和初始资金发放。
- 部署、调度、探索、移动城市、结束行动等命令处理。
- 影响力放置、移动、移除、替换、查询和区块统计基础服务。
- 事件牌堆、资源点指示物和探索事件选择入口。
- 开始页、四人地图显示、移动城市交互、信息面板、行动面板、对局设置入口。
- Unity 官方联网栈方向的多人房间、Host 权威命令传输和状态快照同步 MVP 原型。

### 后续架构缺口

- `Definition Database` 尚未实现。
- `RegionControlService` 已有基础实现，但最终计分服务尚未完成。
- `EffectService` 尚未实现。
- `ScoringService` 尚未实现。
- 建设、特殊行动、采集、收尾和最终计分仍需补齐。
- 存档、回放、日志详情仍需补齐。
- UI 已有可交互原型，但尚未完整覆盖全部规则命令。

## 关键约束

- 规则核心不能依赖 Unity 场景对象。
- 所有状态必须可序列化。
- 所有玩家操作必须先校验再结算。
- 地图热点坐标和地图规则节点分离。
- UI 只负责展示和提交命令，不写玩法规则。

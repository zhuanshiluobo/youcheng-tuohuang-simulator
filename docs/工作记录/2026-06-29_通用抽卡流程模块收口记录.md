# 2026-06-29 通用抽卡流程模块收口记录

## 背景

探索、移动城市和入场事件都存在同一类流程：

1. 根据地块或动作决定牌池
2. 抽取事件牌
3. 执行翻牌即时副作用
4. 打开待选项或直接结算
5. 按选项发奖励并清理待选状态

在本次收口前，这几条链路各自维护抽牌、待选和结算逻辑，复用性弱，也不利于后续建设模块继续接入事件牌流程。

### 2. 扩展统一状态模型

`GameState` 新增：

- `PendingCardSessionState PendingCardSession`
- `DeckRuntimeState.CardPools`

兼容策略：

- `HasPendingChoice()` 同时检查 `PendingChoiceState` 和 `PendingCardSessionState`
- `CardFlowStateAdapter` 会同步写入旧 `PendingChoiceState`
- 现有 UI 和命令处理器无需一次性重写

### 3. 统一牌池访问

`EventDeckService` 已改为委托 `CardPoolService`：

- 三色事件牌初始化仍保留原入口
- `Draw`、`Peek`、`RemainingCount` 已改成统一牌池访问
- 后续可在 `DeckRuntimeState.CardPools` 扩展更多牌池，不再硬编码到 `EventDeckGreen/Yellow/Red`

### 4. 探索事件接入通用流程

新增：

- `ExploreEventCardScenario`

调整：

- `ExplorationService.Explore()` 支持即时结算路径
- `ExplorationService.BeginExploreEvent()` 支持统一打开待选
- `ExplorationService.ResolveExploreEvent()` 支持统一待选结算
- 翻牌副作用、事件选项校验和奖励应用分别拆到内部辅助方法

### 5. 移动城市事件接入通用流程

新增：

- `MoveCityEventCardScenario`

调整：

- `CityMovementService.MoveCity()` 支持即时结算和打开待选两条路径
- `CityMovementService.ResolveMoveCityEvent()` 改为走统一待选结算
- 把基础移动逻辑抽成 `PerformBaseMove(...)`
- 把事件选项校验与奖励应用拆成独立方法，供场景类复用

### 6. 入场事件接入通用流程

新增：

- `EntranceEventCardScenario`

调整：

- `SetupCommandHandler.TryOpenEntranceEventChoice()` 改为走 `CardFlowService.StartPendingChoice(...)`
- `SetupCommandHandler.HandleResolveEntranceEvent()` 改为走 `CardFlowService.ResolvePendingChoice(...)`
- 资源点放置与奖励发放分别交给场景类处理

## 对后续建设模块的意义

后续如果建设模块需要独立事件牌流程，不需要再复制探索或入场事件实现，只需要：

1. 实现一个新的 `IEventCardScenario`
2. 在建设命令中选择调用 `StartPendingChoice()`、`ExecuteImmediate()` 或 `ResolvePendingChoice()`
3. 用 `CardFlowArgumentUtility` 传递建设专属上下文

这意味着建设模块可以复用同一套牌池、待选状态和结算骨架。

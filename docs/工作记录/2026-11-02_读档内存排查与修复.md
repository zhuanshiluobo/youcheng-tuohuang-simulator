# 2026-11-02 读档内存排查与修复

用户反馈读档后接近 10 GB，要求检索此前修复记录、研究并尝试修复。本次修改范围为存档元数据的解析和消费者、本地已恢复结果的一次性交接，不修改场景、预制体、存档格式、领域规则、Lua 内容或规则恢复校验。

## 历史与定位

- `915d9d7f`（2026-10-23）优化 `GameStateCloneService` 和 `StateCopyMetadata`，包括复用诊断路径、标量列表批量复制，降低状态深复制的临时分配。当前代码仍有这些优化。本次定位到的是不同的解析路径。
- `a783d693`（2026-10-28）包含本地保存校验的流式投影优化，但 `MatchSaveData` 的四个便利属性仍分别通过 `ReadArchiveState()` 构建完整 JSON 树。启动预检、启动上下文、地图初始化会重复读取这些属性；存档列表也为少数展示字段构建完整树。
- [此前无夹具发布版记录](../../prompt/Lua-API/API-07无夹具发布版读档内存-20261102.md)已证明：不含测试夹具的正式读档仍出现数 GiB 增长，历史对局页工作集 7.819 GiB、私有提交量 8.587 GiB。不能把两个指标混用，也不能只凭保留堆判断存活对象。

## 修复

复用原有逐 token 校验投影，新增元数据读取入口，只物化启动字段、当前行动者和列表需要的玩家名称/颜色/资源。仍完整读取语法并检查所有对象的重复属性，包括被丢弃的历史分支；完整 `ReadArchiveState()` 和 `HostRecoveryService.RecoverJson()` 的合同保持。

启动流程与联机续局房间一次取得配置、种子、随机状态、玩家顺序，避免逐属性重复解析。存档列表使用元数据入口。不缓存完整 JSON 树，也不通过强制 GC 降低正式程序的采样结果。

第二阶段补充本地恢复结果交接：菜单预检完成的正式恢复结果只允许向同一源档、相同已安装内容及本地席位交接一次；源归档/续接文本或席位变化时重新完整恢复，头/席位摘要被破坏时仍拒绝。失败、销毁和绑定时释放交接引用。联机续局不复用菜单会话。读档异常另保留完整日志堆栈。此阶段隔离交接测试通过，但下述内容指纹阻塞使大档正常流程验证未完成，不能宣称其进一步内存收益已经实测。

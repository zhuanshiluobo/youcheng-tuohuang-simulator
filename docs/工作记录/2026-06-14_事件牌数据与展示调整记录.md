# 事件牌数据与展示调整记录

日期：2026-06-14

## 本次目标

为事件牌补充可展示的名称、描述和代表资源字段，并调整抽出事件牌后的 UI 展示，避免文本显示不全、错位和内部数据外露。

## 已完成内容

1. 事件牌数据结构调整
   - 在 `EventCardDefinition` 中新增事件牌名称、描述、代表资源类型、代表资源数量。
   - 新增 `ChoicePendingEffects`，用于暂存当前尚未接入模块的效果，例如分数、航道影响力、对手奖励等。

2. 事件牌数据库整理
   - 事件牌名称和描述统一显式存放在 `EventCardDatabase`。
   - 删除自动生成占位名称和描述的逻辑。
   - 根据《采集平台卡片文字信息》整理 22 张有效事件牌。
   - 保留现有奖励资源结算，未完成模块效果只暂存文本，不进入当前结算逻辑。

3. 抽牌与地块资源
   - 抽出事件牌后，地块资源 token 使用代表资源字段写入。
   - 代表资源用于后续采集模块识别资源点类型。

4. 事件牌展示 UI
   - 展示框只保留事件牌名称、描述和选项。
   - UI 层隐藏事件牌名中的 `（4）` / `(4)` 标记。
   - 移除编号、颜色、卡面资源、代表资源、内部 ID 等调试/元信息展示。
   - 扩大面板尺寸，增加描述区和选项按钮高度，启用换行与自动缩小，减少显示不全和错位。

5. 测试与校验
   - 更新 EditMode 测试，覆盖事件牌展示文本、代表资源落地块、未完成效果暂存。
   - 使用 Unity/Bee 响应文件配合 Roslyn 编译校验通过：
     - `YC.Domain`
     - `YC.Application`
     - `YC.Tests.EditMode`
     - `Assembly-CSharp`
   - 当前环境未找到可执行的 `Unity.exe`，因此未运行 Unity Test Runner。

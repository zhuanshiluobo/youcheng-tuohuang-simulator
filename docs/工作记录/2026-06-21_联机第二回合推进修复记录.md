# 2026-06-21 联机第二回合推进修复记录

## 背景

运行四个构建好的模拟器联机测试时，第一轮行动结束后进入第二个回合时没有正常推进；玩家 2、3、4 的界面显示正在等待 `player0` 行动。

该现象说明权威状态中的当前行动玩家没有稳定落到有效玩家 id，或者状态停留在客户端仍按行动玩家渲染的非行动阶段。由于联机同步以 Host 权威 `GameState` 快照为准，修复应优先落在权威回合推进逻辑，而不是让各客户端本地推进。

## 根因

- `RoundAdvanceService.AdvanceActionRound` 在多人局第二行动轮结束后会进入 `GamePhase.ResourceCollection`。
- 当前构建版尚未实现完整的资源收集、清理阶段命令闭环；UI 仍围绕行动轮和当前行动玩家刷新。
- 单人局已经有“第二行动轮结束后直接进入下一回合”的路径，多人局没有走该路径，导致联机快照进入一个客户端无法继续交互的中间状态。
- `MobileCityInteractionController.BeginNextRound` 是表现层本地状态修改方法，没有通过 `SubmitGameCommand` 进入 Host 权威命令流，因此不能作为联机推进方案。

## 已完成

- 修改 `RoundAdvanceService`：
  - 第二行动轮最后一名玩家结束行动后，不再区分单人/多人。
  - 统一调用 `AdvanceToNextRound`。
  - 下一回合状态为：
    - `Round += 1`
    - `Phase = GamePhase.ActionRound1`
    - `ActionRound = 1`
    - `CurrentPlayerId = GetFirstTurnPlayerId(state)`
  - 重置所有玩家的 `HasMovedCityThisRound`。
  - 行动轮切换前已有 `ResetActionFlags`，因此所有玩家的 `ActedMainActionThisTurn` 会被清空。
- 更新 `GameplayCommandHandlerTests`：
  - 四人座位顺序行动在第二行动轮结束后应进入下一回合第一行动轮。
  - 断言 `Round == 2`、`Phase == ActionRound1`、`ActionRound == 1`、`CurrentPlayerId == 1`。
  - 断言四名玩家的主行动标记均被清空。
- 更新 `MultiplayerLaunchRegressionTests`：
  - 入场后第一行动轮仍推进到第二行动轮。
  - 第二行动轮结束后直接进入下一回合第一行动轮。
  - 断言回合数推进到 `2`。

## 当前规则口径

- 在采集阶段、收尾阶段和最终计分完整闭环实现之前，多人行动轮采用与单人局一致的临时闭环：两轮主要行动结束后直接进入下一回合第一行动轮。
- 该口径避免联机构建版停在未接入 UI/命令的中间阶段，也避免各客户端本地自行调用表现层方法造成状态分叉。
- 后续实现正式采集/收尾阶段时，需要把 `RoundAdvanceService` 的第二行动轮结束路径重新接入权威阶段命令，并补齐联机快照回归测试。

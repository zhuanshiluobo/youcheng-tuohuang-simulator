# 2026-06-29 城市样式宣告闭环记录

## 背景

此前城市样式已有 `CityStyleDatabase`、`PlayerState.DeclaredCityStyleIds` 和 `FinalScoringService.CalculateCityStyleScore(...)`，最终计分可以读取已记录样式分，但缺少正式宣告流程、样式匹配、状态写回和 UI 入口。

## 本次完成

- 新增 `DeclareCityStyleService`：校验玩家、样式存在、重复宣告、影响力供应和样式匹配，成功后写入 `DeclaredCityStyleIds` 与 `DeclaredCityStyles`。
- 新增 `CityStylePatternMatcher`：基于当前 `GameState.Map.Facilities`、设施定义 `EffectType`、设施资源成本类型和城市面板槽位判断基础样式条件。
- 扩展 `CityStyleDefinition`：补充 `Description` 与 `CityStyleRequirement`，让样式条件落在 Domain 数据层。
- 扩展 `GameState`：新增 `CityStyleDeclarationState`，记录宣告使用的设施与城市面板槽位，作为设施旋转占用和特殊行动标记的后续扩展点。
- 新增 `DeclareCityStyleCommandHandler` 与 `QuickActionCommandGuard`：宣告城市样式作为快速行动处理，不消耗主要行动。
- 接入 `GameLaunchStateFactory`、`GameSessionBootstrapper` 和本地自动跑局 Session 注册，确保命令处理器与样式供应区可用。
- 新增 `CityStyleSelectionController` 和 `EventChoiceDialog.ShowCityStyleOptions(...)`，`MobileCityInteractionController` 的 `宣告样式` 按钮现在可展示可宣告样式、不可宣告原因并提交命令。
- 补充 EditMode 测试覆盖：成功宣告、条件不足拒绝、重复宣告、最终计分加入样式分、表现层选择控制器最小命令生成。

## 当前规则边界

- 样式牌数据仍是最小可验证定义，目前只有 `city_style_source_stone_industrial_hub`。
- 当前匹配使用 3x3 城市面板槽位索引、设施 `EffectType` 和资源成本类型，不包含真实牌面全部形状。
- 设施“宣告后旋转 180 度”的规则已在 Domain 状态中用使用槽位记录表达，但尚未实现 UI 视觉旋转。
- 特殊行动解锁、使用区/未使用区移动、回合收尾复位尚未接通。

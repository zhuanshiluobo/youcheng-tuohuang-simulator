# 2026-06-16 Host 权威快照同步与统一状态刷新记录

## 问题背景

此前联网命令同步仍存在“Host 与 Client 各自本地推演”的风险。`AuthoritativeCommandDispatcher.ApplyConfirmedCommand()` 在客户端收到确认命令后会再次执行 `session.Submit()`，这意味着同一条已由 Host 结算过的命令会在客户端再次走本地规则、牌堆、随机和 UI 刷新路径。

在多人模式下，这会造成几个直接问题：

- 玩家 1 的状态变化只可靠出现在 Host 本地，玩家 2/3/4 可能看不到完整变化。
- 抽牌、事件、资源指示物、待选项等依赖当前状态的结果仍可能分叉。
- UI 刷新分散在局部逻辑中，网络确认、初始同步、本地 Host 成功命令后的表现不一致。
- 地图上只有单个 `cityObject`，天然只能显示一个玩家的移动城市。
- 回合轨道自己维护 `currentIndex`，可能与 `GameState.Round / ActionRound / Phase` 脱节。

## 本轮目标

采用“最小快照同步 + 统一状态刷新”的 MVP 方案：

- Host 仍是规则权威。
- Host 成功执行命令后，把当前完整 `GameState` 放入确认消息。
- Client 只校验确认序号并替换为 Host 快照，不再本地重放命令。
- 联网模式禁止在 transport 缺失时 fallback 到单机提交。
- 表现层统一从 `GameState` 刷新城市、资源、影响力、行动面板和回合轨道。

## 已完成

### 1. 确认命令携带 Host 快照

- `ConfirmedGameCommandDto` 增加 `GameState State` 字段。
- Host 侧 `SubmitAuthorityCommand()` 成功后把当前 `session.State` 填入确认 DTO。
- `State` 默认保持 `null`，用于识别旧消息或缺失快照，避免客户端误把空状态当作权威状态。

### 2. Client 不再重放确认命令

- `AuthoritativeCommandDispatcher.ApplyConfirmedCommand()` 改为：
  - 校验确认 DTO 为空。
  - 校验初始状态已同步。
  - 校验 `Sequence` 顺序。
  - 校验 `confirmed.State` 非空。
  - 通过 `session.ReplaceState(confirmed.State)` 应用 Host 快照。
- 该路径不再调用 `session.Submit(confirmed.Command.ToCommand())`。

### 3. 联网模式禁止本地 fallback

- `MobileCityInteractionController.SubmitGameCommand()` 在 `commandTransport == null` 时增加联网模式判断。
- 如果 `GameLaunchContext.Mode != Local` 且 transport 未初始化，直接返回失败，错误原因为“联网同步未初始化”。
- 本地模式仍保留原有 `session.Submit()` 路径。

### 4. 城市显示改为多玩家字典

- `MobileCityInteractionController` 将单个 `cityObject` 改为 `Dictionary<int, GameObject> cityObjectsByPlayerId`。
- 新增 `RefreshCityViewsFromState()`，遍历 `session.State.Players`：
  - 有 `CityLocationId` 的玩家创建或移动对应城市对象。
  - 没有城市位置的玩家城市对象保持隐藏。
- 城市对象按玩家颜色做基础 tint，方便区分玩家。
- 只有本地玩家城市对象保留点击 collider，避免点击其他玩家城市触发本地行动。

### 5. 建立统一状态刷新入口

- 新增 `RefreshAllFromState()`，统一执行：
  - `RefreshCityViewsFromState()`
  - `RefreshResourceDisplay()`
  - `RefreshInfluenceDisplay()`
  - `RefreshActionPanel()`
  - `RefreshRoundTrackerFromState()`
  - `RefreshPendingChoiceOrHighlights()`
- 网络确认回调、初始网络状态同步回调、本地 Host 成功命令确认回调都进入该入口。
- `BeginNextRound()` 本地推进后也通过该入口刷新表现。

### 6. RoundTracker 改为读取 GameState

- `RoundTrackerController` 增加 `RefreshFromState(GameState state)`。
- marker 位置由 `state.Round` 和终局 phase 计算。
- 联网模式下禁用结束回合按钮，并在点击时直接返回，不再本地推进回合。
- 本地模式点击结束回合时先读取 `MobileCityInteractionController.CurrentState`，避免继续依赖独立 `currentIndex`。
- 增加终局弹窗去重，避免多次刷新叠加多个 Game Over overlay。

## 当前限制与后续工作

- 快照同步是 MVP 级别：每条确认命令发送完整 `GameState`，尚未做增量同步、checksum、断线重连、快照补发或状态版本号。
- Host 快照直接引用当前 `session.State` 后交给 `JsonUtility` 序列化广播；当前流程可满足广播时刻的最小同步需求，后续若引入异步队列应改为显式深拷贝快照。
- 多玩家城市对象已能按状态显示，但视觉表现仍是基础 tint，后续可接入正式玩家颜色/模型资源。
- RoundTracker 已禁止联网本地推进，但完整回合推进仍应最终收口到命令/阶段流转，而不是 Presentation 直接修改状态。

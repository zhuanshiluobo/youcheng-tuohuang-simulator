# 2026-06-28 UI 诊断日志流程记录

## 背景

信息面板正文文字不显示问题多次仅凭截图判断，曾把根因误判为数据、布局宽度或父级 Graphic 缺失。后续处理这类 UI 渲染问题前，需要先有可复查的结构化诊断日志。

## 本次新增

- `Assets/YC/Presentation/UiDiagnosticLog.cs`
  - 新增运行时 UI 诊断日志缓冲。
  - 支持 `Record(...)` 录入分类、消息、上下文对象、层级路径和附加数据。
  - 支持 `Export(...)` 导出 JSON 到 `Application.persistentDataPath/YCDiagnostics`。
  - 支持读取最新导出文件。

- `Assets/YC/Editor/UiDiagnosticLogMenu.cs`
  - 新增 `YC / Dev / UI Diagnostics / Export Snapshot`。
  - 新增 `YC / Dev / UI Diagnostics / Read Latest Snapshot`。
  - 新增 `YC / Dev / UI Diagnostics / Open Log Folder`。
  - 新增 `YC / Dev / UI Diagnostics / Clear Runtime Buffer`。

- `docs/指南/UI诊断日志流程.md`
  - 记录 UI 诊断日志的录入、导出、读取流程。
  - 记录信息面板当前已知诊断结论：正文 Text 的 `CanvasRenderer.cull=True`，后续应围绕裁剪与 Canvas 重建路径验证。

## 使用原则

后续修改 UI 渲染类问题前，先通过 `UiDiagnosticLog.Record(...)` 采集能够区分根因分支的字段，再导出 JSON 作为修改依据。问题解决后，临时诊断点应删除或收敛为可复用检查。

# 2026-07-02 最终计分闭环与终局断言记录

## 背景

需要把最终计分从“进入 `FinalScoring` 阶段”推进为真正可复查的结算闭环，并补齐自动跑局和 EditMode 测试里的终局断言。

实现边界继续遵守分层约束：

- Domain / Application 负责规则结算和状态写回。
- Presentation 只读取 `GameState.FinalScoring` 做展示，不直接修改规则状态。
- 本地联机自动跑局输出可用于排查的结算快照。

## 已完成

- 新增并接入 `FinalScoringService`：
  - 结算 `BaseScore + RegionScore + ResourceScore + FacilityScore + CityStyleScore`。
  - 剩余资源分按规则换算：至纯源石 `1:1`、异铁 `6:1`、源石 `8:1`、源岩 `9:1`。
  - 平局先比较剩余金券，再比较剩余至纯源石，仍相同则共同胜利。
  - 结算结果写入 `GameState.FinalScoring`，包含玩家分数明细、区块控制明细、赢家和比较说明。
- 修正 `RegionControlService`：
  - 区控现在统计地块影响力、航道影响力和移动城市 `+2`。
  - `R` 区这类只有航道的区块可以正常参与最终计分。
- `EndActionCommandHandler` 在 `Cleanup` 推进到 `FinalScoring` 后调用最终计分服务，确保终局由命令链闭环触发。
- `LocalhostAutoplayRunner` 快照新增：
  - `FinalScoringResolved`
  - `Winners`
  - `Tiebreak`
  - `FinalScores`
- 结束弹窗读取 `GameState.FinalScoring` 展示胜者、平局说明和每名玩家分数构成；表现层不直接计算或改写状态。

## 测试覆盖

- 新增 `FinalScoringServiceTests`：
  - 成功结算区控分、资源分、赢家和玩家最终分数。
  - 总分平局时按剩余金券进行第一优先级判定。

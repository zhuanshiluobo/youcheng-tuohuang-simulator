# 交互层统一路由重构与部署反馈记录

## 1. 目标与范围

本轮依据 `docs/设计/交互层重构设计方案.md` 重构对局交互层，目标是把地图点击、Esc、命令结算通知和面板展示统一收口到显式交互契约，同时补齐建设、部署、调度、移动、探索五类主要行动的独立边界。

本记录描述 2026-07-27 至 2026-07-28 已完成的交互基础设施、行动拆分、待选流程加固、部署反馈、架构门禁和自动验证。Steam 双人人工验证模块由其他工作继续推进，不属于本记录范围。

## 2. 统一交互契约与路由

新增纯 C# 交互基础设施：

- `IInteraction`
- `InteractionBase`
- `InteractionResult`
- `InteractionPresentation`
- `InteractionPriority`
- `InteractionRouter`

`InteractionRouter` 按待选结算、活跃行动、默认路由的优先级稳定分发地点、影响力槽位、移动城市和 Esc 输入；`Passthrough` 继续向下传递，`Consumed` 停止分发，拒绝结果统一显示原因。命令完成后由路由器向已注册交互广播 `NotifyCommandSettled`，销毁时统一取消并清空注册表。

`MobileCityInteractionController` 的三个地图点击入口和 Esc 已收口为路由转发。特殊行动、角色牌、设施待选和旧地图链路分别通过适配器注册，旧地图适配器只保留末级兼容行为。`InteractionMode` 从场景步骤枚举收窄为 `Hidden / ChooseAction / Busy / WaitingForNextPlayer`，具体步骤归属各交互或 Presenter。

## 3. 五类主要行动拆分

`TurnActionPresenter` 已拆出并公开五类主要行动交互：

- `BuildInteraction`
- `DeployInteraction`
- `DispatchInteraction`
- `MoveInteraction`
- `ExploreInteraction`

其中部署和调度复用 `InfluenceActionPresenter` 的流程状态，探索复用 `ExplorationEventPresenter` 的流程状态，但两个 Presenter 均不再实现或直接注册为 `IInteraction`。部署与调度使用不同交互 ID，并按互斥阶段判断活跃状态；共享 Presenter 在 `CancelAll` 中最多发生一次有效取消。

`TurnActionPresenter` 只保留动作分发、兼容入口和面板协作，当前保持 400 行。建设草稿由 `BuildInteraction` 持有，移动状态由 `MoveInteraction` 持有，城市样式选择继续由独立的 `CityStyleInteraction` 承担。

## 4. 命令与待选流程加固

新增 `CommandGateway`、`LocalPlayerResolver` 和 `ScoreTrackRefreshingCommandPort`，分别统一命令提交结果、热座本地玩家解析和提交后的分数轨刷新。

建设、设施与角色牌路径同步完成以下加固：

- 建设草稿 ViewModel 改为单一 `BuildFacilityIntent` 分发通道。
- 标准建设和设施待选在等待 Host 确认时使用命令/会话双键锁，拒绝重复提交。
- 匹配结算、新会话、无结果、拒绝或异常会正确释放在途锁。
- 角色牌设施供应选择纳入活跃判断和统一 Esc。
- 建设草稿处于活跃阶段时统一呈现 `Busy`，不会被行动选择面板覆盖。
- Host 拒绝命令后先刷新状态，再恢复提示与交互展示。

## 5. 部署感与地图视觉

本轮按原作“拿起卡牌并部署到格子”的节奏增加交互反馈：

- 行动按钮按下后在 0.08 秒内缩放到 0.92，并点亮青色描边；松开后回弹。
- 合法地图目标改为青色边框脉冲，不再使用纯色填充；alpha 在 0.4～1.0 之间按 0.6 秒循环。
- 确认地点或影响力槽位后播放 0.15 秒的 1.2→1.0 闪光和向外扩散青色圆环。
- 地图相机背景统一为 `(0.08, 0.10, 0.12, 1)` 深石板灰。

相关实现集中在 `DeploymentInteractionFeedback`、`MapInteractionClickTargets`、`MapViewPresenter`、`MapDisplayController` 与 `UiTheme`。

## 6. 行数口径与架构门禁

`MobileCityInteractionController` 的核心职责预算口径为：

- `MobileCityInteractionController.cs`：996 行
- `MobileCityInteractionController.CharacterCards.cs`：195 行
- 架构预算：`996 + 195 = 1191` 行，门禁为不超过 1200 行

`MobileCityInteractionController.RightCardSmoke.cs` 为 358 行，仅从核心职责预算中排除，仍实际参与生产编译，也继续接受危险模式扫描。因此三个 partial 的原始编译总量为 `1191 + 358 = 1549` 行；1191 不能表述为生产 partial 总行数。

架构测试同时约束：

- 五类主要行动交互均存在并继承 `InteractionBase`。
- `InfluenceActionPresenter` 与 `ExplorationEventPresenter` 不再是 `IInteraction`。
- 五类交互均在旧地图适配器之前注册。
- 主控制器不直接注册上述两个 Presenter。
- 全部控制器 partial 不直接创建命令、不直接写入 `GameState`，`RefreshAllFromState` 不启动或取消流程。

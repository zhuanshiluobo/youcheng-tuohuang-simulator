# 2026-06-13 Host 权威命令传输第一版日志

## 背景

本次工作把游戏内原本由 `MobileCityInteractionController` 直接调用 `session.Submit(...)` 的本地入口，改造成 Host 权威的 Netcode 命令传输第一版。

目标是让 Client 只提交 `GameCommandDto` 意图，Host 负责还原、校验和提交到 `GameSession.Submit(GameCommand)`，并且只把 Host 确认成功的命令按顺序广播给 Client 应用。

## 实现内容

- 新增 `ConfirmedGameCommandDto`，在 `GameCommandDto` 外携带 Host 确认后的命令序号。
- 新增 `AuthoritativeCommandDispatcher`，放在 `YC.Application`，不依赖 UnityEngine / Netcode。
- `AuthoritativeCommandDispatcher` 负责：
  - Host 接收 `GameCommandDto` 后按 `NetcodeClientId -> PlayerId` 校验提交者身份。
  - Host 将 DTO 还原为 `GameCommand`，统一提交到 `GameSession.Submit(GameCommand)`。
  - 只对 `Submit` 成功的命令分配递增序号，并触发确认广播事件。
  - Client 应用 Host 确认命令时检查序号连续，避免跳号乱序应用。
  - Client 本地越权提交入口直接拒绝，不写入本地 `GameSession`。
- 新增 `UnityNetcodeCommandTransport`，放在 `YC.Infrastructure.Multiplayer`，使用 Netcode for GameObjects named custom messages：
  - `YC.GameCommand.Submit`：Client -> Host，承载 JSON 化的 `GameCommandDto`。
  - `YC.GameCommand.Accepted`：Host -> Client，承载 JSON 化的 `ConfirmedGameCommandDto`。
- 改造 `MobileCityInteractionController`：
  - 单机模式保持直接提交。
  - Host 模式本机命令仍由 Host 直接提交，并在成功后广播给远端 Client。
  - Client 模式点击地图、移动城市、选择事件选项时只发送 DTO 给 Host，不再立即改本地 `GameState`。
  - Client 收到 Host 确认广播后，按序回放命令到本地 `GameSession.Submit`，再刷新城市、资源、影响力、事件选择 UI。

## 测试覆盖

新增 EditMode 测试 `NetworkCommandDispatcherTests`，覆盖：

- `GameCommandDto` 往返保留 `CommandId`、`Kind`、`PlayerId`、`SourceId`、`TargetId`、`OptionIds`、`Parameters`。

- Client 本地越权提交入口返回失败，不污染本地 `GameSession`。
- Client 收到跳号的确认命令时拒绝应用，避免乱序状态污染。

## 架构约束

- Domain 仍不引用 UnityEngine / Netcode。
- Application 只新增纯 C# 命令调度，不依赖 UnityEngine。
- Presentation 只提交命令和刷新显示，不直接绕过命令系统修改正式规则状态。
- 网络层不绕过 `GameSession.Submit(GameCommand)`。
- Client 不再通过本地点击直接应用权威规则命令。

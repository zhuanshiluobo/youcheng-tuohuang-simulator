# 特殊行动完整结算与样式卡拖拽交互记录

## 1. 目标与范围

本轮把六张基础城市样式牌中的五种特殊行动从占位能力推进为 Host 权威规则闭环，并将发动入口收口到公共样式卡预览中的玩家影响力标记。物资中继站继续只在每次宣告时给予 `1 源岩 + 1 源石碎片 + 1 异铁`，不生成特殊行动入口。

本记录描述 2026-07-22 已落地的领域、应用、表现层、自动跑局和自动验证结果。人工 UI、Editor Host + 两个 Development Build Client 和多个 Steam 账号的验收未执行，不属于本记录的完成结论。

## 2. 五种特殊行动结算

- 军工化区域：按该样式牌上的本方标记数量放置影响力，最多 3 个，并要求提交当前状态下尽可能多的合法目标。
- 动员配套体系：移除一个对手影响力；若同一槽位仍可放置且本方供应足够，再尽量放置本方影响力。
- 复合动力系统：支付 1 个源石碎片，并在源岩与异铁之间支付合计 3 个；免费执行一次完整城市移动，事件结算后尽量在经过航道放置影响力。
- 源石工业中枢：支付 6 金券，消耗原有主要行动预算后增加 2 点额外预算；发动后锁定本行动轮角色牌，玩家可以执行 0、1 或 2 次后续主要行动并提前结束。
- 高效移动管理体系：支付 3 个源石碎片，连续执行两次免费城市移动；每段移动均保留普通目标、阻挡、清除影响力、事件和出发地影响力规则，第二段没有合法目标时按尽量执行完成。

I 级标记发动后进入 `used`，Cleanup 时回到 `unused`。II 级标记发动后进入 `used_from_2` 或 `used_from_1`，剩余次数只在 Cleanup 从 `2→1→0`；普通后续宣告区的标记不随特殊行动生命周期移动。每种特殊行动每名玩家每回合最多使用一次，不会错误地限制其他特殊行动 ID。

## 3. 状态、预算与 Host 命令契约

领域层新增并接通：

- `SpecialActionDefinition` 与 `SpecialActionDatabase`
- `SpecialActionOptionQueryService`
- `SpecialActionService`
- `SpecialActionLifecycleService`
- `MainActionBudgetService`

`GameState` 与 `PlayerState` 保存 `PendingSpecialActionState`、剩余/已完成主要行动预算、行动轮内角色牌使用和锁定状态。多步会话记录会话 ID、玩家、行动、样式标记、当前步骤、剩余移动次数、经过航道和已确认支付，能够随 Host 确认快照进行 JSON 往返。

`UseSpecialActionCommandHandler` 处理首条 `UseSpecialAction` 和对应的 `ResolvePendingChoice`。Host 每一步重新校验阶段、当前玩家、预算、标记、费用、目标和严格匹配的 `specialActionSessionId`；非法、重复或过期命令不会部分扣费、移动标记或消费主要行动。

复合动力系统的源岩/异铁组合在首条命令中提交并原子支付，不再先由 Host 创建一个可取消的支付待选。旧 `AwaitCompositePayment` 分支只保留兼容已有状态的恢复能力。移动触发事件时，普通事件弹窗结算后携带同一特殊行动会话 ID 恢复后续航道放置或第二段移动。

主要行动不再只依赖 `ActedMainActionThisTurn` 单一布尔值。`MainActionBudgetService` 统一开始行动轮、成功消费预算、授予额外预算、提前结束和清理角色牌行动轮状态，同时维护旧字段兼容口径。

## 4. 样式卡拖拽与地图交互

特殊行动没有独立的行动面板按钮。玩家单击公共样式卡后，由 `TurnActionPresenter` 构造宣告和特殊行动所需视图，`CityStyleDeclarationPreviewDialog` 在牌面上渲染全部玩家标记；只有当前玩家、当前可用并且具有合法特殊行动的标记可拖。

拖动时显示虚影与绿色合法落区：I 级目标为 `used`，II 级依剩余次数为 `used_from_2` 或 `used_from_1`。标记未落入自身合法区域时不提交命令；无可执行目标时先显示警告确认；取消、右键、Esc、关闭预览或退出复合动力支付草稿均不会消耗资源、次数或主要行动。

复合动力系统使用 `SpecialActionChoiceDialog` 在本地收集源岩/异铁支付组合，确认后才发送首条命令。Host 接受首命令后，预览关闭，`SpecialActionInteractionUiCoordinator` 按 `PendingSpecialActionState` 恢复精简地图提示和高亮；军工化区域、动员配套体系、移动目标和航道放置直接在地图上选择，移动事件继续复用既有事件流程。源石工业中枢一次完成，不打开待处理弹窗。

已接受的强制后续流程没有取消按钮，只允许收起提示；刷新状态、晚到快照或重新构造表现层时会从当前会话步骤恢复，不重复支付或发动。

## 5. 最终审查与加固

最终代码审查和本轮界面回归复查额外发现并修复五类边界问题：

- 损坏快照中的特殊行动会话现在必须引用真实玩家、该玩家真实宣告且与行动匹配的标记，并满足当前步骤的次数、航道和支付约束；不存在玩家的“幽灵会话”会在 `GameSession` 构造或替换状态时清理，不再永久阻塞所有命令。
- `SpecialActionInteractionUiCoordinator` 只接管通过 `pending.IsValid(state)` 领域校验的会话；当合法的设施 `PendingCardSession` 正在处理设施场景时明确让出控制权。陈旧特殊行动快照不再吞掉佣兵指挥部等设施弹窗。
- 角色牌完成结算时会先移除手牌中同 ID 的陈旧镜像，再清空盖放区并加入弃牌区，保证刚发动的牌不会同时出现在手牌和弃牌区，也不会表现为“回手牌”。
- 无目标警告或复合动力支付模态打开时，左右方向键和翻页按钮不能切换背后的样式卡；支付遮罩会阻断背景射线，样式标记拖拽、板面框选和清空选择也会拒绝执行，关闭后交互恢复。
- 联机地图待选提交后以 `CommandId` 建立本地 in-flight 锁；在收到匹配的 Host 确认或拒绝前，重复点击只显示等待提示，不再重复发送同一会话命令。

对应专项回归已纳入 `SpecialAction` 测试过滤。架构门禁也维持 `MobileCityInteractionController` 生产 partial 总行数不超过 `1200`，未通过放宽阈值绕过审查。

## 6. 自动跑局扩展

`LocalhostAutoplayRunner` 现在把部署、探索、建设、发动角色牌、移动、宣告和特殊行动列为七项强制覆盖；缺少任意一项时不能返回成功。它还会为特殊行动准备正式设施条件、通过命令宣告城市样式，并实际提交一种 II 级和一种 I 级特殊行动。本次构建产物跑局中：

- P1 发动极境策略，结算后盖放牌清空并进入弃牌区，执行摘要为 `discardCount=1`。
- P3 发动源石工业中枢，标记进入 `used_from_2`，获得两点额外主要行动预算。
- P4 发动军工化区域，通过后续待处理命令完成影响力放置，标记进入 `used`。
- `DeployInfluenceSuccesses: 12`、`ExploreLocationSuccesses: 1`、`BuildFacilitySuccesses: 9`、`CharacterCardUseSuccesses: 1`、`MoveCitySuccesses: 1`、`DeclareCityStyleSuccesses: 2`。
- `SpecialActionAttempts: 2`、`SpecialActionSuccesses: 2`、`PendingSpecialActionStep: None`。
- 跑局继续完成采集、Cleanup 和最终计分，最终为 `Phase: FinalScoring`、`FinalScoringResolved: True`。

快照同时输出宣告成功数、特殊行动步骤、执行摘要、标记状态、主要行动预算和最终分数，避免测试只修改状态或停在未完成会话。

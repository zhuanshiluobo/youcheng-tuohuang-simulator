# 2026-06-24 资源采集阶段闭环与提示框修复记录

## 背景

此前本地联机自动跑局在第 2 行动轮结束后会直接推进到后续阶段，采集阶段缺少命令闭环和可用 UI。后续手动验证中又发现：

- 单人模式进入采集阶段时提示会被覆盖成“采集已提交”。
- 支付一条航道路费后，只按默认最短路显示少量资源点，不能沿自有影响力航道继续免费扩展可采集点。
- 航道路费缺少二级确认菜单，无法明确选择支付给银行或多个可接收玩家之一。
- 采集结算提示文本过长时会被固定高度提示框裁切。

## 主要改动

### Domain / Application

- 新增 `ResourceCollectionService` 和 `ResourceCollectionResult`，负责采集目标校验、路费计划、资源奖励和玩家采集状态写入。
- 新增 `CollectResourceCommandHandler`，解析采集目标、显式航道网络和路费接收方参数，执行成功后在全部玩家采集完成时推进到 `Cleanup`。
- `CollectResourceCommandHandler` 参数：
  - `locationIds`：本次采集的资源点列表。
  - `routeIds`：本次采集使用的唯一航道列表。
  - `paymentRecipients`：`routeId=playerId` 形式的路费接收方映射；未指定接收方的应付航道支付给银行。
- `ResourceCollectionService` 支持显式 `routeIds`，并按航道覆盖资源点做可达性 BFS，避免重叠航道场景下 `MapQueryService.FindRoute()` 取第一条匹配航道造成误判。
- 采集路费按唯一航道计费，自有影响力航道免付，对手影响力航道可指定接收方；玩家只能使用采集阶段开始时已有的金券支付路费。

### 阶段推进

- `RoundAdvanceService` 在第 2 行动轮结束后进入 `ResourceCollection`。
- 全部玩家 `HasCollectedResourcesThisRound` 为真后进入 `Cleanup`。
- `Cleanup` 结束后进入下一回合第 1 行动轮；达到最大回合后进入 `FinalScoring`。
- 本地热座模式下，采集阶段会自动切换到下一个未提交采集的玩家。

### Presentation

- `MobileCityInteractionController` 增加 `ResolvingResourceCollection` 模式。
- 进入采集阶段后，UI 计算本地玩家有采集权的资源点，并从移动城市出发，沿“已支付航道 + 自己影响力航道”构造联通网络。
- 点击高亮航道会弹出采集路费二级菜单：
  - 无对手影响力时显示支付给银行的确认按钮。
  - 多个对手玩家可接收时显示分别支付给各玩家的按钮。
  - 卡片右上角 `X` 关闭按钮用于取消本次支付。
- 支付后会重新计算联通网络并高亮所有当前可采集资源点；点击高亮资源点可从本次采集列表中移除或重新加入。
- 采集提交成功后显示本次采集地点和资源总收益。
- `PromptPresenter` 改为按提示文本 preferred height 自适应面板高度，避免长结算提示被裁切；提示停留时间为 3 秒。

### 自动跑局

- `LocalhostAutoplayRunner` 注册 `CollectResourceCommandHandler`。
- 自动跑局进入 `ResourceCollection` 后会提交采集命令，并在 `Cleanup` 提交结束命令继续推进。
- 自动跑局测试断言：
  - 最终进入 `FinalScoring`。
  - `CollectedPlayers: 4/4`。
  - 日志包含资源采集事件。
  - 最终至少有玩家获得非金券采集资源。

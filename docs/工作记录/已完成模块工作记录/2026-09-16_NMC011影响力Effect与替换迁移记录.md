# NMC-011 影响力 Effect 与替换迁移记录

日期：2026-09-16

任务来源：`prompt/NMC-011-影响力Effect与替换迁移.md`

## 完成范围

已将影响力放置、移除、移动、替换收敛为四类可注册、可序列化、可恢复的 Effect：

| Effect | 类型 | 领域原子 | 成功结果 | 成功事件 |
| --- | --- | --- | --- | --- |
| `effect.influence.place` | Atomic | `InfluenceService.Place` | `outcome=placed`、`influenceId`、`slotId`、`playerId` | `InfluencePlaced` |
| `effect.influence.remove` | Atomic | `InfluenceService.Remove` | `outcome=removed`、`influenceId`、`fromSlotId` | `InfluenceRemoved` |
| `effect.influence.move` | IntrinsicFlow | `InfluenceService.Move/MoveAtomically` | `outcome=moved`、逐项移动前后槽位 | `InfluenceMoved` |
| `effect.influence.replace` | IntrinsicFlow | 移除子 Effect + 放置子 Effect | `outcome=replaced` 或 `outcome=removed_only` | 成功时 `InfluenceReplaced` |

参数只使用稳定玩家、位置、影响力实例、来源和 Effect 引用，以及归一化字符串/整数/对象/数组；运行时对象只在领域执行器内解析。统一携带 `ownerSubject`、`influenceSource`、`causeKind` 和父/替换 Effect 关联。

## 替换时序与结果

```text
ReplaceInfluence
  -> 校验目标仍存在
  -> RemoveInfluence 子 Effect
  -> 提交移除后发出 InfluenceRemoved，并等待该事件响应窗口
  -> 基于最新状态重新校验 PlaceInfluence
  -> 成功：提交放置后发出 InfluencePlaced，并等待响应窗口
  -> 成功：发出 InfluenceReplaced，并等待响应窗口，外层完成
  -> 失败：外层 Completed(removed_only)，不回滚，不发出 Placed/Replaced
```

移除前校验失败时外层为 `Failed`，状态保持不变且没有成功事件。替换结果的稳定字段包括 `removedInfluenceRef`、`slot`、`removed`、`placed` 和 `placeFailureReason`。

四类事件均在对应状态提交之后产生：

- `InfluencePlaced`：`placeEffectId`、`influenceRefAfterPlacement`、`toSlot`、`source`、`ownerSubject`、`executingPlayerId`、`causeKind`。
- `InfluenceRemoved`：`removeEffectId`、`influenceRefBeforeRemoval`、`fromSlot`、`destination`、`reasonId`、`executingPlayerId`、`causeKind`。
- `InfluenceMoved`：只携带逐项 `fromSlotId`、`slotId`、`influenceId`，不展开为移除/放置事件。
- `InfluenceReplaced`：`replaceEffectId`、`removeEffectId`、`placeEffectId`、移除/放置影响力引用和 `slot`。

## Service 复用与生产迁移

- `InfluenceIdentity` 为旧快照提供确定性的遗留 ID 投影，并在成功提交边界补齐实例 ID、所有者和来源；失败预校验不写状态。
- `InfluenceService`、`InfluenceRemovalService`、`InfluenceMoveRule` 和查询服务继续作为最低层合法性与原子状态修改器。
- `DeployInfluenceCommandHandler`、`DispatchInfluenceCommandHandler` 使用共享 `EffectRegistry` 进入 Effect executor，并移除旧的重复领域事件返回。
- `FacilityInfluenceEffectService.ReplaceOnce` 使用 `ReplaceInfluence`，保留移除成功、重新放置失败不回滚的既定语义。
- `MoonSharpLuaRuntimeHost` 与 `LuaEffectSpecCompiler` 提供四个只读构造器，执行严格字段白名单、稳定引用和 `causeKind` 校验。
- `GameStateView`、角色卡投影和克隆链路保留影响力实例 ID、owner/source，支持持久化与恢复。

尚未在本任务迁移的直接影响力调用方已登记后续边界：事件牌/探索使用 `ExplorationService`（NMC-012）、城市移动使用 `CityMovementService`/`MoveCityCommandHandler`（NMC-013）、设施及特殊行动剩余路径使用 `SpecialActionService`/`ResolveFacilityEffectCommandHandler`（NMC-014）。本轮不扩大到这些内容的全量迁移。

## 完成结论

特殊行动的正式入口已由 `SpecialActionService + PendingSpecialAction` 切换为共享 `EffectTreeExecutor`。入口 Effect 负责原子前置校验、支付子 Effect、候选集解析、标记占用和 `CityStyleSpecialActionActivated`；城市样式 Lua handler 只返回行为族 Effect，答案通过通用 `AnswerInteraction` 回到 Effect 树。回合清理使用通用 `OperatePlayerMarker` Effect，避免在回合主链中直接调用旧特殊行动清理服务。

旧 `PendingSpecialActionState`、`SpecialActionPendingSteps`、`SpecialActionService` 和旧 UI/测试兼容构造器本轮没有物理删除：`ResolvePendingChoice` 仍被设施/探索/角色牌存量流程使用，旧特殊行动测试仍直接验证旧 DTO。生产启动器和 Localhost 已不再注入旧服务；待这些存量调用迁移后再删除，避免误删跨模块状态或批量删除文件。

## Effect/Event 组合与数据合同

- 入口参数只包含 `specialActionId`、`declarationMarkerId`、可变支付数量和命令 ID；内容 ID 不决定 C# 分支，C# 只按 `SpecialActionEffectKind` 行为族构造 hard constraint 候选和通用支付。
- 候选集使用 NMC-007 `CandidateSetDraft/CandidateSetResolver`，保存 `CandidateSetId`、版本、候选池、策略 patch、最终候选和 state revision。`AnswerInteraction` 只接受稳定候选 ID，并由 `InteractionRequest` 再次检查 revision、候选集和下游 Effect 的当前合法性。
- `CityStyleLuaCatalog` 以 `DefinitionVersion=1.0.0` 注册五条 targeted primary handler 和一条 cleanup observer；每条内容带 `contentId/handlerId/contentHash/contentInstanceId`，恢复时由 Effect runtime 校验绑定。
- `CityStyleSpecialActionActivated` 的公开 payload 包含玩家、marker、候选集、行为族和行动参数；Lua 不接触 `GameState`、领域服务或可写对象。
- 支付、主行动预算、角色牌锁定、移动、影响力和 marker 写回都发生在 Effect 执行副本的提交边界；失败由父 Effect 保留 `FailureReason`，不会留下半扣费的命令事务。

## 清理与恢复证据

- 新增 `NMC013CityStyleSpecialActionEffectEditModeTests`，覆盖 Lua catalog 六个订阅、Lua 候选交互合同、通用额外行动/角色锁定和 cleanup Effect 序列化恢复/幂等。
- 入口失败点：阶段、当前玩家、已有交互、主要行动预算、marker 权限、角色锁定、资源和可变支付金额均在创建支付/事件子树前校验；失败不写 marker、使用集合或资源。
- 恢复点：入口的 `FlowStage=activated`、候选解析记录、Event dispatch receipt、Interaction revision、子 Effect 列表和完成 Event 均由 `EffectRuntime` 持久化；重启后不会再次支付或再次发布激活事件。
- 清理点：`RoundExecutionService` 使用 `effect.player.marker.operate` 执行每位玩家的回合清理；同一节点重复运行时直接返回已完成结果，marker 与使用集合不会二次漂移。

## 未决规则

1. 城市样式宣告本身仍由 `DeclareCityStyleService` 完成；本轮迁移的是特殊行动触发、效果和清理 Event 链。若要把宣告奖励也移入 Lua，应新增 `CityStyleDeclared` owning Effect，并先拆出匹配/状态提交与奖励 Effect，避免奖励重复发放。
2. 复合动力移动的“路线影响力”已接入通用航道槽位交互，但当前 Lua 只返回行为族；后续若规则要求按路线类型区分候选，应增加候选上下文字段，不在 C# 增加内容 ID 分支。
3. 旧特殊行动兼容代码必须在旧 UI/测试全部改为 `InteractionRequest + AnswerInteraction` 后逐文件删除；本轮没有批量删除目录或文件。

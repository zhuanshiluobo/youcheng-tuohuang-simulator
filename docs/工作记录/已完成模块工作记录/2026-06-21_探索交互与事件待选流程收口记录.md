# 2026-06-21 探索交互与事件待选流程收口记录

## 背景

`docs/项目总览.md` 和 `docs/工作总结.md` 将“完善探索交互”列为下一步第一优先级，具体包括事件选项选择 UI、多个对手影响力产生路费时的接收方选择、影响力放置类事件效果 resolver，以及 `PendingChoice` 流程。

本次延续既有边界：表现层只负责展示、选择和提交命令；规则校验、费用支付、资源/分数/影响力结算仍由 Domain/Application 层完成。

## 已完成

- `GameSession.Submit()` 增加统一 `PendingChoice` 拦截：
  - 存在待选择项时，非选择解析类命令会在进入 handler 前被拒绝。
  - `ResolvePendingChoice` 可继续尝试后续 handler，避免移动城市事件和探索事件都接入同一命令后互相抢处理权。
- `MoveCityCommandHandler` 支持用 `ResolvePendingChoice` 解析移动城市揭示事件：
  - 保留旧的 `MoveCity + option` 兼容路径。
  - 新路径和探索事件一样通过待选项解析命令完成奖励与结构化效果结算。
- `ExplorationService.BeginExploreEvent()` 调整校验边界：
  - 开启待选项时只校验基础探索、路线、路费、资源点、探索主影响力槽位。
  - 不再提前校验尚未选择的事件选项影响力目标。
- `MobileCityInteractionController` 补齐事件影响力目标选择流程：
  - 玩家选择含 `PlaceInfluence` 结构化效果的事件选项后，UI 进入事件影响力目标选择模式。
  - UI 按 `EventEffectTargetScope` 高亮可选地块/航道槽位，并排除已占用槽位和探索主影响力保留槽位。
  - 用户选择槽位后，UI 把目标槽位写入命令参数，再提交 `ResolvePendingChoice` 或探索命令。
  - 如果当前选项没有可用槽位，UI 回到事件选项弹窗，允许玩家改选其他选项。
- 路费接收方选择路径补测试：
  - 同一航道存在多个对手影响力拥有者时，可通过 `PaymentRecipientsParameter` 指定实际接收方。
  - 非法接收方仍由 `ExplorationService` 拒绝。

## 测试覆盖

- `GameSessionTests`
  - `PendingChoice` 存在时阻止非解析命令。
  - `ResolvePendingChoice` 遇到不匹配 handler 时继续尝试后续 handler。
- `ExploreLocationCommandHandlerTests`
  - 探索无事件选项时，首个选项需要影响力目标也能打开 `PendingChoice`。
  - 多个对手影响力接收方时，路费支付给命令指定玩家。
  - 影响力放置类事件效果成功放置和槽位占用失败。
- `MoveCityCommandHandlerTests`
  - 移动城市事件可用 `ResolvePendingChoice` 解析。
  - 移动城市事件的影响力放置类效果可通过选择解析命令提交目标槽位。
  - 缺少目标槽位时失败并保留 `PendingChoice`。

## 仍未完成的边界

- 事件选择、路费选择、事件影响力目标选择仍在 `MobileCityInteractionController` 内，应继续拆成独立表现层控制器。
- 当前事件 resolver 覆盖基础资源、分数、对手资源和放置影响力；尚未覆盖更复杂的多段事件链、可选二次支付、多目标排序和跨阶段效果。
- 入场事件仍使用专用 `ResolveEntranceEvent`，后续可评估是否统一到 `ResolvePendingChoice`。
- 采集阶段共享航道路费、建设、收尾和最终计分仍未接入完整闭环。

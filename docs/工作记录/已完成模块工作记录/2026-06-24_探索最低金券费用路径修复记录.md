# 2026-06-24 探索最低金券费用路径修复记录

## 背景

用户反馈探索 `F-03` 时界面预计花费 `6` 金券，但实际存在只需要 `2` 金券的路线：

`A-02 -> B-03 -> E-01 -> F-02 -> F-01 -> F-03`

该路径在玩家已控制 `A2`、`R7`、`E1` 后，只需要为 `F` 航道支付一次路费。旧逻辑会优先使用步数最短路径，并且按路线段逐段计算路费，导致没有保证每次探索都使用最低金券花费。

## 根因

- `ExplorationService.FindDefaultPathChoices()` 先找步数最短路径，再只在同步数路径里比较付费次数；稍长但更便宜的路径不会参与选择。
- 探索付款计划按 `RouteId` 去重，连续经过同一航道分组的多段路线仍可能重复计费。
- 表现层预计费用、路线标签和路费接收方选择也按路线段计算，可能与“同一航道只付一次”的实际规则不一致。

## 已完成

- 将默认探索路径选择改为按实际支付金券最小化：
  - 优先比较付费航道数。
  - 再比较需要支付给对手的航道数。
  - 最后用步数作为平局项。
- 新增探索用的路费分组键：
  - 对 `A` 至 `G` 这类有地块归属的航道区域，同一区域内多段路线只产生一次路费。
  - `R` 跨区连接线没有地块归属，仍按独立 `RouteId` 计费，避免 `R4/R5/R7` 被误合并。
- `TryBuildPaymentPlan()` 按路费分组去重：
  - 玩家自己在同一航道分组已有影响力时免付。
  - 同一航道分组已经产生过付款时，不再为后续同组路线段重复付款。
  - 对手影响力接收方仍沿用现有指定/默认选择规则。
- 同步表现层：
  - 探索二次确认提示的预计金券使用同一套分组去重。
  - 多路线选择标签中的“路费”按分组展示。
  - 路费接收方选择器新增 `BuildForPathWithPaymentKeys()`，避免同一航道分组重复弹出付款选择。
- 保留旧 `BuildForPath()` 方法名，避免既有反射测试因重载歧义失败。

## 回归测试

## 后续边界

- 本次修复只改变探索路径默认选择和探索路费分组，未改变资源采集阶段的路费网络逻辑。
- 如果后续规则明确 `R` 跨区连接线也存在可合并计费的分组，需要在地图数据中为这些连接线增加明确的计费分组字段，而不是复用当前 `RegionId = "R"`。
- 若后续 UI 显示需要标出“具体支付的是哪个航道分组”，可以在 `ExplorePathChoice` 标签中增加路费分组名，但命令参数仍应传实际 `RouteId`，保持现有校验入口稳定。

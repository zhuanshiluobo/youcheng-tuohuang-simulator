# 2026-06-21 移动城市即时付费事件测试修复记录

## 背景

全量 EditMode 中唯一失败用例为：

```text
YC.Tests.EditMode.MoveCityCommandHandlerTests.MoveCity_WithImmediatePaidPlaceInfluenceEvent_WhenCombinedCostInsufficient_FailsBeforeMoving
```

失败表现：

- 期望错误码：`InsufficientResource`
- 实际错误码：`InvalidTarget`
- 位置：`Assets/YC/Tests/EditMode/MoveCityCommandHandlerTests.cs:231`

该用例目标语义是：当玩家无法同时支付城市移动基础费用和即时付费放置影响力事件费用时，应在移动前失败，并且不移动城市、不扣费、不抽牌、不放置资源点或影响力。

## 排查结论

结论：这是测试场景设置错误，不是规则实现错误，也不是当前实现的校验顺序错误。

排查到的关键点：

- `MoveCityCommandHandler` 将移动命令委托给 `CityMovementService.MoveCity`，移动前会先调用 `CanMoveCity`。
- `CityMovementService.CanMoveCity` 会先校验基础移动费用，再通过 `ValidateUnrevealedTargetEvent` 预校验未翻开目标资源点的事件牌。
- 当命令携带即时事件选项时，`ValidateUnrevealedTargetEvent` 会把城市移动基础费用作为 `priorCost` 传入 `EventEffectResolver.Validate`。
- `EventEffectResolver.Validate` 会把事件付费影响力费用与 `priorCost` 合并，并在实际移动、抽牌、放置资源点前用 `player.Resources.CanPay(totalCost)` 检查组合费用。

因此生产规则已经具备“组合成本不足时移动前失败”的语义。

失败的真实原因是测试使用了不匹配的地图位置和牌堆：

- 原测试目标为 `B-02`。
- `StaticMapDefinitions.GetEventColor("B-02")` 因 `B-02` 属于四人地图初始点，返回 `EventColor.Green`。
- 原测试却向 `state.Decks.EventDeckYellow` 加入 `event_yellow_04`。
- 结果是移动前事件预校验先检查到对应绿牌堆为空，返回 `InvalidTarget`，并未进入 `event_yellow_04` 的即时付费影响力组合费用校验。

## 修改内容

修改文件：

- `Assets/YC/Tests/EditMode/MoveCityCommandHandlerTests.cs`

调整用例 `MoveCity_WithImmediatePaidPlaceInfluenceEvent_WhenCombinedCostInsufficient_FailsBeforeMoving`：

- 将玩家城市起点从 `B-01` 改为 `B-02`。
- 将移动目标从 `B-02` 改为相邻黄区 `B-03`。
- 保持事件牌为 `event_yellow_04`，使测试真实命中黄牌即时付费放置影响力效果。
- 将事件影响力槽位从 `B2:0` 改为覆盖目标移动相邻线路的 `C2:0`。
- 更新无副作用断言：
  - 城市仍停在 `B-02`。
  - 源石碎片和金券不变。
  - 黄牌堆仍保留 1 张牌。
  - `B-03` 未放置资源点。
  - 地图没有新增影响力。

# 2026-06-24 字体刷新与房间码剪贴板记录

## 背景

- 模拟器偶发在长时间挂机或恢复焦点后所有 UGUI 文本消失，只剩系统提示框或非 UGUI 元素可见。
- 开始菜单联机流程中，创建房间后房主需要手动复制房间号，加入房间时也需要手动输入房间号，操作不够顺手。
- 既有 EditMode 验证主要覆盖规则、命令、地图、联机同步和自动跑局；对新增的开始菜单剪贴板交互没有专门断言。

## 排查结论

- 项目运行时 UI 主要使用 UGUI `Text`。
- 运行时文本多数通过 `FontUtility.GetCjkFont()` 或直接 `Font.CreateDynamicFontFromOSFont(...)` 创建动态系统字体。
- 项目和构建包中没有随包 `.ttf` / `.otf` 字体资源，因此长时间运行、切后台、显卡上下文恢复或动态字体纹理重建后，存在所有引用同类动态字体的文本一起失效的风险。
- 未发现 `Resources.UnloadUnusedAssets`、`UnloadAsset`、全局清字体材质、全局把文字 alpha 设为 0 或批量隐藏文本的代码。

## 本次改动

### 字体稳定性

- `Assets/YC/Presentation/FontUtility.cs`
  - 将动态字体创建收敛为统一入口，按字号缓存 CJK / Latin 动态字体对象。
  - 记录由 `FontUtility` 管理的字体家族，便于后续刷新场景内对应 `Text`。
  - 增加运行时字体刷新驱动：
    - 监听 `Font.textureRebuilt`。
    - 应用恢复焦点或从暂停恢复时重建托管字体。
    - 定期刷新托管 `Text`，调用 `FontTextureChanged()`、`SetAllDirty()` 和 `Canvas.ForceUpdateCanvases()`。
  - 增加刷新重入保护，避免字体纹理重建事件递归触发刷新。

- `Assets/YC/Presentation/StartMenuController.cs`
  - 将开始菜单中绕过 `FontUtility` 的动态字体创建改为 `FontUtility.GetCjkFont(...)`。

- `Assets/YC/Presentation/RoundTrackerController.cs`
  - 将回合轨中直接创建动态 OS 字体的代码改为 `FontUtility.GetCjkFont(...)`。

### 房间码复制与粘贴

- `Assets/YC/Presentation/StartMenuController.cs`
  - 创建房间成功后，在房间号右侧新增“复制”按钮。
  - 点击“复制”时，将 `room.RoomId` 写入 `GUIUtility.systemCopyBuffer`，并显示“房间号已复制。”。
  - 加入房间面板的房间号输入框右侧新增“粘贴”按钮。
  - 点击“粘贴”时，从 `GUIUtility.systemCopyBuffer` 读取内容，`Trim()` 后填入 `joinRoomInput`，并显示“已粘贴房间号。”。
  - 调整房间号文本和加入房间输入框宽度，给右侧按钮留出空间，避免文字和按钮重叠。

### 验证标准补充

- `Assets/YC/Tests/EditMode/StartMenuClipboardTests.cs`
  - 新增 `CopyRoomCodeToClipboard_WritesRoomId`，验证复制方法会把房间号写入系统剪贴板。
  - 新增 `PasteRoomCodeFromClipboard_FillsJoinRoomInput`，验证粘贴方法会读取剪贴板、去除首尾空白并填入加入房间输入框。
  - 测试通过反射创建 `StartMenuController`，保持与当前 `YC.Tests.EditMode` 程序集边界兼容。

## 后续建议

- 当前修复降低动态系统字体失效风险，但根因仍依赖系统字体和 Unity 动态字体纹理。长期方案建议引入可再分发的随包 CJK 字体资源，并让 `FontUtility` 优先加载项目内字体。
- 可继续补 PlayMode 或运行时 UI 验证，覆盖开始菜单按钮布局、点击路径和恢复焦点后的字体刷新效果。

# NMC-009：联机可见性与恢复实现记录

> 文档性质：2026-09-16 的任务交付快照。本文记录本次 NMC-009 的实现范围和验证证据；当前项目状态仍以项目总览和发布检查清单为准。

## 1. 交付结论

NMC-009 已完成以下闭环：

- Host 是唯一规则权威；客户端网络入口只接收按连接玩家身份投影的 `GameStateView`。
- 私有牌、隐藏 Effect/Event/Interaction、候选集、私有日志和命令参数不会通过序列化字段或稳定 ID 侧漏。
- Host 使用独立的 `snapshot + append journal + StateAfter checkpoint` 恢复；任何不连续、冲突、未知处理器、内容哈希不一致或结构引用损坏都 fail-stop 到 `paused_fault`。
- 已写入的 dispatch receipt 和已回答 interaction 保持幂等状态，恢复不会重新执行已确认的 handler 或重复消费答案。

## 3. 网络 DTO 与调用关系

新增网络 DTO：

- `InitialGameStateViewDto`：包含协议版本、下一确认序号和单一 viewer 的 `GameStateView`。
- `ConfirmedGameStateViewDto`：包含确认序号、仅命令拥有者/Host 可见的命令确认信息和单一 viewer 的 `GameStateView`。

`MirrorCommandTransport` 的初始同步和确认广播现在按每条连接的绑定玩家分别投影；不再先序列化完整 `GameState` 再由客户端隐藏。客户端 `GameSession.ReplaceView` 将 view 适配为旧 Presenter 可消费的公开状态，并明确丢弃 `EffectRuntime`、receipt、隐藏候选和他人私有牌正文。

`InitialGameStateDto`、`ConfirmedGameCommandDto.State`、`AuthoritativeCommandDispatcher` 的完整状态同步方法仍保留为单机/旧 EditMode 测试兼容层，但已不被 Mirror 网络路径调用。Host journal/snapshot DTO 与网络 view DTO 也保持独立。

## 4. Host 恢复算法与 checkpoint

`HostRecoveryService` 的流程：

1. 校验 snapshot schema、`StateRevision`、最后 commit 序号、`NextCommitSequence`、active main node 和未解决 blocker 集合。
2. 校验 journal 从 snapshot 之后连续递增；重复/倒退序号、缺段、同 revision 不同 commit、checkpoint 缺失都会拒绝恢复。
3. 对每个 journal entry 校验内容哈希、状态 revision、commit/entity 对应关系，以及 `StateAfter` 的 Effect/continuation/handler/content version/hash。
4. 对 `DispatchReceipt` 校验 receipt ID、事件 ID、订阅 ID、handler ID 的身份一致性；恢复选择最后一个已提交的 `StateAfter`，不重新广播事件或调用 handler。
5. 校验 blocker 的 owner/target/interaction 引用、Effect 子节点和 active node；任何失败都返回可诊断的故障码并把 Host 状态置为 `paused_fault`。

现有 Effect 内核继续使用 dispatch receipt 做重复分发短路；interaction 依靠稳定请求 ID、目标玩家和 `StateRevision` 校验，已回答请求不会再次消费。NMC-004/NMC-008 的恢复/receipt 场景与本次 Host archive checkpoint 场景共同覆盖中断提交点。

## 5. 移除的泄漏与双执行入口

- 移除 Mirror 初始同步对完整 `InitialGameStateDto.State` 的序列化。
- 移除 Mirror 确认广播对完整 `ConfirmedGameCommandDto.State` 的序列化，改为逐连接 view。
- 隐藏 Interaction 不再返回稳定交互 ID、类型、候选数量、候选 ID、提示参数或答案；非目标只收到等待玩家 ID。
- 隐藏 Event/日志不再通过事件类型、事件 ID、payload、错误信息或稳定内容 ID 下发。
- `EffectCompleted` 与 `InteractionAnswered` 事件继承节点/请求可见性，不再默认向所有观察者公开。
- 非命令玩家不再收到确认命令的 kind、command ID、OptionIds 或参数正文，避免通过确认消息反推私有交互。
- 客户端确认路径不执行规则 handler，也不持有 `EffectRuntimeState`；规则推进仍只发生在 Host。

## 6. 兼容层与边界

- `GameSession.ReplaceState` 和完整状态同步 DTO 仅用于既有单机/内存调用方和历史测试，不属于在线 Mirror wire path。
- `GameStateViewProjector.ToClientState` 是受限适配器，不是完整状态反序列化器；它只恢复公开状态和当前玩家自己的私有字段。
- 本次未迁移具体卡牌内容，也未实现客户端预测、离线客户端权威或 `paused_fault` 自动修复。

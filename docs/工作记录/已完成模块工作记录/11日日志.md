### 多人入场命令流与 TCP 房间入口

- 阅读并参考：
  - `docs/工作记录/已完成模块工作记录/11日日志.md`
  - `docs/项目总览.md`
  - `docs/模块文档/多人房间与联机入口方案.md`
  - `Assets/YC/Application/Setup/SetupCommandHandler.cs`
  - `Assets/YC/Tests/EditMode/SetupCommandHandlerTests.cs`
- 入场命令流补齐：
  - `SetupCommandHandler` 支持 `ResolveEntranceEvent`。
  - 初始入场必须按 `StartPlayerId` 起始的玩家顺序执行，非当前玩家提交 `ChooseInitialLocation` 会返回 `NotCurrentPlayer`。
  - 入场事件抽牌、资源指示物放置、待选择项开启、事件奖励结算全部收口到 Application 命令处理器。
  - `PendingChoiceState` 增加 `CardId`、`TargetId`，用于记录待处理入场事件来源。
  - `MobileCityInteractionController` 的入场事件 UI 改为读取 `PendingChoice` 并提交 `ResolveEntranceEvent`，不再直接抽牌、放资源指示物或改玩家资源。
  - 新增 `GameCommandDto` 和 `GameCommandParameterDto`，避免后续网络/回放直接序列化 `Dictionary<string,string>`。
- 多人入口与房间：
  - 新增 `PlayerSeat`、`LaunchMode` 和 `GameLaunchContext`，跨场景传递启动模式、本地玩家 id、房间号和玩家席位。
  - `MobileCityInteractionController.BuildSession()` 改为从 `GameLaunchContext.Players` 创建 `GameState.Players`，并使用运行时 `localPlayerId`。
  - `StartMenuController` 增加“单机开始 / 创建房间 / 加入房间”入口。
  - 新增 `IRoomService`、`LocalRoomService` 作为房间接口和本地实现入口。
  - 新增 `NetworkRoomService`，实现直接 TCP 房间：
    - Host 创建房间时启动 `TcpListener`，房间号格式为 `ip:port`。
    - Client 在加入菜单输入房间号，通过 `TcpClient` 连接。
    - 协议包含 `JOIN`、`WELCOME`、`ROOM`、`START`、`ERROR`、`DISBAND`。
    - Host 成功分配席位后会刷新自己窗口并广播房间状态。
    - 加入连接改为后台线程，并使用 5 秒连接超时，避免 Unity 主线程未响应。
    - Client 加入后没有修改人数和开始按钮，只能等待房主开始。
    - Host 退出房间时广播 `DISBAND`；Client 收到后显示“房间已解散，点击确认后返回主页”。
    - Host 必须等待全部席位加入后才能开始游戏。

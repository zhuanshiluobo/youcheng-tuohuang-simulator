# 2026-06-29 本地联机自动跑局扩展记录

## 背景

2026-06-27 事实源文档已明确：`LocalhostAutoplayRunner` 当时能跑到第 8 回合结算，但主要行动只覆盖建设或部署，采集也偏向当前城市资源点，尚未自动覆盖探索、城市移动和付费扩路采集。

## 本次改动

- `Assets/YC/Application/Sessions/LocalhostAutoplayRunner.cs`
  - 本地 Host Session 新增注册 `ExploreLocationCommandHandler` 与 `MoveCityCommandHandler`。
  - 自动主行动策略改为先补足一次显式探索和一次城市移动，再回到建设或部署。
  - 探索命令会提交明确事件选项、路径地点和航道参数，不只依赖默认路径或默认事件选项。
  - 采集阶段会优先寻找一次需要支付航道路费的可采集路径，并提交显式 `routeIds`。
  - 快照新增探索地点、移动路线、付费采集路线和对应尝试/成功计数。
  - 命令失败时，快照会输出失败命令、待选择、待处理卡牌会话和最近日志。

- `Assets/YC/Tests/EditMode/LocalhostAutoplayRunnerTests.cs`
  - 最小回归断言新增探索成功、移动城市成功、付费航道采集成功。
  - 断言快照包含 `ExploredLocations`、`MoveCityRoutes`、`PaidRouteCollections`。
  - 断言日志中存在探索和移动城市事件。

- `docs/工作总结.md`、`docs/本地联机自动跑局验证.md`
  - 同步自动跑局当前覆盖范围和未覆盖边界。

## 当前自动化边界

- 调度已在 2026-07-01 追加覆盖：自动跑局会提交一次真实 `DispatchInfluence`，并把调度路线写入快照。
- 尚未覆盖特殊行动。
- 探索和移动城市会选择当前状态中可验证成功的事件选项，但尚未强制覆盖所有事件效果类型，例如需要指定事件影响力目标的选项。
- 付费采集已在 2026-07-01 追加覆盖指定对手为航道路费接收方的分支：自动跑局会在采集命令中写入 `paymentRecipients`，并在快照中输出接收方证据。

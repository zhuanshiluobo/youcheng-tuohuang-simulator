# 桌面透视与地图导航交互改造记录

## 1. 本次目标

本次将对局主视图调整为类似实体卡牌桌面的透视展示，并在不破坏地图点击和既有平面 HUD 的前提下，补齐桌面平移与缩放操作。

最终范围如下：

- 地图、设施供应区、样式卡区、建设面板和分数区位于同一桌面透视层。
- 展开信息面板、主要行动面板、回合栏、日志、设置和各类弹窗保持屏幕平面显示。
- 相机采用 `45°` 视野角和 `30°` 桌面俯视倾角；Unity 实际旋转为 X 轴 `-30°`，画面方向按最终反馈修正为顺时针倾斜。
- 鼠标右键拖动桌面；固定边界的横向和纵向单边余量最终由地图尺寸的 `25%` 缩小为 `15%`，即各方向分别向内收紧 `10` 个百分点。
- 鼠标滚轮以指针所在桌面位置为锚点缩放，初始为 `100%`，最终范围为 `90%–200%`，单步 `10%`，平滑时间 `0.12s`。
- 地图热点、影响力槽和移动城市等原有点击目标在透视相机下继续可交互。

## 2. 多 Agent 并行实施

本次按可独立集成的边界拆为三个并行实现分支，由根任务负责接口约束、场景与 Prefab 集成、Unity 测试和最终方向校准：

- 相机与几何：负责透视相机适配、联合桌面边界、平移限制、缩放距离计算及几何测试。
- 输入与点击兼容：负责右键拖动、滚轮缩放、平面 HUD 阻挡判定、透视射线点击和调试坐标换算。
- 桌面 Canvas 与 HUD 分层：负责 World Space 桌面 Canvas、桌面布局配置、HUD 引用校验和 Editor Builder 接线。

并行开发只用于职责清晰的代码与测试模块；Unity Editor、场景、Prefab 重建、编译、PlayMode 和最终视觉判断仍由根任务串行完成，避免多个代理同时争用同一个 Unity 实例。

## 3. 实现结果

### 3.1 透视相机与桌面边界

- `MapDisplayController` 从正交地图适配升级为全屏透视相机控制器。
- 初始相机距离由地图与桌面 UI 的联合世界边界计算，不只按地图 Sprite 自身适配。
- `TabletopBoundsContributor` 提供可配置的 `RectTransform[]` 边界贡献者；Editor Builder 将设施供应区、样式卡区和建设面板纳入初始 `100%` 视野。
- 相机保持全屏渲染，桌面内容按安全视口 `Rect(0.02865, 0, 0.78385, 1)` 构图，从而给左侧标签和右侧行动面板预留空间，不缩放或裁切平面 HUD。
- 最终运行时桌面视口边界约为 `(0.0264, 0.1888)..(0.7843, 0.9431)`。
- 顺时针倾斜校准后，地图上边投影宽约 `0.4042`、下边投影宽约 `0.5756`，下边更靠近观察者，符合当前桌面方向要求。

### 3.2 桌面 Canvas 与平面 HUD 分层

- `Tabletop UI Canvas` 使用 `WorldSpace`，承载需要随桌面共同倾斜、平移和缩放的 UI。
- `Mobile City UI Canvas` 保持 `ScreenSpaceOverlay`，承载不需要透视的 HUD、日志、设置和弹窗。
- `TabletopCanvasLayout` 统一配置 Canvas、RectTransform、GraphicRaycaster、CanvasScaler 与世界单位/像素换算。
- `GameplayInteractionHudView` 增加桌面 Canvas 显式引用与配置校验；`GameplayInteractionHudEditorAssetBuilder` 负责生成两个独立根 Canvas 并完成场景引用注入。
- 建设面板按最终需求保留在桌面透视层，后续如需改回平面 HUD，可从 Builder 的父子层级和边界贡献者配置处调整。

### 3.3 拖动、缩放与点击兼容

- 右键按下时通过相机射线与地图平面求交，并按世界平面位移更新相机焦点；拖动即时响应，不加入惯性。
- 平移边界由可替换的 `ITabletopNavigationBoundsProvider` 提供；`MapDisplayController` 只消费接口，不再包含边界推导规则。默认 `TabletopViewportNavigationBounds` 将横向、纵向地图余量分别作为 Inspector 序列化参数，当前均为 `0.15`。
- 默认 Provider 以 `100%` 缩放时安全视口在桌面平面上的投影为基准，并与序列化余量合成为固定世界边界。放大后按实际缩小的可视范围扩展相机中心活动范围，缩小后反向收紧，因此 `90%`、`100%`、`200%` 都能以视口边缘贴到同一最终边界，而不是沿用固定的中心距离。
- 当 `90%` 视口在某一轴上略宽于收紧后的固定边界时，Provider 会保留该轴两个贴边端点并规范化为有效拖动区间，不再把反向区间折叠到中心。
- 后续若需要矩形锚点、多边形区域、不同地图或玩家专属边界，可增加新的 Provider 并在 Prefab 中替换 `navigationBoundsSource`，无需继续修改相机控制器。
- 拖动开始后，即使指针经过平面 HUD 也会持续，直至释放右键；从平面 HUD 上按下右键不会启动桌面拖动。
- 滚轮缩放以指针所指的地图平面位置为锚点，并通过 `SmoothDamp` 平滑过渡。
- `TabletopPointerClassifier` 使用 `EventSystem.RaycastAll` 和 `GraphicRaycaster` 区分桌面 UI 与平面 HUD：桌面 UI 不阻挡地图导航，平面 HUD 阻挡新的拖动和缩放输入。
- `MapInteractionRouter` 改用 `ScreenPointToRay + Physics2D.GetRayIntersectionAll` 检测透视相机下的交互目标，保证地图热点仍可点击。
- 调试坐标同样改为相机射线与地图真实平面求交，不再依赖正交屏幕坐标假设。

### 固定 100% 世界边界与 Provider 重写后

- 新增独立边界 Provider、安全视口平面投影和按实际缩放调整相机中心范围的回归，覆盖 `90%`、`100%`、`200%` 下四边对齐同一世界边界。

- 横纵余量缩小到 `0.15` 后，UnityMCP 运行时探针测得最终固定边界为 `x -72.7214..50.7411`、`y -35.0925..52.4371`；`90%`、`100%`、`200%` 四边可达性回归误差均不超过 `0.001`。
- Provider、相机几何与地图 Prefab 定向 EditMode：`17/17 Passed`。
- 完整 EditMode：`993/993 Passed`。
- PlayMode：`2/2 Passed`。
- 测试后 Unity Console：`0` 条项目 error。

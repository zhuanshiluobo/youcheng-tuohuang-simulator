# 2026-06-20 探索事件结构化效果记录

## 背景

探索事件和移动城市触发的资源点事件已经能够结算部分基础效果，但旧实现把 `ChoicePendingEffects` 保存为展示文案字符串，并在 `ExplorationService` / `CityMovementService` 中通过 `Contains("获得 1 分数")`、`Contains("所有对手获得 3 金券")`、`Contains("所有对手获得 1 异铁")` 判断规则效果。

该实现把规则结算绑定到中文显示文案上。只要卡牌描述改字、翻译、标点调整或 UI 文案重写，就可能改变实际结算结果，不利于测试、回放和后续结构化规则数据。

## 已完成

- 在 `EventCardDefinition.cs` 中新增结构化事件效果模型：
  - `EventEffect`
  - `EventEffectKind`
  - `EventEffectTargetScope`
  - `EventEffectUtility`
- 将 `EventCardDefinition.ChoicePendingEffects` 从 `List<string>` 改为 `List<List<EventEffect>>`。
- 在 `EventCardDatabase` 中把已知待处理效果改为结构化数据：
  - `GainScore(1)`：事件黄 01、黄 08 的 `+1 分数`。
  - `GrantResource(Opponents, GoldVoucher, 3)`：事件红 05 的所有对手获得 3 金券。
  - `GrantResource(Opponents, Iron, 1)`：事件黄 07 的所有对手获得 1 异铁。
  - `PlaceInfluence(...)`：事件红 01、黄 04、黄 05 的影响力放置类效果先结构化记录目标范围与费用。
- `ExplorationService` 与 `CityMovementService` 不再解析中文文案，统一通过 `EventEffectUtility.Apply(...)` 执行已支持的结构化效果。
- `ExploreLocationCommandHandler` 与 `MoveCityCommandHandler` 仍向事件数据写入 `pendingEffect` 展示字符串，但展示字符串由 `EventEffectUtility.Format(...)` 从结构化效果生成。
- `ScoreChanged` 事件判断改为 `EventEffectUtility.HasScoreEffect(...)`，不再检查展示字符串中是否包含“分数”。

## 当前规则口径

- 已实际结算的结构化效果：
  - 当前玩家获得分数。
  - 所有对手获得指定资源。
- 已结构化记录但仍未完整执行的效果：
  - 额外支付后放置影响力。
  - 在当前资源点或相邻航道放置影响力。
  - 在当前资源点相邻航道放置影响力。
- 展示文案现在是结构化效果的派生输出，不再作为规则判断输入。
- 卡牌选项描述仍可保留自然语言，用于 UI 展示；规则结算应继续向 `EventEffect` 扩展，而不是从描述文本反推。

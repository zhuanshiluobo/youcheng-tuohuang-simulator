# 2026-06-20 对局界面控制器职责拆分记录

## 背景

用户指出单个 `MonoBehaviour` 职责过宽：同时负责会话构建、命令提交、地图热点、事件选择 UI、网络回调、规则查询和显示刷新。风险是任何改动都容易引入回归，测试也难以覆盖。

本次目标是先做低风险拆分，让 `MobileCityInteractionController` 不再直接承担所有 UI 构建、会话装配和地图表现刷新职责。

## 已完成

- 新增 `GameSessionBootstrapper`：
  - 负责创建地图查询、影响力、探索、事件牌等服务。
  - 负责构造初始 `GameState`。
  - 负责注册现有命令处理器。
  - 负责解析本机玩家 id。
- 新增 `ActionPanelController`：
  - 负责创建右下角行动面板。
  - 负责刷新标题、按钮可用状态和状态文案。
- 新增 `EventChoiceDialog`：
  - 负责事件牌选择 UI。
  - 负责探索路线选择 UI。
  - 负责过路费接收者选择 UI。
- 新增 `ExploreChoiceModels`：
  - 迁出探索路线选择和过路费选择的小模型。
- 新增 `MapInteractionClickTargets`：
  - 迁出 `MapHotspot`、`MobileCityClickTarget`、`InfluenceSlotClickTarget`。
- 新增 `MapViewPresenter`：
  - 负责创建地图热点、资源图标显示对象、资源点影响力槽位、路线影响力槽位和移动城市显示对象。
  - 负责刷新资源图标、影响力占用/高亮状态、城市位置和地图热点高亮。
  - 负责地图坐标换算和调试热点高亮显示。
  - 只做表现层刷新，不提交 `GameCommand`，不接管规则判断和点击状态机。
- 修改 `MobileCityInteractionController`：
  - 移除会话装配细节。
  - 移除行动面板内部 UI 创建细节。
  - 移除事件弹窗内部 UI 创建细节。
  - 移除地图热点、资源图标、影响力槽位、城市对象和高亮显示的具体渲染缓存。
  - 保留 public 点击入口、流程编排、命令提交、状态刷新、地图显示调度和二次确认逻辑。

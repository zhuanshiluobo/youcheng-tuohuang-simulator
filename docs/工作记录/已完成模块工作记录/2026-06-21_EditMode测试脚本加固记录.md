# 2026-06-21 EditMode 测试脚本加固记录

## 背景

近期多次执行 `tools/Run-EditModeTests.ps1` 时出现测试结论不清的问题：

- Unity EditMode 测试已经跑完，但 NUnit XML 结果文件晚于脚本检查写出，脚本先报“未生成结果文件”。
- 同一项目已被另一个 Unity Editor 或 batchmode 实例打开时，Unity 启动失败，但脚本提示只说明缺少 XML，不容易定位到项目占用。
- PowerShell 直接完整解析 Unity 生成的 XML 时，中文项目路径可能导致后续节点解析失败；实际只需要根节点 `<test-run>` 的统计属性即可判定结果。

## 已完成

- 仅修改 `tools/Run-EditModeTests.ps1`，未改游戏逻辑。
- 新增结果文件等待参数：
  - `-ResultsWaitTimeoutSeconds`，默认 `120` 秒。
  - `-ResultsStableMilliseconds`，默认 `1000` 毫秒。
- Unity 退出后不再立刻判断 XML 是否存在，而是等待目标 XML 非空并稳定一段时间。
- 启动 Unity 前新增同项目占用检查：
  - 查询 Windows 上已有 `Unity.exe` 进程命令行。
  - 如果命令行包含当前项目路径，直接输出项目路径、PID 和命令行后退出。
  - 检测 `Temp\UnityLockfile`，命中时提示锁文件路径、写入时间和处理建议。
  - 保留 `-SkipProjectLockCheck` 作为手动绕过入口，用于确认陈旧锁文件等特殊情况。
- XML 结果判定改为只读取 `<test-run>` 根标签属性：
  - 读取 `result`、`total`、`passed`、`failed`、`inconclusive`、`skipped`、`duration`。
  - 避免整份 XML DOM 解析受到中文路径编码问题影响。
- 最终退出码改为以 XML 结果为准：
  - `result=Passed` 且 `failed=0` 时退出码为 `0`。
  - 其他测试结果均退出码为 `1`。
  - 如果 Unity 进程退出码非 0 但 XML 显示全部通过，脚本输出 warning，并按 XML 通过处理。

## 剩余 Unity 环境限制

- Unity 仍不允许同一个项目被多个 Editor 或 batchmode 实例同时打开；脚本现在只负责提前识别并给出清晰提示，不会自动结束已有进程。
- 如果 Unity 异常退出后留下陈旧 `Temp\UnityLockfile`，脚本会默认阻止测试启动。确认没有同项目 Unity 进程后，可人工处理锁文件，或临时使用 `-SkipProjectLockCheck` 交给 Unity 自行判断。
- 当前环境中 Unity 可能先让 PowerShell 看到空退出码，再补写 XML；脚本现在以 XML 根节点结果为最终判定。
- 如果 Unity 本身在启动阶段崩溃且没有 XML，脚本仍会失败，并提示查看 Unity 日志。

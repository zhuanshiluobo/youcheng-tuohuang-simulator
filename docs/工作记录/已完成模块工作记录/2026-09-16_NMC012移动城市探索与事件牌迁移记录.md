## 完成结论

## 移动城市时序

```text
MoveCity command
  -> stable candidate/target ID
  -> effect.city.move 校验玩家、相邻地块、红区、占用、费用和行动预算
  -> BeforeCityMove Event
  -> 等待响应子 Effect 完成
  -> 重新校验目标
  -> pay base cost
  -> remove displaced opponent influence (sorted child Effects)
  -> effect.city.position.commit
  -> place source influence (无合法槽位时 no-op)
  -> CityMoveCompleted Event
  -> EventCardEffect 子节点（无资源点目标才抽牌）
  -> 等待事件牌完成后消费主要行动并结束
```

`CityMoveEffectExecutor` 是唯一提交入口；位置写入由 `CityPositionCommitEffectExecutor` 完成，影响力复用 NMC-011 合同。`CityMoveCandidateQueryService` 输出稳定的 `city.move.target:<locationId>` 候选，表现层已提交该候选 ID，Host 同时兼容旧地点 ID并在 Effect 内重新校验。

Before 响应期间改变占用或合法性时，移动不会扣费、移除影响力或提交位置。子 Effect 失败、玩家拒绝和事件牌后续失败均由父 Effect 保留为明确结果，不依赖额外 C# 链式回调。

## 探索与事件牌行为矩阵

| 行为族 | 通用实现 | 恢复点/提交内容 |
|---|---|---|
| 即时/无额外目标 | `effect.event_card.resolve` + 版本化完成 Event handler | 抽牌、资源点指示物、`EventCardRevealed`；0 选项牌揭示后自动完成，不创建选项交互 |
| 单选/多选候选 | 稳定 `cardId:option:<index>` 候选 | `InteractionRequest` 保存候选集和 revision，回答后只消费一次 |
| 条件效果 | `ChoicePendingEffects` 编译为通用 Resource/Score/Influence Effect | 由 Effect 合同表达条件失败和部分失败 |
| 影响力组合 | `event_card.influence_targets` 稳定槽位候选，多选按 `MinSelections/MaxSelections` 校验 | 保存已选槽位，再生成放置子 Effect |
| 探索路费/目标影响力 | `effect.exploration.resolve` 先生成 pay/gain 路费子树，再生成事件牌子节点 | 路费接收方、路径地点/航道和主影响力槽位均为稳定引用 |
| 移动后响应 | `CityMoveCompleted` observer 按目标地块事件颜色创建事件牌子 Effect | 作为移动父节点的响应子树，不再追加旧服务事件 |
| 动态继续 | `EffectTreeExecutor` 持久化 flow stage、interaction、child、event、dispatch receipt | 恢复时不重复抽牌、不重复分发、不重复提交 |

事件牌目录由 `EventCardLuaCatalog` 按 `DefinitionVersion=1.0.0` 生成脚本并通过 `LuaEffectEventDispatcher` 注册 handler，实际执行经过 MoonSharp 沙箱、Effect 白名单和 `LuaEffectSpecCompiler`。持久化只保存 `handlerId/contentId/version/hash` 和绑定参数，不保存 C# 委托或 Lua 函数引用。牌 ID 只承担内容身份、路由和稳定候选生成；奖励与待选效果统一编译为 Resource/Score/Influence Effect，没有逐牌规则分支。

## 续记：移动后事件牌与换轮边界修复

- `ExploreLocationCommandHandler` 不再要求客户端提交 `influenceSlotId`；空值以 `null` 进入 `effect.exploration.resolve`，由 `ExplorationService.ResolveInfluenceSlotId` 按目标地块槽位索引稳定选择第一个合法空位。
- 新增 `EventCardInteractionUiCoordinator`，通过 `InteractionRequestRouter` 注册为生产 Renderer，同时接入移动城市统一输入路由。`event_card.option` 使用现有事件牌弹窗，`event_card.influence_targets` 使用地图槽位高亮，多选完成后统一提交带 `interactionId` 与 `expectedRevision` 的 `AnswerInteraction`。
- `RoundExecutionService.ValidateNextRoundCreation` 在创建下一回合前检查所有开放 Interaction 与非终态 Effect；发现残留时停止换轮并记录 `round_transition_blocked` 诊断，不清除任何 Interaction/Effect 状态。

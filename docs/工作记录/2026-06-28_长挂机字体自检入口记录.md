# 2026-06-28 长挂机字体自检入口记录
## 背景

- 2026-06-24 与 2026-06-25 已经把 UGUI 动态字体的统一入口、单例缓存、定时健康检查、焦点恢复重建和 `Font.textureRebuilt` 监听接入到 `FontUtility`。
- 现有修复虽然降低了长时间挂机、切后台或纹理重建后的字体异常风险，但开发侧仍缺一个“主动触发检查并输出现场快照”的入口，后续排查仍容易回到人工挂机等待复现。
- 本次目标是在开发/测试环境里补齐最小可回归的字体自检入口，让字体健康检查可以被主动触发、模拟和记录，并把 `PromptPresenter`、`StartMenuController` 这类运行时文本路径一并纳入观察范围。
## 设计判断

- 单靠 30 秒被动巡检，只能在异常已经发生时尽量重建字体，不能帮助开发者在问题现场快速拿到“托管字体缓存、关联 `Text`、纹理状态”的上下文。
- 单纯补一个测试断言仍不够，因为真正高风险的是 Unity 运行时中的动态字体、Best Fit 文本和应用焦点恢复这条链路，需要一个开发态探针把这些路径主动拉起来。
- 最稳妥的方案是：
  - 在 `FontUtility` 内部暴露一次“手动执行健康检查并输出前后快照”的能力。
  - 用临时探针 UI 把 `PromptPresenter`、Best Fit 文本和 Latin/CJK 字体都挂到同一轮快照里。
  - 同时提供 Editor 菜单、命令行参数和最小 EditMode 回归三种入口，减少后续只能靠人工挂机的场景。
## 本次改动

- `Assets/YC/Presentation/FontUtility.cs`
  - 新增 `RunManagedFontHealthCheck(bool simulateInvalidTexture)`，支持主动执行一次托管字体健康检查。
  - 新增托管字体快照采集，记录缓存字体、材质/纹理、关联 `Text`、层级路径、`fontSize`、`resizeTextForBestFit`、启用状态和文本样本。
  - 保留原有 30 秒巡检，但把手动检查与快照能力复用到统一入口，便于开发态直接调用。
- `Assets/YC/Presentation/FontHealthCheckRunner.cs`
  - 新增开发态字体自检运行器，支持 `CheckOnly` 与 `SimulateRecreate` 两种模式。
  - 自检前会临时创建 `YC Font Health Probe`，并通过 `PromptPresenter.Build(...)`、一条 Best Fit 文本和一条 Latin 文本构造探针 UI。
  - 自检后输出包含探针对象信息的快照字符串，便于直接贴到日志或问题记录里。
- `Assets/YC/Presentation/StartMenuController.cs`
  - 将原命令行开发任务入口收敛为 `TryRunDevCommandLineTask()`。
  - 新增 `--yc-dev-font-health-check` 与 `--yc-dev-font-health-check-simulate` 两个开发态参数，允许在 Editor 或 Development Build 启动时直接触发字体自检。
- `Assets/YC/Editor/FontHealthCheckMenu.cs`
  - 新增 `YC/Dev/Run Font Health Check Snapshot`。
  - 新增 `YC/Dev/Run Font Health Check (Simulate Recreate)`。
- `Assets/YC/Tests/EditMode/FontUtilityTests.cs`
  - 保留已有字体单例缓存断言。
  - 新增 `RunFontHealthCheck_CapturesManagedFontSnapshot`，验证自检能创建探针并输出包含探针文本的快照。
  - 新增 `RunFontHealthCheck_SimulatedModeRecreatesManagedFonts`，验证模拟模式会触发托管字体重建。
- `tools/Run-FontHealthCheckValidation.ps1`
  - 新增最小命令行验证脚本，只跑 `YC.Tests.EditMode.FontUtilityTests`，用于快速回归字体自检入口。
## 触发方式

### Editor 菜单

```text
YC/Dev/Run Font Health Check Snapshot
YC/Dev/Run Font Health Check (Simulate Recreate)
```

### 命令行参数

```text
--yc-dev-font-health-check
--yc-dev-font-health-check-simulate
```

- 适用范围：`Unity Editor` 与 `Development Build`。
- 输出位置：`Console` / Player log。

### 最小验证脚本

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Run-FontHealthCheckValidation.ps1
```

## 当前自动化边界

- 仍无法用 EditMode 或这次新增入口稳定自动验证真正的显卡上下文丢失、驱动重置或系统字体被操作系统回收后的平台级行为。
- 仍无法完全替代长时间挂机后的概率性退化复现，尤其是打包后失焦、休眠恢复、窗口最小化和多显示器切换等 Unity 运行时边界。
- 当前自检入口更适合做三件事：
  - 主动检查托管字体缓存与纹理是否处于有效状态。
  - 主动走一遍“模拟异常后重建”的代码路径。
  - 在问题现场快速沉淀快照，降低后续靠口述和截图猜状态的成本。
## 后续建议

- 如果后面还出现真实挂机字体异常，优先要求复现环境先跑一次 `Run Font Health Check Snapshot` 或命令行自检，把快照附到问题记录里。
- 长期最稳的根因方案仍是引入项目内可分发的 CJK 字体资源，逐步降低对系统动态字体与 Unity 动态字体纹理的依赖。

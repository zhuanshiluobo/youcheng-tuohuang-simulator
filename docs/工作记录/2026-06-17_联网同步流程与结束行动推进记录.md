# 2026-06-17 联网同步流程与结束行动推进记录

## 问题背景

本轮联机实测中，四个窗口均使用 `Builds\Localhost\游城拓荒模拟器.exe` 启动。观察到的问题集中在两个方向：

- 客户端初始入场阶段偶发提示“联网同步初始化失败，请返回房间重试”或“联网状态未同步”。
- 玩家 1 完成主要行动后，玩家 2/3/4 的行动解锁流程不完整，且多个客户端右侧面板都显示为 Player 2，导致无法判断本机玩家与当前行动玩家。

结合截图和代码路径判断，问题主要来自两个层面：

- 初始权威状态快照较大，默认可靠消息可能无法稳定承载完整 `GameState`。
- 客户端座位和 Netcode `clientId` 的映射不稳定，不能依赖 `ConnectedClientsIds` 排序推断玩家号。

## 本轮目标

- 让客户端可靠接收 Host 的初始权威快照。
- 用明确的本地玩家号请求建立 `clientId -> playerId` 映射，避免三个客户端都显示或被识别为 Player 2。
- 推进主要行动后的同步流程：主要行动完成后先保留在当前玩家，等待玩家点击“结束本回合”，再解锁下一位玩家行动。
- 让右侧行动面板同时展示“本机玩家”和“当前行动玩家”，便于多人窗口排查。

## 已完成

### 1. 初始同步消息改用分片可靠传输

- `UnityNetcodeCommandTransport` 中的初始状态响应和接受消息改为 `NetworkDelivery.ReliableFragmentedSequenced`。
- 该调整用于承载较大的 Host 权威 `GameState` 快照，降低初始同步阶段因消息过大导致客户端无法入场的概率。

### 2. 客户端初始状态请求增加玩家号

- 新增 `InitialStateRequestDto.PlayerId`。
- Client 请求初始状态时携带本机 `localPlayerId`。
- Host 收到请求后优先注册 `clientId -> playerId`，并记录映射日志。
- Host 在命令提交路径也会尝试补登记映射，用于覆盖请求和命令先后到达的竞态。

### 3. 修复客户端座位排序与默认名称

- `UnityOfficialRoomService.OrderLobbyPlayers()` 改为 Host 固定在第一位，非 Host 按 Lobby `Player.Id` 做稳定排序。
- 默认玩家名在输入为空或仍为 `Player x` 时，统一归一为 `Player {seat.PlayerId}`。
- 该修复用于避免多个加入玩家都被显示为 Player 2，并让玩家 2/3/4 的客户端身份和座位保持一致。

### 4. 主要行动完成与结束本回合拆分

- `RoundAdvanceService` 新增 `MarkMainActionComplete(state, playerId)`，只标记当前玩家已完成主要行动，不立即推进到下一玩家。
- `RoundAdvanceService` 新增 `EndCompletedAction(state, playerId)`，校验当前玩家、行动轮、待选项和主要行动完成状态后，再推进到下一位未行动玩家或下一行动轮。
- 原 `CompleteMainAction()` 保留兼容路径，避免影响旧调用和既有测试语义。

### 5. 主要行动命令不再直接推进玩家

以下主要行动处理器改为调用 `MarkMainActionComplete()`：

- `DeployInfluenceCommandHandler`
- `DispatchInfluenceCommandHandler`
- `ExploreLocationCommandHandler`
- `MoveCityCommandHandler`

因此玩家完成主要行动后，当前玩家仍保持不变，UI 会提示点击“结束本回合”。

### 6. 新增结束行动命令

- 新增 `EndActionCommandHandler`，处理 `GameCommandKind.EndAction`。
- 处理器调用 `RoundAdvanceService.EndCompletedAction()`。
- 成功后返回 `CommandEffect.PlayerAdvanced`，由 Host 权威状态快照同步给所有客户端。
- `MobileCityInteractionController.BuildSession()` 已注册该 handler。

### 7. 结束本回合按钮接入联网命令

- `MobileCityInteractionController` 新增 `CanEndCurrentAction()` 和 `EndCurrentAction()`。
- `RoundTrackerController.EndCurrentRound()` 改为调用 `mobileCityInteraction.EndCurrentAction()`。
- 联网模式下按钮不再因为网络启动而永久禁用，而是根据当前 `GameState`、本机玩家、当前行动玩家、主要行动完成状态和终局状态动态启用。

### 8. 行动面板文案调整

- 右侧面板从只展示“当前玩家”改为展示“本机：Player x / 行动：Player y”。
- 主要行动完成后的提示改为“主要行动已完成，请点击结束本回合”。
- 命令完成提示同步调整为“已完成，请点击结束本回合”，为后续快速行动阶段预留流程空间。

## 测试与验证

- 确认初始状态响应和接受消息使用 `ReliableFragmentedSequenced`。
- 确认初始状态请求会携带 `PlayerId`，Host 会注册请求方玩家映射。

- `EndAction` 在主要行动完成后推进当前玩家。
- `EndAction` 在主要行动未完成时失败且不推进。
- 探索行动相关测试调整为验证“标记完成”而不是“立即推进”。

## 建议复测步骤

1. 重新构建 `Builds\Localhost\游城拓荒模拟器.exe`。
2. 启动 Host 和三个 Client，确认四个窗口分别显示本机 Player 1/2/3/4。
3. 玩家 1 完成一次主要行动后，确认玩家 1 仍是当前行动玩家，且“结束本回合”按钮可用。
4. 玩家 1 点击“结束本回合”，确认 Host 同步权威快照后玩家 2 解锁行动。
5. 玩家 3/4 窗口应显示“本机：Player 3/4 / 行动：Player 2”，并保持等待。
6. 若仍出现“联网状态未同步”，优先查看对应窗口的 PlayerId、`clientId -> playerId` 注册日志和 Netcode 自定义消息异常栈。

## 后续关注

- 快速行动阶段尚未完整接入，本轮只为其保留“主要行动完成后不立刻推进”的流程余地。
- 若实测仍有客户端卡在 Player 2，需要继续采集 Lobby 玩家排序、LocalPlayerId 和 Host 映射注册日志。
- 若初始同步仍失败，需要进一步拆分快照或增加显式 ACK/重发上限与错误提示。

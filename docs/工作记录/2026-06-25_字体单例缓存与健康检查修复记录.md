# 2026-06-25 字体单例缓存与健康检查修复记录

## 背景

- 2026-06-24 已将 UGUI 动态字体入口收敛到 `FontUtility`，并增加运行时刷新驱动，用于降低长时间挂机、焦点恢复或字体纹理重建后文字消失的风险。
- 新截图显示字体仍有异常表现：文字没有完全消失，但部分 UGUI 文本呈现粗糊、渲染状态不稳定的迹象。
- 旧自动化没有覆盖这类运行时字体退化；本次先跑全量 EditMode 建立基线，再收窄字体刷新策略并补回归测试。

## 判断

- 旧实现按字号缓存 CJK / Latin 动态字体对象，`resizeTextForBestFit` 文本在实际渲染字号变化后，容易让同一界面存在多个动态字体纹理与重建路径。
- 旧的 30 秒健康检查会无条件对托管 `Text` 调用 `FontTextureChanged()`、`SetAllDirty()` 和 `Canvas.ForceUpdateCanvases()`，这会周期性扰动 UI 文本布局与字体纹理状态。
- 更稳妥的策略是：每个字体族只保留一个动态字体实例，让 UGUI `Text.fontSize` 和 Best Fit 自己处理字号；周期检查只在字体材质纹理明显丢失时重建，不再无条件刷新所有文本。

## 本次改动

- `Assets/YC/Presentation/FontUtility.cs`
  - 将 `CjkFonts` / `LatinFonts` 从按字号字典缓存改为 `cjkFont` / `latinFont` 单例缓存。
  - 保留 `GetCjkFont(int fontSize)` / `GetLatinFont(int fontSize)` 签名，调用方无需改动；字号参数只用于首次创建动态字体，后续同一字体族复用同一 `Font` 实例。
  - `RecreateManagedFonts()` 清空字体单例后，按已记录的字体家族重新绑定场景内托管 `Text`。
  - 新增 `HasInvalidManagedFontTexture()`，用于判断托管字体的材质或主纹理是否丢失。
  - `FontRefreshDriver.Update()` 保留 30 秒健康检查节奏，但不再无条件刷新所有文本；只有检测到无效字体纹理时才重建托管字体。
  - `Font.textureRebuilt`、应用恢复焦点和从暂停恢复时的刷新路径继续保留。

- `Assets/YC/Tests/EditMode/FontUtilityTests.cs`
  - 新增 `GetCjkFont_ReusesOneFontAcrossTextSizes`，锁定 CJK 字体不同字号复用同一动态字体实例。
  - 新增 `GetLatinFont_ReusesOneFontAcrossTextSizes`，锁定 Latin 字体不同字号复用同一动态字体实例。
  - 测试通过反射访问 `FontUtility`，保持与当前 EditMode 测试程序集边界兼容。

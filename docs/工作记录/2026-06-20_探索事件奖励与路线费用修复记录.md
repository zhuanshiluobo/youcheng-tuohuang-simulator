# 2026-06-20 探索事件奖励与路线费用修复记录

## 背景

在 `ExploreLocationCommandHandlerTests` 全类测试中，红区开放回合回归用例已经通过，但仍有 3 个旧用例失败。失败集中在探索事件奖励结算、显式路线费用，以及显式路径目标被对手城市占用时的命令校验预期。

本次修复要求保持 UI 只提交命令，不绕过 `ExploreLocationCommandHandler` / `ExplorationService` 的命令校验。

## 失败根因

- `event_yellow_01` 的选项 1 是即时结算 `+4 金券` 与 `+1 分数`。探索默认一段路线先扣 `2` 金券，因此玩家初始 `10` 金券应变为 `10 - 2 + 4 = 12`。旧断言仍预期 `8`，等同于只扣路线费、未计算事件奖励。
- `ExploreLocation_WithEventOptionParameter_UsesSelectedEventOption` 与默认路径即时选择用例使用同一事件牌和选项，也应得到 `12` 金券与 `1` 分数。
- `ExploreLocation_WithExplicitPath_UsesChosenRouteSequence` 显式选择 `city-a -> mine-b -> harbor-c` 两段路线。探索路线费用当前按每段固定 `2` 金券计算，总成本为 `4`，选项 1 奖励 `+4 源石碎片`，所以金券应为 `10 - 4 = 6`。旧断言预期 `2`，与领域规则不一致。
- 该显式路径成功用例的目标 `harbor-c` 初始被 2 号玩家城市占用，命令校验正确拒绝探索。成功用例需要移开对手城市；占用目标的拒绝行为应单独作为回归测试。

## 已完成

- 修正即时事件奖励相关断言：`GoldVoucher` 从 `8` 调整为 `12`，与 `ResolvePendingChoice` 延迟结算路径保持一致。
- 修正显式两段路线费用断言：`GoldVoucher` 从 `2` 调整为 `6`。
- 在显式路径成功用例中清空 2 号玩家城市位置，避免目标占用干扰路线费用语义。
- 新增 `ExploreLocation_WithImmediateEventOption_MatchesPendingChoiceResolution`，验证即时选择事件选项与先打开 `PendingChoice` 再解析的最终资源、分数、资源标记、影响力数量一致。
- 新增 `ExploreLocation_WithExplicitPath_WhenTargetHasOpponentCity_FailsWithoutMutatingState`，验证显式路径不能绕过目标占用校验，失败时不扣金券、不抽事件牌、不放资源标记、不放影响力。
- 修复若干既有 UI / Editor 半迁移导致的编译阻断，使 EditMode 测试可重新编译执行：
  - `MobileCityInteractionController` 删除已经迁移到 `MapInteractionClickTargets.cs` / `ExploreChoiceModels.cs` 的重复类型定义。
  - 补齐 `ActionPanelController` 需要的 `UiTheme.DisabledButtonBackground`。
  - 修正 `MapBuildReadinessPreprocessor` 中 `Application.streamingAssetsPath` 的命名空间歧义。

## UI 与命令校验口径

- 探索 UI 仍通过 `GameCommandKind.ExploreLocation` 和 `GameCommandKind.ResolvePendingChoice` 提交命令。
- 路线、事件选项、支付接收方等参数仍进入 `ExploreLocationCommandHandler`，再由 `ExplorationService` 统一校验。
- 本次没有在 UI 层直接改写资源、抽牌、放置资源标记或跳过目标占用校验。

# 2026-06-22 事件选择表现层控制器拆分记录

## 背景

上一轮探索交互已经把事件弹窗、命令提交和提示呈现拆出一部分，但事件选项选择、路费接收方选择、事件影响力目标选择仍由 `MobileCityInteractionController` 直接持有临时状态。这样会让地图点击、UI 展示、命令参数组装和选择状态机继续耦合在同一个 MonoBehaviour 中。

本次目标是继续收窄 `MobileCityInteractionController`：UI 只负责展示和发出命令意图，选择状态与参数编码进入独立表现层控制器。

## 已完成

- 新增 `EventOptionSelectionController`：
  - 保存当前待选事件卡。
  - 校验事件选项索引。
  - 计算该选项是否需要事件影响力目标。
- 新增 `ExplorePaymentRecipientSelectionController`：
  - 根据探索路径生成需要玩家选择接收方的航道列表。
  - 默认选择第一个合法接收方。
  - 校验接收方切换是否合法。
  - 输出 `routeId=playerId` 格式的命令参数编码。
- 新增 `EventInfluenceTargetSelectionController`：
  - 保存事件影响力目标选择中的选项索引和已选槽位。
  - 按 `PlaceInfluence` 结构化效果累计所需槽位数量。
  - 避免重复槽位重复计数。
  - 将已选槽位写入命令参数。
- 调整 `MobileCityInteractionController`：
  - 移除路费接收方字典、路费候选列表、事件影响力目标列表和事件选项索引等直接状态。
  - 通过新控制器驱动事件弹窗、路费弹窗、事件影响力目标点击后的提交逻辑。
  - 保留地图高亮和合法槽位判断在主控制器中，避免本次拆分扩大到地图视图与规则查询边界。
- 调整 `EventChoiceDialog`：
  - 移除 `PendingEventCard` 状态。
  - 弹窗只负责展示事件卡、路径/路费选项，并把用户点击回调给外层控制器。
- 调整 `ExploreChoiceModels`：
  - 将 `ExplorePathChoice` 与 `ExplorePaymentChoice` 改为公开轻量模型，供弹窗和选择控制器共享。

## 后续边界

- 事件影响力目标的候选高亮合法性仍在 `MobileCityInteractionController`，因为它依赖地图视图、资源点状态、影响力服务和探索主影响力保留槽位。后续若继续拆分，可把“候选枚举/合法性判断”再抽为只读查询服务。
- `MobileCityInteractionController` 仍承担移动、探索、部署、调度等多种行动流程编排，后续可继续按行动类型拆分控制器。

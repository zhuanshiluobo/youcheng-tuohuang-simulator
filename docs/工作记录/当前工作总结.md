## 2026-07-13 Steam Lobby 与 Mirror 开局就绪门禁

- 修复“Steam Lobby 席位已满，但远端 Mirror/Fizzy 连接或 SteamID 映射尚未完成时仍可开局”：`PlayerSeat` 现在显式区分 `LobbyMemberPresent`、`TransportConnected`、`IdentityVerified` 与 `GameStateSynchronized`，`IsReady` 仅由 Host 的前三项权威状态计算。
- `MirrorNetworkRuntime` 在 `NetworkManager.StartHost/StartClient` 完成内部回调注册后订阅连接事件，并补枚举已存在连接，兼容 Host 本地连接同步建立、Client 回调延后一帧、远端异步连接三种顺序；Shutdown 对称退订，迟到事件不再恢复状态。
- Steam Host 从 Fizzy/Mirror 的 `connection.address` 解析远端 SteamID，校验实际 Lobby 成员、稳定席位、唯一连接与连接存活状态；非成员、无法解析和重复连接会被拒绝。Host 将只读就绪结果写入 `transportConnected.<seat>` 与 `identityVerified.<seat>` Lobby metadata，协议版本升级为 `2`。
- 本地 Mirror 模式采用同一开局策略；Client 不再上报裸 `PlayerId`，而是呈递由 Host 的 TCP 信令连接签发的随机身份凭据。凭据随信令断线撤销，发送操作在 Unity 主线程执行。
- 进入游戏场景后，`MirrorCommandTransport` 必须按等待房间留下的 `connectionId + identity + PlayerId` 三元组重新校验，Client 应用初始快照后回传确认并进入 `GameStateSynchronized`。
- 已落盘验证：等待房间状态机 `12/12`、上一版全量 EditMode `535/535` 通过；本次新增了本地信令身份凭据回归并调整 Steam/Mirror 核心静态断言，但整理文档时 Unity Editor 正占用项目，新用例和新全量尚未重跑。真实 Editor Host + 两个 Development Build Client 三进程和多 Steam 账号 P2P/Relay 仍未执行，不能视为已通过。

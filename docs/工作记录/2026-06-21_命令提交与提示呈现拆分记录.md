# 2026-06-21 命令提交与提示呈现拆分记录

## 背景

上一轮对局界面控制器拆分后，`MobileCityInteractionController` 仍保留本地/联网命令提交、联网拒绝提示、联网确认刷新、顶部提示 UI 创建和提示渐入渐出动画。用户要求继续降低主控制器职责，但保持现有行为不变，并明确不要把规则结算移入 Presentation。

本次拆分采用小步边界：主控制器继续负责命令构造、行动规则流程编排和命令成功后的 UI 刷新；新类只接管提交通道和提示呈现。

## 已完成

- 新增 `CommandSubmissionController`：
  - 负责初始化 `UnityNetcodeCommandTransport`。
  - 负责本地模式下调用 `GameSession.Submit()`。
  - 负责联网模式下调用 `SubmitOrSend()`。
  - 负责订阅初始网络状态、确认命令和拒绝命令回调。
  - 确认命令或初始状态应用后，通过回调触发主控制器 `RefreshAllFromState()`。
  - 命令被 Host 拒绝后，通过 `NetworkCommandPromptFormatter.BuildRejectedCommandPrompt()` 生成拒绝提示，再交给主控制器提示入口显示。
- 新增 `PromptPresenter`：
  - 负责创建 `Mobile City UI Canvas`、顶部提示面板、提示文本和 `CanvasGroup`。
  - 负责 `SetPrompt()` 后的淡入、停留和淡出动画。
  - 支持二次确认期间保持提示显示，不自动淡出。
- 修改 `MobileCityInteractionController`：
  - 移除 `UnityNetcodeCommandTransport` 字段和网络回调方法。
  - 移除顶部提示文本、`CanvasGroup`、显示计时和动画状态字段。
  - 保留 `SubmitGameCommand()`、`SetPrompt()` 和 `UpdatePromptAnimation()` 作为薄转发入口，减少调用点改动。
  - 保留命令构造、成功后的行动 UI 刷新、二次确认、地图点击状态机和规则流程编排。

## 设计边界

- `CommandSubmissionController` 不构造命令，不决定命令成功后刷新哪些 UI。
- `CommandSubmissionController` 不执行移动、探索、影响力、事件选择等规则结算。
- `PromptPresenter` 不读取 `GameState`，不决定提示文案，只呈现主控制器传入的文本。
- `MobileCityInteractionController` 仍是对局界面的流程编排者，后续拆分应继续围绕明确边界小步推进。

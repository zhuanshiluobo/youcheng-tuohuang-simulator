# 2026-06-24 事件卡片收起点击与座位顺序测试修正记录

## 背景

探索事件卡片在选择“放置影响力”或“支付放置影响力”类选项后，会打开事件卡片并要求玩家在地图上选择影响力槽位。事件卡片展开时会遮挡地图；收起后虽然能看到高亮影响力圆圈，但一段时间内点击只能触发卡片收起或高亮反馈，无法真正完成目标槽位选择。

用户确认最终交互口径为：

- 不改顶部提示栏。
- 事件卡片整体收起为名称与代表资源点所在的一行。
- 收起状态仍可拖动卡片。
- 展开按钮放在名称和代表资源点最右侧。
- 收起后点击地图上的高亮影响力圆圈应与普通“放置影响力”使用同一套点击逻辑，不需要额外换算地图坐标。

## 已完成

- 调整 `EventChoiceDialog` 的事件卡片收起表现：
  - 收起后仅保留摘要行，展示事件卡名称和所属资源点。
  - 展开/收起按钮位于摘要行右侧。
  - 卡片可拖动，收起后不再用大面板遮挡地图交互。
- 修复事件影响力目标选择模式被待选事件状态覆盖的问题：
  - `RefreshActionPanel()` 在 `eventInfluenceTargetSelection.IsSelecting` 为真时，不再把 `actionPanelMode` 覆盖回 `PendingChoice`。
  - 避免出现“高亮仍在，但点击分支不再进入事件影响力目标选择”的状态错位。
- 统一事件影响力目标点击入口：
  - 事件目标选择复用 `InfluenceSlotClickTarget -> OnInfluenceSlotClicked(slotId)`。
  - `OnInfluenceSlotClicked` 只校验 `mapView.ContainsHighlightedInfluenceSlot(slotId)`，随后调用 `SelectEventInfluenceSlot(slotId)`。
  - 删除此前为兜底排查加入的屏幕坐标/地图坐标换算路径。
- 保留同帧去重：
  - 事件目标选择中仍记录 `lastEventInfluenceTargetSelectionFrame`，避免同一帧内地块热点与影响力槽位重复触发导致重复提交。
- 修正 `SetupCommandHandlerTests.ChooseInitialLocation_WithSeatTurnOrder_UsesPlayerIdOrderForEntranceAndFirstAction`：
  - 测试目标是验证座位顺序模式下按玩家 ID 顺序 `1,2,3,4` 入场和进入第一行动轮。
  - 将测试初始化中的 `StartPlayerId` 改为 `1`，与 `GameLaunchStateFactory` 在网络/座位顺序模式下的真实初始状态一致。
  - 保持断言 `P1/P2/P3/P4 = 10/12/14/18` 不变。

## 清理内容

## 后续边界

- 事件卡片收起后的目标选择不再额外做屏幕坐标查找；后续若需要扩大可点范围，应优先调整影响力槽位碰撞体或点击目标对象，而不是在控制器中恢复坐标换算兜底。
- 事件目标选择与普通放置影响力共享点击链路后，地图交互的一致性依赖 `MapViewPresenter` 正确创建并高亮 `InfluenceSlotClickTarget` 对应对象。

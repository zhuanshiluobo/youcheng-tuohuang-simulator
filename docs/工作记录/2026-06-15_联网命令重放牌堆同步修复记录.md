# 2026-06-15 联网命令重放牌堆同步修复记录

## 问题背景

`EventDeckService` 之前默认使用 `new Random()` 初始化事件牌堆。多人模式下 Host 只广播已接受命令，Client 收到确认命令后在本地 `GameSession.Submit(GameCommand)` 重放。入场事件、探索等命令会触发抽牌，如果 Host 与 Client 的本地牌堆顺序不同，同一条命令会抽到不同事件牌，导致 `PendingChoice`、资源指示物、奖励和后续状态分叉。

## 修复策略

本次采用“确定性 seed + Host 初始状态同步”的保守实现。

- `EventDeckService` 增加固定默认 seed 和显式 seed 构造函数，不再默认使用时间相关随机源。
- `GameState` 增加 `EventDeckSeed` 字段，用于记录当前对局事件牌堆初始化来源。
- 多人会话构建时根据 `GameLaunchContext.RoomId` 生成稳定 seed，并用该 seed 初始化事件牌堆。
- 新增 `InitialGameStateDto`，由 Host 下发权威初始 `GameState` 和下一条确认命令序号。
- Client 在应用确认命令前必须先应用 Host 初始状态。
- Client 初始状态未同步时，拒绝发送本地命令，也拒绝应用确认命令。
- 命令重放仍走 `GameSession.Submit(GameCommand)`，网络层没有绕过规则系统。

## 关键实现点

### `EventDeckService`

- 新增 `DefaultSeed`。
- 默认构造函数改为使用固定 seed。
- 新增 `EventDeckService(int seed)`。
- 新增 `CreateSeed(string source)`，用于从房间或对局标识生成稳定 seed。

### `AuthoritativeCommandDispatcher`

- 新增初始状态同步门禁。
- Host 可通过 `CreateInitialStateSynchronization()` 生成初始同步 DTO。
- Client 通过 `ApplyInitialStateSynchronization(...)` 替换为 Host 权威状态。
- `ApplyConfirmedCommand(...)` 在未完成初始同步时直接拒绝。
- 原有确认命令序号顺序校验继续保留。

### `UnityNetcodeCommandTransport`

- 新增初始状态消息：
  - `YC.GameState.Initial`
  - `YC.GameState.Initial.Request`
- Client 初始化后向 Host 请求初始状态。
- Host 在 Client 连接或请求时发送当前 `InitialGameStateDto`。
- Client 收到初始状态后再允许提交命令和应用确认命令。

### `MobileCityInteractionController`

- 多人/本地会话构建时都使用明确 seed 初始化 `EventDeckService`。
- `GameState.EventDeckSeed` 与实际初始化 seed 保持一致。
- Client 收到初始状态同步后刷新 UI 状态。

## 测试补充

扩展 `NetworkCommandDispatcherTests`：

- `EventDeckService_WithSameSeed_InitializesSameDeckOrder`
- `ApplyConfirmedCommand_WhenInitialStateIsNotSynchronized_RejectsWithoutSubmitting`
- `ApplyInitialStateSynchronization_ThenConfirmedEntranceDraw_UsesHostDeckState`

这些测试覆盖：

- 同 seed 初始化牌堆顺序一致。
- 未同步初始状态时不允许重放确认命令。
- Client 本地不同牌堆不会被误用，应用 Host 初始状态后，入场抽牌结果与 Host 一致。

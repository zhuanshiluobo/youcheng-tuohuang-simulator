# 程序模块设计

本文根据 `../规则总结.md` 将规则拆成可实现、可测试、可并行开发的程序模块。目标是支撑基础版 3 到 4 人热座 MVP，同时给企业扩展、二人变体、AI、联网和正式 UI 留出边界。

## 1. 模块总览

推荐继续沿用当前工程分层：

```text
Assets/YC/
  Domain/          纯规则、纯状态、纯查询，不依赖 UnityEngine
  Application/     GameSession、命令分发、流程编排
  Infrastructure/  数据加载、存档、回放、随机种子
  Presentation/    Unity UI、地图显示、输入适配
  Data/            地图、卡牌、效果、图标、图片引用
  Tests/EditMode/  规则和流程测试
```

核心设计原则：

- 所有玩家操作都通过 `GameCommand` 提交。
- 所有规则修改都由 handler/resolver 修改 `GameState`。
- `Presentation` 只展示状态并提交命令，不写规则。
- 地图图片只用于显示；规则必须使用结构化地图数据。
- 每个规则模块都要能独立做成功测试和失败测试。

## 2. 状态模块 State Module

职责：

- 保存一局游戏的完整可序列化状态。
- 支撑存档、回放、测试断言和 UI 刷新。
- 不负责规则判断，只提供数据结构。

建议目录：

```text
Assets/YC/Domain/State
```

关键类型：

- `GameState`：全局状态、阶段、回合、当前玩家、地图、牌堆、日志、待选择项。
- `PlayerState`：资源、分数、城市位置、手牌、弃牌、盖放角色牌、城市面板、样式标记。
- `MapRuntimeState`：已开放资源点、影响力、资源点指示物、公路、特殊标记。
- `DeckRuntimeState`：事件牌堆、设施牌堆、设施供应区、城市样式供应区。
- `PendingChoiceState`：事件选项、角色牌选项、企业特效等需要玩家继续选择的上下文。

建议补充字段：

- `PlayerState.InfluenceSupply` 当前默认 20，应改为规则要求的 30，或拆分为 `TotalMarkers` 与 `AvailableMarkers`。
- `PlayerState.CoveredCharacterCardId` 基础版每回合只盖 1 张，可先用单值；扩展或特殊效果再扩展列表。
- `PlayerState.ActedMainActionThisTurn`、`UsedCharacterThisRound`、`UsedSpecialActionIdsThisRound` 用于行动轮限制。
- `MapRuntimeState.RoadRouteIds` 保存公路覆盖的航道。
- `MapRuntimeState.RemovedFromGameCardIds` 保存放回游戏盒的牌。

依赖：

- 被所有规则模块读取和修改。
- 不依赖任何 resolver。

## 3. 定义数据模块 Definition Module

职责：

- 管理静态规则数据。
- 将卡牌、地图、设施、城市样式、企业板与运行时状态分离。

建议目录：

```text
Assets/YC/Domain/Definitions
Assets/YC/Data
Assets/YC/Infrastructure/DataLoading
```

关键类型：

- `DefinitionDatabase`：统一查询入口。
- `MapDefinition`：资源点、航道、区块、玩家数适用性。
- `LocationDefinition`：资源点 id、颜色、区块、影响力槽、停靠点、是否红区。
- `RouteDefinition`：航道 id、两端资源点、区块、影响力槽。
- `CardDefinition`：基础卡牌字段。
- `CharacterCardDefinition`：策略、计谋、是否一次性、是否持续。
- `EventCardDefinition`：事件选项、资源点指示物、资源奖励。
- `FacilityCardDefinition`：费用、颜色、分数、入场效果、唯一限制。
- `CityStyleDefinition`：宣告图形、等级、奖励、特殊行动。
- `EnterpriseDefinition`：企业等级格、奖励、企业特效。

数据原则：

- 规则 id 使用英文稳定 id，例如 `facility_core_command_tower`。
- 中文名放在 `DisplayName`。
- 图像资源可保留中文文件名，但数据引用稳定 id。
- 效果先用结构化 `EffectDefinition` 表示，实在复杂的牌再绑定 C# resolver。

## 4. 命令模块 Command Module

职责：

- 定义玩家可提交的所有操作。
- 为 UI、Debug、AI、联网提供统一入口。
- 对非法操作返回明确错误，不修改状态。

建议目录：

```text
Assets/YC/Domain/Commands
Assets/YC/Application/Commands
```

现有入口：

- `GameCommand`
- `GameCommandKind`
- `CommandResult`
- `ValidationResult`
- `IGameCommandHandler`

建议拆分：

- `ICommandValidator<TCommand>`：校验命令合法性。
- `ICommandResolver<TCommand>`：结算合法命令。
- `CommandRouter`：按命令类型分发 handler。
- `CommandContext`：包含 `GameState`、定义库、随机数、事件收集器。

基础版命令清单：

- 入场：`ChooseStartPlayer`、`ChooseInitialLocation`、`ResolveEntranceEvent`。
- 回合：`CoverCharacterCard`、`EndAction`。
- 主要行动：`DeployInfluence`、`DispatchInfluence`、`ExploreLocation`、`MoveCity`、`BuildFacility`、`UseSpecialAction`。
- 快速行动：`UseCharacterCard`、`DeclareCityStyle`。
- 采集：`CollectResource`。
- 通用：`ResolvePendingChoice`。

## 5. 回合模块 Round Module

职责：

- 管理阶段推进、行动顺序、当前玩家、当前行动轮。
- 保证 8 回合固定流程。
- 处理起始玩家传递和回合内状态重置。

建议目录：

```text
Assets/YC/Domain/Rules
Assets/YC/Application/Flow
```

关键类型：

- `PhaseFlow`：阶段流转规则。
- `CommandPhasePolicy`：命令允许在哪些阶段提交。
- `TurnOrderService`：根据起始玩家计算顺时针顺序。
- `RoundAdvanceService`：推进回合、行动轮、当前玩家。
- `RoundStateResetService`：重置本回合角色牌、特殊行动和行动限制。

阶段流：

```text
Setup
-> Entrance
-> RoundStart
-> CharacterCover
-> ActionRound1
-> ActionRound2
-> ResourceCollection
-> Cleanup
-> RoundStart 或 FinalScoring
-> GameOver
```

实现要点：

- `CharacterCover` 要追踪每名玩家是否已盖放。
- `ActionRound1/2` 每名玩家必须完成 1 个主要行动后才能推进。
- 快速行动不推进当前玩家。
- `Cleanup` 完成后如果 `Round == MaxRounds`，进入 `FinalScoring`。

## 6. 地图模块 Map Module

职责：

- 提供资源点、航道、区块、相邻关系和路径查询。
- 不计算具体行动，只回答地图结构问题。

建议目录：

```text
Assets/YC/Domain/Maps
Assets/YC/Data/Maps
```

现有类型：

- `IMapQueryService`
- `MapQueryService`
- `MapPathSearchService`
- `MapDefinition`
- `StaticMapDefinitions`

建议补齐：

- `RegionDefinition`：区块 id、计分值、包含资源点和航道。
- `InfluenceSlotDefinition`：空格 id、所在资源点或航道。
- `MapOpenRuleService`：判断红色区域是否开放。
- `MapOccupancyService`：查询资源点是否有移动城市、影响力空格是否被占用。

核心查询：

- 两个资源点是否相邻。
- 航道是否被公路覆盖。
- 资源点是否已开放探索。
- 资源点是否已有资源指示物。
- 资源点是否停靠有对手移动城市。
- 某路径经过哪些航道。

## 7. 影响力模块 Influence Module

职责：

- 统一处理玩家标记在地图上的放置、移动、移除、替换。
- 保证玩家标记数量限制。
- 为部署、调度、探索、城市移动、角色牌、企业效果复用。

建议目录：

```text
Assets/YC/Domain/Influence
```

关键类型：

- `InfluenceService`
- `InfluencePlacementRule`
- `InfluenceMoveRule`
- `InfluenceRemovalService`
- `InfluenceQueryService`

核心接口：

```text
CanPlace(playerId, slotId)
Place(playerId, slotId)
CanMove(influenceId, targetSlotId)
Move(influenceId, targetSlotId)
Remove(influenceId)
Replace(targetInfluenceId, newOwnerPlayerId)
CountInRegion(playerId, regionId, includeCity)
```

放置条件：

- 目标影响力空格为空。
- 如果目标空格在资源点上，该资源点必须已有资源点指示物。
- 如果目标空格在资源点上，该资源点不能停靠其他玩家的移动城市。
- 如果目标空格在航道上，该航道不能被公路覆盖。
- 玩家供应堆必须有可用玩家标记。

实现要点：

- 替换影响力应建模为“移除旧影响力，再尝试在同一空格放置新影响力”。
- 如果移除后因移动城市等限制不能放置，新影响力不能强行落位。
- 影响力移除后玩家标记回到所有者供应堆。

## 8. 移动模块 Movement Module

职责：

- 处理移动城市行动。
- 处理调度影响力移动。
- 提供路径、邻接和移动后清除对手影响力的规则。

建议目录：

```text
Assets/YC/Domain/Movement
Assets/YC/Application/Gameplay
```

现有类型：

- `MoveCityCommandHandler`
- `MapPathSearchService`

建议拆分：

- `CityMovementService`：城市移动合法性和结算。
- `InfluenceMovementService`：调度行动的两次影响力移动。
- `MovementCleanupService`：城市移动时移除目标资源点和使用航道上的对手影响力。

城市移动条件：

- 当前阶段是玩家行动轮。
- 玩家支付 3 源石。
- 目标资源点与当前城市所在地相邻。
- 目标资源点没有其他玩家移动城市。
- 目标资源点已开放探索。

城市移动结算：

1. 支付 3 源石。
2. 移动城市到目标资源点。
3. 移除使用航道和目标资源点上的所有对手影响力。
4. 如果目标资源点未探索，触发事件牌并放置资源点指示物。
5. 在出发资源点放置 1 个自己的影响力。

注意：

- 第 4 步可能打开 `PendingChoice`，等待玩家选择事件选项。
- 第 5 步如果没有玩家标记或目标不合法，应按规则尽量执行并记录无法放置。

## 9. 路费模块 Travel Cost Module

职责：

- 计算探索和采集的路径费用。
- 处理向对手支付、向供应堆支付、公路免费和共享航道路费。

建议目录：

```text
Assets/YC/Domain/Rules
```

现有类型：

- `TravelCostService`

建议补齐：

- `TravelCostQuote`：总费用、每条航道费用、支付对象、免费原因。
- `TravelPaymentResolver`：扣除金券并给对手或供应堆。
- `HarvestRouteCostService`：采集阶段多资源点共享航道路费。

规则：

- 路径每经过一条没有自己影响力的航道，需要支付 2 金券。
- 若该航道有对手影响力，选择一名该影响力所有者支付 2 金券。
- 若无对手影响力，支付给供应堆。
- 有自己影响力的航道免费。
- 被公路覆盖的航道免费，且不需要选择收款对象。
- 采集阶段同一条航道只支付一次。
- 采集阶段不能用本阶段刚获得的金券支付路费。

## 10. 行动模块 Action Module

职责：

- 实现六类主要行动和快速行动窗口。
- 每个行动独立校验、独立结算、独立测试。

建议目录：

```text
Assets/YC/Application/Gameplay
Assets/YC/Domain/Actions
```

子模块：

- `DeployActionResolver`：部署，放置 1 个影响力。
- `DispatchActionResolver`：调度，移动 1 个影响力，最多 2 次。
- `ExploreActionResolver`：探索，支付路费、翻事件、放资源指示物、放影响力。
- `MoveCityActionResolver`：城市移动，调用移动模块。
- `BuildFacilityActionResolver`：建设，支付费用、放设施、得分、入场效果、补供应区。
- `SpecialActionResolver`：城市样式解锁的特殊行动。

行动通用校验：

- 当前阶段必须是 `ActionRound1` 或 `ActionRound2`。
- 当前玩家必须匹配命令玩家。
- 玩家本行动轮尚未执行主要行动。
- 存在 `PendingChoice` 时，除 `ResolvePendingChoice` 外不允许提交新行动。

行动结算后：

- 标记玩家本轮已执行主要行动。
- 发送 `GameEvent`。
- 检查是否推进到下一玩家、下一行动轮或采集阶段。

## 11. 事件模块 Event Module

职责：

- 管理事件牌抽取、资源点指示物放置和事件选项结算。

建议目录：

```text
Assets/YC/Domain/Cards
Assets/YC/Domain/Effects
```

关键类型：

- `EventDeckService`
- `EventResolutionService`
- `ResourceTokenService`
- `PendingChoiceFactory`

触发来源：

- 开局选择初始资源点。
- 探索资源点。
- 城市移动进入未探索资源点。

实现要点：

- 事件牌按资源点颜色从对应牌堆抽取。
- 抽到事件牌后，将对应资源点指示物放在目标资源点。
- 如果事件牌有多个选项，打开 `PendingChoice`。
- 选项结算走效果系统，不在事件模块硬编码。

## 12. 资源与经济模块 Resource Module

职责：

- 管理源岩、源石、异铁、至纯源石、金券和分数变化。
- 提供统一支付与获得接口。

建议目录：

```text
Assets/YC/Domain/Economy
```

关键类型：

- `ResourceService`
- `PaymentService`
- `ScoreService`

规则：

- 源岩、源石、异铁使用玩家资源计数器。
- 金券和至纯源石来自公共供应堆，不足可用替代物，不限制总量。
- 玩家支付资源必须从自己的供应堆扣除。
- 支付给对手和支付给供应堆要区分。
- 分数变化立刻体现在分数轨道状态中。

## 13. 建设模块 Facility Module

职责：

- 管理设施牌供应区、建设费用、城市面板位置、入场效果和唯一限制。

建议目录：

```text
Assets/YC/Domain/Facilities
Assets/YC/Application/Gameplay
```

关键类型：

- `FacilityMarketService`
- `FacilityBuildRule`
- `CityBoardService`
- `FacilityEntranceEffectResolver`

建设条件：

- 城市面板有空位。
- 目标设施在设施供应区，除非特殊效果允许从其他区域建设。
- 玩家能支付资源费用或金券费用。
- 唯一设施不能重复建设同名牌。

结算：

1. 支付费用。
2. 将设施放入城市面板空位。
3. 获得牌面分数。
4. 结算入场效果。
5. 从设施牌堆补充供应区到 6 张。

## 14. 城市样式模块 City Style Module

职责：

- 判断设施颜色与位置是否满足样式。
- 管理设施旋转占用、玩家样式标记、奖励和特殊行动次数。

建议目录：

```text
Assets/YC/Domain/CityStyles
```

关键类型：

- `CityStyleMatchService`
- `CityStyleDeclarationService`
- `CityStyleMarkerService`
- `SpecialActionAvailabilityService`

规则：

- 宣告条件可以旋转，不能翻转。
- 彩色设施可视为任意颜色。
- 每个设施只能用于一次样式宣告。
- 宣告后用于组合的设施旋转 180 度，不能再次用于宣告。
- I 级和 II 级城市样式的标记复位规则不同。
- 特殊行动每名玩家每张样式牌每回合最多使用一次。

## 15. 角色牌与效果模块 Card Effect Module

职责：

- 处理角色牌策略、计谋、设施入场、事件选项、城市样式、企业特效等效果。
- 支持条件式效果、尽量执行、待选择项和延迟到收尾阶段的效果。

建议目录：

```text
Assets/YC/Domain/Effects
Assets/YC/Domain/Cards
```

关键类型：

- `EffectDefinition`
- `EffectResolver`
- `EffectContext`
- `EffectStep`
- `DelayedEffectState`
- `ConditionEvaluator`
- `TargetSelector`

效果执行原则：

- 多步骤效果按定义顺序执行。
- 某一步无法执行时，非条件式效果继续尽量执行后续步骤。
- 条件式效果必须先完整满足条件，才能执行结果部分。
- 需要玩家选择时，写入 `PendingChoice` 并暂停效果链。
- 收尾阶段效果保存为 `DelayedEffectState`。

角色牌规则：

- 玩家只能使用本回合盖放的角色牌。
- 起始玩家可连续使用策略和计谋，顺序自定，也可只用一个。
- 非起始玩家只能选择策略或计谋之一。
- 使用后通常进入弃牌区。
- 未使用的盖放角色牌在收尾阶段与弃牌区一起回手。

## 16. 采集模块 Harvest Module

职责：

- 处理采集阶段的资源点选择、共享路费、资源获得。

建议目录：

```text
Assets/YC/Domain/Harvest
Assets/YC/Application/Gameplay
```

关键类型：

- `HarvestSelectionValidator`
- `HarvestRoutePlanner`
- `HarvestCostResolver`
- `HarvestResourceResolver`

规则：

- 玩家可选择任意数量的资源点。
- 被选资源点必须有自己的影响力，或停靠自己的移动城市。
- 每个资源点每次采集只能获得一次资源。
- 多个资源点共用的航道只支付一次路费。
- 不能用本采集阶段刚获得的金券支付路费。
- 无法支付到某资源点的路费时，不能采集该资源点。

建议实现：

- 先生成玩家选择的资源点集合。
- 计算连接移动城市到这些资源点所需航道集合。
- 生成路费报价并执行支付。
- 支付成功后发放资源。

## 17. 计分模块 Scoring Module

职责：

- 处理最终计分、区控、剩余资源分和平局。

建议目录：

```text
Assets/YC/Domain/Scoring
```

关键类型：

- `RegionControlService`
- `FinalScoringService`
- `TieBreakerService`
- `ScoreBreakdown`

规则：

- 区块内影响力最多的玩家控制该区块。
- 移动城市在所在区块视为 2 个额外影响力。
- 并列最高时无人获得该区块分数。
- A、B、C、D、G、R 区 3 分；E、F 区 4 分。
- 剩余资源分：1 至纯源石 = 1 分，6 异铁 = 1 分，8 源石 = 1 分，9 源岩 = 1 分。
- 平局先比剩余金券，再比剩余至纯源石，仍相同则共同胜利。

输出：

- 每名玩家的 `ScoreBreakdown`。
- 每个区块的控制者、影响力明细和得分。
- 平局比较过程。

## 18. 扩展模块 Expansion Module

职责：

- 隔离企业扩展、二人变体、公路、干员牌等非 MVP 规则。
- 防止基础版规则被扩展逻辑污染。

建议目录：

```text
Assets/YC/Domain/Expansions
```

子模块：

- `EnterpriseModule`：企业合作等级、企业奖励、企业特效。
- `RoadModule`：公路覆盖航道、免费路费、禁止影响力落位。
- `OperatorCardModule`：干员牌、一次性、持续性、放回游戏盒。
- `TwoPlayerVariantModule`：初始企业、初始资金、设施移除、红区开放回合。

接入方式：

- `GameRuleset` 标识基础版、企业扩展、二人变体。
- 各模块注册自己的命令校验、效果 resolver、阶段钩子。
- 基础版测试默认不加载扩展模块。

## 24. 模块依赖关系

```text
Presentation
  -> Application GameSession
    -> Command Handlers
      -> Action / Round / Harvest / Scoring Resolvers
        -> State
        -> Definitions
        -> Map
        -> Influence
        -> TravelCost
        -> Effects

Infrastructure
  -> State serialization
  -> Definition loading
  -> Replay
```

禁止依赖：

- `Domain` 依赖 `Presentation`。
- `Domain` 依赖 Unity 场景对象。
- `Presentation` 直接改 `GameState`。
- 单个行动 handler 内硬编码所有卡牌效果。

# 联网牌堆同步与 Host 快照说明

## 背景

此前 `EventDeckService` 默认使用 `new Random()` 初始化事件牌堆。早期联网方案中，Host 只广播已接受命令，Client 收到后在本地 `GameSession.Submit(GameCommand)` 重放。涉及入场事件或探索抽牌的命令会读取本地 `DeckRuntimeState`，如果各端牌堆顺序不同，Host 与 Client 会抽到不同事件牌，进而产生资源指示物、待选择项和奖励状态分叉。

2026-06-16 之后，联网同步已从“确认命令后本地重放”调整为“Host 确认命令携带完整 `GameState` 快照，Client 按序替换为 Host 快照”。因此本文不再描述 Client 重放确认命令的当前实现，只保留牌堆 seed 和初始状态同步的作用。

## 采用方案

当前采用保守的 Host 权威快照方案：

- 确定性 seed：`EventDeckService` 默认改为固定 seed，并支持显式传入 seed。多人模式下 `MobileCityInteractionController` 根据 `GameLaunchContext.RoomId` 生成对局 seed，写入 `GameState.EventDeckSeed`，用于初始化事件牌堆。
- 权威初始状态同步：新增 `InitialGameStateDto`，Host 可下发当前 `GameState` 与下一条确认命令序号。Client 在应用确认命令前必须先完成初始状态同步。
- 权威确认快照：`ConfirmedGameCommandDto` 携带 Host 成功结算后的 `GameState State`。Client 校验确认序号后通过 `session.ReplaceState(confirmed.State)` 替换本地状态。
- 命令入口不变：Client 只提交 `GameCommandDto` 意图；Host 还原命令并调用 `GameSession.Submit(GameCommand)`。Client 不再对 Host 确认命令本地重放。

该方案优先保证当前 Host/Client 状态一致，不引入完整断线重连、状态版本校验、增量同步或快照补发系统。

## 命令确认流程

Host 流程：

1. Host 初始化权威 `GameState`，包含 `DeckRuntimeState` 与 `EventDeckSeed`。
2. Host 初始化 `AuthoritativeCommandDispatcher`。
3. Client 连接或定时请求初始状态时，Host 通过 `MirrorCommandTransport` 下发 `InitialGameStateDto`。
4. Host 从 FizzySteamworks 取得真实远端 SteamID，按 Lobby 席位校验 `SteamID -> Mirror connectionId -> PlayerId`，再调用 `GameSession.Submit(GameCommand)`；客户端自报的 `PlayerId` 不能改变身份绑定。
5. Host 只广播提交成功的确认命令，并附带递增序号和当前完整 `GameState` 快照。

Client 流程：

1. Client 启动后向 Host 请求初始状态。
2. Client 收到 `InitialGameStateDto` 后，用 Host 的 `GameState` 替换本地初始状态，并设置下一条期望确认命令序号。
3. Client 在初始状态未同步前拒绝发送本地命令，也拒绝应用 Host 确认命令。
4. Client 收到确认命令后继续做顺序校验。
5. 确认 DTO 必须包含非空 `State` 快照；缺失快照时拒绝应用。
6. Client 调用 `session.ReplaceState(confirmed.State)` 替换为 Host 权威状态，不再调用本地 `GameSession.Submit(GameCommand)` 重放。

## 抽牌一致性约束

- Client 不再依赖各自 `new Random()` 产生的独立牌堆顺序。
- 入场事件、探索事件等抽牌命令必须基于 Host 同步过来的初始 `DeckRuntimeState`。
- 对局 seed 作为最小确定性来源保留在 `GameState.EventDeckSeed`，用于 Host 初始化牌堆，也为后续断线重连、重放或快照校验保留可复用信息。
- Client 的牌堆状态以 Host 初始状态和确认快照为准，不依赖本地随机或本地重放结果。

## 测试覆盖

新增或扩展 `NetworkCommandDispatcherTests`：

- 同一 seed 初始化的 Host/Client 事件牌堆顺序一致。
- Client 未同步初始状态前，拒绝应用确认命令。
- Host 接受命令后确认 DTO 携带 Host 状态快照。
- Client 本地没有注册对应 handler 时，也能通过 Host 快照替换状态。
- 缺少 `State` 的确认消息会被拒绝。
- 原有确认命令序号跳号拒绝逻辑继续保留。

2026-07-12 的 Mirror/Steam 迁移已通过项目标准 EditMode 入口验证；Steam P2P 端到端仍必须由两个不同 Steam 账号和两个独立运行环境人工验证。

## 未完成能力

- 尚未实现断线重连。
- 尚未实现状态版本号、checksum 或增量同步。
- 尚未实现确认命令缓冲与缺口补发。
- Host 校验失败原因通过 `RejectedCommandMessage` 只回传给发起 Client；尚未实现断线后的对局恢复。
- 当前每条确认发送完整 `GameState`，是 MVP 级快照同步，不等同于完整在线对局快照系统。

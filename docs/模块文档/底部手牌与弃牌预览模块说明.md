# 底部手牌与弃牌预览模块说明

## 1. 模块定位

`CharacterHandPanel` 是对局 HUD 中独立的角色手牌入口，负责本机玩家的手牌排列、卡牌查看、本地排序、角色牌盖放拖动，以及手牌/弃牌双区预览。角色牌不再依赖信息面板创建或展开，资源统计与玩家宣告等其他信息模块不属于本模块职责。

领域状态和规则仍以 `GameState`、角色牌命令处理器及 `CharacterCardPanelPresenter` 为准。`CharacterHandPanel` 只消费展示模型、维护本机交互状态并调用既有命令/查看器入口，不新增排序命令，也不修改存档或联机协议。

## 2. 主要组成

- `CharacterCardPanelPresenter`：从权威 `GameState` 构建手牌、弃牌、盖放权限、已盖放牌和状态文案等展示模型。
- `CharacterHandPanel`：模块控制器，负责渲染、悬停、拖动排序、弃牌模态窗口和关闭优先级。
- `CharacterHandPanelView`：固定 Prefab 引用集合，不在运行时搜索或补建 UI。
- `CharacterHandCardView`：单张卡牌模板引用和配置校验。
- `CharacterHandLayoutProfile`：手牌尺寸、扇形角度、间距、透明度、悬停倍率、模态网格和弃牌按钮位置的显式布局资产。
- `CardPointerInteraction`：统一转发进入、离开、点击与拖动事件，并在拖动结束后抑制误点击。
- `ZoomableImageViewerController`：继续承载手牌、弃牌和已盖放角色牌的大图查看。
- `CharacterCardCoverDragCoordinator`：继续承载拖到主要行动面板后的既有盖放确认流程。

运行时主链路为：

```text
GameState
  -> CharacterCardPanelPresenter.BuildView
  -> MobileCityInteractionController 刷新编排
  -> CharacterHandPanel.Render
  -> 底部手牌 / 弃牌角标 / 弃牌模态窗口
```

## 3. 手牌状态与布局

布局以 `1920×1080` 为参考分辨率，卡牌基础尺寸为 `180×255`。稳定状态如下：

| 状态 | 排列与可见性 | 交互 |
|---|---|---|
| 普通阶段 | 底部扇形，间距约 `112`，最大角度 `±14°`，透明度 `0.38`，恰好露出卡高的 `30%` | 可悬停、查看和本地排序，不可提交盖放 |
| 悬停 | 当前牌移到最上层、完整上提、缩放到 `1.18`、透明度提高到 `0.82` | 移出后立即恢复当前阶段布局 |
| 本机可盖放 | 全卡展开、全不透明，间距约 `145`，最大角度 `±6°` | 可排序、查看，并可拖到主要行动面板进入盖放确认 |
| 盖放完成或轮到其他玩家 | 立即回到普通扇形 | 不保留展开状态 |

单击卡牌只打开既有大图查看器。拖动是否构成点击由 `CardPointerInteraction` 统一判定，避免重排或盖放拖动结束时误开大图。

## 4. 本地排序契约

- 排序表按 `playerId` 隔离，只存在于当前客户端、当前对局的 `CharacterHandPanel` 实例中。
- 排序表保留已经见过的全部角色卡 ID；卡牌进入弃牌堆后不从偏好顺序中移除，之后回到手牌时恢复原相对位置。
- 新出现且未记录的卡牌追加到末尾。
- 手牌区域内拖动时预览插入位置，只有有效落点才更新本地偏好顺序。
- 非法落点、取消盖放或拖到盖放区域时先恢复拖动前顺序；盖放只由既有确认流程提交。
- UI 排序不得写回 `GameState.HandCardIds`，不得生成网络命令，也不得进入存档。

热座模式切换本机玩家时复用对应 `playerId` 的本地顺序；退出对局并销毁面板后顺序自然回收。

## 5. 弃牌按钮与模态窗口

弃牌按钮位于主要行动面板左下缘外侧，参考尺寸为 `68×68`，右上角角标始终显示当前弃牌数量，包括 `0`。打开后使用全屏遮罩阻断地图、桌面导航和行动面板输入。

模态内容固定为左侧手牌、右侧弃牌：

- 两侧均使用可滚动三列网格，单卡约 `176×249`。
- 手牌保持原色，并沿用本机偏好顺序。
- 弃牌使用 `UiGrayscale` 专用 UGUI 材质并以约 `0.65` 透明度显示；弃牌只读，不参与排序或盖放。
- 两侧卡牌均可单击打开大图。
- 弃牌为空时窗口仍可打开，右区显示“暂无弃牌”。
- 窗口支持右上角关闭按钮、`Esc` 和遮罩内右键关闭；每次打开都会重置关闭输入状态。

全局关闭优先级固定为：

```text
卡牌大图 -> 弃牌模态窗口 -> 其他对局交互 -> 设置菜单
```

`MobileCityInteractionController` 负责把 `WindowCloseInputHandler` 的既有关闭路由接到本模块，关闭操作不得提交命令或改变手牌排序。

## 6. 空手盖放与状态刷新

当本机进入角色牌盖放阶段且真实手牌为空时，`CharacterCardPanelPresenter` 将弃牌堆投影为可盖放手牌，并让弃牌按钮角标显示 `0`。这只是展示模型投影：

- `GameState` 在预览期间保持不变。
- 实际弃牌回收和盖放仍由现有角色牌命令原子完成。
- 命令失败或收到新的权威快照时，面板直接按最新展示模型恢复。

已使用角色牌进入弃牌、锡人收回弃牌、未使用牌在收尾阶段返回等规则结果，均通过同一次权威状态刷新直接更新手牌、弃牌和角标，不制作跨区域移动动画。

## 7. Prefab、材质与构建门禁

主要资产：

- `Assets/YC/Presentation/Prefabs/Gameplay/CharacterHandPanel.prefab`
- `Assets/YC/Presentation/Content/CharacterHandLayoutProfile.asset`
- `Assets/YC/Presentation/Shaders/UiGrayscale.shader`
- `Assets/YC/Presentation/Materials/UiGrayscale.mat`

`GameplayInteractionHudView` 持有序列化的 `CharacterHandPanel` 引用并参与完整性校验。`CharacterHandPanelEditorAssetBuilder` 生成独立预制体，`GameplayInteractionHudEditorAssetBuilder` 将其嵌套到现有 HUD；场景不增加新的根节点。

次级布局 manifest、资产构建器与 `SecondaryLayoutBuildReadiness` 同时锁定布局 Profile、Prefab 引用、灰度材质和场景无覆盖约束。运行时若固定引用缺失，应让配置校验失败，不允许回退到动态创建或场景搜索。

## 8. 回归要求

修改本模块时至少保持以下覆盖：

- Prefab、模板、Profile、灰度材质、HUD 嵌套关系和 Missing Script 校验。
- 普通扇形 `30%` 露出、悬停突出、盖放展开及回合切换收起。
- 玩家隔离排序、弃牌后返回顺序、非法落点还原和权威手牌不变。
- 拖到主要行动面板复用既有确认流程，拖动后不触发点击。
- 弃牌模态遮罩、只读灰度展示、双方卡牌查看与空态。
- 大图、弃牌窗口、其他交互、设置菜单的关闭优先级。
- 空手盖放时弃牌投影、角标为 `0`，以及盖放后与领域状态一致。

# 地图表现锚点与移动适配设计

## 1. 目标

本设计把四人地图中散落在 C# 代码里的地块、资源标记、地块影响力槽和航道影响力槽坐标，迁移为与地图 Sprite 绑定的表现资产，并为后续地图平移、缩放或旋转提供统一坐标空间。

规则层仍只维护稳定 id、地块拓扑和航道拓扑。表现坐标不参与移动、寻路、路费、区控或影响力合法性判断。

## 2. 当前落点

```text
MapDisplayLayout（表现资产）
  ├─ MapId
  ├─ MapSprite
  ├─ Locations
  │   ├─ 地块锚点
  │   ├─ 资源标记相对偏移
  │   └─ 地块影响力槽相对偏移
  └─ Routes
      ├─ 航道锚点
      └─ 航道影响力槽相对偏移

MapCoordinateSpace（场景绑定）
  ├─ mapRenderer
  ├─ layout
  └─ Map Content（运行时地图内容根节点）
```

相关文件：

- `Assets/Resources/MapLayouts/map-four-players.asset`
- `Assets/YC/Presentation/Maps/MapDisplayLayout.cs`
- `Assets/YC/Presentation/Maps/MapCoordinateSpace.cs`
- `Assets/Scenes/SampleScene.unity`

## 3. 数据约束

### 3.1 地块

每个地块只保存一份 `NormalizedPosition`，作为热点和移动城市的锚点。

资源标记与两个地块影响力槽不再各自保存地图绝对坐标，而是保存相对地块锚点的偏移：

```text
资源标记位置 = 地块锚点 + ResourceTokenOffset
影响力槽位置 = 地块锚点 + InfluenceSlot.Offset
```

调整一个地块锚点时，热点、移动城市、资源标记和地块影响力槽会整体移动，避免只改到其中一部分。

### 3.2 航道

每条航道保存一个表现锚点，航道影响力槽保存相对该锚点的偏移。双槽航道因此可以作为一组整体调整。

航道表现资产不保存连接节点或线段数据。航道连接关系只由规则层 `CoveredLocationIds` 维护；表现层只按 `RouteId` 关联航道影响力槽。

## 4. 坐标空间

布局资产继续使用左上角 `(0, 0)`、右下角 `(1, 1)` 的归一化坐标，便于直接依据底图校准。

运行时不再用 `SpriteRenderer.bounds` 的世界轴对齐包围盒计算位置，而是：

1. 根据 `Sprite.bounds` 在 Sprite 局部空间内求点；
2. 使用 `mapRenderer.transform.TransformPoint()` 转成世界坐标；
3. 反向点击换算使用 `InverseTransformPoint()`；
4. 所有热点、城市、资源与槽位统一挂在 `Map Content` 下。

这能避免地图旋转、非等比缩放或地图 Sprite 与控制器拆成不同节点后产生的错位。`flipX`、`flipY` 也在统一换算中处理。

## 5. 后续地图移动模块的接入边界

地图移动模块只应修改承载 `MapCoordinateSpace`/`mapRenderer` 的地图 Transform，或修改相机；不要逐个修改热点、城市和槽位。

推荐职责：

```text
MapPanZoomController
  ├─ 将屏幕拖拽量换算到地图所在平面
  ├─ 修改地图 Transform 或相机
  ├─ 限制平移边界和缩放范围
  └─ 不读取规则地图，不重建表现坐标
```

如果采用“移动地图 Transform”方案，`Map Content` 会自动携带全部地图内容。如果采用“移动相机”方案，布局数据同样无需改动。

## 6. 新地图录入流程

1. 创建 `MapDisplayLayout` 资产，资产名使用规则 `MapId`。
2. 绑定对应地图 Sprite。
3. 录入全部地块锚点。
4. 为每个地块录入资源标记与影响力槽相对偏移。
5. 为全部航道录入航道锚点与槽位相对偏移。
6. 在地图场景对象上配置 `MapCoordinateSpace` 的 `mapRenderer` 与 `layout`。
7. 运行 `MapDisplayLayoutValidator` 和 EditMode 测试。

构建前检查会验证：

- 布局资产已绑定 Sprite；
- `MapId` 与规则地图一致；
- 地块和航道 id 完整且无重复；
- 影响力槽数量与规则一致；
- 最终归一化坐标均在 `[0, 1]` 内；
- 表现定义引用的航道 id 均存在于规则地图中。

## 7. 不在本模块处理的内容

- 不把表现坐标写入 `YC.Domain`。
- 不根据画面距离推断地图相邻关系。
- 不改变航道费用、移动路径或影响力规则。
- 不在地图移动时重新生成所有表现对象。
- 分数轨道属于独立的地图边缘布局，本轮不迁移。

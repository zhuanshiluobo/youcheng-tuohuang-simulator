# 多人房间与联机入口方案

## 当前方案（2026-07-13）

当前联网主链路为 `Steamworks.NET + Steam Matchmaking Lobby + Mirror + FizzySteamworks`，固定使用开发测试 AppID `480`，只面向本地开发和朋友联机测试，不包含 Steamworks 后台、Depot、上架或专用服务器。

实际创建、加入、构建与排障步骤见 `docs/指南/联机手册.md`。

```text
StartMenuController
-> SteamRoomService（Steam Lobby、邀请、席位元数据）
-> MirrorNetworkRuntime（NetworkManager + FizzySteamworks）
-> SteamNetworkingSockets / Steam Relay
-> MirrorCommandTransport
-> AuthoritativeCommandDispatcher
-> GameSession / Domain
```

当前边界：

- `SteamBootstrap` 负责 `SteamAPI.Init/RunCallbacks/Shutdown`，回调只在初始化成功后注册。
- `SteamRoomService` 创建或加入 3/4 人 Lobby，以十进制 Lobby ID 作为房间号，并写入 `gameKey=yc_nomad_city`、`protocolVersion=2`、`roomStatus`、`playerCount`、`hostSteamId`、`seat.1..4` 和 Host 权威就绪 metadata。
- AppID 480 是共享环境，加入时必须校验上述命名空间、协议、人数、等待状态和房主 SteamID。
- 房主固定 `PlayerId=1`；房主把 Lobby 中的真实 SteamID 稳定分配到席位，不能使用成员枚举顺序。
- `MirrorNetworkRuntime` 禁止自动创建 Network Player；本项目不把 Domain 状态改造成 `NetworkBehaviour/SyncVar`。
- `PlayerSeat` 显式区分 Lobby 成员存在、Mirror 传输连接、连接身份验证和游戏初始状态同步；开局只要求前三项，第四项在进入游戏场景并应用初始快照后完成。
- `SteamRoomService` 只接受 Mirror Server 连接事件提供的地址，解析 FizzySteamworks 返回的远端 SteamID，并校验它属于当前 Lobby、对应稳定席位且没有第二条连接。Client 只读取 Host 发布的就绪 metadata。
- `MirrorCommandTransport` 以 FizzySteamworks 提供的真实远端 SteamID 绑定 `Mirror connectionId -> PlayerId`，非 Lobby 成员、未绑定连接和冒用 PlayerId 的命令均被拒绝。
- Client 连接后持续请求初始快照，收到后才能提交命令；确认序号断档时重新请求快照。
- Host 只向远端 Client 广播确认快照，不把已本地应用的确认消息再发给 Host 本地连接。
- 只有原始房主、等待状态、全部目标席位存在且都有唯一存活的已验证 Mirror 连接时才能开始；房主开始后 Lobby 不可加入。第一版不迁移房主，房主断线时 Client 返回 `StartScene`。
- 根目录 `steam_appid.txt` 内容为 `480`；Windows 本地构建完成后由 `SteamAppIdBuildPostprocessor` 复制到可执行文件旁。

依赖锁定在 `Packages/manifest.json`：Mirror `96.6.4`、FizzySteamworks `6.0.1`、Steamworks.NET `2025.163.0`。Fizzy 包不内置 Steamworks.NET，因此工程只保留一份独立 Steamworks.NET 包和原生库。

旧 `UnityOfficialRoomService`、`UnityNetcodeCommandTransport` 以及 Unity Authentication/Lobby/Relay/NGO/Unity Transport 包已经从主线移除；`NetworkRoomService` 不进入正式 Steam 路径，只作为下述本地测试模式的房间协调服务。

## Mirror 本地测试模式

为了在没有多个 Steam 账号时验证当前 Mirror 命令同步链路，开发环境提供显式本地测试模式。该模式不会恢复 UGS/NGO，也不会修改正式 Steam 路径：

```text
StartMenuController
-> OnlineRoomServiceProvider
-> LocalMirrorRoomService
-> NetworkRoomService（仅负责本地房间和席位协调，端口 7780-7799）
-> MirrorNetworkRuntime + TelepathyTransport（端口 7777）
-> MirrorCommandTransport + Host 信令凭据身份握手
-> AuthoritativeCommandDispatcher
```

使用步骤：

1. 停止 Play Mode，在 Unity 菜单选择 `YC/联机测试/启用 Mirror 本地测试模式`。
2. Editor 进入 Play Mode，创建 3 人或 4 人房间，复制界面显示的 `IP:端口` 房间号。
3. 用 Development Build 启动其余实例，并添加参数：`--yc-local-multiplayer-test --yc-local-player-name=Client2`。
4. Client 在“加入房间”中粘贴房间号；所有席位加入后由 Editor 房主开始。
5. 关闭菜单勾选或不给 Development Build 传参数时，入口仍使用 Steam Lobby + FizzySteamworks。

本地模式边界：

- `LocalMirrorIdentity` 为玩家 1-4 生成稳定且互不重复的模拟身份，只用于开发环境。
- TCP 房间信令为每条已分配席位的 Client 连接签发随机凭据；Client 经 Mirror 呈递凭据，Host 解析为稳定席位后才绑定 `connectionId -> 模拟身份 -> PlayerId`。Client 不能用裸 `PlayerId` 声明自己或其他席位就绪。
- 本地模式与 Steam 模式复用同一开局门禁：所有目标席位都必须达到传输连接与身份验证；断线立即清除，重连恢复原稳定席位。
- 本地模式覆盖 Mirror Host/Client、命令权威、快照、序号重同步、断线和返回菜单，不代表 Steam Lobby、真实 SteamID、Steam P2P/Relay 已通过验收。
- 同机测试需允许 TCP `7777` 与房间协调端口 `7780-7799`；一次只运行一个房主。

# 航道位置配置与显示模块文档

本文档描述“航道影响力槽位位置配置与 Unity 显示”的实现范围。该模块只负责把现有地图规则中的航道影响力槽位显示到 Unity 地图上，不修改探索、采集、移动、路费、区控、影响力放置等规则机制。

## 1. 模块定位

航道位置配置与显示模块属于表现层能力，服务于以下目标：

1. 为每条规则航道的影响力槽位配置在地图图片上的显示坐标。
2. 在 Unity 中按配置显示航道影响力空槽和已放置影响力。
3. 支持运行时根据 `GameState.Map.Influences` 刷新槽位占用状态，但不在表现层计算规则。

当前项目中，规则地图数据位于 `Assets/YC/Domain/Maps`：

- `GameMapDefinition`
- `MapLocationDefinition`
- `MapRouteDefinition`
- `MapRegionDefinition`
- `StaticMapDefinitions`
- `MapQueryService`

Unity 表现层目前主要在 `Assets/YC/Presentation`：

- `MapDisplayController`：负责地图 Sprite 与相机适配。
- `MobileCityInteractionController`：已有地块归一化坐标、热点、移动城市和地块/资源点影响力槽位的临时显示逻辑。

本模块应延续上述分层：规则数据留在 `Domain`，槽位显示坐标和刷新逻辑留在 `Presentation` 或 `Data/Presentation`。

## 当前实现状态

截至 2026-06-15，当前实现以“航道影响力槽位显示”为准：

- 四人地图 22 条航道的槽位坐标保存在 `FourPlayerRouteDisplayDefinitions`。
- 当前只显示航道影响力槽位。
- 航道影响力槽位由 `MobileCityInteractionController.BuildInfluenceSlotViews()` 读取显示配置生成。
- `RefreshInfluenceDisplay()` 会刷新资源点和航道影响力槽位；空槽为空心圆，占用后显示为对应玩家颜色的实心方块。

## 2. 范围边界

本模块只做：

- 航道影响力槽位坐标配置。
- 航道影响力空槽显示。
- 根据已有运行时状态刷新航道槽位占用状态。
- 为航道影响力槽位显示预留刷新入口。

本模块不做：

- 不绘制航道本体或路径本体。
- 不实现航道颜色、高亮、选中、禁用、公路覆盖等航道本体表现状态。
- 不改变 `StaticMapDefinitions.CreateFourPlayerMap()` 中的航道规则。
- 不改变 `MapQueryService` 的邻接、寻路、区块查询逻辑。
- 不实现或修改探索、采集、城市移动、路费支付、区控计分等规则。
- 不新增自动探索、采集优化、路线推荐等额外机制。

## 3. 规则数据与表现数据

必须明确区分规则数据和表现数据。表现数据可以引用规则 id，但不能成为规则判断依据。

| 类型 | 字段 | 归属 | 用途 |
|---|---|---|---|
| 规则数据 | `routeId` | `MapRouteDefinition` | 航道稳定规则 id，用于查询、命令、影响力槽位和表现关联 |
| 规则数据 | 连接的地块 | `FromLocationId`、`ToLocationId`、`CoveredLocationIds` | 判断相邻关系、路线/路径、移动和路费 |
| 规则数据 | 所属区块 | `RegionId` | 区控计分、影响力归属统计 |
| 规则数据 | 影响力槽数量 | `InfluenceSlotCount` | 规则允许的航道槽位数量 |
| 表现数据 | 影响力槽位归一化坐标 | 新增显示配置 | 把航道影响力槽位映射到 Unity 世界坐标 |
| 表现数据 | 槽位显示状态 | 表现层读取 `GameState.Map.Influences` | 控制空槽或玩家颜色，不参与规则结算 |

规则层可以回答“航道 A1 连接哪些地块、属于哪个区块、有几个影响力槽位”。表现层回答“航道 A1 的影响力槽位画在哪里、当前槽位是否被玩家占用”。

## 4. 地图优先级

MVP 优先完成四人地图。

原因：

- `StaticMapDefinitions.CreateFourPlayerMap()` 已有完整四人地图数据：22 个地块、22 条航道、8 个区块。
- `FourPlayerMapDefinitionTests` 已覆盖四人地图的航道数量、连接关系、槽位数量和可达性。
- `MobileCityInteractionController.BuildLocationViews()` 已有四人地图地块归一化坐标，可复用坐标采集方式。

三人地图后续补齐：

- 当前 `CreateThreePlayerPlaceholder()` 仍是占位测试数据，不应先为其投入完整表现配置。
- 三人地图的规则航道录入稳定后，再追加 `map-three-players` 对应的航道槽位显示配置。
- 显示配置结构需要支持多地图，但 MVP 数据只要求四人地图完整。

## 5. 显示配置结构建议

建议新增纯表现层配置类型，不放入 `YC.Domain`。

推荐目录：

```text
Assets/YC/Presentation/Maps
```

或如果后续会做 ScriptableObject 资产：

```text
Assets/YC/Data/MapDisplay
Assets/YC/Presentation/Maps
```

建议数据结构：

```csharp
[Serializable]
public sealed class MapRouteDisplayDefinition
{
    public string MapId = string.Empty;
    public string RouteId = string.Empty;
    public List<Vector2> InfluenceSlotPositions = new List<Vector2>();
}
```

字段说明：

- `MapId`：对应规则地图 id，例如 `map-four-players`。
- `RouteId`：对应 `MapRouteDefinition.RouteId`，例如 `A1`、`R7`。
- `InfluenceSlotPositions`：该航道影响力槽位在地图图片上的归一化坐标，数量应等于规则航道的 `InfluenceSlotCount`。

如果 MVP 希望更轻量，也可以先用静态 C# 配置类：

```csharp
public static class FourPlayerRouteDisplayDefinitions
{
    public static IReadOnlyList<MapRouteDisplayDefinition> Create()
    {
        return new[]
        {
            Route("A1", Slot(0.816f, 0.358f)),
            Route("A2", Slot(0.697f, 0.587f), Slot(0.717f, 0.587f)),
        };
    }
}
```

但最终更适合迁移到 ScriptableObject 或 JSON 资产，方便策划和美术按地图图片微调坐标。

## 6. 如何给每条航道槽位配置坐标

坐标使用地图归一化坐标：

- 左上角为 `(0, 0)`。
- 右下角为 `(1, 1)`。
- `x` 从左到右递增。
- `y` 从上到下递增。

该坐标系与 `MobileCityInteractionController.ToWorldPosition()` 当前逻辑一致：

```csharp
world.x = bounds.min.x + bounds.size.x * normalized.x;
world.y = bounds.max.y - bounds.size.y * normalized.y;
```

配置步骤：

1. 打开四人地图场景，确认地图 Sprite 已挂在 `mapRenderer`。
2. 在 `MobileCityInteractionController` 中启用 `debugClicks`。
3. 按住 Shift 点击地图上的航道影响力槽位位置。
4. 从 Console 记录 `normalized=(x, y)`。
5. 为每条航道写入 `InfluenceSlotPositions`：
   - 数量必须等于 `MapRouteDefinition.InfluenceSlotCount`。
   - 槽位坐标应放在航道图案附近，不遮挡地块热点、移动城市、资源点指示物。
6. 运行校验，确保每条四人地图规则航道都有一条槽位显示配置。

建议先以四人地图 22 条航道为完整清单逐条配置：

```text
A1, A2,
B1, B2,
C1, C2,
D1, D2,
E1, E2,
F1, F2, F3,
G1, G2,
R1, R2, R3, R4, R5, R6, R7
```

配置注意事项：

- `RouteId` 必须与规则数据完全一致，不允许用中文名或临时编号。
- 表现层坐标不参与 `FindRoute()`、`FindShortestPath()` 或路费计算。

## 7. 读取与显示方案

可选两种接入方式：

1. 扩展 `MapDisplayController`。
2. 新增 `MapRouteDisplayController`，由 `MapDisplayController` 继续只负责相机适配。

当前实现保留 `MapRouteDisplayController` 和显示配置校验能力，但航道槽位生成已收敛到 `MobileCityInteractionController` 的统一影响力槽位刷新路径。

推荐后续若继续拆分表现层，可抽出 `MapInfluenceSlotDisplayController`，职责更清晰：

- `MapDisplayController`：地图 Sprite 和相机。
- `MapInfluenceSlotDisplayController`：读取地块/资源点与航道槽位显示配置，生成槽位 SpriteRenderer，并根据 `GameState.Map.Influences` 刷新占用状态。
- `MapRouteDisplayController`：仅保留校验或后续航道槽位表现扩展，不负责绘制航道本体。

统一槽位显示控制器的核心流程：

1. 获取 `mapRenderer`。
2. 获取当前规则地图 `GameMapDefinition` 或 `MapQueryService`。
3. 读取当前 `MapId` 对应的 `MapRouteDisplayDefinition` 列表。
4. 校验每个显示配置的 `RouteId` 能在 `MapQueryService.GetRoute(routeId)` 找到。
5. 为每条航道的影响力槽位创建子对象：
   - `GameObject` 名称：`RouteInfluenceSlot {routeId}:{slotIndex}`。
   - 添加 `SpriteRenderer`。
   - 将 `InfluenceSlotPositions` 转换为世界坐标。
   - 设置空槽颜色、玩家占用颜色和排序层级。
6. 刷新槽位状态：
   - 未占用：空槽颜色。
   - 已占用：对应玩家颜色。

坐标转换应复用与资源点一致的逻辑：

```csharp
private Vector3 ToWorldPosition(Vector2 normalizedPosition, float z)
{
    var bounds = mapRenderer.bounds;
    return new Vector3(
        bounds.min.x + bounds.size.x * normalizedPosition.x,
        bounds.max.y - bounds.size.y * normalizedPosition.y,
        z);
}
```

## 8. 航道槽位状态显示

表现层状态只决定槽位显示效果，不决定规则合法性。建议定义：

```csharp
public enum RouteInfluenceSlotDisplayState
{
    Empty,
    Occupied
}
```

状态来源：

- `Empty`：对应航道槽位未被占用。
- `Occupied`：`GameState.Map.Influences` 中存在对应 `routeId` 和 `slotIndex` 的影响力。

注意：

- 红区是否开放、是否可探索由规则模块判断，航道槽位显示模块不做规则判断。
- 公路覆盖的规则效果由现有运行时状态和规则服务处理，表现层不额外绘制公路覆盖状态。

## 9. 航道影响力槽位显示扩展

现有 `MobileCityInteractionController.BuildInfluenceSlotViews()` 只为资源点生成影响力槽位，并且位置是临时偏移。航道影响力槽位应改为显式坐标配置。

扩展方式：

1. 规则槽位仍使用 `InfluenceSlotReference.ForRoute(routeId, slotIndex)` 或 `InfluenceService.GetRouteSlotId(routeId, index)` 一类稳定 id。
2. 表现配置为每条航道提供 `InfluenceSlotPositions`。
3. 初始化时遍历规则地图 `Routes`：
   - 读取 `route.InfluenceSlotCount`。
   - 读取显示配置的 `InfluenceSlotPositions`。
   - 两者数量不一致时记录错误并跳过或使用临时降级位置。
4. 为每个槽位创建显示对象：
   - 名称：`RouteInfluenceSlot {routeId}:{index}`。
   - 位置：配置的归一化坐标转换为世界坐标。
   - 默认显示空槽颜色。
5. 刷新时查询 `GameState.Map.Influences`：
   - `placement.RouteId == routeId` 或 `placement.SlotId == route:{routeId}:{index}`。
   - 已占用则按玩家颜色显示。
   - 未占用则显示空槽。

建议把资源点槽位和航道槽位统一成一个显示控制器：

```text
MapInfluenceSlotDisplayController
  - BuildLocationSlots()
  - BuildRouteSlots()
  - Refresh(GameState state)
```

这样可以避免资源点和航道使用两套刷新逻辑。

## 11. 测试项

编辑器测试：

- 四人地图每个 `MapRouteDefinition.RouteId` 都能找到一条显示配置。
- 显示配置中的 `RouteId` 全部存在于四人规则地图。
- 每条航道 `InfluenceSlotPositions.Count == route.InfluenceSlotCount`。
- 所有归一化坐标满足 `0 <= x <= 1` 且 `0 <= y <= 1`。
- 三人地图未配置时，不影响四人地图配置校验；三人地图可返回“未配置”而不是报规则错误。

Unity 场景验证：

- 打开四人地图场景后，航道影响力槽位全部可见。
- 航道影响力槽位贴合地图图片，不明显偏离航道图案。
- 航道影响力槽位不遮挡地块热点、移动城市、资源点影响力槽位和 UI。
- 切换不同分辨率或相机适配后，航道影响力槽位仍与地图 Sprite 对齐。
- 航道影响力槽位显示数量与规则槽位数量一致。
- 在航道槽位放置影响力后，刷新显示能按玩家颜色更新。

回归测试：

- `FourPlayerMapDefinitionTests` 仍全部通过。
- `MapQueryService` 的相邻关系、寻路和区块查询不受显示配置影响。
- 影响力模块已有放置、移动、移除测试不因显示模块变化而改变结果。

# 独立资源计数卡板模块说明

## 1. 模块定位

独立资源计数卡板用于在对局 HUD 中持续显示当前本地玩家的五类资源。它把资源状态从旧的信息正文中拆出，使用三组机械齿轮计数器和两组辅助资源槽呈现数量变化。

本模块属于纯表现层：只读取 `PlayerState.Resources`，不修改 `GameState`，不提交命令，也不参与支付、采集、出售或资源合法性判断。资源增减仍以 Domain/Application 完成结算后的 `GameState` 为唯一事实源。

## 2. 显示内容

卡板中的资源顺序由 `ResourceCounterBoardView` 固定校验：

| 区域 | `ResourceType` | 界面名称 | 显示方式 |
| --- | --- | --- | --- |
| 机械计数区 1 | `Originium` | 源岩 | 十位、个位双齿轮 |
| 机械计数区 2 | `OriginiumShard` | 源石 | 十位、个位双齿轮 |
| 机械计数区 3 | `Iron` | 异铁 | 十位、个位双齿轮 |
| 辅助资源区 1 | `PureOriginium` | 至纯源石 | 数字、缩放与闪光反馈 |
| 辅助资源区 2 | `GoldVoucher` | 金券 | 数字、缩放与闪光反馈 |

机械计数区当前按两位数字设计。现有玩法资源值应保持在 `0–99` 的可读范围内；如果后续允许三位数资源，需要扩展布局与数字显示逻辑，不能只调整 Prefab 宽度。

## 3. 运行时数据流

```text
Host / 本地规则结算
  -> GameState 中的 PlayerState.Resources 更新
  -> MobileCityInteractionController 统一刷新表现
  -> 根据 localPlayerId 查找当前本地玩家
  -> ResourceCounterBoard.Render(player.Resources, animate)
  -> 五个计数 View 更新数字与动画
```

`MobileCityInteractionController.RefreshResourceCounter()` 是正式刷新入口：

- 对局初始化完成后调用 `RefreshResourceCounter(false)`，首次显示直接落到最终数值，不播放入场动画。
- 后续命令结算、角色牌效果、资源显示刷新等流程调用带动画的刷新入口。
- 热座与联机模式均依据控制器解析出的 `localPlayerId` 显示本地玩家资源，不读取其他玩家的隐藏表现状态。
- 地图上的资源点指示物由 `MapViewPresenter` 负责，本模块不管理地图资源标记。

## 4. 组件职责

### `ResourceCounterBoard`

模块控制器，负责：

- 接收完整 `ResourceSet`；
- 保存五个显示槽的当前动画状态和目标值；
- 区分首次静态渲染与后续动画刷新；
- 使用 `Time.unscaledDeltaTime` 推进动画；
- 在渲染前执行配置完整性检查。

### `ResourceCounterBoardView`

固定引用集合，负责：

- 绑定三个 `ResourceGearCounterView`；
- 绑定两个 `ResourceAuxiliaryCounterView`；
- 绑定 `ResourceCounterVisualLibrary`；
- 校验 Controller/View 双向引用、资源数量和固定顺序。

### `ResourceGearCounterView`

单个机械计数器的引用集合，包括资源图标、名称、十位/个位齿轮、数字文本、齿轮遮罩和读数结构。

### `ResourceAuxiliaryCounterView`

至纯源石或金券资源槽的引用集合，包括图标、名称、数量文本、内容根节点和闪光覆盖层。

### `ResourceCounterBoardLayoutProfile`

持久化布局与动画参数。当前生产资产配置为：

| 参数 | 当前值 |
| --- | ---: |
| 根布局尺寸 | `432 × 222` |
| 根布局位置 | 左上角偏移 `(18, -18)` |
| 单个机械计数器尺寸 | `134 × 132` |
| 单个辅助资源槽尺寸 | `212 × 50` |
| 齿轮动画时长 | `0.46s` |
| 辅助资源动画时长 | `0.32s` |
| 单个数字步进角度 | `36°` |

### `ResourceCounterVisualLibrary`

持久化保存大齿轮、小齿轮、数字齿轮、表盘遮罩、读数环、铆钉和金券 Sprite。运行时不临时生成这些公共视觉资源。

## 5. 动画规则

### 机械资源

- 十位和个位分别旋转到对应数字刻度。
- 资源增加与减少使用相反旋转方向，跨越十位时保持方向连续。
- 数值采用平滑插值，动画过程中同步更新当前显示数字。
- 第一次渲染、显式关闭动画或数值未变化时直接显示最终状态。

### 辅助资源

- 数值变化后立即更新文本。
- 内容根节点在动画中最多放大约 `8%`。
- 闪光覆盖层使用正弦脉冲，最大透明度约 `0.28`。
- 动画结束后恢复原始缩放并清除闪光。

## 6. Prefab 与资产接线

正式运行时资产：

- `Assets/YC/Presentation/Prefabs/Gameplay/ResourceCounterBoard.prefab`
- `Assets/YC/Presentation/Prefabs/Gameplay/GameplayInteractionHud.prefab`
- `Assets/YC/Presentation/Content/ResourceCounterBoardLayoutProfile.asset`
- `Assets/YC/Presentation/Sprites/ResourceCounterVisuals.asset`

`ResourceCounterBoard.prefab` 作为嵌套 Prefab 接入 `GameplayInteractionHud.prefab`。`GameplayInteractionHudView`、`MobileCityInteractionController` 和场景中的序列化引用必须指向同一个资源卡板实例；任一引用不一致时，HUD 配置校验失败并阻止控制器继续运行。

## 7. 配置约束

运行前必须满足：

- Controller 与 View 双向绑定；
- 机械计数器恰好为三个，并按源岩、源石、异铁排列；
- 辅助资源槽恰好为两个，并按至纯源石、金券排列；
- 所有资源图标、齿轮、遮罩、读数环、铆钉和金券 Sprite 均存在；
- 布局尺寸、动画时长和步进角度为有效正数；
- HUD、主控制器和场景引用的是同一个卡板实例。

## 8. 模块边界

本模块不负责：

- 修改玩家资源；
- 判断费用能否支付；
- 决定采集目标或路费接收方；
- 显示地图上的资源点指示物；
- 保存独立于 `GameState` 的资源副本；
- 参与联机协议或资源快照序列化。

后续修改资源规则时应调整 Domain/Application；只有资源显示种类、布局、动画或视觉素材变化时才修改本模块。

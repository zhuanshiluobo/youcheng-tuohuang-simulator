# 本地联机自动跑局验证

此入口仅用于开发和测试，不是正式玩家功能。

## 覆盖范围

- 模拟本地联机 Host 房间。
- 自动占满 4 个席位：Player 1 到 Player 4。
- 使用 Host 权威 `AuthoritativeCommandDispatcher` 提交命令。
- 自动完成四名玩家初始选点，并自动处理入场事件的第一个选项。
- 行动轮会优先补足一次显式探索、一次城市移动和一次调度，再继续自动建设或部署影响力。
- 一次成功跑局必须分别完成至少一次部署、探索、建设、发动角色牌、移动、宣告和特殊行动；缺少任意一项时，即使推进到终局也判定失败。
- P1 会通过正式命令发动极境策略；结算后必须满足盖放牌已清空、该牌只存在于弃牌区且 `discardCount=1`。
- 自动准备两组城市样式条件并通过正式命令宣告，随后分别发动至少一种 II 级和一种 I 级特殊行动；当前确定性路径由 P3 发动源石工业中枢、P4 发动军工化区域。
- 特殊行动按正式 Host 命令和待处理会话逐步结算，不直接修改最终状态；快照会输出行动 ID、样式标记区域、剩余次数、主要行动预算与待处理步骤。
- 探索命令会提交明确事件选项、路径地点和航道参数，避免只依赖默认分支。
- 调度命令会移动已有影响力，并优先把一次对手影响力调度到后续可作为路费接收证据的航道槽。
- 第 2 行动轮结束后会进入 `ResourceCollection`，自动提交 `CollectResource`，并在 `Cleanup` 提交结束命令继续推进。
- 采集阶段至少提交一次带显式航道的付费采集路径，并至少提交一次带 `paymentRecipients` 的采集，显式指定对手为航道路费接收方。
- 稳定推进到第 8 回合第二行动轮、采集和收尾后的 `FinalScoring`，并输出状态快照。
- 如果中途命令失败，快照会包含失败命令、待选择状态、待处理卡牌会话、调度路线、指定接收方采集证据和最近日志，便于定位卡住位置。

## 使用方式

在 Unity Editor 菜单执行：

```text
YC/Dev/Run Localhost Autoplay
```

在 Editor 或 Development Build 中，也可以用命令行显式触发：

```text
--yc-dev-autoplay-localhost
```

成功时 Console 会输出 `本地联机自动跑局快照`，其中应包含：

## 最小验证脚本

从仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Run-EditModeTests.ps1 `
  -TestFilter "YC.Tests.EditMode.LocalhostAutoplayRunnerTests"
```

该脚本只运行 `YC.Tests.EditMode.LocalhostAutoplayRunnerTests`，测试输出中会附带自动跑局快照。

2026-07-09 使用上述通用入口实跑通过：`1 passed / 0 failed`，结果文件为 `Logs/EditModeTests/editmode-20260709_155530.xml`。这是特殊行动接入前的历史结果，当前自动跑局能力以 2026-07-22 证据为准。

当前自动跑局测试还会断言部署、探索、建设、发动角色牌、移动、宣告和特殊行动七项成功数均不少于 `1`，角色牌执行摘要包含 `discardCount=1`，I/II 级特殊行动各完成一次，最终至少有玩家获得采集资源，并确认最终计分快照已经生成 4 名玩家分数明细和赢家，用于防止行动轮、角色牌弃牌、特殊行动待选、采集阶段或终局结算退化为空转。

## Development Build 与构建产物验证

关闭正在使用本项目的 Unity Editor 后，从仓库根目录生成可识别开发参数的 Windows Development Build：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\tests\BuildLocalhost.ps1 -Development
```

`-Development` 会把产物生成到 `Builds/LocalhostDevelopment/tuohuang.exe`；不要用普通 `YC/Build/Localhost Simulator` 产物代替开发参数验证。构建产物可通过 `--yc-dev-autoplay-localhost` 显式启动自动跑局，成功标准与上方快照字段一致。

若本项目已经由 Unity Editor 打开并连接 Unity MCP，不应再启动第二个批处理 Editor；可在当前实例内执行 `manage_build(action="build", target="windows64", development="true", output_path="Builds/LocalhostDevelopment/tuohuang.exe")`，并轮询构建任务到 `succeeded`。

2026-07-22 已落盘证据：

- 特殊行动专项：`Logs/EditModeTests/editmode-20260722_194602.xml`，`41/41 Passed`。
- 本轮回归专项：`Logs/EditModeTests/editmode-20260722_203445.xml`，`73/73 Passed`。
- 完整 EditMode：`Logs/EditModeTests/editmode-20260722_205155.xml`，`697/697 Passed`。

该入口模拟本地 Host 权威命令链，但不等于人工 UI 操作、Editor Host + 两个 Development Build Client 三进程或多个 Steam 账号 P2P/Relay 验收；这些项目仍未执行。

## 构建版 UI 截图验收

左侧信息面板 smoke 使用 `tools/tests/Capture-InfoPanelSmoke.ps1`。

右侧建设/宣告卡区 smoke 使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\tests\Capture-RightCardSmoke.ps1 -Dialog Build
powershell -ExecutionPolicy Bypass -File .\tools\tests\Capture-RightCardSmoke.ps1 -Dialog Declare
powershell -ExecutionPolicy Bypass -File .\tools\tests\Capture-RightCardSmoke.ps1 -Dialog None
```

该脚本会复用同目录的 `BuildLocalhost.ps1` 和 `CaptureLocalhostWindow.ps1`，启动构建版时传入 `--yc-dev-start-localhost` 与 `--yc-dev-right-card-smoke*` 参数，并输出到 `Logs\Screenshots\right-card-smoke-<dialog>.png`。若 Unity 项目已打开或 batch Unity 未创建构建日志，脚本会快速失败或按超时停止自己启动的 Unity 进程，不应再长时间卡住。

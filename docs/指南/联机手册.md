# 联机手册

本文说明当前项目的单机、Steam 联机和 Mirror 本地多实例测试方式。当前正式联机技术栈为 `Steamworks.NET + Steam Matchmaking Lobby + Mirror + FizzySteamworks`，开发测试 AppID 固定为 `480`；本地多实例模式使用 `Mirror + TelepathyTransport`，不需要 Steam 账号。

> 2026-09-08 状态：正式三人图已接入，开发验收进行中，Steam 三账号待验收。以下三人入口操作用于当前开发验证，不代表构建或全流程已通过。

## 1. 模式选择

| 模式 | 房间与身份 | Mirror Transport | 适用场景 |
|---|---|---|---|
| 单机 | 无联网 | 不启动 | 正常单机游戏 |
| Steam 联机 | Steam Lobby、真实 SteamID | FizzySteamworks | 真实朋友联机和最终验收 |
| Mirror 本地测试 | 本地 TCP 房间、模拟身份 | TelepathyTransport | 一台电脑、多实例、无多 Steam 账号测试 |

单机入口不会初始化 Steam，也不会启动 Mirror。关闭 Mirror 本地测试开关且不传本地测试参数时，创建/加入房间默认使用 Steam。

## 2. 单机操作

1. 打开 `StartScene` 并进入 Play Mode，或启动 Windows 构建。
2. 点击“本地游戏”。
3. 在地图选择弹窗中点击“三人地图”或“四人地图”；正式三人图已接入，开发验收进行中。
4. 不需要启动或登录 Steam。

若 Steam 未运行，主菜单和本地游戏入口不应产生 Steam 初始化错误。Steam 只在“创建联机”中选择“三人地图”或“四人地图”，或实际提交“加入联机”时按需初始化。

## 3. Steam 联机（AppID 480）

### 3.1 前置条件

- 所有参与者均启动 Steam 客户端并登录。
- 根目录和 Windows 构建可执行文件旁存在内容为 `480` 的 `steam_appid.txt`。
- “创建联机”中的“三人地图”和“四人地图”分别创建 3 人房和 4 人房；正式三人图已接入，Steam 三账号待验收。双人验证协议仍供开发测试使用，但主菜单不再提供入口。
- 每个参与者必须使用不同 Steam 账号；同一 SteamID 不能占用多个席位。
- AppID 480 是共享测试环境，项目会使用 `gameKey=yc_nomad_city` 和 `protocolVersion=2` 过滤非本项目 Lobby。

### 3.2 房主创建

1. 确认 Unity 菜单 `YC/联机测试/启用 Mirror 本地测试模式` 没有勾选。
2. 进入开始页，点击“创建联机”。
3. 在地图选择弹窗中点击“三人地图”或“四人地图”，按所选人数创建房间。
4. 创建成功后复制十进制 Steam Lobby ID，或点击“邀请好友”打开 Steam Overlay。
5. 等待所有席位依次显示“已在 Lobby / 传输已连接 / 身份已验证”后点击“开始”。仅 Lobby 席位已满时，“开始”按钮仍保持禁用。

### 3.3 双人 Steam 人工验证

当暂时只有两个不同 Steam 账号时，可以使用专用验证入口：

1. 两台电脑均启动 Steam，并分别登录不同账号。
2. 确认房主没有启用 `YC/联机测试/启用 Mirror 本地测试模式`。
3. 当前开始页不再提供“Steam 双人验证”按钮；需要验证该协议时，应通过开发测试代码直接创建明确标记的双人验证房。
4. 房主复制 Lobby ID 或通过 Steam Overlay 邀请第二名测试者。
5. 第二名测试者照常点击“加入联机”并输入 Lobby ID，或接受 Steam 邀请。
6. 等待两个席位的 Lobby、Mirror 传输和身份校验全部完成，再由房主点击“开始”。

双人验证房会写入 `sessionKind=steam_two_player_validation`，未带该标记的 2 人 Lobby 会被兼容策略拒绝。进入对局后复用当前四人地图和基础流程，仅用于检查 Steam Lobby、好友邀请、FizzySteamworks P2P/Relay、Host 权威命令、初始快照、状态同步和断线返回；它不是正式二人规则实现，不能用于规则验收或平衡结论。

### 3.4 Client 加入

1. 点击“加入联机”。
2. 粘贴房主发送的 Steam Lobby ID。
3. 点击“加入”，等待房主开始。

房主退出或网络断开时，Client 会停止 Mirror、退出当前 Lobby 并返回 `StartScene`。第一版不迁移房主。

### 3.5 开局就绪状态

房间界面区分四个阶段：

| 阶段 | 权威来源 | 开局前要求 |
|---|---|---|
| `LobbyMemberPresent` | Host 枚举 Steam Lobby 实际成员并分配稳定席位 | 必须 |
| `TransportConnected` | Mirror Server connected/disconnected 事件与当前连接表 | 必须 |
| `IdentityVerified` | Fizzy 连接地址解析出的 SteamID 与 Lobby 席位完全匹配 | 必须 |
| `GameStateSynchronized` | Client 进入游戏场景、应用 Host 初始快照并回传确认 | 开局后完成 |

客户端只读取 Host 写入 Lobby metadata 的就绪结果，不能把自己或其他玩家标记为已验证。等待房间中任一 Lobby 成员离开、Mirror 连接断开、地址无法解析、SteamID 不属于 Lobby 或同一 SteamID 建立第二条连接时，对应席位不会保持就绪，Host 也不能开始游戏。

## 4. Mirror 本地多实例测试

本模式用于在只有一个 Steam 账号或 Steam 未运行时验证 Mirror Host/Client、房主权威命令、初始快照、确认序号、断档重同步、断线和返回菜单。它不验证 Steam Lobby、真实 SteamID、Steam P2P 或 Steam Relay。

### 4.1 构建客户端

现有 `YC/Build/Localhost Simulator` 生成的不是 Development Build，不能识别本地联机参数。关闭正在使用本项目的 Unity Editor 后，优先从仓库根目录运行统一构建脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\tests\BuildLocalhost.ps1 -Development
```

脚本会生成 `Builds/LocalhostDevelopment/tuohuang.exe`。如果必须手动构建，则使用 Unity 的 Build Settings 并保持相同配置：

1. 打开 `文件/File -> 生成设置/Build Settings`。
2. 确认启用以下场景：
   - `Assets/Scenes/StartScene.unity`
   - `Assets/Scenes/SampleScene.unity`
3. 选择 `PC, Mac & Linux Standalone -> Windows -> x86_64`。
4. 勾选 `Development Build`。
5. 勾选后构建到 `Builds/LocalhostDevelopment/tuohuang.exe`。

### 4.2 Editor 作为房主

1. 停止 Play Mode。
2. 点击 Unity 顶部菜单 `YC -> 联机测试 -> 启用 Mirror 本地测试模式`。
3. 确认菜单项前出现勾选。
4. 进入 Play Mode，点击“创建联机”，再点击“三人地图”或“四人地图”，创建对应人数的本地测试房间。
5. 记录房间界面显示的 `IP:端口`。本地房间协调端口从 `7780` 开始。

若菜单未出现，先退出 Play Mode，执行 `Assets/资源 -> Refresh`，等待脚本编译完成后再查看。

当前开始页已接入三人房选择，开发自动化也可用 `--yc-dev-local-mirror-host=3` 创建 3 人房。正式三人图已接入，开发验收进行中；旧三席链路测试结果不能替代当前三人规则及全流程验收，Steam 三账号仍待验收。

### 4.3 启动本地 Client

先启动两个构建 Client。PowerShell 示例：

```powershell
$exe = "F:\游城拓荒模拟器\Builds\LocalhostDevelopment\tuohuang.exe"
$dir = Split-Path $exe

Start-Process -FilePath $exe -WorkingDirectory $dir -ArgumentList @(
    "--yc-local-multiplayer-test",
    "--yc-local-player-name=Client2"
)

Start-Process -FilePath $exe -WorkingDirectory $dir -ArgumentList @(
    "--yc-local-multiplayer-test",
    "--yc-local-player-name=Client3"
)
```

当前普通入口创建的四人房还需再启动一个 Client：

```powershell
Start-Process -FilePath $exe -WorkingDirectory $dir -ArgumentList @(
    "--yc-local-multiplayer-test",
    "--yc-local-player-name=Client4"
)
```

每个 Client 点击“加入联机”，输入 Editor 显示的房间号。同一台电脑可优先尝试 `127.0.0.1:7780`；若房主实际使用了其他协调端口，应保持端口一致。所有席位加入且 Mirror 身份均验证后，Editor 房主的“开始”按钮才会启用。

本地模式不会信任 Client 上报的裸 `PlayerId`。Host 会通过每条 TCP 房间信令连接签发随机身份凭据，Client 只把该凭据呈递给 Mirror；Host 验证凭据对应的稳定席位后才设置传输与身份就绪。TCP 信令断开会撤销凭据并清除就绪，单独的 Mirror 断线重连可在同一信令会话内恢复原席位。

### 4.4 结束测试

1. 各 Client 返回主菜单并关闭。
2. Editor 停止 Play Mode。
3. 再次点击 `YC -> 联机测试 -> 启用 Mirror 本地测试模式`，取消勾选。

取消勾选后，Editor 的创建/加入入口恢复为 Steam 模式。Development Build 只有传入 `--yc-local-multiplayer-test` 时才进入本地模式。

## 5. 端口与防火墙

| 端口 | 协议 | 用途 |
|---|---|---|
| 7777 | TCP | Mirror Telepathy 游戏通信 |
| 7780-7799 | TCP | 本地房间创建、加入、席位和开始信号 |

Windows 首次运行可能弹出防火墙提示；同机或局域网测试时应允许专用网络访问。一次只启动一个本地房主，避免 Mirror `7777` 端口冲突。

## 6. 常见问题

### 主菜单打开就提示 Steam 初始化失败

当前代码已改为按需初始化。请确认脚本已重新编译，并停止旧 Play Mode 后重新进入。单机入口不应初始化 Steam。

### Steam 失败后界面像卡死

Steam 未运行属于可恢复失败，当前使用警告和 UI 提示，不再调用会触发 Unity `Error Pause` 的错误日志。若编辑器已被旧错误暂停，先解除顶部 Pause 或重新进入 Play Mode；“取消”会关闭面板并撤销尚未完成的建房/加入操作。

### 本地 Client 无法加入

- 确认客户端是 Development Build。
- 确认启动参数包含 `--yc-local-multiplayer-test`。
- 同机优先使用 `127.0.0.1:<房间端口>`。
- 检查 TCP `7777` 和实际房间端口是否被防火墙拦截。
- 确认只运行一个房主，且房间没有坐满。

### 同一 Steam 账号多开为什么不能测试 Steam 联机

Steam Lobby 成员和项目席位都以 SteamID 唯一标识；同一账号不能模拟多个合法玩家。本地多实例模式用开发限定的模拟身份解决此问题，但不能替代真实 Steam P2P 验收。

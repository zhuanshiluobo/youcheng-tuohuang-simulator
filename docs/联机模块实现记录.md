# 联机模块实现记录

本文记录 Unity 官方联网栈接入过程中已经写入项目的代码。方案背景见 `多人房间与联机入口方案.md`。

## 实现范围

本轮实现范围是“多人房间连接方式替换”，即把开始页的创建房间和加入房间从直接 TCP 原型切换到 Unity 官方联网栈：

```text
Unity Authentication
-> Unity Relay
-> Unity Lobby
-> Unity Transport
-> Netcode for GameObjects
```

已覆盖：

- Host 创建 Lobby 房间并生成 Lobby 房间码。
- Host 创建 Relay allocation 并把 Relay join code 写入 Lobby data。
- Client 通过 Lobby 房间码加入房间。
- Client 从 Lobby data 读取 Relay join code 并加入 Relay allocation。
- Host 调用 `NetworkManager.StartHost()`。
- Client 调用 `NetworkManager.StartClient()`。
- Lobby 轮询刷新房间席位列表。
- Host Lobby 心跳。
- Host 点击开始后锁定 Lobby，并通过 Lobby 状态通知 Client 进入游戏。

未覆盖：

- 游戏内 `GameCommand` 的 Netcode RPC / 自定义消息同步。
- Host 广播 `GameState` 快照。
- 完整断线重连。
- 完整的远端 `NetcodeClientId` 与项目内 `PlayerId` 映射。

## 核心文件

### `UnityOfficialRoomService`

路径：

```text
Assets/YC/Infrastructure/Multiplayer/UnityOfficialRoomService.cs
```

职责：

- 初始化 Unity Services。
- 使用 Authentication 匿名登录。
- 创建或加入 Relay。
- 创建或加入 Lobby。
- 配置 `UnityTransport` 的 Relay Server Data。
- 动态确保 `NetworkManager` 和 `UnityTransport` 可用。
- 维护 `RoomState`。
- 通过事件向 Presentation 层报告房间刷新、开始游戏、房间解散和错误。

主要方法：

- `CreateRoomAsync(string hostPlayerName, int playerCount)`
  - 检查当前是否在 Play Mode。
  - 初始化 Unity Services。
  - 匿名登录 Authentication。
  - 创建 Relay allocation。
  - 获取 Relay join code。
  - 创建 Lobby，并写入 `relayJoinCode`、`roomStatus`、`playerCount`。
  - 调用 `NetworkManager.StartHost()`。
  - 启动 Lobby 心跳和轮询。

- `JoinRoomAsync(string roomCode, string playerName)`
  - 检查当前是否在 Play Mode。
  - 初始化 Unity Services。
  - 匿名登录 Authentication。
  - 通过 Lobby 房间码加入 Lobby。
  - 从 Lobby data 读取 `relayJoinCode`。
  - 加入 Relay allocation。
  - 调用 `NetworkManager.StartClient()`。
  - 启动 Lobby 轮询。

- `StartGameAsync()`
  - 仅 Host 可调用。
  - 检查席位是否全部加入。
  - 将 Lobby 锁定。
  - 把 `roomStatus` 改为 `started`。
  - 触发 `GameStarted` 事件。

- `EnsureUnityServicesAsync()`
  - 调用 `UnityServices.InitializeAsync()`。
  - 调用 `AuthenticationService.Instance.SignInAnonymouslyAsync()`。
  - 捕获 SSL / 网络失败并转换为更明确的中文错误。

- `EnsureNetworkManager()`
  - 优先使用 `NetworkManager.Singleton`。
  - 若场景中没有，则运行时创建 `NetworkManager` 和 `UnityTransport`。
  - 只在 Play Mode 下调用 `DontDestroyOnLoad`。

- `BuildRoomState(Lobby lobby)`
  - 将 Lobby 玩家列表转换为项目内 `RoomState`。
  - Host 玩家排第一，其余玩家按 Lobby 顺序排列。
  - Lobby 房间码写入 `RoomState.RoomId`。
  - 本地玩家写入 `RoomState.LocalPlayerId`。

## Lobby 数据约定

当前 `UnityOfficialRoomService` 使用以下 Lobby data key：

```text
relayJoinCode
roomStatus
playerCount
```

含义：

- `relayJoinCode`：Relay join code，Member 可见。
- `roomStatus`：`waiting` 或 `started`，Member 可见。
- `playerCount`：目标人数，Public 可见。

当前 Player data key：

```text
playerName
ready
```

含义：

- `playerName`：玩家显示名。
- `ready`：当前固定为 `1`，表示加入后即准备。

## 本地四窗口测试约定

Standalone 多开时，每个 exe 进程会使用独立 Authentication profile：

```text
local-{processId}
```

这样 4 个本地窗口不会被 Authentication / Lobby 识别为同一个匿名玩家。

Editor 中使用：

```text
editor
```

因此四窗口测试建议使用构建后的 exe 多开，而不是只依赖单个 Editor Play Mode。

## Unity Editor 配置要求

在 Unity 中需要确认：

1. `File > Build Settings...` 中包含 `StartScene` 和 `SampleScene`。
2. `Edit > Project Settings > Services` 已绑定 Unity Project ID。
3. Unity Dashboard 中已启用：
   - Authentication
   - Lobby
   - Relay
4. Package Manager 已正确解析 Netcode、Transport、Authentication、Lobby、Relay。
5. 创建/加入房间必须发生在 Play Mode 或构建后的运行程序中。

## 已处理的错误

### Authentication SSL 失败

现象：

```text
Network Error: Unable to complete SSL connection
```

原因：

- Authentication 匿名登录阶段 HTTPS / SSL 握手失败。
- 通常与网络、代理、防火墙、系统时间、证书或 Unity Services 访问有关。

处理：

- 代码捕获 `RequestFailedException`，在 UI 中显示中文提示。
- 保留完整 Unity Console 堆栈。

### `DontDestroyOnLoad` 非 Play Mode 调用

现象：

```text
DontDestroyOnLoad can only be used in play mode
```

原因：

- 在非 Play Mode 下触发创建房间逻辑。

处理：

- 创建/加入前调用 `EnsurePlayModeNetworking()`。
- `DontDestroyOnLoad` 只在 `UnityEngine.Application.isPlaying` 时调用。

### `Application` 命名冲突

现象：

```text
YC.Application.isPlaying does not exist
YC.Application.runInBackground does not exist
```

原因：

- 项目存在 `YC.Application` 命名空间，裸写 `Application` 会被解析到项目命名空间。

处理：

- 全部改为 `UnityEngine.Application`。

### `Debug` 命名冲突

现象：

```text
'Debug' is an ambiguous reference between 'UnityEngine.Debug' and 'System.Diagnostics.Debug'
```

原因：

- 使用进程 id 时需要 `System.Diagnostics.Process`，与 `UnityEngine.Debug` 产生歧义。

处理：

- 使用 `System.Diagnostics.Process.GetCurrentProcess().Id`。
- 使用 `UnityEngine.Debug.LogException(ex)`。

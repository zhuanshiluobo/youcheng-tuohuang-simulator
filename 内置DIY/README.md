## 源码包目录

把准备随安装包提供的正式 DIY 源码包放在 `包` 目录下，每个包使用一个独立文件夹，例如：

```text
内置DIY/
  README.md
  文档/                 开发文档和配套 Schema
  包/
    my-mode/
      pack.json
      lua/
      ...
```

`pack.json` 必须位于该包文件夹的根目录，格式和资源限制见 [DIY 包体作者指南](文档/DIY包体作者指南.md)。文件夹名用于整理源码，包的身份和版本由 `pack.json` 决定；同一安装器不能包含相同包 ID 的多个版本。不要将测试示例或未准备发布的内容放进 `包`。

## 构建与安装

运行 `tools/packaging/build_windows_installer.py` 构建安装器时，工具会自动发现 `内置DIY/包` 下的每个包，使用目标游戏的解析器发布并校验 ZIP，再加入安装器的可选组件。生成的 ZIP 与发布清单位于本次安装器输出目录的 `内置DIY发布` 下，不会写回或覆盖源码。未指定 `--diy-tool` 时，打包脚本会从项目源码构建自包含发布工具；这需要 .NET 8 SDK，首次构建还需能还原 Windows x64 运行时依赖。指定 `--diy-tool` 时使用所给的自包含工具。

如需明确制作不含目录内置包的安装器，可在打包命令中使用 `--no-builtin-diy`；若同时使用 `--diy-manifest`，命令行明确指定的包仍会加入。初始的 `包` 目录没有任何内容包，已有的测试示例保留在 `tools/packaging/examples`，不会因它们存在而自动加入。

包可提供模式、扩展或两者。安装后，玩家可在原有模式与扩展控件中选择；安装、补装、导出及手动安装说明见 [DIY 内容安装与发布说明](文档/DIY内容安装与发布说明.md)。

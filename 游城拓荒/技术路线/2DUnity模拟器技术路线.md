# 2D Unity 模拟器技术路线

本文基于 `规则书/《游城拓荒：铸基者》规则说明书（新）.pdf` 中的基础版玩法整理。目标不是复刻实体桌游的所有美术细节，而是先做一个能正确模拟基础版规则、支持多人热座操作、可持续扩展到企业扩展版的 2D Unity 规则模拟器。

## 1. 基础版玩法抽象

基础版可以抽象为一个在地图图结构上运行的回合制资源与区控游戏。

- 玩家人数：主要支持 3 到 4 人。
- 核心目标：探索荒野、占领矿区、建设城市、使用角色牌和城市样式获得分数，最终分数最高者获胜。
- 地图结构：地图由资源点、航道、区块组成，资源点有颜色、事件牌、资源指示物、移动城市停靠点、影响力空格。
- 主要物件：移动城市、玩家影响力标记、资源点指示物、事件牌、设施牌、城市样式牌、角色牌、资源与金券。
- 游戏阶段：开局入场，8 个连续回合的拓荒探索，每回合包含角色牌盖放、两轮玩家行动、采集资源、收尾，最后进入分数结算。
- 玩家行动：每轮至少选择 1 个主要行动，主要行动包括部署、调度、探索、城市移动、建设、特殊行动；主要行动前后可以执行快速行动。
- 关键结算：探索需要计算路费并结算事件；城市移动会移动城市并清除路径与目标点上的对手影响力；建设需要支付设施费用并结算入场效果；采集资源会按已占领资源点获得资源；分数结算包含区块控制、剩余资源、设施、城市样式等。

## 2. 技术选型

### Unity 版本

- 推荐使用 Unity 2022.3 LTS 或 Unity 6 LTS。
- 2D Renderer 适合桌面模拟器，后续如果要做炫酷牌桌效果可以切到 URP 2D。
- 初版以 PC 本地热座为目标，避免过早引入联网同步复杂度。

### C# 与工程形态

- 使用纯 C# 规则核心，尽量不依赖 `MonoBehaviour`。
- 使用 Unity Assembly Definition 拆分 `Domain`、`Application`、`Presentation`、`Infrastructure`。
- 使用 Command Pattern 表示玩家操作，便于撤销、回放、AI、联机同步。
- 使用 State Machine 管理开局、回合、行动轮、采集、收尾、计分等阶段。
- 使用 ScriptableObject 或 JSON 作为规则数据源，优先保证规则可配置。

### Unity 包建议

- `Input System`：鼠标拖拽、点击、快捷键、手柄可选。
- `TextMeshPro`：中文 UI 与数字提示。
- `Unity UI Toolkit` 或 UGUI：初版建议 UGUI，上手快，适合卡牌和面板；中后期可逐步迁移到 UI Toolkit。
- `2D Sprite`、`Sprite Atlas`：地图、牌面、标记、资源图标。
- `Newtonsoft Json`：如使用 JSON 配表，可用于外部规则数据加载。
- `Unity Test Framework`：规则单元测试、结算测试、回放测试。

## 3. 数据建模路线

### 地图数据

地图不宜用格子系统强行表达，建议建成图模型。

- `MapNode`：资源点或城市可停靠点。
- `RouteEdge`：航道，连接两个资源点，记录颜色、是否危险、影响力槽位、路费计算规则。
- `Region`：区块，如 A 区、B 区、C 区等，包含若干资源点和航道，用于区控计分。
- `InfluenceSlot`：可放置影响力的位置，可能位于资源点或航道上。
- `ResourceMarker`：资源点指示物，表示该资源点本轮可采集资源类型和数量。
- `EventSlot`：资源点对应事件牌位置。
- `CityDock`：移动城市当前位置或可移动目标。

### 卡牌数据

卡牌建议全部数据驱动，牌面图和规则效果分离。

- `CharacterCardDefinition`：角色牌，含策略效果、计谋效果、费用、使用窗口。
- `EventCardDefinition`：事件牌，含资源点颜色、事件选项、奖励、惩罚。
- `FacilityCardDefinition`：设施牌，含设施颜色、分数、费用、入场效果、限制关键字。
- `CityPatternDefinition`：城市样式牌，含宣告条件、宣告奖励、特殊行动解锁。

### 玩家状态

- 资源：源岩、源石、异铁、金券、至纯源石。
- 影响力供应堆与地图上的影响力。
- 移动城市位置。
- 手牌、盖放角色牌、弃牌区。
- 城市面板中的设施。
- 已宣告或已使用的城市样式标记。
- 当前分数与最终计分明细。

## 4. 规则引擎实现路线

### 阶段状态机

先实现固定流程，不急着做自由脚本化。

```text
Setup
-> Entrance
-> RoundStart
-> CharacterCover
-> PlayerActionRound1
-> PlayerActionRound2
-> ResourceCollection
-> Cleanup
-> NextRound 或 FinalScoring
```

每个状态只暴露当前可执行命令，例如 `CoverCharacterCardCommand`、`ExploreCommand`、`BuildFacilityCommand`。

### 命令与校验

每个玩家操作拆成三层：

- `Command`：玩家意图，例如探索某资源点。
- `Validator`：判断资源、路径、空位、回合窗口、颜色限制、红色区域限制等是否满足。
- `Resolver`：实际修改游戏状态，并产生日志、动画事件、后续选择请求。

这样做的好处是 UI、AI、联机都可以复用同一套规则判断。

### 路径与费用

探索和采集都需要路费计算，城市移动也依赖相邻判断。

- 使用 Dijkstra 或 BFS 计算移动城市当前位置到目标资源点的可达路径。
- 航道费用按“连接过程中经过没有自己影响力的航道”计算。
- 若航道上有对手影响力，需要选择一个该航道上的对手影响力并向其所有者支付金券。
- 采集资源阶段同一条航道即使用于连接多个资源点，也只支付一次路费。
- 需要明确禁止用采集阶段获得的金券支付本阶段路费。

### 效果系统

角色牌、事件、设施入场、城市样式都属于规则效果。建议初版采用“枚举效果类型 + 参数”的方式，后续再抽象脚本系统。

```text
EffectDefinition
- trigger: OnBuild / OnExplore / OnRoundCleanup / OnFinalScoring / Manual
- cost: ResourceCost
- condition: ConditionDefinition[]
- operations: EffectOperation[]
```

常见操作：

- 获得或支付资源。
- 放置、移动、移除影响力。
- 抽取、翻开、弃置卡牌。
- 移动城市。
- 建设设施。
- 增加分数。
- 解锁或标记城市样式。

### 自动结算与人工选择

模拟器要避免玩家手算，但也不能隐藏选择权。

- 自动计算所有确定性结果，如费用、资源收益、设施分数。
- 遇到选择点时弹出选择 UI，如选择路径、选择事件选项、选择移除哪名玩家的影响力。
- 所有结算都写入日志，便于玩家回看。

## 5. Unity 表现层路线

### 场景结构

- `BootstrapScene`：加载配置、初始化服务。
- `GameScene`：主桌面、地图、卡牌区、玩家面板。
- `DebugScene`：规则测试、快速造局、回放验证。

### 地图表现

- 地图底图使用 Sprite。
- 在地图上叠加可交互热点：资源点、航道、影响力槽、城市停靠点。
- 热点坐标由自定义编辑器或 JSON 配置维护，不依赖图片识别。
- 鼠标悬停显示可行动作、费用、资源收益和规则原因。

### 卡牌与面板

- 卡牌使用统一 `CardView`，绑定卡牌定义和当前状态。
- 玩家面板展示资源、手牌、城市面板、弃牌区、影响力供应。
- 行动面板根据状态机动态显示可用主行动和快速行动。
- 结算预览面板显示“执行后会发生什么”，降低规则误操作。

### 交互体验

- 支持点击式操作作为首选，不依赖拖拽。
- 关键操作进入预览确认，例如探索、城市移动、建设。
- 不合法操作要给出具体原因，例如“目标资源点未开放探索”或“没有足够源石”。
- 提供撤销当前未确认操作，不提供随意回滚已结算回合，避免规则状态混乱。

## 6. 开发里程碑

### M0：规则数据与地图原型

- 建立地图图模型。
- 手工录入基础版地图资源点、航道、区块。
- 实现玩家、资源、影响力、城市位置的基础状态。
- 做一个控制台或 Debug UI 运行开局入场。

### M1：核心回合循环

- 实现 8 回合流程。
- 实现角色牌盖放、两轮玩家行动、采集资源、收尾。
- 实现部署、调度、探索、城市移动、建设五个基础主行动。
- 先用占位卡牌和占位美术验证规则。

### M2：卡牌与效果

- 接入基础角色牌。
- 接入事件牌效果。
- 接入设施牌费用、分数、入场效果。
- 接入城市样式宣告和特殊行动。

### M3：计分与胜负

- 实现区块控制计分。
- 实现剩余资源计分。
- 实现设施与城市样式相关分数。
- 实现平局判定：先比较剩余金券，再比较剩余至纯源石数量。
- 输出最终结算明细。

### M4：完整桌面 UI

- 完成地图热点、卡牌手牌、玩家面板。
- 完成行动选择、费用预览、日志面板。
- 完成存档、读档、回放。
- 加入基础动画和音效反馈。

### M5：质量与扩展

- 建立规则单元测试和回放 golden case。
- 增加 AI 辅助玩家或自动模拟。
- 准备企业扩展版规则开关。
- 预留本地联机或远程联机同步接口。

## 7. 测试策略

### 单元测试

- 路费计算。
- 资源采集。
- 影响力放置和移动。
- 城市移动清除对手影响力。
- 建设费用和入场效果。
- 区块控制计分。
- 平局判定。

### 回放测试

将一整局游戏记录为命令序列：

```json
[
  { "round": 1, "player": "Blue", "command": "Explore", "target": "B-01" },
  { "round": 1, "player": "Red", "command": "BuildFacility", "card": "CoreCommandTower" }
]
```

每次改规则后重跑回放，确认最终状态和计分没有意外变化。

### 随机模拟

- 随机生成合法操作序列。
- 检查资源不会变成非法负数。
- 检查影响力数量守恒。
- 检查回合阶段不会卡死。
- 检查可执行命令始终能进入下一状态。

## 8. 技术风险

- 扫描规则书无法直接 OCR，规则录入需要人工校对。
- 卡牌效果数量多，若过早硬编码会导致维护困难。
- 地图是图结构而不是规则网格，坐标编辑器很重要。
- 费用和路径选择存在玩家选择权，不能只做单一路径自动最短路。
- 城市样式与设施组合可能产生很多条件判断，需要统一的条件系统。
- 如果后续做联机，必须保证规则引擎确定性和命令可序列化。

## 9. 推荐优先级

1. 先做纯规则引擎，不急着做漂亮 UI。
2. 先支持 3 到 4 人本地热座，不急着做 AI 和联网。
3. 先完整跑通基础版一局，再补美术和动画。
4. 所有卡牌效果尽量数据化，硬编码只用于少数无法泛化的特殊效果。
5. 从第一天开始记录操作日志和回放，后期调试会轻松很多。

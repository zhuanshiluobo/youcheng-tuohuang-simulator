## Effect式约定与共享裁定

下文是文字规格，**不是可直接运行的Lua**。`RegisterRule`、`GainCommand`、`GainReputation`、`FundInvestment`、`OperateFacilityStack`、`ExchangeBlueprint`等名称是组合流程或建议合同，不代表宿主已公开这些API。

| 写法 | 语义 |
| --- | --- |
| `[A,B]` | 同一条效果内部按序结算A及其必要子效果／响应依赖，再执行B；无依赖的旁路响应按通用调度继续，不一律阻塞后项。普通逗号不自动改成条件式。不同“立即”条目各自独立，不能用此写法串成一个效果 |
| `立即① F`、`立即② G` | 两条独立的立即效果，各有来源条目ID、节点与完成收据；即使由同一时点按序调度，也不是`[F,G]`或前一条的后继子效果 |
| `Condition(A,B)` | 卡面红箭头或明确的条件式：执行到本节点时结算左侧，真实支付/移除完成后才创建右侧；条件不成立只影响其右侧，不连带跳过其他独立条目；普通右侧失败不回退已经完成的左侧 |
| `EntryCost(A)` | 行动入口本身的费用，按入口合同校验并受理；与效果内部`Condition`左侧分开，不把整棵效果树的条件预收为入口总费用。此名称为规格记法，不是现有Lua API |
| `Choice(A/B)` | 只创建所选分支；`可选`允许不执行该项 |
| `Repeat(n,A)` | 按次选择与执行，中途状态改变须更新候选 |
| `RegisterRule(来源,时点,规则)` | 注册能力牌或已选抉择面的持续能力；保留来源、触发事件和次数记录 |
| `设置` | 选定企业家入场时执行一次，保存完成状态；不是每回合效果，恢复会话不重复发放组件或移动标记 |
| `本回合收尾` | 已登记的一次义务；全体玩家收尾效果及新增义务、后续响应全部完成后才统一复位使用轨道，不在各玩家结算期间复位 |
| `收尾任意次` | 同一收尾窗口保留来源入口，每次点击建立独立执行，完成返回收尾区；放弃只结束本次执行，库存暂缺时不可执行、补足后重新可用，窗口正式关闭才结束本次收尾机会。与“收尾一次”不同，详见L09 |
| `GainCommand/Reputation(n)` | 指令/声望是能力牌上的真实玩家标记；取得可以拒绝，供应不足不能生成虚构标记 |
| `PayCommand/Reputation(n)` | 从对应能力牌移出实际标记；未明确写“放回游戏盒”的标记移除／支付均返本人玩家供应区，包括指令、普通声望及第五号兑换标记；明确回盒则永久离开本局 |

源岩、源石碎片、异铁、至纯源石、金券沿用已有资源。指令和声望分别是能力区中的真实玩家标记，不是新增资源；帮派是独立标记类型。黑色影响力图标沿用基础操作资格，涉及己方、非帮派、资源点或原位置时按卡面额外过滤。企业特效直接选特效；单纯升级才选择企业。合作等级封顶5，满级升级成功无效果；分数没有下限。普通操作空集合成功结束，不完整Effect跳过并记日志，但真实条件费用不足不能当作已支付。

效果边界以卡面独立条目为准，不以整个卡面或页面操作顺序为单位。A3B、T5A、T5B各有两条独立立即效果；P5B的失分、资源和特派则在同一条立即内。每条内部保留原本的逗号、顺序和条件作用范围。A1A/A1B的立即2指令与每盖放阶段1指令属于不同触发来源，阶段效果不接在立即效果后，也不依赖玩家是否接受立即指令。

### 模式的公共流程

开局先抽取并分配合作企业候选板，各玩家已知道自己的候选企业后，从末位玩家起逆时针各选择1位未被选择的企业家，拿能力牌、该企业家的4张抉择牌和配件，执行设置；最后从原先分配的企业候选中决定初始企业，不重新抽取。三/四人局每人先知道自己的2张候选，再选企业家，最后2选1；二人局沿用每人先抽4张、选企业家后4选2。未选企业家及组件退出本局。每张抉择对应第1、3、5、7回合，A/B是同一张卡的两面，不能按8张独立卡发牌。

上述四个回合的供应裁牌后、盖角色前，按正常行动顺序公开选择对应抉择的一面：保存已选状态并激活该面的持续规则及行动，再分别调度每条独立立即效果。需要作用于本面立即效果的条件规则必须已生效；艾格尼丝第三回合B面的指令加价就是规则书明确的例子。不同立即条目保留独立身份和恢复进度，按序调度不把它们串成同一效果。未选面不执行，也不注册。旧回合已选面保留到游戏结束。

以上实体数量与A/B是本文件官方卡面内容的规格，不是DIY选择数上限。用户已明确同一回合可有更多DIY候选，因此通用数据和页面按“回合选择组＋候选列表＋所选候选身份”实现。局内企业家区域从左到右展示能力牌及第1/3/5/7回合牌位；未抉择牌位点击同时查看本回合全部候选。入场选企业家使用卡牌选择页，只列可选企业家的能力牌，详情展示该企业家的完整抉择牌组并按回合排列。通用页面合同见[实装方案的页面规格](实装准备与待确认事项.md#企业家页面与交互实装规格)，五位逐效果流程统一见[企业家逐效果页面流程](企业家逐效果页面流程.md)。

带未使用/已使用轨道的行动，每回合只能使用一次。轨道需要真实玩家标记；供应无标记时，规则书要求取回自己1枚影响力放在未使用处。用户明确：所有参局玩家的收尾效果、期间新增的本回合义务及其后续响应全部结算完成后，才统一进入轨道复位步骤；四人局须等四人全部完成，二/三人局按实际人数，不能每人结算完就先复位自己的标记。每回合一次轨道此时将已使用标记移回未使用处，有限次数轨道仍按各自转换规则处理。频率键按“来源卡＋行动”，不能因使用入口变化、重连或不同玩家行动窗口而重置。

城市样式迁入同一注册机制时，须保留首次与后续宣告的区别：同玩家同卡首次一级按牌进入未使用或已宣告，首次二级进入2；后续标记只放已宣告区或宣告条件旁，不重复授予特殊行动或增加次数。每次宣告的真实标记和记录不等于每次都新建可用行动轨道。当前逻辑槽位`declared`可以承载已宣告区或条件旁的状态，不要求各卡面都有独立印刷框；详见[实装方案](实装准备与待确认事项.md)。

现状例外：城区管理中心回收同卡本人最后一枚标记后，宣告历史仍在，但当前执行器用“仍在牌上的宣告数量”判断首次，导致再次合法宣告重新放入2并获得次数；尚不能正确进入已宣告。此缺口需修正首次判定及现有测试期望，不能把上段规则合同误写成该回收场景已经实现。本次只记录核查结果，未改代码。

能力牌在对应企业家入场时完成设置并登记持续能力，不等待第1回合选面。能力牌与回合抉择牌分别保留来源；后续抉择增加或修正基础能力，不重复执行能力牌设置。下列每位企业家的“能力牌”表与“回合抉择牌”表共同构成完整效果规格，不能只录入回合表。

### 能力牌（A01）

| 时点/类型 | 卡面效果文字（图标以文字表示） | Effect式 |
| --- | --- | --- |
| 持续能力 | 你在游戏中会获得指令、解锁专属的战术行动。 | `RegisterRule(A01,指令取得/支付与战术调用,下列标记及入口规则)`；具体指令收益与战术内容由相应效果提供，本句不额外发放初始指令或战术 |
| 获得指令时 | 获得指令时，在此牌上放置玩家标记以记录；玩家可以选择不获得指令；若没有玩家标记，则无法获得指令。 | 统一Lua封装`GainCommand(n)`：未加价为一个可放弃的`Choice(取得n指令/…/取得1指令)`；加价且n>1为一个可放弃的`Choice(Condition(付2n券,取得n指令)/…/Condition(付2券,取得1指令))`；加价且n=1直接2券条件。Choice用“结束行动”放弃当前请求，不把“不获得”当Effect。所选数量固定转移实际k枚，不再问剩余数量或递归调用封装 |
| 支付指令时 | 支付指令时，在此牌上移除玩家标记以记录。 | `PayCommand(n)=MovePlayerMarker(A01指令区实际n枚→本人玩家供应区)`；不足n枚不能完成支付，返供应去向已由用户确认 |
| 战术的快速行动入口 | 执行战术行动时，支付2指令将其作为快速行动。 | `选择已解锁且本回合未用战术T；EntryCost(PayCommand(2))；调用T原效果树`；T内的条件在执行到相应节点时单独处理 |
| 战术的特殊行动入口 | 执行战术行动时，获得10金券将其作为特殊行动。 | `选择已解锁且本回合未用战术T→特殊行动 [执行战术T,GainResource(金券,10)]`；战术自身费用另付 |

战术行动有两种入口：支付2指令，作为快速行动执行；或作为特殊行动执行并获得10金券。**特殊入口是获得10金券，不是支付10金券。**两种入口共用同一战术行动的每回合一次额度（规则书印刷第5页）。特殊入口仍占对应主要行动中的特殊行动；快速入口按游戏的快速行动窗口运行，不额外生成任意主要行动预算。

上述入口调用同一项战术的完整子树，不把入口变成另一项战术。战术正式发动时，快速/特殊行动统一内核根据声明移动其真实使用标记；企业家Lua不另写移动标记或已用登记。快速入口的2指令须先支付，特殊入口正式受理后进入战术；5B则在收尾条件支付成功、选定战术后通过同一内核直接调用。内部条件不执行、不成立或被放弃，仍算已经执行战术，不恢复标记。3B战术放弃2碎片条件时不移除/放置影响力，但快速入口费用不退，特殊入口的10金券仍照常结算。无合法目标同样保持已用，不能换入口再次发动；未提交草稿、快速入口费用未付成或5B尚未选定战术，不视为战术已发动。J-Q05已关闭。

快速入口2指令是入口费用；3B战术的2碎片是该战术`Condition`左侧；5B收尾的2指令是该收尾效果`Condition`左侧；加价取得所选k枚指令的2k金券是该数量分支内同一个条件的费用。这几者不能合成一个入口总报价或重复扣取；所选k枚仍在本条件中足额支付2k金券。特殊入口10金券仍是收益。具体节点按当时状态结算，不能因某条内部条件目前不满足就把其他独立效果一并禁止。

#### 由能力牌读取抉择状态的共用实现

采用A01承载共用处理器的方案：能力牌读取本人已确认、已启用的回合选项，决定哪些共用能力生效。回合卡仍保留卡面文字、选择身份、立即效果及独有能力；迁移的是重复实现，不改变规则来源和触发时点。下列选择状态投影和内容声明属于待实现合同，不能把本节伪式视为已公开API。

| 共用内容 | A01处理方式 | 回合牌职责 |
| --- | --- | --- |
| 1A/1B每角色盖放阶段1指令 | A01只有一份阶段处理器；本人第1回合有效选项声明启用此规则后，盖放阶段到达时独立调用`GainCommand(1)`，按玩家、回合和阶段记录一次 | 各面仍各有独立`立即 GainCommand(2)`和自己的战术；立即是否接受、取得几枚均不决定阶段触发 |
| 3A/3B每枚指令2金券 | A01统一Lua封装按有效规则生成免费可放弃数量Choice，或付费可放弃数量Choice（n>1，各数量对应支付2k券取得k枚），或直接单枚2券条件（n=1） | 所选面的共同加价声明先于本面立即效果生效；3B只挂一个列4/3/2/1的Choice，用“结束行动”放弃当前选择；3A独有离场订阅及联机旁路仍由3A提供 |
| 5A/5B终局影响力比较 | A01只有一份终局处理器，在有效选项声明启用后按原比较口径计分一次 | 5A城市移动事件响应、5B收尾调用及新战术分别保留在其所选来源，不并入共用能力 |

读取依据是权威已选候选ID、实际启用来源与该候选声明的规则，不以“当前回合≥3”、A/B布尔值或浏览中的候选推断。DIY新增候选可声明不同规则，不能自动套上官方加价。确认3B时先使选择与加价声明生效，再分别调度两条立即效果。所有取得来源使用同一Lua封装：免费一次选择取得k枚或不获得；付费多枚先选择数量分支，再由所选条件的付款窗口决定执行/放弃，单枚则直接条件窗口。条件右侧固定移动所选k枚，不再询问数量或是否接受，不调用`GainCommand(k)`递归收费。

按用户最新修订，撤销免费逐枚Choice及付费逐枚条件串。1A/1B立即2指令为一个可放弃的`Choice(取得2枚/取得1枚)`；3B为一个可放弃的`Choice(Condition(付8券,取4)/Condition(付6券,取3)/Condition(付4券,取2)/Condition(付2券,取1))`；5A加价后立即2枚为一个可放弃的4券取2/2券取1 Choice。“不获得指令”不是Effect，不作为0候选、`decline`候选或空效果分支；玩家用“结束行动”放弃本次选择。只执行选中的数量，不在选择k枚后继续询问n−k枚，也不在放弃所选付款后自动重开Choice。按实际供应与费用校验，固定移动k枚不同的真实标记；不得少付、少给或付款后静默改量，必要依赖沿用等待合同。保存所选数量、支付及转移收据，恢复不重复领取。企业家载体、固定数量转移及共用Lua组织仍按实装方案补齐；该封装不是新增内核专用API。

## 终局规则的执行合同

规则书总览仍是企业家特殊计分→区控→剩余资源。有些绿色计分条款修改区控算法或在企业家计分时发资源，不能把全部绿色条款简单转成结束时一次`GainScore`。

具体接入见[第四项技术提案](企业家逐效果页面流程.md#终局结算与区控合同第四项技术提案用户已确认待实现)：先对照现有RoundEnded、FinalScoringStarted、RegionControlService及FinalScoringService，再复用阶段执行和普通Effect，补只读修正、区控快照与分项提交。技术方案已获用户确认，阶段及返回结构仍待实现；已经通过Effect发放的特殊分数不在汇总中再加一次。

建议先登记所有计分修正，形成最终地图与设施视图；企业家特殊计分按该视图执行（例如M07获得的异铁会进入后续剩余资源计分）。需知道控制者的条款用同一份应用修正后的区控查询结果，随后只正式入账一次区控分，再按各玩家自己的资源计分配方入账。规则上下文、自动选定的计分格及计数依据、资源快照、逐项分数和结算完成标记均持久化；M3B自动取设施最多格，不创建手动选格请求。

区块影响力修正、并列控制优先、区块价值修正和“每控制/每有帮派额外得分”是四类不同合同。P07只替换保罗的资源公式；T01是额外奖励，不替换公式。A02的并列规则已由用户确认：本人用于区控的有效影响力须大于0且并列最多，不能把无人有影响力的0比0当作占领；J-Q09已关闭。缺候选与不完整式继续沿用已批准日志规则，不宣称尚未完成的模式已可玩。

# token能力与岩蹄安保合约改动方案

**状态：实装方案，尚未实施。更新日期：2026年10月19日。**

将现有授勋卡的能力来源接入扩展为通用物品能力来源，让卡牌、合约和token复用同一套能力声明、Lua宿主及来源校验。补齐区控接口后，将岩蹄安保终身安保合约的“本区公司影响力每2算1”迁入该合约自身的Lua有效影响力修正。

本方案承接[实装准备与待确认事项](实装准备与待确认事项.md)和[卡面效果与Effect式](卡面效果与Effect式.md)。下面的声明字段含义、处理流程和返回数据是待实施合同，不是已经存在的JSON字段或Lua API。实现时统一确定字段名，不得将本文伪式直接当作可运行脚本。

## 改动范围

本次规划包含通用物品能力注册、持有与生效资格、收尾及其他受支持事件的接入、次数与恢复记录，以及岩蹄安保合约的终局区控迁移。普通物品只有声明能力并满足生效条件后才提供效果；扫描到一个物品，不等于执行其全部脚本。

终局区控迁移应同时适用于未开启企业家的感染者基础模式和开启企业家的模式。正常采集的合约行为继续保持正确；区域信息展示暂不处理，不纳入本次交付。快速行动和特殊行动复用既定的统一注册方案，企业家或token内容不单独移动使用标记，也不新增专属UI分支。

## 通用物品能力来源

### 声明与运行事实

JSON负责说明物品具有什么能力、何时生效和调用哪个脚本；Lua负责效果内容或规则计算；内核负责判断来源是否合法、调度、交互、记录和恢复。

| 内容 | 必须表达的信息 |
| --- | --- |
| 定义与脚本 | 物品定义ID、能力ID、脚本及版本；继续使用现有内容哈希校验 |
| 触发类别 | 收尾、指定事件、快速行动、特殊行动或规则查询；每项能力明确自己的入口 |
| 生效位置 | 持有区、已启用区、地图或其他受支持区域；未声明为生效位置的区域不提供该能力 |
| 授权关系 | 由持有者、控制者或公共卡的有效授权关系确定执行及受益玩家；不能仅凭物品外观或颜色授权 |
| 使用限制 | 按卡面声明每轮、每阶段、一次性等限制；绑定玩家标记的行动以统一行动内核维护的真实位置为准 |
| 收尾交互 | 收尾条目及文案、整项必做或可放弃、可用性判断，复用既有结算声明 |
| 规则返回 | 修正类别、作用对象和处理器；返回值只能影响该查询允许的范围 |

运行时来源至少能追溯到真实物品实例ID、定义ID、能力ID、授权玩家和生效依据。同一定义有多个真实实例时，必须区分实例；同一个实例的一项能力也不能因同时经过旧、新注册链而登记两次。

来源资格按当前权威状态确定。取得、移动、转移控制、离开生效区域后，后续事件和查询应使用更新后的资格；恢复时从保存的真实物品及能力记录重建。可为查询建立索引，但索引不能成为独立的持有状态或漏掉失效来源。

公共卡仍可以通过玩家宣告标记等有效关系提供能力。通用来源查询不能只扫描“所有者是当前玩家”的物品，否则会遗漏城市样式。公司影响力仍是公司的物品，不能为了给合约持有人提供修正而改成玩家所有。

### 按入口分流

| 能力类别 | 生效流程 | 边界 |
| --- | --- | --- |
| 收尾效果 | 玩家收尾开始→查询有效收尾来源→创建收尾条目→按结算顺序执行Lua | 不扫描所有物品后无条件执行；保留每条效果的必做或可放弃政策 |
| 事件响应 | 领域事件发生→匹配声明及有效来源→按事件合同调度Lua | 每个来源对同一事件去重；需要旁路响应的效果沿用事件响应合同 |
| 快速或特殊行动 | 查询有效来源→生成条目→提交时再次校验→由统一行动入口执行 | 没有行动声明就没有行动条目；使用标记的移动和复位由统一内核完成 |
| 规则修正 | 发起受支持的只读查询→查询有效来源→Lua返回结构化修正→内核合并 | 不生成收尾条目，不打开选择界面，不发分，不移动物品 |

“剩余游戏中生效”表达能力的持续资格，不固定等同于收尾。梅兰德的持续授勋卡声明收尾入口；岩蹄安保合约声明区控查询入口，两者共享来源机制，使用不同触发时机。

## 授勋卡流程迁入通用来源

以[梅兰德持续授勋卡](../../Assets/StreamingAssets/Content/core/award/infected.award.permanent_support.json)作为已有行为的迁移基准：

1. 内容加载时将收尾能力和脚本注册到通用目录。按声明注册处理器，不在获得卡牌时由Lua另挂一个永久监听。
2. `PlayerCleanupStarted`触发时，查找本玩家此刻有效的收尾能力来源。该授勋卡要求仍在本人玩家奖励持有区，并满足其持有关系。
3. 每个来源能力生成自己的收尾节点，携带实例及能力身份，接入现有收尾顺序页面。持续授勋卡当前整项可放弃的行为保持不变。
4. 正式执行时，通用执行器重新验证执行依据及次数，调用原[收尾Lua](../../Assets/StreamingAssets/Content/core/lua/awards/infected.award.permanent_support.cleanup.lua)。Lua继续返回3金券、任选1个基础资源、移动1个己方影响力。
5. 执行、放弃、恢复与重复提交由结算窗口和来源使用记录共同保证幂等。执行后的本轮使用记录必须在发布可重复响应的后续事件前写入；整项放弃按现有结算窗口的完成记录关闭，不能刷新后重新出现。

上述关闭与恢复规则针对每收尾一次的授勋来源，不将所有物品收尾能力强制为一次。D01／D02与T09按[逐效果流程L09](企业家逐效果页面流程.md#当前lua不能独立完成的通用改动)声明可重复来源：本次执行或放弃完成后保留来源入口，库存补足可再次执行，新点击有独立收据；不能重开已完成的同一次执行。

对事件和收尾使用次数的去重，需要区分来源实例、能力和适用事件或周期。不能只按定义ID去重而吞掉不同合法实例，也不能只换个取得节点就恢复本轮次数。绑定使用标记的快速／特殊行动不再额外维护一套相互独立的已使用布尔值。

物品离场后的新订阅资格与已经成立的效果义务分开处理：离场停止后续来源发现；已挂链段是否继续由对应事件或结算合同决定，不以删除来源为由一律撤销。通用化不能将收尾义务、已支付费用或事件响应默默取消。

已有授勋卡的奖励取得记录继续保留其取得事件和历史用途，但不再作为所有物品都必须具备的能力运行前提。迁移需覆盖存档中的`lastAwardCleanupKey`、已生成的收尾节点、结算条目及完成记录；恢复后不能重新注入本轮已执行或已放弃的条目。

## 岩蹄安保合约的Lua迁移

### 能力挂载位置

规则挂在玩家奖励持有区中的终身合作指示物上。当前代码将它表示为[终身安保合约](../../Assets/StreamingAssets/Content/core/contract/infected.contract.lifetime_security.json)，定义ID为`infected.contract.lifetime_security`，物理类型为`core.contract_card`，当前`abilities`为空。

给该定义增加有效影响力修正能力并绑定Lua即可，不为挂脚本改造物理类型，也不额外复制一枚token。地图上的公司影响力只提供数量事实，不让每枚公司标记各自注册整份合约规则。既有取得流程限制每名玩家持有一张合约，迁移不放开该限制。

玩家奖励持有区沿用既定更名方案。`core.zone.player_awards`是当前代码及旧存档标识；实施时统一迁移，不保留新旧两个并行持有区。

### 输入事实与计算结果

区控查询必须提供同一状态版本下的区域、来源、授权玩家以及真实影响力事实。Lua按公司主体`stonehoove_security`筛选当前区域内有效的公司影响力，使用与现有`ItemZoneQuery.IsInfluence`及区域归属查询一致的事实口径。不能用渲染颜色、公司资源库存或普通玩家标记数量代替真实影响力数量。

规则规格为：

```text
本区公司影响力数 = 当前区域中属于岩蹄安保公司的真实有效影响力数量
本玩家合约贡献 = floor(本区公司影响力数 / 2)
```

Lua返回本次查询允许的有效影响力增量及作用区域、受益玩家。来源身份由内核从调用上下文绑定或校验，脚本不能伪装另一张合约或任意指定其他玩家。返回结果保留实例、能力和贡献值，供最终区控结果追溯。

| 当前区域公司影响力数 | 每名有效合约持有人的增量 |
| --- | --- |
| 0 | 0 |
| 1 | 0 |
| 2 | 1 |
| 3 | 1 |
| 4 | 2 |
| 5 | 2 |

按区域独立整除，余数不跨区域合并。多个玩家各持有合法合约时，每人都取得该区的同一份贡献，不在持有人之间分摊。不持有合约、合约在公共供应或回盒等非生效区域时，不提供贡献。

该能力不消耗合约、不移动公司影响力、不修改公司所有权，也不直接加分。合约只有持续区控修正声明时，不产生快速行动、特殊行动或收尾条目。

### 接入区控计算

区控通用流程应先汇总普通影响力、城市基础贡献及全部适用的有效影响力修正，再判定正值最高集合与并列控制，随后应用区块分值修正，输出带来源分项的最终控制结果。

已确认技术方案的源码对照与接口合同集中在[终局结算与区控合同](企业家逐效果页面流程.md#终局结算与区控合同第四项技术提案用户已确认待实现)。该提案沿用现有计数与终局节点，补结构化只读返回、来源校验、统一快照、阶段恢复及分项入账；合约只参与有效影响力增量，不新增独立合约计分流程。 通用物品来源的注册／有效性合同及旧区引用迁移分别见[第十项](企业家逐效果页面流程.md#模式选择与统一来源接入合同第十项技术提案源码对照后讨论稿)和[第十一项](企业家逐效果页面流程.md#版本迁移与状态校验合同第十一项技术提案源码对照后讨论稿)；帮派的真实离场、旁路保管与挂链见[第十二项](企业家逐效果页面流程.md#离场响应与挂链改写补全合同第一项回查及第十二项技术提案源码对照后讨论稿)，不为token另建一套事件来源。

合约贡献与艾格尼丝7B的城市贡献修正、保罗5A的帮派区域修正等共同参与有效影响力比较。艾格尼丝7A读取完整有效值，不能退回比较己方普通玩家标记数。合约自身只返回影响力增量，不决定并列优先权、控制者或区块分值。

查询必须只读。同一状态、区域和来源得到相同结果；重复查询从基础事实重新汇总或读取同版本结果，不在上一次合计上再次加值。同一来源能力在一次区域查询中只应用一次，不同有效持有人的贡献各自保留。最终入账由终局计分流程完成，不能在查询或详情刷新中执行`GainScore`。

### 替换旧代码与保留行为

迁移时将[RegionControlService](../../Assets/YC/Domain/Scoring/RegionControlService.cs)中的合约专属累加替换为通用修正结果。新旧路径不得同时为同一持有人增加公司贡献；内核中不再用合约定义ID或公司ID直接实现该区控算法。

[CompanyInfluenceRules](../../Assets/YC/Domain/Influence/CompanyInfluenceRules.cs)还有公司合法放置、合约持有判断等用途；`HasContract`被[正常采集](../../Assets/YC/Domain/Harvest/ResourceCollectionService.cs)调用，`GetControlContribution`仍被[状态展示](../../Assets/YC/Domain/State/GameStateView.cs)使用。因此只撤换终局区控路径的专属计算，不整类删除。保留这些调用的正确行为，区域信息展示仍暂不改动。

## 实施顺序与交付内容

| 顺序 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1 | 通用能力声明和来源查询 | 组件、合约和现有卡牌可通过同一来源合同确定实例、能力、授权玩家及生效区域；未接入事件仍明确拒绝 |
| 2 | 通用执行入口和使用记录 | 清除对授勋卡取得记录的强制依赖，支持确定性恢复；现有授勋收尾接入通用机制后行为不回归 |
| 3 | 受支持事件及行动来源适配 | 来源发现共用，触发时机分别接入；角色既有生效条件、城市样式授权和统一使用标记规则保持正确 |
| 4 | 通用有效影响力修正接口 | Lua取得受控事实并返回只读修正，内核统一校验、合并和记录来源，进入最高值及并列判定前生效 |
| 5 | 合约JSON与Lua | 给现有合约增加能力声明，Lua实现逐区整除2规则，不增加专属UI或额外物品实例 |
| 6 | 切换区控与恢复兼容 | 移除区控中的旧专属累加；更新内容版本及保存兼容处理，保留正常采集和当前展示调用 |
| 7 | 验收 | 完成以下规则验证与正常流程覆盖，并记录未覆盖项 |

声明的具体字段名、规则查询返回结构以及旧记录迁移版本在通用接口实现阶段统一确定。上述字段含义和行为约束不因命名选择改变；已经保存的实例、已消费次数和已成立义务必须保留，不能通过清空效果运行状态完成迁移。

## 验收条件

| 类别 | 场景 | 期望结果 |
| --- | --- | --- |
| 来源发现 | 有能力的Cube组件或token处于声明的生效位置 | 能按相应入口参与，不要求经过授勋卡取得流程；保罗玩家级规则以P09为单一执行载体，不随四枚帮派重复触发 |
| 帮派与多萝西 | 合法帮派离场收容、混合标记支付及载体退出 | 同一帮派可收容和使用，保留类型与原供应，选择支付组合后真实返还；在牌上不计地图／供应，支付不再触发地图离场，恢复不重复 |
| 来源过滤 | 无能力物品，或合约处于公共供应、回盒 | 不执行脚本，不生成条目，不提供合约修正 |
| 来源变化 | 合法移动、授权变化或离场后再次查询 | 后续资格准确更新；旧命令重新校验，已成立义务按所属合同处理 |
| 入口分流 | 只声明区控修正的合约 | 不出现在快速、特殊或收尾条目中 |
| 授勋回归 | 持续授勋在本玩家收尾 | 通过既有页面选择结算顺序；资源与影响力效果正确，整项可放弃 |
| 收尾次数 | 执行或放弃后重复提交、刷新、恢复 | 本轮不重入；下一轮仍持有时重新提供一次 |
| 实例去重 | 同一实例被重复发现，或存在不同合法实例 | 同一来源能力不重复登记；不同合法实例不因定义相同被吞掉 |
| 合约计数 | 每区0、1、2、3、4、5枚公司影响力 | 合约贡献分别为0、0、1、1、2、2 |
| 区域边界 | 相邻两区各1枚公司影响力 | 两区贡献都为0，不跨区配对 |
| 多人持约 | 两名玩家各持合约，某区4枚公司影响力 | 两人各增加2；无合约玩家不增加 |
| 合并规则 | 同时存在城市、企业家及合约贡献 | 先合并全部有效影响力，再裁定正值最高与并列，保留各来源明细 |
| 只读查询 | 同一状态重复查询、保存恢复后查询 | 结果一致，不加分、不移动物品、不累加旧结果 |
| 旧新切换 | 合约Lua启用后的终局区控 | 仅按通用修正计算一次，不叠加旧C#贡献 |
| 原有行为 | 未开企业家模式、正常采集及公司归属 | 基础模式合约仍生效，正常采集和公司独立主体行为不回归 |

规则定位可以使用隔离测试，但不能计作正常界面验收。实际页面和对局验收从可见独立程序的正常建房、开局、合法取得合约或授勋卡及正常结算进入；随机候选未出现时记录本局缺口，通过多局累积覆盖，不注入物品、修改资源或强制状态。按版本或内容哈希、GameId及实际证据记录结果。区域信息展示不在本次验收范围内。

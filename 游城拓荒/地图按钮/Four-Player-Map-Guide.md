# 四人地图：高亮贴图使用说明与坐标表

适用文件：`四人.jpg`，2048×2048。版本：Map Highlights v1.0。

本图已定位 **22 个资源点、22 个航道、77 个影响力槽位**。航道分为 11 个单槽、11 个双槽；槽位总数为 `22×2 + 11 + 11×2 = 77`。

本图专用导入数据：`data/four-player-map.json`。共用贴图参数：`data/assets.json`。

## 贴图与状态

资源点沿阶梯形外轮廓高亮；航道高亮包住三角标、字母条和槽位底条，**不沿整条白色航线绘制**。影响力槽位使用单独的方形高亮。资源点和航道内部的槽位只有在需要选择该槽位时才另行高亮。

所有类别都提供两个状态：`available` 为可选择，使用较细的冷青亮边；`selected` 为已选择，使用更亮、更粗的暖金亮边。中央完全透明，光晕向外衰减。选中时替换贴图，不把两种状态叠加；不可选择时隐藏高亮。

B-01 与其他资源点使用相同尺寸、相同轮廓、相同导入方法。上方入场奖励不参与资源点的几何尺寸与中心计算。

|---|---|---:|---:|---:|---:|
| 资源点 | `resource` | 202×208 | 20 | **242×248** | 968×992 |
| 单槽航道 | `route-single` | 118×64 | 16 | **150×96** | 600×384 |

表中尺寸均以原图像素为逻辑单位。`1x`、`2x`、`4x` 是同一贴图的采样倍率，不是三种显示大小。比如使用 `resource-selected@4x.png`，显示尺寸仍按 **242×248** 乘地图缩放计算，不能直接按 968×992 显示，也不能只按内部轮廓的 202×208 显示。

文件位置：`assets/png-1x/`、`assets/png-2x/`、`assets/png-4x/`；可编辑源文件位于 `assets/svg/`。每组有 8 张贴图，3 类用途，其中航道分单槽、双槽两种形状。命名例：`assets/png-4x/route-double-selected@4x.png`。

## 坐标约定

- 原图为 **2048×2048**。原点是整张图片的左下角，包含外框、计分轨、标题，不能改用内部地形区域的左下角。
- X 向右增加，Y 向上增加。表中 `(x,y)` 是贴图中心，单位为原图像素。
- 所有贴图的 pivot 都是 **(0.5, 0.5)**。轮廓四周留白对称，因此贴图中心与轮廓包围盒中心一致；不要另外添加留白补偿。
- 资源点中心是整个阶梯形标记的包围盒中心，不是右侧灰色长方形的中心。航道中心是包括三角标在内的整体包围盒中心，不是字母或槽位组中心。
- `u=x/2048`，`v=y/2048` 是左下原点的归一化坐标。表中显示 6 位小数，JSON 保存 8 位；导入优先使用 JSON 的原图像素坐标。
- 坐标使用图片边缘坐标：边界是 0 和 2048，像素中心位于 `i+0.5`。左上原点转换是 `topY=2048-y`，不是 `2047-y`。

## 导入与缩放

假设原图完整显示在内容矩形 `(left, top, displayWidth, displayHeight)` 中，其中 `(left,top)` 是显示图片的左上角：

```text
sx = displayWidth  / 2048
sy = displayHeight / 2048
screenCenterX = left + x * sx
screenCenterY = top  + (2048 - y) * sy
spriteWidth  = logicalWidth  * sx
spriteHeight = logicalHeight * sy
```

使用保持比例后的**实际图片内容矩形**计算，不使用包含上下或左右空白的外层容器。地图裁剪、平移、旋转、缩放后，高亮应继承同一变换。最简单的做法是让地图与高亮共用一个以 2048×2048 为逻辑尺寸的父级。

如果地图是放在场景内的平面并经过透视相机显示，把高亮放在地图同一平面：`localX=(u-0.5)*mapWidth`、`localY=(v-0.5)*mapHeight`，再使用地图本身的世界变换；不要把这里的原图坐标直接当屏幕坐标。若地图平面使用 XZ 轴，将第二个坐标映射到该平面的 Z 轴。

导入使用完整矩形网格和透明混合，保留 Alpha 与四侧留白。不要自动裁边、九宫格拉伸、按图案紧密裁网格或只使用“非透明像素包围盒”定位。推荐使用 2× 或 4× PNG，以便地图放大后边线仍平滑。图集打包时保留留白，不使用重复平铺。

点击区域与发光区域分开：可按 `data/assets.json` 的 `polygon_top_left` 建立资源点／航道命中轮廓；槽位使用 34×34 的逻辑矩形。光晕不应扩大点击范围。该多边形以轮廓左上角为局部原点；转换到左下原点局部坐标时，`localX=px-outlineWidth/2`、`localY=outlineHeight/2-py`。

## 编号约定

资源点沿用原图的 A-01 等编号。航道的 `L01`、`L02` 等是本包按画面从上到下建立的定位编号，区域字母仍按地图原标记记录；这些编号不代表游戏规则中的路线顺序或邻接关系。

资源点的 `S1/S2` 分别指上槽、下槽。双槽航道的 `S1/S2` 分别指左槽、右槽，单槽航道只有 `S1`。槽位表的“序号”用于叠图定位，真正导入建议使用完整 `id`。

**三人、四人地图的坐标必须分开读取。** 两张地图中的同名资源点、同名 L 编号都可能位置不同；程序索引使用 `(map_id, id)`，不要仅用 `id` 合并两张地图。

## 已做的校验

1. 从原图的白色方槽逐个检测位置，确认 77 个槽位无重复、无遗漏，并分配到 22 个资源点和 22 个航道。
2. 使用交付的 PNG，按本表的中心与含留白逻辑尺寸叠回原图；逐项查看资源点、航道、槽位局部图。航道左下斜边在检查后做过轮廓校准。
3. 用 215、225、235 三种白色检测阈值复查槽位中心，最大中心变化为 **1.12 个原图像素**。这是检测稳定性指标，不等同于未知矢量原稿的绝对误差。JPG 边缘存在抗锯齿与压缩软化，统一轮廓按该图做贴合校准。
4. 检查全部 1×／2×／4× PNG：尺寸正确，中心 Alpha 为 0，画布四边最大 Alpha 为 0，外发散光晕没有被画布裁掉。
5. 核对左下原点与左上原点可互相转换，所有中心都在 2048×2048 内。未在游戏工程中执行集成测试。

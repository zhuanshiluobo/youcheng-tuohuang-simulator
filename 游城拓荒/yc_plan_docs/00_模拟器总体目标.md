# 模拟器总体目标

## 1. 项目定位

《游城拓荒：铸基者》2D Unity 模拟器的首要目标，是把基础版规则转化为一套可运行、可验证、可扩展的数字规则系统。当前阶段不追求完整复刻实体桌游的全部美术细节，而是优先保证规则流程正确、玩家操作清晰、结算可追踪。

模拟器面向本地 PC 热座使用，先支持 3 到 4 人基础版游戏。后续可以逐步扩展到完整桌面 UI、AI、联网、企业扩展版和更完整的视听表现。

## 3. 产品目标

### 基础目标

- 完整模拟基础版 3 到 4 人游戏。
- 支持开局入场、8 回合拓荒探索、采集资源、收尾和最终计分。
- 支持主要行动、快速行动、角色牌、事件牌、设施牌和城市样式牌。
- 自动处理费用、路径、资源、影响力、设施、区控和胜负结算。
- 记录所有玩家操作和规则事件，支持回看、调试和回放。

### 体验目标

- 玩家不需要手工计算路费、资源收益、设施费用和最终计分。
- 每次关键操作在确认前能看到费用、影响和非法原因。
- UI 只负责展示状态和提交命令，不直接修改规则状态。
- 规则日志能够解释每一步为什么发生，便于查错和复盘。

### 工程目标

- 规则核心使用纯 C#，不依赖 Unity 场景对象和 `MonoBehaviour`。
- 玩家操作统一通过命令系统进入校验与结算流水线。
- 游戏状态必须可序列化，以支持存档、回放和自动测试。
- 地图、卡牌、效果、计分规则尽量数据化，少量特殊规则由专用 resolver 处理。
- 为企业扩展版、AI 和联网保留结构空间，但不让它们阻塞 MVP。

## 4. MVP 边界

### MVP 必须包含

- 3 到 4 人热座。
- 基础版地图图模型。
- 开局入场流程。
- 8 回合固定状态机。
- 角色牌盖放。
- 两轮玩家行动。
- 部署、调度、探索、城市移动、建设。
- 简化但规则正确的快速行动接入点。
- 资源采集与阶段路费规则。
- 收尾阶段。
- 最终计分和平局判定。
- 操作日志和基础回放。
- 规则单元测试与关键场景测试。

### MVP 暂缓内容

- 完整动画与音效。
- 高完成度牌面和桌面美术。
- AI 玩家。
- 本地或远程联机。
- 企业扩展版规则。
- 完整新手引导。
- 自定义地图编辑器。

## 5. 架构原则

- `Domain` 只表达规则，不引用 UnityEngine。
- `Application` 管理一局游戏的生命周期、命令提交、事件派发、存档和回放。
- `Presentation` 只读状态、展示状态、提交命令。
- `Infrastructure` 负责存档、回放、数据加载、资源加载和调试工具。
- `Data` 负责地图、卡牌、效果、图标和计分配置。
- `Tests` 从第一天覆盖路径费用、行动校验、资源结算和最终计分。

## 6. 长期方向

- 规则闭环稳定后，补全桌面 UI：地图热点、卡牌区、玩家面板、行动面板、费用预览和日志面板。
- 以回放系统为基础建立规则回归测试和自动模拟。
- 用规则开关接入企业扩展版，而不是改写基础版主流程。
- AI 和联网都通过同一套命令系统接入，避免规则分叉。

# 测试与验收计划

## 1. 总体目标

测试体系的目标，是保证模拟器规则正确、状态稳定、日志可复查、回放可复现。MVP 阶段测试优先级高于视觉完成度。

## 2. 测试分层

### Domain 单元测试

测试纯 C# 规则核心，不加载 Unity 场景。

覆盖：

- 资源增减。
- 影响力放置、移动、移除。
- 地图邻接和航道查询。
- 路径枚举和费用计算。
- 行动校验。
- 行动结算。
- 效果执行。
- 区块控制。
- 最终计分。

### Application 流程测试

测试 `GameSession`、命令流水线和阶段推进。

覆盖：

- 新游戏创建。
- 开局入场。
- 回合开始。
- 角色牌盖放。
- 两轮玩家行动。
- 采集资源。
- 收尾阶段。
- 第 8 回合后进入最终计分。
- GameOver 状态。

### 回放测试

用固定 seed 和命令序列重放关键局面。

覆盖：

- 固定命令序列得到固定最终状态。
- 修改规则后能发现最终分数或资源变化。
- 非法命令不会进入回放日志。
- 待处理选择能被稳定重放。

### 随机模拟测试

随机生成合法命令序列，检查规则系统不会进入非法状态。

覆盖：

- 资源不出现非法负数。
- 影响力总数守恒。
- 当前玩家推进不丢失。
- 阶段状态机不卡死。
- 可执行命令列表为空时能明确结束或进入下一阶段。

## 3. 必测规则场景

### 路费计算

验收标准：

- 能从移动城市所在地枚举到目标资源点的可用路径。
- 航道费用按规则计算。
- 遇到多个对手影响力时产生支付对象选择。
- 采集阶段同一航道只支付一次路费。
- 采集阶段刚获得的金券不能用于支付本阶段路费。

### 资源采集

验收标准：

- 只能采集自己有影响力或移动城市停靠的资源点。
- 每个资源点每次采集只获得一次资源指示物收益。
- 支付失败时不获得资源，状态不变化。
- 多资源点采集能正确合并费用和收益。

### 影响力

验收标准：

- 部署消耗供应堆影响力。
- 调度保持影响力总量守恒。
- 城市移动、事件、设施和卡牌移除影响力时记录来源和目标。
- 影响力槽满时不能继续放置。

### 城市移动

验收标准：

- 支付 3 源石后才能移动。
- 移动目标必须合法。
- 出发点按规则放置影响力。
- 路径与目标点上的对手影响力按规则处理。
- 移动城市在区控中按 2 影响力计算。

### 建设

验收标准：

- 费用不足不能建设。
- 设施供应或限制条件不满足不能建设。
- 建设成功后设施进入玩家城市面板。
- 设施分数和入场效果正确结算。

### 最终计分

验收标准：

- 区块控制分数正确。
- 剩余资源分数正确。
- 设施相关分数正确。
- 城市样式相关分数正确。
- 平局按剩余金券、剩余至纯源石依次比较；仍相同则共同胜利。

## 4. 文档与计划验收

本次生成的计划文档验收标准：

- 文件位于 `F:\hby\游城拓荒\模拟器计划与目标`。
- 总体目标单独成文。
- 具体计划按目标段落归类。
- 明确引用最新资料目录和 Unity 项目路径。
- MVP 始终聚焦规则闭环。
- 每个计划文档都有可执行的完成标准。

## 5. MVP 完成定义

MVP 视为完成时，应满足：

- 可创建 3 到 4 人基础版游戏。
- 可从开局入场推进到最终计分。
- 五个基础主要行动可用。
- 快速行动和效果系统有最小可用接入。
- 采集、收尾、计分规则可测试。
- 操作日志完整。
- 至少一条完整回放 golden case 可重放。
- 核心规则测试通过。

## 6. 暂缓测试

以下测试不进入 MVP 必须项：

- 联机同步一致性测试。
- AI 决策质量测试。
- 大规模性能测试。
- 完整动画时序测试。
- 多语言 UI 测试。

# 结算区域插入效果按钮 · v1.0

这是嵌入现有结算区域的横向按钮条。暖米色圆角按钮沿用主界面的深褐底、细边框与克制的金色；不含切角或金属高光。按钮按效果加入顺序从左向右排列，超出可视范围后横向滚动，不显示滚动条。

## 一、布局与安全边距

以下数值是 1920×1080 设计基准下的逻辑像素。画面适配其他分辨率时统一缩放整套 UI，不分别缩小字和边框。

| 项目 | 默认值 |
| --- | ---: |
| 结算槽高度 | 60 px |
| 按钮高度 | 44 px |
| 按钮顶部／底部留白 | 各 8 px |
| 可滚动区域左右安全边距 | 各 24 px |
| 按钮之间距离 | 10 px |
| 左侧固定标题预留宽度 | 152 px，可关闭 |
| 结算槽最小宽度 | 136 px |
| 标题自动收起阈值 | 结算槽宽度小于 520 px |

层级为：结算槽背景 → 固定标题（可选）→ 裁切窗口 → 单行按钮容器 → 按钮 → 小图标／文字。提示浮层在裁切窗口之外绘制。

设结算槽宽度为 `W`，固定标题预留为 `R`，左右安全边距均为 `P=24`：

```text
R = 有标题且 W >= 520 时取 152，否则取 0
Viewport.x      = R + P
Viewport.y      = 8
Viewport.width  = W - R - 2P
Viewport.height = 44
第一个按钮.x    = 0     // 相对 Viewport 内容容器
后一个按钮.x    = 前一个按钮.x + 前一个按钮.width + 10
```

**安全边距在裁切窗口外，不随内容滚动。** 不能只给滚动内容加 Padding：那样滚动后边距会被吃掉。所有按钮，包括入场动画中的按钮，都必须被这个内部窗口裁切。右端最后一个按钮可完整显示到 `W-24`，两端的 24 px 永不被覆盖。

预览沿用现有主界面槽位：左上坐标约 `(190,1000)`，尺寸 `1420×60`。保留标题时，按钮可视窗口左上为 `(366,1008)`，宽 `1220`、高 `44`。这些是当前预览的放置值；组件只依赖自身容器尺寸，移动结算槽时不用重做素材。小屏幕不能给组件分配小于 136 px 的宽度，应由外层布局调整。

固定标题默认写“结算区域”，第二行可显示“建设结算中”等简短上下文。按钮条可作为结算区域的一种内容模式；若项目已有标题或底板，只保留本组件的 Viewport 和按钮部分即可。

## 二、文字和图标如何自动定宽

字体默认 18 px，单行，使用项目已有中文字体。**测量实际渲染字体的文字宽度，不按字符数量估算**；字体加载、文字变更和容器尺寸变化后重新测量。

| 内容模式 | 内部排布 | 宽度 |
| --- | --- | --- |
| 纯文字 | 文字居中，左右至少各 16 px | `文字宽 + 32`，最小 88 px |
| 图标＋文字 | 图标 22×22，间距 8，整体居中 | `文字宽 + 22 + 8 + 32`，最小 88 px |
| 纯图标 | 22×22 图标居中 | 固定 48 px |

文字类按钮按 2 px 向上取整；最终宽度上限是 `min(280, Viewport.width)`，该上限按 2 px 向下取整。宽度计算依据完整文案，完成限宽后才进行单行省略。不要缩小字体，也不自动换行或拉长图标。

例如使用本预览字体、18 px 时，“使用减价卡”为 122 px，“企业合作＋图标”为 134 px，“异客 · 建设减免＋图标”为 196 px。字体不同，计算结果可以略有不同。

超长标题以 `…` 截断。悬停或键盘聚焦显示完整名称；纯图标也必须提供完整名称作为提示和无障碍标签。触屏项目应同时在现有说明／卡牌查看界面提供效果详情，不依靠悬停提示传递使用条件。通常应先缩短按钮文案，详细规则放在说明中。

按钮在悬停、按下、处理中、不可用之间切换时不改变宽高。状态改变不应引发队列抖动。

## 三、素材导入与九宫格

| 素材 | 1× 尺寸 | 2× 尺寸 | 九宫格 L / T / R / B |
| --- | --- | --- | --- |
| 按钮整底／独立底色／独立边框 | 192×44 | 384×88 | 1×：22 / 21 / 22 / 21 |
| 同上 2× 导入切片 | — | 384×88 | 44 / 42 / 44 / 42 |
| 焦点框 | 192×44 | 384×88 | 与按钮相同 |
| 示例图标 | 24×24 | 48×48 | 不切片，等比显示为 22×22 |

按钮圆头的逻辑半径约 21 px。左右端盖固定，只拉伸中段；不要把 192×44 整图直接缩放到任意宽度，否则端盖和边线会变形。2× 图片仍显示为同一逻辑尺寸。高度默认固定 44；需要更大触控尺寸时整体等比放大，包括字体、间距和切片显示尺寸。

PNG 为透明背景、sRGB、直通 Alpha。UI 色调设为白色，素材透明度为 1，不叠额外有损压缩或统一灰色滤镜。文字和图标单独绘制。

`state` 文件名：`default`（可用）、`hover`（悬停）、`pressed`（按下）、`pending`（处理中）、`disabled`（不可用）。悬停与按下只作用于可用按钮。`focus-ring` 可独立叠加在可用按钮上，不能作为另一份底图。

图标默认用深色版；处理中用浅色版；不可用用弱化色版。用户自备彩色图标时保持原色，不套单色图标的颜色滤镜。

## 四、横向滚动

内容总宽：`C = Σ按钮宽度 + max(0, 数量-1) × 10`。滚动范围：`0 … max(0, C-Viewport.width)`。不挤压按钮、不换行、不显示滚动条。

- 鼠标可左右拖动；水平滚轮或普通滚轮均可在此区域内推动横向内容。
- 触屏使用原生横向滑动。滚轮已到边界且无法继续滚动时，不吞掉外层页面的滚动。
- 鼠标拖动超过 6 px 后视为滚动，本次松开不触发按钮使用，避免误操作。
- 键盘使用 Tab 聚焦；方向键、Home、End 浏览可用按钮，自动让聚焦按钮完整进入窗口。
- 到达最右端时，末尾按钮完整露出，右侧仍留 24 px。中途允许两端出现被裁切的按钮片段，提示还可继续横向浏览。

这里没有左右翻页按钮或滑动条素材。若项目已有惯性滚动容器，可以复用，但要保留相同的裁切窗口和点击／拖动判定。

## 五、从右侧“装填”的动画

**加入顺序决定位置。** 第一个效果最靠左，后加入的效果追加到队尾；“从右侧进入”是运动方向，不代表把新效果插到最左边。点击更新内容或变更状态，不重新播放入场。

1. 接收效果，按稳定 `id` 去重；先测量宽度并为新按钮预留布局位置。
2. 计算新按钮的正常位置 `x`（内容容器坐标），当前滚动值 `s`，可视宽度 `V`。
3. 入场平移量 `dx = max(0, V+24-(x-s))`，使新按钮从右侧裁切线之外开始。
4. 在 360 ms 内将 `translateX(dx)` 归零，缓动 `cubic-bezier(.22,.75,.22,1)`。前 100 ms 从透明过渡到正常。按钮不旋转、不弹跳，不改变高度。
5. 同一帧收到多个效果时批量布局。参考组件按 60 ms 错开入场，最长额外延迟 180 ms。大量效果建议一次传入数组，避免多次重复计算。

移动的是按钮视觉层，布局占位保持不动；不要动画修改按钮宽度，否则已有按钮会被持续挤动。使用减弱动态效果设置时，直接归位。

### 新按钮导致溢出时

- 添加前本来没有溢出，或视野距离最右端不超过 12 px，默认跟随队尾：同时向新的右端滚动，保证新效果可见。
- 玩家主动拖动、滑轮浏览或离开队尾时，不强制跟随。新效果仍加入右侧；不可见部分在裁切区域外完成入场。
- 参考组件在主动交互后保留 1200 ms 的不抢滚动时间。之后玩家回到最右端，后续添加可恢复跟随。
- 新一段结算开始时清空旧队列并回到左端。不能把上一结算的未完成异步回调应用到新结算上。

## 六、给其他代码的接口

示例组件只负责展示、交互和发出使用请求。效果是否满足条件、费用、结算结果、撤销和结束行动的可用性由现有游戏逻辑决定。

网页参考接入：加载同目录的 CSS 和 JS，在一个空元素上创建组件。`PREVIEW.html` 已将这些内容与素材内嵌，无需启动服务器。

```html
<link rel="stylesheet" href="components/settlement-effects.css">
<div id="settlement"></div>
<script src="components/settlement-effects.js"></script>
```

```js
const { SettlementEffects } = SettlementEffectsUI;
const strip = new SettlementEffects(document.querySelector('#settlement'), {
  title: '结算区域',
  subtitle: '建设结算中',
  heading: true,
  maxWidth: 280,
  onUse(effect, ui) {
    // 交给项目现有结算系统；实际接入时再次验证可使用条件。
    requestInsertEffect(effect.id);
  }
});

strip.add({
  id: 'resolution-42:effect-discount', // 包含本次结算身份，避免跨结算串用
  label: '使用减价卡',
  icon: 'assets/icons/discount-dark.png', // 可省略
  monochrome: true,                      // 自备彩色图标设为 false
  state: 'default',
  description: '使用本次建设的减价效果'
});

strip.add({ id:'resolution-42:cooperate', icon:'assets/icons/cooperate-dark.png',
  ariaLabel:'插入企业合作效果', monochrome:true }); // 纯图标必须有 ariaLabel

strip.update('resolution-42:effect-discount', { state:'pending' });
// 游戏逻辑确认成功后，移除或将 state 设为 disabled；失败则恢复 default。
strip.remove('resolution-42:effect-discount');
strip.setContext('下一项结算');
strip.clear();   // 取消未提交入场和当前动画、清空按钮、滚回起点
// strip.destroy(); // 离开此页面，释放监听器、观察器和提示层
```

`add()` 可传单个对象或数组；重复 id 会更新原位置，不制造重复按钮或重复入场。`update()` 只修改指定字段；`remove()` 找不到 id 时返回 false。`pending` 与 `disabled` 不会触发 `onUse`。点击本身不会自动删除效果，方便接入确认、失败恢复和撤销。

Unity 或其他引擎可按相同层级搭建：固定背景和标题、带矩形裁切的水平滚动窗口、横向容器、九宫格按钮。先完成布局计算再取目标位置，动画作用于按钮下的视觉子节点；点击事件传稳定的效果 id，动画、对象池、长文本提示和滚动逻辑由引擎实现。

## 七、验证范围

预览使用本包导出的 PNG 按实际九宫格拼装。已检查透明边角、各状态尺寸、拆分层与整底一致性，并验证定宽上限、安全边距、右端装填位置和内容溢出的数值边界。参考 JS 已检查语法。

当前环境没有可运行的浏览器内核，网页示例未做真实浏览器自动化验证；也未接入你的游戏工程。浏览器中的拖动、焦点提示与动画、以及引擎中的材质和事件接入，仍需在目标环境试用。示例代码和精确布局参数均随包交付。

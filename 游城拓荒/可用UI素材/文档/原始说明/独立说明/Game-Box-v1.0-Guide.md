# 游戏盒 UI 接入说明 v1.0

## 1. 结构与范围

游戏盒统计所有玩家放回的角色牌、事件牌、玩家标记及 Token；合作企业板只显示当前查看者放回的板，最多一张。页面用于查看，不提供使用、取回或执行操作。

| 内容 | 呈现 | 交互 |
| --- | --- | --- |
| 角色牌 | 一个错位牌堆，正反面混排；标题右侧显示总数 | 单击牌堆调用已有弃牌区／卡牌查看流程 |
| 事件牌 | 独立牌堆，按事件原图比例；标题右侧显示总数 | 同上，使用查看模式 |
| 玩家标记 | 顶栏右侧四个原企业合作方块，数字居中 | 只读 |
| 我的合作企业板 | 当前玩家放回的板，最多一张 | 只读；不展示其他玩家的板 |
| Token | 不同形状原图和数量，紧凑换行 | 在本模块内滚动 |
| 空白区域 | 窗口内外未承载上述内容的部分 | 一次完整点击关闭游戏盒 |

不拆分角色牌的正面／背面返回分类。背面返回牌的 `displayImage` 直接传卡背，查看时保持该状态；牌面是否可见由既有规则层决定，UI 不自动翻面。

## 2. 贴图与文字分层

从后向前绘制：主界面 → 遮罩 → 窗口底板 → 顶栏底板 → 模块底板 → 各自边框 → 内容与文字。

窗口用 `assets/window/fill` 与 `frame` 两张图。顶栏用 `assets/header/fill`，开盒图标与黄色装饰线独立摆放。模块用 `assets/modules/fill`、`frame`、`title-fill`、`title-frame`、`title-accent`。不要把模块标题底图当作模块边框。

所有运行时文字独立绘制，包括“游戏盒”“已放回的组件”“玩家标记”、模块名、总数、方块内数字、“单击查看”和页脚提示。所有卡图和 Token 图独立绘制；卡边为可选的通用九宫格，不限定长宽比。正式贴图里没有这些文字与卡图。

推荐文字颜色：正文 `#302F2A`、深底标题 `#EEEBDD`、辅助文字 `#877B64`。参考字号：大标题 48、模块标题 23、方块内数字 27、辅助文字 21。字号随整体 Canvas 比例缩放。

## 4. 卡牌尺寸与牌堆

### 角色牌

当前保留的角色图集是 2400×1700，4 列×2 行；单张 600×850，即 12:17。本包预览卡图是按此比例导出的缩小图。运行时仍应读取项目 Sprite 的实际宽高。

### 事件牌

**事件原图未保留，本包没有验证实卡尺寸。** 不从效果图估计真实规格，也不默认事件牌与角色牌同宽同高。`preview/placeholders/event-demo.png` 的 300×450 仅为占位图尺寸。

1. 从单张可见 Sprite 的矩形读取 `sourceWidth`、`sourceHeight`；不要读取整张图集大小。如果图片带多余透明留白，先使用项目约定的 Sprite 裁切矩形。
2. 每张图按自身原始比例 contain，不裁切、不同轴拉伸。
3. 应用错位和旋转后，计算整堆的外接矩形，再等比缩小至可用区内。
4. 事件牌与角色牌的展示上限分开：`pileMaxBox.event=[200,250]`，`character=[182,260]`。前者只控制当前预览大小，**不是实卡规格**，可根据真实事件素材单独调整。
5. 如果游戏还需要表现不同牌种的实体尺寸差异，应另传牌种的逻辑显示上限；图片像素大小本身不能代表实体尺寸。
6. 原图尺寸还没加载时，函数返回 `awaiting-image-size`；待宽高就绪重排，不先套用 12:17 渲染。

两类牌堆输入都按“底 → 顶”排序，显示最后至多 5 层，顶部仍为真实堆顶；标题数量显示完整数据条数。角度与错位固定，同一批牌刷新不重新随机。1 张牌居中不旋转；空堆不画假牌槽，显示“暂无放回的角色牌／事件牌”。

`components/game-box-layout.js` 提供 `layoutPile(cards, area, options)`，输出每张可见牌的中心、宽高、角度和层级，以及整堆边界。参考用法：

```js
const eventPile = GameBoxLayout.layoutPile(eventCards,
  { x: 506, y: 364, width: 276, height: 360 },
  { maxWidth: 200, maxHeight: 250, padding: 10 }
);
// 按 eventPile.cards 的顺序绘制；卡面和卡背已由 displayImage 指定。
// status 为 awaiting-image-size 时等待真实 Sprite 尺寸。
```

边框用 `piles/card-frame`，可比卡面外扩 4；阴影用 `piles/shadow`，参考左右外扩 10、上扩 8、下扩 12。给整堆留安全间距；缩放布局时装饰扩展量同步缩放。阴影不是额外卡槽。

## 5. 标记、企业板与 Token

| 玩家 | 原文件 | 游戏颜色 | 数字颜色 |
| --- | --- | --- | --- |
| 绿 | `cooperation-01-64.png` | `#5FD200` | `#26301A` |
| 黄 | `cooperation-02-64.png` | `#FFBF00` | `#302F22` |
| 蓝 | `cooperation-04-64.png` | `#006CFF` | `#F5F1E5` |
| 红 | `cooperation-08-64.png` | `#EC0000` | `#F5F1E5` |

方块直接复用原图，四个独立数字由数据驱动，0 也可正常显示。数量并非拼色占比。

企业板绑定当前查看玩家 ID：`ownEnterprise.ownerPlayerId` 不相符时不显示。预览原板比例是 650×1850，按最大高度 350 等比放入，显示“已放回 · 1”；没有时显示“尚未放回合作企业板”。当前玩家指查看者，不是当前正在行动的玩家；热座切换查看者后更新。

Token 区接收任意数量、形状和长宽比，不把图强塞进方形卡槽。当前参考排布为行高 126、间距 14；普通条目宽 168，宽高比超过 2.5 的横条用宽 228。实际图像高度上限 100，右侧预留 58 给“×数量”；条目按可用宽度换行。

`layoutTokens` 不主动合并条目：只有数据层明确认为同类、同状态的 Token 才合并计数。Token 名称或状态需要说明时可绑定现有悬浮提示。没有 Token 时显示“暂无放回的 Token”，隐藏滚动条，默认保留模块位置；若另做紧凑版，可重新分配剩余宽度。

### 右侧竖直滚动条

滚动条位于 **Token 模块内部右侧**。在 1920×1080 基准下，可见轨道为 `(1736,360,8,412)`，底部 y=772；轨道距模块右边 16。内容右边 x=1720，与轨道相隔 16。滚动条不穿过标题条或页脚。

交互命中区是 `(1728,360,24,412)`，比可见轨道宽；移动或缩放 Token 模块时，相对右边和视口上下边锚定。轨道和滑块只纵向伸展，保留圆头。滑块提供普通、悬停、拖动三态；视觉宽度均为 8。

滑块高度按 `视口高度 / 内容高度 × 轨道高度` 计算，最小 36，最大为轨道高度。`maxScroll=max(0,内容高度-视口高度)`；无溢出时隐藏滚动条。鼠标滚轮只作用于 Token 内容，拖动滑块或内容不触发关闭窗口。

## 6. 点击查看与关闭

单击角色／事件牌堆，将所有对应数据交给已有弃牌区查看流程，再使用卡牌查看 UI 的 `inspect` 模式。查看模式不显示“策略、计谋、取消”。不要拿快速行动的使用模式打开。

参考事件负载为 `GameBoxLayout.inspectPile('character'|'event', cards)`，其中 `source:'game-box'`，每张卡保留 `id`、`displayImage`、`face` 及原图尺寸。卡背数据不会在这个函数中替换成正面。

把牌堆作为一个点击入口；露出的下层装饰牌不分别截获输入。打开查看界面时保留游戏盒，关闭查看界面后回到相同位置和 Token 滚动偏移。打开查看界面的那一次点击必须被消费，不能继续传给游戏盒的空白关闭处理。

空白关闭需要同一次指针的按下和抬起都发生在空白，移动超过 6 个屏幕像素视为拖动。遮罩阻止输入穿透到主界面；关闭游戏盒的点击不能同时执行后方行动按钮。玩家标记、企业板、卡牌内容、Token 及滚动条区域消费点击。

`PREVIEW.html` 用简化的多卡查看层演示传参和返回，未替代项目既有查看组件。没有显式关闭按钮；关闭游戏盒后可刷新演示页重新打开。

## 7. PNG、SVG 与九宫格导入

PNG 使用 sRGB、straight alpha。显示时保持贴图原色；边框中心透明，底板另画。`assets.json` 的 `sliceLTRB` 顺序为左、上、右、下，数值以 1× 文件像素计。2× PNG 的切片边界全部乘 2，绘制逻辑尺寸不变。

普通底板可随容器拉伸；框线必须使用九宫格，避免横竖方向整体拉伸造成粗细变化。图标、卡面、Token、玩家方块只等比缩放。竖直滚动条按上、下端点保护方式纵向伸长。

| 贴图 | 1× 切片 L/T/R/B |
| --- | --- |
| 窗口边框 | 20 / 20 / 20 / 20 |
| 模块边框 | 12 / 12 / 12 / 12 |
| 模块标题底与框、标记条底与框 | 8 / 8 / 8 / 8 |
| 卡边 | 8 / 8 / 8 / 8 |
| 牌堆 hover 外框 | 12 / 12 / 12 / 12 |
| 卡片阴影 | 18 / 18 / 18 / 18 |
| Token 数量底 | 6 / 6 / 6 / 6 |
| Token hover | 8 / 8 / 8 / 8 |
| 滚动条 | 顶／底各 4，宽度保持 8 |

Unity UGUI 可将框导入为 Sprite 后使用 Sliced；使用 @2x 时 Sprite PPU 也设为 1× 的两倍，以保持切片的逻辑厚度。别调用 SetNativeSize 把 @2x 直接放大。其他引擎按同样的像素密度换算。

## 8. 本包验证与限制

`preview/main.png` 是本包独立 PNG 实际拼装，非概念效果图；预览中的文字及卡图是在最后一层叠加的。已确认原企业合作方块文件校验和保持一致，边框中心透明，1× 与 2× 尺寸匹配。

布局检查覆盖 5 种事件示例比例、旋转后边界、混合卡面卡背、真实堆顶、最多 5 层、空堆、缺失图片尺寸、企业板归属、Token 比例和滚动上下限。示例比例通过不等于真实事件规格已核实。

离线演示完成代码语法与资源路径检查，未运行浏览器自动交互测试；图包也未在项目引擎内导入。接入时应以真实事件 Sprite 再确认视觉大小和点击体验。`preview/` 的示意事件与 Token 不属于正式游戏美术。

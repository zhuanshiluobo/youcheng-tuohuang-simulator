# 通用卡牌选择 UI：贴图与文字布局

本方案供开局 7 选 2、建设 N 选 1、干员特派 2 选 1 共用，标题、说明、计数、按钮文字由程序叠加，卡牌下方不放编号喵

全部坐标采用窗口局部逻辑像素，矩形记作 `(x, y, width, height)`，卡面宽高比始终为 `12:17`，对应图包中的 `600 × 850` 竖卡喵

## 2. 窗口坐标和缩放

基准屏幕为 `1920 × 1080`，窗口为 `1774 × 887`，保持 `2:1`，居中后的屏幕左上角为 `(73, 96.5)` 喵

```text
screenX = 73 + localX
screenY = 96.5 + localY
```

其他屏幕尺寸下可将整套逻辑画布等比缩放后居中，不单独拉宽或压扁窗口和卡面喵

```text
scale = min(screenWidth / 1920, screenHeight / 1080)
windowScreenX = (screenWidth - 1774 * scale) / 2
windowScreenY = (screenHeight - 887 * scale) / 2

screenX = windowScreenX + localX * scale
screenY = windowScreenY + localY * scale
```

坐标中的 `.5` 可以保留为浮点数，由引擎在最终渲染时处理像素对齐，不要分别取整卡面的宽高而改变比例喵

## 4. 贴图对齐：以卡面区域为基准

卡面、卡槽 PNG、选中框 PNG 是三个独立层，不能直接把三张图设置成相同的整图矩形喵

普通槽与选中框的透明留白不同，下面使用各自的源内容安全框映射到同一个卡面目标矩形，让真正的卡面保持 `12:17` 喵

| 贴图 | 源画布 `(sourceW, sourceH)` | 源内容安全框 `R = (rx, ry, rw, rh)` |
|---|---:|---:|
| 普通卡槽 | `(1053, 1493)` | `(118, 130, 817, 1233)` |
| 选中边框 | `(1054, 1493)` | `(80, 130, 896, 1280)` |

给定卡面目标矩形 `C = (x, y, w, h)`，贴图本身应显示在下面的矩形喵

```text
textureX = x - rx * w / rw
textureY = y - ry * h / rh
textureW = sourceW * w / rw
textureH = sourceH * h / rh

textureRect = (textureX, textureY, textureW, textureH)
```

该映射只调整边框贴图，原始卡面直接显示在 `C` 中，始终等比完整显示，不裁切、不压缩比例喵

选中框的源安全框起点位于勾选徽章下方，特意为徽章留出空间，避免其覆盖卡面正文喵

普通槽在最大卡面下的实际可见外扩约在 `14 px` 以内，选中框上方装饰实际可见外扩约 `25 px`，纵向预留 `28 px` 用于这些装饰即可喵

纵向装饰预留不计入卡面高度，不得为了容纳徽章而缩短卡图喵

PNG 的透明画布可能比可见边框伸出得更多，因此透明边距不能用来推算卡面比例、相邻卡间距或点击范围喵

这里未制作九宫格资源，映射也不代表纹理可以无损任意缩放，本版应优先使用本文给出的显示尺寸喵

## 5. 一至七张卡的排布公式

卡牌行垂直中心固定为 `y = 439`，横向整体居中，卡面宽度取 `12` 的倍数，使宽高均能保持精确的 `12:17` 喵

```text
A = 1582       // 内容视口宽度
g = 16         // 相邻槽布局区域之间的间距
b = 16         // 卡面左右各预留的布局安全边
m = 卡牌数量   // 1 <= m <= 7

cw = min(288, 12 * floor(((A - (m - 1) * 16) / m - 32) / 12))
ch = cw * 17 / 12

slotW = cw + 32
rowW = m * slotW + (m - 1) * 16
rowX = (1774 - rowW) / 2

cardX(i) = rowX + i * (slotW + 16) + 16
cardY = 439 - ch / 2

cardRect(i) = (cardX(i), cardY, cw, ch)
// i 从 0 开始
```

其中 `slotW` 仅表示排布所占宽度，不能直接作为普通槽或选中框 PNG 的整图宽度，实际贴图矩形使用上一节的源区域映射喵

| 卡牌数 | 卡面尺寸 | 卡面 Y | 各张卡面 X | 行总宽 `rowW` |
|---:|---:|---:|---|---:|
| 2 | `288 × 408` | `235` | `575, 911` | `656` |
| 6 | `216 × 306` | `286` | `119, 383, 647, 911, 1175, 1439` | `1568` |
| 7 | `180 × 255` | `311.5` | `113, 341, 569, 797, 1025, 1253, 1481` | `1580` |

两张卡在屏幕中的矩形分别为 `(648, 331.5, 288, 408)` 和 `(984, 331.5, 288, 408)` 喵

主按钮在基准屏幕中的逻辑矩形为 `(1465, 840.5, 280, 84)`，次按钮为 `(1161, 840.5, 280, 84)` 喵

所有卡牌均不设置卡下编号，选择数量仅通过底部计数显示，选中情况通过边框及勾选标记表达喵

## 6. 超过七张：固定卡面大小并横向滚动

`N > 7` 时采用七张布局的卡面尺寸 `180 × 255`，不继续缩小卡牌，标题、说明、计数与按钮保持固定喵

```text
viewport = (96, 198, 1582, 482)
cw = 180
ch = 255
slotW = 212
gap = 16

contentWidth = 2 + N * 212 + (N - 1) * 16
maxScroll = contentWidth - 1582
scrollX = clamp(scrollX, 0, maxScroll)

cardX(i) = 113 + 228 * i - scrollX
cardY = 311.5
cardRect(i) = (cardX(i), 311.5, 180, 255)

scrollbarTrack = (120, 650, 1534, 16)
scrollbarHitArea = (120, 638, 1534, 40)

thumbW = clamp(1534 * 1582 / contentWidth, 80, 1534)
thumbX = 120 + (scrollX / maxScroll) * (1534 - thumbW)
thumbRect = (thumbX, 652, thumbW, 12)
```

`contentWidth` 中额外的 `2 px` 对应内容两侧各 `1 px` 留白，保证七张时恰好占满视口逻辑宽度喵

例如九张卡的内容宽为 `2038 px`，最大滚动量为 `456 px`，未滚动时前七张卡面的坐标与七张案例一致喵

滚动条只在 `N > 7` 时显示，轨道与滑块使用独立贴图，滑块长度表示当前可见内容占总内容的比例，最短为 `80 px` 喵

轨道可见区域位于视口最底部，垂直范围 `650..666`，交互热区范围 `638..678`，均位于视口内部且与上方卡牌留有空隙喵

在轨道贴图上绘制滑块贴图，拖动滑块改变 `scrollX`，两者的点击及拖动热区均需按逻辑矩形判断，不使用 PNG 透明画布作为热区喵

轨道源可见框为 `(82, 333, 2008, 50)`，滑块源可见框为 `(92, 326, 1988, 71)`，两张源图均为 `2172 × 724`，按第 4 节同一公式将可见框映射到目标矩形，并裁切在各自逻辑矩形内，完整参数也写入 `layout.json`，轨道宽度变化时保持可见高度 `16 px`，滑块保持高度 `12 px` 并垂直居中 喵

卡牌、普通槽及选中框随同一内容容器滚动，并统一裁切到视口内，不能让选中框滞留在固定窗口坐标喵

内容容器本身也应裁切超出其总宽的透明图片画布，预览使用 `.track { overflow: hidden; }`，避免透明留白意外扩大原生滚动范围喵

游戏接入时建议支持横向滚动、拖动滚动条，并在键盘或手柄焦点移到不可见卡牌时自动滚动使其可见，这些属于接入建议，不代表本包已实现完整游戏输入系统喵

放大预览如需越过视口边缘，应放在独立的上层容器中，不参与卡牌行排布喵

## 7. 按钮贴图和点击区域

主、次按钮使用相同的源可见框 `R = (35, 102, 1916, 582)`，两张源 PNG 都为 `1983 × 793` 喵

将该源可见框映射到逻辑按钮目标矩形，使用与卡槽相同的公式，最后在目标按钮矩形边界裁切喵

```text
target = (buttonX, buttonY, 280, 84)
sourceW = 1983
sourceH = 793
rx = 35
ry = 102
rw = 1916
rh = 582

textureX = buttonX - 35 * 280 / 1916
textureY = buttonY - 102 * 84 / 582
textureW = 1983 * 280 / 1916
textureH = 793 * 84 / 582

clipRect = target
hitRect = target
```

透明画布不能直接作为点击区，所有按钮点击和悬停判定仅使用逻辑按钮矩形，按钮文字层不应截获独立点击喵

按钮文字放在贴图上方，不参与贴图映射，并保持固定的字号与安全边距喵

| 状态 | 贴图与程序处理 | 输入行为 |
|---|---|---|
| `normal` | 使用对应普通状态 PNG，原色显示 | 可点击 |
| `hover` | 同一 PNG，由程序小幅提亮 | 可点击 |
| `pressed` | 同一 PNG，由程序适度压暗 | 按下后等待释放确认 |
| `disabled` | 同一 PNG，由程序降低亮度或饱和度，并降低文字强调 | 不接受点击 |

状态着色应针对按钮整体保持一致，不能只把文字变灰却仍接受点击，也不能为了表示按下状态改变按钮点击区域喵

## 8. 层级和点击分配

| 层级 | 内容 | 点击分配 |
|---:|---|---|
| `-10` | 模态背景暗化遮罩 | 阻止操作窗口背后的游戏内容 |
| `0` | 窗口底图 | 不承担选牌动作 |
| `10` | 普通卡槽 | 与对应卡牌共用选择逻辑 |
| `20` | 原始卡面 | 对应卡牌的选择入口 |

## 9. 三种场景的文案与行为

下表中的文字是供程序显示的 UI 字符串，卡面本身仍使用对应真实卡牌资源喵

| 场景 | 标题 | 说明 | 计数 | 主按钮 |
|---|---|---|---|---|
| 开局 7 选 2 | 选择卡牌 | 选择 2 张角色牌移出本局 | `已选择 {k} / 2` | 移出所选 |
| 建设 N 选 1 | 选择建设方案 | 选择 1 张设施牌进行建设 | `已选择 {k} / 1` | 确认建设 |
| 干员特派 2 选 1 | 干员特派 | 选择 1 张干员牌 | `已选择 {k} / 1` | 确认选择 |

### 多选

- 点击未选卡牌时加入选择，点击已选卡牌时撤销选择喵
- 达到所需数量后，再点击其他未选卡牌不自动替换，应提示先取消一个已选项喵
- 只有恰好选满所需数量时，主按钮才进入可用状态喵
- 操作提示可使用 `再次点击可取消选择` 或 `已选满，请先取消一个选择` 喵

### 单选

- 点击其他卡牌时直接替换当前选择喵
- 再次点击当前已选卡牌时允许撤选，主按钮随之禁用喵
- 只有选中一张合法候选卡时，主按钮可用喵
- 操作提示可使用 `点击另一张卡牌可切换选择` 喵

### 取消与返回

- 次按钮承担退出时，仅在流程允许取消或返回时显示，按钮文字可用 `取消` 或 `返回` 喵
- 开局多选可把次按钮配置为 `重新选择`，它仅清空选择，不退出强制步骤；干员特派示例隐藏次按钮喵
- 不需要次按钮时隐藏它，主按钮保持原位置，不重新居中喵
- 不允许取消的流程不能通过点击背景或按 Escape 绕过必选步骤喵
- 取消、返回、确认对游戏状态的实际影响由游戏逻辑处理，布局预览不能替代规则校验喵

## 10. 接入检查清单

- [ ] `600 × 850` 卡面显示时仍为 `12:17`，没有拉伸、裁切或压缩正文喵
- [ ] 普通卡槽和选中框分别使用自己的源安全框，切换选中状态时卡面位置与尺寸不变喵
- [ ] 勾选装饰位于卡面上方，不遮住卡牌内容，视口内预留的纵向 `28 px` 足够喵
- [ ] 2、6、7 张案例的卡面坐标与本文表格一致，没有卡下编号喵
- [ ] 9 张案例可达到 `scrollX = 456`，末张卡牌可以完整进入视口喵
- [ ] 仅在超过七张时显示轨道和滑块，滑块长度随总卡数变化，拖到最右侧恰好达到 `maxScroll` 喵
- [ ] 滚动条可见区域为 `(120, 650, 1534, 16)`，热区为 `(120, 638, 1534, 40)`，两者不侵入卡面或底部操作区喵
- [ ] 滚动时卡槽、卡面、选中边框一起移动，窗口标题和底部操作区保持固定喵
- [ ] 主、次按钮贴图裁切到逻辑矩形，透明画布不扩大点击范围喵
- [ ] 按钮文案处于安全区内，悬停、按下和禁用只使用程序着色，不引用不存在的状态 PNG 喵
- [ ] 未满足选择数量时确认按钮既有禁用外观，也在逻辑上禁止提交喵
- [ ] 强制选择流程不能通过次按钮、背景或 Escape 退出；`重新选择`只清空当前选择喵
- [ ] 在实际目标屏幕上检查字体、对比度和卡面可读性，必要时通过独立放大预览阅读小字喵
- [ ] 正式接入时用真实候选卡替换重复的设施样本，不能把预览样本当作游戏规则数据喵

## 11. 本次按钮和滚动条素材的生成说明

主、次按钮及轨道、滑块本次通过内建 ImageGen 生成，提示词要点包括无文字、透明背景、工业棕金材质、按钮中央留白，以及滚动条长条中段减少装饰以便横向拉伸喵

两张按钮与窗口沿用磨损金属和棕金色调，但它们仍是栅格素材，本文的映射与裁切用于在明确的目标尺寸下对齐，不包含九宫格制作或任意尺寸下无损缩放的保证喵

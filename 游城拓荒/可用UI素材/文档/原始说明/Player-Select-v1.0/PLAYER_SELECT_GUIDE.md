# 游戏内选择玩家窗口 · 接入说明 v1.0

## 窗口内容与拆分

本窗口承载 1–4 位实际玩家，显示头像、名字、玩家标记颜色。房间空座位和关闭的位置不作为玩家选项。玩家数量少于四位时整行居中，不保留空位占位框。

窗口沿用当前浅纸面、暖灰棕细框。选中状态使用淡金色填充、金色完整边框和勾号；玩家方块始终显示实际玩家色，不用换色表示选中。

| 层级 | 资产 ID | 使用方式 |
| --- | --- | --- |
| 全屏遮罩 | `dim-overlay` | 遮住下层输入；不绑定点击关闭 |
| 窗口底板 | `window-fill` | 与边框独立，使用已有区控／游戏盒纸面 |
| 窗口边框 | `window-frame` | 透明中部，九宫格伸缩 |
| 标题 | `accent`、`icon-players-dark`、`divider` | 标题和提示文字由程序显示 |
| 玩家选项底板 | `option-fill-{default,hover,selected,disabled}` | 半透明独立填充层 |
| 玩家选项边框 | `option-frame-{default,hover,selected,disabled}` | 透明框，九宫格伸缩 |
| 头像 | `avatar-fill`、运行时头像、`avatar-frame` | 头像等比裁切，框用九宫格 |
| 标记颜色 | `marker-{green,yellow,blue,red}` | 沿用企业合作原方块，保持等比与原色 |
| 选择状态 | `checkbox-unchecked`、`checkbox-checked`、`icon-check-dark` | 勾号独立；单选与多选共用卡片选中样式 |
| 不可选择 | `icon-lock-muted` | 显示锁和原因；不能加入选择集 |
| 确认／取消 | `confirm-{normal,hover,pressed,disabled}`、`cancel-*` | 复用修订后的卡牌查看按钮，文字独立 |
| 右上关闭 | `close-{default,hover,pressed,disabled}`、`icon-close-dark` | 独立点击区域，与取消同一行为 |

不要把整张预览作为运行时底板。填充层与框层分别导入；按钮本身是完整底图，无需重复叠另一份边框。

## 玩家颜色与头像

| 颜色 | 精确 sRGB | 资产 |
| --- | --- | --- |
| Green | `#5FD200` | `marker-green` |
| Yellow | `#FFBF00` | `marker-yellow` |
| Blue | `#006CFF` | `marker-blue` |
| Red | `#EC0000` | `marker-red` |

这四个方块来自原企业合作区贴图，64×64 原文件直接复用。默认显示为 32×32；不叠数字，因为这里表示玩家身份颜色。设置 Tint 为白色，避免对整个选项统一降低透明度导致方块变色。不可选时只降低头像和名字的强调，原色方块仍正常显示。

头像使用 Cover 等比裁切到方形。头像缺失或加载失败时显示 `avatar-fill` 与 `icon-empty-seat-muted`。头像框源画布为 320×456，但它是可伸缩边框；用 12 像素九宫格绘制为方形，不能把整张边框直接压缩。

预览头像来自现有角色卡图，只是示例；它们不绑定玩家的实际角色牌或游戏能力。

## 单选、多选与确认

| 情况 | 设置 | 表现 |
| --- | --- | --- |
| 选择一位 | `mode: single, min: 1, max: 1` | 点击另一位替换选择；点击当前已选不取消 |
| 选择一至两位 | `mode: multiple, min: 1, max: 2` | 点选和取消；最多选两位 |
| 必须选择两位 | `mode: multiple, min: 2, max: 2` | 恰好两位才可确认 |
| 可不选、最多两位 | `mode: multiple, min: 0, max: 2` | 零人也可确认，返回空数组 |

点击玩家选项只改变选择，不立即执行效果。多选达到上限后再点未选玩家，保留原选择并提示“已达选择上限，请先取消一位已选玩家”；仍可取消已有选择。不会自动替换最早选择的玩家。

底部显示已选人数和上限，标题下方显示本次最少／最多数量。未达到最少人数时确认按钮使用 disabled 贴图；数量合法后使用 normal，悬停和按下分别切换。不可用按钮不能提交事件。

`eligible: false` 的玩家仍可显示头像、名字、颜色及 `disabledReason`，但不能加入选择集。是否允许选择自己、盟友、其他特定玩家由本次游戏效果传入；窗口不自行推断。示例“不能选择自己”只演示禁用状态。

玩家列表或可选性变化时，按玩家 ID 清除失效选择并重新判断确认状态，不自动选择别人补足数量。若可选玩家少于最少要求，显示数量不足并禁用确认，交由调用方处理，不擅自降低规则要求。

## 关闭与输入

默认 `allowCancel: true`。取消、右上 X 和 Escape 都返回取消事件；不会把当前选择当成确认。点击窗口外区域不关闭，也不操作下层地图。

必须完成的结算传 `allowCancel: false`，隐藏取消与 X，忽略 Escape。若这种结算出现可选人数不足，调用方必须解决状态；本窗口不通过取消绕过结算。

整个玩家卡片都是点击区，头像、色块和文字的点击统一交给卡片。单选与多选使用同一预制体，只切换数量规则和提示。键盘可通过 Tab 聚焦、Enter／Space 点选；模态打开时焦点保留在窗口内。

## 调用数据与结果

```js
const config = {
  title: '选择玩家',
  mode: 'multiple',
  min: 1,
  max: 2,
  allowCancel: true,
  players: [
    { id: 'p1', name: '玩家 1', color: 'green', avatar: '实际头像地址', eligible: true },
    { id: 'p2', name: '玩家 2', color: 'yellow', avatar: '实际头像地址', eligible: true }
  ],
  selectedIds: []
};
```

`isSelf` 只控制“你”标签；`eligible` 控制能否选中。ID 必须稳定且唯一，不以显示顺序、头像或颜色代替。房间换位改变颜色后仍以玩家 ID 关联选择。

`components/player-selection.js` 提供 `normalize`、`toggle`、`canConfirm`、`instruction`、`hint`、`confirm`、`cancel`，可移植到项目语言。确认返回 `{ type: 'confirm-player-selection', playerIds: [...] }`；取消返回 `{ type: 'cancel-player-selection', reason: ... }`。确认返回数组表示玩家集合，数组先后次序不表示效果结算顺序。调用方应按当前游戏状态再次确认目标合法，再执行结算。

离线示例只展示选择与回调结果，不发送联网请求，也不执行牌面效果。

## 导入与验证

PNG 使用 sRGB、straight alpha。`assets.json` 中九宫格顺序是左／上／右／下。窗口框 20，选项框 12，头像框 12，确认／取消按钮 12，关闭按钮 10。使用 @2x 贴图时源切片像素加倍，显示逻辑尺寸保持不变。

文字、头像、勾号和颜色方块独立绘制。图标与方块保持原比例；`assets/` 内无烘焙文字。SVG 中的相对纹理引用指向 `sources/`，请保留目录结构；PNG 可单独使用。

已核对独立贴图、透明框、原色方块、多个拼装状态、单选替换、多选上限／取消、禁用玩家、确认人数与取消限制。详情见 `QA.json` 和 `SHA256SUMS.txt`。未在实际游戏引擎中导入，也未做浏览器自动化测试。

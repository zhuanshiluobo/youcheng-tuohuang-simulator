# 通用选项窗口：重复执行与 N 选 1

本包为新的选项窗口素材包，延续此前深褐灰工业底板、米白纸面、磨损边缘与少量金黄色强调的画风，并与原卡牌选择素材包分别保留喵
新增的横向纸面选项条用于承载资源、费用、回报与组合效果，不将上一版竖卡框拉伸成横条喵
窗口标题、说明、库存、费用、数量、选项内容、按钮文字与状态提示均由程序绘制，PNG 不绑定卡牌名称、选项数量或具体规则喵

## 1. 两种窗口

| 模式 | 操作与结束方式 | 适用场景 |
|---|---|---|
| 重复执行 `repeat` | 逐行用减号、数量输入框和加号编辑待售数量，底部“确认售卖”统一提交多种、多份资源；成交后可编辑下一批，也允许 0 售出结束喵 | 贸易街区、坎诺特策略「秘密渠道」喵 |
| 单次选择 `single` | 点击选项只改变待确认项，点击主按钮才提交；一次选择提交 1 项喵 | 坎诺特计谋、极境并列最少资源、其他 N 选 1 效果喵 |

重复执行窗口不显示勾选框或固定“已选 X／K”，也不累计 `selectedId`；它保存各资源的待售数量草稿，并区分本批预计收入与已经成交的累计收入喵
每种资源的草稿数量必须是 0 到当前库存之间的整数，编辑草稿只更新预计剩余量与收入，不扣除资源、不增加金券喵
全部待售数量为 0 时，主按钮“确认售卖”禁用；至少一项为正且整批合法时才能提交喵
点击确认后，由规则层重新校验整批数量、库存与交易上下文，然后原子结算全部资源与金券，不能出现部分资源成交、部分资源失败的结果喵
请求处理中锁住数量编辑、确认及结束操作，避免重复提交或结束与成交同时发生；失败时不扣除任何本批资源，并显示原因喵
提交成功后刷新真实库存、累计成交量与收入，清零全部待售草稿，窗口保持打开以便继续下一批，没有固定批次数上限喵
次按钮在草稿全部为 0 时显示“结束出售”，有任一非零草稿时显示“放弃并结束”，后者清空尚未成交的草稿并退出，不执行交易喵
玩家可以完全不出售资源就结束；结束不会撤销已经成交的批次，结束这一次效果结算后不能再通过该窗口交易喵
库存为 0 时该资源的加号不可用；数量为 0 时减号不可用，数量达到库存时加号不可用，所有库存耗尽后仍可正常结束出售喵

单次选择窗口使用单一 `selectedId`，选择另一项会替换待确认项；尚未选择或所选项已失效时，确认按钮不可提交喵
是否允许取消、跳过或提前结束由当前效果的上下文决定，不为所有 N 选 1 效果默认开放“取消”喵
需要地图目标的复杂选项在确认后进入目标步骤，完成目标与效果结算后才算完成本次选择喵

本批待售数量与收入按以下公式实时预览，计算过程不改变真实库存喵

```text
0 <= draftQuantity[resource] <= inventory[resource]
draftQuantity[resource] must be an integer
remaining[resource] = inventory[resource] - draftQuantity[resource]
rowIncome[resource] = unitPrice[resource] * draftQuantity[resource]
batchQuantity = sum(draftQuantity[resource])
batchIncome = sum(unitPrice[resource] * draftQuantity[resource])
```

## 4. 按钮与滚动条的贴图映射

主、次按钮的源 PNG 均为 1983 × 793，可见部分使用 `source_rect = (35, 102, 1916, 582)`，其余为透明留白喵
布局表中的按钮矩形指可见按钮区域，不能把整张含透明留白的 PNG 直接当作该矩形喵

源矩形为 `(sx, sy, sw, sh)`、目标可见矩形为 `(dx, dy, dw, dh)`、整张源图尺寸为 `(iw, ih)` 时，映射公式如下喵

```text
scaleX = dw / sw
scaleY = dh / sh
textureX = dx - sx * scaleX
textureY = dy - sy * scaleY
textureWidth = iw * scaleX
textureHeight = ih * scaleY
```

主、次按钮将上述源可见框映射到 280 × 84，文字仍由独立层按目标可见区域居中喵
重复执行行内的加减按钮改用 `assets/button-stepper.png`，其可见源框映射到 60 × 60；字符“+”与“−”另行绘制，源框参数采用本包最终实测记录喵
采用裁切绘制的引擎也可以直接将源可见框绘制到目标矩形，避免透明留白影响命中区喵
若改用九宫格拉伸，需根据实际贴图确认固定边缘区域，不能凭本次可见框参数自动推定九宫格边距喵

滚动条源图同样包含透明留白，沿用可见源框：轨道 `(82, 333, 2008, 50)`，滑块 `(92, 326, 1988, 71)`，两张图均为 2172 × 724喵
这些水平源图在本窗口中先裁切可见源框、再旋转 90°，分别映射为右侧竖直轨道与滑块，不能把整张含透明留白的图片直接旋转缩放喵

### 4.1 右侧竖直滚动条：位置与算法

滚动条位于选项行右侧，固定在窗口上，不随列表内容移动，精确位置如下喵
以 1774 × 887 窗口锚定时，轨道右边距为 96、上边距为 228；在 1920 × 1080 参考屏幕上，轨道全局左上角为 `(1729, 324.5)`，下表仍以窗口内坐标为准喵

| 元素 | 窗口内矩形或坐标 | 说明 |
|---|---|---|
| 内容视口 | `(96, 228, 1582, 438)` | 保持前述视口边界，内部给右侧控件保留空间喵 |
| 内容行右缘 | `x = 1644` | 对应起点 96 加行宽 1548，文字与选项底图不跨过此边界喵 |
| 竖直轨道 | `(1656, 228, 22, 438)` | 左侧与内容行右缘相隔 12 像素，轨道底端为 `y = 666` 喵 |
| 扩大后的鼠标命中区 | `(1650, 228, 34, 438)` | 左缘仍位于内容行外，不能遮挡行内加减按钮或选项点击喵 |
| 滑块 | 纵向起点 `thumbY`，高度 `thumbHeight` | 横向与轨道对齐，随内容高度与滚动位置变化喵 |

右侧滚动条空间始终预留，内容高度大于 438 时显示轨道与滑块，否则隐藏并将滚动位置归零，不能因显示状态变化而改变选项行宽喵
`contentHeight` 必须包含所有选项的实际高度与行间距，复杂选项换行或增加禁用原因后应重新测量喵

```text
viewportHeight = 438
trackTop = 228
trackHeight = 438
maxScroll = max(0, contentHeight - viewportHeight)

if maxScroll == 0:
    hideTrackAndThumb()
    scrollTop = 0
else:
    thumbHeight = max(48, 438 * 438 / contentHeight)
    scrollTop = clamp(scrollTop, 0, maxScroll)
    thumbY = 228 + (438 - thumbHeight) * scrollTop / maxScroll
```

滑块最小高度为 48，内容越长，滑块占轨道的比例越小；最大滚动位置时滑块底端与轨道底端对齐喵
拖动滑块时将纵向位移换算为 `deltaScroll = deltaY × maxScroll / (438 - thumbHeight)`，结果限制在 `0…maxScroll`，拖动期间保持指针捕获喵
点击轨道时可以把滑块中心移动到点击位置，夹紧到轨道范围，再由相同的映射关系计算 `scrollTop` 喵
鼠标滚轮作用于内容视口时更新列表滚动位置，同时更新滑块；拖动、轨道点击和滚轮必须共用同一个 `scrollTop`，避免列表与滑块不同步喵
窗口数据或行高变化时同时重算总内容高度、滑块高度与当前位置，不能让旧滚动偏移把全部选项留在视口外喵

## 5. 各场景规则映射

### 5.1 贸易街区与坎诺特策略

| 出售资源 | 单位出售收入 | 每售出 1 个的变化 |
|---|---:|---|
| 源岩 | 3 金券 | 源岩 −1，金券 +3喵 |
| 源石 | 3 金券 | 源石 −1，金券 +3喵 |
| 异铁 | 4 金券 | 异铁 −1，金券 +4喵 |
| 至纯源石 | 15 金券 | 至纯源石 −1，金券 +15喵 |

贸易街区是在建设完成后结算的设施入场效果，坎诺特策略「秘密渠道」是在该角色策略结算时开放出售，二者都没有买入选项喵
规则书明确坎诺特可以自行选择每种资源的出售数量，也可以不出售某一种资源，因此本窗口允许 0 售出结束，不能要求玩家至少卖出一份喵
界面将多种资源、多份数量合并为一批统一确认，批次只是数字版交互组织方式，不会改变每种资源的单价与出售规则喵
出售数量受持有量限制，没有固定批次数上限；玩家可以提交一批、查看新库存，再继续下一批，所有出售均属于当前这一次效果结算喵
重复出售不等于重复使用角色牌，也不提供离开结算窗口后继续随时出售的权限喵

### 5.2 坎诺特计谋「征收物资」

从源岩、源石、异铁中选择一种，所有玩家以 2 金券／单位出售其持有的全部该种资源，使用该计谋的玩家获得 1 分喵
“所有玩家”包含使用坎诺特者本人，至纯源石不是此计谋的候选项喵
这是单次三选一，确认后各玩家应售至该资源为 0，不再为每个玩家打开出售数量选择，也不能让其拒绝出售喵
选项可展示当前各玩家预计出售量与收入，但这些预览必须来自当前游戏状态，不能把示例数字印入底图喵

### 5.3 极境策略「后勤调遣」

比较玩家持有的源岩、源石与异铁数量，从数量最少的资源种类中选择一种，获得 4 个该资源喵
若只有一种最少，规则层可以直接确定并结算，无需强行打开选择窗口；两种并列最少时使用二选一，三种并列时使用三选一喵
至纯源石不参与此次最少资源比较，不能在数量较少时把它加入候选列表喵
如果列表保留全部三种资源用于说明，非最少项须禁用并注明原因；也可以只展示真正的候选项喵

### 5.4 警备队辖区：连续两次 N 选 1

警备队辖区要求从三个选项中选择 2 次并依次执行，所以复用单次选择窗口两次，第一项完整结算后再选择第二项喵
窗口可显示“第 1 次／共 2 次”和“第 2 次／共 2 次”，这个进度属于本效果上下文，不是单次选择模板永久写死的计数喵
卡面没有“选择不同项”的限制，同项可以在第二次继续出现，规则层应根据变化后的资源、影响力与目标状态重新判断可执行过程喵

默认示例采用与规则书扩展配件图一致的 6 分版，三个选项如下喵

| 选项 | 费用与效果 | 内容呈现建议 |
|---|---|---|
| 替换影响力 | 支付 2 源岩 + 1 异铁 → 替换 1 个影响力喵 | 费用、条件箭头、替换效果、地图目标阶段分开显示喵 |
| 放置并获取资源 | 放置 1 个影响力，然后获得 1 源石喵 | 依次列出两个效果，不能将前一效果误标为条件费用喵 |
| 移除并获取资源 | 移除 1 个影响力，然后获得 2 异铁喵 | 依次列出两个效果，目标步骤由规则层决定喵 |

使用这项特殊行动的轮中不能使用角色牌；每张城市样式所解锁的特殊行动每回合最多执行一次，Ⅱ级样式还受剩余使用次数限制，此卡初始标记为 2喵
一次特殊行动内的“两次选择”不等于把城市样式的总使用次数扣除两次喵

**版本差异：** 图包还包含 7 分版警备队辖区，其第一个选项费用为 1 源岩，另外两个选项不变喵
图包内 TTS 存档同时引用两版，不能仅按图片编号认定某一版为最新版；接入时应让费用与卡面版本由项目规则配置决定喵

**尽量执行与条件费用：** 规则书规定普通组合效果须按顺序尽量执行，前一部分无法执行，不代表后一部分自动失效喵
因此没有影响力放置或移除目标时，不能直接把“放置后获得源石”或“移除后获得异铁”整项判定为无效，后续资源效果仍应依规则处理喵
带条件箭头的支付则必须完整执行，才能执行箭头后面的效果；UI 不自行把所有前置动作都解释成成本喵
禁用状态、可跳过的地图步骤与最终收益由规则层返回，窗口只展示结果与原因喵

## 6. 通用配置与接入契约

以下是建议的数据含义，用于与项目现有状态系统对接，并不构成完整游戏规则引擎喵

| 字段 | 建议用途 |
|---|---|
| `id` | 稳定选项标识，显示文字变化时保持不变喵 |
| `title` | 选项主标题，由程序绘制喵 |
| `description` | 解释效果顺序、范围或限制喵 |
| `costs` | 条件费用明细，含资源标识与数量喵 |
| `rewards` | 可展示的资源或分数结果，复杂地图操作另用描述或动作数据表达喵 |
| `actionLabel` | 当前按钮文案，例如“确认售卖”或“确认选择”喵 |
| `enabled` | 当前状态下是否允许提交，由规则层计算喵 |
| `disabledReason` | 不允许提交时的具体原因，空字符串不能代替有效解释喵 |
| `maxExecutions` | 若某项确有独立次数上限，可提供上限；无固定上限不代表忽略库存与其他限制喵 |
| `requiresTarget` | 是否进入地图目标阶段；实际是否可跳过仍由规则层判断喵 |
| `unitPrice` | 重复模式中该资源每单位的金券收入，用于单行与整批收入预览喵 |
| `draftQuantities` | 按资源标识保存的待售整数数量，仅为本批草稿，不是已成交记录喵 |

上下文至少应区分模式、来源效果、当前玩家、候选列表、是否允许结束或取消、当前第几次选择及总选择次数喵
重复模式还需区分真实库存、当前草稿、本批预计收入、已成交累计、请求处理中与已结束状态，不能混用草稿数量和成交数量喵
选项级 `maxExecutions` 与上下文的总选择次数分别处理，例如警备队辖区是整个效果完成两次选择，不是每一个选项各执行两次喵
以下为接口示意，字段可适配现有项目，不能据此推定 `options.json` 的全部结构喵

```json
{
  "context": {
    "mode": "single",
    "sourceId": "guard_district_6_points",
    "choiceIndex": 1,
    "totalChoices": 2,
    "canFinishEarly": false
  },
  "option": {
    "id": "replace_influence",
    "title": "替换影响力",
    "description": "支付费用，替换 1 个影响力",
    "costs": [
      { "resource": "rock", "amount": 2 },
      { "resource": "iron", "amount": 1 }
    ],
    "rewards": [],
    "actionLabel": "选择目标",
    "enabled": true,
    "disabledReason": "",
    "maxExecutions": null,
    "requiresTarget": true
  }
}
```

重复执行状态流为“编辑草稿 → 确认整批 → 校验与原子结算 → 刷新库存并清零草稿 → 编辑下一批”，玩家选择结束或放弃并结束后进入终止状态喵
整批提交时再次检查所有资源数量与当前权限，只在全部有效时统一扣除资源并增加总收入；校验失败时本批不成交，不能悄悄减少数量或只成交合法部分喵
数量编辑、清空未成交草稿与结束出售均不扣除资源，成功成交才更新真实资源与累计数据喵
单次选择状态流为“未选择 → 已选择 → 提交 → 必要的目标步骤 → 完成结算”，连续效果在一次结算完成后清空旧选择并装载下一次上下文喵
规则状态变化后应重新校验已选项，不能让已失效的选择依旧提交，也不能把上一阶段的 `selectedId` 自动带入下一阶段喵
影响力目标、费用结算、分数变化与多人同步由项目逻辑实现，窗口不自行模拟完整桌游规则喵

## 7. 预览范围与验证说明

`PREVIEW.html` 使用示例玩家库存展示多资源批量出售、单次选择与复杂选项的基本状态变化，示例库存不代表实际存档喵
重复出售预览支持加减按钮与直接输入整数数量，实时显示本批总量、预计收入和预计剩余资源，再由“确认售卖”一次提交喵
重复出售视觉样例中，源岩、源石、异铁、至纯源石的待售数量依次为 3、1、2、0，预计收入为 `3 × 3 + 1 × 3 + 2 × 4 = 20` 金券，这些数量只用于展示喵
解压完整素材包后打开 `PREVIEW.html` 即可使用；HTML 为支持直接本地打开而内置配置，修改配置时须同步更新 `options.json` 与 HTML 中的对应常量喵
警备队辖区的地图操作通过外部“模拟地图步骤完成”控件演示，预览未实现真实地图、完整影响力目标规则或多人同步喵
外部滚动测试勾选项仅增大行间距以触发内容溢出，不增加虚假选项，也不改变默认设计中的行高与间距喵
两张视觉样例用于查看风格与内容层次，不是逐像素实现截图；实现坐标以本文、`options.json` 与 `PREVIEW.html` 为准喵
正式游戏中的所有数值、候选内容与可执行性仍需读取项目状态喵
当前环境没有浏览器，验证范围为 JavaScript 静态检查及有限状态逻辑验证，未进行浏览器交互与渲染实测喵
接入引擎后应重点核对透明留白映射、中文字体实际占宽、数量输入与库存边界、批量结算的一致性、不同选项数量下的滚动、连续目标阶段以及键盘焦点可见性喵

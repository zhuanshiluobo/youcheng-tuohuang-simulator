# CardViewer v3.6.1 接入说明

这是独立卡牌查看窗口的增量规范与素材补丁，未修改实际游戏工程。窗口背景沿用角色牌选择界面，卡牌居中呈现，不新增效果列表。

## 两种模式

| 入口 | `mode` | 窗口底部操作 |
| --- | --- | --- |
| 快速行动中的「使用角色牌」 | `use-character` | 从左至右：**计谋、策略、取消** |
| 点击设施牌 | `inspect` | 不显示上述三个按钮 |
| 点击盖放区、手牌区、弃牌区的角色牌 | `inspect` | 不显示上述三个按钮 |

快速行动列表仍可容纳其他种类的快速行动；「使用角色牌」只是其中一个入口。窗口不根据卡牌类型或所在区域自行开启使用权限，必须由调用方显式传入 `mode`。

## 显示和关闭

- 卡牌按原图比例完整显示，采用 `contain`；不拉伸、不裁切，也不把文字或数字烘焙到卡图上。
- 普通查看模式隐藏整个按钮组，卡牌位置保持不变，底部仅显示关闭提示。点击窗口外部、按 Esc 或系统返回操作关闭窗口。
- 使用模式在卡牌下方显示三个按钮。计谋和策略各自支持可用、不可用状态；不可用原因由规则层传入，在对应按钮附近显示。
- 「取消」、点击窗口外部、Esc 或系统返回关闭窗口并回到原快速行动页面，不提交效果。点击卡牌本身不执行任何操作。
- 关闭后恢复原页面的分页、滚动位置与焦点。普通查看不会改变卡牌状态。

布局采用 1920 × 1080 基准，窗口复用原始 1774 × 887 背景。卡牌在固定的 520 × 558 展示区域内居中，计谋、策略按钮均为 224 × 64，取消为 176 × 64；前两项使用同款米灰底和细金线，取消使用暖棕色次按钮。精确坐标、缩放与新版按钮切片见 `LAYOUT.md` 和布局数据文件。

## 规则层与界面的分工

`card.displayImage` 是调用方已确认可向当前玩家展示的图像。查看盖放牌时，调用方应按游戏规则传入正面或背面；本窗口不推断身份、不自行翻面，也不预载未授权的正面图。

规则层分别提供计谋、策略是否可用及不可用原因。点击可用按钮后，界面发出 `request-effect` 事件并隐藏窗口；规则层再次校验并决定执行效果或进入后续目标、资源等选择流程。按钮点击本身不等于规则结算完成。此时不额外发出 `close` 事件。

规则层处理期间应避免再次提交同一请求。若复核失败，由调用方提示原因，并按更新后的规则状态重新打开窗口。不要因为只有一项可用就自动执行该项。演示页面仅输出事件，不执行实际游戏规则。

## 调用数据

完整约束见 `integration/viewer-schema.json`。`plot` 对应**计谋**，`strategy` 对应**策略**。

使用角色牌示例（卡图路径为接入时替换的示例值）：

```json
{
  "mode": "use-character",
  "source": "quick-action",
  "card": {
    "id": "character-001",
    "type": "character",
    "name": "角色名称",
    "displayImage": "cards/character-001-front.png"
  },
  "effects": {
    "plot": { "enabled": true },
    "strategy": {
      "enabled": false,
      "disabledReason": "由规则层提供不可用原因"
    }
  }
}
```

普通查看示例：

```json
{
  "mode": "inspect",
  "source": "covered-area",
  "card": {
    "id": "covered-slot-001",
    "type": "character",
    "displayImage": "cards/character-back.png"
  }
}
```

`card.name` 可省略。盖放牌的实例 ID、名称和替代文本也应避免泄露当前玩家无权知道的信息。

## 输出事件

| 事件 | 数据 | 调用方行为 |
| --- | --- | --- |
| `request-effect` | `{ "cardId": "…", "effect": "plot" }` 或 `"strategy"` | 复核规则，执行或衔接后续选择 |
| `close` | `{ "reason": "cancel" }`、`"back"` 或 `"outside"` | 关闭并恢复原页面，不执行卡牌效果 |

普通查看只会发出 `close`。使用模式的取消按钮发出 `close`，其 `reason` 为 `cancel`；Esc 与系统返回统一为 `back`。两种模式均可点击窗口外部关闭，理由为 `outside`。

## 接入验收

1. 同一张角色牌：从「使用角色牌」进入时有三个按钮；从手牌区点击查看时无按钮。
2. 设施牌、弃牌与盖放牌查看均不出现操作按钮；盖放牌仅显示上游传入的图像。
3. 横向或纵向卡图均保持完整比例，并在可用展示区域居中。
4. 两个效果分别按传入状态禁用；禁用按钮不触发事件；取消和返回不执行效果。

## 浏览器参考组件

页面引入 `integration/card-viewer.css` 和 `integration/card-viewer.js` 后：

```js
const viewer = new CardViewer({
  assetBase: 'assets',
  onRequestEffect: ({ cardId, effect }) => {
    // 宿主复核规则，随后执行或进入下一步选择。
  },
  onClose: ({ reason }) => {
    // 取消/返回只关闭查看窗口，不消耗卡牌。
  }
});
viewer.open(input, invokingButton); // input 使用上面的数据结构。
// 系统返回键由宿主映射：viewer.close('back');
// 释放组件：viewer.destroy();
```

默认覆盖整个页面；可用构造参数 `host` 指定有尺寸、已定位的容器。组件同时发出 `cardviewer:request-effect` 和 `cardviewer:close` DOM 事件，可选用事件监听或回调一种方式接入，避免重复结算。

实际游戏通常传入独立卡图。图集可选用构造参数 `resolveImageRegion(card)` 返回 `{x,y,width,height}`，以源像素指定完整的单张卡区域；不传时显示整张图。演示只用它从原图集中取出完整坎诺特卡面，没有修改原图。

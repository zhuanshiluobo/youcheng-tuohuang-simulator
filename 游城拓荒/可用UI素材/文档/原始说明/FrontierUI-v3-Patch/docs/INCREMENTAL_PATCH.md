# 拓荒协作风格 · 3.1 增量补丁说明

本补丁以 `MainGameUI-v2.2` 为主界面基线，替换框体与顶栏，增加常驻底栏、结算链／可选效果抽屉及撤销入口，保留游戏原卡、原城市板和现有规则语义喵

补丁采用暖灰资料底、石墨色薄框与工程黄操作色，底图、边框、内容、图标、文字和命中区保持分层，避免把完整界面烘焙成一张图片喵

## 增量范围与基线

| 区域 | 补丁内容／接入目标 | 接入方式 |
|---|---|---|
| 主界面框体与顶栏 | 改用新版通用组件与顶栏组件 | 用新映射覆盖对应旧素材角色 |
| 主界面布局 | 为常驻底栏腾出空间 | 使用下表新矩形，不只替换图片 |
| 结束行动 | 从右下主要行动页移到全局底栏 | 只保留一处交互入口 |
| 结算链与可选效果 | 全局底栏摘要＋可收起抽屉 | 由规则层提供当前步骤与可选项 |
| 撤销 | 新增可用／禁用状态与原因 | 绑定当前可撤销步骤 |
| 建设窗口效果区 | 提供迁往全局抽屉的接入合同 | 适配后原区仅保留只读报价摘要 |
| 其他已交付窗口 | 可映射新版通用框、底图和标题组件 | 需要各窗口独立接入与复核 |

旧包中的卡牌比例、企业合作等级、城市样式标记和内容权限继续有效，补丁没有把企业家可见槽位数改成游戏数量上限，也没有改变盖放卡的查看权限喵

组件可供其他窗口复用，不代表企业、城市样式、莱茵科室等历史窗口已经全部完成新版渲染，实际重绘范围以本补丁随附预览为准喵

## 底栏与结算状态

中央槽在收起状态展示当前步骤、必要处理数量和可选效果摘要，展开后分别显示必选结算链与规则允许的可选效果喵

| 内容 | 展示与交互约定 |
|---|---|
| 必选结算链 | 保留顺序、当前节点和待完成原因，未完成时阻止结束行动 |
| 可选效果 | 显示来源、资格、选择状态、费用影响和不可用原因 |
| 子选择 | 打开对应选择器，结果回到同一结算上下文 |
| 暂无效果 | 显示空状态，不隐藏整个底栏 |
| 等待规则结果 | 显示处理中，锁定重复提交入口 |
| 结束行动 | 由规则层提供可用状态；必要结算未完成时强制禁用 |

抽屉为更多条目预留以下独立纵向滚动区域，当前示例仅 3 个结算步骤与 2 个效果，没有溢出时不显示滚动条，以下坐标是扩展接入合同喵

| 内容 | 视口 | 右侧轨道 | 命中热区 |
|---|---|---|---|
| 结算链 | `(467,842,276,105)` | `(750,842,4,105)` | `(744,838,16,113)` |
| 两列可选效果 | `(787,844,502,112)` | `(1300,844,4,112)` | `(1294,840,16,120)` |

两个区域分别保存滚动偏移，标题和右侧结算摘要固定，长文或复杂选项进入子选择器处理，不能将全部内容强塞进 `112 px` 高的效果区喵

子选择器继承当前 scope，主体与操作区也须避开常驻底栏，不新建第二套独立效果状态喵

必选与可选分别保存，不把所有条目都做成勾选框，也不默认允许拖动重排、一次批量发动或任意叠加减免喵

可选效果只有在规则层允许的时点才能提供，进入底栏并不意味着它可以绕过普通快速行动的时机限制喵

`结束行动` 仍然表示结束当前行动，界面不据此推断结束整回合、自动跳过必要步骤或自动发动剩余可选效果喵

## 撤销接入合同

撤销针对规则层明确给出的当前可撤销步骤，不默认回退整回合，按钮名称由 `undoLabel` 提供，例如 `撤销选择` 或 `撤销上一步` 喵

| 规则字段 | UI 责任 |
|---|---|
| `undo.canUndo` | 决定撤销是否可提交 |
| `undo.disabledReason` | 显示禁用原因 |
| `undo.undoLabel` | 显示本次撤销的实际范围 |
| 当前结算 scope | 保证弹窗、抽屉、底栏属于同一操作 |
| 异步 pending | 统一阻止重复或冲突提交 |

`canUndo = false` 时禁用样式、鼠标、键盘快捷入口和公开接口都必须阻断撤销意图，不能只改变按钮颜色喵

`canUndo = true` 时也需在提交入口重新检查当前 scope 与 pending，旧回调、重复按键或旧窗口不能连续发出同一步骤的撤销喵

UI 不根据“最近点击过某按钮”或本地操作历史猜测能否撤销，能否回退、回退范围和状态恢复均由规则层决定喵

撤销成功后使用规则层返回的新状态刷新结算链、可选效果、城市／卡牌选择和当前报价，失效的报价与子选择不得继续确认喵

撤销失败或被拒绝时保留当前合法状态并显示原因，不先做本地回退再等待规则结果喵

## 建设窗口迁移合同

建设适配器应将旧窗口左侧效果列表迁到全局抽屉，窗口保留设施候选、城市目标、付款路线和只读报价摘要，不再保留第二套可点击的效果控制器喵

建设主体及确认区须避开常驻底栏，不能直接沿用旧窗口延伸到屏幕 Y `1012` 的矩形，底栏需要在建设过程中保持可见喵

设施、城市格或付款路线变化后，报价请求继续携带当前效果选择及子参数；底栏效果变化或撤销成功后，同步刷新建设报价喵

不能因为按原价暂时支付不起就删除候选，实际能否建设须依据当前目标、付款路线、合法效果及规则返回的最终报价判断喵

异客资源分配和其他需要选卡的效果继续使用各自子参数与子选择，不改成通用减价开关，也不默认可抵扣所有付款路线喵

弹窗与全局底栏共享同一个 scope，关闭或切换到其他操作时解除旧绑定，旧异步子选择不得写入后来打开的建设窗口喵

必要结算、待完成子选择、无效报价或统一 pending 任一仍存在时，相应建设确认或结束行动必须保持禁用喵

## 规则层责任

本补丁的素材与交互示例用于展示新版外观、组件分层和状态流转，示例不是真实规则执行器喵

真实接入需由游戏层提供候选、费用、必要步骤、可选效果、可用次数、顺序约束、取消权限和撤销能力，UI 只提交操作意图喵

回调与事件若同时暴露，接入层只选择一条结算入口或按意图标识去重，避免一次用户操作被执行两次喵

异步请求开始后统一进入 pending，完成后只接受仍属于当前 scope 的结果，再整体刷新页面和底栏，不能让各面板各自维护相互矛盾的结算副本喵

## 3.1 顶栏细化

本次仅细化顶栏内容：标题标识、回合编号块、动态进度刻度、行动旗图标、红区状态片及统一描边的功能按钮，64 px 顶栏高度和底部布局保持既定坐标喵

新素材包含 `round-plaque`、`turn-tag-refined`、`redzone-plaque`、`topbar-tool-default`、`topbar-tool-hover` 和五个 `icon-*` 图标，编号、标签、当前回合刻度与已开放状态由界面独立绘制喵

`turn-tag` 保留用于兼容旧映射，当前主界面使用 `turn-tag-refined`，设置图标已替换为确定的 SVG 路径，不再依赖字体中的齿轮字符喵

`topbar-tool-hover` 为已交付的悬停素材，当前 HTML 仍沿用控件整体高亮，游戏工程可将它绑定到按钮 hover 状态喵

开放回合由玩家人数决定，状态片使用 `round >= redZoneOpenRound` 判断已开放；两个信息同时显示，不能只显示当前状态而丢失开放回合喵

查看 `preview/topbar-detail.png` 可放大核对顶栏细节；完整重建依次运行 `node tools/build_assets.mjs`、`node tools/refine_topbar.mjs`、`node tools/render_preview.mjs`、`node tools/render_topbar_detail.mjs` 喵

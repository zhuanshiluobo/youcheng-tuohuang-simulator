# 《游城拓荒：铸基者》主界面图包与布局说明 · 2.2.0

这套图包将边框、底图、图标、玩家标记和交互状态拆开，文字及数字由程序渲染，每个模块可以独立移动或调整尺寸喵

2.2.0 仅重绘顶栏，按已确认效果图的比例、轮廓和留白使用哑光灰褐底、黄色小旗与右侧灰色三分区，屏幕 `y ≥ 72` 的模块沿用已确认布局与素材喵

概念图用于确定材质、配色和整体气氛，最终外观以本包实际 PNG 组合出的静态预览为准，不承诺与概念图逐像素一致喵

基础拼装顺序为独立底图 → 透明边框 → 内容图像 → 图标及文字 → 交互叠层，不能将标题、卡牌数量或玩家数字合并进背景 PNG 喵

新版艺术框体及按钮的 SVG 是通过相对路径引用生成 PNG 并进行九宫格裁切的封装，不代表内部金属、磨损和漆面细节变成了可编辑的矢量路径喵

`chrome.json` 中的艺术 SVG 和标题装饰板 SVG 通过相对路径引用 `05-textures/art/`，移动或重新导出时需保留这一目录关系，导出的组件 PNG 可以独立使用喵

模块填充底图包括 `module-fill-dark`、`module-fill-paper`、`module-header-fill`、`card-slot-fill`，顶栏和屏幕分别使用 `topbar-fill`、`screen-fill`，均与对应边框分离喵

通用填充 SVG 通过相对路径依赖 `05-textures/` 中的底纹，顶栏 SVG 引用 `05-textures/art/topbar-matte-source.png` 与独立无框底纹 `topbar-matte-background.png`，移动组件文件夹时必须保留这些目录关系；对应 PNG 已包含外观，可以独立使用喵

通用底图推荐独立采用温和拉伸或按 `cover` 裁切，底纹没有被宣称或验证为无缝平铺纹理；顶栏各部件遵循第 4 节的独立缩放约定喵

底图若采用不透明矩形，应在所属模块的形状内裁切，避免填充盖到切角边框外侧喵

标准外边距为 `16 px`，列间距为 `12 px`，模块内容建议留 `16 px`，子模块留 `12 px`，行内容留 `8 px` 喵

模块标题区预留 `40 px` 高度，图标与相邻文字一般相隔 `6 px`，按钮文字必须在控件内居中，不与外框共同拉伸喵

其他分辨率可先将整张逻辑画布按以下公式等比缩放并居中，不要单独压扁卡牌或城市板喵

```text
s = min(screenWidth / 1920, screenHeight / 1080)
offsetX = (screenWidth - 1920 * s) / 2
offsetY = (screenHeight - 1080 * s) / 2

screenRect = (
  offsetX + x * s,
  offsetY + y * s,
  width * s,
  height * s
)
```

需要更大的可读字号时，应调整模块排布或打开详情层，不通过改变卡面比例来挤出文字空间喵

表中的按钮和页签状态文件均位于 `03-controls/`，分别有 `.svg` 与 `.png`，图标保持方形等比缩放，不做九宫格喵

切分边距和内容留白是两个参数，例如普通模块的切分边距是 `24 px`，清单内容留白为 `12 px`，不能把切片宽度直接当成文字必须退让的距离喵

新版 `module-header-frame` 是底部金属接缝配左侧强调条，`thin-row-frame` 只有底部接缝，均不再形成包围整行的厚框喵

框体按四角、边条和透明中心分别处理，边框与底图保持独立，文字和图标不参与纹理的拉伸喵

SVG 封装与 PNG 输出对应同一艺术源图，修改目标尺寸时仍需遵守切分参数，不直接非等比拉伸整张框图喵

九宫格的源切分宽度不等于所有目标控件都必须保留同样大的内容内边距，顶栏、小图标按钮、页签属于紧凑显示，必要时缩放装饰或换用细行框喵

常规按钮应优先满足 `chrome.json` 中的推荐最小尺寸，按钮源切分的上下边距为 `18 px`，最低推荐高度为 `38 px`，地图加减等紧凑控件使用独立的 `stepper-frame` 与同名状态填充，推荐至少 `40 × 38` 喵

滚动条按清单中的长轴和端部切分参数伸缩，短轴整体按目标厚度缩放，轨道与滑块保持独立喵

卡槽框只负责内容外围装饰，不能从卡槽整张 PNG 的宽高推算原卡比例，完整卡详情按原比例显示，主界面的人物缩略图可以使用人像区域裁切喵

左侧标题装饰板为独立的 `01-topbar/title-plaque-frame.png` 与 `title-plaque-fill.png`，源尺寸均为 `474 × 64`，在 `(16, 0, 474, 64)` 显示，文字独立叠加，两层一起等比缩放喵

可选 `title-plaque.png` 是合并便捷版，不替代独立边框与底图，当前参数由 `01-topbar/topbar-v22.json` 定义，不能继续套用旧版 `512 × 72` 的端帽参数喵

## 5. 城市板与地图

城市板总共是 **3 列 × 4 行、12 个格子**，核心指挥塔是第三行第二列的单个格子，不是一个 3×2 区域喵

```text
coreCommandTower = { indexBase: 1, row: 3, column: 2 }
// 等价的零基索引：row = 2, column = 1
```

`07-originals/city-board.png` 沿用原城市板 `2059 × 3801` 的比例，置于 `(32, 472, 384, 576)` 内容区内完整显示，不裁切也不横向拉宽喵

按该内容区等比适配后，城市板约为 `(67.991, 472, 312.019, 576)`，左右空余位置属于正常留白喵

设施格的点击区域应按原图的实际格线标定，然后随城市板同一坐标变换移动，不能把包含外框的整张图简单平均分成 12 个点击框喵

| 弃牌区 | `(1368, 414, 220, 204)` | `(1604, 414, 6, 204)` | `(1598, 410, 18, 212)` |
| 盖放角色 | `(1650, 414, 220, 204)` | `(1886, 414, 6, 204)` | `(1880, 410, 18, 212)` |

本次弃牌和盖放角色示例各显示三层横向叠放，弃牌缩略图槽为 `136 × 182`，盖放卡背为 `108 × 153`，总牌数与当前绘制的示例层数分别处理喵

竖向滑块高度根据可见高度与内容高度计算，内容未溢出时隐藏滚动条喵

```text
maxScrollY = max(0, contentHeight - viewportHeight)
thumbHeight = clamp(trackHeight * viewportHeight / contentHeight, 24, trackHeight)
thumbY = trackY + (scrollY / maxScrollY) * (trackHeight - thumbHeight)
// maxScrollY = 0 时隐藏，不执行除法
```

滚动内容应裁切到自己的内容容器，透明图片画布不能扩大滚动范围或点击热区，轨道和滑块始终在卡牌内容右边的独立保留区喵

### 城市样式页

本局样式固定展示 6 张，其中 `Ⅰ` 类 4 张、`Ⅱ` 类 2 张，卡名、类型标签和玩家状态分开绘制喵

城市样式表使用一整块浅纸底和低对比度行分隔，保留外层模块框，逐行不再叠加厚重边框喵

`Ⅰ` 类四行的 Y 为 `750、790、830、870`，每行高 `36 px`，具体状态模式由该张卡的规则配置，不统一规定为未用与已用喵

当前四张行动型样例采用默认 `action` 模式，保留未用和已用两个状态槽；物资中转站等需要记录宣告的卡可采用 `declared_only` 模式，只显示独立的已宣告槽喵

| `Ⅰ` 类模式 | 状态 ID 与标签 | 相对于该行左上角的状态区域 |
|---|---|---|
| `action` | `unused`／未用、`used`／已用 | `(212, 0, 148, 36)`、`(368, 0, 148, 36)` |
| `declared_only` | `declared`／已宣告 | `(212, 0, 304, 36)` |

已宣告槽内仍按玩家颜色分别合并数量，没有该颜色标记表示未记录该玩家的宣告，不将已宣告当作已用，也不额外生成一个含义不同的未用槽喵

`Ⅱ` 类两行的 Y 为 `944、996`，每行高 `48 px`，五个状态列从左到右必须保持下面的顺序喵

| 顺序 | 状态 ID | 显示标签 | 含义字段 |
|---:|---|---|---|
| 1 | `remaining_2` | `2` | 余量 2，未标为已用 |
| 2 | `used_remaining_1` | `已用余1` | 已用标记，余量 1 |
| 3 | `remaining_1` | `1` | 余量 1，未标为已用 |
| 4 | `used_remaining_0` | `已用余0` | 已用标记，余量 0，无法执行 |
| 5 | `remaining_0` | `0` | 已耗尽，余量 0，无法执行 |

五列的 X 分别为 `1556、1624、1692、1760、1828`，每列宽 `60 px`，表头放在 `y = 910`，较长标签可以分为“已用／余1”两行喵

这五个标签是格子的状态说明，不是色块里的计数，不能把“已用余1”和“1”合并成同一格，也不能把两个余量为零的状态合并喵

最后一列 `0` 表示耗尽，即使 `used_flag = false` 也不能执行，未标为已用不等于当前可用喵

状态迁移及何时解除已用标记由规则层提供，UI 不擅自按回合自动重置喵

城市样式采用各玩家独立的纯色数字块，仅将同一样式、同一状态槽、同一玩家颜色的数量合并，不将不同玩家颜色合并成分色格喵

例如同一未用槽内的红色 `1` 和蓝色 `1` 应分别显示，不能换成一个红蓝分色块或合计数字 `2`，企业合作的分色格规则不用于这里喵

`Ⅰ` 类状态槽内可横排四个 `24 px` 数字块；`Ⅱ` 类状态槽采用两行两列的 `20 px` 数字块、间隔 `4 px`，使四名玩家同时处于同一状态时仍可全部显示喵

点击样式名称或详情入口查看完整卡文，不将长效果说明塞进紧凑行内喵

## 10. 玩家颜色组合、数字与格子标签

| 玩家标识 | 位值 | 色值 |
|---|---:|---|
| `G` | 1 | `#5FD200` |
| `Y` | 2 | `#FFBF00` |
| `B` | 4 | `#006CFF` |
| `R` | 8 | `#EC0000` |

组合掩码采用按位或，图包提供从 `00` 到 `0f` 的全部 16 种组合，`00` 表示没有玩家，其他 15 种表示非空组合喵

本次艺术修订保留精确色值和现有玩家标记资产，预览中的空等级格改用浅灰槽位底图，`cooperation-00` 原资产不因此被重新着色或替换喵

例如绿蓝同格为 `01 | 04 = 05`，对应 `04-markers/cooperation-05.svg` 或 `cooperation-05-32.png`，同组还有 `64` 和 `128` 像素版本喵

两色按对角线平分，三色按等宽竖条划分，四色固定为左上绿、右上黄、左下蓝、右下红，少于四色时按 `G、Y、B、R` 的固定顺序选取喵

| 状态 | 独立叠层基本名 |
|---|---|
| 悬停 | `04-markers/overlay-hover` |
| 选中 | `04-markers/overlay-selected` |
| 焦点 | `04-markers/overlay-focus` |

标记与状态叠层使用完全相同的位置及尺寸，叠层保留内部颜色，不能通过整体染色将多色标记变成单色喵

数字底块为 `digit-base-green`、`digit-base-yellow`、`digit-base-blue`、`digit-base-red`，底块没有数字，数字必须由程序在独立文字层绘制喵

绿、黄、蓝底上的数字建议黑色，红底上的数字建议白色，确切建议及对应颜色数据见 `markers.json` 喵

**颜色组合、数量和格子标签是三种不同数据**，颜色组合表示有哪些玩家，数量表示规则提供的数值，格子标签表示等级或状态喵

不能把组合掩码的十进制值当作数量，也不能自动把颜色数当作数量，企业合作格通常只需分色标记，等级 `0—5` 已由列标签表达喵

若某一用途需要显示各玩家不同的数量，应为每名玩家保留独立计数或在详情中列出，避免把一个没有归属说明的数字盖在多个颜色上喵

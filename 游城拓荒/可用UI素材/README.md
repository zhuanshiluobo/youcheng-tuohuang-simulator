# 可用 UI 素材阅读说明

本目录是 UI 开发 agent 的唯一选材入口。它按当前有效用途筛选原档案，去掉已被补丁替换的候选、示例图和预览图；同字节素材只存一份，并保留各自用途。整理日期为 2026-10-08。共核对 23 个源包、3,941 个包内文件，最终提供 1,276 个可用文件（含状态、分辨率变体和五种字体），约 86.6 MiB。

2026-10-18 用户批准将远端两套通用 UI 素材及制作源纳入仓库，见[通用 UI 补充包登记](文档/通用UI补充包登记.md)。这些包尚未接入正式界面；登记不替换现有用途标准，实际选材仍从本入口确认目标用途。

## 开始工作前

1. 先读 [当前用途标准与实际参数](文档/当前用途标准与实际参数.md)及[机器清单](清单/当前用途标准.json)，确认当前应该用哪张图；再查 [用途与替换规则](文档/用途与替换规则.md)。
2. 阅读 [用途依据与访问边界](文档/用户例外与入口.md)。主界面 2.2 卡框、企业/科室 3.2 按钮、普通窗口 module-frame、现用建设/部署图标均已直接成为当前标准，不能按旧默认映射回退。
3. 从 [素材用途索引](素材用途索引.md) 查到功能包，再在 [可用素材索引](清单/可用素材索引.json) 读取具体 `uses`、`sources`、`documents` 和 `parameters`。同一图的多个来源不等于可随意互换用途。
4. 读取该用途的原始说明和参数，检查状态、裁切、九宫格、透明区、留白及图层组合；最后核对当前场景/Prefab 实际绑定与场景覆盖。
5. 改图前记录“目标对象 → 用途 → 本库路径 → Unity 实际资源 → 采用依据”。只在被授权的界面改动范围内接入。

## 找不到素材时

必须反馈具体缺项，而不是用近似素材掩盖问题。反馈至少包括目标页面/控件、需要表达的语义与状态、已经查过的条目，以及缺少哪一张图或哪一态。可继续处理其他不依赖该素材的工作。

禁止因为“看起来差不多”借用别的按钮、框体、玩家标记、区域标记或卡面符号；禁止从预览中截图、恢复被替换旧图、自动生成/重画替代图，或用无说明的纯色块和系统默认图兜底。需要新增或特殊复用时，先取得用户对具体用途的授权并登记依据。

## 目录和清单

| 位置 | 作用 |
| --- | --- |
| `资产/` | 唯一可导入候选，按功能组织；仍须匹配条目用途 |
| `文档/原始说明/` | 原文副本，保留用途和方法；旧版角色映射以当前用途标准为准 |
| `参数/` | 原包参数及 `项目实际用法/` 的当前资产参数；二者冲突时以已确认的当前用法为准，不整包加载历史配置 |
| `清单/当前用途标准.json` | 当前角色、期望素材、实施状态及实际参数入口，优先于旧映射 |
| `清单/可用素材索引.json` | 唯一路径、哈希、尺寸、逐来源用途、使用说明和参数定位 |
| `清单/来源成员与去向.json` | 全部包成员的取舍原因；只有 `decision=可用` 的条目授予对应用途 |
| `清单/源包索引.json` | 23 个源包版本和 SHA-256；不需要日常重新访问原 ZIP |
| `清单/文档与参数哈希.json` | 原始说明/参数字节校验，防止转述丢失原规则 |
| `文档/项目贴图使用审计.md` | 当前标准、已撤销的误判、实际待修项和未实现项 |

原说明中的 `assets/...` 等路径是包内相对路径。通过“包名 + member”在来源成员清单中查 `catalogPath`；去重后可能位于另一个功能目录，**不可凭相对路径猜文件，更不能回到受限原档案补找**。参数中包含历史图名时，仅保留解释用途，不自动赋予可用资格。旧 QA、示例状态和参数不代表当前项目已实现或验收。

本库以 PNG/JPG 覆盖获准的独立视觉，五种字体保留原字节。SVG 是生产格式，其独立视觉已有 PNG 对应，不作为额外选材入口。1×、2×、4× 是同一素材的分辨率变体，不是不同功能；默认按现有 Unity 导入和源参数选择，不混用源像素切片与逻辑尺寸。原包预览、示例卡、生产纹理、HTML 和生成脚本不放入资产目录。

## 版本和资产所有权

素材期望按当前已确认用途直接维护。用户更改选材后，必须覆写对应用途、版本和实际参数，同时撤销旧期望；不能保留“旧默认＋新例外”两套冲突规则。没有其他当前用途的旧候选退出可用库。不同页面仍有各自标准，不能把企业/科室 3.2 按钮扩展成所有 UI 按钮的统一规则。

素材库是选材来源，当前场景和预制体仍是界面结构、样式、位置和静态文字的唯一来源。本次只整理素材及审计，没有重建界面、自动换图或修改场景/Prefab；报告中的问题应在后续明确的界面修改任务中处理。哈希或静态引用检查通过不代表视觉验收通过。

## 校验和后续维护

日常校验：

```powershell
python -X utf8 tools/ui/curate_ui_library.py --verify
```

该命令只读本库素材、说明和清单，不访问受限原档案；结果写入 `清单/校验结果.json`。修改素材或新增许可时，先记录用户目标与来源，再同步用途、替换关系和哈希；不得把新文件直接扔入资产目录绕过清单。

原档案目录在根 AGENTS.md 中设为未经授权禁止访问，`.rgignore` 另行排除常规搜索。此限制是 agent 工作规则，不是 Windows ACL。旧提示词、历史链接和脚本硬编码都不能绕过限制。

日常项目引用复扫：

```powershell
python -X utf8 tools/ui/audit_ui_library_usage.py --output Artifacts/ui-usage-audit
```

该工具只读取 Assets、BuildSettings 和新库清单；结果包括 GUID/哈希映射、对象引用、嵌套覆盖和场景依赖，不自动把未引用项判为漏用，也不会覆盖人工审计报告。

# 可选扩展包实装改动清单

企业扩和感染者扩应以开局选择的内容和规则模块接入，同一局的牌池、替换关系、规则版本和有效脚本在开局后固定。现有外部内容架构可继续使用，但单加 JSON 和 Lua 文件不足以完成企业、干员、持续技能和特殊牌区玩法。

本文基于 2026 年 10 月 1 日当前工作区源码和本地素材核对，2026年10月2日另补企业家49图及对应源码合同，列出“现在是什么、应改成什么、还缺什么”。本次只新增、补充文档；未改代码、内容包配置、场景、预制体或原始素材，未运行 Unity、构建、测试和界面生成器。工作区此前已有大量未提交改动，以下以磁盘当前源码为准，不代表 Git HEAD，也不构成运行验收。

## 应新增的最小数据合同

下列字段和类型是**建议**，不是当前已经存在的API；名称可在实装时统一，语义应保留。新状态沿用项目DTO与List形式，不放Lua table、闭包或Unity对象。

| 数据 | 需要记录的内容 | 解决的卡面要求 |
| --- | --- | --- |
| 本局规则配置 | 分开的启用扩展集合与房间模式、人数规则、定义版本、替换解析、有效模式能力、会话指纹。 | 同感染者扩展的基础部分与企业家模式有不同有效内容和流程；联机与恢复不丢模式。 |
| 企业实例 | 本局企业ID、来源definitionId、每玩家合作等级、已解锁特效、共享激活科室。 | 升级、触发、莱茵共享科室、罗德岛替换。 |
| 卡牌实例 | instanceId、runtime槽位、最终definitionId、持有者、所在牌区、激活模式、状态版本。 | 共享干员不变成每玩家一份，跨玩家转交及牌下区。 |
| 盖牌槽 | 槽ID、允许来源/类型、盖牌实例、可见性、当前使用状态、禁用行动轮。 | 流形额外盖牌、赫拉格、普通角色兼容。 |
| 持续能力实例 | 来源卡、能力模式、激活事件、订阅、频率记录、离场注销策略。 | 泥岩、阿米娅、诗怀雅、林和剩余游戏授勋。 |
| 专属区域 | 来源实例、区域ID、首次投入上限、可选容量、所存卡/标记实例、各实例所有者。 | 可露希尔设施、多萝西和异客标记、诗怀雅对手标记；不把“初始最多4枚”当成多萝西容量。 |
| Token实例 | 类型、实例ID、归属主体、地图位置或绑定城市、到期策略、供应。 | 公路、锁定、嘉维尔、终身合作。 |
| 绑定关系 | 角色实例与设施实例、来源效果、解绑/设施离场行为。 | 涤火杰西卡收尾买回。 |
| 随机与选择结果 | Host结果、来源effectNodeId、continuation版本、已完成阶段。 | 掷骰、企业/样式抽牌、干员选择、恢复不重掷。 |

`RuntimeId`表示替换链原稳定槽位，`definitionId`表示实际生效卡面，`instanceId`表示本局物理卡。三者不能混用。已有玩家角色ID带所有者语义，需给共享干员和跨玩家转交另定稳定实体策略，不能只改字符串前缀造成新实例。

## Effect和交互缺口

每个需要选择的原语要同时有宿主合法性、InteractionRequest持久化、决策玩家/可见性、候选ID、投影适配、回答命令、失败与恢复合同。UI本地算出的合法选项不能代替Host复验。没有候选、库存不足、离场目标和玩家放弃应有不同规范结果。

按用户裁定补空集合与不完整式合同：W/银灰直接选择影响力，每步排除已处理原所有者、更新候选；集合空时自动成功结束，不弹空框。企业特效无候选同样成功无效果。任意运行时Effect式不完整时跳过该式并输出日志，保留来源、节点ID、缺失项、原因和已完成状态；不虚构实际移除/支付，不重连重记。条件左式不完整跳过整个条件，不能当作支付成功创建右侧；左侧已支付后右式不完整则跳右式、保留已支付事实。

条件式沿用项目当前语义：先左侧支付，再创建右侧；右侧失败通常不回退已付费用并继续普通兄弟。雷神“结束无论如何洗混”、一次性回盒等收尾义务要采用显式finalization，不依赖成功分支最后一行恰好执行。不可偷偷改全局Condition的失败语义。

## 联机与恢复要求

房主确定扩展与模式后，将启用集合、模式值、规则版本及有效内容指纹作为房间开局合同。客户端校验本机可用内容、模式能力和指纹再入场；本次不要求顺带实现在线自动下载。缺包或版本不同应显示具体中文原因，不能回退基础规则继续玩。

当前ContentPackHash包含已读取的清单、定义、脚本和贴图，未启用内容也可能影响完整安装包哈希。建议保留安装完整性哈希，同时新增本局“有效定义+启用扩展+模式+规则版本”的会话指纹；是否拆分应作为版本决策，不能为了让不同包客户端连上就取消原检查。恢复要求原规则快照，运行中不重装配替换链或改变模式。

秘密裁掉的初始角色、干员抽牌、盖牌身份按所有者可见；企业等级、共享科室、公路、公开持续牌和地图token公开。Host日志可保存权威结果，客户端日志按可见性生成；“已回盒”不意味着此前秘密回盒的牌名变公开。

所有交互中断恢复都应验证已支付、已抽取、已移动、已注册、已结束的事实只提交一次。骰子和洗牌顺序由Host保存，不使用Lua隐式随机数或客户端本地重算。

## 界面需要新增的内容

房间使用用户已有的扩展与模式选项；读取、验证和同步分别绑定对应配置，Host控制，其他玩家只读。企业家是感染者模式，不在扩展列表再加一个企业家包。依赖、人数与模式能力不满足时用动态状态说明，静态选项名和布局沿用用户资产。

对局需要企业板与每玩家等级、共享科室、干员特派私密选牌、持续角色及其标记/牌下设施、授勋持有区、普通和流形盖牌槽、公路/嘉维尔/锁定token及到期状态。可复用已有图片查看器、卡牌选择器和统一Effect交互，新增区域与内容来源要保持一致。

UI文字配置原则沿用AGENTS.md：静态标题、按钮和布局由场景/预制体提供；卡名、等级、剩余次数、状态和错误是动态内容。多种固定交互提示放在可序列化配置或文案资产。实装时明确改动为场景覆盖还是回写源预制体；禁止通过测试和启动生成器覆盖现有资产。

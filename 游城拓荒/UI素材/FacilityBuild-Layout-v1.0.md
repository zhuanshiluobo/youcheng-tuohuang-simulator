# 设施建设窗口 · 1.0.0

本窗口将本次结算效果、设施候选与玩家城市分为三栏，沿用企业选择窗口的深色模块与原卡牌选择窗口的黄色确认按钮，卡面、城市、边框、底图与文字保持独立喵

## 三栏职责

| 区域 | 内容 | 固定部分 | 溢出处理 |
|---|---|---|---|
| 左侧结算效果栏 | 本次规则提供的效果选项与状态 | 标题、当前费用摘要 | 效果列表独立纵向滚动 |
| 中间设施候选栏 | 本次建设可选的设施卡 | 标题及候选来源说明 | 卡牌列表独立纵向滚动 |
| 右侧玩家城市栏 | 原城市板、现有设施与规则允许的目标格 | 城市保持完整等比 | 查看详情，不横向压缩原板 |
| 窗口页脚 | 当前选择、取消与确认 | 固定在窗口底部 | 不随任何列表滚动 |

设施卡默认按 3 列排列，常规 6 张占 2 行，候选数量由本次规则数据决定，界面没有固定 6 张的游戏上限喵

左侧效果栏即使没有可用效果也保留位置，以空状态说明当前没有可插入的结算效果，候选列表与城市不会因此跳位喵

候选列表滚动时，城市、效果选项、费用摘要与确认按钮保持原位置，左侧效果列表和中间卡牌列表拥有各自的滚动偏移喵

## 候选资格与支付能力

候选集合必须来自本次操作的规则来源，不能因为玩家当前按原价支付不起就将某张卡从列表删掉，减价、代付或其他已提供的结算效果可能改变最终可建设状态喵

原价、当前预计费用与最终可确认状态分别显示，费用尚未确定时显示待计算状态，不能把未完成计算当作费用为零喵

| 情况 | 候选显示 | 确认边界 |
|---|---|---|
| 本次规则提供的候选 | 保持可见，可查看与预选 | 等待目标、效果和费用校验 |
| 原价暂不可支付 | 保持可见，说明当前费用条件 | 不按原价提前过滤 |
| 已计算费用后仍不满足条件 | 保留选择与原因 | 阻止确认 |
| 规则明确不允许的对象 | 不作为可确认目标，原因由调用方提供 | 无法绕过资格检查 |
| 候选库存少于常规数量 | 显示实际候选数 | 不复制卡牌补足数量 |

选中设施与确认建设是两个阶段，预选可以让玩家查看效果选择后的费用变化，确认只能提交当前通过规则层校验的建设意图喵

## 可插入的结算效果

左侧固定区域用于显示调用方提供的结算效果，例如本次操作涉及的异客或马丁相关效果，名称、可选状态、费用影响和使用条件均来自规则数据喵

效果区可以表达可选择、已选择、强制适用、不可用、已结算等状态，具体状态种类以实际规则接口为准，不能根据角色名称自行添加效果喵

本组件不假设两个效果一定可以叠加，也不擅自决定减免、支付或结算的顺序，互斥、次数、前置选择与剩余资格由规则层提供喵

这里仅展示规则允许在当前结算时点处理的效果，不是可以任意插入快速行动的入口，普通快速行动不能因为出现在效果栏就绕过原时机限制喵

需要额外选择的效果应继续调用项目已有的选择流程，并在结果返回后刷新当前费用，不把复杂效果压缩成没有依据的开关喵

费用摘要固定在效果列表下方，显示当前付款路线、规则返回的本次应付数值与校验原因，基础费用保留在原卡上，已选调整保留在效果区，效果列表过长时摘要仍然可见喵

## 原图与比例

设施原图集为 `originals/facility-atlas.jpg`，尺寸为 `5400 × 5100`，网格为 9 列 × 6 行，每个卡面源区域 `600 × 850`，图集格数不等于本次候选数量喵

每张候选设施完整保持 `600:850 = 12:17`，显示尺寸为 `204 × 289`，卡片外的选中框、状态标签与命中区域分别配置喵

```text
facilityScale = displayCardWidth / 600
cardHeight = 850 * facilityScale
atlasCrop = (column * 600, row * 850, 600, 850)
```

玩家城市使用 `originals/city-board.png`，当前交付源为 `2059 × 3801`，按原比例完整显示，不能为了填满右栏把城市板压扁或拉宽喵

以宽 `354 px` 显示时，城市图高为 `354 × 3801 / 2059 ≈ 653.499 px`，布局允许保留小数，空余边距属于正常留白喵

城市仍为 3 列 × 4 行、12 个格，核心指挥塔是第三行第二列的单个格，不是一个 3×2 区域喵

城市目标格使用已标定的局部源矩形：三列 X 为 `100、730、1360`，四行 Y 为 `156、1036、1916、2796`，每格 `600 × 850`，不能把包含标题与外边框的整张图片简单平均分成 12 个命中区域喵

一基第 `r` 行、第 `c` 列的源矩形为 `(100 + 630 × (c−1), 156 + 880 × (r−1), 600, 850)`，核心指挥塔对应 `(730, 1916, 600, 850)` 喵

```text
cityScale = displayCityWidth / 2059
screenSlot = (
  cityX + sourceSlotX * cityScale,
  cityY + sourceSlotY * cityScale,
  sourceSlotWidth * cityScale,
  sourceSlotHeight * cityScale
)
```

现有设施、可用目标与选中目标由游戏状态提供，UI 不自行假设可以覆盖、替换或移走已有设施喵

常规 6 张时，三列卡面 X 分别为 `492、788、1084`，每张卡下方 `305 px` 处显示设施名称与放大入口，各卡的装饰与文字不得跨入独立滚动条热区喵

选中徽标位于卡面左上角的相对 `(208, 4)`，使用 `20 × 20` 金色底块和独立勾标，整体放在卡牌右侧留白，不覆盖原卡印刷分数喵

```text
column = i % 3
row = floor(i / 3)
centerOffsetX = N <= 3 ? (872 - (N * 280 + (N - 1) * 16)) / 2 : 0
cardX = 454 + centerOffsetX + column * 296 + 38
cardY = (N <= 3 ? 401.5 : 242) + row * 320 - candidateScrollY
cardWidth = 204
cardHeight = 289
captionY = cardY + 305
```

候选为 `1～3` 张时，包含卡名的 `313 px` 高单行内容在候选视口内水平、垂直居中，三张时 X 保持 `492、788、1084`，Y 统一为 `401.5`，不渲染第二排空牌占位喵

候选超过两行时继续在同一列宽和卡面尺寸下增加行数，容器只滚动候选内容，不压缩卡面或改变城市比例喵

两个竖向滚动条均放在各自列表右侧，轨道、滑块与较宽命中热区独立，滑块最小高为 `44 px`、宽为 `10 px`，不能让效果栏与候选栏共用一个滚动偏移喵

```text
maxScrollY = max(0, contentHeight - viewportHeight)
scrollY = clamp(scrollY, 0, maxScrollY)
thumbHeight = clamp(trackHeight * viewportHeight / contentHeight, minThumbHeight, trackHeight)
thumbY = trackY + (maxScrollY > 0 ? scrollY / maxScrollY : 0) * (trackHeight - thumbHeight)
```

没有溢出时隐藏对应滚动条并把该栏滚动偏移归零，列表内容不能滑入固定标题、费用摘要或页脚按钮区域喵

## 规则接入边界

常规设施来源是当前公共供应区，目标供应数为 6，牌库耗尽等情况下可能不足 6，其他候选来源必须由本次效果或项目规则明确许可喵

可露希尔《工程订单》允许从公共供应选至多 2 张名称不同的卡，第一张取走后先补供应再选择第二张，保存在角色卡下，之后建设可以使用这些卡下设施，并不因此免费建设，卡下设施清空后才弃置该角色喵

付款路线由调用方明确为资源费用或金券费用，资源路线应包含卡面规定的完整费用组合，若组合中也要求金券仍需支付；全金券费用是替代路线，不能将两条路线重复结算喵

异客《隐蔽仓库》的已生效卡最多存 5 个标记，每次支付资源时最多移除 2 个标记，抵扣等量源岩、源石或异铁，不能抵扣金券或至纯源石喵

异客需要按资源分配抵扣数量，接口应能表达源岩 `1` 加异铁 `1` 等分配，不自行添加只能抵同一种资源的限制喵

分配合计不能超过本次允许移除的标记数或实际持有数，各项也不能超过对应应付资源，具体合法性和最终费用由报价接口返回，界面不把它表示成无条件通用减价开关喵

### 延伸枢纽的独立选择

蓝、黄、红三张延伸枢纽各 1 张，初始从常规设施牌库移除，图集零基索引分别为 `21、32、43`，不能把这些卡加入常规设施供应候选喵

物流枢纽入场效果允许从余下延伸枢纽中选择 1 张并建设，因此该步骤展示实际余下的 `0～3` 张，可以放弃，不能固定补足 3 张喵

延伸枢纽与物流枢纽本体是两个建设对象，延伸需要另一个城市空位，自身没有建设费用、建造得 `−1` 分，不与本体共占一个格，也不退回此前已结算的本体费用喵

这一后续选择应由新的规则上下文打开窗口，保留三种颜色的独立候选身份，不因为名称相同而将它们合并喵

### 项目版本与可配置来源

用户项目中的“黑钢 5 级”以及马丁图纸／减价作为可配置来源支持，当前上传纸质规则中“从牌堆任意选择设施建设”见雷神 5 级，两者的版本差异由实际规则层提供对应来源，组件不绑定企业名称或固定候选数量喵

当前资料没有足够文本来给马丁图纸或减价写入具体张数与数值，示例槽可以显示 `暂无可用减价卡`，有实际效果数据时通过子选择接口继续选择对应卡牌，不影响窗口本身使用喵

## 运行时数据与报价

`preview/data.js` 保存实际布局和演示数据，设施候选来自 `candidateIds`，不能由 UI 对印刷费用自行筛选后重新生成喵

| 字段 | 责任 |
|---|---|
| `cards[].id`、`sourceRect` | 稳定设施身份与原图源区域 |
| `scenario.candidateIds` | 本次候选集合与顺序 |
| `scenario.sourceLabel`、`contextLabel` | 来源与当前操作说明 |
| `scenario.effectIds` | 当前时点允许展示的效果 |
| `scenario.legalCellsByCard` | 每个设施当前合法的城市目标格 |
| `scenario.occupiedCells` | 当前城市占用情况 |
| `scenario.resources` | 用于显示和报价的当前持有量 |
| `scenario.paymentModes` | 调用方允许的付款路线 |
| `scenario.canCancel`、`cancelLabel` | 取消权限及按钮文案 |
| `scenario.quoteTable` | 演示用显式报价表，不是完整规则引擎 |
| `state.cardId`、`cellId` | 当前预选设施与城市格 |
| `state.paymentMode` | 当前付款路线 |
| `state.effectSelections` | 当前效果选择及子参数 |

正常付款路线 ID 为 `resources` 或 `gold`，仅当规则上下文明确允许时才提供 `free`，例如单独的延伸枢纽步骤，玩家不能自由切换到未经允许的免费建设喵

异客的当前参数使用按资源分配的 `credits` 对象，以下仅表示选择意图，是否合法仍由报价接口判断喵

```json
{
  "passenger": {
    "credits": {
      "rock": 1,
      "originium": 0,
      "iron": 1
    }
  }
}
```

报价请求应包含当前 `cardId`、`cellId`、`paymentMode`、`effectSelections` 与持有资源，报价结果通过 `valid`、`affordable`、`costs`、`reason` 和 `pendingSubchoice` 表示合法性、支付能力、费用、原因与待完成子选择喵

只有候选及目标有效、报价合法且可支付、所有必要子选择完成时才允许确认，没有匹配报价时显示等待调用方提供结果，不用空费用列表代替已计算的免费建设喵

## 预览接口与确认返回

离线预览提供 `window.facilityBuildPreview.open(configOrId)`，可传入示例场景 ID 或完整配置，配置中的 `quote(request)` 同步返回当前报价，演示中的 `quoteTable` 只用于固定示例喵

配置可额外提供 `cards`、`effects`、`cityCells` 替代演示集合，用于项目自己的设施、效果和城市数据，不需要修改全局示例对象喵

`requestSubchoice({ effectId, cardId, cellId, paymentMode })` 可异步打开项目的其他选择器，返回的选择参数写入对应 `effectSelections`，子选择未完成时不能确认建设喵

异步子选择和确认响应绑定本次操作，旧窗口的迟到结果不会写入新打开的操作，调用方仍负责规则版本和实时对局状态的复核喵

`onConfirm(payload)` 可以异步交给规则层复核，返回 `false` 时保留当前窗口和选择，接受后才关闭预览窗口；组件仍不自行扣除资源、效果标记或变更城市喵

确认结果包含以下字段，示例仅演示数据结构喵

```json
{
  "scenarioId": "standard",
  "cardId": "facility-15",
  "cellId": "r2c2",
  "paymentMode": "resources",
  "effectSelections": {
    "passenger": {
      "credits": { "rock": 2, "originium": 0, "iron": 0 }
    }
  },
  "quote": {
    "valid": true,
    "affordable": true,
    "costs": [
      { "resource": "rock", "count": 1 },
      { "resource": "iron", "count": 2 }
    ],
    "pendingSubchoice": false
  }
}
```

接受确认后在 `window` 派发 `facility-build-confirm`，结果位于事件 `detail`，需要在接入层避免同时通过回调和事件重复执行建设喵

`onCancel(payload)` 与 `facility-build-cancel` 返回 `scenarioId` 和 `reason`，普通取消为 `cancel`，延伸步骤的跳过为 `skip`，取消仍遵循 `canCancel`，提交或等待子选择期间不能取消喵

每张候选的 `放大` 入口可显示 `480 × 680` 的完整原卡，比例仍为 `12:17`，关闭后回到原选择，放大不修改候选、付款或城市状态喵

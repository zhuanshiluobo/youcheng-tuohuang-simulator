# 通用效果条目补丁 v3.4

## 1. 统一样式与分层

v3.4 仅更新视觉：以暖灰棕底图、轻微纸面纹理和米灰细边框替换 v3.3 的冷灰绿外观，减弱双层框线，工程黄只用于可执行入口及悬停、按下等交互强调喵。

三种模式、零至两个玩家标记、右侧状态语义、向下展开与城市压缩参数均沿用 v3.3，不增加规则行为喵。

| 色彩部件 | v3.4 色值 |
| --- | --- |
| 默认底图填色／底部压线 | `#453E35` / `#3B352D` |
| 默认细边框 | `#9A8D78` |
| 正文／次级文字 | `#E8DDC3` / `#A89B83` |
| 可执行图标 | `#DFBE68` |
| 已使用只读图标 | `#CABB9D` |
| 未使用只读图标 | `#E8DDC3` |

底图内部保持完全不透明，仅圆角外部透明，换用不同背景不会使其主体变成冷灰绿喵。

纸面纹理的局部透明度约为 2.5% 至 8%，用于轻微纤维与颗粒，不会改变底图主体的不透明属性喵。

默认边框采用单条完整细轮廓，不再叠加第二层完整内框，悬停与按下外观沿用原有状态字段喵。


选择执行选项、左上其他玩家永续效果明细、右下快速行动共用一个条目组件，以模式和可选插槽控制内容喵。

从底到顶依次绘制独立底图、独立边框、可选左侧玩家标记、运行时标题与说明、可选右侧状态／使用图标及焦点提示喵。

底图和边框分开缩放，文字、数字和图标不烘焙进底图，便于调整宽度、替换卡名和接入不同引擎喵。

## 2. 模式与字段

| `mode` | `markers` | `right.status` | 行为 |
| --- | --- | --- | --- |
| `choice_execute` | 必须为空数组喵。 | 必须为 `use` 喵。 | 右侧使用按钮执行选项，是否可用由 `right.enabled` 决定喵。 |
| `persistent_detail` | 长度为 0、1 或 2 喵。 | `none`、`unused`、`used`、`use` 喵。 | 以查看效果和标记为主，仅在规则确有执行入口时使用 `use` 喵。 |
| `quick_action` | 长度为 0、1 或 2 喵。 | `none`、`unused`、`used`、`use` 喵。 | 沿用同一条目，根据行动当前状态选择右侧呈现喵。 |

`markers` 与 `right` 两个区域分别可选，不要求同时存在，永续效果也不必一律显示“已使用／未使用”喵。

`persistent_detail` 查看别人的效果时默认只读，只有游戏规则明确允许当前操作者执行的效果才可以显示可点击的 `use` 喵。

模式控制允许出现的区域，游戏规则层提供状态与数据，组件不根据标题推断效果次数、标记含义或行动合法性喵。

## 3. 右侧状态与交互

| `right.status` | `enabled` | 显示含义 | 接收执行事件 |
| --- | --- | --- | --- |
| `none` | 忽略喵。 | 无右侧图标并回收该区域喵。 | 否喵。 |
| `unused` | 忽略喵。 | 尚未使用的只读状态喵。 | 否喵。 |
| `used` | 忽略喵。 | 已使用的只读状态喵。 | 否喵。 |
| `use` | `true` | 当前可执行的使用按钮喵。 | 是喵。 |
| `use` | `false` | 当前不能执行的使用按钮喵。 | 否喵。 |

禁用的使用按钮保留操作图形，使用禁用配色，不替换成已使用图标喵。

`use` 有普通、悬停、按下和禁用外观，键盘焦点另行叠加，不改变 `right.status` 的业务含义喵。

预览中的使用按钮通过 `data-action="row-use-{id}"` 发出界面操作标识，宿主把条目 `id` 映射到实际游戏操作，使用次数和执行后的状态由游戏规则回传，不在点击时直接假设变成 `used` 喵。

可选的 `bodyAction` 为正文区域添加独立的详情入口，与右侧使用按钮分开，不覆盖右侧状态区喵。

当前组件省略 `right.enabled` 时默认可用，正式接入应由规则层显式传入布尔值，避免未就绪的规则数据误显示为可用喵。

只读状态不进入按钮的键盘焦点序列，不触发执行回调，禁用按钮阻止鼠标、触摸和键盘执行，禁用原因可由宿主界面提供额外提示，当前组件的默认提示为“当前不可使用”喵。

图标旁无需强制烘焙“使用”等文字，鼠标提示、长按提示和辅助阅读名称可使用“使用”“已使用”“未使用”喵。

## 4. 左侧玩家标记

每个条目支持零、一或两个玩家标记槽，每槽显示一个拼色方块，槽的数量与参与方的数量相互独立喵。

例如一个双色方块表示同一对应区域有两个玩家颜色，不等于两个槽位，一个条目上的两个方块则表示两个由游戏指定的对应区域喵。

| 玩家颜色 | 十六进制颜色 | 位值 |
| --- | --- | ---: |
| Green | `#5FD200` | 1 |
| Yellow | `#FFBF00` | 2 |
| Blue | `#006CFF` | 4 |
| Red | `#EC0000` | 8 |

每槽用 `mask` 指定非空组合，按位或计算，范围为 1 至 15，例如绿蓝为 `1 | 4 = 5`，四种颜色为 15 喵。

十五种非空颜色组合全部可复用，视觉分色顺序固定为绿、黄、蓝、红，避免同一组合在不同条目中改变含义喵。

隐藏玩家标记应删除对应槽，或使用空数组，不以 `mask=0` 表示一个空方块喵。

单色方块可以在其上叠加 `count` 非负整数，数字由运行时文字层绘制，显式的 `count=0` 仍显示为零，不把零自动当成隐藏喵。

多色方块在当前 28 像素尺寸下不强行塞入多个数字，各玩家数量写入 `label`，作为提示与辅助阅读文本表达，游戏层可保留自己的分色数量结构喵。

方块的 `label` 同时用于提示与辅助阅读，应解释对应区域及完整颜色、数量信息，两个槽位需要分别描述喵。

## 5. 条目布局与尺寸

以下尺寸为逻辑像素，缩放 UI 时统一乘以界面缩放比例喵。

| 参数 | 标准值 |
| --- | ---: |
| 标准条目高度 | 76 |
| 紧凑条目高度 | 60 |
| 左右内边距 `P` | 12 |
| 玩家标记边长 `M` | 28 |
| 两个标记之间间距 `Gm` | 4 |
| 标记／正文、正文／右图标间距 `Gs` | 12 |
| 右侧状态图标边长 `R` | 32 |
| 底图与边框九切边距 | 上下左右均为 12 |

设条目宽为 `W`、高为 `H`，左侧槽数为 `N`，则左标记组宽度 `L = N == 0 ? 0 : N × 28 + (N − 1) × 4` 喵。

正文左边界为 `textLeft = 12 + (N > 0 ? L + 12 : 0)`，正文右边界为 `textRight = W − 12 − (right.status != none ? 32 + 12 : 0)` 喵。

正文可用宽度为 `textRight − textLeft`，隐藏任一区域时由上述公式回收该区域及其间隔喵。

每个标记的左坐标为 `12 + index × 32`，上坐标为 `(H − 28) / 2`，右图标左坐标为 `W − 12 − 32`，上坐标为 `(H − 32) / 2` 喵。

当前 SVG 示例的使用按钮点击区为 32 × 32，触摸端接入时可扩至 44 × 44 并居中对齐图标，扩展部分不得遮挡相邻条目的交互区域喵。

正文作为整体垂直居中，推荐标题一行、说明一至两行，超长正文可增高条目或用省略和完整提示，不将字横向压缩喵。

组件直接使用 `x`、`y`、`w`、`h` 布局字段，`h` 省略时为 76，左上紧凑明细传入 `h=60`，模式与尺寸可以分别配置喵。

对照预览用 `h=84` 展示较宽松的条目，标准 76 和紧凑 60 是建议高度，并非禁止调整的固定贴图比例喵。

## 6. 左上玩家明细展开与城市压缩

查看入口沿用可点击的展开／收起按钮，以向下／向上的箭头区分状态，并保留清楚的悬停、按下和焦点呈现喵。

没有永续条目的玩家仍可展开显示空态，不将空列表误当成按钮不可用喵。

按钮在收起时提供“查看永续效果”的提示，展开时提供“收起永续效果”的提示，辅助状态使用 `aria-expanded` 或引擎对应的展开属性喵。

默认同一时间只展开一名其他玩家，再次点击同一玩家收起，点击另一名玩家则切换展开对象喵。

明细插入在对应玩家面板下方，后续玩家面板顺次向下移动，不让明细以浮层覆盖其他玩家信息喵。

以 1920 × 1080 主界面为例，“我的城市”区域底边固定在 `y=978`，其原始顶部为 424、高度为 554 喵。

设本次明细展开量为 `E`，则 `cityTop = 424 + E`，`cityHeight = 554 − E`，任何情形下均保持 `cityTop + cityHeight = 978` 喵。

默认展开量为 `E=224`，因此展开后的城市区域为 `y=648`、`height=330`，收起后恢复 `y=424`、`height=554` 喵。

城市贴图沿用原图包素材，在压缩后的内容视口内使用等比 `contain`，缩放比例为 `min(viewportWidth / sourceWidth, viewportHeight / sourceHeight)`，再在视口中居中喵。

不要为了填满区域而纵向拉扁城市原图，城市显示缩放不改变城市格子、设施、标记和任何游戏数值喵。

展开面板内容过多时在内部纵向滚动，右侧竖直滚动条贴近展开内容视口的右边缘，轨道只覆盖条目列表的高度，不穿过玩家摘要或下方城市喵。

列表应预留独立的右侧滚动条通道，滚动条不叠在条目的右侧状态／使用图标上喵。

实际主界面坐标如下，`playerY` 表示被展开玩家摘要面板的顶部喵。

| 区域 | 条目视口 | 滚动条轨道 |
| --- | --- | --- |
| 左上永续明细 | x=28，y=playerY+126，宽374，高196 | x=414，y=playerY+146，宽4，高156 |
| 右下快速行动 | x=1366，y=703，宽510，高248 | x=1886，y=723，宽4，高208 |

轨道上下各留20像素给滚动箭头，4像素轨道的透明交互热区横向扩展到16像素，滑块高度按视口占内容的比例计算喵。

尺寸适配时优先限制明细高度并启用内部滚动，城市区域保留可读高度，不能允许 `cityHeight` 变为零或负数喵。

## 7. 引擎接入

`prefab-contract.json` 是组件字段和约束说明，可在 Unity、Godot 或现有 UI 框架内搭建对应组件，不是引擎可直接导入的预制体文件喵。

建议组件层级为 `RowRoot → Background / Frame / MarkerGroup / TextGroup / RightSlot / FocusRing`，装饰图层关闭输入拦截喵。

底图与边框按九切绘制，标记与状态图标保持等比，正文与标记数字使用项目字体独立绘制喵。

列表复用条目时要同时重置模式、左右可见性、数字、提示、点击回调和禁用状态，避免上一个条目的内容残留喵。

原有卡牌、城市面板、企业和行动规则继续由游戏数据层提供，本补丁只定义呈现和界面事件喵。

所有预览数据均为界面占位，示例数量、效果名称和使用状态不构成规则推断喵。

## 9. 主界面增量安装

`preview/effect-rows.html` 可独立离线打开，用于检查可选插槽、三种模式与使用状态，无需完整游戏资源喵。

完整主界面演示依赖 v3.1 的主界面资源和 v3.2 按钮补丁，可直接在该完整基线上安装 v3.4，也支持在已有 EffectRows v3.3 的同一完整主界面上升级，不要求先安装 v3.3 喵。

在本补丁目录运行以下命令，将参数替换为完整主界面根目录，目标不能是单独的按钮或条目增量补丁文件夹喵。

```bash
python tools/apply_patch.py "FrontierUI-v3-Patch完整目录"
```

安装脚本校验受支持的基线及输入文件，在替换前备份受影响的目标文件，遇到不匹配的本地修改时停止，以保留已有改动喵。

集成后的新素材目录为 `effect-assets-v3.4/`，渲染模块仍为 `preview/effect-row.mjs`，组件的独立源码位于本包的 `components/effect-row.mjs` 喵。

包内的 `assets/` 路径和安装后的 `effect-assets-v3.4/` 路径属于不同使用入口，接入引擎时以各自清单中的路径为准喵。

为保持宿主代码兼容，渲染器素材标识继续使用 `v33-` 前缀，前缀不代表仍加载旧版外观，v3.4 清单会将这些标识映射到新版素材目录喵。

本包与 v3.3 原交付包分别保存，运行升级仅作用于指定的完整主界面目录，不覆盖原交付压缩包喵。

当前归一化会丢弃不在 1 至 15 范围内或不是整数的标记掩码，不会把 `mask=0` 自动变成绿色标记，正式数据仍应在游戏层校验喵。

# 企业与企业特效选择窗口 · 1.0.1

本组件使用同一个窗口承载整家企业选择与企业板内特效选择，保留原企业板文字，通过独立边框、底图、状态叠层和程序文字表达当前操作喵

## 两种操作模式

| 模式 | 候选对象 | 选中内容 | 确认返回 |
|---|---|---|---|
| `company` | 一整张企业板 | 企业整体 | `companyId` |
| `effect` | 企业板中由规则层提供的企业特效行 | 某企业的某项特效与等级 | `companyId`、`effectId`、`tier` |

两种模式是不同操作的入口，企业确认后不会由本组件自动切换为特效选择喵

普通升级奖励行不是企业特效候选，不叠特殊框，也不注册为可选候选喵

窗口只展示调用方提供的数据并返回选择结果，不执行支付、合作升级、奖励结算或特效触发喵

是否允许取消、确认前的资格检查及确认后的动作均由规则层决定，程序接入时应再次校验最终候选仍然有效喵

## 原图、比例与图层

原企业图集为 `originals/enterprise-atlas.jpg`，原尺寸 `2600 × 3700`，共 4 列 × 2 行、8 张企业板，每板 `650 × 1850` 喵

以零基企业索引 `i` 计算源裁切矩形，完整企业板必须保持 `650:1850 = 13:37` 的原比例喵

```text
sourceX = (i % 4) * 650
sourceY = floor(i / 4) * 1850
sourceRect = (sourceX, sourceY, 650, 1850)
scale = min(targetWidth / 650, targetHeight / 1850)
displayWidth = 650 * scale
displayHeight = 1850 * scale
```

原始图集保持独立且不重画，选择边框不得合并进图集，详情放大仍展示原板中的原始文字喵

| 层次 | 内容 | 与原图的关系 |
|---:|---|---|
| 0 | 对局背景及模态遮罩 | 仅衬托窗口 |
| 10 | 窗口、卡槽与详情底图 | 独立 `fill` |
| 20 | 窗口、槽位与按钮边框 | 独立 `frame` |
| 30 | 完整原企业板、详情原文裁切 | 独立 `content` |
| 40 | 特效候选特殊框、选中与不可选叠层 | 不修改原图 |
| 50 | 标题、原因、合作等级数字、按钮文字 | 程序文字 |
| 60 | 横向滚动条及焦点层 | 独立交互层 |

装饰边框与底图不包含企业名称、回合数、合作等级、按钮文字或候选序号，文字与数字在运行时绘制喵

每张企业板上方单独设置 4 个玩家颜色数字块，预览从左到右为红、蓝、黄、绿，数字由规则数据提供，表示各玩家在该企业的合作等级，不遮挡原板文字喵

| 玩家颜色 | 精确色值 | 数字含义 |
|---|---|---|
| Green | `#5FD200` | 该玩家在本企业的合作等级 |
| Yellow | `#FFBF00` | 该玩家在本企业的合作等级 |
| Blue | `#006CFF` | 该玩家在本企业的合作等级 |
| Red | `#EC0000` | 该玩家在本企业的合作等级 |

这些数字块与企业整体选择状态、特效等级标签分别处理，不将多个玩家的合作等级合并为一个数字喵

## 候选、选中与不可选

| 状态 | 展示要求 | 查看详情 | 确认 |
|---|---|---|---|
| 可选 | 候选范围清楚，普通状态框 | 允许 | 选中后由调用方校验 |
| 选中 | 独立高亮叠层与文字摘要 | 允许 | 当前候选有效时允许 |
| 不可选 | 可见但弱化，并展示原因 | 允许 | 禁止 |
| 非候选升级奖励 | 保留原板，不加特效候选框 | 可随原板查看 | 不作为候选 |

整企业模式将选择状态附着在企业整体，特效模式只为明确提供的特效行叠特殊框，不根据印刷色彩或行高自动猜测候选喵

查看对象 `inspected` 与已选对象 `selected` 分开管理，点击不可选灰框时清空选择、更新查看对象并禁用确认，仍能阅读原文和原因喵

不可选条目不能通过点击、键盘或确认按钮绕过资格检查喵

未选中有效对象时确认按钮保持不可用，确认标签与摘要应指向同一个选择对象喵

状态框正文区统一为 `x = 160, width = 482`，上下各缩进 `6` 源像素；所有勾选与锁图标统一位于 `boardX + 252`，即板右侧 `4 px` 外，显示为 `20 × 20`，最后一列也使用右侧留白，不遮盖原板正文喵

对局部源矩形 `(rx, ry, rw, rh)`，使用与企业板相同的显示缩放和滚动偏移，不能单独拉伸特效框内容喵

```text
boardScale = displayBoardHeight / 1850
frameRect = (
  displayBoardX + rx * boardScale,
  displayBoardY + ry * boardScale,
  rw * boardScale,
  rh * boardScale
)
```

框的装饰外扩可与命中区域分开配置，透明贴图画布不自动成为候选命中区，框体不得遮住需要阅读的原特效文字喵

详情区使用同一候选的原图裁切放大，并单独显示企业、等级、选择状态与不可选原因，特效规则不由美术文档另行编写喵

## 布局与横向浏览

窗口使用 `1920 × 1080` 逻辑画布，坐标以左上角为原点，布局只缩放视觉，不改变原企业板比例喵

固定区域包括窗口标题、候选说明、右侧详情、选择摘要、取消与确认，企业板列表单独横向滚动喵

候选数为 2 时在候选视口内居中，4 张时同屏展示，超过 4 张时使用横向滚动，不缩窄每张板来强塞全部候选喵

横向滚动条位于候选区下方，轨道、滑块与交互热区分离，滑块长度根据视口与内容宽度计算，当前最小宽为 `48 px`、高为 `12 px`、顶部 `y = 922` 喵

```text
maxScroll = max(0, contentWidth - viewportWidth)
scrollX = clamp(scrollX, 0, maxScroll)
thumbWidth = clamp(trackWidth * viewportWidth / contentWidth, minThumbWidth, trackWidth)
thumbX = trackX + (maxScroll > 0 ? scrollX / maxScroll : 0) * (trackWidth - thumbWidth)
```

未溢出时隐藏滚动条并把滚动偏移归零，拖动滑块、列表滚动和切换候选时使用同一 `scrollX`，右侧详情不随候选列表移动喵

最终主区域使用以下屏幕矩形，父窗口原点为 `(88, 68)`，需要窗口局部坐标时分别减去 `88` 与 `68` 喵

```text

```

## 规则层的判定边界

企业升级与企业特效触发是两种动作，合作升级使相应特效解锁，触发特效时可从全部已解锁特效中选择 1 项，不只选择当前等级所在行喵

已解锁的基本阈值为自身在该企业的合作等级不低于特效要求等级，是否可在当前操作触发还需要规则层检查费用、目标和触发条件喵

不可选原因应区分未解锁、费用不足、缺少必要目标等情况，不使用一个模糊的锁定标记代替具体说明喵

不能统一添加每回合只能触发 1 次的限制，重复触发是否允许由具体规则决定；普通组合效果应按规则尽量执行，不能仅因某一步无目标就一律禁止整个特效喵

罗德岛 4 级特效在没有弃牌时明确不可使用，这类具体限制由调用方绑定到对应特效，不扩展为所有企业的共同规则喵

| 规则说明 | 规则书印刷页 |
|---|---:|
| 每局 4 家公共企业，3 人补足 4 家 | 17 |
| 升级解锁与触发已解锁特效的区别 | 18 |
| 雷神工业特效可反复触发的具体说明 | 21 |
| 罗德岛 4 级无弃牌时不可使用 | 22 |
| 组合效果按规则尽量执行 | 13 |

## 演示与游戏数据

演示候选使用图集索引 `0、1、6、3` 的罗德岛、海德兄弟、黑钢国际、富森银行，HTML 与静态渲染共用 `preview/data.js`，演示状态与数字用于说明视觉和交互，不作为真实对局的规则判定喵

当前示例中红方在四家企业的合作等级依次为 `2、3、2、1`，持有 `1` 源岩，海德 2 级特效已解锁但费用不足，海德 4 级尚未解锁，两种不可选原因分别显示喵

窗口数据是独立的另一局示例，后方静态主界面只作为背景，不能将背景企业或等级数字当作本窗口的数据来源喵

每局使用 4 家企业，开局各玩家从 2 家中选择 1 家，3 人局补充随机第 4 家；本组件仍支持 2、4 或更多候选的显示喵

需要由调用方提供的内容包括当前模式、操作来源、候选集合、特效源区域、可选资格、不可选原因、当前选择以及是否允许取消，玩家合作等级可以按场景提供或省略喵

接入项目时以稳定企业 ID 和特效 ID 关联数据，图集索引仅用于美术定位，不把数组位置当作游戏规则身份喵

数据字段以 `preview/data.js` 为准，其中 `companyId` 表示企业 ID，`effectId` 表示特效 ID，`tier` 表示特效要求等级，不使用另一个不同命名的返回结构喵

| 字段 | 含义 |
|---|---|
| `scenario.mode` | `company` 或 `effect` |
| `scenario.contextLabel` | 当前规则操作的说明 |
| `scenario.companyIds` | 本次展示企业集合与顺序 |
| `scenario.canCancel` | 当前操作是否允许取消 |
| `scenario.initialSelectedId` | 初始已选目标，可为 `null` |
| `scenario.targets` | 调用方提供的候选目标及资格 |
| `target.id` | 当前目标的稳定唯一 ID |
| `target.companyId` | 目标所属企业 |
| `target.effectId`、`target.tier` | 特效模式的目标特效及要求等级 |
| `target.available` | 规则层给出的当前可选资格 |
| `target.disabledReason`、`target.reasonCode` | 不可选说明与原因代码 |
| `company.playerLevels` | 可省略的各玩家合作等级 |

预览提供 `company-choice`、`company-two`、`effect-choice` 三个场景，分别展示 4 家企业选择、2 家企业选择及企业特效选择喵

`effect` 模式需要一个来自规则层的当前触发来源，本组件不提供可随时免费触发全部企业特效的入口，也不自行添加每回合触发次数喵


## 确认、取消与预览接入

预览脚本 `preview/app.js` 提供 `window.enterprisePickerPreview.open(configOrScenarioId)`，可以传入场景 ID 或含候选数据的配置对象喵

配置对象可以附带 `onConfirm(payload)` 和 `onCancel(payload)`，预览也会在 `window` 上派发 `enterprise-picker-confirm` 与 `enterprise-picker-cancel` 事件，结果位于事件的 `detail` 中喵

整企业确认结果为以下结构，`contextLabel` 继续标识当前调用操作喵

```json
{
  "mode": "company",
  "contextLabel": "提升合作等级 · 选择1家企业",
  "companyId": "rhodes"
}
```

特效确认增加特效 ID 和要求等级，不提交支付或升级后的数值喵

```json
{
  "mode": "effect",
  "contextLabel": "企业特效结算 · 本次选择1项",
  "companyId": "hyde",
  "effectId": "hyde-1",
  "tier": 1
}
```

确认要求当前选中对象仍然可选，且详情查看对象与已选对象一致，确认后关闭演示窗口并返回目标，后续结算交给调用方喵

取消按钮、关闭入口与 Escape 均遵循 `canCancel`，允许取消时返回 `{ "reason": "cancel" }`，不提交任何选择目标喵

切换上方场景按钮只切换演示配置，重置只重新打开示例，不改变合作等级、资源或真实对局状态喵

# UI 素材整理与接入文档 · 2026-09-24

本目录整合当前 10 个 UI 素材包，按 `MainGameUI 2.2.0` 内容基线与 `Frontier 3.1` 增量组件确定采用关系。城市样式、莱茵科室等窗口已纳入整理。这里的“当前”指素材选用基线，不表示这些界面已在 Unity 中完成接入。

本次所有文件均为新增。上级目录的 10 个 ZIP、8 份原始说明，以及项目原有文档保持原样；没有运行 Unity 界面生成器，没有修改场景、预制体或游戏代码。

## 从这里开始

1. 阅读 [版本与替换关系](文档/01_版本与替换关系.md)，确定新版覆盖范围和仍需适配的窗口。
2. 查看 [预览索引](预览索引.md)，区分新版主界面、历史窗口拼装图和视觉样例。
3. 阅读 [界面布局与交互说明](文档/02_界面布局与交互说明.md)，获取合并后的主界面布局、窗口行为和数据边界。
4. 按 [Unity 接入说明](文档/03_Unity接入说明.md) 选择组件、转换坐标并连接现有 View。
5. 从 [资产目录](资产目录.md) 查找文件；机器读取使用 [资产索引](清单/资产索引.json) 与 [新版组件索引](清单/新版组件索引.json)。

## 目录用途

| 目录 | 内容与使用边界 |
|---|---|
| `资产/新版组件/Frontier-3.1/` | 当前新版组件的独立 PNG，包含主界面框体、顶栏、底栏、按钮和图标 |
| `资产/兼容组件/Frontier-3.1/` | 旧 `turn-tag`、`redzone-paper`；3.1 主预览未采用 |
| `资产/沿用标记/` | 四玩家色、企业合作组合及状态叠层；相同字节仅保留一份 |
| `资产/沿用图标/` | 基线图标；同用途已有新版图标时优先新版 |
| `资产/沿用控件/` | 未交付专用新版切图的页签、步进器和滚动条；保留原样供适配 |
| `资产/窗口专用/` | 选择状态框、选项条、卡牌选中图等窗口专用素材 |
| `资产/原始内容/` | 原卡图集、城市板、地图、资源图标、六张科室板；实际规则版本由项目选定 |
| `预览/` | 源包图片的原样副本，目录名保留来源版本 |
| `参考/示例内容/` | 用于布局校准的示例卡，不是正式候选数据 |
| `原包参数/` | 71 份 JSON 的原样副本，内部相对路径仍以各自源包根目录为基准 |
| `清单/` | 源包哈希、全部成员、唯一图像、重复来源、替换关系和校验结果 |
| `文档/` | 本次新写的综合说明，原始说明仍在上级目录 |

`原包参数` 不能整体作为游戏运行时配置直接加载。先通过 `源包文件索引.json` 的 `package + relativePath` 查到整理后的 `catalogPath`，再使用对应参数。SVG、HTML、脚本和艺术源图仍完整保存在原 ZIP；需要运行原包预览时，将对应 ZIP 解压到独立目录并保持其结构。

详见 [整理校验报告](清单/整理校验报告.json)。包内旧 QA 文档中的检查结论属于原包作者记录，本次没有将其转写为游戏已验收结论。

## 后续更新

新增素材包时，先确认覆盖的组件角色和窗口范围，再新增一份整理版本。文件名的 `v3`、`v1.0` 不足以确定实际版本，必须同时读取包内清单。

整理脚本为项目根目录的 `tools/prepare_ui_asset_catalog.py`。默认创建本目录；目录已存在时拒绝覆盖。现有目录只读复核命令：

```powershell
python -X utf8 tools/prepare_ui_asset_catalog.py --verify
```

脚本生成资产、参数和 JSON 清单；本目录的综合说明与阅读索引是本次另行新增的文档。后续更新应建立新版本目录，不在原包或旧说明上静默覆盖。

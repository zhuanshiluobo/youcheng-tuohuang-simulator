# UI 版本采用与替换关系 · 2026-09-24

本文新增记录当前素材的采用关系。原包与原说明继续保留，用于追溯和复现历史预览。本文中的替换指接入时的素材角色映射，不代表已经改动 Unity 资产。

## 2. 参数采用顺序

按“哪一项被新版明确覆盖”选取数据，不把整个旧包判为过期，也不根据 ZIP 的写入时间决定版本。

| 需要的参数 | 当前依据 |
|---|---|
| 新版组件尺寸、切片、留白、PNG 路径 | [Frontier 组件清单](../原包参数/FrontierUI-v3-Patch/asset-manifest.json)，实际版本 3.1 |
| 新版顶栏内容位置 | [顶栏内容布局](../原包参数/FrontierUI-v3-Patch/topbar-v3/content-layout.json)，版本 3.1 |
| 主界面各区域和层级 | [区域布局补丁](../原包参数/FrontierUI-v3-Patch/layout-patch.json)，仍标记 3.0.0 |
| 旧角色如何转为新组件 | [皮肤映射](../原包参数/FrontierUI-v3-Patch/skin-patch.json) |
| 未被补丁覆盖的主界面内容结构 | [原主界面说明](../../MainGameUI-Layout-v2.2.md) 与 [原布局](../原包参数/MainGameUI-v2.2/layout.json) |
| 各窗口模式、候选与原图区域 | 对应窗口原说明、`sources/*.json`、`assets/component-map.json` |
| 真实候选、费用、权限、撤销和结算状态 | 项目当前规则与会话状态；素材包中的示例不提供正式规则实现 |

包名、布局版本、组件版本可以不同。本次保留这些原始字段，并在综合文档中解释它们，没有改写源 JSON 来制造一个表面统一的版本号。

## 3. 主界面角色映射

下表的组件 ID 对应 [新版组件索引](../清单/新版组件索引.json)。旧角色前缀省略文件目录和扩展名。

| 旧视觉角色 | 新组件 ID | 接入处理 |
|---|---|---|
| `screen-fill` | `module-bg` | 独立背景 |
| `screen-frame` | `outer-frame` | 外框使用新切片 |
| `module-frame`、`submodule-frame`、`thin-row-frame` | `module-frame` | 按模块用途与目标尺寸布置 |
| `module-fill-dark` | `module-bg` | 独立底图 |
| `module-fill-paper` | `paper-bg` | 暖灰资料底 |
| `module-header-fill` | `header-bg` | 标题文字单独配置 |
| `module-header-frame` | 空映射 | 停止绘制此旧装饰层 |
| `card-slot-fill`／`card-slot-frame` | `card-bg`／`card-frame` | 不从外框比例推导原卡比例 |
| `topbar-fill`／`topbar-frame` | `topbar-bg`／`topbar-frame` | 采用 64 高的新版顶栏区域 |
| `turn-ribbon-fill` | `turn-tag-refined` | 新版行动状态标签 |
| `turn-ribbon-frame` | 空映射 | 不叠旧旗框 |
| `title-plaque-fill/frame` | 空映射 | 新版标题、标识独立布局 |
| `right-cluster-fill/frame` | 空映射 | 改为独立红区、收起与设置控件 |

空映射表示停止绘制对应旧视觉层。原文件继续保留，标题、设置、收起等语义控件仍需重新接线。v2.2 合并标题板和已弃用红旗也不进入新版主界面。

`turn-tag` 是补丁 3.0 的兼容项，当前使用 `turn-tag-refined`；`redzone-paper` 未被 3.1 的 `preview/scene.mjs` 引用，当前红区分组使用 `redzone-plaque`。两项兼容图保存在单独目录，未删除。

## 4. 其他窗口映射

| 窗口职责 | 新组件 |
|---|---|
| 窗口底图／最外框／标题底 | `module-bg`／`outer-frame`／`header-bg` |
| 分区底图／边框／纸面摘要 | `module-bg`／`module-frame`／`paper-bg` |
| 普通卡槽 | `card-bg` + `card-frame` |
| 确认／取消／禁用按钮 | `button-primary`／`button-secondary`／`button-disabled` |
| 可选、选中、不可选叠层 | 沿用独立选择状态素材及逻辑；普通卡框不替代状态框 |

历史 `component-map.json` 的 `window-fill`、`section-fill`、`confirm-art`、`cancel-art`，分别对应补丁的窗口背景、分区背景、确认按钮和取消按钮职责。映射应根据用途确认，不能仅匹配同名文件。

卡牌与选项旧 `window.png` 是整张底板；改用新版外壳时需要组合多个独立组件。旧主／次按钮通过 `visibleRect=(35,102,1916,582)` 映射；新版按钮已经导出为 `320×98`，直接使用新版九宫格参数，不再应用旧可见区裁切。

页签、步进器、滚动条和部分窗口专用选中图仍保留原资源。补丁主预览会复用新按钮拼出部分控件，但没有为每种历史控件提供一套独立的新状态切图；本次没有自行重绘或推断这些映射。

## 5. 已确认的差异与待适配项

| 发现 | 本次处理 |
|---|---|
| 企业包名写 v1.0，包内说明与清单为 1.0.1 | 按实际 1.0.1 记录，源文件名保持原样 |
| 补丁组件为 3.1，区域布局仍标 3.0.0 | 分别标明职责；3.1 顶栏细化沿用该区域布局 |
| 补丁 `verification.json` 写 `assetCount:51`，组件清单实际 35 项 | 统计以实际清单为准；原记录原样保存 |
| 旧设施、企业、城市样式、科室窗口到 y=1012；新底栏从 y=986 开始 | 旧窗口外框重叠 26 像素，部分页脚也可能进入底栏；列为布局适配项 |
| 建设旧左栏有可交互效果，新版要求全局抽屉管理 | 保留候选、城市、付款与只读报价职责；将效果控制集中到同一上下文 |
| 新底栏有撤销入口，但素材没有真实撤销实现 | 按规则层提供的可撤销范围接入；未提供能力时禁用并显示原因 |
| 历史预览仍显示旧顶栏作为背景 | 保留作历史参考，不视为推翻 3.1 顶栏的新设计 |
| 城市样式示例含扩展版军工化区域、核心商业区及 6 分版警备队辖区 | 图集与来源完整保留，不能据此覆盖当前对局的卡组或内容版本 |

这些待适配事项没有通过改图或编造新矩形消除。主界面有新版完整拼装图；其余窗口应在 Unity 适配后，以实际使用的场景／Prefab 检查最终画面。

## 6. 去重和保全

去重键为完整 SHA-256，相同内容仅保存一个整理副本；不同内容即使同名也不会互相覆盖。`资产索引.json` 的 `sources` 保存所有源包成员，`uses` 保存选入整理时的用途。`源包文件索引.json` 可按原包路径反查整理位置。

例如多个窗口共用同一套选择框、资源图标和城市板，它们仍有各自的使用参数，但不会重复保存图像。城市样式和科室的独立来源清单继续保留，图像去重不意味着游戏内容或规则定义可以合并。

源 ZIP 和旧说明均未移动、删除或改写。新增目录外的保全证据见 [源文件保全](../清单/源文件保全.json)。

# Unity UI 资产接入说明 · 2026-09-24

本文给后续界面替换使用。本次只在 `游城拓荒/UI素材/整理版-2026-09-24` 新增整理结果，没有导入 `Assets`，也没有保存任何场景或预制体。

## 1. 使用整理资源

新版 PNG 从 `资产/新版组件/Frontier-3.1` 选取。组件实际尺寸、原切片及整理路径统一查询 [新版组件索引](../清单/新版组件索引.json)。原卡、标记和窗口专用素材查询 [资产目录](../资产目录.md)。

同一图像在多个包内出现时，整理目录仅保留一份。若原说明中的路径在整理目录找不到，使用 `源包文件索引.json` 中的 `package + relativePath` 查询 `catalogPath`。不要按旧目录结构猜测新路径。

将确认采用的运行时 PNG 导入项目专用目录，保留 Unity 生成的 `.meta`。原 ZIP、SVG、预览图片、QA、生成脚本和机器索引不应被误当作游戏运行时纹理整包导入。

`原包参数` 是原文副本，其路径仍按原 ZIP 根目录解释。使用 SVG 时需完整保留相对引用的艺术源图；当前整理图像库选择独立 PNG，因此没有移动 SVG 并破坏其依赖。

## 2. 纹理与切片

UI 装饰通常使用 Sprite，保留 Alpha。根据目标显示尺寸决定导入尺寸和压缩，先检查中文卡文、细线及透明边缘是否清楚；不要把 2000 多像素的旧按钮画布误认为必须按其全尺寸显示。

Frontier 清单的 `slices` 顺序是 **左、上、右、下**，Unity Sprite border 顺序是 **左、下、右、上**。新版组件索引已提供转换后的 `unityBorderLeftBottomRightTop`，避免直接按相同数组顺序拷贝。

| 新组件 | 源尺寸 | 源切片：左、上、右、下 |
|---|---|---|
| `outer-frame` | 1024×576 | 64、64、64、64 |
| `module-frame` | 512×320 | 16、16、16、16 |
| `drawer-frame` | 1024×240 | 20、20、20、20 |
| `card-frame` | 320×456 | 12、12、12、12 |
| `button-primary/secondary/disabled` | 320×98 | 28、20、28、20 |
| `undo-enabled/disabled` | 200×64 | 28、20、28、20 |
| `topbar-bg` | 1920×72 | 16、8、16、8 |
| `topbar-frame` | 1920×72 | 28、8、12、8 |

切片用于保护边角，`contentInset` 是内容留白，两者不能混用。底图与透明边框使用独立 Image；文字不随边框纹理拉伸。全零切片的背景按角色缩放或裁切，方形图标等比显示。

新版按钮已经裁出可见外观，不再使用旧按钮的 `visibleRect`。沿用的卡牌选中图、选项条或旧滚动条仍需要自己的源区域映射。命中区取逻辑控件矩形，装饰图层关闭不必要的 Raycast Target。

## 3. 坐标与现有承载方式

设计采用左上原点。如果 Unity 节点使用左上锚点和左上 pivot，逻辑 `(x,y)` 可转换为 `anchoredPosition=(x,-y)`；若使用其他锚点，需要按实际父级换算，不能机械写入同一组数值。

现有 [GameplayInteractionHud](../../../../Assets/YC/Presentation/Prefabs/Gameplay/GameplayInteractionHud.prefab) 包含屏幕 UI Canvas 和桌面 WorldSpace Canvas。[TabletopCanvasLayout](../../../../Assets/YC/Presentation/TabletopCanvasLayout.cs) 会按地图相机及地图边界配置桌面层。新版固定屏幕布局接入前，需要明确每个模块所属的 Canvas，以及地图视口、屏幕到地图坐标转换和相机缩放的关系。

不能将历史桌面层的相机跟随布局和新版屏幕矩形同时作用于同一对象。常驻底栏、弹窗、抽屉与子选择器要统一处理遮挡、点击优先级和输入锁定。

## 4. 现有接线位置

以下是仓库中已存在的接入位置参考，不表示只修改一个 Prefab 就能完成整套替换。

| 目标 | 现有位置 | 接入时检查 |
|---|---|---|
| 对局主界面 | `GameplayInteractionHud.prefab`、`GameplayInteractionHudView` | View 序列化引用、Canvas、场景控制器的双向绑定 |
| 行动与卡牌操作 | `ActionPanelView`、`ActionPanelController`、`CharacterHandPanel.prefab` | 新页签、底栏入口与现有命令提交的关系 |
| 建设与城市 | `BuildInfoPanel.prefab`、`BuildFacilitySelectionController` | 候选、位置、付款、报价与旧选择流程的接线 |
| 通用选择 | `Dialogs/EffectDialogShell.prefab`、`EffectDialogShellView` | 行模板、卡模板、确认、取消、滚动和布局 Profile |
| 弹窗实例化 | `GameplayDialogRegistry` | 实际使用的 Prefab 注册、卡图目录与配置验证 |
| 城市样式预览 | `Dialogs/CityStyleDeclarationPreviewDialog.prefab` | 新详情／宣告模式与现有入口的职责衔接 |
| 资源及回合表现 | `ResourceCounterBoard.prefab`、`RoundTracker.prefab` | 新摘要与顶栏读数的来源，避免重复可操作入口 |

`SampleScene` 与 `ThreePlayerScene` 共用 Gameplay HUD，但地图 Prefab 不同。共享界面改动优先落在明确的共享源资产；确属单场景的差异则保留为场景覆盖。接入和测试必须读取实际使用的同一资产来源。

企业／科室等窗口需要根据当前游戏实现确认正式接线位置。图包中的 `window.*Preview`、回调和浏览器事件是预览接口，不是可直接搬进游戏的命令或联网协议。

## 5. 数据边界

Presentation 展示候选和动态数据，提交意图；候选合法性、报价、支付、奖励、信息权限、取消和撤销由现有会话及规则层负责。素材包里的规则描述用作 UI 语义参考，不能替换正式内容包或 Lua 效果。

建设适配必须注意原有选择入口与新交互请求不能争用输入。底栏、抽屉、建设窗口和子选择器共享同一操作上下文；报价及异步结果需要匹配当前请求。必要步骤未完成、报价无效或 pending 时，对应提交入口禁用。

静态标题、按钮名称、布局与样式以编辑器资产为准。动态人数、地图、库存、回合、状态和错误由代码刷新。需要多种固定文案的同一控件，将文案集合序列化；不要在刷新函数中写回固定设计文案。

## 6. 实施批次

1. **组件样板**：导入选定 PNG，配置九宫格、字体和状态层，检查透明留白与点击范围。
2. **主界面**：按 3.1 顶栏及补丁区域布局适配，接入常驻底栏，集中结束行动入口，核对地图视口。
3. **全局结算**：实现底栏与抽屉的展示适配、pending 和当前操作绑定；规则没有提供的撤销能力保持禁用并显示原因。
4. **窗口迁移**：通用卡牌、选项、建设、企业、科室、城市样式分别适配。重排与底栏重叠的历史页脚，完成一个窗口再确认一个窗口的实际画面。
5. **实际场景验收**：检查两个对局场景与当前发布入口，确认运行中引用的资产来源及场景覆盖。

上述批次是后续计划，本次资产整理未执行这些 Unity 修改。已完成资产的覆盖需要明确目标和范围；普通验证不调用 `Assets/YC/Editor` 中的界面 Rebuild 或保存覆盖方法。

## 7. 验收重点

| 范围 | 验收内容 |
|---|---|
| 资产绑定 | 没有丢失 Sprite、脚本、View 或 Registry 引用；场景使用的是本次实际修改来源 |
| 比例与文字 | 原卡与城市完整等比；中文可读；动态数字增加位数不截断 |
| 数量与滚动 | 零候选、少量、标准与超量候选都可用；各列表滚动独立 |
| 选择与提交 | 预选不提前结算；失效选择不可提交；pending 阻止重复输入；取消遵循规则 |
| 结算与窗口 | 底栏可见；抽屉遮挡不穿透；子选择返回同一上下文；报价同步刷新 |
| 隐藏信息 | 对手手牌、盖放卡和不可公开内容遵循当前玩家权限 |
| 适配 | 1920×1080 基准及实际支持的较小／较宽窗口检查；不靠压扁卡面解决拥挤 |

自动测试验证引用、必要组件、交互及动态数据。可编辑的静态文字、坐标、尺寸、颜色和装饰不应变成测试硬约束。视觉结果必须检查当前场景或 Prefab 的实际显示。

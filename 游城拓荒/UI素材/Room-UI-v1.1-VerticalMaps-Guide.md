# 房间页与说明页接入说明 v1.1 · 地图上下排列

本版将三人地图放在上方、四人地图放在下方，完整显示地图。模式、扩展包与当前配置移至地图右侧。沿用 v1.0 的独立皮肤与控件，调整布局数据和全部房间拼装预览。

## 1. 组件拆分与画风

房间页覆盖全屏。背景为暖灰黑纸面，内容区域为浅纸面，主要操作使用柔和黄色；地图、头像及文字均运行时填充。

| 层级 | 素材 | 绘制要点 |
| --- | --- | --- |
| 整屏 | `shell/screen-fill`、`screen-frame` | 背景与边框分开；边框使用 1920×1080 或 3840×2160 版本 |
| 顶栏 | `shell/topbar-fill`、`topbar-frame` | 文字、Logo、密码／复制／说明控件独立 |
| 模块 | `panels/paper-fill`、`module-frame` | 底图与边框独立；调整容器宽高时只伸展框的直边 |
| 栏目标题 | `panels/section-fill`、`section-frame`、`accent` | 标题文本独立，黄色装饰条可以移动或隐藏 |
| 座位标题 | `panels/seat-header-fill`、`seats/bar-*`、`square-*` | 色条与方块由座位索引绑定 |
| 头像 | `avatars/fill`、`frame` | 框源自主界面共用框，通过九宫格绘制为方形；头像等比裁切 |
| 底栏 | `shell/footer-fill`、`footer-frame` | 状态文字与两侧按钮单独放置 |
| 说明页 | `help/reading-fill`、`panels/module-frame` | 低对比纸纹适合长文本；关闭按钮固定在顶栏 |

主界面原框的 1× PNG 保持原文件；清单记录来源校验和。头像框的源画布为 320×456，这是通用框的源尺寸，不是头像比例。绘制为 136×136 时使用切片，不能把整个源框直接压成正方形。

全部正式底图不含文字。不要把 `preview/` 的整页图当运行时底图。按钮可以选择完整底图，也可以叠加对应 fill 与 frame；两种方式不能重复叠加。

## 3. 地图规则：只有满 4 人才强制

| 房间状态 | 可选地图 | 当前地图如何变化 |
| --- | --- | --- |
| 少于 4 个已入座玩家 | 房主可选三人图或四人图 | 保留房主选择 |
| 第 4 个玩家入座，当前是三人图 | 仅四人图 | 立即切到四人图，三人图禁用 |
| 第 4 个玩家入座，当前已是四人图 | 仅四人图 | 保持四人图 |
| 从 4 人减少到 3 人或更少 | 恢复两种地图可选 | 保持当前四人图，不自动退回三人图 |

判断对象是有玩家实例占据的座位：在线玩家、已添加的热座玩家、人机均计入。空座、仅发出邀请但尚未入座的座位、关闭座位均不计入。

不要用 `地图 = 人数 == 3 ? 三人图 : 四人图` 之类的默认映射。辅助函数 `normalizeRoom` 只在人数为 4 时施加四人图约束；其余人数不替换 `mapId`。

三人图禁用时叠加 `maps/disabled-overlay`，使用禁用边框和居中的锁图标；四人图继续显示选中框与标题条右侧勾号。非房主看到当前配置，但不能修改地图、模式或扩展包。

独立的人数选择已移除。设置摘要里的“3 位玩家／4 位玩家”是只读统计；最少开局人数、其他开局条件通过房间逻辑提供的 `canStart` 判断，不由贴图包设定。

玩家颜色由当前座位决定，颜色不随玩家对象迁移。换位时交换／迁移占位对象，原座位颜色仍留在原位置；房主身份跟随玩家 ID，与座位号和颜色无关。

| 座位状态 | 房主看到的操作 | 非房主看到的操作 |
| --- | --- | --- |
| 自己已入座 | 换位置 | 换位置 |
| 其他玩家已入座 | 独立的移除按钮 | 只读成员状态 |
| 开放空座 | 邀请、热座、人机、关闭座位 | 只读空座信息 |
| 已关闭 | 开启座位 | 已关闭状态 |

“换位置”调用座位选择流程。可移入开放空座；目标已有玩家时发出交换请求，由项目既有房间逻辑决定如何接受。辅助函数只产生请求数据，`applyAcceptedSeatChange` 供请求获准后更新展示。关闭座位不能作为换位目标。目标选项可复用浅色按钮与原色方块，不需要新画一套边框。

“移除”仅房主对其他已入座玩家显示，图标为 `remove-danger`，配浅色底图。移除后该位置变为开放空座，出现空座配置选项。移除不会关闭座位。

“关闭座位”仅出现在开放空座；对已入座位置隐藏，并在事件处理层拒绝关闭。开启已关闭座位只恢复为空座，不自动加入玩家。房主自己的离开／移交沿用项目原流程。

说明页为遮罩上的独立纸面窗口，仅承载文本。背景用 `help/reading-fill`，框用共用 module-frame；标题、章节标题、正文、关闭按钮分别绘制。页面正文来自规则书或项目文本，本包中的文字仅为排版示例。

| 顶部关闭按钮 | 1524, 120, 64, 64 |

## 7. 设置密码的配套控件

顶栏密码按钮位于房间号左侧，仅房主显示。`isProtected` 决定“设置密码／修改密码”文案。说明与复制入口对所有房间玩家保留。

配套密码弹窗参考矩形 `(590,308,740,464)`；输入区 `(636,458,648,58)`，顶部关闭 `(1244,328,56,56)`。使用共用阅读底图、模块框和 neutral／accent 按钮，无需单独固定尺寸底板。

输入框提供 default、focus、error、disabled 四态，实际输入默认遮蔽，eye／eye-off 图标切换可见性。保存与取消使用已有按钮；输入长度、合法字符、已有密码能否清除等规则由项目定义，本包不写死。校验消息作为独立文字放在输入框下方。

保存成功后关闭弹窗，顶栏变为“修改密码”；请求期间使用禁用状态。取消或关闭不提交修改。房间号复制只复制房间号字符串，成功提示以剪贴板操作实际返回为准。贴图包和状态辅助函数不实现密码存储、校验或联网服务。

## 8. 导入与九宫格

PNG 为 sRGB、straight alpha。颜色 Tint 为白色，避免改变四种玩家色。`assets.json` 的切片顺序是 **左／上／右／下**，1× 数值如下；使用 2× PNG 时切片像素全部乘 2，目标逻辑尺寸与厚度保持不变。

| 类别 | 切片 |
| --- | --- |
| 整屏框 | 24 / 24 / 24 / 24 |
| 顶栏底 | 16 / 8 / 16 / 8 |
| 顶栏框 | 28 / 8 / 12 / 8 |
| 模块框／说明页框 | 16 / 16 / 16 / 16 |
| 头像框 | 12 / 12 / 12 / 12 |
| 按钮 | 10 / 10 / 10 / 10 |
| 地图选项框 | 12 / 12 / 12 / 12 |
| 输入框 | 8 / 8 / 8 / 8 |
| 滚动条 | 顶、底各 5，逻辑宽度保持 12 |

按钮与边框采用 Sliced／九宫格。图标、玩家方块、头像、地图内容保持原比例。本版地图使用完整等比显示（Contain / Preserve Aspect），不旋转、不裁切、不拉伸。两张原图均为正方形，对应 326×326 视口。地图标题条在图像下方，选中勾号放在标题条右侧，不遮挡地图。

若使用 Unity，@2x 的 Sprite PPU 设为 1× 的两倍，同时用相同 RectTransform 大小和双倍源切片像素；不要 SetNativeSize 到两倍大小。其他引擎按等价像素密度处理。

SVG 源文件引用包内 `sources/` 的共用纹理；保留目录关系。PNG 已完成渲染，不依赖 SVG 或 sources。`ASSET_MANIFEST.md` 是完整文件映射。

## 9. 状态辅助代码与验证

`components/room-ui-state.js` 可直接作为 JavaScript 参考，也可移植到项目语言。输入 `example-room.json` 中的结构；通过 `normalizeRoom` 处理每次收到的房间更新，再绑定控件。客户端控件权限只是 UI 行为，实际请求仍交由房间服务处理。

关键字段：`hostId`、`viewerId`、`roomNumber`、`mapId`、`isProtected`、`canStart`、`canReady`、`seats[]`。座位状态为 open／closed／occupied，occupied 必须有 occupant。房主身份以玩家 ID 判断，不以座位 1 判断。

检查覆盖：3 人选择三人图或四人图、4 人强制四人图、玩家离开后不自动改图、关闭空座不算人数、不能关闭有人座位、移除后空座仍开放、非房主操作限制、准备切换、换位颜色与房主身份、房间号前导零。

`QA.json`、`rules-QA.json` 记录验证结果，`SHA256SUMS.txt` 用于校验压缩包内容。已使用包内 PNG 拼装并检查多个状态；HTML 状态切换器已做语法和引用检查，未做浏览器自动化或用户游戏引擎的导入测试。

# 城市样式详情与宣告窗口 · 1.0.0

本窗口共用一套布局展示本局 6 张城市样式原牌与玩家城市，详情模式只查看，宣告模式在选中样式和条件组合后才允许确认，点击卡牌本身不会执行宣告喵

完整图包为 `CityPattern-UI-v1.0.zip`，独立说明为 `CityPattern-Layout-v1.0.md` 喵

## 两种模式与操作边界

| 模式 | 查看内容 | 点击原牌 | 页脚动作 |
|---|---|---|---|
| `view` | 本局样式、全部玩家标记及当前城市 | 切换详情或放大 | 关闭／返回，不提交宣告 |
| `declare` | 同一内容，加当前玩家的条件和资格 | 预选样式 | 规则校验通过后确认宣告 |

详情中查看其他玩家的标记不会改变当前行动玩家身份，宣告资格始终针对调用方指定的当前玩家喵

宣告和使用城市样式特效是两种不同操作，本窗口不在确认宣告后自动触发特效，也不自动进入警备队辖区的后续选项喵

## 原状态槽与标记叠层

状态槽位置使用完整原牌内的局部源坐标，下面的矩形仅用于叠层安全区，不能据此裁切整张牌喵

| 类型 | 状态 ID | 原义标签 | 卡内安全矩形 `(x, y, w, h)` |
|---|---|---|---:|
| Ⅰ | `unused` | 未使用 | `(530, 76, 300, 229)` |
| Ⅰ | `used` | 已使用 | `(530, 309, 300, 225)` |
| Ⅱ | `ready2` | 2 | `(530, 76, 300, 71)` |
| Ⅱ | `used2` | 已使用，上段 | `(530, 151, 300, 87)` |
| Ⅱ | `ready1` | 1 | `(530, 242, 300, 127)` |
| Ⅱ | `used1` | 已使用，下段 | `(530, 373, 300, 87)` |
| Ⅱ | `exhausted0` | 0 | `(530, 464, 300, 70)` |

`Ⅱ` 五槽按 `2 → 已使用 → 1 → 已使用 → 0` 的原牌顺序保留，两个已使用槽是不同位置，不能合并；`0` 表示次数耗尽喵

来源清单用 `zero` 标识最后一槽，当前预览运行时使用 `exhausted0`，两者对应同一个原图安全矩形，接入时不能将来源键直接当作全部运行时键喵

小尺寸显示将未使用／已使用缩写为 `未用`／`已用`，只简化显示标签，不改变原状态含义喵

`Ⅰ` 原牌分隔位于局部 Y 的 `305–308`，`Ⅱ` 四处分隔位于 `147–150、238–241、369–372、460–463`，叠层避开原分隔线喵

允许在状态栏安全区内叠加独立暗色半透明底、原义标签与玩家颜色数字块，以提高缩略尺寸下的可读性，覆盖范围不得扩展到原牌条件、奖励与规则正文喵

当前状态底为 `#272820`、透明度 `0.96`，缩略卡状态标签为 `10 px`，左内边距为 `5 px`，颜色块为 `18 × 18`、间距 `3 px`，从槽左侧 `25 px` 处开始，按红、蓝、黄、绿排列喵

每个颜色块在对应安全槽内垂直居中，缩略卡中其位置为 `slotX + 25 + i × 21`、`slotY + (slotHeight − 18) / 2`，放大原卡时这些内部距离与卡面一起按比例增大喵

额外宣告带的颜色块为 `16 × 16`，从卡片左边 `76 px` 处开始、按 `56 px` 步长排列，Y 为条带顶部加 `2 px`，数量为零时弱化显示以表示未放置标记喵


给卡内状态矩形 `R = (rx, ry, rw, rh)`，它与原卡使用同一个等比变换喵

```text
screenSlot = (
  cardX + rx * patternScale,
  cardY + ry * patternScale,
  rw * patternScale,
  rh * patternScale
)
```

| 玩家颜色 | 精确色值 |
|---|---|
| Green | `#5FD200` |
| Yellow | `#FFBF00` |
| Blue | `#006CFF` |
| Red | `#EC0000` |

同槽须能显示多名玩家，也须能按数据表示同一玩家多个标记，使用各玩家独立的纯色数字块表达数量，不将不同玩家合并为分色块或一个总数喵

数字只是标记数量的压缩表达，不能把数字理解为剩余使用次数，也不能根据槽内已有其他玩家就判定该槽满员喵

## 额外宣告标记与次数轨道

首次宣告按每名玩家自己在该样式上的状态判定，不按全场是否已有别人宣告判定喵

首次宣告的标记落点由规则类型决定：主动 `Ⅰ` 初次进入未使用，纯奖励型初次属于已宣告，`Ⅱ` 初次进入 `2` 槽，不能对所有样式使用同一个默认位置喵

后续宣告的新标记应放在已宣告区或宣告条件旁，本界面用靠近原牌的额外宣告带保留这些标记，不将它们再放入 `Ⅱ` 的 `2` 槽喵

重复宣告不会重置使用次数，也不会为同一玩家创建第二条使用次数轨道，当前使用状态由调用方传入喵

当某项效果中的 `X` 按本人在该样式的标记总数计算时，需要同时统计该玩家的状态槽标记与额外宣告标记，不只统计当前高亮槽喵

回合收尾时，主动 `Ⅰ` 已使用标记回到未使用，`Ⅱ` 已使用标记前进到下一数字槽，仍处于 `2` 槽且未使用的标记不会自动降到 `1`，这些迁移由规则层处理喵

## 城市条件与原面板

城市原图为 `2059 × 3801`，以宽 `354 px` 完整等比显示，不能裁去城市格或将原板压扁喵

城市格为 3 列 × 4 行，每格局部源尺寸 `600 × 850`，列 X 为 `100、730、1360`，行 Y 为 `156、1036、1916、2796`，核心指挥塔是第三行第二列单格喵

格子、设施和条件高亮均使用 `354 / 2059` 的同一变换，不能把含边框的整张城市图片等分成 12 个点击矩形喵

每张设施在整局中只可用于一次城市样式宣告，宣告后转动 `180°`，原卡文件不变，显示层体现其已使用状态喵

已用于宣告的设施不能再参与后续宣告条件，当前匹配格、已使用设施及不可选原因由规则层提供，UI 不根据图案颜色自行推断资格喵

条件可以旋转、不能镜像，彩色设施可按规则视为任意颜色，当前旋转方向和选用设施组合应与规则返回的匹配结果一致喵

匹配同时检查颜色和相对位置，不能只统计颜色数量，也不能改变设施之间的格距；双颜色条件格表示任选其中一种颜色的 1 张设施，不是同时要求两张喵

图案留白不额外要求对应城市格为空，彩色设施也只能占用图案中的一个条件格，不能一张设施同时满足多个位置喵

查看模式不修改任何设施的方向或资格，宣告模式的高亮只是预览，确认前也不旋转设施、不花费玩家标记、不发放奖励喵

## 宣告规则边界

宣告是快速行动，可以在主要行动前后进行，不能中途插入主要行动结算，也没有统一的每回合只能宣告一次限制喵

同一样式可以多次宣告，但每次仍需满足对应条件、使用尚未用于宣告的设施并消耗 1 个可用玩家标记，再按卡面获得分数和结算宣告效果喵

使用城市样式特殊行动是主要行动，每个样式每名玩家每回合最多使用一次，该限制不能误用为宣告次数上限喵

当前不能宣告时仍可查看原卡、状态槽和原因，诸如时机不符、没有匹配组合、设施已经用于宣告或没有可用玩家标记，都由规则层明确返回喵

确认在调用方的当前玩家上下文中提交选中样式与设施组合等选择意图，玩家标记移动、设施旋转、得分和后续效果由规则层执行喵

## 数据与接入 API

离线入口为 `preview/index.html`，HTML 与静态导出共用 `preview/data.js` 和 `preview/scene.js`，交互由 `preview/app.js` 承担喵

```js
window.cityPatternPreview.open('details');
window.cityPatternPreview.open('declaration');
```

真实接入可传入完整配置对象，并提供下列回调，示例数据仅展示 UI 状态，不是通用图案匹配引擎喵

| 字段 | 含义 |
|---|---|
| `mode` | `view` 或 `declare` |
| `patternIds`、`patterns` | 本局卡序和可替换的完整样式定义 |
| `activePlayerId` | 当前行动玩家 |
| `availableMarkers` | 当前可用玩家标记数 |
| `canCancel` | 是否允许关闭／取消 |
| `actionPhaseAllowed` | 当前是否允许宣告 |
| `cityFacilities` | 城市设施、所在格、`usedForPattern` 和可选资格 |
| `declarationHistory` | 当前玩家对各样式的已宣告次数 |
| `initialPatternId`、`selectedCellIds` | 初始查看对象与预选城市格 |
| `validateMatch(request)` | 同步返回规则校验结果 |
| `onConfirm(payload)` | 提交意图，可返回 Promise；返回 `false` 保留窗口及选择 |
| `onClose(payload)` | 关闭通知 |

样式定义中的 `markerTracks[slotId][playerId]` 与 `extraDeclarations[playerId]` 都是数量，前者表示原状态槽中的标记，后者表示额外宣告标记，两者不可合并成同一个使用次数值喵

`patterns` 中的 `sourceRect`、`slotLayout`、`versionId` 必须对应同一张原卡，`firstDeclarationState` 决定首次标记落点，`repeatConditionText` 可用于显示不同的再次宣告条件喵

演示配置的 `matchSets` 只为预设城市提供明确匹配组合，实际对局应使用 `validateMatch` 检查完整规则，不能据此推断未列出的组合必定不合法喵

校验回调在基本时机、可用标记和设施资格检查后收到下列字段喵

```js
{
  patternId, versionId,
  cellIds, facilityIds,
  activePlayerId, declarationCount, availableMarkers
}
```

返回失败时至少提供 `{ valid: false, reason }`，成功时应提供确认所需的匹配信息，下面字段名与预览一致喵

```js
{
  valid: true,
  reason: '组合符合条件',
  matchId,
  rotation,
  conditionVariant,
  score,
  markerDestination
}
```

旋转值由规则层给出，首次标记落点示例为 `unused` 或 `ready2`，再次宣告落点为 `extraDeclarations`，预览不自行移动任何标记喵

确认前会重新校验，实际传给 `onConfirm` 的对象如下，当前玩家沿用调用方打开窗口时的上下文喵

```js
{
  mode: 'declare',
  patternId, versionId,
  cellIds, facilityIds,
  matchId, rotation, conditionVariant,
  markerDestination
}
```

`onConfirm` 接受后关闭演示窗，并派发 `window` 上的 `city-pattern-declare` 事件，其 `detail` 为同一对象；回调返回 `false` 时保留当前选择，不派发确认事件喵

待确认期间阻止重复操作，异步确认通过操作序号避免旧窗口结果影响后来打开的新窗口，界面自身不扣标记、加分、旋转设施或发动特殊行动喵

关闭会调用 `onClose({ mode, reason: 'close' })` 并派发 `city-pattern-close`，`canCancel = false` 时不执行关闭，详情模式没有宣告提交入口喵

点击样式切换查看对象并清空城市格预选，已用于宣告的设施不能选中，放大及关闭放大不会改变已选样式或城市格喵

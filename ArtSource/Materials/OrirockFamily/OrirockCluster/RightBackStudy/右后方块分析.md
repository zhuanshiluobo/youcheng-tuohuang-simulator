## 当前算法为何没有保留手填边向量

`corner_cube` 先将三条屏幕边组成2×3矩阵，翻转y并乘0.016，使用SVD取最近的等长正交投影行，再通过叉乘补出深度。三轴因此始终正交、等长，生成完整立方体，而不是分别拉扯八个角点。

当前输入：

```python
corner = (153, 108, .10)
screen_edges = [(-19, -19), (-1, 31), (14, -37)]
```

实际输出的屏幕边却是：

```text
u = (-32.087, -15.353)
v = (  0.795,  22.565)
w = ( 19.684, -25.938)
```

所以右上角`corner+w`实际在(172.684,82.062)，不是手填向量暗示的(167,71)。相对原图右上角约(167.5,65.5)，偏右约5.2、偏下约16.6像素。灰浅分界下端`corner+v`在(153.795,130.565)，又偏左约1.7、偏上约4.9像素。只调整手填边方向而不检查正交修正后的输出，会继续低估这些偏差。

```python
right_back_cube = corner_cube(
    '右后_单个倾斜立方体_灰左浅右褐顶',

    [(-40.490, -13.413), (-1.860, 24.573), (15.088, -32.967)],
    [2, 1, 4, 1, 1, 0],

```

这组屏幕行已近似满足正交、等模条件，两个像素尺度奇异值为43.2502和43.2497；经过现有算法后，向量改动不足0.001像素。实际立方体边长约0.692，当前约0.602，增大约15%。三轴深度增量均为负，共用角点是朝向相机的角点，灰左、褐顶、浅右可属于同一完整物体的三个可见面。

## 面材质和真实三维结构

按`BOX_FACES`顺序，正对相机共角的三个面应为：

- 面0 `[0,1,2,3]`：u-v灰左面，当前材质2。
- 面2 `[0,4,5,1]`：u-w褐顶面，当前实际材质4“棕灰”，不是材质1“赭褐”。
- 面5 `[3,7,4,0]`：v-w浅右面，当前材质0。

如果上材质阶段需要更明确的褐顶，可只将`indices`第2项由4改为1，即`[2,1,1,1,1,0]`；其余项不动。白模对照尚不能验证颜色。使用三面分别着色及各面局部颗粒/风化，保留共同八顶点、六个平面和完整背面，不用整图投射制造颜色拼块。

本对象仍是既有右后主方块。它不是新增的第三个后撑；主代理保留背后1–2个大方块的数量约束。本次没有提出额外薄片、贴面壳或用封口充当造型的做法。

## 单视图与刚性立方体的具体限制

不是简单地说“单视图做不到”。限制可以在本图的可见边上直接计算：若硬将灰褐可见段方向取作约(-17,-20)，褐浅上部方向取作约(12,-27)，二者屏幕点积为`-204+540=336`，为正。正交投影下，同一朝向相机的立方体共角的三条边都向后退，必须满足`屏幕点积=-深度乘积≤0`。这些观测方向因此不能同时作为当前算法中完整立方体的精确直棱。原图的边缘凹凸、遮挡和绘制夸张也使外轮廓难以组成完全平行的三对边。

已实际完成两种权重的等长正交拟合，而没有把上述限制当成停止依据。深度0.10是沿用值，不是从单图恢复的真值；隐藏角点、背面及与主块的穿插仍需结合主代理的实际三维现场判断。先试首选并检查灰浅交界、灰褐露出范围、上侧轮廓及右侧肩部；若轮廓优先，再试备选。两种方案均不应仅凭物体数量、封口或数值误差被判定视觉通过。
